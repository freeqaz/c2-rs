#3336: a control never seen red is decoration, and this repo shipped a
`--check` that could not fail. Exit codes below are read DIRECTLY from $?
with no pipe in between — the wave-13 lane's first evidence capture read
EXIT=0 on a broken run because `$?` after a `tee` pipe is `tee`'s.

THE BREAK, applied to a throw-away copy of the script and never to the tree:
in `diff_rows()`, a constant that APPEARED already tagged is booked as if it
had been retagged in place. That is the exact conflation the mode exists to
prevent, it is what a plausible-looking differ does silently, and it makes
the tagged-count delta read as provenance work when it is new surface.

6. THE #3649 FIX, WATCHED FAILING (the same discipline, a different break)
==========================================================================
The defect: a glob written inside a `///` doc comment — `coff/*.rs`,
`fixtures/cpp/*.cpp` — was read as an unterminated block comment, so the
file's brace depth froze from that line to EOF and every `#[cfg(test)]`
region below it stopped being excluded. Eighteen files in `crates/` contain
one. Section [10] of the suite plants the shape.

With the fix reverted:

  FAIL  population is the TWO production consts, not four: got 4, want 2
  FAIL  untagged residue: got 4, want 2
  FAIL  removing the glob moves NOTHING (it never should have): got (2, 2), want (4, 4)
EXIT=1

The third check is the defect stated as a property: REMOVING the glob moved
the population from 4 to 2. A doc comment's contents cannot be allowed to
change a count, and before the fix they did.
