## 1. What this lane is for, stated before it is built

CEILING §6.1's complaint about all seven phases is that they *"would have to
exist, and do not."* Phase 1 is the row where that is least true and most
confusing, and the confusion is **located in one comment**.

`crates/c2-harness/src/gap/factors.rs`'s doc on `PORT_CFG_CLASSES` says

> *"it is a **hand-maintained mirror of a `c2-core` enum**, and nothing in the
> type system ties the two together"*

and

> *"`Selected` has seven variants — `Plain`, `Tail`, `Float`, `Framed`, `Seq`,
> `CondPair` — and between them they cover straight-line bodies and one two-arm
> conditional."*

**Read before probing, from tracked source at `e82c9ede6`:** that sentence names
*seven* and lists *six*, and `crates/c2-core/src/codegen/select.rs`'s `Selected`
carries many more than either number — the exact count is registered as a probe
result (**R1**, §4 P7) rather than asserted here. The comment instructs
*"re-check when a variant is added"*; variants were added and it was not
re-checked, **because nothing can fail when it is not**.

**So phase 1's construct is: give the emitter a CFG class it can STATE, and tie
the screen's claim to it by something that fails.** That is the "thing that
exists" the §6.1 row asks for, and it is buildable at a required-zero byte delta
because every class it names is already byte-exact.

## 2. What will be built

`crates/c2-core/src/codegen/cfg_class.rs`, new, plus one `pub mod` line, plus a
derivation in `crates/c2-harness/src/gap/factors.rs`.

| # | thing | why it is not decoration |
|---|---|---|
| **C1** | `CflowClass` — the census spellings the emitter can name (`cflow-straight`, `cflow-if-1`, `cflow-if-2`, `cflow-if-n`, `cflow-loop`), with a `census_str()` | the screen matches census strings; a Rust enum that cannot render one is useless |
| **C2** | `Lowering` — one unit variant per shipped lowering reachable from `select_function` | the unit of a CFG-class claim is a **lowering**, not a `Selected` variant: `Selected::Plain` carries `ptr_walk_loop` (a `cflow-loop`) *and* every straight-line leaf |
| **C3** | `const fn class_of(Lowering) -> CflowClass`, an **exhaustive match** | adding a `Lowering` without declaring its CFG class is a **compile error**. This is the "tie" the `PORT_CFG_CLASSES` comment says does not exist |
| **C4** | `lowering_of(&IlFunction) -> Option<Lowering>` | lets the port answer *"which CFG class did I lower this into"* — phase 1's whole content |
| **C5** | a test grading C4 against `select_function`, per function, by name, over the fixtures | C4 is still a mirror. The difference from today is that this one is **measured every run instead of argued once** |
| **C6** | `SHIPPED_CFG_CLAIMS` — per `CflowClass`, `Whole` or `Partial(&[Lowering])` | `Partial` is exactly the claim `w-rotate` §7 and `w-sched2` §8 measured and had nowhere to record. Recording it is not shipping it |
| **C7** | `PORT_CFG_CLASSES` **derived** from C6's `Whole` claims, with a test asserting the derived list equals the frozen 4-entry literal | the re-expression, and its identity |

**C6/C7 together are the fence.** A `Partial` claim is recorded in `c2-core` and
**deliberately does not reach the screen**. `cfg-reach-shipped` must not move.

## 5. The pricing campaign, two-sided, registered before it runs

The decline in §3 is not free and this lane prices both sides before the rung
says `declined` on it.

**Side A — the cost of the refusal.** For each `cflow-*` class the port
demonstrably lowers but does not claim (P5), record the number of frontier TUs
whose `NeedsClass` verdict names that class. That is the reach the screen
*forgoes* by not claiming, measured with `cfg_reach_with` against a candidate
list — which board #778 built for exactly this and which no lane has used.

**Side B — the cost of shipping it.** #3270's rule: *a predicate is priced
against the ORACLE, on the population it will apply to, or it is not priced.* A
`CfgSub::Keys(K)` entry applies to every workload function whose cross-tab row is
`<class>|K`. So, per candidate key `K`: how many workload functions carry `K`,
and on how many is the port byte-exact against real `c2` rather than refusing or
differing? A key on which the port is exact 1-in-40 is a screen claim 97.5 %
wrong about c2 **at a metric delta of exactly zero** — `w-sizebracket`'s finding
restated in this lane's units.

**Registered invalidation:** if the join side B needs (per symbol:
`(cflow class|key, fnbyte verdict)`) cannot be produced from the existing scan
without changing what the port emits, side B is reported as **NOT PRICED** and
the §3 fence as **NOT SHIPPABLE ON THIS LANE'S EVIDENCE** — not as "declined".
An unpriceable fence is not a priced one.

## 6. Must-fail mutations — the instrument is graded, not trusted

Each is applied, the named failure recorded, and reverted. A mutation that does
**not** produce its named failure is a hole in the instrument and is the lane's
finding.

| # | mutation | must fail, BY NAME |
|---|---|---|
| **M1** | `class_of` returns `CflowClass::Straight` for every `Lowering` | the C7 derivation test — the derived `PORT_CFG_CLASSES` stops equalling the frozen 4-entry literal |
| **M2** | `lowering_of` returns `None` for one named shipped lowering (`IfCallJoin`) | C5's agreement test, naming that lowering |
| **M3** | `lowering_of` returns `Some(_)` for a function `select_function` refuses | C5, in the **over-claiming** direction, which is the one that matters |

**M2 and M3 are the pair.** A test that catches only M2 grades the mirror in the
under-claiming direction, which is the safe one; #3270's whole point is that the
unsound direction can be free in the metric used to choose it.
