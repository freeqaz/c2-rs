THE HEADLINE
------------
The whitebox record could answer "what did lane X find" and could not answer
"what is already known about 0x10b2b82d". At base: 19 findings documents, ~13,700
lines of prose, 428 hand label rows, 474 non-unknown rows in c2_functions.tsv,
1,126 distinct c2.dll addresses cited across docs/ (1,129 at this tip -- the
index is self-referential, see ref/README.md 4) -- and ZERO documents joining
those five sources. That is why the alignment nibble cost a lane, why dag.c's
lowering order took two, and why #1823's "there is no instruction scheduler"
stood for months IN A DIRECTORY THAT ALSO CONTAINED THE SCHEDULER'S BAND.

ADDR.tsv is that join. One row per address that is cited in docs/ or carries a
hand label: containing function + size, caller/callee counts, translation unit
WITH its in-anchor/gap/no-ice-site confidence, subsystem page, confidence,
label, and every doc that already mentions it.

FIVE FINDINGS THE JOIN PRODUCED (the lane read no new behaviour otherwise)
--------------------------------------------------------------------------
#3256  0x10b7f022 IS A REAL FUNCTION GHIDRA NEVER CREATED, and C2_MAP.md 3E's
       "the walk loop at 0x10b7f15f, inside FUN_10b7f1ff" is WRONG. 0x10b7f15f
       is BELOW that function's entry; the loop is inside a TAIL-JUMP TARGET
       (jmp 0x10b7f022 at 0x10b7f362) that auto-analysis never made a function,
       so decomp_all.c has NO BODY containing the project's most-cited whitebox
       finding. Found by 17 addresses failing to resolve. The predicate, the
       bits and the cascade are UNAFFECTED; only the location was wrong.
       "Ghidra found 4,916 functions" is a statement about Ghidra.

#3257  THE ADDRESS REGEX IS WRONG IN THREE DIRECTIONS AND THIS LANE'S OWN PREREG
       DENOMINATOR WAS BUILT WITH IT. \b does not fire between 'x' and '1' so
       \b10[bc]...\b misses every 0x10b9b8e9; unanchored it matches substrings
       inside the sha256; and FUN_/DAT_/LAB_ prefixed forms are missed by BOTH
       anchorings because '_' is a word character. 120 addresses are prefix-only
       -- INCLUDING FUN_10b8303c, the symbol-list driver that is the whole of
       open question R6. Frozen 1,079 vs corrected 1,126; the two sets are not
       nested, so the lane grades both ways and does NOT repair the frozen
       number in place.

#3258  THREE DOCUMENTS' Selection/CheckSum RULES ARE SCOPED STATEMENTS READ AS
       GENERAL ONES. "only 0 and 2 occur anywhere" is about .data/.bss -- .pdata
       carries Selection 5, and FUN_10be76d4 special-cases selection != 5, so
       the binary knows. "CheckSum nonzero ONLY for COMDAT" is refuted for .data
       at 9/9. All three dated claims stand; the corrections are beside them.

#3259  THERE ARE TWO DIFFERENT +0x44 FIELDS AND NO DOCUMENT SAID SO. Allocator
       candidate +0x44 (tie-break, DESC unsigned, 0x10b2b82d) vs DAG node +0x44
       (original tuple index, ASC, 0x10b327cd / 0x10be5cea). Different records,
       different passes, OPPOSITE DIRECTIONS. #3243 and WB_DAGORDER 2 each
       describe one of them as "the tie-break".

#3260  823 OF 1,199 ROWS HAVE NO PAGE -- most cited addresses are outside the
       six prioritized subsystems, and the reference says so with a denominator.
       Cheapest next page: P_READER over WB_READER_FINDINGS.md (596 lines, 79
       addresses, no index). EXPLICITLY NOT NEXT: instruction selection -- three
       lanes have read it and WB_SELECT_RECONCILED.md is their join.


DESIGN DECISIONS WORTH THE FUNNEL'S ATTENTION
---------------------------------------------
1. PROVENANCE IS THREE-WAY AND MANDATORY. [R] read-but-not-obj-checked (a
   hypothesis), [O] obj-confirmed with the grid named, [I] inferred; plus
   [O] port for readings the port has emitted a byte-exact obj on. An unmarked
   claim is a defect and that was FAILED criterion F5, frozen in advance. The
   reason is C2_MAP_METHOD.md 7: the .bss bump rule was read correctly out of a
   clean function and was WRONG ABOUT c2.

2. THE INDEX NEVER GUESSES WHICH PAGE OWNS AN ADDRESS. A page owns an address
   when the address is the FIRST CELL of one of that page's table rows.
   Authoring a page is what puts an address on it.

3. CORRECTIONS ARE AMENDED BESIDE, NEVER REWRITTEN. C2_MAP.md 3E keeps its wrong
   sentence with a revision box under it. WB_LIVE's candidate field table is
   reproduced in P_REGALLOC 4.1 AS WB-LIVE WROTE IT with #3243's two corrections
   in the same rows.

4. NO PAGE IS A DUMP. Full decompiled bodies stay in the uncommitted,
   regenerable Ghidra export; each page carries the five-line retrieval recipe.
   Volume was not the deliverable and a thousand unread pages would have been
   FAILED.

5. THE EXPORT PATH IS ENV-DRIVEN. $C2RS_GHIDRA_EXPORT, defaulting to
   ~/ghidra-projects/export/c2. No /home/... path is in any tracked file
   (verified: `git grep -n "/home/" -- docs/whitebox/ref docs/whitebox/scripts`
   is empty).
