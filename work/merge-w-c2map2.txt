THE HEADLINE -- AND IT IS A FINDING, NOT THE LAYOUT
---------------------------------------------------
C2_MAP.md 3E, the project's most-cited whitebox section, places the emit walk
"at 0x10b7f15f, inside FUN_10b7f1ff".

  0x10b7f15f IS BELOW FUN_10b7f1ff's ENTRY ADDRESS.

So it cannot be inside it, and decomp_all.c HAS NO BODY CONTAINING THE LOOP.
Anyone grepping the flat export for FUN_10b7f1ff to read the emit predicate --
the decision the whole census rests on -- reads the wrong function.

The loop is inside 0x10b7f022, which IS a real function entry that Ghidra's
auto-analysis never created:

  10b7f021:  c3                    ret
  10b7f022:  56                    push   esi          <- a function entry
  ...
  10b7f362:  e9 bb fc ff ff        jmp    0x10b7f022   <- reached by TAIL JUMP

functions.tsv has no entry anywhere in 0x10b7f022-0x10b7f1fe. A tail-called
routine is exactly the shape auto-analysis misses, and "Ghidra found 4,916
functions" is a statement about Ghidra.

THE WAY IT WAS FOUND IS THE ARGUMENT FOR THE LANE. Nobody went looking. The
address index was built, and SEVENTEEN ADDRESSES IN THAT ONE SECTION FAILED TO
RESOLVE TO ANY FUNCTION. The join produced the finding as a by-product of being
correct about containment. That is what a reference buys that a nineteenth
findings document does not.

The emit predicate itself, its bits, its cascade and the tag-0x0e decode are
UNAFFECTED -- only the location was wrong. Amended BESIDE 3E in a revision box;
the original sentence stands as written. Carried in build_ref.py's
GHIDRA_MISSED so the index cannot repeat it. Board #3256.

CONSEQUENCE FOR EVERY OTHER LANE: any claim of the form "address A is inside
function F" must be checked against F's ENTRY and SIZE, not against proximity.
ADDR.tsv now prints both.


WHAT WAS BUILT, AND WHY THIS SHAPE
-----------------------------------
The whitebox record could answer "what did lane X find" and could not answer
"what is already known about 0x10b2b82d". At base: 19 findings documents, ~13,700
lines of prose, 428 hand label rows, 474 non-unknown rows in c2_functions.tsv,
1,126 distinct c2.dll addresses cited across docs/ (1,129 at this tip -- the
index is self-referential, see ref/README.md 4) -- and ZERO documents joining
those five sources.

Building THE JOIN rather than more prose is what makes this a reference instead
of a nineteenth findings file. ADDR.tsv is that join: one row per address that is
cited in docs/ or carries a hand label -- containing function + size,
caller/callee counts, translation unit WITH its in-anchor/gap/no-ice-site
confidence, subsystem page, confidence, label, and every doc that already
mentions it.

A page OWNS an address when the address is the FIRST CELL of one of that page's
table rows. Authoring assigns; THE INDEX NEVER GUESSES. That is the property
that keeps it correct as it grows.

DESIGN DECISIONS WORTH THE FUNNEL'S ATTENTION
---------------------------------------------
1. PROVENANCE IS THREE-WAY AND MANDATORY. [R] read-but-not-obj-checked (a
   hypothesis), [O] obj-confirmed with the grid named, [I] inferred; plus
   [O] port for readings the port has emitted a byte-exact obj on. An unmarked
   claim is a defect and that was FAILED criterion F5, frozen in advance. The
   reason is C2_MAP_METHOD.md 7: the .bss bump rule was read correctly out of a
   clean function and was WRONG ABOUT c2.

2. THE INDEX NEVER GUESSES WHICH PAGE OWNS AN ADDRESS. A page owns an address
   when the address is the FIRST CELL of one of that page's table rows.
   Authoring a page is what puts an address on it.

3. CORRECTIONS ARE AMENDED BESIDE, NEVER REWRITTEN. C2_MAP.md 3E keeps its wrong
   sentence with a revision box under it. WB_LIVE's candidate field table is
   reproduced in P_REGALLOC 4.1 AS WB-LIVE WROTE IT with #3243's two corrections
   in the same rows.

4. NO PAGE IS A DUMP. Full decompiled bodies stay in the uncommitted,
   regenerable Ghidra export; each page carries the five-line retrieval recipe.
   Volume was not the deliverable and a thousand unread pages would have been
   FAILED.

5. THE EXPORT PATH IS ENV-DRIVEN. $C2RS_GHIDRA_EXPORT, defaulting to
   ~/ghidra-projects/export/c2. No /home/... path is in any tracked file
   (verified: `git grep -n "/home/" -- docs/whitebox/ref docs/whitebox/scripts`
   is empty).
