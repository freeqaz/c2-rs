TWO GATE-VOIDS, AHEAD OF THE SPEEDUP, BECAUSE THEY OUTRANK IT
--------------------------------------------------------------
**1. The mode cross has consulted `work/capture-cache` since 2026-08-04
and has never checked it.** `w-gateperf` gave the SWEEP a bypass-and-
compare validator the day that row acquired the same dependency, and made
poisoned/foreign a hard red; the cross never got one, and
`gate.sh --selftest` carries an explicit *"an ABSENT cache line is not a
zero and not a failure"* case that exists **precisely because this row
printed none**. That was survivable while a fresh worktree's cross was
~100 % misses. **It is not survivable at the ~100 % hits this lane
creates** — so the hazard this lane's own optimization would have
introduced is closed in the same lane. Each of the 18 `c2rs gap` batches
now runs `--validate-cache` (**894 real re-captures per run**) and the
driver prints `cache:` in `expr_sweep.sh`'s **exact spelling**, so
`gate.sh`'s existing `sweep_verdict` reddens the cross on `cache-bad>0`
**with no change to the decision path at all**. A/B'd back to back in one
session, four alternating runs, all printing `hit=90424 miss=388
cache-bad=0`: **validate=0 reads 29 s twice, validate=100 reads 32 s and
31 s** — 894 re-captures for 2-3 s, ~9 % of the leg.

**2. Neither generated row has ever verified its corpus.** Both
regenerate 19,556 cases every run and grade them with no check beyond
`count > 0`. Each run now still generates its own private corpus and
adopts a shared generation **only if `diff -rq` finds all 19,556 files
byte-identical** — 1.2 s including the generation.

**And that is the second instance in two days, in the same two files, of
a CORPUS-SIZED QUANTITY TRUSTED ON A COUNT — where the first fix is what
made the second visible.** #3264 found `ls | wc -l` blowing ARG_MAX and
`cross of 0 cases` sitting in a gate row's headline; `w-gateperf`
replaced it with a *positively checked* `total_cases -eq 0`, which is
strictly better and **is still a count**. A count cannot see a corpus
short by one case, long by one, or **one byte different at the same name
and the same count** — and the third is the only one that would silently
change what the gate grades. **When the thing being checked is a corpus,
the check has to be corpus-shaped.** It costs 1.2 s, which is the whole
reason the weaker check survived: nobody had priced the stronger one.

`gate.sh --selftest` 170 -> **183 cases, 0 failed**. Ten of the thirteen
new arms construct a WRONG shared generation — short, long, one byte
tampered at the same name and count, unwritable root, ungenerable tree —
and require a REFUSAL and a cold private fallback.

THE QUESTION, AND THE MEASUREMENT
---------------------------------
`w-gateperf` §11.1 declined worktree-independent case directories and
said, in its own words, that the decline rested on REASONING about the
lock's cold fallback and not on a measurement. This lane measured it.

  * `scripts/sweep_gen.py` writes all 19,556 cases in **0.65 s**.
  * `scripts/mode_cross.sh` takes its case-directory lock before that
    generation and releases it in an EXIT trap, so it holds it for the
    **entire run — 29 s warm, 347 s cold**. The exposure window is ~500x
    the hazard window.

Driven, both arms, N launched simultaneously, 3,000-cell stride, every
run printing `checked=2939 mismatches=0 graded=2919 ungraded=20`:

  naive  (one MUTABLE shared dir — the arrangement that was declined)
         N=2 -> FALLBACKS 1 of 2 · N=3 -> 2 of 3 · N=4 -> 3 of 4
  shared (content-addressed, IMMUTABLE, no lock)
         N=2/3/4 -> FALLBACKS **0 of N**

and at N=4 three of the four runs LOST the per-worktree lock and were
warm anyway. The lock is untouched and still fires; what changed is that
losing it no longer costs anything.

**`w-gateperf`'s inference was correct and its premise was replaceable.**
It priced a MUTABLE corpus, and on that premise the trade really is bad —
priced out, the naive share is a PERMANENT 3 x 347 s tax where
per-worktree pays 4 x 347 s ONCE. The prerequisite it named ("the
regeneration made non-destructive first") was the right one; the cheaper
form of it is immutability.

WHAT THE IDENTITY DIFF ESTABLISHES, AND WHAT IT DOES NOT
---------------------------------------------------------
`docs/rungs/README.md` gained a section mid-lane (de269b644) naming the
exact evidence this rung leans on: *"a required-zero identity diff [is]
compatible with a rule that is wrong about c2 four times in ten."* It
applies. The 25-row byte-identical block establishes **reach** — the same
19,556 cases reached the same 18 lanes for the same 90,424 graded cells —
and reach is what a faster gate has to hold constant. It establishes
**nothing** about whether the gate can still SEE a wrong emit through a
shared, cached oracle: a run that had quietly stopped grading would print
an identical block if it also stopped counting. **That question is
answered by the injection and only by the injection.** The identity diff
is the coverage claim; the injection is the correctness claim; this lane
would have been unsound with either alone.
