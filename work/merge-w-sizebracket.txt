1. THE FINDING THAT OUTLIVES THIS FENCE — put where it cannot be missed
================================================================================

  **A predicate can be 39.6% wrong about c2 and FREE in the metric used to
  choose it.** `fnbyte-exact Δ = 0` is evidence about a predicate's REACH,
  never its CORRECTNESS — the population where it errs is refused for other
  reasons today, which is #876-#879's latent hazard rather than its absence.
  **And split-half replication CANNOT detect this, because both halves share
  the blind spot.**

That sentence indicts a validation this project has been treating as strong.
`w-dataseam` §6.2 split the 878-TU workload odd/even, held each half out for the
other, and got ZERO `fnbyte-exact` cost on both with effect sizes agreeing to
ONE body (-414 vs -415). It reads as out-of-sample confirmation. It is blind by
construction: the edges where the predicate is wrong are refused for unrelated
reasons in *both* halves, so no partition of the corpus can surface them.

WHAT CAUGHT IT was scoring the predicate against real `c2.dll` instead — GRID-S,
`w-fence2` GRID-W's observable (does the reference caller's REL24 name the
callee?) over **7,667 workload call edges, 0 `unknown`**:

    cut 128   wrong 4,987 / 7,667 = 65.0%
    cut 180   wrong 3,037 / 7,667 = 39.6%   <- w-dataseam's lower end
    cut 192   wrong 2,892 / 7,667 = 37.7%
    cut 224   wrong 2,091 / 7,667 = 27.3%
    cut 231   wrong 1,610 / 7,667 = 21.0%   <- w-dataseam's upper end

**3,036 of the 3,037 errors at cut 180 are in the UNSOUND direction** —
asserting c2 kept a call it in fact inlined, which is the wrong-obj direction.
At a metric delta of exactly zero.

The instrument that does this is cheap and already existed: GRID-W built it in
68 lines, this lane re-used it in 274. **Every lane pricing a predicate should
score it against the oracle's own per-edge verdict before quoting a zero-cost
result as validation.**

SCOPING, STATED RATHER THAN SMUGGLED: GRID-S grades every IL call edge to a
defined-here callee. `w-dataseam`'s rule fires on a SUBSET (it also requires
`∉ tu_modelled_callees` and `cflow_key ≠ eh-state1`; realized reach 2,875
bodies), so 39.6% is the cut's error rate AS A SIZE AXIS, not necessarily inside
the fence's conjunction. Unaffected by that: the mechanism is unconditional and
demonstrated on constructed source; the DIRECTION is 3,036 of 3,037 and a
conjunction can only remove edges, never flip a verdict; and the two units are
compared on IDENTICAL edges.

3. `[sym+0x50]` — THE RESULT A FUTURE LANE WILL MOST NEED, STATED AS THE REASON
   THE AXIS CANNOT CARRY THE RULE
================================================================================

The operand of c2's inline size test is the **`.gl` FUNCTION RECORD'S `SIZE`
FIELD, read verbatim** — the field the port **already walks past** to reach
`FN_FLAG_INLINABLE`. There is exactly ONE 16-bit store to `[reg+0x50]` in the
whole image, `0x10b9bf6c`, inside `FUN_10b9b8e9`, which `ADDR.tsv` ALREADY
labelled "p2symtab .gl record reader; reads the emit flag word +0x4c at
0x10b9bf70" — the same three instructions, written down from the other side
before anyone looked for this one. Source: `0x10c1f9a6`, `il-read-varint16`.
Field order matches `gl_function_attrs`' own record comment exactly.

**AND IT IS AN UPPER BOUND, NOT THE TESTED VALUE. That is the reason the axis
cannot carry the rule — not a caveat on it.**

`arith_012_O1` and `mix_008_O1` share `.gl SIZE = 115`, differ by 12 bytes of
`.ex`, and c2 **INLINES THE LARGER IL BODY AND KEEPS THE SMALLER** — narrating
both from the identical source line `int caller(int a) { return callee(a) + 7; }`
in its own `/FAsc` listing:

    arith_012_O1   lis/lis/ori/ori/mullw/subf/blr    -- twelve statements
                   no bl, no relocation, no .pdata      collapsed to two
                                                        constants and a mullw
    mix_008_O1     mflr/stw/stwu/.endprolog
                   bl ?callee@@YAHH@Z               -- KEPT, plus a COMDAT
                   ...                                 .pdata record

Confirmed independently in the obj: nrel=0 against nrel=1 REL24 -> ?callee.

Folding reduces the count before the inliner looks. So the ONLY sound
implication is

    .gl SIZE < T  =>  c2 INLINED it        (0 counterexamples over 100 cells;
                                            /O1 T=98, /Ox T=122)

which is **the OPPOSITE direction from the exemption a size fence needs**. The
converse — "SIZE large => c2 kept it" — has 14 counterexamples at /O1 and 20 at
/Ox. The axis is closed, not narrowed.

Corollary worth keeping: the best axis this lane found, `.gl SIZE >= 96`, is
**0-for-330 on the workload** (three orders of magnitude better than the IL axis
on the same edges) and is killed by a three-line `.cpp` written IN THE SAME
LANE, BEFORE THE RULE WAS PROPOSED. #1148's lesson, one step earlier than #1148
got to it.
