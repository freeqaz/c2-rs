## 0. What this lane was asked and what it found

The campaign asked: how does c2 lower a counted loop — when is `mtctr`/`bdnz`
chosen, where does the `cmpwi cr6` zero-trip guard come from, how does the
induction rewrite work, and what is the class boundary in port terms.

The answer that reorganises the question is that **there is no "counted loop
lowering"**. There are three passes, they run in three different translation
units, two of them have their own documented disable switch, and the objs
separate them cleanly:

| pass | TU | switch |
|---|---|---|
| rotation + the zero-trip guard | `p2\lur.c` | `-NoLUR` |
| the `mtctr`/`bdnz` conversion | **`p2\ppc\lower.c`** (`FUN_10c0f7f9` @ `0x10c0f7f9`) | `-QXnobdnz` |
| the `lwzu`/`stwu` update form | **`p2\misc.c`** — machine-**in**dependent (`FUN_10b84869` @ `0x10b84869`) | `-QXnopreinc` |

Recompiling the same 36-cell grid with `/d2QXnobdnz` removes **all 29 `bdnz`**
and leaves every guard and every update form byte-identical; with
`/d2QXnopreinc` it removes **all 28 update forms** and leaves all 29 `bdnz`
byte-identical. Both were frozen predictions and both hit exactly. That is the
option→pass link confirmed against real objs, and it is why the class can be
built and graded in three increments instead of one.

## 3. Results

* **The `mtctr` choice: RC0' 34/36.** RC1 ("exits do not matter") refuted on 4
  cells, RC2 ("constant trip count") on 27, RC3 ("always") and RC4 (late
  peephole) on 10 each, RC5 ("no call in the body" — the one-clause rule) on 6.
* **The guard: 7/7, and it is not a `> 0` test.** The guard is `lur.c`'s
  **rotated pre-test**: it compares the loop's *start* against its *bound* in
  the loop's own signedness in `cr6`. `for (i=3; i<n; ++i)` guards with
  `cmpwi 6,r4,3`; `for (i=0; i<=n; ++i)` branches on **LT**;
  `for (unsigned i=1; i<n; ++i)` guards with `cmplwi 6,r4,1`. Four different
  branch conditions out of one rule. Omitted when the pre-test is a
  compile-time truth. Realised as a conditional `bclr` when the loop is the
  function's tail.
* **The update form: no rival won**, and that is the result. The frozen rule
  and RU2 both score 8/10 with *disjoint* failures. The replacement (RU-H) is
  filed as an explicitly **unfrozen hypothesis** for the next lane's grid, not
  as a finding.
* **The base-difference rule is the biggest scratch.** With ≥2 arrays at the
  same byte stride, c2 keeps **one** walking pointer and reaches the rest with
  `lwzx` at a `sub`-computed base difference — one live pointer, not N. When
  the strides differ the trick is inapplicable and two induction variables
  survive: cell `c3` (`int` + `char`) emits a real `lwzu` walk **and** an
  `lbzx`+index in one loop, exactly as frozen.

### 3.1 The cell of the lane

`a5` is a nested loop whose **inner** loop has a `break`. Every rival except
RC0' predicted the inner loop takes `ctr` (or that both do, or neither). RC0'
predicted, in advance, that the **outer** loop takes it — because
`FUN_10c0f7f9` recurses innermost-first and `FUN_10c0d3fe` only refuses when
CTR is actually occupied, so a disqualified inner loop *leaves CTR free for its
parent*. The obj:

```
    cmpwi 6,r4,0 / bf 25 / mtctr r4        ; the OUTER loop
      … cmpw 6,r11,r5 / bt 24              ; the INNER loop, compare-and-branch
    bdnz .-48                              ; the OUTER latch
```

"The inner loop gets `ctr`" is refuted as a rule. It is a resource rule.

## 4. Retractions

**WB-D's, on its behalf.** `WB_REGALLOC_FINDINGS.md` §9.3 nominates the counted
`for` loop as the first class-conversion candidate *because* its normal form was
"**identical across three different bodies** (L1, L2, L3 share `cmpwi cr6`
guard / `addi ptr,-4` / `mtctr` / `lwzu` / `bdnz`)". **L3 does not share it.**
L3's body makes a call, and a call's clobber set contains CTR, so c2 emits
`addic. r31,r31,-1` / `bf 2` instead — no `mtctr`, no `bdnz`. WB-D's own §7.2
row F5 graded only L1, so its grid never checked the sentence. The conclusion
survives (a two-witness shape that this lane then reproduced on 28 more cells is
still a class) but the stated evidence was wrong.

**This lane's own.** The frozen update-fold clause RU0'-b — "fold the `addi`
into the pointer's last access iff every other use is a D-form access" — is
refuted by `c9` (`a[i] + a[i+1]`) and `c10`: two and three D-form accesses on
one walker and c2 emits **no** update form, keeping a second incremented
register instead. Retracted, not hedged.

**Two misses that the reading covered and the lane did not.** A **64-bit
counter** (`a9`) and a **computed bound** (`a10`) both defeat the conversion.
`FUN_10c0f7f9`'s clause R3 requires the compare's type to map through table
`0x10b18990` to size 4 or 2, and clause R4 requires the bound to be a symbol
with zero displacement — so both cells were predicted by the disassembly and
mis-predicted by me. Scored MISS and **not** re-scored in the rule's favour,
per WB-D §7.3's precedent.

## 5. The block-order question WB-D left open

WB-D §9.2 item 3 recorded that M1 emitted blocks in source order and M2 in
reverse, "both from the same compiler on the same day", and left it open. **The
contradiction is not one.**

* A `switch` lowered to a **decision tree** emits its arms in **reverse** source
  order (`d5` — confirming M2 as a rule).
* A `switch` lowered to a **jump table** emits them in **source** order (`a7` —
  12 dense cases, `lbzx` index table and `bctr`; the control WB-D did not have).
* Everything else is source order — `if`/`else`/`else-if`, sequential loops,
  nested loops, dominating early returns.
* **One new exception**: a block reachable only as an exit from *inside* a loop
  body is **sunk past the function's normal return** (`a1`). That was a frozen
  miss and it is the more useful of the two.

For the `loop_counted` class specifically the order rule is now complete,
because the class excludes switches.

## 6. What a `loop_counted` class needs beyond WB-D's register rule

WB-D said "yes for registers, no for selection and block order". This lane
converts two of the three "no"s and finds a fourth requirement nobody listed:

1. **the loop normal form — YES**, and it is three composable rules, so a port
   can ship guard + `bdnz` first and be byte-correct on every loop where the
   update form does not apply (any body with an `if`, any 1-byte stride, any
   two same-stride arrays, any pointer with two distinct displacements);
2. **block order — PARTLY YES**, §5, complete for this class;
3. **the operator pattern set — STILL NO**, and now the only "no": within a
   converted loop every body word in all 36 cells was a plain one-to-one
   lowering, so the idiom library bites on value-producing comparisons, not on
   arithmetic;
4. **NEW — the trip-count arithmetic** for a non-unit step (`addi -1`, then
   `srwi` for a power of two or `divwu` for 3, then `addi +1`) is unread, which
   is why an honest first class should require step ∈ {+1, −1}.

WB-D's register rule held on all 36 cells and was needed by none of them:
selection → order → registers, again.
