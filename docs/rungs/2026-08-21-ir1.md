## 0. What this lane is, in one paragraph

The census and the gate answered "what is this function's name" through **two
different bindings** in `crates/c2-il/src/func/bind.rs`. The gate bound **per
record** (`Bindings::per_record` → `gl::gl_bound_names`): it walks the `.gl`
function records, reads each one's body-start offset, and pairs a name to a
segment only when the record set binds **1:1** onto the split points, `??`-names
included. The census bound **positionally** (`Bindings::positional` →
`gl::mangled_names`): a narrow scan of every `?…@@…` name in file order, with
`paired` decided on **count alone** and body offsets ignored. `mangled_names`
cannot see a `??`-prefixed name and cannot tell a data symbol from a function,
so on any TU whose name-scan count happened to equal the segment count it **slid
pairing by one** and attached a wrong-but-green name to an emitted census row.
The compiler cannot grade a name (`docs/GAPS.md` §8), so the slide was invisible
in the byte judge and visible only in the gap metric that measures it. This lane
**deletes `positional`** and routes the census through the gate's binding.

## 1. What shipped

**One binding, two totality policies.** `Bindings::positional` is deleted.
`Bindings::census` replaces it: it is `per_record`'s exact, `??`-aware,
offset-checked pairing **made total** — where the records do not bind 1:1 it
returns an *unpaired* binding with **empty names** instead of `per_record`'s
`None`. So the census stays infallible (it must classify every segment) while
binding the **same way** the gate does. `census` takes the segment `starts`
`per_record` already takes, and computes `paired = bound.len() == segs.len() &&
offsets == starts` — the gate's own predicate.

**The callers.** `census.rs`'s `census_functions` and the locals-only probe in
`diag.rs` move from `Bindings::positional` to `Bindings::census`. The **emit
path** (`IlBundle::functions`, via `Bindings::per_record` / `Bindings::selective`)
never touched `positional` and is unchanged — which is why the obj byte delta is
zero by construction and confirmed by the gate.

**What the census now reports for a name.** `FnCensus::name` is
`bind.reported_name(i)` — `Some` only when the TU binds 1:1, `None` otherwise;
`name_for_shape(i)` (fed to `shape_to_function`, reaching only
`IlFunction::mangled_name`, which the census never emits from) is the bound name
when paired and `""` when not. The name-derived varargs refusal
(`is_varargs(i)`) already gated on `paired`, so it now fires on the gate's paired
population rather than the positional-count one. `emit_name` (the THIRD binding,
`EmitBinding`, containment-based) is untouched and still names the broad emitted
population.

**Tests.** The pinned-apart seam test
`the_two_bindings_are_the_open_seam_and_are_pinned_apart` — which asserted the
two bindings **disagree** on the `il_gl_record_order.cpp` `??`-layout and existed
to fail "the day roadmap #14 lands" — is rewritten as
`the_two_bindings_agree_after_the_ir1_consolidation`: `per_record.names() ==
census.names()`, and the census reports the CORRECT `??__Egs@@YAXXZ` for the
thunk rather than the slid `?w_add@@YAHH@Z`. Two census unit fixtures that relied
on the loose name-scan are updated: `census_classifies_each_function_
independently` (renamed field assertion) now asserts the **honest `None`** on a
minimal TU that carries only token records and no body-offset records — the same
answer the real workload's unpaired TUs get — while
`a_body_the_ladder_never_ran_for_reads_disp_not_run` gains the body-offset
records a real TU carries, so it still binds and exercises the name-derived
varargs refusal it was written to test. `bind.rs`'s
`census_is_unpaired_and_nameless_when_the_records_do_not_bind_one_to_one` pins
that an unpaired census binding feeds `""` and no name, deleting the positional
slide's behaviour in a unit.

## 5. The published numerator move — `fnbyte-name-disagree` 74,033 → 0

**Workload stamp:** `c2rs gap --list work/dc3-workload/files.txt --flags-file
work/dc3-workload/flags.txt --cwd ../dc3-decomp --replay-every 1`, 878 TUs, 24
flags, workload `dc3-decomp 2f666acc8aa2 (clean)`, cl.exe `16.00.11886.00` under
`wibo 1.2.0-c2rs.1`. Base `work/ir1/base_metrics.txt` (c7049bac1), tip
`work/ir1/tip_scan.out` (74df5c50d).

A full `diff` of the GAP-METRICS block (484 `gap-metric` lines) between base and
tip returns **exactly one changed line**:

```
< gap-metric fnbyte-name-disagree 74033
> gap-metric fnbyte-name-disagree 0
```

`fnbyte-name-disagree` counts emitted census rows whose per-record
`IlFunction::mangled_name` is non-empty **and disagrees** with the emit binding's
`emit_name`. At base the positional slide put a name on 74,033 rows that the emit
binding named differently — 74,033 wrong-but-green name attachments the byte
judge could never see. At tip it is **0**.

**The move splits (measured with a temporary counter over the same scan, then
reverted):** of the emitted census rows,
- **44** now carry a per-record name (their TU binds 1:1) and **every one agrees**
  with the emit binding — so the metric is a *real* zero, not a vacuous one: 44
  comparable non-empty names, 0 disagreements;
- **336,353** carry **no** per-record name because their TU does not bind 1:1
  (`src/App.cpp`: 3,752 records against 9,033 segments) — honest residue, the
  positional slide's wrong name replaced by silence.

So the 74,033 disagreements are retired not by re-pairing them all to correct
names (only 44 emitted rows bind 1:1) but by the census **declining to name**
what it cannot bind — exactly what deleting the slide means.

**Everything the goal is written in is unmoved:** `match 26`, `mismatch 0`,
`fnbyte-exact 35894`, EMITTED CENSUS `39344/162147 (24.26%)`, and every other one
of the 483 remaining gap-metrics is byte-identical base vs tip. The obj byte
delta is zero.

## 7. What this lane deliberately did NOT do

- **It did not touch the emit path.** `EmitBinding` (the THIRD binding) and
  `per_record`/`selective` on the gate are unchanged; the consolidation is of the
  two *name* bindings only.
- **It did not chase the residue.** That 336,353 emitted rows carry no per-record
  name is the honest state of a strict 1:1 binding on a workload whose TUs mostly
  do not bind 1:1 — the same reason the gate's `match` is 26. Widening the census
  binding to name more rows would be re-introducing a looser scan under a new
  name; the brief forbids it and `docs/GAPS.md` §6 prices it.
- **It did not absorb the numerator.** The 74,033 → 0 move is the published
  deliverable of this rung, board #3347.
