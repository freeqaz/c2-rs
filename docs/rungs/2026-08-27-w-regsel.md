## 2. The finding, before the machinery

**Board `#543` — *"`r12` is never used (recorded, not explained)"* — is
explained, and the explanation had been sitting in this repo's own whitebox
record since `wb-regalloc` ran.**

`WB_REGALLOC_FINDINGS.md` §3.1 transcribes three zero-terminated arrays of c2
register indices. Decoded through the name table at `0x10b181c0` (where the
index *is* c2's register number, so `ppc = c2_index − 1` over the whole GPR
file), the default order at `0x10c37de0` is

```
r11 r10 r9 r8 r7 r6 r5 r4 r3   r31 r30 r29 … r15 r14
```

**c2 index `13` — `r12` — is in none of the three arrays. Neither are `r13`,
`r0`, `sp` or `toc`.** `r12` was never *reserved*; it was never in the list.

The port recorded that fact twice, as two independent copies of the same fitted
literal:

* `codegen::alloc::POOL_TOP = 11`, comment *"`r12` is never allocated (board
  #543)"*;
* `codegen::select::SCRATCH_REG = 11`, **124 use sites**, comment *"r12 is
  reserved; COLOR picks r11 next"* — of which the first clause is `#543` stated
  backwards and the second is right.

Both are now `regalloc::GPR_DEFAULT.regs[0]`, one expression over one array, so
they cannot drift and the planted-order controls reach all 124 sites. Board
`#3695`.

## 3. What was built

### 3.1 `codegen::regalloc::select` — `0x10b2e7f8`

`P_REGALLOC.md` §3 step 5, transcribed:

```rust
for &r in order.regs {
    if !allowed.contains(r) { continue; }
    match best {
        None                     => best = Some((r, cost.get(r))),
        Some((_, bc)) if c < bc  => best = Some((r, c)),   // STRICT
        Some(_)                  => {}
    }
}
```

The strict `<` is the whole `[O]` claim — it is what sends a tie to the
**earliest** entry of the order — and control C3 plants `<=` and watches 22
tests go red.

Around it: `RegSet` (the candidate's allowed set, c2's `cand+0x20`, where
*"allocation only ever removes"*), `Costs` (the array at `0x10c435e8`), and
`select_sequence`, which is c2's driver loop collapsed to the one shape the
port reaches — *n* mutually-interfering candidates over one allowed set, each
colouring removing what it took.

### 3.2 The parameter

`ORDERS` holds four named orders — `gpr-default` (`0x10c37de0`),
`gpr-qgprreserve` (`0x10c37e50`), `gpr-pogo` (`0x10c37eb8`) and `fpr-default`
(`0x10c37f20`). Index 0 is the default and **reproduces c2 byte-exactly**;
every other entry is an instrument state and licenses no emit, pinned by a test
that scans the crate and fails if a non-default name appears in a production
line.

They are **decoded**, not transcribed twice: `C2_GPR_DEFAULT` holds c2's own
index numbers and `map_gpr` is a `const fn` that applies `0x10b181c0`'s
mapping. A transcription error can therefore be found by reading one array
against one document, rather than by reading two lists against each other.

The FPR order is `[R]` with **no obj cell in existence at all**
(`P_REGALLOC.md` §7). It is marked so at its site and held here for lane
`w-regcells`, whose deliverable closing that cell is.

### 3.3 The cost fence, and why it is executable rather than a paragraph

Decision 20 §3 and `P_REGALLOC.md` §3's correction box: on all 10 cells of
`wb-live`'s grid and all 15 of `wb-regalloc`'s, **every cost array is uniformly
zero over its allowed set**, so no obj this project can build separates a cost
model from list order. **This lane confirmed nothing about the cost model and
its module says so at the top.**

The fence is a test. `the_only_cost_array_the_port_constructs_is_zero_and_the_call_sites_are_enumerated`
walks every `.rs` under `crates/c2-core/src` — excluding `regalloc.rs` itself,
because a control that greps for a token it must contain to do the grepping
cannot pass — and requires every mention of the type to be `Costs::ZERO`, with
the call sites enumerated at 2.

`Costs::ZERO` is marked `PROV[R]`, **not `[O]`**, and the reason is in the
mark: 25 cells establish that every array they saw was *uniform over its
allowed set*, which is consistent with zero and does not pin it — a uniform
non-zero array selects identically. Board `#3697`.

### 3.4 The re-expression

`alloc::allocate`'s two hand-rolled guards and two hand-rolled subtractions

```rust
if pool_floor > POOL_TOP { return None }                 // the cap
if (POOL_TOP - pool_floor + 1) < len { return None }     // the pool
.map(|(i, p)| (p.id, POOL_TOP - i as u8))                // the walk
```

become one `select_sequence` call over the volatiles with `Costs::ZERO`. The
allowed set runs up to `r12` (`VOLATILE_GPR_TOP`, `PROV[S]` PPC EABI) and
`r12`'s exclusion is c2's order's, not the port's.

## 6. What contradicts the brief — the part worth reading

### 6.1 *"the already byte-exact classes' register choices"* is a population of one

`docs/REGALLOC_BRIEF_2026-08-27.md` §3 and decision 20 §1 both say to
*"re-express the already byte-exact classes' register choices"*, plural.
Enumerated on this tree, **the port makes a register choice — a selection among
alternatives — in exactly one function**, `codegen::alloc::allocate`.
Everything else is ABI-fixed (`ARG_REGS = [3..10]`, `RET_REG = 3`) or a frame
constant, and `SCRATCH_REG` turned out to be the *same* choice's answer copied
to 124 sites rather than a second choice.

This does not damage the deliverable — one production call site is enough to
make the required-zero criterion bite, and it did. It corrects what the phrase
advertised.

### 6.2 **27 entries are executable; 3 are exercised by an emitted byte**

The order has **27** entries. Production reaches the first **three** — `r11`,
`r10`, `r9` — and no more, because `MAX_MODELLED_PRODUCERS` is 3 and the
allowed set is capped at the volatiles.
`only_the_first_three_entries_of_the_order_are_reachable_from_an_emitted_byte`
pins it, with the 27 as its denominator.

**11.1 %.** *"Executable"* and *"exercised"* are different numbers here and
must not be quoted for each other. Closing the gap is not this lane's: it is
`#541` (raise `MAX_MODELLED_PRODUCERS`) and the callee-saved tail, which needs
a spill regime the port does not have.

The corollary for `#3692`'s headline — *"a well-read algorithm has never been
written down as code"* — is that it is **still roughly true**. What is written
down is the selector, one of the seven boxes in `P_REGALLOC` §1's pipeline.
Board `#3699`.

### 6.3 And one thing the prereg did not predict

The old supply guard, `POOL_TOP - pool_floor + 1`, **counted `r0`, `sp` and
`toc` as allocatable** at `pool_floor < 3` — twelve registers where the read
says nine. It is unreachable today only because `MAX_MODELLED_PRODUCERS` is 3,
and `#541` is the open item that would raise it. Found by the fail-axis grid,
removed by the re-expression, pinned by
`the_old_pool_arithmetic_counted_three_registers_c2_never_allocates` at exactly
`[(0,12,9), (1,11,9), (2,10,9)]`. Board `#3698`.
