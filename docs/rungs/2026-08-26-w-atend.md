## 2. The question, and why the answer had to be read before it was designed

Decision 14 gives this lane one question — *"can the admission layer own a
refusal reason at all?"* — with `declined` named in advance as a legitimate
answer. My brief's step 1 was **establish the fact before designing anything**,
and it is the whole reason this rung says `built` rather than `declined`: the
fact was already in the tree, in two places, and neither needed a probe.

Board **#3556** (`w-unfuse`, 2026-08-25) concluded:

> **THE ADMISSION LAYER CANNOT OWN A REFUSAL *REASON*** — a `Block` says where
> the READ stopped, and a policy that refuses a body the decode read whole has
> no such point. Minting a `Block` for it publishes a `:eof` census key **no
> scan can ever reach**.
>
> …*"an admission verdict is a yes/no, and **every refusal KEY in this port
> belongs to the DECODE**."*

---

## 3. THE FINDING — the second sentence is false, and it is the one a future lane would act on

### 3.1 Reading (a): the key space already expresses it, and had 7 live sites

`Block::at_end` (`crates/c2-il/src/func/body/mod.rs:1601`) is documented as *"a
refusal raised **after the parse reached the end of the segment** — the
post-parse gates, which run only on a body that already parsed end to end"*. It
had **7** production sites at base, every one in `crates/c2-il/src/func/census.rs`
(lines 1446, 1450, 1500, 1516, 1528, 1594, 1684). Two of their constants
document themselves as admission predicates in as many words:

* **`OPT_MODE`** (`func/body/mod.rs:1145`) — *"a function whose body parses in
  class but whose optimization-settings word is not one this port emits under"*;
* **`CALLEE_DEFINED_IN_TU`** (`func/body/mod.rs:1199`) — *"the body parses in
  class, its callee resolves, and the TU DEFINES that callee, so c2 may inline
  it and **the port may not emit**"*.

Neither is a statement about where a read stopped. Both are refusal **reasons**
for bodies the decode read whole, both are census keys, and both are ranked.

### 3.2 Reading (b): a scan reaches them, and a peer had already sized the population

Board **#3582** (`w-decodereach`, the day before) measured
`decode-reach-grammar-not-admitted` = **4,001** over the 878-TU workload. **This
lane re-measured it independently on its own base scan and got the same digits**
(`work/w-atend/scan_base.log`), decomposed by the key each body publishes:

| census key | bodies |
|---|---:|
| `callee-unresolved-tail-call:eof` | 2,282 |
| `data-sym-unresolved:eof` | 1,665 |
| `data-sym-not-extern:eof` | 52 |
| `callee-defined-in-tu:eof` | 1 |
| `data-sym-strlit-fenced:eof` | 1 |

`admitted-not-grammar` is 0. So **4,001 bodies of a real workload are refused
after the decode read them end to end, under five keys a scan publishes and
ranks**, and *"every refusal key in this port belongs to the decode"* was false
of five keys and 4,001 bodies on the day it was written.

### 3.3 What DOES survive of `#3556`, and it is about the CALL SITES

`#3556` was right about the thing it actually built. `AdmissionPolicy::Nothing`'s
key **is** unreachable in production — measured here, not argued: the tip's own
878-TU row dump contains **0** `admission-declined` rows out of 2,417,794. But
the reason is that **no production call site passes a non-default policy**, not
that admission cannot name a reason. That is a property of the caller.

The tree already carries the counter-precedent for closing it. `Relax`
(`crates/c2-il/src/func/census.rs:94`) is a named, settable census parameter
whose **non-default** level is selected by production code
(`crates/c2-harness/src/gap/scan.rs:982`, `factors.rs:2430`) and whose numbers
are published (`fnbyte-blind-level|<name>`, `gap/blind.rs:446`). A policy sweep
of the same shape makes `admission-declined` exactly as reachable as those.

**And `#3582` gives the sharper reading of the same fact.** `w-decodereach`
describes the 4,001 as *"a THIRD layer … the census refuses them at
`shape_to_function`'s SYMBOL BINDING, **downstream of `AdmissionPolicy`**"*.
That is right, and it is the point rather than an objection: those refusals
answer *"may the port emit this body"* — they are the admission gate — and
`census.rs` and `IlBundle::functions` apply the identical predicates, which is
what `census/gate disagreement: 0` measures. **The admission gate is bigger than
the `AdmissionPolicy` type**, and every reason it already owns lives outside
that type. Peer lane `w-symbind` owns whether that layer separates; this rung
owes it the input that **the layer it is going to unfuse is already producing
named, scored, reachable admission refusal keys**, so an `AdmissionPolicy`
variant carrying those reasons has a place to put them.

### 3.4 What the second variant is, and the shape of the answer

`AdmissionPolicy::Nothing`, in `crates/c2-il/src/func/body/decode.rs`:

```rust
AdmissionPolicy::Nothing => match self.read {
    Err(b) => Err(b),                                              // the DECODE stopped
    Ok(_)  => Err(Block::at_end(self.seg, super::ADMISSION_DECLINED)),  // the POLICY refused
},
```

**The admission layer owns a reason for exactly the bodies it alone refuses.**
When the decode stopped, the reason was never admission's and the decode's own
`Block` is returned untouched — overwriting it would destroy the histogram that
ranks the roadmap, which is `OPT_MODE`'s own recorded reason for being applied
last. When the decode read the body whole, the policy is the only thing that
refused and it says so.

`:eof` is the **true** statement here, by `Block::seg_len`'s own rule
(`docs/GAPS.md`: *"`Block::at_end` … is sound because `eat_fn_tail` returns `Ok`
only at `p == seg.len()`, so an accepted body's cursor **is** the segment
end"*). The refusal is raised only on the `Ok` side, so the cursor reached the
end by construction and no second blocker hides behind the row.

**`#3556`'s API reading survives unchanged**: `is_admitted_under` is still a
`bool`. A *verdict* is a yes/no even when a *reason* exists beside it.

### 3.5 The 7 → 8 is a PARTITION, not a bump — the hazard #3556 named is kept as a number

`crates/c2-harness/tests/fence_site_census.rs` counted `Block::at_end(`
production sites and its message read *"Every one renders a `:eof` key a scan
reports, so one landing unscored is a published key nothing measured."* That
rationale was true of all 7 and is **not** true of all 8, and this lane's site
is the first one it is false of.

Taking the constant to a bare `8` would have hidden exactly that. So the
expectation is keyed on the **file**:

| file | sites | reachable by a scan? |
|---|---:|---|
| `crates/c2-il/src/func/census.rs` | **7** | yes — 4,001 workload bodies under five keys (§3.2) |
| `crates/c2-il/src/func/body/decode.rs` | **1** | **no** — instrument state, 0 rows in the tip's own dump |

…with `EXPECTED_AT_END_SITES_INSTRUMENT_ONLY = 1` asserted separately, so *"how
many published keys does nothing measure"* is a quantity on that page and not a
paragraph. A refactor that moved a fence from `census.rs` into `decode.rs` would
leave the total at 8 and be invisible to the old rule; it fails the new one.
That is this file's own header argument (*"a single integer is satisfied by any
change that adds one site and removes another"*) applied one axis over.

**The site is SCORED, which is what that file's failure message demands before a
row moves.** Three tests in `decode.rs` fail if it moves:
`the_admission_layer_owns_a_reason_only_where_it_alone_refused` pins the
rendered key `admission-declined:eof`, its offset, its `seg_len`, its
`byte: None` and its `Complete::is_whole`;
`the_yes_no_and_the_emitting_form_cannot_disagree_under_any_policy` sweeps every
policy; `all_is_complete_and_indexed` refuses a variant that is indexed but
unlisted.

### 3.6 Two-sided price, because a fence is never priced one-sided

`#1042`, NC-5/`#2691`. **What shipping the second variant costs:** one
`Block::at_end` site whose key no production scan reaches, i.e. one row of
`docs/STATUS.md` trap 0 installed deliberately — and that is why it is *counted*
rather than absorbed, and why the count is asserted in both directions.
**What NOT shipping it cost, which `#3556` did not price:** `AdmissionPolicy`
stays an enum with one value, so the DECISION-SURFACE CLAUSE is met in name and
not in effect, the permuter has no knob, and — the expensive part — the
tree's own doc comment tells the next lane that *"every refusal KEY in this port
belongs to the decode"*, which is false of five keys and 4,001 bodies. **A wrong
design input costs more than an unreachable key**, because the unreachable key
is measured (0 of 2,417,794) and the wrong input is not.

## 4. THE PROOF THE DIFF CAN FAIL

**A diff nobody has watched produce a nonzero is not a diff** (`#1236`). Two
controls, and the second is the one that matters.

### 4.1 Control A — the procedure, against a signature somebody else measured (P3: CONFIRMED)

`scripts/gate_identity_diff.sh --self-test`, the committed instrument `w-guard`
shipped for exactly this (`#3579`), which fabricates `#3515`'s measured
one-TU-refused signature and requires the procedure to find it:

```
  enumeration: 21 count-bearing rows (hatch-red/ladder-red dropped)
  control: a table against itself                      -> 0 lines, exit 0
  #3515's one-TU-refused signature                    -> 14 lines, 7 rows
  the signature case exits NONZERO
  a TRUNCATED table -> exit 2 (a short extraction is not 'no differences')
SELF-TEST PASS
```

**14 lines / 7 rows, exactly as registered.** `w-unfuse` produced this control
by hand-fabricating the mutation into a real gate run; the instrument that
lane's peer committed does the same thing without spending a gate, and this rung
uses it rather than retyping it — which is `#3451`'s whole point.

### 4.2 Control B — this lane's own seam (P4: **MISSED, twice, and the miss is the informative part**)

`#3346`'s question asked directly: a construct rung's zero byte delta is
evidence **only when the re-expression is on a path the gate exercises**.
`AdmissionPolicy::DEFAULT` was flipped `RecognizedShape` → `Nothing` — a
one-line mutation of this lane's own new arm — and gated with
`--allow-dirty-crates`. **The mutation was verified to have applied before the
case was scored** (`cmp` against a pre-mutation copy), because a `sed` that
matched nothing would leave a clean tree and test the control twice (`#3516`).

**32 diff lines = 16 rows moved:**

```

O1-EHsc         187 -> 22      Ox-EHsc         157 -> 21     O1-Oi-EHsc-GR   189 -> 22
O1-Oi           188 -> 21      Ox-Gy           157 -> 21     Ox-GR           157 -> 21
O1-Oi-EHsc      189 -> 22      Ox-Gy-EHsc      157 -> 21     Ox-EHsc-GR      157 -> 21
                               O2              163 -> 21
                               O2-EHsc         163 -> 21     debug-lane     2479 -> 381
                                                             expr-sweep    19460 -> 19455
```

`Od`, `Od-EHsc`, `Od-GR`, `Od-EHsc-GR` **unmoved at 21**; `mode-cross`
**unmoved at 90,424**. **`debug-lane` 381 is exactly the sum of the 18
mode-lane match counts** — computed from the table, not asserted: at the tip
they sum to **2,479** and under the control to **381**, matching each run's
`debug-lane` digit for digit. So this is one internally consistent observation
and not two.

**So `into_admit` is on a path the gate exercises, and the seam is real.**

**Both of P4's registered numbers are MISSES, and both are worth more than the
hit would have been:**

* *"≥ 18 of the 21 rows move"* — **16 moved**, and 15 of those 16 are the
  mutation's (14 mode lanes + `debug-lane`). The four `/Od` lanes could not
  move, for a reason the mutation itself demonstrates (next bullet), and
  `mode-cross` grades a *count* that a refusal does not change.
* *"every mode lane's `match` goes to 0"* — **it goes to 21 or 22, never 0.**
  With the port admitting **no function body at all**, 21 fixtures still match
  byte-exactly. Those are the TUs that need no admitted body — the
  functionless/data-only path (`emit_data_obj`) and the whole-TU recognizers.
  **The `/Od` lanes were already sitting at exactly that floor**, which is why
  they did not move at all, and it is why the collapse lands on 21 rather than
  on 0. `21` is a quantity this control measured by accident and it is the size
  of the port's *body-free* match set at the fixture gate.

**And one of the 16 rows is NOT the mutation, which the signature says out
loud.** `expr-sweep` **19,460 → 19,455** and `PASS → FAIL`, with the run's own
prose reading *"19455 GRADED by the oracle (**101 ungraded: no reference obj**)"*
against the tip's **96**. The deltas reconcile exactly — 5 fewer matched, 5 more
ungraded — and the failures are `capture_reference produced no obj … cache=miss`
on a box carrying four lanes. **That is the reference side losing captures, not
the port changing a verdict**: a mutation that turns emits into refusals cannot
move what the *oracle* graded, and `mismatch` is **0** in every lane, the sweep,
and the cross under the control, which is `PROGRESS_METRIC.md`'s ordering
holding under an ablation designed to break everything.

`GATE: FAIL — expr-sweep failed` at `GATE_EXIT=1`, graded tree
**`5a6063899633` at both ends** with **no movement line** — the run is evidence
about one tree, which is the condition `w-unfuse` lost its first control-B run
to. **No `crates/` file was touched while either gate was running**, and the
revert is verified at the byte level rather than textually: rebuilding after it
reproduces the tip binary's md5 `cc3649c43330e92bd82cef3bb668a08d` exactly.

## 5. The cost clause — the three axes named in §0.6, measured

### 5.1 Axis 1 — a published key nothing measures

The hazard, as a number: **0 `admission-declined` rows out of 2,417,794** in the
tip's own 878-TU dump, and `EXPECTED_AT_END_SITES_INSTRUMENT_ONLY = 1` asserted
on the guard page beside the 8. Both directions matter — the constant fails if
the number rises *or* falls, because a fall means a production caller started
selecting a non-default policy and that caller owes its own price.

### 5.2 Axis 2 — the denominators

* `gap-metric` keys: **537 at base, 537 at tip, diff 0 lines**. Both printed,
  because a zero difference between two empty sets is this project's
  most-repeated defect.
* Per-key fence census: `(20, 23)` → `(21, 24)` — exactly `(+1, +1)`, the one
  key at the one raise site.
* Per-symbol rows: **2,417,794 both arms**, with the two-sided split printed
  (152,950 EMITTED / 2,264,844 not).
* The whole scan report: **0 diff lines over 1,357**.

### 5.3 Axis 3 — the census-key population

Every one of the 2,417,794 rows carries its census key, its `EMITTED` flag, its
mangled name, its frame class, `cflow`, `eh`, `dispatch`, `prod` and its
completeness reading. Sorted, both arms are **byte-identical** (md5
`fa3165870221cb012425bda6f9f1da88`), and `comm -3` is empty in **both**
directions. So no census key moved, no dispatch tag moved, no production tag
moved and no completeness reading moved, for any function in the workload.

Throughput is deliberately **not** claimed as an axis: the change is one `match`
arm on a `Copy` enum, and `#3551` measured this repo's build-to-build floor at
`F = 0.93 %` against `w-unfuse`'s within-arm scatter of 6–7 %. An instrument
that cannot resolve what the change could plausibly cost abstains rather than
passes, which is what `#3336` forbids calling evidence.

### 5.4 The workspace suite — and the one red, which is a PEER'S WORKTREE

`C2RS_REQUIRE_TOOLCHAIN=1 cargo test --workspace --release --no-fail-fast` at the

The failure is `wt_pin_audit.rs::no_worktree_holds_an_unlocked_pinned_artifact`:

## 7. What this lane did NOT do, on purpose

* **It widened nothing** — checked per symbol over 2,417,794 rows, not by
  subtracting totals. `AdmissionPolicy::DEFAULT` is unchanged and pinned, the
  `RecognizedShape` arm of both matches is **textually unchanged**, and no
  production call site references `Nothing` (grepped: every mention outside
  `decode.rs` is a doc comment).
* **It did not make the new key reachable.** Doing so needs a policy-sweeping
  instrument in `crates/c2-harness/src/gap/**`, which is peer lane `w-symbind`'s
  this wave. The fence is that a lane needing a peer's file stops and reports —
  and the shape it would take is written down in §3.3 so nobody re-derives it.
* **It did not touch the 4,001.** Those refusals stay exactly where they are;
  this lane only says what they *are*. Converting any of them would be a
  widening and is forbidden.
* **It did not lock or reap a peer's worktree** — §5.4.
* **It did not amend `#3556` on the board.** The row stands as written and is
  linked from the new rows; `#3591` records the refutation beside it rather than
  editing history. A dated record that turned out to be too broad, with the
  correction next to it, is worth more than a tidy row.
