### 2.3 DECLINED IN ADVANCE, WITH THE REASON

**Three sites are declined here, before measuring, because they are not producer
work at all — they are S1c (ii), which decision 8 did not dispatch:**

| site | why it is out of scope |
|---|---|
| `ptr_walk_loop_text` | Builds through `BodyLayout`; `producer_at(&run, …)` **decodes already-emitted bytes**, and `block_ir.rs::finish()` reads `text.len()` per block, appends placeholder branch words and **back-patches** them via `labels.resolve(&mut text)`. |
| `ptr_walk_chain_loop_text` | All of the above, plus explicit slicing of a built run (`let cut = 4 * (body_len - 1); … body_run[..cut] … body_run[cut..]`). |
| `int_tail_call_text` | **Its return type is a byte offset.** `base_off + text.len() as u32` is the REL24 relocation site, and its `select.rs` caller truncates 4 more bytes off the result. |

**The finding this registers, before the work rather than after:** these three
are *not* three producers. They share one root cause — `BodyLayout`,
`producer_at` and `LabelMap` speak `&[u8]` and `&mut Vec<u8>` — so converting
`block_ir.rs` unlocks all three at once and converting them one at a time is
strictly more expensive than the lane that does `block_ir`. **They should be
priced as part of S1c (ii), not as a residue of S1c (i).** If this lane's
survey is right, `w-s1bc` §6's split of the remainder into "12 producers" and "a
separate (ii)" mis-assigns three of the twelve.

**Registered consequence:** if I later find one of these three IS convertible
without touching `block_ir`, I report that this prereg's decline was wrong.

## 4. THE DECISION SURFACE — a stated NULL again, and why

`GOAL_DECISION_2026-08-21.md` § AMENDED requires a general layer to ship its
arbitrary choices as named, settable parameters.

**Registered before measuring: S1c (i)'s remainder exposes NO new parameter, and
that is a stated null rather than an omission.** The `mop_*` twins are the same
expression with `.word()` removed — there is no configuration in which a
different value reproduces c2, so a parameter would be a fake surface. The real
surface is `EncodeParams`, shipped by S1a, and this lane inherits it unchanged
and adds nothing. Producers likewise: an op stream is a *representation* change,
not a decision. **What S1c (i) buys is that `C2Op` survives to the producer
boundary**, which is what the goal's two named consumers need — not a knob.

## 5. CONTROLS, AND WHAT THEY CANNOT CATCH

Registered in advance:

1. **The `#[cfg(test)] mod incumbent` cross-check proves PRESERVATION, never
   correctness.** Two derivations wrong the same way agree. Only real `c2.dll`
   under wibo does the latter.
2. **The domain sweep is over the port's own encoders**, so an encoder that is
   wrong about c2 stays wrong and stays green.
3. **The gate exercises the shapes its fixtures contain.** `fnbyte-refused-parse`
   is ~70 % of the function population; no identity diff can see a defect in a
   shape the parser refuses.
4. **`hatch-red` is `REFUSED` at both ends** on #1389's `HATCH-STALE`,
   contributing 0 lines to every identity diff; per #1406 neither run
   establishes what a full run would.
5. **A required-zero byte delta is silent about everything that is not a byte**
   (#3336, demonstrated live by #3428). The evidence notes are a first-class
   deliverable under goal (1), so **the generator carries a doc-check that fails
   if any encoder's `///` block changes**, and I read the whole diff regardless.
   A generated post-check is not a substitute for reading it.
6. **A mutation that goes red proves the control is wired, not that it is
   sufficient.** The five mutations below are chosen to hit distinct
   signatures; a sixth defect class that none of them models is not thereby
   excluded.

## 6. SEQUENCING, and the freeze rule this lane inherits

`w-s1bc` §5.1 failed one armed run by writing its rung while the suite was in
flight. The corrected rule, adopted here:

> **The freeze during an evidence run covers every path an instrument in that
> run READS.** For `gate.sh` that is `crates fixtures scripts`; for the armed
> suite it additionally includes `docs/rungs/`.

Order: base gate (pristine) → prereg commit → T1 → T2 → T3 → §2.2 in order →
mutations → tip gate → armed suite on a fully frozen tree → **scan pair, both
binaries pinned, back to back** → rung + board, then a final armed re-run if
`docs/rungs/` moved after the last one.

**On the generator's own mortality:** `work/` is gitignored, so
`work/w-s1c2/mkmop.py` will vanish with this worktree exactly as its predecessor
did. This lane does **not** smuggle a tool into `scripts/` inside a required-zero
rung — that would add an unrelated diff to a lane whose whole claim is that its
diff is inert. It records the fact in the rung and prices the fix for whoever
owns lane tooling.
