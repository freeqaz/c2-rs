## What it admits, and what it refuses

`[globregs]`'s **set** half was read by `w-globarms` (`#3808`–`#3810`) and
expressed nowhere. This rung is that read as executable code, with the
arbitrary choices shipped as named parameters whose defaults reproduce c2 —
`rungs/README.md`'s DECISION-SURFACE CLAUSE, and goal (1)'s stated purpose for
this port.

| # | parameter | default = the read | c2 address |
|---|---|---|---|
| **P1** | `KindMap::table` — the 8-entry jump table indexed by the front end's 3-bit COFF linkage field `([gl+0x37]>>0x15)&7` | `NullSlot, Kind(4), StorageBits{8,7}, Kind(5), StorageKind, AliasBit, StorageBits{8,7}, StorageKind` | `0x10bd2a9f` |
| **P2** | the `.gl` kind chain | `2→4`, `3 (function) →0xb`, `4 (extern) and else →0xa` | `0x10bd2926` |
| **P3** | `GateA`'s seven kind bounds | sentinel `0x10`, temp `3`, reject `≤3`, autos `≤5`, reject `≤6`, COFF `≤8`, extern `!=0xa` | `0x10b5511a`–`0x10b5514e` |
| **P4** | `AliasingPolicy` — what sets `sym+0x05 & 2` | `EscapesToOpaqueCallee` | sole setter `FUN_10bd2db7` |
| **P5** | `TypeClassPolicy` — gate B's table and the kinds that reach it | not-promotable `{0x00,0x12,0x13,0x18,0x1d}`; gate-B kinds `{3,4,5,7,8}` | `0x10b18b28` |

**Two parameters for A6, which is what the brief asked for.** P4 takes a
`SymbolGroup`, not a `Symbol`, because the escape bit's sole setter walks the
**leader's `+0x0c` chain** — the same fact gate A's A3 arm is the other half
of. And it is **not** "address taken": `AliasingPolicy::AddressTaken` ships as
the **refuted rival** `gb_addr_local` killed.

**What it refuses, by name.** Linkage 0 → `MappedKind::Unreachable` (a NULL
table slot; c2 would jump to address 0, and the port refuses rather than
inventing a kind). A type class above `TYPE_CLASS_MAX` → `None` (not a value
the 13-entry nibble table can produce). Gate A's five reject arms and two skip
arms, each named. In the registered domain that is **988 refusals of 1,920
cells**.

**`w-globarms` §2.2's refutation is in the code, not only in the prose**:
`kinds_reaching_gate_b` is `{3,4,5,7,8}`, and a test asserts a kind-10 symbol
is admitted *even at a class gate B would reject* — the type gate is not on its
path.

**What it deliberately does not do.** No `ported` numerator (decision 21 §4,
`#3809`, `#3505`). No production caller — `PortC2::build` cannot reach it and
`this_module_has_no_production_caller` scans all 100+ crate sources to keep it
that way, permitting exactly two references, both from `surface.rs`'s registry
row. No register allocator. No new `gate.sh` row (`#3691`). No new read: every
address is `w-globarms`' or `w-globobj`'s, cited and not re-taken.

## Found and not taken

1. **THE BRIEF'S PREMISE IS WRONG AND IT IS A DISPATCH DEFECT, NOT A
   PREAMBLE.** Both the brief and `ROADMAP` §12.5 say this lane should do for
   the SET *"what is already done for the order"* / *"the way the order already
   is"*. **The order is not in the port either.** The mint/definition order is
   `[O]` exact 42/42 (`#3774`) and is expressed **nowhere** in `crates/` —
   `subsys.rs`:519-521 says so in its own words, *"the port does no global
   register promotion; there is no site to count. `P_GLOBREGS` §2's order and
   tie key are read but unadopted"* — and **none of the ten surfaces registered
   before this one is a `[globregs]` surface.** What is a settable *order* in
   the port is `regalloc.select`'s allocation array and `regalloc_worklist`'s
   comparator, and both belong to `[regalloc]`. `globregs.candidate_set` is
   `[globregs]`'s **first** decision point, built without a model to imitate.
   Board **#3831**.

2. **The mint ORDER is now the cheap follow-on, and it is one construct rung.**
   Everything it needs exists: the finding is `[O]` at 42/42 with seven rivals
   refuted and its rivals are named by cell count (`REVDEF` 46, `REVDECL` 32,
   `DECL` 24, `USE` 24, `LASTUSE` 24, `LIVELEN` 14, `USECOUNT` 6), the answer
   key is `work/w-globobj/GRADE.txt`, and this rung's fail-axis parser reads
   that file already. A `MintOrder` parameter with those seven as enumerable
   rivals would have **real** separating power on day one — which is exactly
   what four of this lane's seven rivals do not have.

3. **The read that would unlock the 46-cell promote grid: the C++-type → gate-B
   type-CLASS map.** `P_GLOBREGS` §3 gives the 30-byte class table; what is
   unread is the nibble resolution of a front-end type word through
   `0x10bd7c10` / `0x10bd7cf0`. Until it is read, **P5's separating power over
   every obj cell this project owns is zero** and `pc_int` … `pc_double` cannot
   grade the table entry by entry. This lane publishes that zero rather than
   letting "the default agrees with every cell" read as confirmation.

4. **E4's screen cannot see a boundary spelled as a struct FIELD** (board
   **#3834**). The only token it flagged here was a `const` holding a *mutant*
   whose name happened to contain `BOUND`; the five real boundaries are fields
   and are invisible to a name screen over `const` items. That is not a defect
   in E4 — its own doc says it is a ratchet on a hole, not a proof the hole is
   closed — but it is a design rule for every parameterised policy that
   follows: **the boundaries belong in a registered domain, because the const
   screen will never reach them.** The mutant became `GateA::with_auto_bound`,
   which is strictly better as a permuter entry point, and `UNCOVERED_RATCHET`
   stays at **8**.

5. **`gate.sh` prints its tree hash twice and nothing compares them** (board
   **#3835**). This lane's first base gate overlapped its own authoring and
   printed `a00a40351045 (808 files)` at the start and `24afdf51d441 (810
   files)` at the end. Declared void, kept unedited, re-taken on a detached
   checkout. The cheap fix is a one-line assertion the gate already has the
   data for; until then the rule is procedural — take the base before touching
   `crates/`, or take it detached.

6. **Not taken, deliberately: A10 and A12.** `w-globarms` §7 names both cells
   and this module models both conditional bits, so the parameters are in place
   — but neither is `[O]` and building the cells is a characterization lane's
   work, not a construct rung's. The port refuses at both, by name.
