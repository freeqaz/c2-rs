## 2. The defect

`scripts/expr_sweep.sh` reported `checked=14484 mismatches=1`. **Reproduced on
this tip before the fix**, by a full independent sweep run. The failing case is
**`62-ctor-base-delegation-0032`** — *not* the `50-dtor-base` fragment; ten cases
share the reported first line, which is what made the reporting lane call it
unreproducible.

```cpp
struct Bd { Bd(); ~Bd(); int b0; };
struct M : Bd { M();  };
struct D : M { D();  };
D::D() {}
```

Real c2 emits **seven** sections with **two** `.text`: `??1M@@QAA@XZ` — the
**implicitly generated** destructor of `M` — in its own COMDAT
(`chars 0x60401020`, `SELECT_ANY`) placed **first**, then `??0D@@QAA@XZ` in the
ordinary packed `.text` (`0x60400020`). The port emitted **six** sections with
both packed into one `.text` **in the opposite order** — `Port=Mismatch @ offset
2`, `NumberOfSections`. **A refusal had become a wrong emit.**

**The discriminator is measured, not guessed.** `.gl` introduces `??0D` with
`00` and `??1M` with **`26`**, and `gl.rs`'s `NAME_SEPARATORS` already records
that every witness carrying `26` is a symbol with COMDAT-style linkage. So the
gate now refuses a **defined** record whose name is `26`-**introduced**.
`d0d8a98` (W-ADOPT) closed the case where a run **ends** at `26` and left open
the case where one **begins** at it — a different shape, because a
`26`-introduced name is NUL-terminated and every downstream field arithmetic is
fine. **Nothing was wrong with the name; what is wrong is the obj shape it
implies.**

**Refusal rather than emit, and the reason is not timidity.** Teaching the
packed writer to mint a per-function COMDAT is an emit-set / section-layout
model, which `docs/STATUS.md` puts in **Phase 7** and says plainly is not
reachable by widening. Its ordering half is unmeasured on top: across the sweep
**twelve** cases carry two `.text` sections in packed mode and **the COMDAT is
not always first** (`51-dtor-member` 0250 and 0255 put it second). **Eleven of
the twelve already refused for unrelated reasons and exactly one reached the
emitter**, so the refusal costs nothing measurable — `perf` Match is 106 before
and after, the gate's per-lane match counts are unchanged, and the 878-TU scan
is identical.

**W-ADOPT's own test asserted the behaviour that was the wrong emit**, and its
revision is the transferable part: *seeing a name and being able to emit a body
under it are different claims*, and the test conflated them. It now asserts the
split — the widened **scanner** still sees the `26`-introduced name (that half
stands, and it is what made the record accountable instead of invisible) and the
**gate** refuses the record — and flips the one separator byte to `00` to show
the refusal keys on it and on nothing else.

**Why `il_gl_sep26.cpp` could not have caught it**, which is the same lesson
w-frame landed today one level down: its `26` symbol is a **deleting**
destructor beside a vftable, so its TU is out of class for four other reasons
and the `NotImplemented` it asserts is right for the wrong cause. The axis it
holds fixed is **implicit vs explicit**. `w232_gl_sep26_implicit.cpp` varies it,
and it runs in all twelve gate lanes.

## 3. Found on the same axis and NOT fixed

Writing `M::~M() {}` **explicitly** makes `.gl` introduce `??1M` with `00`, and
c2 packs both functions into one `.text` — **with `??1M` still first**, where
the `.ex` segment order is `??0D` first. The port emits `.ex` order and
mismatches at offset 8. That TU's `.gl` **contains no `0x26` byte at all**, so
`d0d8a98` provably cannot have caused it: it is a **pre-existing packed-`.text`
ordering defect**, on an axis no instrument enumerates (the sweep's generator
never writes an out-of-line implicit-sibling destructor). Reproducer in
`work/w-cross/alarm/`. Not fixed here: the predicate would have to be "the port
cannot know the emit order", which refuses every multi-function TU.

  coordinator's, and the sequencing matters: wiring it while red turns the merge
  gate red for every lane.
