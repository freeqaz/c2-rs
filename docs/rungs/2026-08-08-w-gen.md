## 2. Was this family one of #283's 56 unreached markers? **No — it is genuinely absent, and the table cannot represent it.**

The brief asks this first because getting it wrong wastes the lane, and the two
answers need different repairs. Measured rather than asserted:

* **Every marker in `scripts/sweep_shapes.py` is LEXICAL** — a keyword, a type,
  an operator, a regex over source text. There is no row for a *composition of
  two productions*, and there cannot be one: "a scheduled store run whose
  successor statement is a call" is a property of the body's shape, not of any
  token in it.
* The table has grown from 56 rows to **60**, and on master it already reads
  **`0 of 60 shape markers have zero cases`**. Lane `w-shapes` closed the last of
  #283's zero rows on 2026-08-04. So there was no unreached row to fill.
* `work/w-gen/markerdelta.py` prints the corpus with and without the new
  fragment. **The fragment adds zero new marker rows and closes zero.** Every row
  it moves was already non-zero: `function definition` +1,576, `pointer` +1,576,
  `unsigned` +1,576, `constructor/destructor` +536, `reference type &` +599,
  `cast` +300.

**So the marker table is blind to this family in both directions** — it could not
have reported the gap before, and it does not report the closure now. That is the
finding, not a complaint: #283's instrument answers *"which source tokens does the
corpus never contain"*, and #232's mechanism was never a missing token.

### 2.1 Two of the 60 rows are satisfied by non-instances

Falling out of the same measurement, and worth more than the answer it came from:

| row | regex | what it actually matches |
|---|---|---|
| **`pure virtual`** | `=\s*0\s*;` | **every assignment of zero.** `mCount = 0;` is a pure virtual function |
| **`bitwise & \| ^ ~`** | `(?<![&])&(?![&])\|…` | **every address-of and every reference declarator.** `&mListHead` is a bitwise AND |

Counted over the whole corpus at this lane's tip: `pure virtual` reads **1,240**
and **14** of those TUs contain the word `virtual`. On master it read **166** and
the same test leaves **14**. `bitwise` reads **1,988**, of which **1,166** look
like a real binary or unary bitwise operator.

The consequence is exact and is #283's own gate: `sweep_shapes.py --check` fails
when any row reads zero, `C2RS_MAX_ZERO_MARKERS` defaults to **0**, and
**`pure virtual` has been held above zero by 152 cases that are not pure virtual
functions.** The row is not evidence the shape is in the corpus. This lane files
it (**#1140**) and does not fix it, because narrowing a marker moves the number
`--check` compares against and belongs with the fragment repairs #281 already
wants in their own lane.

## 3. The axes, and why exactly these

`w-heap`'s GRID F3 graded 27 frozen cells and collapsed six candidate axes to two
that matter. Those are **consumed here, not re-derived** — the lane's brief says
so and re-deriving them would have spent the lane on measurement somebody already
paid for. The generator's axes are the ones that survived that collapse plus the
three the same rung names as unpriced.

| axis | levels | why it is structural and not a value |
|---|---|---|
| **C** the call's **argument setup** | none (member on `this`, arg already in slot) · nullary · **writes `r4`** (`Alloc(size)`) · **writes `r3`** (free callee) · two moves | **the regime boundary.** #870 states it as *"a call that takes an ARGUMENT breaks the run"*, which is one level too coarse: `Alloc(size)` sets up `mr 4,5` and **still transfers**. What breaks it is the setup writing `r3` and destroying `this` — the base switches `r3 → r31` mid-run and the setup interleaves. `c1b` is the level that separates them and it exists only because the axis is enumerated by *what the setup writes* |
| **F** the **return-value use** | ctor · void · `return <call>` · discarded `int` | **only the ctor frames.** The other three are frame words **0** and tail-call behind the run (#869, `w-heap` §3.3). A generator that varied the run and not this would grade three tail calls and report a composition |
| **P** the **producer count** | 0 · 1 (lit) · 1 (lit, 2 uses) · 2 (two lits) · 1 (addr) · 1 (addr, 2 uses) · **2 (addr@2 + lit@1)** · **2 (lit@2 + addr@1)** · 2 (two addrs) · 3 | **the store count is not the axis.** #1099's evidence cell `x7` has **one** producer where `xboxheap` has two; it matched the target's store *count* and the schedule is about producers (`w-heap` §5). The `lit@2 + addr@1` level is `w-heap` §4.1.1's `j1_lit2` counterexample — the inverse of `xboxheap`'s own use counts, where a clause fitted on the target alone is **wrong** |
| **W** the store-run **width** | 0 · 1 · 3 padding stores | **held orthogonal to P** by padding with stores that materialise nothing (`mSize = size` is a formal already in a register, `mFreeHead = this` is `r3`). A grid where width and producer count move together cannot attribute a schedule change to either, which is how #1099 got the wrong width |
| **R** the **reference bind** | direct · `BE& lh = mListHead` | **load-bearing at this width.** `xboxheap`'s ctor without the bind is a **different body** — both producers swap emission order and one store moves (`w-heap` §4.2). A widening that collapses the two spellings emits the other body's words, which is **#232's exact shape**, available to anyone who reads a published price of 3 and starts writing. So it is crossed, never held |
| **F2** a member's **address as a stored value** | absent · present | reader refusal item **1** of `w-heap`'s five, and the thing that makes the run *mixed-kind* (`addi` beside `li`) and therefore reaches `alloc::allocate`'s mixed-kind refusal (#836/#868) |

**Axes `w-heap` measured as NOT free-standing are not crossed.** D (callee kind)
and E (receiver slot 0) are *determined by* C — a free function and a member call
on another object both put a non-`this` value in slot 0, so both force
C = writes-`r3`. They get their own block (§4.3) instead of a factor in the
product. Recording the coupling is the point; a cross would claim to separate two
axes that are one, and this project has three defects on record from exactly that
(`GAPS.md` §6 #4, #5, #6, #8: a formal's index and its register were the same
number in every fixture).

### 3.1 What the field layout is for

The struct is `xboxheap`'s own `CXboxHeap` — `mFreeHead 0 · mUsedHead 4 ·
mListHead 8 (mNext 8, mPrev 12) · mSize 16 · mCount 20` — extended with
`mSecond 24 · mFlags 32 · mPeak 36` so that **no two axes ever write the same
offset**. That is not tidiness: a dead store makes c2 emit **one** store
(`82-store-run.py` §8 lists it as a refused form for that reason), so a width
axis that reused `mSize` would have silently shortened its own runs and the
producer axis would have been measuring a different length than it printed.

The struct is otherwise held **fixed across the whole cross**, including the
member declarations a given cell does not define, so a difference between two
cells is a difference in the body and never in the type.

## 4. What the fragment contains

`scripts/sweep.d/88-store-run-call.py`, 1,576 cases, seven blocks.

| § | block | cases | what only it can reach |
|---|---|---:|---|
| 1 | **the cross** — run-kind × bind × width × setup × form | 1,320 | the product. 20 run/bind pairs (the bind axis is dropped, not faked, on the four runs that never touch `mListHead`) × 3 widths × 22 legal (setup, form) combinations. `cnone` is the **leaf control**: the identical run with no call at all, without which *"the run transfers"* is a claim about one cell instead of a comparison — #866's own construction |
| 2 | **axis B, two store bases** | 36 | `w-heap`'s `f3_b2` emits and is left refused, matching the parser's multi-symbol gate. Swept against the setup axis because the second base and a setup that writes `r3` compete for the same volatiles |
| 3 | **axes D/E, callee kind and receiver slot** | 54 | slot 0 as `this`, as a formal, as a **member load**, and as **the F2 value itself** (`ga(&mListHead)` — the address in the argument position rather than the store position) |
| 4 | **axis G, the F2 value's member offset** | 72 | offset **0** (the address *is* `this`, no `addi` at all), **8** (`xboxheap`'s), **24**. Crossed with the bind and the setup, because the producer the offset creates is the one whose emission order the bind swaps |
| 5 | **the over-accept guards** | 48 | twelve shapes **one statement away from an accepted cell and not the accepted shape**: the call in the *middle* of the run; a store *after* the call; the call *first*; two calls; the call's result feeding a store; a branch between run and call; a loop; a member-load argument; the F2 value as the argument; a call through a member; the run under a nested scope and the call outside it, and the reverse |
| 6 | **source lines and statement boundaries** | 16 | `GAPS.md` §6 instance #1's axis on a body that now has **two** productions ending it, including the run at source line 70 where the first `0x46` is a line marker's payload. The composition is what is new: the call's own line marker sits after the run's and **nothing has ever varied their distance** |
| 7 | **the composition beside a neighbour** | 30 | the per-TU label counter and `_fltused` are decided by the whole TU (§6 #12/#13); a framed composition is a new way to own `$M`/`$T`. Both orders against seven leaf strides, plus the only configuration that separates a per-function label rule from a per-TU one (**two** compositions in one TU — at n = 1 the two formulations are indistinguishable) |

### 4.1 The guards are the reason the fragment is worth its runtime

Blocks 1–4 are what a widening should accept. **Block 5 is what it must not**,
and it is the half that makes the widening *safe* rather than merely *watched*.
`w-heap` §6.3's own sentence is that the gate cannot see the half that would be
wrong; a corpus of positive cells would reproduce that exactly one instrument
further out.

## 5. It grades, and what it grades

```text
  C2RS_SWEEP_ONLY=88-store-run-call, jobs 16, /Ox /GS- /c
  sweeping 1576 of 1576 generated cases
  checked=1576 mismatches=0 graded=1576 ungraded=0 unknown=0
```

**`ungraded=0` is the load-bearing number in that line**, not `mismatches=0`. The
brief's standing warning is that a generator emitting sources the reference
rejects grades nothing and reads as coverage — absence-read-as-success, recorded
thirteen times on this project. `ReferenceReplay=ByteExact` on **1,576 of 1,576**:
real `c2.dll` under wibo produced an obj for every case and ruled on every one.
Board #281's baseline of **96** is unmoved, so the fragment adds no ungraded
residue of its own.

The port's own verdicts, tallied separately because `mismatches=0` alone does not
distinguish *right* from *silent*:

```text
    44  Port=Match             the leaf controls, and the offset-0 cells where the
                               address IS `this` — shapes today's leaf-store
                               emitter already handles byte-exactly
  1532  Port=NotImplemented    the honest refusal outside the ported class
```

So the fragment is **not purely negative**: 44 cells guard today's emitter on
this family from the day it lands, and the other 1,532 are the alarm that arms
when a reader widens.

### 5.1 The profile, stated rather than conflated (board #1112)

The sweep compiles at **`/Ox /GS- /c`**. `xboxheap` and every `w-heap` grid cell
were graded at the workload's **`/GR /O1 /Oi /EHsc`**. These are **different
populations** and a refusal can read as paid at one while being unpaid at the
other. Nothing in this fragment is a statement about the workload profile: the
cells are shaped to reach the *productions*, not to reproduce `xboxheap`'s bytes.
The fragment's own header says so, so the next reader of the file gets the caveat
without having to find this page.

## 6. Alarm semantics and the gate

`git diff master..HEAD --stat -- crates/` is **empty**. This lane ships one file
under `scripts/sweep.d/` and one read-only script under `work/`, so every
emit-side number is unchanged *by construction* — and "by construction" is the
reasoning that let #232 run 255 commits, so the gate was run anyway.

**Peer-key check.** Concurrent lane `w-align` owns the `.gl` type/alignment
reader (#1110). This lane adds **no reader, no collector and no metric key**: the
`crates/` diff is empty and nothing it touches prints a `gap-metric` line, so
there is no surface for the duplicate-walk or dropped-prefix hazards the brief
names. That is checked (empty diff) rather than assumed. `work/w-splice/peerkeys.py`
compares two scan JSONLs; with an identical binary at both ends it compares a
file to itself, which is why the empty diff is the stronger statement.

The one count this lane **does** move is the sweep's own corpus total, and it
moves it in one direction only: **+1,576 reached, +1,576 graded, +0 ungraded,
+0 mismatch**. Every lane quoting `16,710 / 16,614` should read `18,286 / 18,190`
from this merge forward.

### 6.2 The one cost this lane adds, measured rather than discovered later

`scripts/mode_cross.sh`'s assignment goes **81,905 → 110,273 cells** — the corpus
grew 9.4 % and the cross grew **34.6 %**. The reason is printed by the gate's own
`cross/assign.log`:

```text
  3 fragment(s) have NO ROW in scripts/mode_classes.txt and are graded at ALL 18 lanes:
      12-alloc-depth
      77-reinterpret-2c
      88-store-run-call
```

1,576 cases × 18 lanes = **28,368 cells**, against a corpus average of **4.9**
lanes per case. That is the **fail-safe** direction and `mode_classes.txt`'s own
header says it is deliberate: *"adding a `sweep.d/` fragment then costs more than
it needs to and never less, and nothing is silently excluded by being
forgotten."* Two fragments are already in that state.

Buying the reduction back means `mode_invariance.py --write-classes`, and that
**rewrites every row's digest**: `--only` narrows the *measurement*, but the
writer emits only what it measured, so a scoped append is not expressible in the
tool. A whole-table regeneration moves a number every lane quotes and belongs to
a lane that owns that count. Filed as **#1143** with the figure attached, rather
than left for whoever next wonders why the cross row got slower.
