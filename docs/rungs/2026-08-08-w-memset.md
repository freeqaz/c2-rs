## 3. The production, read

```text
  53                            the loop's own scope
  3A <Lcond>                    goto COND
  29 <Lincr>            INCR:
     26 <formal> 33 <TYPE> <k> 0F <TYPE> 4B      one pure induction step
  29 <Lcond>            COND:
     B9 <formal> <TYPE>  B9 <formal> <TYPE>  <cmp>  38 <Lexit>
     <one discarded call statement>
     3A <Lincr>                 continue
  29 <Lexit>            EXIT:
  54 <n>  <return plumbing to the segment end>
```

`Some(callee_token)` — **a condition, never a verdict**, and a **LINK, never a
seed**, which is the containment `w-inl0` established and this lane inherits
without editing.

### 3.1 Why a loop can be read this way, as five things rather than an argument

1. **The walk is TOTAL over the segment** — it ends on `eat_return_plumbing`'s
   fail-closed terminal, so the induction variable is provably read nowhere
   after the loop. Mutation **M3** removes this and a named test goes red.
2. **The answer is CONDITIONAL on the callee**, decided by `elide.rs`'s own
   fixpoint. `l03` and `l04` are the graded cells.
3. **The induction step is PURE** — one lvalue that must name one of *this
   function's own formals*, one literal, one operator, discarded. `26` is also
   the **data-symbol** push, so without the membership test a step that
   incremented a global would read as pure while the body materialized a data
   reference — `elide.rs`'s condition 3 one level down, `w-fix`'s `k16`.
   Mutation **M2**.
4. **The exit test reads only formals**, for the same reason (`l07`).
5. **EVERY LABEL IS MATCHED** — the head's `3A` names the label that opens the
   test, the tail's `3A` names the label that opens the step, the `38` names the
   label that closes the loop, and the three are pairwise distinct. Mutation
   **M1**.

**The trip count is not modelled and does not need to be**: if the body emits
nothing then no number of iterations of it emits anything, and the induction and
the test are pure by (3) and (4). What that does *not* license is any claim
about **termination** — nothing here says the loop halts, only that c2 emits no
code for it, which `l01`/`l09` measured at `/O1` **and** at `/Ob0`. Board
**#1051**.

### 3.2 The argument walk is FACTORED, not copied

`eat_no_effect_call_stmt` is `no_effect_call`'s own closed vocabulary, lifted out
byte for byte, and the loop's single statement goes through it. The one
difference is a parameter: a plain discarded call at the top of a body has an
accepted shape already and inside a loop it has none, so `require_temp` is a
*narrowing* in the first case and never a widening in the second.

`w-relo`'s merge is why this is a factoring and not a second reader: **two lanes
wrote the same reader in different files, auto-merged with no conflict marker,
and the duplicate walks were caught only by a compile error.** Board **#1050**.

## 5. THE STOP, and why this lane does not step over it

Level 4's whole body, from the capture:

```text
4c 4f 11 53 <line> 33 86 41 74 00 · 33 82 07 03 00 · 44 · 4b <line> <return plumbing>
```

An `int` literal, a **`void`** literal, a bind, a discard. `p->~T()` on a class
with a trivial destructor. **There is no call in it.**

`c2_core::elide::Reduction` has two variants and its own doc pins the asymmetry:
*"a refused body contributes a **link and never a seed**"*. `NoEffectCall(&str)`
cannot express a body with no callee, so **no chain through this leaf can
close**, however many productions above it are read.

The lane brief: *"Do not change `crates/c2-core/src/elide.rs`'s rule — you are
feeding it, not editing it; if you believe E's rule must change, STOP and
report."* **E's rule must change.** `git diff master..HEAD -- crates/c2-core/`
is **empty** and this rung is the report. Board **#1053**.

**What it is worth, measured and not inferred:**

| | n |
|---|---:|
| `differs` that would close (`fnbyte-blr-stop3-expr-lit-type-8207`) | **227** |
| …the 228th, at `expr-call-in-expr-recv-load-then-type-void-and-op-more` | 1 |

## 6. THE FINDING — a key that is collected and not rendered is a key that does not exist

Reading the loop made the chain one link longer, and the instrument could not
see it. `fnbyte-blr-stop2` read **228 at both ends** and the scan looked exactly
like a reader that had done nothing.

The collector stopped at two levels. Fixed — and **the scan still said nothing**,
which is what sent the search to the renderer: `gap::factors` iterated
`[("fnbyte-blr-stop|", …), ("fnbyte-blr-stop2|", …)]`, two hard-coded prefixes,
and dropped `fnbyte-blr-stop3|…` on the floor. Both sides now walk **levels**.

It cost a debugging pass, and it is the same shape as `w-fix` §4's green
mutation and `w-inl0` §7's M2: **an instrument that cannot see the thing under
test reports "unchanged", which is indistinguishable from success.** Board
**#1049**.

The walk is bounded by `MAX_BLR_STOP_LEVELS = 8` rather than by the chain, for
`elide.rs`'s own round-ceiling reason: `no_effect_callee` is a graph edge, a
cycle in it would spin the walk, and the bound is there so a future reader that
admits one terminates instead of hanging a scan. The workload's deepest readable
chain is **3 hops**, so it cannot fire — and a non-zero count at the last level
is the observation that says the chain outran the instrument.
