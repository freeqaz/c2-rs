## 3. Decline clause **D1 fired**, on one byte, and the byte is now decided (#1680, #1681)

### 3.1 What fired

`PREREG.md` §4 **D1**: *if `gl_data_objects_ordered` and `in_scalar_initializers`
cannot between them produce, for this bundle, both the name and 248 bytes
byte-identical to the reference obj's `.data`, decline.*

* **`.in` DELIVERS.** For token `0xea09` the shipped reader returns **248 bytes**
  byte-identical to the reference obj's `.data`, `0000001d 00000025 … 000d744f
  00000000`, with `records=38 accepted=38 elements=106 residue=0` and the
  totality identity closed.
* **`.gl` returns ZERO records.** The record is *there* and frames perfectly —
  `86 06 00 02 04 · 80 f8 00 00 00 · a0`, tag `86` align 4, kind `06`, the literal
  `00 02`, linkage `04` STATIC, size varint **248** — and is rejected on the
  attribute byte, which `data_object_at` enumerated as `{00, 80}` and failed
  closed on.

**So D1 fires as written and is scored as fired.** It is also the clause of this
prereg that was mis-drawn, and §9 scores it that way: D1 cannot tell *"the
reader has no production for this shape"* from *"the reader has the production
and one enumerated byte value is unwitnessed"*, and the measured answer is the
second. Its own remedy — *"the honest deliverable is the measurement"* — is §3.2.

### 3.2 GRID A — the attribute is two independent bits, 6 cells, **both halves**

Frozen at `470b908f` before the first `cl.exe` on it: six cells, four rival
readings, every rival's per-cell prediction written down and **the separating
cell named for each**. Each cell read twice and independently — the `.gl`
attribute byte, and the obj real `c2.dll` produced for the same source — and a
rule banked only if the two agree.

| cell | source | `.gl` frame | attr | obj |
|---|---|---|---|---|
| **a1** | `int f(){ static int p[4]={1,2,3,0}; … }` | `86 06 00 02 04 10 a0` | **`a0`** | `.data` **after** `.text`, COMDAT `0xc0301040`, sel 2, STATIC |
| **a2** | `int f(){ static int p=7; … }` | `86 01 00 02 04 04 a0` | **`a0`** | `.data` after `.text`, COMDAT, sel 2, STATIC |
| **a3** | `int f(int i){ static int p[4]; … }` | `86 06 00 02 04 10 20` | **`20`** | `.bss` **after** `.text`, COMDAT `0xc0301080`, sel 2, STATIC |
| **a4** | `static int p[4]={1,2,3,0};` | `86 06 00 02 04 10 80` | **`80`** | `.data` **before** `.text`, plain `0xc0300040`, sel 0, STATIC |
| **a5** | `int p[4]={1,2,3,0};` | `86 06 00 02 01 10 80` | **`80`** | `.data` before `.text`, plain, sel 0, EXTERNAL |
| **a6** | `int gDef=3;` | `86 01 00 02 01 04 80` | **`80`** | `.data` before `.text`, plain, sel 0, EXTERNAL |

> **`0x80` = initialized (`.data` vs `.bss`), unchanged. `0x20` = the object is
> its OWN COMDAT** — `IMAGE_SCN_LNK_COMDAT`, aux `Selection = 2` ANY, symbol
> STATIC — which over this grid is exactly *a function-local `static`*.

* **a6 is the positive control** and reads the `80` `data_object_at`'s own doc
  already recorded for `?gDef@@3HA`, so the instrument is reading the right byte.
* *aggregate* dies at **a2** (a **scalar** function-local static reads `a0`) and
  again at **a4** (a namespace-scope **array** reads `80`).
* *the reader under-counted the initializer* dies with it on the same two cells.
* *`a0` is a third enumerated value, not a bit* dies at **a3**, the cell the
  freeze named for it: an **uninitialized** function-local static reads **`20`**,
  which that reading has no member for. It is the load-bearing cell because it
  is the one that says the widening touches the `.bss` arm too.

**`0x40` is deliberately NOT admitted.** `data_object_at`'s doc records `60`/`E0`
as the `__declspec(selectany)` forms — the same COMDAT bit plus `0x40` — and no
cell of this grid is a `selectany`. `the_selectany_forms_still_fail_closed` is a
`#[test]`, because widening a byte to a bit field is exactly the change that
makes an ungraded neighbour fall out for free.

### 3.3 What shipped, and why it moves no obj (#1680)

`GlDataObject::comdat`, read from `DATA_ATTR_COMDAT`, and **`data_tu` refuses an
object that carries it**. `emit_data_obj` builds one shared `.data` and one
shared `.bss`; a COMDAT object is its own section with its own `Selection`, and
dropping it into either is a wrong section count at file offset 2. Before the
widening such an object made `data_object_at` return `None` and the TU refused
at clause 6's exhaustive accounting; now it frames and is refused with an honest
reason. **Same verdict on every TU that path emits, and a reader that can now be
asked about the record** — which is what `Primes.cpp`'s `gl-data records=0 → 1`
is.

### 3.4 A second rule the grid was not built for — the SECTION SLOT (#1682)

Unanimous over six cells:

> A **COMDAT** data object is placed **after** the code groups; a **non-COMDAT**
> one is placed **before** them, between the second `.XBLD$W` watermark and
> `.text`.

**a4 is the cell that makes this sharp.** `static int p[4]` at namespace scope,
whose *first referrer is a function body*, still lands **before** `.text` — so
over these cells the discriminator is the object's own COMDAT bit and **not**
the first-referrer test board **#1179** states for `.bss`. #1179's cells are
namespace-scope `.bss` in a TU with a `.data` initializer and are not
contradicted; what this grid says is that the first-referrer test does not
extend to the function-local class, which has its own answer. `Primes.cpp` is
a1's row exactly, so **P5 is confirmed** and **D3's "≥ 3 graded cells" threshold
is met with six**.

### 3.5 The 1:2 fan-out arrives as fixtures, unlooked-for

**a1, a4 and a5 each carry `REFHI` at `0x0000` and TWO `REFLO`s** (`0x0004`,
`0x0008`) against one symbol — w-loop's **R3** exactly, on cells that are one
line of C++ each, where `Primes.cpp` was the only known instance. a2 and a6
carry the 1:1 form, so the grid separates the two fan-outs as well.

## 5. The IL body, decoded, and two opcodes pinned (#1686)

`work/w-cfg2/PRIMES_BODY.md`, committed: `?NextHashPrime@@YAHH@Z`'s **294 bytes,
~60 tokens**, annotated against `docs/IL_STMT_GRAMMAR.md`. It is **one linear
sequence with no value merge at a join**, so **D2 does not fire** — measured on a
built decode, not argued.

The rotation and the opening statement are `ptr_walk_loop`'s byte for byte
(`3A Ltest · 29 Lincr · <incr> · 29 Ltest · <test>`, and `26 <local> · 33 <lit> ·
32 <TYPE> 4B`). What differs is what the loop carries: a subscript of a defined
static array, and an early `41`/`3a` return out of the body.

Two opcodes that were a hex bucket, each with a two-line probe of this lane's:

* **`0x04` is `*` (multiply)** — `int f(int a,int b){ return a*b; }` captures
  `b9 <a> <int> · b9 <b> <int> · 04 · 41 <int> · 3a <ret>`.
* **the SUBSCRIPT IDIOM is `26 <base> · b9 <index> <TYPE> · 33 <86 41 12>
  <scale> · 04 · 28 00 00 · 30 <TYPE>`** — `int g[8]; int f(int i){ return
  g[i]; }` captures it byte-for-byte identically to all three occurrences in
  `Primes`, `28 00 00` included (a `varU` of 0, which is `WB_READER_FINDINGS.md`
  §3.4's reading of opcode `0x28` confirmed from the black-box side).

So `idx.cpp` is a two-line reproducer for the one sub-expression `Primes.cpp`
uses three times, and the subscript production can be graded without the loop.

**And the trap is named for whoever writes the recognizer**: board **#1636** is
`ptr_walk_loop`'s accumulator clause copied verbatim into a class whose
accumulator is a different `.sy` kind, where the conjunction is vacuously false
and refuses every instance by construction. `i2` is a plain `int` local, so
`locals` is the right list and `ptr_locals` is the wrong one.

## 8. The `ptr_walk_loop` carry item (board #1638), and why it is left

The brief asks this lane to carry, if its path touches it, w-cfgclass §5.3's
recorded gap: `codegen::ptr_walk_loop` holds the `/O1`-only gate in the
**emitter** with no parser half, which is the census-over-claim shape
w-cfgclass fixed for its own class.

**Left, deliberately, and the reason is a measurement rather than a preference.**
Moving that clause into the parser changes `ptr_walk_loop`'s **accept boundary**,
and `ptr_walk_loop` is the class behind `src/system/math/Sort.cpp` — a **matched
TU**. A change to a matched TU's accept path owes the same grid as the class
itself: §5.3's own last paragraph declines the move for exactly this reason
(*"changing `ptr_walk_loop`'s accept boundary is a change to a class it did not
grade"*), and this lane's path never touched that class — its target is a
different shape whose loop the port does not accept at all. Carrying it here
would have been a change graded by nothing.

**What a lane that does take it needs, so the next reading is cheaper than this
one:** the missing half is a mode test in
`shapes::ptr_walk_loop::try_parse_ptr_walk_loop`'s prologue, before any body
byte is read, mirroring `if_call_join`'s; the cross-check that would catch its
absence is `crates/c2-harness/tests/census_gate.rs`, which **does not fire
today** only because no fixture puts the pointer-walk shape in front of the
packed lane's profile — an absence of evidence, and it should be a fixture in
the same commit as the fix.

### What the scoring bought

**D1 is the useful loss, and it is a defect in a clause rather than in a
target.** It was written to separate *"the `.data` half is a reader rung"* from
*"it is plumbing"*, and it cannot: it asks whether the shipped readers produce
an artifact **today**, and the shipped readers were one enumerated byte away.
The measurement it demanded turned out to be four hours cheaper than the clause
implied and settled the byte on both halves.

The right form of that clause, for whoever writes the next one: **a scope clause
must name the size of the thing it declines, not its presence.** *"Decline if the
`.gl` half needs a new production"* would have passed here — the production
exists — and *"decline if it needs a new grid"* would have fired honestly, and
been paid, because the grid is six cells and one afternoon.

**And P1's miss is board #666's shape once more, from the third side.**
w-cfgclass had a correct construct inventory and a cost model for a thing it was
not building. This lane had a correct *ranking* — `Primes.cpp` really is the
