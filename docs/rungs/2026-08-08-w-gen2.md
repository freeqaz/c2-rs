## 2. What `88` could not produce, stated mechanically

`w-gen` landed `88-store-run-call.py` — 1,576 cases, six structural axes —
**before** the widening it was written to protect, precisely so board #232 could
not repeat in this family. That evening `w-seam2` widened into the family, shipped
an emitter that graded `Port=Mismatch` twice, and `88` reported
`checked=1576 mismatches=0` through both. The cell that caught it was a
hand-written fixture.

There are **two independent reasons**, and closing either one alone leaves the
hole open:

1. **No case in `88` stores the formal its call passes.** Its runs store
   `mSize = size` (the *last* formal), `mFreeHead = this`, `mUsedHead = this`,
   literals and interior addresses. Its call setups are `Alloc(initSize)` and
   `Reset()`, and **`initSize` is never a stored value anywhere in the file**.
2. **The one setup that would pass a stored formal cannot reach the transfer
   gate.** `88`'s `c1b` is `Alloc(size)`, and `size` *is* stored by the width
   axis (`mSize = size`). But the reader's **regime gate** requires slot `i` to
   hold `params[i]`; `Alloc(size)` puts `params[2]` in slot 1, so the argument
   setup is `mr 4,5` and the body is refused **one step earlier**. Liveness is
   never asked about it.

So reaching the axis at all needs a callee whose argument list is a **prefix of
the formals in identity order** at arity ≥ 2. `88`'s `H` declares none, and `H`
has only two formals.

### 2.1 Why a SIBLING fragment and not an extension of `88`

`88`'s `PRE` is held FIXED across its whole cross by construction — its own
comment: *"so a difference between two cells is a difference in the body and
never in the type"*. Adding a two-argument identity-slot callee, and the third
formal the arity axis needs, rewrites the source of **all 1,576 existing cases**.
That would re-baseline the port split `w-gen` and `w-seam2` both published for
that fragment (44 Match / 1,532 NotImplemented, then 83 / 1,493), so neither
number would still name a measured population, and it would make every one of
`88`'s cells non-comparable with the cells `w-seam2` graded against them — for a
change that has nothing to do with `88`'s own axes.

A sibling keeps `88`'s 1,576 cases **byte-identical** (verified: `88` alone still
generates 1,576 and still grades 1,576) and adds a disjoint family whose own type
can be shaped for liveness. It is also the `sweep.d/` one-file-per-axis contract:
two fragments cannot conflict in git, and two rungs claiming one fragment name is
an add/add conflict git flags loudly.

### 3.1 The shape of what it finds

`work/w-gen2/classify2.py`, over the 186:

**The `slots {2}` cells are the ones the arity axis buys**, and they are
`w-seam2`'s `a2_break2` generated:

```cpp
  K::K(unsigned int a, unsigned int b, unsigned int c) {

  }
```

Three of them (`0229`, `0230`, `0231`, differing in producer count 0/1/2). A
generator whose live-argument axis was keyed on *slot 1* — the reading every
derivation cell in `w-seam2` was consistent with before GRID S4 — produces none
of these and reports **183 of 186**, which reads as a working instrument.

### 3.2 A finding the lane did not go looking for: the swap is NOT a function of "some stored value is live"

Two cells with the **identical run**, differing only in the callee's arity, under
the counterfactual (`work/w-gen2/probe/cf.txt`):

```text
  K::K(a,b,c) { mD=0; mB=b; mA=a; A1(a);    }   ->  Port=Mismatch
  K::K(a,b,c) { mD=0; mB=b; mA=a; A2(a, b); }   ->  Port=Match
```

Adding `b` to the argument list — making **more** of the run live — makes the
framed schedule agree with the leaf's again. And at arity 3 the fully-live run
`mD=0; mA=a; mB=b; mC=c; A3(a,b,c)` mismatches. So the schedule is not monotone
in liveness, and **#1173's hoist rule cannot be fitted as "hoist the live store"**
— it would be wrong on the second line here. That is board **#1189**, filed with
its two cells rather than left as an impression.

## 4. The axes, and why each is STRUCTURAL

The rule this project has now paid for four times is *enumerate STRUCTURAL axes
and cross them; vary values inside each cell*. Both grids that missed #1174
varied values thoroughly and left one structural axis constant.

| axis | levels | why it is structural, not a value |
|---|---|---|
| **callee ARITY**, identity slot binding | none (leaf control) · 0 · 1 · 2 · 3 | at arity 2 *"slot 1 is live"* and *"slot ≥ 1 is live"* are the same statement (GRID S4). Three formals is the minimum that separates the three readings — `88` has two |
| **WHICH formals the run stores** | 16 subsets of `{a,b,c}` × `this`, both orders at cardinality 2–3 | the receiver at slot 0 is measured EXEMPT, so it is a level and not an omission |
| **POSITION of the live store** | every permutation of a 3-store run × producer at front/middle/back | `work/w-seam2/grid3/p3` stores the live argument FIRST, where the hoist is a no-op and the framed run *is* the leaf's. Position decides whether the defect is VISIBLE |
| **the REGIME break** | `A1(b)` · `A2(b,a)` · `A2(a,c)` · `A3(a,c,b)` · free `f0/f1/f2` · `p0->A1(a)` | `88`'s axis C one level in: there the question is what the setup writes, here it is what the setup writes *while the run stores something the setup reads* |
| producer count, held orthogonal to width | 0 · 1 literal · 2 literals · 1 interior address (F2) | `88`'s axis, **crossed against** the new one rather than replaced (#1099's wrong width) |
| the reference bind | absent · `BE& lh = mList` × 1 or 2 uses × address before/after the run | #839: the two spellings are DIFFERENT bodies. The bind decides the producers' order and the live store decides the unproduced stores', so a rule fitted on one spelling is being asked about both |
| the return-value use | ctor (framed) · void · `return <call>` · discarded | only the ctor frames; the other three tail-call at frame words 0 (`w-heap` §3.3) and are controls |

Seven blocks, **1,270 cases after dedupe** (the fragment dedupes: two axes can
name one body, and two copies of a case is coverage the sweep did not buy,
board #281). The 2-formal `P` family (block 5) is `w-seam2` §4.2's witness struct
generated rather than hand-written, so a future regression cannot hide behind
*"that is a different struct"* — **12 of the 186** are `P` cells.

this wave's brief names first, on a file the header itself calls generated. The
file's own words are the other half: *"A fragment with NO ROW HERE is graded at
ALL 18 lanes. That is the fail-safe direction and it is deliberate."*

**What a regeneration would buy, for whoever takes it** (board #1190): `88` has
no row either and costs **28,368** cells, so the two together are **51,228 of
