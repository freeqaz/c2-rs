`json_utf8_copy` is **twenty basic blocks** in `BlockOrder::IlStatement`. Every

### 1.1 It is a `#3142` shape, in full force, and that answers the brief's question

The brief asked which category this class is before anything was designed.
**`#3142`**, and it is the extreme of the surveyed thirteen: it publishes
**three** positions off the same running `t.len()` —

| published | was | is |
|---|---|---|
| `bl __savegprlr_28` `REL24` site | `base_off + 4` | `base_off + at(entry, 4)` |
| `prolog_len` — `$M(prologue)`, `.pdata` `PrologLen` | `t.len()` after the prologue | the entry block's own run length, with a **refusal** if the entry block is not placed first |
| `b __restgprlr_28` `REL24` site | `base_off + t.len()` | `base_off + tail_sites[0]` |

So its fourteen branches could never have moved alone, exactly as `w-layout`'s
`P17` predicted. `ptr_walk_chain_loop` — the one class in this residue that
publishes **nothing** (`#3154`) — is the other end of that scale, and with this
lane both ends of `P17` are witnessed rather than one.

`FrameLayout` stays the **single producer** of both frameless Class C words: it
is asked again after `finish`, at the offsets the layout gave, and the second
write is the one that is true by construction. The epilogue is
`Terminator::TailCall`, because an external branch is a **relocation and not a
label reference** (board #191) — the same composition `w-fencea` found for
`xlrc_create_guard` and `xtea_encrypt_loop`, and it needed no new mechanism
here either.

`prolog_len` is the one position that is *not* a block-relative constant: it is
an offset from the **function's** `.text` start. It is taken as a run-local
length and then a check makes it a body offset — a refusal rather than a
`debug_assert`, because the release build the gate runs compiles those out.

This is the lane's finding, and it is `#3151`'s disease one level out: **the

compares them.** `#3151` found it between a module header and the predicate
three hundred lines below it. Here it is between a **board row's budget** and

Three of the row's four load-bearing figures are wrong and the fourth is right
because it was measured by a different lane counting a different thing. **The
row's headline is still correct** — the blocker really was size and not a rule,
and the admission really was one enum variant. What was wrong was every number

**And the emitter agreed with the board against itself.** Its own comment read
*"the nine forward branches, patched"* over thirteen `patch` calls. So the
undercount was in two places and neither could see the other.

### 2.1 `label_slots` `Some(5)` is the non-framed formula, and the reason it cost nothing is structural

`IlFunction::is_framed()` is **true** for this class. It has no `stwu` — the
Class C prologue is two words — but what that predicate means is a `.pdata`
record and a `$M`/`$M`/`$T` triple, and it carries both. So `plan_labels`
advances `label_lead() + 4` and `label_slots(false)` is `Some(8)`, arm **1**.

The row published `Some(lead + 1)`. **It cost nothing, and the reason is the
one `w-fencea` §1.1 recommended and this lane is the first to be saved by:**
`every_admitted_class_has_a_registered_control_flow_surcharge` reads
`label_slots` and `label_lead` **off `c2-il`**, never off the board (`#3148`).
A wrong number on a board row could not become a wrong number in this crate,
and the variant was admitted correctly by a test that never saw the row.

`json_utf8_copy_is_admitted_as_a_framed_class_and_not_at_lead_plus_one` records
the correction and **writes no number down** — it asserts which *arm* the class
comes in on and that the `+ 1` reading is impossible, so it stays true if
`c2-il` re-measures the lead and goes red if the class stops being framed,
which is the change that would matter.

### 5.1 `P17`'s premise was wrong in the direction the lane is about

`P17` registered *"an off-by-one-word back edge"*. **A back edge cannot be off
by one word any more, and that is the migration's doing**: the target is a
`BlockId`, so the finest error the shape admits is off-by-one-**block**. The
row is realized as `M2` (the back edge names the preheader) and separately as
`M3`, which produces a genuine one-word displacement error by moving the
**block boundary** instead of the branch.

This is worth recording as a property rather than a bookkeeping note.
**Migrating a site to the layout does not make its branch harder to get wrong —
it changes the shape of the wrongness**, from "a displacement that is a legal
word pointing at no instruction boundary" to "a legal branch to the wrong
block". The first is `docs/CODEGEN_PPC_MVP.md`'s fuzzy-invisible class; the
second is not. That is a real reduction in failure surface and no instrument
here measures it.

2. **`WJ-b` — two dated blocks in `docs/` were stale and each went stale at a

3. **`WJ-c` — migrating a site to the layout changes the SHAPE of its
   wrongness, and that is a bigger result than the site count.** §5.1. Off by

   first is the fuzzy-invisible class this project keeps paying for; the second
   is caught by a name. **No metric here measures failure surface**, so the
