## 2. What it admits — the framed × branching cell

`work/w-frame/RANKING.md` §4 measured the port's one empty cross-product cell:

> **105 functions emitted byte-exact. 28 framed. 2 branching. ZERO both** — and
> **10 of the 17 FRONTIER TUs need the product.**

**W10 — a guarded call in a framed call sequence.** `CallSeq` is the shipped
Class A/B many-call body; this rung admits its **first call being guarded by a
conditional branch**:

```cpp
void f(int a) { if (a != 0) g(); h(); }
```

```text
7d8802a6  mflr  r12          the shipped Class A 96-byte frame
9181fff8  stw   r12,-8(r1)
9421ffa0  stwu  r1,-96(r1)
2f030000  cmpwi cr6,r3,0     <- the guard, between the prologue and the sequence
419a0008  bt    26,+8           NEGATION of the IL relation (`38` is brFALSE)
4bffffed  bl    ?g            the GUARDED call, REL24
4bffffe9  bl    ?h            the sequence continues, REL24
38210060  addi  r1,r1,96
8181fff8  lwz   r12,-8(r1)
7d8803a6  mtlr  r12
4e800020  blr
```

44 bytes, **identical at `/O1` and `/Ox`**. It is `mvp_call_seq.cpp`'s shipped
`void two(){ v0(); v1(); }` with two words inserted.

**One production, not two implementations.** The recognizer
(`c2-il/.../shapes/guarded_seq.rs`) reads the `if` itself and hands the rest of
the body to the **same** `parse_call_sequence` loop, so the tail forms, the
`MAX_SEQ_CALLS` bound, `plan_saved_gprs` and the one-call-and-a-void-tail
tail-call escape are shared rather than copied. The emitter shares
`branch_sense` with `cond_tail` for the same reason — that table's `bt`/`bf`
split had no oracle witness at all until W9, and a second copy is a second place
for it to be wrong.

## 3. The `else` arm was built, graded, and REMOVED — and that is the finding

Prediction **X3** — *"at least one new cell does not come out `Port=Match` first
time"* — was registered as the ceiling taken neat and **came true**. The seven
one-armed cells matched on the first differential run; all three `else` cells
did not.

> **`/Ox` and `/O2` TAIL-DUPLICATE the join block and the whole epilogue.
> `/O1` shares them behind one intra-section `b`.**

`void e(int a){ if(a) v0(); else v1(); v2(); }`:

| `/O1` — 52 B | `/Ox` and `/O2` — 68 B |
|---|---|
| `cmpwi cr6,r3,0` | `cmpwi cr6,r3,0` |
| `bt 26,+12` | `bt 26,+28` |
| `bl ?v0` | `bl ?v0` |
| **`b +8`** ← intra-section, no reloc | `bl ?v2` ← the JOIN, **duplicated** |
| `bl ?v1` | `addi r1,r1,96` ← the EPILOGUE, duplicated |
| `bl ?v2` | `lwz`/`mtlr`/`blr` |
| epilogue, once | `bl ?v1` · `bl ?v2` · epilogue again |

**This refutes a standing claim.** `docs/OPT_MODE.md`, restated verbatim in
`c2_core::codegen::OptMode`'s own doc comment, says the two modes *"differ in
**exactly one rule** … **never a different opcode, never a different operand
order** — only a register field."* Here they differ in **block structure**: 52
bytes against 68, one `b` against none, one epilogue against two.

**And the duplication has a threshold this lane did not crack.** At `/Ox`, with
the join at **one** call it duplicates; at **two** and **three** it emits
`/O1`'s shared `b` (`probe5.cpp`, `j1` against `j2`/`j3`). The boundary is
bracketed by exactly one cell either side, on the quantity *"how many bytes are
worth duplicating"* — a c2 cost model. `docs/CFG_SHAPE.md` §3.5 declined the
fold cost model for precisely this reason and `work/w-cross/PREREG.md` §3.2
clause 2 forbids fitting it here.

So the `3A <join>` is refused by name in the parser, **`encode_b_intra` was
deleted rather than left as an ungraded encoder** (w-frame row **F-c**: a rung
adding a code path with no coverage under the graded profile is adding a first
witness), and board **#191**'s intra-section `b` stays open — with a far sharper
characterization than it had. The positive file's `n2`/`n3` are the control that
says the mode-dependence belongs to the **`else`** and not to the guard: a
one-armed guard duplicates at no join length in either mode.

**The one-armed cell is the reason the rung ships at all.** Had the class been
drawn to include the `else`, this rung would have been a measurement and nothing
else.

## 4. `negate_test.cpp` — declined at NINE independent refusals

Registered before the implementation, and the count is **the deliverable**:
w-frame priced the cheapest frontier TU at **five** and this lane re-derived it

against the code rather than against the byte listing, which is the direction
that matters. Full table with *"what varies between these?"* answered per row in
`work/w-cross/PREREG.md` §1; the deltas against w-frame:

* **−1** — its refusal 4, *"two `bl` sites in one body — board #35 … `CallSeq`
  admits one"*. **It does not.** `CallSeq` carries `calls: Vec<SeqCall>` and
  `mvp_call_seq.cpp` grades `void two(){v0();v1();}` at 36 B and
  `void four(){…}` at 44 B. Not a refusal.
* **−1** — its refusal 2, `cmpwi`/`bt`, closed by W9.
* **+5** — its refusal 1, *"a framed body containing basic blocks"*, is a
  **bucket**: read against the code it is at least four independent facts (the
  frame-with-a-branch itself, the intra-section `b`, three targets with two
  branches naming one of them, and the r11 local). Plus two nobody had counted:
  an **`enum`** compare operand with a `2c` convert, and a **`float`**
  passthrough formal with the `_fltused` it obliges.

Two of the nine are new to the record entirely:

* **the empty-arm inversion** — `!(blendMode != 1)` is `Rel::Ne` under a `39`
  (brTRUE), whose naive emission is `bne` to the else entry. `n = 0` is dead
  (r11 already holds 0), the then-block empties to a bare jump, and c2 inverts
  to `bt EQ` straight to the join;
* **the in-body tail-merge** — both call arms end in `n = <result>` and c2
  emits **one** `mr r11,r3` at the join. Board #193's shape, inside a body
  rather than across two tail calls.

**The other frames × blocks frontier TUs were read, not assumed.**
`undname.cpp` (gap 1) is 140 B with a 112-byte two-GPR frame, two REFHI/REFLO
data-symbol pairs and five stores; `vswprnc.cpp`/`vsnprnc.cpp` (gap 2) are three
chained guards with a REFHI/REFLO pair and an 8-formal descending shuffle. All
≥ 6 by inspection. `negate_test.cpp` is still the cheapest; it is simply not
cheap.

### 4.1 A new finding that unsettles `cr6`

`docs/CFG_SHAPE.md` §3.2 states *"an explicit compare feeding a branch writes
**cr6**"*, with a record-form `addic.` the only exception. **Three frontier TUs
refute it as stated**: `undname` @0x38 `28030000 cmplwi cr0,r3,0`, `vswprnc`
@0x50 and `vsnprnc` @0x4c `2c030000 cmpwi cr0,r3,0`. All three are an explicit
compare of a **call's result in r3, immediately after the `bl`**, and each of
the same bodies later compares r3 into **cr6** (`2b030000`, `2f03fffe`). The
discriminator is unmeasured. **Recorded, not modelled** — the W10 class compares
a *formal*, never a call result, so it cannot reach the cell; an emitter that
hard-codes cr6 for a result-compare emits `409a…` where the obj has `4082…`,
which is §3.2's own fuzzy-invisible shape.

### 4.2 And a second unrecorded fold

`probe2 t1`/`u2`: **c2 propagates the branch condition's value range.**
`void t1(int a,int b){ if(a!=0) a1(b); else a1(a); v1(); }` emits `li r3,0` for
`a` on the else path, because the branch proved `a == 0`. Not in `docs/` today.
