## 2. THE MEASUREMENT — how much of the flag axis can the corpus see?

The brief asked for this first, before any design, and it decided everything
below.

### 2.1 The redundancy criterion is a proof, not an observation

For one generated case `c` and two lane profiles `p`, `q`:

* the **port's** entire input is `(IlBundle, obj_name, gy)`. It never reads the
  cl flags — `gap.rs:1534` derives `gy` from them with
  `PortC2::flags_imply_function_level_linking` and hands it in, and the
  optimization mode arrives *inside* the IL as `IlFunction::opt_word`.
  `obj_name` comes from the source name and is equal at both profiles.
* the **reference's** output is measured directly, at a **fixed `-Fo` path** so
  the `S_OBJNAME` c2 bakes into `.debug$S` is constant and the two objs are
  byte-comparable. (That is why the instrument cannot use `c2rs compile`, whose
  scratch directory differs per invocation — w-order's §2 records the same trap
  one level down.)

> **IL(c,p) == IL(c,q) ∧ gy(p) == gy(q) ∧ refobj(c,p) == refobj(c,q)
> ⟹ grading `c` at `q` after `p` establishes nothing.**

**Neither half alone is sound, and the measurement is what says so** (§2.3, P3):
`/Ox /Gy` and `/Ox` produce **byte-identical IL on all 48 fragments** and
**different objs on all 48**. An IL-only redundancy test — the obvious one, and
the one I would have written from the armchair — would have merged them and
stopped grading the COMDAT-per-function layout entirely.

And it is deliberately **not** "the verdicts agreed": `scripts/lanes.txt`
already records that `/O1 /EHsc` and `/O1` differ in **0 verdict rows** over the
fixture corpus while emitting genuinely different objs.

### 2.2 The instrument, and its control

`scripts/mode_invariance.py`. Per fragment it takes a **stride** of its cases
(never a prefix — `head -n` over a name-sorted list is the trap `expr_sweep.sh`
records, and it applies one level in: a prefix of one fragment's cases is its
first axis value and nothing else), captures the reference obj and the IL bundle
at each of the 12 lanes, and partitions the lanes by `(il, obj, gy)`.

**`--verify K` is the control that could go red.** Every Kth cell is captured a
second time and both hashes must reproduce. If any run-varying byte — a temp
path, a timestamp, the bundle's scratch base name — leaked into either hash,
every lane would look distinct, the script would report "nothing collapses", and
that reads as a *maximally conservative* result while being pure noise. It is on
by default. **1,850 of 12,948 cells re-captured, 0 disagreed.**

The two positive controls were registered before the run
(`_2026-08-04-w-modes-prereg.md` §4) and both are defect-carrying fragments:
**`63-emit-order` and `62-ctor-base-delegation` must NOT come back
flag-invariant**, because w-order's Y-a is a *demonstrated* wrong emit at
`/O1 /EHsc` on the first fragment's shape and #232 is the second's. Both came
back with **8 classes, /EHsc split out** — the instrument separates exactly where
the two known defects live.

### 2.3 The numbers — 48 fragments, 24 strided cases each, 12,948 cells

Every prediction in the prereg is scored here.

| | prediction | result |
|---|---|---|
| **P1** | `/Od` its own class on ≥95 % of fragments | **HELD** — 48 of 48 |
| **P2** | `/O1` vs `/O2` differ in IL on nearly every fragment, so nothing collapses to 1 | **HELD** — 48 of 48 |
| **P3** | `/Ox /Gy` vs `/Ox`: **identical IL** on every fragment, different objs on most | **HELD, and sharper** — IL identical **48/48**, obj differs **48/48**. This is the prediction that made the obj hash load-bearing |
| **P4** | `/EHsc` changes the IL on ≤12 fragments | **HELD, and sharper** — **6 of 48** |
| **P5** | `/Oi` over `/O1` changes nothing on 0 fragments | **HELD** — IL **and** obj identical on 48 of 48 |
| **P6** | median ≥4 classes, so no useful invariant set and the cross cannot shrink to 1 | **HELD on the median (4), REFUTED on the pessimism** — no fragment needs more than 8 and the cross shrinks **2.85×** |

```text
classes over 12 lanes: min 4, median 4, max 8; 48 of 48 fragments collapse at all

  41 fragments -> 4   O1+O1-Oi+O1-EHsc+O1-Oi-EHsc | O2+Ox-Gy+their EHsc twins | Ox+Ox-EHsc | Od+Od-EHsc
   6 fragments -> 8   the same four, split by ±EHsc
                      50-dtor-base 51-dtor-member 52-callee-name
                      62-ctor-base-delegation 63-emit-order 93-virtual-byval

  O1    vs O2       IL 48  obj 22      O1 vs O1-Oi    IL  0  obj  0   <- provably redundant
  O1    vs Ox       IL 48  obj 48      Ox vs Ox-Gy    IL  0  obj 48   <- IL-only would be WRONG
  O1    vs Od       IL 48  obj 48      any ±/EHsc     IL  6  obj 4-6
```

**The cost consequence, and the economic fact that shaped the design:**

```text
full cross           175620 gradings   14635 cases x 12 lanes
class-reduced cross   61539 gradings   2.85x smaller
single profile        14635 gradings   what expr_sweep.sh does today
```

and, per lane:

```text
O1 14635   O2 14635   Ox 14635   Od 14635      <- the optimization-mode axis, 58,540 cells
O1-EHsc 714  O2-EHsc 714  Ox-EHsc 714  Od-EHsc 714  Ox-Gy 143   <- 2,999 cells
O1-Oi 0   O1-Oi-EHsc 0   Ox-Gy-EHsc 0          <- provably redundant on the WHOLE corpus
```

> **The `/EHsc` product — the axis Y-a actually needed — is 2,999 cells, 5 % of
> one sweep run,** because only 6 of 48 fragments can see `/EHsc` at all. The
> expensive 95 % is the optimization-mode axis, which is real coverage and was
> equally ungraded.

The partition is a **per-case** property, not a per-fragment one: 6 fragments'
sampled cases disagree about their own partition. The table therefore records
the **common refinement** — two lanes are merged only if they were equivalent in
*every* sampled case — because the other direction of that error is the one that
silently drops coverage.

### 2.4 The table cannot go stale silently

`scripts/mode_classes.txt` is generated, and **every row carries a digest of its
fragment's own generated case set**. A row applies only while the digest matches;
edit a generator and the row stops applying and that fragment falls back to all
12 lanes, loudly. A fragment with **no row at all** — a newly added one, such as
the data-only fragment w-sect is writing — is likewise graded at all 12.

That is the answer to the brief's sharpest warning, *"a fragment you exclude as
invariant is one nothing will ever grade again"*: the exclusion can only ever
cost time, never coverage, and it is closed **by construction** rather than by
re-sampling and hoping the sample hits the change. (`--check` still re-derives
against a live measurement when you want one.)

## 3. What was built, the cost, and the trade-off

`scripts/mode_cross.sh` — the product, at the class representatives, as an
**unconditional row of `scripts/gate.sh`** under exactly the sweep's rules: an
absent verdict fails, a short count fails, an unrecognized verdict fails, a
strided subset forfeits the unqualified PASS. There is no `--no-cross`; an
omittable check is an omitted check, and this project has twelve recorded
instances of an absence reading as a success.

**It is affordable because the cost was removed, not because the check was made
optional** — w-book3's move, applied to a different lever:

```text
MEASURED, 61,539 cells, --jobs 8, 32-core host
  cold  (a fresh case directory)      5 min 45 s
  warm  (the same paths again)            13.8 s
both:  checked=61539 mismatches=0 graded=61151 ungraded=388 unknown=0
```

**25×, and the lever is the capture cache.** `c2rs gap` consults it and its key
includes the *source path* (baked verbatim into `.gl` and `.debug$S`), so a
per-run case directory is a guaranteed cold cache forever. `mode_cross.sh`
therefore keeps its **cases** at a stable path (`work/mode-cross/cases`,
gitignored) and its **run artifacts** in the caller's outdir, so two runs never
read each other's numbers. The gate pays 5m45s once per worktree and 13.8 s
after.

`expr_sweep.sh` cannot take that path: it drives `c2rs diff`, which does not
consult the cache at all. **Its 14,635 `/Ox` cases are a strict subset of the
cross's `Ox` lane**, so the gate now grades them twice, once uncached for 1m26s.
Left open, §8 row **Y-j** — merging the two rows is a bigger change than this
lane should make while three other lanes are in flight.

### 3.1 What I declined

* **The naive 175,620-cell cross.** 114,081 of its cells are the same
  computation twice, and the proof is §2.1.
* **An IL-only redundancy key.** It is cheaper, it is obvious, and P3 says it is
  wrong on all 48 fragments.
* **Sampling.** The cross grades every non-redundant cell. `--cross-cells N` is
  a stride for iteration and it forfeits the PASS, exactly as `--sweep-cases`
  does.
* **Fixing the 96 uncompilable generated cases** (§4). Editing those generators
  moves the corpus total every lane is quoting today. Filed, not done.
* **Dropping the duplicated `Ox` lane** from the cross to save 14,635 cells.
  The cross's `Ox` is graded by `c2rs gap` and the sweep's by `c2rs diff`, and
  the two are not the same check — `diff` additionally asserts the reference
  **replay** is byte-exact. Removing the row on an assumed equivalence is the
  shape this rung exists to argue against.

## 4. The defect this lane found on the way — `expr_sweep.sh` graded 96 cases it never graded

`c2rs diff` prints **four** verdict shapes. The sweep's grading loop was one arm:

```sh
case "$verdict" in
    *Mismatch*) ... ;;
esac
```

`case` in `sh` is **case-sensitive**, so that arm matches `Port=Mismatch` and
misses `ReferenceReplay=MISMATCH` — the P0.1 **oracle itself** failing, spelled
in capitals. It also misses `ReferenceError:` and anything unforeseen. All three
fell out of the `case` with no default arm, were counted in `_n`, and landed
inside `checked=14635 mismatches=0`.

**Measured over the whole corpus at `/Ox /GS- /c`: 96 of 14,635 cases print
`ReferenceError` — `cl.exe` refuses to compile the generated source.**

```text
14635 verdict lines bucketed
  10126  Port=Match
   4413  Port=NotImplemented
     89  ReferenceError (capture_reference produced no obj)
      7  ReferenceError (replay produced no obj)
      0  Port=Mismatch
```

Eleven fragments: `99-chain-tail-fp-load` 17, `98-cmp-order` 16,
`93-virtual-byval` 15, `34-volatile-formal` 12, `99-chain-tail-load` 10,
`96-cmp-two-calls` 8, `98-chain-link-arg` 4, `97-chained-call` 4,
`72-member-call` 4, `73-framed-member-call` 3, `45-offset-run` 3. Two causes:

```text
error C2662: 'A::gi' : cannot convert 'this' pointer from 'volatile A' to 'A &'
    int f(volatile A* p) { return p->gi()- 20; }       <- a volatile receiver
                                                          calling a member that
                                                          is not volatile-qualified
error C2065 / C4716
    intstruct S { virtual int Make(); int m; };        <- a generator typo
    int f(W* p) { p->v00(); }                          <- no return in an int f
```

The counts the gate re-derives were **real**; the grading behind 96 of them was
not. This is the same class as the row it sits in — `checked` was standing in
for `graded`, and `mismatch 0` over a population nothing ruled on.

**Fixed here, in the instrument.** The classifier is positive (`Port=Match` and
`Port=NotImplemented` are the OK set, everything else is named), `graded` is
reported separately from `checked`, an **unrecognized** verdict is fatal — the
next verdict string nobody foresaw must not be the next silence — and the 96 are
carried as `C2RS_SWEEP_MAX_UNGRADED=96`, a number with its reason and its eleven
fragments written next to it, the discipline `sweep_mode.sh`'s
`C2RS_SWEEP_MODE_MAX_DISAGREE` already carries. `gate.sh` requires the new
fields and calls a log without them **NO-RESULT**, not `ungraded=0`.

## 5. What the corpus cannot express — at any flag profile

The coordinator's mid-lane correction, and it is the more valuable half. w-sect's
data-only-TU defect is not a flag gap: **no generator emits a TU without a
function, so no flag profile would have helped.** `scripts/sweep_shapes.py`
enumerates the axis. It is a text scan and approximate in one direction only — a
marker reported PRESENT is present; the actionable output is the **zero** rows,
and a real parser could only find more of them.

functions, or static locals, or `try`/`throw`, costs an afternoon each and opens
a class nothing in this tree can currently represent. If a lane has to be chosen
between "widen the flag cross further" and "close a zero row", **close the zero
row**.
