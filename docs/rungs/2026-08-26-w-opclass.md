## 2. What it read, and how

`dump_opclass.py` hard-codes **one** address — the operand decoder's entry
`0x10b3d610` — and derives the class table (`0x10b25e48`), the class bound
(`0x1c` → 29), the jump table (`0x10b3d954`), all 29 targets, the epilogue and
every primitive callee from the operand bytes it decodes there. It walks each
arm's CFG recording conditionals as their **own rows** with both successors, and
derives *"this callee does not return"* structurally: class `0B`'s
`call 0x10b33526` has **class `0C`'s own arm** as its return address.

**The checks nobody had run on this table:**

* **29 entries, 27 distinct arms** — `0x10b3d922` shared by classes `0D`/`11`,
  `0x10b3d941` by `10`/`16`. "N entries" is not "N arms" for the third time in
  this tree (R2's encoder `111 → 79`; `w-ilarms` ran it on the *record* table
  and got 62 of 62).
* **29 of 29 contained**, zero-byte gap between the body and the table.
* the class table's own bytes bound it at **`0x00`…`0xCB`** (first illegal class
  byte at opcode `0xCC`), where `#1591` publishes `0x00`–`0xBF`. Nothing
  downstream depends on it; a published extent narrower than the bytes needs a
  citation and that one had none.
* `--cross` against `dump_ilarms.py`'s independent reader: class table VA, the
  class byte for all 95 handled opcodes, 0 out-of-bound — `ALL AGREE`.
