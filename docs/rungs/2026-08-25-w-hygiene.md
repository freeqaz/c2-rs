## 3. ITEM 2 — `repo_root()` AT RUNTIME

### 3.1 The fix, and the thing §7.7's shape does not say

`crates/c2-reference/src/lib.rs:81` was
`Path::new(env!("CARGO_MANIFEST_DIR")).join("../..")` — the repo root captured
when the binary was **compiled**. It now resolves at runtime: `C2RS_REPO_ROOT`
if set → else a walk up from `current_exe()` then `current_dir()` → else the
`env!` value as last resort. That is §7.7's shape.

**But §7.7's marker alone does not fix #3470, and this is the load-bearing
correction this item makes.** §7.7 says walk up *"for a marker such as
`Cargo.toml` + `crates/`"*. The tree #3470 was found in is a **scratch checkout
under `work/`** — and a checkout has a `Cargo.toml` and a `crates/`. The nearest
marker **is** the scratch tree, so a plain nearest-marker walk finds it, resolves
`compilers/` relative to it, and reproduces `SKIP: toolchain absent` + exit 0
exactly as before.

The search therefore returns **two** answers in one pass — the nearest marker and
the nearest marker that also carries `compilers/X360/16.00.11886.00` — and
prefers the second. It keeps walking past markers that have no toolchain.

**That correction is watched, not asserted.** A mutation removing the toolchain
condition (making `with_tc` the nearest marker — precisely the §7.7 reading)
takes `the_search_walks_past_a_scratch_tree_to_the_root_that_has_the_toolchain`
**RED**, and it is green on revert.

### 3.2 P2a — measured, with the positive control §7.7 asked for

§7.7 prices the item as *"one function, plus the tests that assert a relocated
binary still finds the toolchain — which is exactly the case #3470 discovered by
accident and nothing currently covers."* Four rows, one binary per row, run
against the same fixture:

| binary | built in | result |
|---|---|---|
| **base code** | a scratch tree under `work/` | `SKIP: toolchain absent`, **exit 0** |
| **fixed code** | the same scratch tree | **4/4 bodies decoded — graded** |
| fixed code | run from a directory with no repo above it | `SKIP: toolchain absent`, exit 0 |
| fixed code + `C2RS_REPO_ROOT` | the same directory | 4/4 bodies decoded — graded |

**Row 1 is the positive control and it fires.** Row 3 is `CLAUDE.md`'s
degrade-cleanly hard constraint, checked rather than assumed: absent toolchain
still SKIPs, still exits 0, never panics.

A fifth, incidental demonstration is on record from §2.1's F arms: the same
`c2rs-b1` binary grades 4/4 with `C2RS_COMPILERS`/`C2RS_WIBO` set and prints
`SKIP: toolchain absent` with them unset — **#3470 in one command, on a binary
built for another purpose entirely**.

### 3.3 P2b — HOLDS, and it is the more useful half

**Prediction (p = 0.85): after fixing only `c2-reference::repo_root()`, binary
size still tracks build-directory path length.** It does, and the mechanism is
sharper than the prediction. Three builds of the fixed code at path lengths
2/4/8, and the same three at base:

| dir chars | fixed code | base code |
|---|---|---|
| 2 | 6,145,016 | 6,142,128 |
| 4 | 6,144,976 | 6,142,160 |
| 8 | 6,145,008 | 6,142,128 |

Six distinct md5s. **Two things fall out, and the second was not predicted:**

1. **The fix does not remove the capture.** Reading the binary directly — not
   inferring from size — the fixed binary still contains the build path **three
   times**, one of them the `…/crates/c2-reference` string. **Because the `env!`
   fallback §7.7 prescribes IS the capture.** A `&'static str` literal occupies
   `.rodata` whether or not control ever reaches it. *Keeping the fallback and
   removing the string are mutually exclusive*, and §7.7's shape asks for both.
2. **`#3525`'s monotonicity does not reproduce at HEAD, on either arm.** The
   fixed middle build is *smaller* than the shortest-path one; the base arm has
   two **equal** sizes at different md5s. `#3525` read *"monotonic in path
   length, which `rustc` nondeterminism would not be"* — the *mechanism* it
   named is confirmed by the string read above, but the *monotonicity* is an
   alignment artefact of one commit and must not be used as a diagnostic.
   **The invariant that survives is the one that matters for cost work: the
   binaries always differ.**

### 3.4 Why #3525 is left OPEN, and the decline floor that decided it

`#3525` closed with the padding mitigation *"rest[ing] on the **untested**
assumption that `CARGO_MANIFEST_DIR` is the only path-length-sensitive capture."*
**Read at base before this lane's prereg was written, and it is false.** Thirty
`env!(` sites under `crates/`; **three** live in the release binary:

| site | what it is |
|---|---|
| `c2-reference/src/lib.rs:81` | `repo_root()` — **fixed here**, though its literal survives as the fallback |
| `c2-harness/src/provenance.rs:44` | `repo_root()` — **deliberately** compile-time |
| `c2-harness/src/lib.rs:494` | `fixtures_dir()` |

The other 27 are one `#[cfg(test)]` site and 26 under `tests/`.

**`provenance.rs` is why this stops here.** Its doc argues *for* compile-time
capture on the merits — *"a binary built inside `.claude/worktrees/<lane>`
reports that worktree as the repo root. **For provenance that is exactly
right** — the reader wants to know which tree was measured."* Overriding a
documented decision in another crate's file is not a hygiene fix; it is a
semantics change, and prereg §2.3 registered the decline floor before any of
this was measured. **Closing #3525 requires deciding whether provenance should
report the tree a binary was BUILT in or the tree it RUNS in, and that decision
is not this lane's.**

**Padding remains ranked LAST, and is now ranked last on evidence**: it was
already rejected for resting on an untested uniqueness assumption; that
assumption is now tested and false.

## 4. ITEM 3 — `configure_existing_worktree.sh`, TWO DEFECTS

### 4.1 `#3500` — the positive control, on a real worktree

`MAIN_REPO` was `dirname $0/..`. Every worktree carries its own `scripts/`, so
for a **sibling-directory** worktree invoked through its own copy, that path
**is** the worktree; the equality test fires and the script exits 0 having
configured nothing.

**Reproduced on a real `git worktree add`, not a simulation**, and the three
shapes were all checked:

| shape | before | after |
|---|---|---|
| sibling worktree | `"is the main repo; nothing to configure"`, **exit 0** | configures; `OK: w5_chain.cpp -> 4/4`, exit 0 |
| `.claude/worktrees/` | configures (already worked) | configures — **unchanged**, checked not assumed |
| the main repo itself | `"is the main repo"`, exit 0 | `"is the main repo"`, exit 0 |

`MAIN_REPO` now asks git: `rev-parse --path-format=absolute --git-common-dir` is
the main repo's `.git` from a linked worktree **and** from the main repo itself,
which is exactly the question being asked. The `$0` arithmetic survives only as a
**warned** fallback for a tree that is not a git checkout.

**The failure direction is what makes this worth a control**: an unconfigured
worktree has no `compilers/`, so the differential degrades to
`SKIP: toolchain absent` and grades every change as passing. The script's own
header says this in its first paragraph; the script then skipped four of five
worktrees.

### 4.2 `#3516` — one comment, in live onboarding guidance

`./target/release/c2rs bench   # every fixture, the correctness gate`.
`cmd_bench` → `oracle_selftest` exercises the **reference** and never calls
`PortC2::build`: **0** probe hits against a clean `summary: 391 pass, 0 fail`,
against **73,083** under `gate.sh`. `391 pass` grading no port build is
indistinguishable from `391 pass` grading 391 of them.

`CLAUDE.md` § Layout has always had this right, so the defect was localisable to
one comment — printed on **every worktree setup**. `bench` is kept and described
as what it is (the oracle self-test, determinism + capture stability); the
correctness-gate label moves to `scripts/gate.sh`, the next line down.

## 5. ITEM 4 — THREE NUL BYTES

`bundle.rs:3440`, `:3449`, `:3458` held `b"junkjunk\0"` with a **literal 0x00**
rather than the two-character escape. The two forms are the **same bytes**, so
this is a source-encoding change with no semantic content — and the encoding was
removing a 4,120-line file from every text search in the repo.

**The detector was proved to fire before anything was believed**, because `grep`
cannot do this. Both broken methods were run against `printf 'a\0b\n'` and are
on record failing on it: `grep -c $'\0'` counts **lines**, and
`LC_ALL=C grep -qP '\x00'` **does not fire at all**. The check used compares byte
counts through `tr -d '\000'`; it fires on that file and does **not** fire on
`printf 'ab\n'`, so it is specific as well as sensitive.

| | before | after |
|---|---|---|
| NUL bytes in `bundle.rs` | 3 | **0** |
| `.rs` files under `crates/` holding a NUL (**re-derived**, not inherited from #3513) | 1 | **0** |
| `grep -n junkjunk` | `binary file matches`, no content | all three lines **with content** |

`cargo test -p c2-il --release`: **687 passed, 0 failed**, and the three tests at
those lines — `the_root_record_fence_reads_the_linkage_byte`,
`a_module_block_carrying_statements_refuses_class_b`,
`class_b_without_a_module_block_refuses` — each pass by name.

## 6. ITEM 5 — THE `#3156` FUNNEL CHECK

### 6.1 The prescription is wrong-sized, measured before a line was written

`#3156`: *"a one-line check — `git ls-files` against `.gitignore`'s own
patterns — would have caught all nineteen."*

    git ls-files -c --ignored --exclude-standard | wc -l   ->  8041

**8,041 tracked files match `.gitignore` at HEAD.** Essentially all under
`/work` (`w-mmio` 918, `emitpred` 277, `w-prod` 209, …), which `.gitignore:24`
ignores wholesale and which ~200 lanes have force-added evidence into for months.
**A gate on that number is red at HEAD by 8,041** and could ship only behind an
8,041-entry allowlist — not a one-line check, and not a gate.

The classes `CLAUDE.md` actually enumerates under "Never commit" read **0**,
which is `2c0de2ad4` having worked. That is the guard that ships. **The wide
number is printed every run as an advisory**, so the wide version cannot be
re-proposed without its price visible.

Two traps met and demonstrated rather than asserted:

* **`git check-ignore` does not report TRACKED files without `--no-index`.** A
  guard built on it reports clean over exactly the population it polices. Shown
  both ways on `work/emitpred/MAGNITUDE.md`.
* **`grep` cannot test for a NUL byte** — §5's finding, in the same wave.

### 6.2 Proved red before trusted — and it found a live violation

`--self-test` plants one violation per covered class in a **throwaway** repo
(never this one, so a killed run cannot leave a plant behind): `.obj`, `.o`,
`_CL_*`, `.il`, `.profraw`, `target/`, and an absolute machine path — **7
classes, all RED**, control GREEN, each reversible, and an **empty index refused
with exit 2**, because a clean report over zero files is not a clean report
(#3470, #1002). End-to-end, in this repo: `git add -f crates/planted_control.obj`
turned the gating test RED and **named the file**; removing it turned it green.

**The guard's first real run found a live pre-existing violation.**
`scripts/w_tu_census.sh` carried two hardcoded absolute machine paths — a `main=`
assignment and a literal `--cwd` — which `CLAUDE.md` forbids in those words. Both
are now env-driven (`C2RS_MAIN_REPO` / `C2RS_DC3_ROOT`), with the main repo asked
of git rather than derived from `$0` — **#3500's defect, one directory over.**

It also flagged the comment *describing* the removal, because the check is
content-based. That comment now uses a placeholder and records why.

### 6.3 AND THEN IT FLAGGED ITSELF — the finding this item is actually worth

The audit went green, was committed, and went **RED on the very next run** at
**9,618** tracked files having passed at **9,616**. The two extra files were the
guard and its test, and the violation reported was
`scripts/tracked_artifact_audit.sh`: its `--self-test` plant list carried a
literal `/home/<a-user>/…` string, and class 2 scans the **content** of every
tracked file under `scripts/`.

**The first run could not have seen it.** It ran *before* `git add`, so
`git ls-files` did not list the file being validated. **A guard validated
against a population that does not yet contain the guard is not validated** —
the same shape as #3513 (an instrument not reading one file at all cannot be
caught by re-running it with a different parameter) and #3470 (only a
denominator can catch an absence), arriving this time through the **enforcer**
rather than the enforced.

It was caught by `cargo test --workspace --release` — **the wiring from the
previous commit doing its job on the next run**, which is the only reason this is
a commit rather than a defect somebody finds in a month. Fixed by assembling the
plant string at runtime from two halves, so the file is clean under its own rule.
**Self-exemption was the alternative and was rejected: a rule its own enforcer is
exempt from has exactly one guaranteed blind spot, and it is the enforcer.**

### 6.4 Wired so the exit status gates something

Two tests under `cargo test --workspace`, needing `git` and no toolchain:
`the_index_carries_no_artifact_claude_md_forbids` (and it asserts the
**denominator** is nonzero, from outside), and
`every_class_the_guard_claims_is_watched_going_red`. **The second gates the
guard's own controls**, which is the part that matters: if a pattern is narrowed
later and a class stops being detectable, the tree audit stays green — it *is*
green — and only the self-test can tell.
