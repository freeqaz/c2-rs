## 2. Where the guards had to go, and why that is the stronger form

**This lane owns `crates/c2-harness/src/gap/` and nothing else.** Peer
`w-section` is single-occupancy in `crates/c2-core/src/coff/`; peer `w-three`
owns `crates/c2-il` and `crates/c2-core/src/codegen/`. **All three unguarded
sites are in `crates/c2-il`**, and inside it `parse_segment_detail`,
`DATA_SYM_UNRESOLVED`, `DATA_SYM_LINKAGE` and `gl_extern_data_names` are all
`pub(crate)` and unreachable across the crate boundary.

The route that exists is `IlBundle::census_functions()` — **public** — driven by
hand-built synthetic `.ex` + `.gl` bundles, asserting on `FnVerdict::key()`.

**That is not a workaround, it is the better instrument**, and the reason is
#3199's own complaint. The published ranking is not built from
`DATA_SYM_UNRESOLVED` the constant; it is built from the **string**
`data-sym-unresolved`, because `scan.rs:654` writes

```rust
format!("emit-cflow-modeled-key|{}", f.verdict.key())
```

and `report.rs:230` strips that prefix back off. A guard on the constant would
pass a mutation that renamed the constant *and* its uses while the published key
moved. **A guard on the key string cannot.**

## 3. The cells — four of them, each pair differing in exactly one thing

One transcript, four `.gl` variants, two body variants. The transcript is
`??__EsLicense@@YAXXZ`, a **real** `c2.dll` capture at the workload's own flags
(`/nologo /c /GR /O1 /Oi /EHsc`), whose body decodes to
`MultiArgTailCall { arg_sources: [SymAddr(0xF909), SymAddr(0xFC09), Lit(0)] }`.
It is **transcribed** from `c2-il`'s own `wr1_dyninit::TOMCRYPT_DYNINIT` rather
than referenced, because that module is `#[cfg(test)]` inside a crate this lane
does not own — a copy of a capture, not a second source of truth.

| cell | what differs | measured key |
|---|---|---|
| **A** | `.gl` names the callee only — token `0xF909` is **unnamed** | `data-sym-unresolved:eof` |
| **B** | the same `.gl` **plus** a record for `0xF909` at linkage **`01`** | `data-sym-not-extern:eof` |
| **C** | cell B with **one byte changed**: linkage **`02`** | `callee-unresolved-tail-call:eof` — **neither** data-sym key |
| **D** | cell C's `.gl`, body marker composed `4C 4F 11` not bare `4C` | `call-arg-multi-sym:eof` |

**A and B differ in exactly one fact** — whether `.gl` names the token — and
that is precisely the discrimination M4 destroys. **B and C differ in exactly
one byte**, and the guard **asserts that byte count is 1** rather than trusting
it: the two `.gl` are compared position by position and the differing-byte count
must be `1`, so a cell pair that drifted apart fails instead of passing on a
coincidence.

### 3.1 The arity fence is graded as a SERIES, not a cell

**#3147** is the standing correction `w-slots` paid for: told to read the charge
off its fixture's own obj it did, **the objs read 3, and the series was `2n+1`,
not `3n`**. So the arity fence gets a series:

| n | body | measured key |
|---:|---|---|
| **1** | second symbol argument replaced by a literal | **`multiarg-tail-call`** — IN CLASS |
| **2** | the transcript as captured, composed marker | `call-arg-multi-sym:eof` |
| **3** | the literal argument replaced by a third symbol | `call-arg-multi-sym:eof` |

**n = 1 is the positive control and it is load-bearing**: without it the two
refusals below would be consistent with a fence that refuses its whole input,
and the guard would be a constant rather than a discrimination. The series also
catches two different weakenings — `syms > 2` breaks n = 2, `syms > 3` breaks
n = 3 — where a single cell catches only one.

### 3.2 And the `two_sym_thunk` exemption, which had the same property

`calls.rs` admits `syms == 2` when `body_start_is_bare` — the bare `4C` every
`??__E`/`??__F` dynamic-initializer thunk carries (W-R1). Guarded as a **pair on
otherwise identical bytes**: bare must **not** take the arity refusal, composed
**must**, and the two segments must differ by exactly the two bytes the composed
marker adds. That third assertion is what stops the pair passing if something
other than the marker moved.

## 8. Found and not taken, ranked

1. **`emit-cflow-modeled-key|*` has no printer, so #3177's own table is not
   reproducible from a scan log.** `report.rs:230`'s
   `cflow_emitted_modeled_keys` is called by no printer;
   reproducing the ranking that dispatched this wave needs `--jsonl` plus a
   script. `w-bind16` found it and did not take it because `gap/` was another
   lane's; **this lane owns `gap/` and still did not take it**, because adding a
   printer adds `gap-metric` keys and **P-K must be 394 at both ends** — a
   required-zero byte delta and a new printed key are the same commit's two
   halves and cannot both happen. **The right shape is a separate lane that
   prices the key-count change explicitly**, and it is one function.
2. **The `two_sym_thunk` exemption was unguarded too, and nobody had counted
   it.** #3199 registered three unguarded surfaces; this is a **fourth**, found
   only because the M1 cell had to be built non-bare. It is now guarded. **The
   generalization is the finding: #3199's list was not exhaustive, and nothing
   enumerates the fences that have no test.** A mutation census over
   `crates/c2-il`'s refusal sites would be a lane.
3. **`Bindings::resolve` itself is unguarded from this side.** Cells A and C
   pin `resolve_data`; nothing here would catch `resolve` being widened to admit
   the `25` string-literal separator (`gl.rs:1085`) — which is exactly the L3
   rung `w-bind16` ran and measured `mismatch` **0** on, **with the risk never
   exercised**. A guard for it needs a `.gl` carrying a `26`-separated record,
   which these cells do not build.
4. **The `.gl` record builders here duplicate `c2-il`'s own private test
   helpers** (`gl.rs`' `record`/`record_flags`, `gl_symbol_index_binds_tokens…`).
   Two spellings of one format is how a format drifts. Not taken because
   unifying them means a `pub` in a crate this lane does not own.
5. **The merge funnel's "graded tree identical at both ends" check cannot be
   met by any lane that LANDS a test.** It was asked for here and is
   structurally impossible: `gate.sh` content-hashes `crates fixtures scripts`,
   so a lane whose whole deliverable is `#[cfg(test)]` code under `crates/`
   moves the hash **by construction**. The check that *does* discriminate for
   such a lane is the one `README.md` § "Lane kinds" already specifies — a
   line-for-line identity diff of the gate's counts — plus the **release binary
   sha256**, which is the direct statement that nothing landed can reach a
   graded byte. **Both are recorded in §7.2.** The funnel should ask for the
   binary hash from a test-landing lane and the tree hash only from a
   revert-everything lane; asking for the tree hash of a lane that lands code
   invites the lane to either fail a check it cannot pass or quietly not run it.
6. **Nothing checks that a `gap-metric` key's *value type* is stable.** #3181's
   two-string / two-float finding is a fact nobody asserts: a key that changed
   from an integer to a float would move every downstream filter and no test
   would see it. Cheap, and in this lane's own crate.

## 9. A note on what this lane did NOT establish

**GREEN and RED here are scoped to `cargo test --workspace --release`, 42
targets — the probe this lane registered.** §7.3 records `gate.sh` on the
**unmutated** tree; **the 381 × 18 fixture gate was not re-run under each

**And a guard that fires is not a correctness proof.** These cells are
synthetic; they grade the census's *key assignment*, not whether the key is the
right thing to refuse on. `mismatch 0` is still an absence
(`docs/STATUS.md` trap 5), and nothing here changes that.
