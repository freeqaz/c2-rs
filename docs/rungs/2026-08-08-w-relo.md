## 2. RELOC-EQ — the rule as shipped

> For a function whose **bytes are already exact**, let `R_ref` be its reference
> `.text` COMDAT's relocation records **in disk order** and `R_port` the port's
> own plan **in the order `PortC2::build` writes it**. The relocations MATCH iff
> the two are equal as **sequences**: same length, same `va`, same **whole
> packed** 16-bit `ty`, same target.

Five decisions, all five registered in `PREREG.md` §2 before the code existed:

1. **A sequence, and nothing is sorted at the compare.** Two sets equal as
   multisets and swapped in order produce different obj bytes.
2. **`ty` is compared WHOLE.** The high byte carries `NEG`/`BRTAKEN`/
   `BRNTAKEN`/`TOCDEFN`; `REL24|BRTAKEN` = `0x0206` is a different relocation
   from `REL24` = `0x0006`, and `c2-obj::reloc`'s module doc names a whole-word
   compare against a masked constant as the defect its `Reloc` type is shaped to
   prevent. This lane does the *opposite* comparison and inherits the same rule:
   mask nothing.
3. **Target identity is a NAME through the symbol table, never an index.**
   Indices differ across objs legitimately, and the port has no obj here at all
   — it has names. Where a census binding is involved the key is
   `FnCensus::emit_name` (**#918**), which is the binding the surrounding walk
   already uses to decide which row *is* which COMDAT.
4. **Three target kinds as a typed enum, not a string with a prefix.** A
   section-definition symbol's "name" is a *section* name, which is not unique
   in a `/Gy` obj; as a variant, `Section(".rdata")` can never compare equal to
   `Symbol(".rdata")`. A `PAIR` record's index field is **a displacement and not
   an index** (PE/COFF rev 6.0) and is compared as a number.
5. **Fail closed, into a bucket and never into a credit.** An undecodable table,
   an index out of range, **or an index landing on an auxiliary record** refuses
   the whole obj, and every byte-exact function in it becomes
   `fnbyte-reloc-unknown` — ungraded, not credited.

### What REFUSES, precisely

* a function whose **bytes already differ** is not re-graded — a wrong body
  scores zero and there is no second way to score zero;
* `partial` / `refused` / `unbound` / `nobytes` are untouched;
* a byte-exact function whose reference table did not decode is
  `fnbyte-reloc-unknown`, printed as the residue and counted (§3.1).

### 2.1 ONE LOCATOR — the writer calls the plan the instrument grades

`crates/c2-core/src/coff/writer.rs`'s `/Gy` branch used to build its relocation
record list inline. It now calls **`comdat::text_reloc_plan`**, and so does FBM.
Only the NAME → symbol-index resolution stays in the writer, because only the
writer has a symbol table — and the two-table split is preserved deliberately: a
`REL24` resolves in the callee table and a data reference in the data table,
never one list searched for both, which would silently resolve a data symbol
against a callee of the same spelling.

This is **board #880's argument one field along**, and it is load-bearing:

> a second implementation in the harness could drift from the emitter, and an
> alarm that is green about bytes the port does not emit is worse than the blind
> one it replaced.

The lift is what makes `fnbyte-reloc-differs 0` mean something if a later lane
ever drives it there. The gate across the lift is 18/18 PASS, 0 mismatch (§9).

### 4.2 The witnesses

Per differing function the scan publishes
`fnbyte-reloc-differs-fn|<shape>|<kind>|n<port>/<ref>|@<index>|<port record> => <ref record>|<symbol>`.
The largest single signature is **51 functions**:

```text
tail|target|n1/1|@0|REL24@4 -> ??1?$list@PAVObjectDir@@…@stlpmtx_std@@QAA@XZ
                 => REL24@4 -> ?clear@?$_List_base@PAVObjectDir@@…@stlpmtx_std@@QAAXXZ
   e.g. ??1?$ObjDirItr@VBaseMaterial@@@@QAA@XZ
```

An STL `list` destructor whose body c2 expanded, leaving the caller's branch
pointing at what that destructor itself tail-calls. Two more shapes worth
naming:

```text
seq |target|n2/2|@1|REL24@20 -> ?Issue@D3DQuery@@QAAJK@Z  => REL24@20 -> D3DQuery_Issue
tail|target|n1/1|@0|REL24@0  -> ??1logic_error@stlpmtx_std@@UAA@XZ
                             => REL24@0  -> ??1exception@std@@UAA@XZ
```

The first is a wrapper collapsing to the C entry point it forwards to; the second
is a base-class destructor chain flattened by one level.

**`fnbyte-reloc-witnesses` is 277 over 861 pairs, and that is an AGGREGATION.** A
witness key is `(shape, kind, counts, index, target pair, symbol)`, so two TUs
emitting the same template instantiation with the same targets share one key —
exactly the aggregation `fnbyte-differs-witnesses` **1,333** already has over
`fnbyte-differs` **3,195**. `fn_byte_reloc_signatures` collapses the 277 further
to **223**. w-fnbyte §5's rule inherited whole: **count pairs, never distinct
symbols, and never quote one against the other.**

### 4.3 TWO READERS, WRITTEN INDEPENDENTLY, AGREE ON EVERY ONE OF THE 861

This lane started off master `cda124c`. By the time it finished, master carried
lane **`w-drop3`**, whose board **#986** reads *"861 `fnbyte-exact` bodies call a
different symbol than c2 does"* — **the same number, on the same corpus, from a
different reader**, reached while this lane was writing its own.

| | `w-drop3` (#984, #986) | `w-relo` (#1006) |
|---|---|---|
| reference side | `ObjImage::text_comdat_call_targets` — `REL24` records only | `ObjImage::text_comdat_relocs` — **every** record |
| compared | `(offset, name)` pairs, ordered | offset · **whole packed type word** · target, as a sequence |
| port side | `comdat_function_body().calls` | `comdat::text_reloc_plan(calls, data_refs)` |
| lands where | a **side count** beside `fnbyte-exact` | **inside the partition** — `exact` shrinks |
| reads | `calltarget-disagree-exact` **861** | `fnbyte-reloc-differs` **861** |

Two equal totals are not evidence that two readers agree — they are consistent
with each reader finding 861 *different* functions. So the rebase turned it into
a **per-function** control, published as three directional keys:

| key | measured | known answer |
|---|---:|---|
| `fnbyte-reloc-vs-calltarget-both` | **861** | — |
| `fnbyte-reloc-vs-calltarget-calltarget-only` | **0** | **0** — a `REL24` target disagreement IS a record disagreement; the full compare cannot miss it |
| `fnbyte-reloc-vs-calltarget-reloc-only` | **0** | none — a data-symbol `REFHI`/`REFLO` target, a type or an offset would land here legitimately, so this is measured and not predicted |

**Every one of the 861 is the same function under both readers.**

#### The rebase also caught a live erasure, and it is worth stating plainly

`w-drop3`'s walk guards on `matches!(v, FnByte::Exact | FnByte::Differs { .. })`
and buckets on `if v == FnByte::Exact { "exact" }`. When it was written,
`FnByte::Exact` **meant** *"the bytes are c2's"*. This lane narrowed it to *"the
bytes AND the relocations are c2's"* — so after the merge, every function that
key exists to report lands in `FnByte::RelocDiffers` instead, and left alone
**`fnbyte-calltarget-disagree-exact` would have printed 0.**

A finding deleted by a change to a *different* predicate, with no test red and no
conflict marker: the merge is textually clean, because the two lanes never touch
the same line. Both sites read `bytes_exact()` now — which is the predicate that
walk always meant — and the eight `fnbyte-calltarget-*` keys are **unchanged to
the digit** across this lane, checked by `diff` (§1).

**The generalization, for the merge funnel:** *when a lane narrows the meaning of
a shared predicate, every existing reader of that predicate is a candidate
erasure, and `git` will not say so.* The thing that caught it here was reading
`w-drop3`'s walk while resolving an unrelated conflict twenty lines away.

## 6. WHAT THIS LANE DID NOT DO

* **No repair.** The prereg refuses it in advance (§6): *a reloc-differ is a
  finding, not a repair; the repair is a later rung, priced from the families
  this one names.* **#1013** is the queue.
* **No relaxation of a control.** C3 was written to stop the lane if it fired.
  It did not.
* **No new gate.** FBM and every `fnbyte-` key stay out of `scripts/gate.sh`
  (`FUNCTION_BYTE_MATCH.md` §0). This licenses no emit.
* **No re-grading of the `differs` bucket on relocations.** A body whose bytes
  are already wrong scores zero and there is no second way to score zero.

**The interaction the next lane needs.** **#968** measured SPLICE-0 holding on
1,967 of the 3,195 byte-differs, 726 of which have a callee the port already
lowers byte-exactly. An emitter that acts on that must get the **relocation**
right as well as the bytes — and this instrument is now the thing that would
catch it if it did not. Before this lane, a splice emitter could have moved 726
functions from `differs` to `exact` while pointing every one of them at the
wrong symbol, and the scan would have read it as progress.
