### 3.2 The clause, and why it is one line

`lit_arg_tail_call` required every non-literal slot to be the formal already in
that argument register. `mmioGetInfo`'s slot list is
`[Formal(1), Formal(0), Lit(72)]`.

That requirement is **right at a tail call**: there is no park and no prologue,
the argument setup *is* the body, and `permute_args_text`'s walk has never been
captured beside a `li`. It is **wrong at the sequence site**, where two fences
already run downstream and already compose with literals:

* `callseq-early-return-permuted-args` calls `park_in_class` on
  `slot_sources(...)`, whose doc reads: *"a literal slot reading as a **fixed
  point** — the value is already where it belongs, because it is about to be
  materialized there by a `li` … Shared by the parser's fence and the emitter's
  backstop so the two cannot disagree about which slots move."*
* the five-clause `callseq-multiarg-lit-*` fence — one call, a guarded early
  return, no saved GPR, no W10 guard, ≤ 1 literal, none in slot 0.

**The composition was built and never reached.** `ArgSite::{Tail, Sequence}`
makes the axis explicit rather than inferring it; nine of `tail_call_shape`'s ten
call sites pass `Tail` and keep the historical behaviour to the byte.

This is the **third** item on the list board #1444 published as two, and
`w-memcpy` §1 had already found it — *"between them sits `call-arg-lit-permuted`
… it is in `tail_call_shape`, the locator the tail-call form shares, so widening
