## 2. The carrier — what is now expressible that was not

```rust
pub struct Root {
    pub tok: u32,                    // the root symbol of one `B9 <tok> <TYPE>`
    pub is_bind: bool,               // is it a temp bind head (`26 <tok>`)
    pub base: Option<u32>,           // what THAT root is itself rooted at
    pub offsets: Option<Vec<i32>>,   // the literal LIST, #908 — None = sum only
}
pub struct ProducerRoots { pub value: Root, pub lvalue: Root }
pub struct Producer { id, kind, uses, first, roots: Option<ProducerRoots> }
```

```text
  r.store_root_is_bind()            the SCHEDULE bit of #1235.
```

### 2.1 The value's root token was one `..` pattern from being kept

`codegen/leaf/store.rs`'s `parse_simple_gpr_run` has had **both roots live at
one site since board #1199**:

```rust
  let (base_tok, base_reg, base_off) = match b {
      IlOp::Load(t)                     => (*t, reg_of(*t)?, 0i32),
      IlOp::BoundAddr { tok, base, off} => (*tok, reg_of(*base)?, *off),
  };
  let (lit, src, value_bound) = match v {
      IlOp::Load(t)          => (None, reg_of(*t)?, false),
      IlOp::Lit(k)           => (Some(*k), SCRATCH_REG, false),
      IlOp::BoundAddr { .. } => (None, SCRATCH_REG, true),   // <- the token
  };                                                         //    is DISCARDED
```

The lvalue's root was kept because the schedule needs it (`schedule::Stmt::base`)
and the value's was thrown away by a `..`, **because `Producer` had no field
that could receive it**. That is the whole mechanism behind nine deaths, and it
is one line.

### 2.2 `eat_offset_adds` did NOT change — said explicitly, because a peer reads it

`crates/c2-il/.../designator.rs` gains `eat_offset_adds_list`.
**`eat_offset_adds`'s signature and behaviour are unchanged**; both now delegate
to one `walk_offset_adds`, so there is still **one locator** for the overflow
check, the `28` payload rule and the stop condition — the module header states
that as its whole purpose, and a second summing loop would be a second place for
all three to drift. Its callers — `leaf_load.rs`, `leaf_store.rs`,
`mcall_chain.rs`, `eat_addr_offset_adds` — are untouched, and its own two tests
pass unedited.

### 2.3 One half is honestly missing, and it is ONE NAMED FIELD

`Root::offsets` arrives `None` from today's emitter. The seam that would carry
the list is `IlOp::BoundAddr`, whose `off` is a **sum** — and that variant is
matched and constructed in `codegen/store_run_call.rs` and the call-tail path
**concurrent lane `w-mrslot` owns**, so this lane did not change it. Prereg
**F-3** registered that outcome in advance so it could not be presented
afterwards as a completed carrier.

**A one-element list holding the sum is exactly the lie #908 warns about, so it
is not written.** `the_offset_lists_state_a_prefix_and_a_sum_only_carrier_refuses`
pins that the predicate **refuses** rather than answering confidently.
