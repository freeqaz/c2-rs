## §2 Two refutations, and the second one is mine

### 2.1 The commissioned premise is FALSE — the corpus could produce `.rdata$r` all along

The brief, and `rungs/2026-08-04-w-shapes.md` before it, state that `.rdata$r`
is *"the last workload section name the corpus cannot produce"*. Measured on the
**unmodified** 57-fragment corpus, every case captured at the workload's own
profile `/GR /O1 /Oi /EHsc /GS- /c`:

```
16,164 sources -> COMPILED 16,068, FAILED 96; objs with .rdata$r: 5 (27 sections)
```

**Five cases, twenty-seven sections, before this lane wrote a line of source.**
`scripts/sweep_shapes.py`'s pass B already reports `HONEST REMAINDER … 0` on the
*pre-fragment* corpus once `/GR` is in the profile. The five live in
`60-ctor-epilogue`, `51-dtor-member` and `62-ctor-base-delegation`, which
incidentally contain shapes like `struct NV{int m; virtual void f(); NV();};
NV::NV(){}` — a vftable-emitting TU that nobody wrote *as* one.

So the true statement is not "the corpus cannot produce it" but **"nothing ever
compiled the corpus at a flag that would show it"**, and the gap was **entirely
the lane**. Two things made the false version look true:

* **`/GR` is not this compiler's default.** MSVC documents `/GR` as on by
  default; this `cl.exe` (X360 16.00.11886.00, under wibo) behaves as `/GR-`
  unless `/GR` is passed. Measured three ways: the section is present with
  `/GR`, absent without it, and absent with an explicit `/GR-`.
* **The instrument was measuring at the wrong profile and said otherwise.**
  `sweep_shapes.py --flags` defaulted to `/O1 /Oi /EHsc` and its help text
  called that *"the dc3 workload's own"*. `work/dc3-workload/flags.txt` reads
  `/nologo /wd4355 /wd4164 /c /GR /O1 /Oi /EHsc /I …`. **It was short by the one
  flag that mints the one section it was reporting as unreachable** — and it
  would have gone on reporting it unreachable after a fragment closed it. Fixed;
  the default is now the workload's string verbatim.

The `.XBLD$W:C1` / `:C2` rows w-shapes identified as artefacts are real
artefacts — the census names those two XDK build-info sections after the
`__C1_*` / `__C2_*` symbols they hold, and the COFF section header spells both
`.XBLD$W`, which every generated case already produces. They are now **labelled
in the report and subtracted**, and the remainder is printed as its own number,
because *a list whose every row is a known artefact reads exactly like a list of
real gaps* — and this one did, for two lanes.

### 2.2 My own P5 is refuted: `/Od /GR` is not redundant

The prereg declined `/Od /GR` on the ground that `/Od` is the same *placement
class* as `/Ox` (both pack `.text`). It is not. Over the new fragment's 230
cases at nine profiles, comparing the `.rdata$r` record set per case:

| | rtti records differ | section order differs |
|---|---:|---:|
| `/O1 /GR` vs `/O1 /Oi /GR` | 0 | 0 |
| `/O2 /GR` vs `/O1 /Oi /GR` | 0 | 0 |
| `/Ox /Gy /GR` vs `/O1 /Oi /GR` | 0 | 0 |
| `/Ox /GR` vs `/O1 /Oi /GR` | 0 | **145** |
| **`/Od /GR` vs `/Ox /GR`** | **2** | 75 |
| `… /EHsc` vs the same base | 0 | 43 |

`/Od` is the **only** profile in the registry that changes *which RTTI records
exist*. The reproducer is four lines:

```cpp
struct A{A();virtual ~A();virtual int f();int a;};
struct S:A{S();virtual ~S();virtual int f();int s;};
A::~A(){}
S::~S(){}
```

`/Ox`, `/O1`, `/O2`, `/Ox /Gy` all emit **one** vftable and **4** `.rdata$r`
records; `/Od` emits **two** and **8**. Two cases, eight sections — small, and
not zero, and no other lane can see it. The row went into the registry and the
declination came back out. Registered at `d07b3e9`; refuted by the measurement
in the same afternoon.

## §4 The fragment: `scripts/sweep.d/91-rtti-vftable.py`

230 cases, **all 230 compiling at all 18 lane profiles** (checked directly, not
inferred), **all 230 graded** by the sweep, ungraded delta **0**.

The axis order is the finding, and it is the opposite of the obvious one. A
15-shape grid at `/O1 /Oi /EHsc /GR`:

| shape | `.rdata$r` |
|---|---|
| polymorphic class, **destructor defined here** | **yes** — 4 records + `.rdata` vftable + `.data` |
| polymorphic class, **pure virtual + destructor here** | **yes** |
| polymorphic class, only `int B::f(){…}` defined here | no |
| base + derived, both `f()` defined, no ctor/dtor | no |
| `dynamic_cast<D*>` / `<D&>` / `<void*>` | **no** — obj content-identical with and without `/GR` |
| `typeid(*p)` | **no** |
| multiple inheritance, virtual inheritance (no ctor/dtor) | **no** |

**The vftable mints the records, and the vftable is emitted by whichever TU
generates a constructor or destructor body** — that body is what writes the
vfptr. `dynamic_cast` and `typeid` reference `??_R0` type descriptors, which
land in **`.data`** (they hold a mutable name buffer), so they move `.data` and
`.text` and leave `.rdata$r` empty. **A fragment written from the obvious model
— "RTTI means `dynamic_cast` and `typeid`" — would have emitted zero `.rdata$r`
and read as success.**

Axes: the emission trigger (dtor / ctor / both / a non-ctor virtual / nothing);
hierarchy shape (standalone, SI depth 1–3, MI 2 and 3 bases, MI with one
non-polymorphic base, virtual inheritance, diamond, abstract) — this is the
arity of the `??_R2` base-class array; polymorphic classes per TU (1, 2, 3, in
both definition orders and with only some defined) — the arity of the *section
count*; the RTTI-consuming expressions, crossed with the trigger; TU position
against functions the port matches; and the controls, which are every row with
`virtual` deleted or the ctor/dtor definition deleted. `__declspec(novtable)` is
in there too — an XDK idiom where the ctor does not write the vfptr.

Two constructs are absent on purpose, both measured: `typeid(a)==typeid(b)` is
`error C2676` without a real `<typeinfo>`, and `#include <typeinfo>` is
`fatal error C1034` (the sweep sets no include path). `class type_info;` as a
forward declaration is enough for `typeid` to be *written*, and that is what the
fragment uses. Writing either would have moved the ungraded baseline.

## §5 A hole this lane opened and closed: registry drift in `mode_classes.txt`

**Adding the six lanes would have made them decorative, and the gate would have
gone green with a *larger* cell count.**

Every row of `scripts/mode_classes.txt` is an **exclusion** of the lanes it does
not name. The per-fragment digest closes drift in the *fragments* — edit a
generator and its row stops applying, loudly. Nothing closed drift in the
*registry*. Measured on this tree before the fix: **57 of 58 fragments would
have been graded at zero of the six new lanes**, while `mode_cross.sh` reported
more cells (the new lanes appear as rows of their own, grading only the one
fragment that happened to have no row yet) and PASSed.

The fix is a `# measured-over-lanes:` directive, written by `--write-classes`
and read by `--assign`: a lane the table never saw is added back to **every**
fragment, fail-safe, and it self-clears the moment the table is regenerated.
`--assign` prints which lanes those are and how to buy the reduction back.

It is deliberately **not** derived from the rows. A lane can legitimately be
named by no row because it merged into another everywhere — `O1-EHsc` does today
— so *"named by no row"* and *"never measured"* are different facts and only the
second is a hole. Deriving it would have forced the full 295,092-cell cross
forever.

## §6 What `/GR` actually is, for the next lane

* **It is a pure additive overlay whose *content* is optimization-invariant and
  whose *placement* is not.** The `.rdata$r` record bytes are identical across
  all eight profiles measured; their index in the section table is not, and
  section index drives symbol index drives the `.pdata` association number.
* **Its trigger is a ctor/dtor body, i.e. `??_R*` follows `??_7`.** That is why
  676 of 871 workload objs carry it: most TUs that define a class also define
  one of its special members.
* **`??_R0` is not in `.rdata$r`.** The type descriptor lands in `.data` because
  it holds a mutable name buffer; `??_R1`–`??_R4` are the `.rdata$r` population,
  which matches `STATUS.md`'s "24,163 content symbols, every one `??_R1..R4`".
  A rung that plans the `.rdata$r` writer therefore needs a `.data` object too,
  and `.data` is already in `PORT_WRITER_SECTIONS`.
* **At `/Od` the vftable set is larger** (§2.2). An emit-set model keyed on "one
  vftable per class defined here" is right at every optimized mode and wrong at
  `/Od`.

## §7 The counterfactual — can the new cases FAIL?

A fragment that only ever prints `NotImplemented` and `Match` is
indistinguishable from a fragment that grades nothing.
`scripts/w_gr_counterfactual.sh` is committed so the answer is re-runnable.

**The breaker: `encode_lwz` loses 4 from every displacement ≥ 4 — the port
forgets the vfptr.** That is not an arbitrary corruption. A polymorphic class
puts its vftable pointer at offset 0, so `struct S{S();virtual ~S();int s;}` has
`s` at **+4** where its non-virtual twin has it at **+0**; multiple inheritance
pushes the second base's members further and a virtual base adds a displacement
on top. The 27 cases of this fragment that the port accepts today are almost
entirely member loads through exactly those layouts. Leaving displacement 0
alone is what keeps the breaker off most of the corpus.

**Measured, whole corpus, both halves graded in the same run:**

```
base:    graded 16394 cases,   0 mismatches
broken:  graded 16394 cases, 385 mismatches
restored; git status --porcelain crates/ = 0 path(s)
```

Per-fragment histogram under the breaker:

| fragment | mismatches |
|---|---:|
| `45-offset-run` | 124 |
| `83-store-load` | 93 |
| `99-chain-tail-load` | 60 |
| `40-indirect-load` | 39 |
| `41-ptr-value-leaves` | 30 |
| **`91-rtti-vftable`** | **20** |
| `86-union` | 10 |
| `54-addr-leaves` | 7 |
| `80-store-leaf` | 2 |
| **49 other fragments** | **0** |

**20 of this fragment's 27 accepted cases flip to `Port=Mismatch`.** The three
floor conditions the script asserts, as counts:

* `91-rtti-vftable` mismatches **20 > 0** — the new cases are graded on bytes,
  not merely reached;
* total **385 > 20** — they are not alone, and the breaker is not a fragment-
  specific fiction;
* fragments untouched **49 of 58 > 0** — the breaker is **not uniform**, which
  is the condition that makes the first number mean anything. A breaker that
  breaks everything proves nothing.

The nine fragments it does light up are all offset-bearing loads, which is
exactly what "forget the vfptr" predicts, and it leaves `50-dtor-base`,
`62-ctor-base-delegation`, `67-eh-try-throw` and 46 others at zero.
`git status --porcelain crates/` is **0 paths** afterwards, checked by the
script rather than by hand, and the script refuses to start on a dirty
`crates/` so that check cannot be vacuous.

**And the honest limit of it.** The 203 cases this fragment adds that the port
*refuses* cannot be made to mismatch by any breaker, because refusing is what
they do. Their value is prospective: they stand over a class the port does not
emit yet, so that the rung which widens into it cannot do so silently. That is
the same thing `67-eh-try-throw` bought and the same thing board #232 cost when
it was missing.

## §10 Found and deliberately not taken, priced

* **The `/Od` two-vftable divergence (§2.2) is a fact about the emit set, not
  about `/GR`.** It says an emit-set model keyed on "one vftable per class
  defined in this TU" is wrong at `/Od`. Not taken: Phase 7 work, and this lane
  does not touch `crates/`. **Price: unknown; the reproducer is four lines and
  is now case `91-rtti-vftable-0144/0145`, so the next lane starts from a
  failing example rather than from a search.**
* **`??_R0` lands in `.data`, not `.rdata$r` (§6).** This slightly re-prices
  board **#160**'s rung three: the `.rdata$r` step also needs `.data` objects
  for the descriptors — a section the writer already has, so the price does not
  go up, but a plan that budgets only for `.rdata$r` is short by one object
  kind. Not taken: `crates/c2-core`.
* **`sweep_shapes.py` pass B is a 2-minute full-corpus capture and is in no
  gate.** `--check` (pass A, no toolchain) is a `gate.sh --selftest` case; pass
  B, the half that would have caught the profile bug in §2.1, runs only when a
  human types it. Not taken: adding a 2-minute row to the merge gate is a
  cost decision somebody else should make, and the `HONEST REMAINDER` line now
  makes it a single number to assert on. **Price: ~2 min per gate run at 12
  jobs, measured.**
* **The census spells two sections `.XBLD$W:C1/:C2` and the COFF spells both
  `.XBLD$W`.** Now labelled rather than fixed. Fixing it means regenerating
  `work/w-bss/census/sections.jsonl`, which needs the dc3 tree and ~102 MB of
  objs (`scripts/regen_census.sh`). Not taken: the label costs nothing and the
  regeneration costs a lot.
* **16 of 56 shape markers had zero cases as recently as board #283, and the
  marker table is still hand-maintained.** Four rows added here; nothing
  enumerates what the *table itself* is missing. Not taken, and it is the same
  shape one level up as everything in §2.
