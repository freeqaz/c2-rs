## 1. What was built

### 1.1 The five producers `w-s1c2` §6.2 priced (`3ed75c2c3`, `54fc8f259`)

`pool_ctor_chain`, `xtea_round_loop`, `float_walk_loop`, `compare_leaf`,
`select` (`straightline.rs`). All five split `X_text` (a thin `ops_to_bytes`
wrapper) + `X_ops` (the producer) — `w-s1c2` §1.3's shape, for its reason: only
the split one leaves the op stream **reachable by a caller**, and a permuter and
a matching-pretext generator need to *read* the decisions, not to know they
briefly existed.

**Every obstruction §6.2 named was real and every one was exactly as described.**
The **five** line counts it gives (79 / 72 / 84 / 257 / 330) verify to the line,
and so do `store_leaf_text`'s 353 and `permute_args_parts`' 144.

**`reach::direct_op` is the one piece of shared machinery, and it is the
interesting one.** `reach.rs`'s own header counts the crate's live `direct` call
sites down from 23 to **one** — `pool_ctor_chain`'s forward guard — and that
count is confirmed here by grep. So a gate returning `[u8; 4]` was the single
thing standing between that class and an op stream, and *not* because the class
does byte-position arithmetic: both its displacements are file-level constants.
`direct` is now `direct_op(..).word()`, so the verdict, `Reach::of`'s clause
order and the refusal text are each read exactly once.

Two conversions changed an assertion deliberately:

* `pool_ctor_chain`'s length invariant read `t.len() == 80`. It reads **20**.
  The invariant was always *"the class's body length is a constant"*; 80 was
  that constant in the old representation. Its two **displacement** assertions
  still read words off the rendered bytes, because they are claims about what
  the `bf` and the `bdnz` *span*, which is a byte fact.
* `float_walk_loop`'s `body_word` became `body_op` — but its injectivity pin
  still compares `**.word()**` on both sides. The claim is that two operations
  must not collapse onto one **encoding**; asserting it on the op values would
  be strictly weaker, and would pass for exactly the defect it exists to forbid.
  Same reasoning kept `xtea`'s `rldimi` pin on the encoder.

### 1.3 `store_leaf_text` and the #844 seam, moved together (`e5fc13c4a`)

`ScheduledRun::slots` is `Vec<(bool, Ops)>`. It **had** to move as one commit:
the field exists in slot form precisely so the run is scheduled once and the two
consumers — the leaf, which concatenates, and `store_run_call`'s framed
composition, which splices `mr rSaved,r3` **between** two slots — differ only in
what they do with it. A `slots` one consumer read as ops while the other read as
bytes is that seam split in half.

`store_run_call`'s own argument survives verbatim: *"a producer is one slot, so
the splice can never split a `lis`/`ori` pair."* A slot boundary was always an
instruction boundary; it is one in the representation now.

**`emit_load_imm` is deleted, one commit after this lane created it.** §8.2.

### 1.4 The decision surface — a stated NULL, registered in advance

### 3.1 THE FIRST PAIR WAS VOID, AND THE STAMP GUARD IS NOT WHAT CAUGHT IT

The first pair ran to completion with the stamp at `a29f559d0790` at every one
of its four reads, `gap exit: 0` on both arms, and `PAIR_EXIT=0`. **The base arm
had graded nothing.** Its entire log is one line:

    SKIP: toolchain absent

`repo_root()` is `CARGO_MANIFEST_DIR/../..` **baked at compile time**, so a base
binary built from a scratch tree under `work/` resolves `compilers/` relative to
*that* tree and finds none. The subcommand then degrades cleanly — which is
`CLAUDE.md`'s requirement — and **exits 0**, which is the whole trap.

**What caught it was the key denominator**: `base: 0 keys` beside `tip: 399`.
The stamp guard was live, correct, and completely silent, because the corpus
genuinely had not moved. **A pair can be void for reasons the stamp cannot
see.** The pair script now asserts, per arm, that the log carries no
`SKIP: toolchain absent`, that the exit code is 0, **and that the key count is
nonzero** — and exits 4 rather than printing a comparison. The void attempt's
numbers were never read and its logs are kept as `*_VOID1.log`.

The re-run set `C2RS_COMPILERS` and `C2RS_WIBO` explicitly for **both** arms,
which is better protocol independently: two arms resolving the toolchain by two
different mechanisms are two arms that can silently disagree about what they
compared against.

**This adds to `w-s1c2` §3.1 rather than repeating it.** That lane established
that recording a stamp is not refusing on it. This adds: **a guard that is right
about its own question is not a guard against the run being empty**, and the
denominator is the only thing that ever catches an absence.

## 4. Criterion B — the pre-registered COST criterion (#3336), and it RESOLVED

Protocol: `ir0`'s, now committed as `scripts/cost_arms.py` (§5.3). Three arms
(`base`, **`nulldup`**, `tip`), order rotated every round, estimator = per
fixture and arm the **minimum port median over the rounds**, pairing per
fixture, the reference column parsed and discarded. `nulldup` is a copy of base
**verified byte-identical by the script itself**. Population **n = 156**, the
fixtures every arm matched in every round.

### 4.1 The two runs

| run | rounds | balanced? | load | **null arm** | null split | **tip arm** |
|---|---|---|---|---|---|---|
| 1 | 8 | **no** (8 % 3 ≠ 0) | 3.6 → 7.0 | **+0.57 % [+0.45, +0.68]** | **76 %** | **+1.33 % [+1.01, +1.66]** |
| 2 | 9 | **yes** | 4.5 → 5.8 | **+0.09 % [−0.07, +0.26]** | **51 %** | **+0.99 % [+0.63, +1.35]** |

### 4.2 THE FINDING: `--rounds 8` OVER THREE ARMS IS NOT A ROTATION

`w-s1bc` §4.3 and `w-s1c2` §4.3 both concluded that this box has a noise floor
of about **±1–1.7 %** and that a construct rung's cost is below it. Both reached
that conclusion from a **misbehaving null arm** — an arm byte-identical to base
reading −1.08 %, +0.47 % or +0.52 %, with sign splits of 40 % and 52 % and two
runs flipping sign.

**The floor is not the box. It is the rotation.** With 3 arms and 8 rounds:

```text
  r1 base null tip     position 1:  base 3   null 3   tip 2
  r2 null tip base     position 3:  tip  3   base 3   null 2
  r3 tip base null
  … repeating
```

`tip` runs first twice and last three times; `nulldup` runs first three times and
last twice. On a box whose load is moving, that residue lands **on the arm
axis**, and it is enough to make an arm with an effect of *exactly zero* read
**+0.57 % with a 95 % CI that excludes zero**.

Run 2 changes one thing — 9 rounds, so each arm occupies each position exactly
three times — and the null arm collapses to **+0.09 % [−0.07, +0.26], split
51 %**: the reading an effect of zero must give. **The protocol can resolve well
under half a percent on this box.** It never could not.

### 4.3 So the cost of S1c (i)'s producer half is a NUMBER, not a bound

**+0.99 %**, CI **[+0.63, +1.35]**, median +0.90 %, aggregate +2.06 %, slower on
104 of 156 (67 %) — read off the run whose null arm is certified by its own
sign split. The tip's CI does not overlap the null's at either end.

Corroborated by the unbalanced run rather than contradicted by it: run 1's
**tip − null** is +0.76 points and run 2's is +0.90. The two runs agree about the
*difference*; what the balanced one adds is a null at zero, so the tip's own
number can be read directly.

**Prereg P3 is a MISS, by the rule it was registered under.** P3 predicted the
tip would land inside the null's CI and that only a bound would be reportable,
with an explicit scoring clause: MISS if the tip is outside the null's CI on a
run whose null sign-split is 45–55 %. Run 2's split is **51 %** and the tip is
far outside. The prediction was wrong, and it was wrong because it inherited
`w-s1c2`'s floor as if it were a property of the hardware.

**And the costliest fixtures agree across runs, which is the second reason to
believe this one.** `w-s1c2` §4.3 reported top-fives that shared **no** member
between its two runs and correctly called that measuring the box. This lane's
two share **three of five** — `il_sy_locals_clean.cpp` (+7.5 / +7.6),
`wadjust_obj_recv.cpp` (+5.9 / +6.8), `w16_addr_leaf.cpp` (+6.0 / +4.9). And
`wadjust_obj_recv.cpp` is one of **`w-s1bc`'s two residual fixtures** (~+24 %),
which `w-s1c2` explicitly neither reproduced nor refuted. This lane reproduces
it, smaller.

**What +0.99 % is and is not.** It is one extra `Vec<MachineOp>` allocation and
one extra pass per body, on a port that is 550–5000× faster than the thing it
replaces. It is not a reason to undo S1c (i) — throughput is a property and not
the goal (`CLAUDE.md`) — and the reason to report it as a number is that a
project which cannot measure a 1 % regression cannot measure a 5 % one either.

## 8. WHAT THESE CONTROLS COULD NOT CATCH — and what they did

### 8.1 The `_text`/`_ops` split moves the code and leaves the DOCUMENTATION behind

Four class records ended up on a thin `Ok(ops_to_bytes(...))` wrapper — and
three of them contain the word **"below"**:

* `compare_leaf_text`'s *"Temporaries are allocated descending from r11 in
  emission order … each arm below names its own substitution"*;
* `cmp_of_two_call_results`'s three transcribed spines;
* `emit_load_imm`'s `lis`-alone table, six measured rows of real c2 output;
* `float_walk_loop_text`'s *"Every register below is derived from a formal
  index"*.

After the split, "below" is the render call. **Every one of these is
byte-identical, fully green, and invisible to every control this project has** —
`#3336`'s clause, restated by a mechanism nobody had named. All four records are
moved onto the producers whose arms they describe, with a pointer left on the
wrapper.

Two references deliberately **not** moved or renamed, because renaming a record
corrupts it: `leaf/store.rs`'s note about `encode_std`'s two independent
captures is about the **encoder**, and `xtea`'s `rldimi` pin asks the encoder
because its claim is about the **word**.

### 8.2 A dead wrapper this lane CREATED, and caught one commit later

`emit_load_imm` was kept as a `&mut Vec<u8>` wrapper in `54fc8f259` for a stated
reason: `leaf::store` still had one call site and duplicating the rule — the
`ori`-by-zero clause among it, a live wrong-bytes emit for as long as the
function existed — was the thing to avoid. In `e5fc13c4a` that call site
converted, and `cargo` said `function emit_load_imm is never used`.

**This is §1.2's defect, committed by this lane, one commit after being written
up as a predecessor's.** It is deleted, and the pattern is recorded on
`emit_load_imm_ops`: a `_text`/`_ops` split leaves a wrapper alive only while it
has a caller, and **nothing but the build warning says when that stops being
true**. Prereg §6 item 7 registered `cargo`'s dead-code warning as a control
this project was not reading; it fired twice in one lane.

### 8.3 The five registered in advance, restated

1. **A producer conversion is required-zero BY CONSTRUCTION**, so the gate
   mostly cannot fail on it and a green gate is **weak evidence about these
   conversions specifically**. `ops_to_bytes` is concatenated encoder output
   (`mop.rs::ops_tests`), and every `encode_X` is `mop_X(..).word()`. What the
   gate *can* catch is an op dropped or reordered — M4, M5, M5b.
2. **`mod incumbent` proves PRESERVATION, never correctness.** Two derivations
   wrong the same way agree. Only real `c2.dll` under wibo does the latter.
3. **`fnbyte-refused-parse` is ~70 % of the function population** — **113,589**
   of `fnbyte-denominator` **162,205** at this stamp, read off the scan — so no
   identity diff can see a defect in a shape the parser refuses.
4. **`hatch-red` is `REFUSED`** at both ends; per #1406 neither run establishes
   what a full run would.
5. **A required-zero byte delta is silent about everything that is not a byte**
   (#3336) — demonstrated live twice here, by §8.1 and §8.2.

### 8.4 And one this lane learned the hard way

**A guard that is correct about its own question is not a guard against the run
being empty.** §3.1's void pair passed every stamp check because the corpus
genuinely had not moved. The denominator caught it. Every instrument in this
rung now prints its denominator beside its diff, and the pair script asserts on
the key count rather than leaving it to a reader.
