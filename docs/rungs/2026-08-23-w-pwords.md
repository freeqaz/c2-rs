## 0. HEADLINE

Board **#3431** found that `.pdata`'s unwind word records the prologue's
expanded size, and priced a follow-up: feed that oracle field into the
port-side bijection and see whether `ROADMAP_SLICING` §5's **AMENDED**
demotion — equality → per-function ratio — becomes **repairable**.

It is not repairable. **It is unnecessary.**

| form | what it says | result |
|---|---|---|
| **H0** | `T == W` — the demoted equality itself | **2,214/2,214 leaf + 689/689 framed = 100.00 %** |
| **H1** | `T - I + P == W` — the `prolog_words` correction | **0/689 = 0.00 %** |
| **H2** | `R = W - (T - I + P)` — the residual | **`R = -P` identically on all 689** |

`prolog_words` is a real field, #3431 stands and reproduces to the digit, and
it is **the wrong tool for the job it was nominated for**: adding it breaks an
equality that already holds.

**Denominator: 2,922 functions over 346 fixtures — 974× the bijection's three.**

## 1. The thing nobody had done

The AMENDED block demoted the equality with a **prediction**:

> Pointed at the corpus it goes **red on the first framed function** …

and its own text concedes the graded population is *"three functions, nine
words, all leaf, **frameless** … precisely the ones that *cannot* exhibit the
framed-prologue expansion."*

**So the equality had never once been evaluated on a framed function.** Before
this lane could ask whether `prolog_words` repairs the demotion, it had to ask
whether the demotion describes anything. It does not — at the site the
bijection uses.

## 2. Where the expansion actually is  (#3458)

`T == W` by tap site, 689 framed functions, one run:

```
  sched1      16/689  =   2.32%
  globregs    16/689  =   2.32%
  sched2      21/689  =   3.05%
  color       21/689  =   3.05%
  sched3      22/689  =   3.19%
  sched0     689/689  = 100.00%
  after0     689/689  = 100.00%   <- the site the bijection uses
```

**Both sides were right about different things.** The AMENDED block's
mechanism is real — the prologue pseudo-op *is* one tuple that becomes many
words, which is exactly why `sched1` reads 2.32 % — but
`the_final_tuple_order_reproduces_the_text_words` counts at **`after0`**,
downstream of the expansion. A demotion correct about the compiler and wrong
about the site.

Corroborating this from the tuple side: in 2,922 functions, **no** prologue
tuple (`0x2f0`/`0x2f4`), **no** epilogue tuple (`0x2f6`) and **no**
unbounded-arm tuple (`0x27b`/`0x2e5`/`0x28f`) survives to `after0`. The only
pseudo-ops that do are `0x308`–`0x30f` markers, ~1 per function, none flagged
real — which is why `I == 0` everywhere and the correction collapses to zero.

**Consequence for future instruments:** a tuple count must say **which site**.
Upstream of `sched0` the ratio treatment remains exactly right.

## 3. What this lane does NOT claim

- **It grades COUNTS, not the encoding.** The bijection asserts both a count
  equality *and* all 32 bits of every word; `encode()` implements two forms and
  REFUSES the rest. **Refuting the count demotion does not license promoting
  that test to the corpus** — the encode subset is a separate, untouched
  constraint.
- **`FramedUnbounded` is empty** — not because `nopalign` and friends do not
  exist, but because they too are expanded before `after0`. Their behaviour
  upstream is **untested here**.
- **The epilogue term is still UNGRADED** (#3431 caveat 2). This lane did not
  grade it; it showed that at this site **no** correction applies, which is a
  different statement and a weaker one about the epilogue itself.
- **40 fixtures excluded**, counted and never floored: 29 tap-not-armed, 8 no
  `.text`, 2 replay failed, 1 walk TRUNCATED.
- **19 functions (0.7 %) quarantined** `OrdinalUnverified` — see §5.
- The corpus is **386 fixtures**, not the 878-TU workload. The tap has no
  capture-cache path, so the obj corpus behind #3431's 12,610 cannot be used
  for the bijection at all: it carries no tuple counts.

## 5. The ordinal hazard, which no document named

This instrument pairs funcwalk `func == i+1` with the i-th `.text` function in
address order. **Nothing in the funcwalk payload carries a name to check that
with.** `wkg_splice_pos.cpp` produced six "failures" with mismatches in *both*
directions — `T=73` against `W=14` beside `T=6` against `W=72` — which is the
signature of a permuted pairing, not of a compiler that sometimes emits 59
extra words.

Quarantining TUs whose funcwalk count disagrees with their `.text` function
count removes **every** H0 failure. **The fence is not circular, and that is
the point: it also quarantines 10 rows that PASSED.** A criterion fitted to its
own failures would not have.

This is a live limitation of every funcwalk-based instrument in the tree, not
just this one, and it is recorded as #3459 rather than buried here.

## 6. The failure axis: the fence, watched refusing

Per `CLAUDE.md`'s formatter rule generalized — *a fence never seen refusing is
not a fence*:

| corruption | must do | measured |
|---|---|---|
| `P += 1` on every framed function | every residual shifts by exactly `-1` | **holds** |
| drop the `is_instruction()` filter | H0 collapses | **416/416 → 0/416** |

**The first check could not be graded the way the prereg wrote it.** Prereg §3
registered *"H1's hold-rate must collapse"* — but H1 measures **0/689**, and a
hold count of zero cannot be reduced, so that assertion would have passed while
reading nothing. It was rewritten onto the residual, which is the quantity that
actually moves when `P` moves. **Registering a check in advance does not make
it a check; the result can make it vacuous.**

### 6.1 Two defects the gate caught — and neither was a wrong number

The first armed suite came back **`EXIT=101`, 1,839 passed / 1 failed**, and
the one failure was this lane's own fence.

1. **The fence died on its own precondition.** The broken-input test took
   `.take(16)` of the spread population; that subset contains **no framed
   function**, so the control had nothing to perturb. Keyed to the same
   `population()` the measurement test asserts `framed > 0` over, the
   precondition now holds by construction rather than by where the stride
   landed.
2. **The work root was keyed on the PID alone.** cargo runs this file's tests
   as parallel threads of **one** process, so both callers of `run_corpus`
   shared `j0..jN` and clobbered each other's captures. The symptom was not a
   crash: the control pass graded **37** framed functions and the perturbed
   pass **76**, from the same fixture list. Every evidence run used a
   single-test filter — one caller — so **the 2,922 figure is unaffected**, and
   it was re-taken on the fixed tree and reproduced **identically**. But a
   combined run was racy and would have stayed racy.

Also fixed: the "is `R` a function of `P`" line swept the `OrdinalUnverified`
quarantine and printed *"**NOT** an exact function of P"* while the hold-rates
above it said `R = -P` on every verified row — a report contradicting itself
out of a population mismatch. Now scoped to the verified strata, with the
quarantined residuals printed separately.

**This is #3336's thesis demonstrated rather than cited**: the byte delta was
structurally zero throughout (§7), every headline number was already correct,
and the gate still found two real defects in the instrument that produced them.

## 9. What this changes, and what it does not

**Changes.** `ROADMAP_SLICING` §5's AMENDED block should be read with #3456
and #3458 beside it: its reasoning about the compiler stands, its conclusion
about the bijection does not, and the ratio treatment it prescribes belongs to
sites upstream of `sched0`. **The demotion needs no repair at `after0`.**

**Does not change.** The bijection is still not promotable to the corpus —
§3's first bullet. `prolog_words` remains a correct and useful field (#3431),
and this lane says only that *this* consumer never needed it. No emit is
licensed, no gate is added, and the byte judge is untouched.

**Priced follow-up, not taken here.** The ordinal hazard (§5, #3459) is a
property of every funcwalk instrument in the tree. Closing it means carrying a
function identity through the tap payload — a `c2-reference` change, outside
this lane's fence, and it should be dispatched as its own construct rung rather
than bolted onto a lane that merely tripped over it.
