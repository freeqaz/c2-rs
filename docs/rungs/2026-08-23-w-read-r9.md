## 1. What was asked, and what the brief got wrong

R9 was dispatched as *"the `0x4F` sub-record switch `FUN_10b9761e`
(~14 arms)"*, priced **1–2 days** — the cheapest row in the plan, with
completeness a reasonable target rather than an aspiration — and with an
explicit instruction to verify the address and the arm count first, because
*"R5's target was claimed to have 189 arms and actually has 62"*.

**The address is right. The arm count is right. The thing the arms count is
wrong.**

`0x10b26268` is not a width table. Each 8-byte entry's first dword is a
`const char *` to a NUL-terminated string of **field-type codes**, and
`FUN_10b9761e` is a **format-string interpreter** that walks that string one
byte at a time (`0x10b97860` fetch, `0x10b9785a` advance) dispatching each
code through the cascade at `0x10b9766c`. There are exactly **14 arms — 13
field-type codes plus a default — over a 64-entry sub-opcode domain**.

This is R5's error in mirror image, and it is the more interesting direction:
there the number was wrong, here the number is right and **the level it
describes is wrong**. A prediction registered at 0.60 that "~14" would be
wrong the way "189" was wrong is a **MISS**, and it is reported as one.

Three further errors were corrected **before the target was read**, from
committed text alone, and are in the prereg's §0 so they cannot be claimed
after the fact:

1. **The brief's entry point.** `DECISIONS_2026-08-22.md:275` and the brief
   both say R5 handed R9 *"arms 48/49"*. R5's rung
   (`2026-08-23-w-read-r5.md:195-198`) is a compound sentence naming **two**
   reads: R9 gets **arm 32** → `0x10bbe561`; arms 48/49 are **R6's**.
2. **"The one transcribed width in the port"** is at least **five** readers
   carrying **two** inconsistent widths — two fixed-byte, three varint.
3. **`FUN_10b9761e` is not virgin ground**: R3 already read `0x10b97807`
   inside it. Registered as prediction P7, and it produced §4 below.

## 2. The deliverable, complete

All **64** sub-opcodes, all **14** arms, all **5** scalar readers
(`BYTE` 1 · `VARU` 2-or-4 · `VI16` 1-or-3 · `VI32` 1-or-5 · `STR` count+n),
and both list siblings. Domain: **12 decode a payload · 17 are FATAL** (16
reach ICE `p2pragma.c:160`; `0x17` has a dedicated ICE at `:88`) **· 35 read
nothing**.

So the refusal half of the deliverable has a sharp answer: **c2 does not
silently skip an unknown `0x4F` sub-record — it ICEs**, `0x10b33526` ending in
`int3`. The port's refusal posture is right; its stated reason ("the table it
did not decode") is not the reason.

Three of the port's own transcribed constants fall straight out of the table
— `BLOCK_START = [4F 02 20 00]` is exactly VARU's four bytes, `LO_RECORD =
[4F 11]` is exactly a null descriptor's two, and `4F 01`'s escape is the
`4f 01 80 c8 00 00 00` `readers.rs` already had from the corpus. And
`IL_STMT_GRAMMAR` §12.6's *"unexplained"* `47` is explained: `4F 12` is **two**
bytes, so `47` is the next record's opcode.

## 3. The port's transcribed width is CONTRADICTED — reported, not fixed

`4F 01 <byte>` is three bytes **only below source line 128**. The payload is
`VI32`: one sign-extended byte, or `0x80` plus **four** more. At line ≥ 128
the record is **seven** bytes. `middle_interfaces.rs:716-724` and
`codec.rs:1128-1145` bake the three.

**Zero `crates/` bytes changed.** `w-s1bc` is the only lane in `crates/` this
wave, and `w-read-r3` set the precedent by declining to fix a shipped defect
under a docs-only fence. Board **#3443** carries it for a follow-up lane.

**Latent, not live, and that is the point.** Every fixture in `fixtures/cpp`
sits below line 128, where the two rules **agree** — so the defect is green on
the entire corpus and no gate has ever seen it. That is `w-read-r3`'s shape
exactly and board #2668's hazard.

## 4. What P7 turned up, and it is not comfortable

`ref/P_LABEL.md:51` (read R3) places the label-seed install at `0x10b97807`
for *"IL directive `0x16`"*. P7 **HITs** — the address is in the
field-type-`0x16` arm. But of the 13 handled codes, **exactly one is selected
by no descriptor in the table, and it is `0x16`**. So `0x10b97807` **cannot be
reached by any `0x4F` sub-record**. R3 read the instructions correctly; the
arm is not on the path — the `.bss`-bump mode, which is precisely what `[R]`
is defined not to exclude.

**Bounded deliberately: `LABEL_SEED_GAP` is untouched.** `w-seedgap` measured
its coefficients black box from a 22-cell obj grid, so no shipped number
depends on this arm. What is removed is a mechanism story, not a value.
`P_LABEL.md` is **amended beside, never rewritten**, and no claim of R3's is
edited. Board **#3444**; asserted by `--selftest` so it cannot rot.

## 5. The confirmation probe, and the one clause reported UNGRADED

**Probe A, the twin grid — 10/10.** Ten sources, byte-identical bodies,
differing only in `#line L` across the VI32 escape boundary. The decisive cell
`#line 127` carries **both widths in one file**. **Verified capable of
failing**: re-grading the *identical captures* under the port's fixed-byte
rule scores **2/10**, every line ≥ 128 decoding as the constant 128. Cells
`L=1` and `L=100` pass under **both** rules — which is FM4, the vacuous-green
trap, made visible rather than argued about.

**Probe B, the corpus — 386/386 fixtures, 6,840/6,840 `4F 01` records, 0
width violations.**

**Probe B's histogram clause went RED on its registered rule, and is reported
UNGRADED rather than relaxed.** The contexts were dumped before the claim was
doubted, per the standing rule, and the flagged candidates are payload bytes:
`4f 01 4f` is a line marker for **line 79**, and a bare search reads that
payload `4F` as a record. Span exclusion removed all but 67. The decisive
evidence they are not records is a **positive fact** — `0x10b33526` ends in
`int3`, so a real sub-record with an unhandled code kills c2, and **386/386
fixtures compiled**. The registered rule assumed a soundness the superset scan
does not have; **rewriting it to obtain a green is the failure the prereg
ladder exists to prevent**, so it is reported as UNGRADED and the width clause
— which the scan *can* decide — is the graded one.

The instrument self-test was likewise **watched failing on deliberately
corrupted input** (three of eleven checks red on two flipped bytes) before its
exit code was trusted, per `CLAUDE.md`.
