# W31 — the single-argument floating-point tail call

    Tag:       W31
    Slug:      fp-tail
    Date:      2026-07-31

    Record:    docs/CODEGEN_FP_ARGS.md §5 (the item this rung takes)

`return g(x);` and `g(x);` where `x` is a floating-point formal — the whole
body, no frame, at most one instruction plus the branch. It is the
single-argument half of `docs/CODEGEN_FP_ARGS.md` §5's largest measured
remaining item (85,231 whole bodies, of which **59,095** parsed as
`IntTailCall`-shaped under that section's lax counterfactual).

## What it admits, and what it refuses

The rule is `docs/CODEGEN_FP_ARGS.md` §0 — the FP register file is numbered over
the **FP parameters alone**, `this` displaces nothing in it, and the numbering is
width-agnostic — consumed through the one locator `sy::SyView::arg_classes`,
not re-derived. The destination is always `f1`: the argument region held exactly
one argument and it is FP, so it is the callee's first FP parameter.

```text
  float  a1(float a)                     { return g1f(a); }  48000000  b g1f
  float  a2(float a, float b)            { return g1f(b); }  fc201090  fmr f1,f2
  float  a4(int k, float b)              { return g1f(b); }  (nothing)  b g1f
  double a8(float a, double b)           { return g1d(b); }  fc201090  fmr f1,f2
  double w1(float a)                     { return g1d(a); }  (nothing)  b g1d
  float  n1(double a)                    { return g1f(a); }  fc200818  frsp f1,f1
  float  n2(double a, double b)          { return g1f(b); }  fc201018  frsp f1,f2
  int    b1(float a, float b)            { return gif(b); }  fc201090  fmr f1,f2
  void   b2(float a, float b)            { gvf(b); }         fc201090  fmr f1,f2
  float  C::m(float a, float b) const    { return g1f(b); }  fc201090  fmr f1,f2
```

Two rows carry facts nothing else in the corpus does:

* **`n2` — the narrowing is FUSED with the move.** `double`→`float` at the
  argument boundary is a real `frsp`, and it does **not** decompose into
  `fmr f1,f2 ; frsp f1,f1`; c2 writes the source straight into the `frsp`'s
  operands. A port that emitted the move first is wrong by one instruction on
  every narrowing call from anything but f1. Its twin `w1`/`w2` is the same
  `2C <TYPE> 00` in the other direction costing nothing at all — one field, two
  facts, and only an instruction separates them (`GAPS.md` §6).
* **`b1`/`b2` — the result class is not this rung's business.** An `int` return
  and a discarded `void` call emit the identical `fmr`: the callee's value is
  already in the register the caller returns in, whichever file that is.

Refused, each because a capture shows it emits something else:

| refused | what c2 emits |
|---|---|
| a conversion of the **result** (`4C 2C … 41`), either direction | `float r2(double a){ return g1d(a); }` is a whole frame (`bl` ; `frsp f1,f1` ; epilogue). Its widening twin `r1` really is a bare `b` — free, and refused anyway, because separating them needs the CALL token's own return TYPE, which this recognizer does not read. See "Found and not taken". |
| a conversion **across** the files (`int`↔`float`) | a frame in both directions: `fcfid` one way, `fctiwz` the other, both round-tripping through the stack |
| a **computed** argument (`g(a+b)`) | `fadds f1,f1,f2 ; b` — emittable in principle (it is the W13 leaf's selector with f1 as the destination) but a different lowering with its own contraction and constant gates |
| an FP **literal** argument | `lis`/`lfs` through an `.rdata` COMDAT, which `/Gy` refuses anyway |
| two or more arguments | the two register files' moves interleave on a schedule no per-file solver reproduces (`CODEGEN_FP_ARGS.md` §1.1) |
| a `volatile` FP formal | W32 — and it was a live mis-emit, see that rung |

Where it lives: one new recognizer, `c2-il`'s `shapes::leaf_fp_tail`, which
shares `calls::eat_call_head` (a second copy of the head decode is the drift
`GAPS.md` §6 #9 records, and the `call-conv` gate lives in it — a varargs callee
would need the argument in a GPR pair as well) and has its own **argument**
grammar, because `parse_expr`'s operand vocabulary is the width-4
integer/pointer one and cannot spell an FP value at all. One arm in
`codegen::select_function`, one lowering beside `float_leaf_text` (what it
decides is the FP *register file*, and the only thing it shares with the integer
tail call is the branch, which it does not emit).

The label stride was **measured, not assumed into the existing rule** — the same
seed-free two-framed-function construction `IlFunction::label_slots` documents:

```text
  fr1;                     fr2      delta 5     leaves 0
  fr1; fp_tail;            fr2      delta 7     leaves 1
  fr1; fp_tail fp_tail;    fr2      delta 8     leaves 2
```

5 + 1·leaves + 1 for the TU, zero residual. The extra slot is `_fltused`, which
the obj does carry, placed by the existing rule (immediately after the first
FP-touching function's symbol group) — so `touches_floating_point` gains a third
producer and `label_slots` is untouched.

## Estimate vs outcome

**Estimate, recorded before the scan: +34,000** (491,013 → ~525,000,
19.94 % → ~21.3 %), biased **HIGH**.

It is taken from `CODEGEN_FP_ARGS.md` §6's 59,095 and reduced by the strictness
this rung has and that counterfactual did not, in expected order of size:

1. **Computed FP arguments.** `g(a*b)` parsed as `IntTailCall` under the lax
   probe (widening `eat_int_like` admits the FP LOADs and the ops are the
   integer vocabulary's) and is refused here. Unmeasured; guessed at 20–40 % of
   the bucket, and it is the term that could be wrong by a factor.
2. **Cross-file conversions.** `float f(int a){ return g1f(a); }` is admitted by
   a probe with one gate per position and is a frame in reality.
3. **Result conversions**, refused here in both directions (see above).
4. **`arg_classes`**, which this rung consults and `tail_call_shape` does not —
   a `param-kind-unknown` formal refuses the whole list.
5. **W32's volatile fix subtracts**, estimated at −150.

Net estimate **+33,850**. Outcome: PENDING.
