3. **The `c2rs` CLI surface diffs empty** over 93 probes — `--help`, `-h`,

## 4. The `argv` / `Toolchain` single-producer invariant, and the lint that had to be widened

`mod argv` is the binary's **only** argument parser and `Args::toolchain()` its
**only** producer of a `Toolchain`, so that *"parse and validate, then locate"*
is the only order the binary can express. That structure exists because of four
defects of one shape (`#194`/`#195`, found at fourteen more sites), and it was
this lane's acceptance criterion above tidiness: **if the new structure makes a
second parser or a second `Toolchain` producer expressible, the structure is
wrong.**

**What was kept, and why it is not conservatism.** `mod argv` stays **inline in
`main.rs`**, doc comment verbatim, unmoved. Two reasons, and the second is the
sharper one:

* `tests/cli_flags.rs::locate_is_reachable_only_through_the_arg_seam` finds the
  seam by searching for the literal `mod argv {` and the literal `use argv::{`
  as its end boundary. Moving the parser to a file would have silently voided
  the lint's own bounds.
* That `use argv::{…}` line became `pub(crate) use argv::{…}` and is now **the
  path every handler module imports the parser through**. The boundary marker
  the lint keys on is therefore load-bearing: delete it and the build breaks. A
  marker that only a test depends on can be deleted by someone tidying up; this
  one cannot.

**What had to change, and it is the important part.** Left as written, the lint
would have kept passing while covering almost nothing. It read `main.rs`, and
once the handlers moved to `src/cli/`, `main.rs` is the parser and little else —
so **every site the eight original "locate before validate" defects actually
lived at would have become free to call `Toolchain::locate` directly, with the
lint still green.** That is exactly the "a second producer becomes expressible"
failure the invariant forbids, arriving through the test rather than through the
code.

So both source lints now take their file set from a new `bin_sources()` —
`main.rs` **plus every `.rs` under `src/cli/`** — and are strictly stronger than
what they replace:

| | before | after |
|---|---|---|
| files scanned | `main.rs` | `main.rs` + all 11 `src/cli/*.rs` |
| floor against vacuity | "no `Toolchain::locate` at all ⇒ measuring nothing" | that, **plus** a floor of 11 files on the directory listing, **plus** "at least one hit inside the seam ⇒ the exemption range is measuring nothing" |
| second parser | not checked | **every non-`main.rs` file asserted to contain no `mod argv {`** |
| `position(|a| a ==` scan | `main.rs` only | whole binary, reporting the offending filename |

The file-count floor is there because an empty `read_dir` is the project's
standing failure mode — absence reading as success (`STATUS.md` trap 5).

**Both widenings were mutation-proven**: planting a `Toolchain::locate()` and a
`position(|a| a == "--x")` in `src/cli/util.rs` made both tests fail, naming
`src/cli/util.rs:50`. Neither would have noticed before.

## 5. The source-reading tests, decided deliberately

`crates/c2-harness/tests/` contains tests that read the source itself, and a
split that moves code out of `main.rs` can break a test that is not about the
refactor at all. All three were decided, not discovered:

| test | decision | why |
|---|---|---|
| `every_subcommand_refuses_an_unknown_option` | **kept the code where the test is, edited nothing** | it extracts dispatch arms from `main.rs`'s text and asserts a floor of **26**. Re-derived on master: there are **exactly 26** — 17 top-level + 3 `corpus` + 2 `retrieve` + 4 `search`. **The floor has zero headroom.** So the three group dispatchers stayed in `main.rs` (that is what preserves their nine sub-arms), and each moved handler is `use`d by bare name so the arm still reads `"capture" => cmd_capture(rest),` — the extractor searches for the literal `=> cmd_`, which `=> cli::reference::cmd_capture(` would not match. Re-derived after: **26**. The test passes unedited. |
| `locate_is_reachable_only_through_the_arg_seam` | **widened** | §4 |
| `the_position_scan_helper_is_not_reintroduced` | **widened** | §4 — its nine historical callers now live in `src/cli/` |

`rung_registry.rs`, `lane_registry.rs` and `sweep_registry.rs` also read files,
but none of them reads any file this lane touched; `lane_registry`'s source read
is of `scripts/cross_sweep.py`, which is outside this seam entirely.

## 6. Defects found and deliberately NOT fixed

A lane that both restructures and fixes cannot attribute a behaviour change to
either. Three pre-existing defects were found while moving code and **all three
were moved verbatim**:

1. **An orphaned doc comment glued onto the `PORT_WRITER_SECTIONS` import** —
   `crates/c2-harness/src/gap/mod.rs:332-354` (was `gap.rs:324-346`). The block
   opens with a bare `///` where a summary sentence should be, then documents
   *compiler-generated symbol prefixes* (`??_G` scalar deleting destructor,
   `??_E` vector deleting, …) — which is `is_compiler_generated`'s
   documentation, or a deleted const's — and only at line 342 begins the actual
   `PORT_WRITER_SECTIONS` doc. Two unrelated doc bodies render on one `use`.
2. **`fn_complete_histogram` carries what reads as `fn_dispatch_histogram`'s doc
   comment** — `crates/c2-harness/src/gap/report.rs:104-111` (was
   `gap.rs:681-689`). The comment says *"**The body-dispatch axis**, aggregated…
   See [`TuResult::fn_dispatch`] for the row shapes"*, but the function it sits
   on reads `r.fn_complete`, the grammar-completeness axis; `fn_dispatch_histogram`
   immediately below has no doc at all. The two look swapped.
3. **The `c2rs census` command doc is attached to `fn hexdump_marked`** —
   `crates/c2-harness/src/cli/census.rs:11-19` (was `main.rs:450-457`). The
   hexdump's own three doc lines were appended *below* the command's, so
   `cmd_census` has no doc comment and its helper carries one.

None affects behaviour. All three are cheap for a later lane; each needs someone
to decide what the text *should* say, which is a judgement, not a move.

## 8. What was deliberately NOT split, priced

| left alone | lines | price of leaving it |
|---|---:|---|
| `scan_one` (`gap/scan.rs`) | 795 | one linear pass whose ten labelled steps mutate a single `res: TuResult`, and whose step comments **explicitly forbid sharing a variable between steps** (§10.18's record of 865 TUs silently changing class). Extracting helpers means inventing parameter lists and threading `res` — a behavioural risk, and not a move. |
| `cmd_gap` (`cli/gap.rs`) | 821 | one function body, not a set of items. Its reporting section is the natural seam, but lifting it means inventing a signature and threading ~20 locals. Same reason. |
| `print_factorization` (`gap/render.rs`) | 281 | one straight-line sequence of `println!`s over locals bound at the top. |
| `corpus.rs` | **1,323** | now the largest file in the crate, and untouched. It was outside the commissioned three; splitting it is a further lane at roughly this one's cost per file. |
| `capture_cache.rs` | 1,114 | same. |
| `tests/cli_flags.rs` | 969 | it is the file that *checks* this lane's invariant; restructuring the checker in the same change as the checked would be the worst possible ordering. |
| `search/similarity.rs` not divided at decode/score | 452 | the boundary runs through `PpcInsn`/`Operand` fields and would cost ~6 more visibility widenings for no reader benefit. |
| `search/tests.rs`, `gap/tests.rs` kept whole | 1,098 / 979 | ~15 helpers are shared across tests that would otherwise land in five modules; a shared test-helper module plus cross-imports is more churn and more risk than the split saves. |

**The honest summary of the ceiling:** a mechanical, zero-behaviour-change pass
can move *items* between files. It cannot decompose a 795-line function, because
that requires choosing an interface, and choosing an interface is a change. The
resting point for this lane is `1,098` lines, and everything above `800` in the
list above is a single function body or a single test module.

## 9. How it was run

Four worktrees off `b6fa935`: three sub-lanes with **disjoint file seams**
(`gap.rs`, `main.rs` + `tests/cli_flags.rs`, `search.rs`) so they could not
collide or break each other's builds, and one integration worktree that held the
baseline. Each sub-lane ran `cargo test --workspace` and its own faithfulness
checks; **none of them ran `scripts/gate.sh`** — eight concurrent gates is how
this box gets into trouble. The gate ran **once, serially, on the integrated
tree**, after all three merges and both follow-up commits.

The baseline was taken **in the integration worktree itself**, not in the main
repo, so the before/after comparison holds the environment fixed.

> **A worktree trap, recorded because it cost this lane a full baseline run.**
> The first `scripts/gate.sh` in the worktree returned `GATE: SKIPPED — all 18
> lanes, the sweep and the cross skipped, NOTHING WAS GRADED`, exit **0**.
> `Toolchain::locate` resolves `compilers/` and `../wibo` relative to the *repo
> root*, which is `CARGO_MANIFEST_DIR/../..` — **the worktree**, not the main
> repo — and `compilers/` is gitignored, so it is absent from every fresh
> worktree. `scripts/configure_existing_worktree.sh` exists precisely for this
> and says so at length; this lane instead set `C2RS_COMPILERS` / `C2RS_WIBO` /
> `C2RS_GAP_CACHE` explicitly, which has the advantage that the before and after
> runs are provably identically configured. Either way: **a gate run from an
> unconfigured worktree grades nothing and exits 0**, and the only thing that
> distinguishes it from a green run is reading the verdict line.
