## 1. `Sort.cpp` re-derived — the brief's characterization, and where it breaks

The brief supplies `src/system/math/Sort.cpp` as *"one function (`HashString`),
80 bytes, zero relocations, no `.pdata`, no `$M`/`$T`, no `.data`, no `.rdata`.
Blocked **only** by `cflow-loop`"*, and adds *"unlike every previous attempt, the
thing in the way is one structural gap rather than a chain of unmodelled
tokens."* It instructs the lane to verify that itself.

**Every stated fact reproduces.** `c2rs gap` on the TU alone: 1 emitted, 1
blocked, factor A/B/C all 1, byte fraction **0/80 = 0.0 %**, CFG screen *"needs a
CFG class the port lacks: `cflow-loop`"*. The obj is 5 sections
(`.drectve`, `.debug$S`, `.XBLD$W` × 2, `.text`), `nrel = 0`, 14 symbols, no
`$M`, no `$T`, no `.pdata`, no `.data`.

**The implied fact does not.** Here is the whole function
(`?HashString@@YAHPBDH@Z`, `/O1 /Oi /EHsc /GR …`):

```text
0000  89630000  lbz    r11,0(r3)        ; *u
0004  7c691b78  mr     r9,r3            ; u = str
0008  39400000  li     r10,0            ; ret = 0
000c  280b0000  cmplwi cr0,r11,0
0010  41820038  beq    cr0,+56          ; -> 0x48
0014  1d0a007f  mulli  r8,r10,127       ; <- loop top:  ret * 0x7F
0018  8d490001  lbzu   r10,1(r9)        ; UPDATE-form byte load: r10 = *++u
001c  7d085a14  add    r8,r8,r11        ; + *u
0020  7d4b5379  mr.    r11,r10          ; record form -> cr0, the loop test
0024  550a083e  rotlwi r10,r8,1         ; \
0028  7ce823d6  divw   r7,r8,r4         ;  |  the signed `%` expansion, with the
002c  394affff  addi   r10,r10,-1       ;  |  INT_MIN/-1 trap predicate
0030  7ce721d6  mullw  r7,r7,r4         ;  |  INTERLEAVED between divw and mullw
0034  7c865078  andc   r6,r4,r10        ; /
0038  0cc40000  twi    6,r4,0           ; TRAP if i == 0
003c  7d474050  subf   r10,r7,r8        ; ret = r8 - (r8/i)*i
0040  0ca6ffff  twi    5,r6,-1          ; TRAP on the overflow case
0044  4082ffd0  bne    cr0,-48          ; <- BACK EDGE, on cr0
0048  7d435378  mr     r3,r10
004c  4e800020  blr
```

Counted the way `w-conv` counted the frontier (independent facts the port does
not have, stopping when the ≥ 4 decline clause has plainly fired):

1. the back edge itself — the class this lane was sent for;
2. a signed `%` as `divw` + `mullw` + `subf`;
3. **two `twi` trap instructions**, MSVC's divide-by-zero and `INT_MIN / -1`
   guards, which nothing in `docs/` mentions;
4. the three-instruction trap predicate `rotlwi` / `addi` / `andc`;
5. `lbzu` — an **update-form** byte load, i.e. the pointer induction is folded
   into the load;
6. `mr.` — a record form used as the loop test, so the branch is on **cr0**;
7. `mulli` against a literal 127;
8. the **schedule**: the trap predicate is interleaved *between* `divw` and
   `mullw`, which is not the source order and not the obvious emission order.

**`cflow-loop` is the first refused thing, and `CFG_SHAPE.md` §5.0 Trap 1 says in
terms that a blocker name is never a promise that granting it converts.** The
honest reading is that `Sort.cpp` is a chain of unmodelled tokens *with a loop
around it* — the shape the brief says it is not. Board **#740**.

## 2. What a leaf loop costs the label counter

`docs/LABEL_COUNTER.md` **§4.2.1** carries the table; it is not repeated here.
The three things that matter for a rung:

* **17 seed-free cells, anchor control 5 on every row.** `while` +2, `do/while`
  +1, `for` +2, `for(;;)`+`break` +3, nested +4, two sequential +4, backward
  `goto` +1, `Sort.cpp`'s pointer-walk shape +3, `Primes.cpp`'s indexed-load
  shape +2 — against `leaf-none` = 1, which reproduces the shipped `leaf-int`.
* **The integers are §4's framed integers**, row for row where the two grids
  overlap. The control-flow surcharge does **not** key on frame class. That
  closes the last route by which a loop rung could have avoided the counter.
* **`minted` is 1 on every row.** The surcharge mints nothing — §2.1's shape, a
  fourth time.

## 3. The counter is not a function of the emitted object — now at the byte level

§4.1 closed *"derive the surcharge from the blocks"* with `ho-ternary` and
`cf-ifelse`: the same emitted **shape**, +2 against +1. The leaf grid closes it
with the same emitted **bytes**.

```text
  do/while       int P(int a){ int r=0; do { r=r+a; a=a-1; } while (a); return r; }   +1
  for(;;)+break  int P(int a){ int r=0; for(;;){ r=r+a; a=a-1; if(!a) break; } … }    +3
  goto           int P(int a){ int r=0; top: r=r+a; a=a-1; if (a) goto top; … }       +1

  .text, all three, 24 bytes, IDENTICAL:
  7c6b1b78 38600000 7c635a14 356bffff 4082fff8 4e800020
```

And from the other end: `for (int i=0;i<10;i++) r=r+a;` emits **8 bytes with no
control flow at all** — `mulli r3,r3,10 ; blr` — and charges **+2**.

Board **#743**. A lane that fitted the charge to the emitted CFG would fit it to
a body that has none.

## 4. The emission grid — what it closed in `CFG_SHAPE.md` §8.2

All 17 bodies at `/O1 /GS- /c` as leaf-only TUs, `mtctr`/`bdnz` counted by
opcode and every backward branch classified by its own sign.

**L2 — when CTR.** Computable entry trip count **and** no call in the body:
`while`(decrement), counted `for`, **stride 3**, counting down, `+continue`,
indexed load — **7 cells**. Otherwise compare-form: `do/while`, `for(;;)`+`break`,
backward `goto`, `+break`, pointer-walk-to-sentinel — **5 cells**. The
discriminator is *"is there an entry test whose trip count c2 can compute"*, not
the loop keyword. (`leaf-for-k`, `i<10`, is a thirteenth cell that emits no loop
at all.)

**L3 — partly.** Stride 3 gets CTR, so c2 **does** compute `(hi−lo+k−1)/k`. The
computation is still unmodelled and a non-zero start is still unvaried.

**L4 — one cell moved and the obvious rule is dead.** `+continue` **keeps** CTR
here, where §3.7a's `?d_cont` (call-bearing) got the compare form. So the entry
form is not decided by *"a `continue` makes the test a join target"*. Still
unstated.

**L5 — the rotation held on 28 more back edges.** **0 of 28** backward
intra-section branches is unconditional; every one is `bdnz` (`BO=16, BI=0`) or a
`bc`. The cell registered as most likely to break it — `for(;;)` whose only exit
is inside the body — emits `bne cr0` and is byte-identical to the `do/while`.
§3.7a now holds on 35 cells across two grids and two frame classes.

**L1 — register allocation across the back edge — is untouched and is still the
largest unknown**, and §1's `HashString` is what it looks like in the wild: four
live GPRs, an update-form load folding the induction variable into the addressing
mode, and a schedule that is not source order.

## 5. What was built, and the one thing that was deliberately not

### 5.1 Built — the LABEL CHANNEL, per TU, on every scan (#742)

`coff::plan_labels` returns `Some([n, n+1, n+2])` for a function with a `frame`
and `None` for a leaf, and `label_name` is its only renderer. So **`$M<n>` /
`$T<n>` short names are the only channel by which the counter's value reaches an
object file** — and §2's charge, real as it is, has nowhere to land in a TU
without one.

c2 agrees, and the control is what makes that a reading:

```text
  leafonly     the probe alone                 0 labels   17 of 17
  leafx3       the probe and two more leaves   0 labels   17 of 17
  leaf_framed  the probe THEN a framed fn      3 labels   17 of 17   <== CONTROL
```

**34 of 34 leaf-only TUs mint zero labels, 28 of them carrying a backward
branch.**

Shipped as `c2_obj::ObjImage::compiler_label_symbols` (read off the **reference**
obj, five unit tests) plus `emit-label-{readable,unreadable,syms,free}` in the
scan and a column on the CFG-reachability screen. **Fail-closed in three states,
not two**: an obj that does not decode prints `label ??` and never `label-free`,
because *absence read as success* is this project's most-repeated defect and this
is exactly its shape.

On the 878-TU workload: **4 of 18** frontier TUs are label-free; of the **6**
blocked on `cflow-loop`, **3** are — `Sort.cpp`, `Primes.cpp`,
`IPP_basicmath_xbox.cpp`, six loop functions between them. The other three
(`EncryptXTEA`, `jsonwriter`, `keygen_xbox`) carry labels and a loop rung must
charge them correctly.

**An instrument, never a licence.** It reads c2's own output, moves no
numerator, appears in no accept path, and every label-free TU is still gated on
codegen that does not exist.

### 5.2 Corrected — `codegen::labels`' stated reason

Invariant 4 refuses every backward reference and its justification reads *"the
obj would carry a wrong `$M`"*. That is **conditional on the TU having a framed
function**, and w-label's grid could not see the condition because all 33 of its
probes are framed. The module header and the refusal text now carry both halves:
the charge (which is why the refusal is right) and the channel (which is where
its damage can land). No behaviour changed; **the refusal is unchanged and still
fires on every backward reference.**

### 5.3 NOT built, on purpose — the relaxation, and where it belongs (#746)

The measurement licenses exactly one relaxation: *a backward branch is byte-safe
when no function in the TU mints a label triple.* It is **not** shipped, for
three reasons and each is load-bearing:

1. **The counter is only the first refusal.** §1 and §1.1 price every one of the
   six loop TUs at ≥ 4 independent refusals. Relaxing the counter converts
   nothing.
2. **`Selected` still has no variant with a back edge**, so no caller would pass
   the relaxation and a `resolve` that accepted one would be an **ungraded code
   path by construction** — w-frame row **F-c**, the same argument that keeps the
   long-branch expansion unbuilt.
3. **The precondition is TU-level and `LabelMap` is per-body.** The mechanism
   that *can* see it already exists: `IlBundle::functions` demands
   `label_slots(..) == 1` from every non-framed function in a TU containing a
   framed one, and is three-valued so an unmeasured class refuses. **A loop body
   returning `None` there refuses in exactly the TUs where §5.1 says the charge
   is observable and admits in exactly the TUs where it is not** — no new
   constant, no fitted rule. That is where a loop rung puts it.

**And the honest form of the refusal**, in the brief's own terms: the fold
between `do/while`'s +1 and `for(;;)`+`break`'s +3 is a rule this lane could
state and could not test — §3's identical-bytes triple means the port would have
to tell them apart from the *IL*, and two source shapes that differ only in a
`break` are exactly the cell where a fitted rule would be a hypothesis. So the
port keeps refusing, and the measurement ships with the refusal — `CFG_SHAPE.md`
§3.5's declined fold model, one level up.

## 6. The corpus question, answered before it was needed (#747)

`work/w-loop/PREREG.md` §4 registered, before any measurement:

> the breaking shape is **a TU where a loop leaf is followed by a framed
> function** … the generated sweep enumerates single-function TUs at `/Ox`, so
> **it cannot express this shape at all**.

That is now confirmed, and it is sharper than a caveat: `expr_sweep.sh` generates
single-function TUs, and `mode_cross.sh` crosses the *same* corpus with the lane
registry. **Neither standing instrument can produce a two-function TU of mixed
frame class**, so both would grade a wrong label charge green — the same family
as the standing `gate.sh cannot see expr_sweep` finding, one level down, where
the sweep *does* run and still cannot represent the class.

The 17 `leaf_framed` probes that *can* express it live in `work/w-loop/`, which
is not the gate. **Any lane that ships the §5.3 relaxation owes a committed
fixture of that layout as a deliverable, not as an extra.** Written down here so
the next lane inherits the requirement rather than the omission.
