(w-rdata) are untouched, as are `scripts/`, `fixtures/`, `tools/`,

| | |
|---|---|
| `GapReport::factor_letters` | one TU's five factors as `"AB-D-"` — fixed width, fixed order |
| `GapReport::factor_membership` | `(src, class, letters)` for every **graded** TU |
| `GapReport::factor_tsv` | the file body, pure, so the unit test grades the bytes with no toolchain |
| `c2rs gap --factors-tsv PATH` | writes it. Off by default |

**Two design decisions, both load-bearing.**

* **A `capture-fail` TU is ABSENT from the file, never a `-----` row.** It has no
  obj and no census: it was never measured, which is a different fact from every
  factor being false. A consumer summing absences as zeros would report every
  factor *tighter* than it is — `docs/STATUS.md` trap 5 with the mask on.
* **A file, not stdout.** `c2rs gap` also grades the generated case corpus
  through `scripts/mode_lane.sh` and `scripts/mode_cross.sh`, where "one line
  per graded TU" is tens of thousands of lines per lane, twelve lanes over, plus
  the mode cross's 75,829. stdout gains **exactly one line**, and it states the
  NOT-REQUESTED case **positively**, so "the membership was never asked for" and
  "the membership is empty" cannot look alike.

The unit test grades the property that makes the file a publication of the *same*
measurement rather than a second one: **every joint in the `GAP-METRICS` block is
re-derivable from the rows.** If the rows and the counts could disagree, an
intersection taken against the rows would not be an intersection with `B∧C`.

**Deliberately NOT done:** the `--jsonl` per-TU record is unchanged. `scan.rs`
documents that its rows carry no `record` field so two scans stay
byte-comparable, and appending a field to serve one lane is not worth spending
that. The TSV is complete on its own.
