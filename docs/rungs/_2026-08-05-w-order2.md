## 1. Result

Board **#544** — *"the store ORDER when every store of the run is produced"* —
is closed, and closing it **absorbed rule 1**.

> **ORDER.** Rank the run's distinct value-producers by **(use count
> descending, first-use source index ascending)**. Let
> **`u = min(2, #unproduced)`**. A store whose producer has rank `j` may not
> occupy store position `< u + j`; an unproduced store is never blocked. Walk
> the source statements in order and emit the earliest allowed store.
> Producers are emitted in **rank order** — the first `u` interleaved one
> apiece, the rest contiguous before slot `u`.

`w-sched`'s **rule 1** is `j = 0` with `u = 2`; `w-alloc`'s **hoist** is
`j = 0` with `u < 2`. Both are recomputed in `order.rs`'s tests rather than
transcribed. Rule 1's *"if every remaining store is blocked, source order
wins"* fallback is **deleted**, not carried — with `u < 2` the floors drop with
it and nothing is ever fully blocked. **The relaxation branch fired 0 times**
on all 1,301 measured cells and on all 5,460 runs the enumerating test walks.

The holdout was declared before `grid.py` was written, partitioned by the
generator, and scored only after the rule was frozen at commit **`980e42e`**.
`search.py` **refuses** to open any path containing `holdout` — a raise.

## 2. The two families, characterised before anything was fitted

`w-alloc` left the residual as *"structured but not one family"*. It is
**exactly two families plus a five-cell measurement artifact**, and every other
`(counts, unproduced)` family in its 526-cell grid is 0 miss:

| family | counts | unproduced | cells | misses |
|---|---|---:|---:|---:|
| **A** | `(2,2,1)` | 0 | 99 | **44** |
| **B** | `(2,1)` | 2 | 62 | **20** |
| artifact | kind `W` | — | 5 | **5** |

* **Family B was never a new regime.** Its 20 misses are exactly the cells
  whose produced sub-word begins with the **count-1** value; the 42 beginning
  with the shared value are hits. `w-alloc` gated the hoist on the unproduced
  stores running out — they had not run out, and the hoist fires anyway.
* **Family A is a rank effect, not a count effect.** Two producers tie at
  count 2, one has count 1, and the count-1 store is displaced to position 2 —
  while in counts `(2,1)` with no unproduced store it **stays at position 1**.
  No release time keyed on a store's own use count can separate `aba` from
  `abcac`, and that is the whole of §3.
* **The artifact is kind `W`.** `lis`+`ori` is **two** instructions and every
  canon in `work/` emits one token per producer. Board **#562** — a fact about
  the observation, not the order.

## 3. The corroborating negative — again the more valuable half

Preregistered in §5 and run **before** ORDER was scored on the holdout: an
exhaustive search over the class every release-time answer lives in — 2
counters × `4^9` thresholds over `{unproduced} ∪ {count 1,2,3,≥4} × {first
use?}` × 2 tiebreaks = **1,048,576** configurations, of which `w-sched` rule 1
is a member.

```
CEILING 196 of 250 fit cells  (78.4%)

RESIDUAL of the best configuration:
  rank order != producers' source order    93 cells,  50 miss
  rank order == producers' source order   157 cells,   4 miss
```

Two producers can tie on the use count and still take different ranks, so no
member of that class can carry the axis — **and the residual says so in its own
shape**. Third lane running, third time the answer was outside the class being
searched, third time the residual named the mechanism rather than the score.

## 4. Two corrections to my own prereg, both made on FIT and both recorded

* **Clause (b)'s counter was wrong, and correcting it made the rule shorter.**
  The version frozen *with the prereg* at `7ee557e` counted **produced stores
  already emitted**; it scores **246 of 248** on FIT and both misses are one
  shape — three unproduced fillers ahead of a produced word beginning with the
  lower-ranked producer. Discovery could not contain it: five-statement runs
  with three fillers leave two producers whose ranks can never disagree with
  source order. The floor `u + j` replaces it, and it is what lets clause (a)
  *and* the fallback be deleted. `order.py` stays committed beside `order2.py`
  so the frozen original is on the page.
* **R4's axis was wrong.** I predicted the search's residual would concentrate
  on **tie** cells. It concentrates on the strictly more general
  `rank ≠ source order` — and it had to, because my own holdout clause 2 had
  already removed nearly every tie cell from FIT. See §5, R4.

## 6. What `xboxheap` now says, and it is not nothing

`STORE_SCHEDULE.md` §5 recorded `xboxheap`'s producer placement as *"one
instance. Not a rule."* It is now a **discriminated** fact:

* `xboxheap` — three unproduced stores, then a count-1 producer whose store
  precedes a count-2 producer's, through **two** base symbols — emits the
  **count-1** producer first (`li r10,0` before `addi r11,r3,8`).
* **Eight cells of this grid have that exact statement shape through ONE
  symbol** — `t3_011_FFFvvv` and `t3_011_vFFFvv` in fit, six more in holdout —
  and every one emits the **rank-0** producer first.

Eight controls one way, one cell the other, one axis between them. `order.rs`
**refuses** a multi-symbol run rather than guess; board **#564** is the grid
that would settle it. This does not convert `xboxheap` — `w-alloc`'s R8 found
it blocked on three *parse* facts and an order rule cannot unblock a parse —
but it moves the remaining instruction-order question from *"unknown"* to *"one
named axis, with controls on both sides"*.

## 8. Found and not taken

1. **How two same-symbol runs compose** (board **#564**) — the biggest item
   this lane opens, and the only one that touches the FRONTIER. The grid is a
   symbol-split axis crossed against producer ranks; the eight controls above
   are already compiled and one side of it is already known.
2. **The `W` producer's width** (board **#562**) — five cells, and the fix is
   one field in the canon (`P` tokens carry an instruction count). It would
   also let `alloc.rs` stop refusing `lis`+`ori` runs.
3. **The reuse choice** (board **#541**) and **`r12`** (board **#543**) are
   untouched: this lane's signature is capped at three formals so that it
   cannot measure the pool, which is deliberate — `w-alloc` found `w-sched`'s
   six-formal signature ate its own pool from below and manufactured a
   "conflicted cells" table.
4. **Four-producer store order is already exact** — 822 of 822 — and only the
   *register* is refused there. If #541 falls, the order costs nothing.
5. **A shared-module-name trap**, worth a minute from whoever writes the next
   lane's scripts: `work/w-alloc/` and `work/w-order2/` both carry a `model.py`
   and a `search.py`. A bare `import search` resolves by `sys.path` order and
   silently picked up `w-alloc`'s here, surfacing as a missing *attribute*
   rather than a wrong module. Everything in this lane imports by explicit file
   path; `docs/ORDER.md` §6 says so where the next reader will be.
