## 2. Why four grids missed this for five months, and it was one line of C

`P_GLOBREGS` §7.1 closes: *"the separator remains unbuilt."* The reason is
structural and it is about the grids, not about c2:

> **Every register-order cell this repo had ever compiled welded the
> DECLARATION order and the DEFINITION order together.** `wb-live`'s ten,
> `wb-regalloc`'s fifteen, `w-dagorder`'s twenty and R4's own
> `scripts/globregs_c2.py` all write `int x = …; int y = …;` or use formals, in
> which the two orders are the same sequence *by construction*.

Declare first and assign in the other order — `int x, y;` then
`y = p[1]; x = p[0];` — and the observable moves. **Declaration order moves the
map by zero cells; use order by zero cells; definition order moves it every
time.** All six N=3 permutations give six distinct maps, which is the grid's
positive control firing.

The readout was also changed on purpose: R4 read the **formal → register** map
out of prologue `mr` moves, and a formal's arrival register is itself a
declaration-side property that confounds every declaration-order rival. This
lane reads **locals defined by an indexed load off one pointer formal**, so
`p[0]` and `p[1]` are told apart by *displacement*.

treated the C++ type as the thing the gate sees.** c2 sees what c1xx lowered

**One HIT this lane refuses to bank**: `pc_struct2` was predicted MEMORY and
*is* MEMORY, but the deciding pair (`pa_struct2cpy` MEMORY vs `pa_struct2mem`

not evidence for the mechanism.

**ADDENDUM 2 is one hit and one miss on the same cell pair, and the miss is the
useful one.** `ob_loop_y` moved the order as predicted — `DEF` refuted for the
first time in 48 cells, `cand+0x0c` shown to respond to a loop-weighted use
count — and `ob_loop2_y`, the deeper loop predicted to move it *more*, did not
move it at all. **A deeper loop moving the key less than a shallower one is not
a behaviour this lane has a model for**, and it is published as an anomaly
rather than smoothed into a rule.

### The ceiling this lane registered, and the half of it that broke

`PREREG.md` §5.4 registered, **before any cell existed**, that this grid could
not separate `cand+0x44` from `cand+0x0c`, because moving a definition moves
the live interval too. **Half wrong, and the addendum said so before compiling
the cell that showed it:** holding the definition order fixed and moving the
**last use** changes the interval and leaves the ordinal alone.

That gives `#3778`: `P_REGALLOC`:71's `cand[0x0c] += cand[0x18] * n_live` is
monotone in live extent **under either sign of `+0x18`** and therefore predicts
`LIVELEN` — refuted by 14 of 48 cells. **The published formula, as published,
cannot be the whole story.** Filed here and cited from `P_GLOBREGS` §7.1 only;
`P_REGALLOC.md` was **not edited** (seam assignment).

**The half that stands** is whether the 42 straight-line cells are decided by
`+0x44` or by a definition-ordered `+0x0c`. `UNCOMP`.
