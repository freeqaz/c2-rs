## 1. What was built

### 1.1 S1b — the collapse (`196eabde6`)

Three variants that carried the same payload — a `Vec<u8>` of finished words —
and differed **only** in a post-body obligation that lived, spelled out twice,
in the two dispatchers:

```rust
pub enum Terminator { None, TailCall, MemcpyCall }
Selected::Body { text: Vec<u8>, term: Terminator }
```

Producers keep their spelling through `Selected::plain()` / `::tail()` /
`::memcpy_tail()`, so all **24** producer sites are a one-word diff. The
retired variants return as `#[cfg(test)]` views (`as_plain`, `as_tail`,
`as_memcpy_tail`) — S1's own instruction, in S1a's `mod incumbent` shape.

**The construct content beyond the collapse is `terminator_callee()`.** The
callee resolution was the "one rule, two implementations" shape `docs/GAPS.md`
§6 keeps recording — `f.tail_call().expect(…)` in one arm and `MEMCPY_NAME` in
the next, **in two different files** — and it is now one function both
dispatchers read.

### 1.2 S1c (i) — the op stream (`221898f4f`, `1c0b4b7ae`)

* **`mop_X` for 22 encoders** — the `MachineOp` *unrendered* — with `encode_X`
  redefined as `mop_X(args).word()`. Required-zero **by construction**: the same
  expression, with the `.word()` moved.
* **`codegen::mop::{Ops, ops_to_bytes}`** — the one boundary at which an op
  stream becomes bytes, composing through `EncodeParams::C2`, the default and
  nowhere else.
* **6 producers build `Vec<MachineOp>` natively**: `global_store_leaf`,
  `addr_leaf`, `indirect_load`, `nonce_add_run`, `div_mod_leaf`, and the
  `EmptyBody` arm — plus the void-tail arm, whose setup is now the **empty op
  stream** rather than an empty byte vector.

**The denominators, because a fraction without one is not a result** (standing
rule 4, #3356): **22 of 85** encoders; **6 of 18** `Selected::plain` producers;
**1 of 5** `Tail` construction sites.

### 1.3 A correction to the count of `Tail` producers

`w-s1` §6 and its prereg both say **4** `Tail` producers. There are **4
`BodyShape` arms** and **5 construction sites** — the plain `Tail` arm splits on
`func.ops.is_empty()`, a void tail call producing an empty setup and an integer
one producing its text minus the last word. Both numbers are right and they
answer different questions; this rung says which is which rather than picking.

### 1.4 The decision surface — a stated NULL, not an invented parameter

`GOAL_DECISION_2026-08-21.md` § AMENDED and `ROADMAP_SLICING` §6 rule 7 require
a general layer to ship its arbitrary choices as named, settable parameters.
**Registered in the prereg §1.5 before measuring, and it held: S1b has no
arbitrary choice to expose.** The terminator is a total function of the
`BodyShape` arm; there is no configuration in which a different value reproduces
c2, so exposing it as a *parameter* would be a fake surface — worse than a
stated null. What S1b ships is the **name**. S1c (i) inherits S1a's real surface
(`EncodeParams`) unchanged and adds none.

### 3.1 The finding: ONE unchanged binary produced FOUR different `fnbyte-exact` readings in two hours

`w-s1` §7.1 found the filed threshold was three different numbers and said
*"re-derive it on your own tree at your own base, with the workload stamp beside
it."* **This lane found the sharper version of that, because it measured four
times in one session:**

| `fnbyte-exact` | source | corpus |
|---|---|---|
| **35,894** | `ROADMAP_SLICING` §5 and every brief | unrecorded |
| **35,886** | `docs/STATUS.md` generated block | tree `977827d78` |
| **35,891** | `w-s1` §7, `w-s0` independently | `e5aef017d456` |
| **35,885** | **this lane's base binary** | `209f943d401f` |
| **35,890** | **the same binary** | `36d344f0504a` |
| **35,905** | **the same binary** | `562e734427c7` |
| **35,898** | **the same binary** | `d0a1a127c7cc` |

**The bottom four rows are one unchanged binary over four corpora, spread over
about two hours.** `../dc3-decomp` is a live repo other agents merge into; it
moved from `e5aef017d456` to `6f5fa9ccfcd7` before this lane took a single
measurement, then again to `209f943d401f` inside the next minute, and four more
times before the lane finished.

Three consequences, and the first two are already load-bearing:

1. **A stop condition keyed to a filed number is not a stop condition — it is a
   coin flip.** Scoring this lane's final tip (35,898) against the brief's
   35,894 reads *"`fnbyte-exact` moved by 4"* and, on the registered rule,
   **should have stopped the program.** Scoring it against `w-s1`'s 35,891 reads
   *"moved by 7."* Both are artefacts of the corpus, and **the port emitted
   identical bytes throughout.**
2. **Pinning the tree is not enough; the BINARIES must be pinned.** This lane
   copied `target/release/c2rs` per arm and ran base and tip **back to back**,
   checking the stamp before and after. Without that, base and tip land on
   different corpora and their difference is not zero-or-nonzero, it is
   meaningless — #3048's reasoning one level out. **The first base scan of this
   lane is at a corpus no later scan shares, and it is reported above rather
   than deleted.**
3. **`docs/STATUS.md`'s standing instruction needs a sharper form for
   thresholds.** "Quote it from a scan, never from a page" is necessary and not
   sufficient: a scan taken an hour apart is a *different* scan. A threshold and
   the corpus it was taken over are **one fact**, and a lane that publishes the
   figure without the stamp has published half of it.

**Registered response, unused: this lane did not patch, tune, or explain away a
move, because there was none to explain.**

## 4. Criterion B — the pre-registered COST criterion (#3336)

Protocol: `ir0`'s, reused verbatim and extended to **four arms** so S1b's and
S1c's prices are measured against **one** base in one protocol run —
`base`, **`nulldup` (a `cp` of base verified byte-identical with `cmp`)**,
`s1b`, `s1c`; **8 rounds**, arm order **rotated every round**; estimator = per
fixture and arm, the **minimum port median over the 8 rounds**; pairing per
fixture; the reference column never entering. Population **n = 153**, the
fixtures the port `Match`es — the exact set `perf`'s geomean is computed over,
published beside every figure.

### 4.1 The measurement — **both arms PASS**, and one went against its prediction

| pair | port time per obj | 95% CI | median | aggregate | slower on |
|---|---|---|---|---|---|
| **`nulldup` vs base — NULL, byte-identical** | **−0.08 %** | [−0.34, +0.17] | −0.15 % | −0.16 % | **70 of 153** |
| **`s1b` vs base** | **−0.70 %** | [−0.98, −0.42] | −0.76 % | −0.31 % | 58 of 153 |
| **`s1c` vs base** | **+1.78 %** | **[+1.24, +2.31]** | +1.47 % | +3.71 % | 110 of 153 |

**Registered verdict for both: PASS** — the registered band was `< +5 %`.

**The null arm reads −0.08 % and splits the sign 70 of 153** — 46 %, about half,
as an effect of zero must, and the same behaviour `ir0` and S1a measured. So the
estimator is unbiased on this run and its floor is **±0.08 %**, with a CI
half-width of ±0.25 %. S1a re-derived ±0.15 %; the two agree.

### 4.2 A registered prediction that MISSED, reported as a miss

Prereg §2.3 predicted **S1b would land inside the null arm's CI** — "below the
noise floor", not "no cost". **It did not.** S1b's CI `[−0.98, −0.42]` does not
overlap the null's `[−0.34, +0.17]`, so it is distinguishable from an effect of
zero, and it is **negative**: the collapse makes the port about **0.7 % faster**.

That direction is explicable after the fact — three dispatcher arms with
identical bodies became one, in both dispatchers — but this rung does not
promote an after-the-fact explanation to a finding. **What is registered is that
the prediction was wrong in a way the protocol was capable of detecting, and
that a 0.7 % speedup is not a reason to land anything.** S1b's case rests on
criterion A.

### 4.3 The noise floor is a property of the BOX, not a constant

This lane ran the protocol **twice** — once on the pre-fixup tip while four peer
lanes were live, once on the final tip. The **null arm's own reading moved**:

| run | null arm | sign split |
|---|---|---|
| first (box loaded, load avg 50–90) | **+0.47 %**, CI [+0.12, +0.83] | 88 of 153 (**57 %**) |
| final (box quieter) | **−0.08 %**, CI [−0.34, +0.17] | 70 of 153 (**46 %**) |

**On the first run the null arm's CI excluded zero and its sign split was
visibly off half** — an effect of exactly zero reading as a +0.47 % cost. Had
this lane quoted only that run, S1c's +1.9 % would have been reported against a
floor that was itself an artefact. **The sign split is what exposed it**, which
is why the registered protocol publishes it rather than only a mean. Both runs
are recorded; the final tip is graded by the final run.

## 8. WHAT THESE CONTROLS COULD NOT CATCH — and one thing they demonstrably did not

Prereg §5 registered six of these before measuring. **One of them stopped being
hypothetical during the lane**, which is why it is first.

### 8.1 A defect that shipped, was byte-identical, and was caught by reading the diff

This lane's own generator inserted each `mop_X` **between** its encoder's doc
comment and the encoder's signature. Rust attaches a doc comment to the item
that *follows* it, so all 22 hand-written evidence notes — the transcribed
captures, the `xo` values read off `bits.cod`, `encode_subf`'s
non-commutativity warning — **silently moved onto the generated function**,
leaving the encoders undocumented. The generated text then read *"see `encode_X`
for the evidence note"* while pointing at a function that no longer had one.

**Bytes were identical, all 618 c2-core tests were green, the gate was green,
and the identity diff was 0 lines — both before and after the fix
(`1c0b4b7ae`).** It was found by reading the diff. This is #3336's thesis
demonstrated live rather than cited: **a required-zero byte delta is silent
about everything that is not a byte**, and on this project the evidence notes
are a first-class deliverable under goal (1).

### 8.2 The five registered in advance, restated

1. **The packed `MemcpyCall` arm is unreachable by construction** — `/O1`-only
   class, `/O1` implies `/Gy` — so its rewrite is **graded by nothing**. Named
   in the prereg before measuring; still true.
2. **The gate exercises the `Selected` variants its fixtures happen to
   contain.** `Selected` has 20.
3. **`fnbyte-refused-parse` was 113,543–113,557 of ~162,190** — roughly **70 %
