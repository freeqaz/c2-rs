## 2. The instrument, audited before its output was trusted

The brief's standing rule — *an instrument that has never been audited is not
evidence* — and this one had a live defect.

### 2.1 The sampler was a stride, and it aliased on the corpus's own loop period

`--write-classes` measures `p` cases per fragment, picked
`cs[::ceil(n/p)][:p]`. A spread and not a prefix, which is the trap
`expr_sweep.sh` records. **It has its own version of the same failure.** A
`sweep.d/` fragment is a nested loop, so its case list is periodic; a stride whose
step is a multiple of an inner period lands on the same inner coordinate every
time — maximally spread in index, degenerate in structure.

At the incumbent `--per-fragment 24`:

```text
  88-store-run-call   n = 1576   step = ceil(1576/24) = 66
  its block 1         20 run/bind pairs x 3 widths x 22 setup/form cells
                      = 66 cases per run/bind pair          <- the same 66
```

so `cs[::66]` returned index 0, 66, 132 … — the **`w0 / cnone / fctor`** cell of
each run/bind pair, which is the leaf control with **no call**. Measured
(`work/w-classes/stride_audit.py`):

```text
  88-store-run-call   strided p=24   with-a-call   3/24  (12%)
                      stratified     with-a-call  20/24  (83%)
                      corpus                    1438/1576 (91%)
```

The fragment exists to grade *a store run followed by a call*, and the sample its
class row would have been measured on was **87.5 % call-free**. The direction of
the error is the unsafe one: a degenerate sample separates fewer lanes, writes a
**coarser** row, and silently removes grading.

Replaced with a **stratified** sample — `p` contiguous blocks, one case from each
at an offset from `sha256(fragment, block)`. Every block of the index range is
still represented (the anti-prefix property is unchanged) and the offset varies
per block, so no fixed period can be tracked. Deterministic in `(fragment, n, p)`,
which `--verify` and `--check` both assume.

### 2.2 …and it bought this table exactly nothing, which is also the finding

A/B at a fixed budget (`work/w-classes/sampler_ab.py`, both samplers, 24 cases,
432 cells each, `--verify` green on both):

```text
  88-store-run-call      strided  O1,O2,Od,Ox      stratified  O1,O2,Od,Ox
  89-store-run-live-arg  strided  O1,O2,Od,Ox      stratified  O1,O2,Od,Ox
```

**The degenerate sample and the good one give the same partition**, at 24 and
again at 64. The aliasing is real, its demonstration is exact, and its effect on
this table is **zero**. Recorded that way (board #1238) rather than as a
correction it was not: a repair that is sold as having fixed an output nobody
measured is the next lane's false confidence.

### 2.3 The instrument's own control ran and was green

`--verify` re-captures every 7th cell and requires both hashes to reproduce; it
is the control that can go red if any run-varying byte leaked into a hash, which
would make every profile look distinct and read as a maximally conservative
result while being pure noise.

```text
  main measurement  69,066 cells   9,867 re-captured   0 disagreed
  cross-validation  43,776 cells   6,254 re-captured   0 disagreed
```

29 sampled cases the reference rejects at **all 18** profiles were named and
excluded; **0** cases were rejected at some profiles and not others (which the
script treats as fatal, and which would have invalidated every partition below).

## 3. The regeneration hazard, discharged row by row

Re-deriving 60 peers' lane sets is 60 chances to narrow someone else's coverage
with no textual conflict and no failing test. The incumbent table is the control
(`work/w-classes/table_diff.py`):

```text
  NARROWED   0
  SAME      56      every digest byte-identical — no generator moved
  NEW        4      12-alloc-depth, 77-reinterpret-2c, 88, 89
  WIDENED    2      51-dtor-member 8 -> 14, 60-ctor-epilogue 4 -> 7
  GONE       0
```

**Not one row narrows.** The four NEW rows are the only exclusions this lane
takes, and §4 and §5 are their evidence.

### 3.1 The two widenings are a hole this closed, and it belongs to the budget

A widening is free in coverage terms, so the interesting question is which change
bought it. `sampler_ab.py` at a fixed 24 cases per fragment:

```text
  51-dtor-member     strided  8 lanes    stratified  8 lanes   (incumbent: 8)
  60-ctor-epilogue   strided  4 lanes    stratified  4 lanes   (incumbent: 4)
```

Both samplers reproduce the incumbent row. Only the larger budget (64) finds the
split. So the cause is the **budget**, and the consequence is that
`scripts/mode_classes.txt` on master was **excluding six lanes on
`51-dtor-member` and three on `60-ctor-epilogue` that do separate** — nine
lane-exclusions that were wrong, on fragments nothing else grades at those
profiles. That is board **#1239**, and it is the strongest argument in this rung
for regenerating at a budget larger than the one being replaced rather than
matching it.

The independent cross-validation (§5) corroborates the direction: at p=40 it
reports `60-ctor-epilogue` as a fragment *the table over-grades*, which costs
time and never coverage.

## 7. What the per-fragment split found that nobody was looking for

Splitting the cross by fragment made the cross and the sweep comparable on the
same corpus at the same profile for the first time, and they disagree by **7**.

```text
  expr_sweep.sh   19,556 checked   19,460 graded   96 UNGRADED   (at /Ox /GS- /c)
  mode-cross      lane Ox          89 capture-fail
```

Every one of the 7 is in `93-virtual-byval`, and the cross grades all of them —
**8 lanes each, 56 cells, `vocab-gap`, a real verdict.** `expr_sweep.sh`'s
carried baseline says all 96 are one thing:

> *96 generated cases do not compile: `cl.exe` rejects them, so no reference obj
> exists and the differential never runs.*

**That is wrong for 7 of the 96, and the true cause is more interesting than the
label.** Their verdict is not a capture failure but

```text
  ReferenceError: replay failed: replay produced no (or an empty) obj
```

and the reason, from `c2rs replay` on `93-virtual-byval-0001.cpp`:

```text
  ...(5) : error C4716: 'f' : must return a value
  [c2host] returned 1
```

`C4716` is a **warning** under the full `cl.exe` driver — which is why cl emits an
obj and the cross grades the case at all 8 lanes — and an **error** under the
standalone-c2 replay host. Adding the `return` makes the same TU replay
byte-exact (`ref=846B replay=846B raw_identical=true`).

So 7 cells of the P0.1 replay seam's own boundary (board #282's distinction: only
`diff` asserts the replay is byte-exact, `gap` does not) are parked inside a
number whose published reason says *the generator wrote bad C++*. That is board
**#1242** — filed, not fixed: the repair moves `expr_sweep.sh`'s carried baseline,
which is a number every lane quotes, and it belongs to whoever owns that file.

## 9. What this rung deliberately did NOT do

1. **Did not narrow a single peer row to buy cost.** 56 rows are byte-identical
   and 2 widened. Every cell this rung gives back comes from the four fragments
   that had **no** row, which cost 18 lanes each by the table's own fail-safe.
2. **Did not fix `88`'s 18 duplicate sources** (#1191). Deduping moves `88`'s case
   count, which is the baseline `w-gen` and `w-seam2` both published, and the
   honest repair is a loader-level distinctness assertion in `sweep_gen.py` —
   a different lane's file. The duplicates are inside the strata and do not bias
   the stratified sample: 24 of 24 sampled cases are distinct sources.
3. **Did not wire per-fragment accounting into the gate** (#1241, §6).
4. **Did not repair `expr_sweep.sh`'s ungraded baseline** (#1242, §7).
5. **Did not claim the sampler repair changed this table.** It did not (§2.2).
6. **Did not touch `crates/`.** No verdict moves, no census moves, and the two
   numbers a class table can break — `mismatch` and *cases graded* — are
   unchanged at 0 and 19,467.
