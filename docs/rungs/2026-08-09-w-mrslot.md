## 2. WHAT #584's LEADING RUN IS FOR A MULTI-SYMBOL RUN

The two readings of `u`:

* **COUNT** — `#{stores whose value materialises nothing}`, capped at 2. This is
  `order::head_slots`, it was `ScheduledRun::nsw`, and it is what `save_slot` was
  fed.
* **LEADING RUN (#584)** — walk the **FINAL store order** from its front and
  count stores whose value materialises nothing, **stopping at the first store
  that consumes a producer**, capped at `HEAD_SLOTS_MAX = 2`. This is
  `order::lead_slots`.

**On a single-symbol run they are equal.** `store_order` forbids a store whose
producer has rank `j` from occupying a position below `u + j`, so with one symbol
the unproduced stores are pinned into the head and the leading run reaches the
capped count. `order::tests::the_two_readings_of_u_agree_on_every_single_symbol_run`
enumerates 5,460 of them.

**On a MULTI-SYMBOL run the leading run is the smaller one.** The store order is
additionally pinned by symbol grouping, and that pin can place a **produced**
store ahead of an **unproduced** one. The leading run stops there; the count
keeps counting the stranded store.

    u_lead  =  |leading run of unproduced stores in the FINAL order|  <=  min(count, 2)

with strict inequality exactly when a produced store precedes an unproduced one.
**A reference bind is a second base symbol** (board #1128), which is why board
#1199's carrier is what opened the region: before it, the only multi-symbol
admission was the all-one-literal run, where the count is 0 and both readings
agree trivially.

### 2.1 GRID R, and the two template defects that were fixed before scoring

`work/w-mrslot/gridr.py`. **145 cells, one directory each (#1045), sha256'd
before the first `cl.exe`.** The axis is the one `w-carrier` §5.2 names as what
its own GRID K held constant — **which kind of store LEADS the run** — crossed
with the symbol pattern, exhaustively over two and three stores:

```text
  A  two stores    {TT,TR,RT,RR} x {LL,LF,FL,FF}                       16
  B  three stores  {T,R}^3 x {L,F}^3                                   64
  C  callee arity 1 (a one-argument callee, #1189)                      8
  D  live-argument stores (must stay refused, #1169)                    3
  E  the bind hanging off a LIVE formal (#1215's deleted clause)         2
  F  leaf controls — the identical run with NO call                    52
                                                                      ---
                                                                      145
```

`T` = based on `this`, `R` = based on the bind; `L` = the one literal the bind
production admits, `F` = a formal already live in a register.

**The generator asserts its own classes** and writes nothing if one is absent, if
fewer than 12 cells can structurally separate the rivals, or if a separating cell
has no leaf control. It deliberately predicts **no store order**: `u_lead` is
defined over the FINAL order, which is c2's answer, so the class that decides the
rung is asserted by the **scorer** on the OBSERVED population instead.

**Two template defects were found by smoke-testing the instruments and the freeze
was amended in the open** — `6883ea19` → `34d48f65`, with no cell scored at
either point, and the first freeze left standing in history:

1. The template emitted `BE& r = mBlk;` unconditionally, so the 24 `T`-only cells
   carried a **dead bind**. `c1xx` renders it as an op the reader refuses at
   `expr-op-0x27` — one layer *above* this rung — so the single-symbol control
   class would have been **silently empty while the class assertion passed**,
   because the generator counts cells and not verdicts. Amended, those cells
   grade `Port=Match` at the base binary, which is what makes them controls for
   *"the swap is inert on a single-symbol run"*. **Board #1263.**
2. `BE& r = *w;` is not a bind the reader recognises (`assign-store-type-8643`).
   `H* w` plus `BE& r = w->mBlk;` reaches the clause under test.

The three `lv_*` live-argument cells are reported with the key they actually
produce — **`expr-op-0x27`**, again one layer above. A store of the formal the
call passes does not reach this production through this template, so they are
refusal controls and **not** witnesses for `LIVE_ARG_STORED`; that gate's
witnesses remain `w-seam2`'s `grid3/`.

### 5.1 And the bottom rung is misidentified in the record

Board #1218 names `codegen/leaf/store.rs:274`'s `value_bound` refusal as what
sits below everything. It does not, and cannot:

* `value_bound` is set only when an `IlOp::BoundAddr` stands in a store's **VALUE**
  position;
* the **only** producer of `BoundAddr` anywhere in `crates/c2-il` is
  `bind_run_ops`' discharge loop, which rewrites the **BASE** position and
  nothing else (`leaf_store.rs`, one `out.push(IlOp::BoundAddr { .. })`);
* so no reader can hand the emitter a bound VALUE, and `value_bound` is a
  backstop with no reachable input.

What actually stops `xboxheap` one step earlier is `parse_simple_gpr_run`
declining `Load(<bound local>)` in the value position, because the local is not a
formal and `reg_of` answers `None`. That is the message rung B prints.

**`crates/c2-core/src/codegen/alloc.rs`'s module doc carries #1218's wording and
is deliberately NOT edited.** It is `w-prod`'s file this week, eleven lanes have
erased each other through shared semantics with no textual conflict, and a doc
correction is not worth that risk — the correction is here and on the board
instead.

### 10.1 `alloc::Root::offsets` is `None` at this seam, and this rung does NOT fill it

`w-prod` registered that `IlOp::BoundAddr` is this lane's path and left
`Root::offsets` arriving as `None`, naming it as ours to fill if the rung needed
it. **It does not, and the reason is board #1235**: `offsets` is board #908's
*allocation* input, and the `mr` slot is a *schedule* fact — `save_slot(nprod,
u_lead)` reads only `order::schedule` and `order::leading_unproduced` over
`schedule::Stmt { producer, base }`, neither of which can see an offset chain.
`IlOp::BoundAddr` is unchanged by this lane in shape as well as in spelling, so
the named gap is exactly as wide after this rung as before it.

### 10.2 `w-prod`'s `P6`/`P7` result does not touch this rung's argument

`w-prod` measured that cells `P6` (TWOBIND) and `P7` (CHAINBIND) **decode
identically** — same lvalue token, same value token, same bind bits — and c2 still
assigns different registers, so *"these two decode the same, therefore they emit
the same"* is not a valid step. **No step of this rung is of that form.** Every
GRID R cell is graded individually by `c2rs gap` against real `c2.dll`, and every
number in §3 is parsed out of that cell's own disassembly; no cell's verdict is
carried to another by a decode-equality argument. The one place this lane does
generalise is the *rule* `nprod - 1 + min(u_lead, 2)`, and its warrant is 93
independently graded cells rather than an equivalence between any two of them.
