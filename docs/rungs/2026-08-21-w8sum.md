## 0. What this lane is, in one paragraph

`docs/ARCHITECTURE_PROPOSAL_2026-08-20.md` §5 step 2: retire board **#844** — the
defect that `IlFunction` carried **34 mutually-exclusive `Option<Shape>` fields**
and `select_function` dispatched over them with an **ordered `if func.X.is_some()`
chain**, so a body that set two fields was half-emitted (a store run without its
`bl`, or a `bl` without its run: both complete, plausible, wrong bodies — board
**#232**, the 255-commit cost of exactly that shape reading `mismatch 0`).
Replace the 34 Options with a single `IlFunction.body: BodyShape` enum; rewrite
`select_function` as a **total `match &func.body`**. It is a **construct rung**:
it converts nothing, admits nothing, and is graded by a **required-zero byte
delta** — the identity diff of per-lane gate counts before and after.

## 1. What shipped

**The enum.** `crates/c2-il/src/func/mod.rs` gains
`pub enum BodyShape` with **35 variants** (`Plain`, `Tail`, `FpTail`,
`FpMultiTail`, `MultiTail`, `Framed`, `Seq`, `CondPair`, `Compare`, `CmpShiftOr`,
`PtrWalkLoop`, `IfCallJoin`, `PtrWalkChainLoop`, `DivModLeaf`, `FloatLeaf`,
`StaticScanLoop`, `GlobalStoreLeaf`, `CountedAccumLoop`, `FloatWalkLoop`,
`FpStoreDiamond`, `CtorForwardCall`, `GuardChainSharedTail`, `AllocInitOrFail`,
`OsfHandleGuard`, `XlrcCreateGuard`, `JsonUtf8Copy`, `PoolFreeList`,
`PoolCtorChain`, `GuardRetChain`, `CloseCallChain`, `MemcpyTail`, `NonceAddRun`,
`XteaRoundLoop`, `XteaEncryptLoop`, `EmptyBody`). Each variant is one retired
`Option<Shape>` field; each carries exactly the payload the old field carried
(`Tail(String)`, `FpTail{callee,fp}`, `CondPair(CondPair)`, …), and `Plain` /
`EmptyBody` are the two payload-free arms. The struct field is a single
`pub body: BodyShape`; the co-fields the old shapes never contended
(`mangled_name`, `source_path`, `params`, `ops`, `data_syms`, `fn_addr_sym`,
`data_def`, `eh_*`, `inlinable`) are untouched.

**The projection accessors.** Every downstream reader that said `func.tail_call`
now calls `func.tail_call()` — ~34 methods named for the old fields, each
returning `Option<&T>` (three specials: `float_leaf() -> Option<bool>`,
`empty_body() -> bool`, `tail_call() -> Option<&str>`). This keeps the
read-site diff mechanical while the storage is a sum type: the accessor is the
one place that pattern-matches, and it is a projection, never a second copy of
the dispatch.

**The dispatch.** `crates/c2-core/src/codegen/select.rs::select_function` is a
**total `match &func.body`** — **35 arms, one per variant, exhaustive** — with
the `store_run_call::gate_carrier(func)?` backstop still ahead of it. The
ordered `if …is_some()` chain is deleted. `cfg_class.rs::lowering_of` (the
downstream grading helper that mirrors the same precedence) is converted the
same way.

**Net −438 lines across 35 files** (896 insertions, 1,334 deletions): the enum
and its accessors are additive, and they retire more field-plumbing than they
add.

## 2. The precedence answer — did any site rely on the old `if`-order?

**Yes, exactly one, and it is preserved as arm-internal order — not as the order
of the arms.** The old chain's ordering was load-bearing in exactly one place
and incidental everywhere else, and the sum type makes that distinction
mechanical:

- **The 34 shape fields were mutually exclusive by construction** — the parser
  sets exactly one per production. The old chain's `is_some` order over them
  could only *assert* "exactly one is `Some`" by convention; a body that set two
  fell through to whichever came first. **The enum makes that a type**: a value
  is exactly one variant, so the order in which the arms are written is now
  readability, and the `match` being exhaustive means a 36th shape cannot be
  silently unhandled the way a 35th `is_some` branch could be forgotten.

- **The one surviving precedence is *inside* the `Plain` arm.** Only `Plain`
  runs the ordered leaf recognizers — `indirect_load_text` → `addr_leaf_text` →
  `store_leaf_text` → `select_text` — and they stay ordered because **all four
  read the same `func.ops` stream**, so which one claims a given stream is a
  real priority. That order is transcribed verbatim into the `Plain` arm.

- **`Compare` / `CmpShiftOr` / `FloatLeaf` / `EmptyBody` were tail checks of the
  old chain and are now their own arms** — precedence-safe because each carries
  an **empty or disjoint `ops` stream**: the three `Plain` leaf matchers returned
  `None` for them in the old chain (which is *why* the old chain only reached
  their `is_some` checks after the matchers declined), so promoting them to
  peer arms cannot change which recognizer claims a body. `FloatLeaf`'s op
  vocabulary (`Load`/`Lit`/`FpLit` + `+ - * /`) is disjoint from the
  indirect-load and address leaves' by inspection.

- **The tail-call family** (`Tail`/`FpTail`/`FpMultiTail`/`MultiTail`), which the
  old code reached through one `func.tail_call` block that then re-inspected the
  register file and argument count, is split into four arms. The void-vs-int
  split inside `Tail` is preserved exactly where it lived — `func.ops.is_empty()`
  distinguishes a void tail call (empty setup) from an integer one (setup =
  `int_tail_call_text` minus its trailing branch word).

So: one construction site setting >1 field would have been a latent
half-emit under the old chain; the sum type makes it unspellable, and the only
ordering that survives is the four-matcher leaf order inside `Plain`, transcribed
unchanged.

## 3. Grading criterion

**Primary — REQUIRED-ZERO BYTE DELTA.** A line-for-line identity diff of per-lane
gate counts, base vs tip. A construct rung that changed any emitted byte
**FAILED**, whatever else it did.

**How this rung differs from `ir0` (#3336), and why its grading instrument is
ARMED.** `ir0` shipped a tree with **no production caller** (its switch was
reverted), so its byte delta held *by construction* and the identity diff was a
tautology — the construct-rung definition grades machinery *"by re-expressing
already-byte-exact classes through it"*, and `ir0` reverted the re-expression.
**This lane does not.** `select_function` is the **live production dispatcher**
and `cfg_class::lowering_of` is a live grading helper; both are re-expressed
through the sum type on the path the port actually runs. So the byte delta here
is a real re-expression check, not a tautology on an additive tree — the whole
byte-exact class is routed through the new type, which is exactly what the
construct-rung definition asks.

**1,761 passed / 0 failed / 1 ignored / 51 targets / 1,762 named results**,

toolchain skip could not have produced a green suite here.

The change is `#[cfg(test)]`-heavy on the write side: every test that built an
`IlFunction` by setting a field now sets `body:` in the struct literal or writes
`f.body = c2_il::BodyShape::Variant(v)`. Those write-site edits are what most of
the −438 lines are, and the suite exercising them at 1,761 green is the evidence
the projection accessors round-trip the old field semantics.

## 6. Decline conditions — none fired

The brief's implicit decline was **"if the collapse moves any obj, report the
specific body/shape that re-bound and STOP — do not force green."** It did not
move one. Had a construction site relied on the old chain's order to pick between
two set fields, the total match would have surfaced it as a compile error (two
variants cannot both be constructed) or a moved count (an arm claiming a body the
chain gave to a later branch); neither occurred, and §2 is why: the fields were
already mutually exclusive and the one live precedence is inside `Plain`.
