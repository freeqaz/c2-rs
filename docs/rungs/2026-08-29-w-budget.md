## 1. What it admits, and what it refuses

`w-instrcount` (wave 20) resolved `no-instr-count`: the quantity c2's inline
decision tests is the `.gl` function record's **`SIZE`** field, `WORD
[[fn]+0x50]` — one indirection, because `0x10b626f5` loads the *symbol* first —
whose **sole writer in the image is `0x10b9bf6c`**, the `.gl` reader, and which
c2 never recomputes. **The port already decoded that field and threw the value
away** to reach the `ATTR` byte beside it. That was C24's own note and
`P_INLINE` §6.2 item 3's *"the sharpest row on the page"*.

This rung threads it.

| what | where | c2 |
|---|---|---|
| the field's **value**, from the walk that already read `ATTR` | `c2_il::func::gl_function_instr_counts` | `0x10b9bf6c` writes it, `0x10b626f7` loads it |
| the count per census row | `FnCensus::gl_instr_count`, keyed on `emit_name` as `inlinable` is | — |
| the count per bundle, name-keyed | `TuContext::with_instr_counts` / `instr_count` | — |
| **C2** — the running growth total, seeded | `Expansion::growth_total` + `at_pass_entry_seeded` | `mov ds:0x10c3f5cc,eax`, `0x10b62703` |
| **C3** — `B`, on a production path for the first time | `BudgetModel::seed`, called from the same constructor | `add eax,eax`, `0x10b62708` |
| **C16** — decline a caller whose total is over 35,000 | `declines_at_growth_total` + `INLINE_GROWTH_TOTAL_MAX` | `cmp ds:0x10c3f5cc,0x88b8` / `jg`, `0x10b60a63` |
| **C17** — decline an unaffordable callee | `declines_unaffordable` | `cmp [ebp+0x10],eax` / `jge`, `0x10b60a73`, then `cmp eax,0x28` / `ja` |
| **C19** — the charge, on the walk's own state | `BudgetModel::enter_site` | `sub [edi],eax` `0x10b625bb`; `add ds:0x10c3f5cc,eax` `0x10b625c1` |

**What changed in the decision, and it is the one sentence this rung is for:**

> `S6-budget-divided` was a **blanket refusal** at every `n ≥ 2`, because `B`
> was unknowable. It is now a **computed verdict** wherever the caller's count
> is readable, and it refuses only where the count genuinely is not — a `.gl`
> the reader refused whole-file, the `0x81..=0xff` encoding, a name with no
> record, or two records disagreeing.

**What it still refuses, by name:** `S6-budget-divided` (no count),
`S6-budget-depth-cap` (C14), `S6-budget-maxlevel` (C15),
`S6-budget-caller-huge` (C16, new), `S6-budget-unaffordable` (C17, new),
`S6-budget-no-sites` and `S6-budget-site-index` (malformed).

**`None` is UNASKED everywhere and that is the byte-neutrality argument's
skeleton, not a courtesy.** Every field this rung adds is three-valued in
`IlFunction::inlinable`'s sense, and with no count in hand the model's state is
*identical to the pre-lane state* — which is why the 985 domain rows rendered
without a count did not move by one character (§3).

## 2. The `ushort` hazard is c2's behaviour and it is modelled, not fixed

`WB_INSTRCOUNT_FINDINGS` §4: the `.gl` `SIZE` byte has three forms, and the
third — `0x81..=0xff` — is **one signed byte** in c2, delivering
**65,409..65,535** to the consumer's `movzx`. A caller in that state seeds
`DAT_10c3f5cc` above 35,000, so **C16 declines the caller's very first site and
it inlines nothing at all**.

Two separate statements, kept separate:

* **The model reproduces it.** `a_caller_over_the_growth_cap_declines_its_first_site`
  asserts the decline at `65,409` and `65,535`, and the whole band is enumerated
  in the decision surface.
* **The port cannot be handed one.** `gl_function_records` refuses that encoding
  **whole-file**, exactly as `gl_function_attrs` always has. The refusal was
  there for a desync-canary reason; it now also stops a number that means
  *"decline everything"* from arriving looking like a size. Zero witnesses in
  28,838 workload records.

Not a bug to fix, and the rung says so rather than quietly widening the reader.

## 4. RDC-1 — the registered refusal-domain check, and why a byte delta does not discharge it

* in the domain, as the `seeded caller=065409` / `caller=065535` rows, which

* in the port's own walk, as `the_walk_seeds_from_the_callers_own_count` — the
  same two functions, the same `TuContext`, **one number different**, splicing
  in one case and refusing `S6-budget-caller-huge` in the other. That test is
  what shows the parameter reaching the *decision* and not only the renderer,
  which was the prereg's registered falsifier for the whole lane.

## 5. C17 — registered as conditional, and decided by measurement

C17 puts a **new refusal on a production path**, and a refusal that fires
changes an emit. The prereg registered it as adopted **only if measured not to
fire**, with the negative result published if it did.

`WB_INSTRCOUNT_FINDINGS` §5.2's first-site theorem is why this was not a coin
flip: `B ≥ 1000` for every caller including one of size zero, so at an undrained
budget C17 cannot decline any callee counting below 1,000, and the caller's own
size only scales `B` **upward**. The port's walk drains one link at a time down a
chain, so the arm can only bind on a chain deep enough or a link fat enough to
spend 1,000 count units — and `S2` pins every link to one call site.

**Measured: see §7's gate block.** The arm is asserted reachable in both
directions by `the_affordability_arm_obeys_the_first_site_theorem`, so it is a
live boundary in the domain and not a dead branch.

## 6. `#3847` — the multiply-blocked audit, and it changes what the column means

Full working in `work/w-budget/BLOCKER_AUDIT.md`. The headline:

> **10 of the 12 `absent` rows carry a second blocker.** The published
> `no-instr-count 4 / no-instr-stream 2 / emit-change 5 / writer-unread 1`
> partition is therefore not a partition of the work — it is a partition of
> *the first reason somebody wrote down*.

The sharpest single result, because it inverts a published readiness claim:
**C10 and C12 are marked `R1` = "read and derivable today", and they are not.**
Both test `[sym+0x4c]` bits **above the low byte** (`0x2000` = bit 13,
`0x80000` = bit 19, `0x200` = bit 9), and the port's `.gl` `ATTR` reader takes
the low byte only and says so in its own words. The input is unreadable, which
is a prior and different obstacle to `emit-change`'s *"derivable, but it costs
an emit"*.

`CLAUSES.tsv` gains a **`blocker2`** column with an audited cell on every row,
and one `blocker` cell moved — C4's, from `no-instr-count` (which this lane
closes) to `no-driver`, with `no-instr-stream` beside it.

### 6.1 The audit's own ordering was an artifact on 2 of 5 rows, and a peer lane caught it before it shipped

The audit also claimed *which* of the two cells binds, and said so for five
rows. Peer lane `w-emitprice` priced the five `emit-change` clauses; the
coordinator relayed its verdicts; **two of my five orderings did not survive
them.** Their evidence is not in this tree and none of it was re-derived here.

* **C7.** I said `value-refuted` binds over `emit-change`, arguing that a lane
  willing to pay the emit price *"still has nothing to write down."* That lane
  wrote `128` down and measured it: **3 wrong emits at `/O1` raw against a
  standing-refusal cost of 0 byte-exact functions.** So the price is negative
  **because** the value is refuted — one finding, not two ordered ones. The
  ordering is withdrawn; the cell stays, as the mechanism.
* **C9.** I said `depends-on-C8` binds over `emit-change`. They measured that
  **there is no emit change**: `0x10b8238d` computes the favour-speed bit from
  the option word, the port already holds it (`OPT_WORD_O1 = 0x00200005`, bit
  23 clear; `OPT_WORD_OX = 0x00a00005`, set), so at `/O1` c2's size test runs
  and an adoption is byte-neutral by construction — C15's argument one clause
  over. **`C9.blocker` is re-pointed to `none`** on their evidence, attributed
  in the row's note. **The clause was NOT adopted** — out of this lane's
  commission, and the coordinator said so — but leaving a blocker cell a peer
  lane measured false would publish something known-wrong in the file `#3814`
  made the single source.
* **C10, C11, C12.** Independent agreement, reached from opposite sides. I read
  the **container** — `gl.rs`'s own docstring saying nothing decodes the `ATTR`
  continuation — and they read the **image**, concluding the three rows want one
  absent thing: a `.gl` **symbol-record decoder**, where the port has a
  fixed-pattern walk reaching one byte. `attr-hi-unread` and `no-field-mapping`
  are its two faces, and `#3853` widens from two rows to three. Two facts of
  theirs this lane did not have: C11 and C12 are **one predicate** (six
  interleaved tests, one sink), and C13 converted while C12 did not because of
  **field width**, not difficulty.

**The corrected count is 3 binding-second — C1, C10, C12 — not 5.** *"10 of 12
carry a second blocker"* does not move, because every one of those five rows
still carries two cells. And this is `#3505`'s pattern firing on my own
instrument: **`binding` is an ordering, and 2 of 5 of mine were artifacts of
having one lane's evidence.** The coordinator's message asked me to check for
exactly this and it was there. **The table therefore publishes a partition and
asserts no cross-row ranking** — which is what `w-emitprice` did when four of
its five rows priced identically at zero.

Their mechanism lands inside this rung's own seam and is carried forward rather
than merely cited: **the consequence of a size-rule error flips between the
port's two seams.** At `splice.rs`'s S7 — an **accept** — a false inline is a
wrong emit; at `comdat::fenced_inlined_callee` — a **refusal** — a false keep
is. `INLINE_DECLINE_BYTES` is already 128 and shows the same 3 error cells,
harmless at the fence and 3 wrong emits at the accept seam. Same constant, same
cells, opposite verdict. **Anyone widening S7 on a size rule owes that
distinction**, and this rung did not widen S7.

**No other `blocker` cell was touched** beyond C4's and C9's; a blocker cell is
a verdict, and C9's moved on a peer lane's measurement with the attribution in
the cell.

### 7.1 The one thing this evidence does NOT establish, said plainly

**The corpus does not exercise mechanism I at all**, and both required-zero
instruments are therefore silent about the thing this rung changed.
`fnbyte-spliced` is **absent from all 566 `gap-metric` keys at both ends** — the
splice composed **zero** bodies over 878 TUs — while `fnbyte-elided` reads
1,862 and `fnbyte-census-disagree-inlined-callee` reads 948. So:

* the byte delta is real, and it is **necessary and known not to be
  sufficient** — `#3723`'s sentence, arriving here in its strongest form:
  the gate can only see emissions the corpus exercises, and this corpus
  exercises none of them;
* which makes **the decision surface the grading instrument for this rung**,
  not a supplement to one, and RDC-1 (§4) the thing that actually shows the
  parameter reaching the decision;
* and it says **nothing** about whether the count is right — a metric delta of
  zero is not evidence of correctness (`w-sizebracket`, `#3270`–`#3275`).

Two facts about that zero, both measured here and neither this lane's to chase:
it is **pre-existing** (the base arm has no `fnbyte-spliced` key either, so this
rung did not silence anything), and the 948 `inlined-callee` disagreements are
the same order as `splice.rs`'s own *"150 of 945 spliced functions"* note —
which reads as the splice's population having moved behind
`comdat::fenced_inlined_callee` since that note was written. **Naming it is not
pricing it**, and the module doc is left as written rather than edited on an
inference.
