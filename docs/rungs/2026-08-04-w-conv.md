## 3. Deliverable 2 — the mechanism the frontier shares

Ranking by **construct** instead of by TU, over the same 17 objs:

| missing mechanism | FRONTIER TUs |
|---|---:|
| **a real label→offset map** (≥ 2 transfers, ≥ 1 shared target) | **14** |
| **the intra-section unconditional `b`** (board #191) | **10** |
| a branch on **cr0** (record-form or call-result compare) | 10 |
| callee-saved GPR formals / `savegprlr` | 9 |
| a REFHI/REFLO data-symbol pair | 6 |
| `cmplw` / `cmpw` register-register | 5 |
| a CTR loop | 4 |

The top two are one rung and the port had emitted **neither**. Board #191 has
been open since w-cfg, and W10 closed the only route to it that had been tried —
the `else` arm — because *"the only source shape that produces an intra-section
`b` also produces `/Ox`'s duplication"*, on a threshold bracketed by one cell
either side and declined as a c2 cost model.

**There is a second route.** A guarded **early return** in a framed call
sequence, whose `b` targets the **epilogue** rather than a join block:

```cpp
int f(int a, int b) { if (a != 0) return 5; if (b != 0) return 11; v0(); return 0; }
```

```text
  /O1  (what the dc3 workload compiles)     /Ox and /O2
    mflr/stw/stwu   Class A frame             mflr/stw/stwu
    cmpwi cr6,r3,0                            cmpwi cr6,r3,0
    bt    26,+12                              bt    26,+24
    li    r3,5                                li    r3,5
    b     +28       <- 48000...               addi/lwz/mtlr/blr   <- epilogue COPIED
    cmpwi cr6,r4,0                            cmpwi cr6,r4,0
    bt    26,+12                              bt    26,+24
    li    r3,11                               li    r3,11
    b     +12       <- and it names the       addi/lwz/mtlr/blr   <- and again
    bl    ?v0          SAME target            bl    ?v0
    li    r3,0                                li    r3,0
    addi/lwz/mtlr/blr                         addi/lwz/mtlr/blr
```

Two `b`s naming one target whose offset is not known until the whole body is laid
out. That is the label map, and neither W8 nor W10 needed one — both say so in
their own file, and both were right that the first shape needing it would be a
different rung.

### 3.1 The mode split is X-b's, and here it has nothing to fit

`/Ox` and `/O2` **tail-duplicate the epilogue into every early-return arm**;
`/O1` shares it behind one `b`. That is board row **X-b**, and it **refutes**
`docs/OPT_MODE.md` and `c2_core::codegen::OptMode`'s own doc comment, which said
the modes *"differ in exactly one rule … never a different opcode, never a
different operand order — only a register field."* This rung corrects that doc
comment in place: the register-field rule holds **inside a straight-line chain**
and is refuted as a general claim.

**But this is not W10's declined cost model, and the difference is the whole
argument for building it.** W10's quantity was *how many bytes a join is worth
duplicating*, and it varied with join length — one call duplicated, two did not.
The block duplicated here is the **epilogue**, whose length is a constant of the
frame class, and `/Ox` copies it in **every** measured cell:

| axis | values measured, at `/O1`, `/O2` and `/Ox` |
|---|---|
| guard count | 1, 2, 3 |
| result kind | `int`, `void` |
| trailing-call count | 1, 2, 3, 4 |
| scrutinee position | formals 0, 1, 2, 3 |
| relation / signedness | `!=`, `<`, `>`, `>=`, `==`; `int`, `unsigned`, pointer |
| exit literal | 0, 5, 11, 22, −1, 4660, 32767 |

Two layouts, one per mode, **≥ 8 witnesses each**, and no quantity in between.
`work/w-conv/p/probe1.cpp`, `probe2.cpp`, `probe3.cpp`.

### 3.2 The void arm is a different branch SENSE, and it is the empty-arm inversion

`void w1(int a){ if (a != 0) return; v0(); v1(); }` has an **empty** arm. c2
deletes the block and points the branch straight at the epilogue with the
relation *itself* where the value form emits its negation:

```text
  int  g1:  cmpwi cr6,r3,0 ; bt 26,+12 ; li r3,5 ; b -> EPI     (negated)
  void w1:  cmpwi cr6,r3,0 ; bf 26,+12 -> EPI                   (NOT negated)
```

That is `work/w-cross/PREREG.md` §1's **empty-arm inversion** — found in
`src/system/negate_test.cpp`, where it is one of nine refusals — reproduced in
the smallest body that has it, and it composes (`w2`, two void guards, two `bf`,
both to the epilogue).

**And the void rows are byte-identical at `/O1` and `/Ox`**, which makes them the
control on §3.1's mode split rather than a second cell of it: with no arm there
is nothing to duplicate, so the two modes cannot differ, and they do not.

### 3.3 A frontier function's whole block layout, graded

`?mmioGetInfo` in `src/xdk/nuispeech/mmio.cpp` — a FRONTIER TU — **is this rung's
`g2` plus a two-word entry-block park and two words of call setup**:

```text
  reference, at the workload's flags           the port's `mm`, byte-exact
    mflr/stw/stwu                                mflr/stw/stwu
    mr    r11,r3     <- the park                 —
    mr    r3,r4      <-                          —
    cmplwi cr6,r11,0 ; bf 26,+12                 cmplwi cr6,r3,0 ; bf 26,+12
    li r3,5  ; b +36                             li r3,5  ; b +28
    cmplwi cr6,r3,0  ; bf 26,+12                 cmplwi cr6,r4,0 ; bf 26,+12
    li r3,11 ; b +20                             li r3,11 ; b +12
    li r5,72 ; mr r4,r11 ; bl memcpy             bl ?v0
    li r3,0                                      li r3,0
    epilogue                                     epilogue
```

Same guard count, same relation, same operand class, the same three exit literals
`5`/`11`/`0`, the same block skeleton, the same two branch kinds — and the two
`b` displacements differ by exactly the **8 bytes** of `memcpy` setup that sits
between the last branch and the epilogue. `mm` is in the positive fixture and
grades at all 12 lanes, so *"this rung emits a real frontier function's entire
block layout"* is a byte compare and not an argument.

What is left of `?mmioGetInfo` is W10's declined entry-block park (three cells,
no test) and an inlined `memcpy`; §2 prices the whole TU at 7.

## 8. What was deliberately not done

* **No cost model** — neither #187's fold bands nor X-b's duplication threshold.
  The two layouts here are measured per mode, not fitted to a size.
* **No entry-block park, no callee-saved allocation, no r10 descent.** W10 refused
  them with three cells and nothing has been added since — and §3.3 shows exactly
  what that costs: one frontier function is two words away.
* **No `coff/` edit.** The label lead was measured before the code was written
  (C4) and the counter is untouched. This lane owned `codegen/` for its duration
  and did not need `coff/`.
* **No `else` arm.** Still W10's refusal, still for W10's reason.
* **No attempt on any frontier TU.** All 17 read, all 17 priced, all 17 declined
  by name in `work/w-conv/PREREG.md` §1.
* **No `BOARD.md` / `STATUS.md` / `ROADMAP.md` / `gate.sh` / `scripts/` edit.**
  `scripts/` belongs to lane w-modes for the duration. Rows proposed in §10.

Ranked by frontier TUs, per `CFG_SHAPE.md` §5.0 Trap 2.

   `CODEGEN_W6_COMPARE.md` §6 still calls the allocator *"demonstrably richer

   two-instruction instance of it.
2. **A branch on `cr0` — 10 frontier TUs, and it has two producers.** A
   record-form instruction (`mr.`, `clrlwi.`, `addic.`) and a compare of a call's
   result in r3 (board **X-e**, three counterexamples to `CFG_SHAPE.md` §3.2).
   Any rung that reads a call result before branching needs it, and an emitter
   that hard-codes cr6 emits `409a…` where the obj has `4082…`.
3. **The `else` arm's duplication threshold** (X-b). Still blocking the *other*
   half of board #191. What would close it is unchanged from W10's §9: a probe
   grid varying the duplicated size at `/O1` and `/Ox` together. **This rung
   narrows the question usefully** — the epilogue is duplicated unconditionally,
   so whatever the threshold is, it is about the *join*, not about duplication in
   general.
4. **`cmplw` / `cmpw` register-register — 5 frontier TUs, no witness.**
   `encode_cmpwi` already refuses a literal outside `i16`; the register form is
   simply absent, and w-frame listed it two rungs ago.
5. **The exit-value merge** (§4). Not worth building on its own, but it is a
   *second* place where c2 merges equal values — board #193's tail-merge is the
   first — and a future rung that touches either should look at both.
