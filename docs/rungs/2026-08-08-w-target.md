## 3. THE COUNTERFACTUAL — a rule graded without moving one emitted byte

`w-drop3` §6 declined this rung and registered why: a rule that names a different
relocation target must fire on **none** of the ~6,176 `tail`/`seq` bodies that
are `exact` **because** c2 did not inline their callee — *"the one
grammar-grounded candidate … is not disjoint from the `fnbyte-exact` bodies"* —
and **it never built that number**. §10.1 added the rule: *"a lane that builds a
number and then acts on it in the same commit has no before."*

So R-CLOSE is applied to a **copy** of the port's relocation plan, and the copy
is graded by the same `compare_relocs` the partition uses. Five outcomes, all
printed:

| outcome | meaning |
|---|---|
| `convert` | was `reloc-differs`; the rule fires and the new target **is** c2's |
| `wrong` | was `reloc-differs`; the rule fires and it is **still** not c2's |
| `regress` | was **`exact`** and the rule fires **at all** — the §1.1 stop |
| `null-exact` / `null-differ` | the rule does not fire |

`regress` deliberately does **not** consult whether the new answer happens to be
right: a rule that moves a credited body is stopped either way.

### 3.1 The two variants, over all 4,664 relocating graded functions

| | `convert` | `wrong` | `null-differ` | `null-exact` | **`regress`** |
|---|---:|---:|---:|---:|---:|
| **R-CLOSE** (one step) | 85 | 244 | 532 | 3,803 | **0** |
| **R-CLOSE\*** (fixpoint) | **158** | 171 | 532 | 3,803 | **0** |

`3,803 + 861 = 4,664` — the population is the whole of
`fnbyte-reloc-graded-relocated`, printed rather than implied (trap 0).

The cross-tab against `w-relo`'s own family axis is exact, and that is what turns
*"the rule converts 158"* into *"the rule converts precisely the reachable
families and nothing else"*:

```text
wtarget-fix-rel|chain1|convert       69      wtarget-fix-rel|same|convert       16
wtarget-fix-rel|chain2|convert       73      wtarget-fix-rel|same|null-exact  3,803
wtarget-fix-rel|unrelated|wrong     171      wtarget-fix-rel|blocked|null-differ 529
```

**Why `regress` is 0, and it is structural rather than lucky.** Every one of the
3,803 credited relocating functions fails the rule's precondition: **2,738** name
a callee no census row binds and **1,065** name one the parser refuses. A callee
whose own emitted body is a *single call* is four bytes, and
`INLINE_PREDICATE.md`'s `s ≤ 64` is the region where the inline decision is
**categorical** — `N_max` unbounded in both linkage classes — rather than 0.9716
with a 2.84 % residual. On this corpus, whenever the port names a local callee
whose emitted body is one call, **c2 inlined it, 158 times out of 158**.

**That argument is exactly what `w04a` breaks.** `noinline` is the one thing that
overrides a categorical region, and it is unreadable (§6).

### 3.2 R-REFUSE — `w-drop3` §6.1's number, built

> *"how many `fnbyte-exact` bodies name a same-bundle callee the port refuses. If
> that number is 0 the rule is free and converts ~1,540 differs to honest
> refusals; if it is positive the rule is forbidden as written."*

**`wtarget-refuse-regress` = 1,065**, against `wtarget-refuse-convert` = **531**.
A refusal that removes 531 wrong claims by removing 1,065 right ones is strictly
worse than the incumbent, and the incumbent is doing nothing. Board **#1042**.

Counted in the same pass and over the same denominator as R-CLOSE, so the two
rules are priced against **one** population — the arithmetic `w-splice` proved
subtraction cannot do.

### 3.3 There is no new reader

*What does the port emit for `g`* has exactly one reader in this file:
`complete_comdat`, which is `PortC2::build`'s own composition and therefore
already carries `w-splice`'s chain closure. `close_target` asks **it**, rather
than walking a second chain. A second walk would drift from the emitter the rule
would have had to change — `docs/GAPS.md` §6's most-recorded failure, and the one
the brief names as this wave's: *"independent invention never produces a conflict
marker."*

## 6. WHY THE RULE CANNOT SIMPLY BE NARROWED — the discriminator is two bytes of `.gl`

A matched pair differing **only** by the attribute, compiled under filenames of
the **same length** (the `.gl` embeds the source path, and an unmatched pair
shows a difference that is the path and not the attribute),
`work/w-target/nicmp2.sh`:

| | pair **V** — `void g(){ext();}` | pair **I** — `int g(int a){return a+1;}` |
|---|---|---|
| `.ex` | **BYTE-IDENTICAL** (2,842 B) | **BYTE-IDENTICAL** (2,862 B) |
| `.sy` · `.in` · `.db` | **BYTE-IDENTICAL** | **BYTE-IDENTICAL** |
| `.gl` | **DIFFERS**, 381 → **383** | **DIFFERS**, 377 → **379** |

`docs/OPT_MODE.md` §2 already records the other half: `__declspec(noinline)`
leaves the per-function optimization word at `00a00005`, exactly like `static`,
`__forceinline` and `extern "C"`. **So no clause over the body IL or the opt word
can separate the two cases**, and the discriminator is an undecoded `.gl` field.
Board **#1039**.

**It is not this lane's to take.** `crates/c2-il/` decode is another lane's
ownership this wave, and the clause needed is **fail-closed**: a function whose
`.gl` record carries the undecoded field must be **refused**, not parsed and
silently treated as inlinable. That is a whole-workload blast radius — every
census and `refused` count moves — and it needs its own before and after.
`w04d` is the shape that is already safe by that mechanism: the parser refuses
the callee outright, so nothing can fire.

### 6.1 A parallel test fabricated evidence, and it reversed the conclusion

The first version of `noinline_boundary.rs` keyed its work directory on the
process id. **`cargo test` runs a target's tests in parallel threads of ONE
process**, so four captures raced through one directory and `?f@@YAXXZ` was
graded against another cell's obj. The failure presented as:

```text
assertion `left == right` failed: `.ex` differs between the two cells.
```

— i.e. *"the attribute IS readable outside `.gl`"*, which would have made #1039
payable inside `crates/c2-core/` and **reversed this lane's decline**. It was
re-measured **serially**, outside the test, on **both** shapes (the table above),
and the fix is a directory per cell.

Recorded as a defect of that file's first version, not as a design — the same
discipline `w-relo` §4.1 applied to its own `blocked`/`unrelated` merge. The
general form is worth keeping: **a parallel test that shares a filesystem path
with its siblings can fabricate evidence, and the fabrication looks exactly like
a finding.** Board **#1045**.

## 10. WHAT THIS LANE DID NOT DO

* **No repair.** `fnbyte-reloc-differs` is 861 at both ends. #1013 stays **OPEN**
  and is now priced: 158 reachable behind #1039, 532 behind #1008's five parse
  productions, 171 unreached by any closure.
* **No emitter change of any kind.** `crates/c2-core/` and `crates/c2-il/` are
  untouched.
* **No `.gl` decode.** The discriminator is located and left (#1039) — another
  lane owns that file this wave, and the clause it needs is a fail-closed refusal
  with a whole-workload blast radius.
* **No relaxation of a control.** §1.1 was written to stop the lane if it fired.
  It fired.
* **No fix for #1038.** Found in a peer's landed mechanism, pinned with a test,
  and left to be repaired by whoever pays #1039 — because the two are the same
  missing bit and fixing one without the other would leave the other silent.

**The interaction the next lane needs.** #1039 and #1038 are one purchase. A
fail-closed `.gl` clause that refuses a function carrying the undecoded field
simultaneously (a) makes `w04a` unreachable, which unblocks R-CLOSE\* and its
158, and (b) makes `w10` unreachable, which closes #1038. Bought separately they
cost twice and can drift; the counterfactual keys and GRID-W are already in place
to grade the purchase the day it is made.
