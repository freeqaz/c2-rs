## 2. The alarm, which outranked the lane

### 2.1 What it was

`PortC2::build` reached `emit_empty_obj` — the bare four-section shell — for
every TU whose `.ex` declares an empty module. But `is_empty_module` is a
property of `.ex` **alone** and cannot see `.gl`, and a TU can define no
functions and still cost c2 a fifth or sixth section. Eight of eleven
hand-written probe shapes were live `Port=Mismatch @ offset 2` — a wrong section
**count**:

It is **older than #232 and #259 and nobody was looking for it.**

### 2.2 Why three green instruments could not see it — trap 5's purest instance

`docs/STATUS.md` trap 5 is *absence reads as success unless something forbids
it*, recorded twelve times before today. This is the cleanest case yet, because
all three instruments were green **for the same reason**: none of them can
*represent* the failure.

* **`scripts/expr_sweep.sh`.** Its 47 other fragments all emit **expressions**.
  Not one of them writes a bare declaration, so the class is unrepresentable in
  the corpus that found #232.
* **`differential.rs`.** Names a **fixed list of three fixtures** — the trap the
  brief already records.
* **The 878-TU workload.** Contains **zero** TUs whose section set is the shell
  plus data. Measured, not assumed, on `work/w-bss/census/sections.jsonl`: 8 of
  871 objs carry no `.text`, and all eight are either shell-only (6) or the two
  `??__E` license TUs. So `c2rs gap` read `mismatch 0` over a class it cannot
  generate.

The mitigation is the same as #232's: **an instrument that can represent the
class.** `scripts/sweep.d/64-data-only-tu.py`, 182 cases, and the counterfactual
is the evidence that it *grades* the class rather than merely containing it —
`mismatches=154` against the pre-fix binary and `mismatches=0` after, over the
identical case set.

### 2.3 Refusal, not correction — and why, given that the writer landed anyway

The precedent is split: w-cross **refused** on #232 and priced it; w-order
**corrected** on X-d and gave the asymmetry that justified correcting.

This lane refused first and widened second, in two separate commits, and the
argument is not *"the writer will refuse these anyway"*. It is arithmetic:
**correcting would have closed 5 of the 8 shapes** — the writer refuses
`extern const`, `selectany`, `.tls$`, floats and pointer initializers by
design — **and left 3 live for however long the writer took**. A partial
closure of a wrong-emit family is worse than it looks, because the three
survivors then sit behind a fix everyone reads as having handled the class. The
refusal closes all 8 in one commit and the writer lands as a widening against a
known-good base.

## 3. What the writer admits, and what it refuses

**The class.** A TU that defines **no functions** and at most **two objects per
non-COMDAT section**.

Two is not a preference. `OBJ_DATA_BSS_SHAPE.md` §8.1: a section with **one**
object is trivially right and that is **23,253 of the workload's 24,055**
`.data`/`.bss` sections; a `.bss` with **exactly two** is right on **47 of 48**
real sections; above that it is **38 of 62**. The residual is **walk order**
(board #184) and *not* size — 10 of the 64 real sections needing no alignment
padding at all, where every candidate allocator coincides by construction, are
still wrong.

### 3.1 The rules implemented

| rule | what | source |
|---|---|---|
| **S1** | the **uninitialized** section comes first, **between** the two `.XBLD$W` watermarks; the **initialized** one comes **after** the second | §2.2 |
| **A1** | `.bss` walks **`.gl` file order**, forwards | §5.2 |
| **A2** | `.data` walks **declaration order** | §5.3 |
| **A3′** | a **plain bump, no free list**; `align(obj) = max(t, 1 if n<2 else 4 if n<64 else 8)` | §5.7 |

## 5. Findings — the parts worth more than the writer

### 5.1 c2 DROPS an unreferenced, uninitialized, internal-linkage object

**A rule no document in this repo had.** Found by the differential as six
mismatches on the *first* run of this lane's own sweep fragment.

An object that is `static`, **uninitialized** and **unreferenced** is removed
entirely: no section, no symbol, and the obj comes back as the bare 720-byte
shell. The three axes are separated one at a time, so the predicate is the
conjunction and not any pair:

```text
  static int za;                       04 04 00 · 00    DROPPED — obj is 720 B
  static int zc; int r(){return zc;}   04 04 00 · 01    emitted to .bss
  static int zb = 1;                   04 04 80 · 00    emitted to .data
  int ze;                              01 04 00 · 00    emitted to .bss
```

`za`→`zc` moves only the reference, `za`→`zb` only the initializer, `za`→`ze`
only the linkage.

**Why `OBJ_DATA_BSS_SHAPE.md` could not see it, which is the transferable
part.** §5.2's static cells are every one of them *"8 uninit statics **and one
function each**"* — the function is there to keep the objects alive, so **every
object in that grid is referenced** and the drop is invisible by construction.
§4.4 records the same shape for `const` (*"dropped when every use was
folded"*) and did not generalize it to plain storage. A grid that adds a
function to make the shape observable has changed the shape.

The consequence for the writer is not just a filter: **when every object drops,
the bare shell IS the right obj**, so `data_tu` is also the reader that takes a
TU *back* to `emit_empty_obj` — a path `shell_only_tu` correctly says no to,
because the `.gl` genuinely does name storage.

### 5.2 The `.gl` data record DOES carry COMDAT-ness — with a stated limit

Board **#172** records *"COMDAT-ness is **not** in tag 9"*. That is about the
**section** record and **does not carry over to the data record**, which says so
in its attribute byte:

```text
  int sa = 3;                        … 01 04 80      ordinary .data
  __declspec(selectany) int sa = 3;  … 01 04 E0      COMDAT .data
  int sb;                            … 01 04 00      ordinary .bss
  __declspec(selectany) int sb;      … 01 04 60      COMDAT .bss
```

`data_object_at` admits only `00` and `80`, so `selectany` was **already failing
closed** before this lane touched anything — which is prereg P2, and the reason
no COMDAT gate is needed anywhere else in this path.

**The limit, stated because the coordinator asked for it and because the axis is
one-dimensional.** This is measured on the **`selectany` axis only**. It does
**not** establish that the data record sees every COMDAT-producing path:

* **`??_R0` RTTI descriptors** are COMDAT `.data` with no `selectany` in the
  source (§4.3), and this lane did **not** measure their attribute byte. They
  are refused here by a **different** mechanism — the exhaustive accounting in
  `data_tu`, which requires every indexed `.gl` name to be a recognized object, an
  undefined external or shell furniture.
* **Template instantiations** are the workload's *dominant* COMDAT producer
  (8,382 of 9,139 `.data`), and none was measured on this axis either. Every one
  of them lives in a TU with `.text`, so none can reach this writer — but that
  is a property of the class, not of the attribute byte.

So the honest claim is: **on the `selectany` axis the data record discriminates
COMDAT-ness; on the RTTI and template axes it is untested and the refusal comes
from the accounting gate instead.**

### 5.3 `bss_deferred_layout` is dead code that encodes a **refuted** rule

The brief said *"`.bss` is already landed by #158 — check what exists before
building it again"*. Checking is what produced this.

`container.rs::bss_deferred_layout` implements §5.4's **Rule A3** — a bump
**with hole reuse** — behind an `#[allow(dead_code)]` and with **no caller at
all**. §5.7 supersedes that clause with **Rule A3′**: a plain bump with **no
free list**, exact on **110 of 117** real `.bss` sections, **68 of 68** real
`.data` and **38 of 38** probe cells.

So the helper is not merely ungraded. **It is a claim the project is still
making, and it is the wrong one.** Three things kept it looking correct:

1. It emits nothing, so **no byte compare can see it**.
2. It agrees with the census by construction.
3. **Its three unit tests assert the refuted behaviour** — and one of them,
   `a_later_object_lands_in_an_earlier_holes_gap`, is a **constructed** cell
   rather than a measured obj, so it is a test of the code against itself.

That is the `bt`/`cmpwi` shape w-frame's sweep was built for, one level worse:
there the code was merely unreached, here it is unreached *and* its tests
certify a rule a later lane refuted. **Dead code with passing tests is a claim
the project is still making, and `#[allow(dead_code)]` is what hides it from
every instrument.** This lane did not call it and wrote a fresh A3′ bump; see
proposed row **W-d** for deleting it.

### 5.4 Board #183's error bar does not apply to the data record's id

#183 asks for a **forward** parser because `glparse.py` reads the
declaration-order id by scanning **backwards** from the name, which is right on
small TUs and demonstrably wrong on some large ones — and Rule A2 walks
declaration order, so every `.data` number w-bss2 published inherits that bar.

For the `.gl` **data record** the id is the **operand token**, and this crate
already reads it **forward**, by `read_token_var` at a position the record
framing has validated — the same discipline `gl_symbol_index` applies. The
control is six names chosen so declaration order, sorted order and `.gl` order
are **pairwise different**, so the reading can fail:

```text
  source      zulu alpha mike bravo yankee charlie
  tokens      09e3 09e4  09e5 09e6  09e7   09e8      <- ascending == source
  .gl file    zulu yankee mike charlie bravo alpha
```

Ascending token reproduces §5.3's transcribed declaration order exactly. So
**Rule A2's walk is available today, without #183** — which is why this writer
implements A2 rather than approximating it with `.gl` order. #183 is still worth
doing for the *general* record stream; it is no longer a blocker for `.data`
layout.

### 5.5 The allow-list was the trap, not the gate — and it nearly cost TU match 2

**This is the finding to read if you read one.**

`__declspec(thread)`'s `.gl` data record is byte-identical to an ordinary
uninitialized object in **every field the reader had**, and lands in `.tls$`.
The obvious fix is an **allow-list** in the shared reader: admit the flag values
we can explain, refuse the rest. That looks conservative and is the safest-shaped
thing to write.

It would have refused the two `??__E` license TUs — their object carries flags
`0x61` — and taken **TU match 8 → 6**.

Two things make this worth a numbered finding:

* **An allow-list of values you can *explain* fails closed on everything you
  have not yet met, including things that already work.** The flag byte carries
  at least five meanings (`00` plain, `01` referenced, `20` address-taken, `40`
  unexplained, `80` unexplained) and this lane can account for three. A gate
  built from the three refuses the other two. **Publish the byte and let each
  caller apply its own test**: `dyninit_tu` is a graded path and keeps today's
  behaviour; the new consumer is the one that fails closed.
* **Nothing in the gate would have caught it as a regression.** The objs would
  simply have started refusing. `mismatch` stays 0, every lane stays green, the
  sweep stays green, and **the payoff metric drops quietly by 2**. That is trap
  5 again with TU match as the victim, and the only reason it was caught is that
  the flag values were checked *against the match set* before the gate was
  written.

the suspect band goes 79 → **1**.


**`emit_data_obj`'s STATIC branch of Rule Y1 has no witness, and cannot have one
in this class.** Y1 emits every EXTERNAL `.bss` symbol first in reverse `.gl`
order and then every STATIC in declaration order — but §5.1 says an
uninitialized `static` in a functionless TU is **always dropped**, because
nothing exists that could reference it. The only way to reference one is from a
function, and a TU with a function is not this class.

So the branch is **reachable only from a future caller**, and this rung says so
rather than counting its unit test as coverage. `wsect_data_linkage.cpp` grades
mixed linkage in a `.data` (where §6.2 says the order is declaration order for
both linkages, and the writer does not branch), so the *linkage* axis is graded;
the **`.bss` two-block order** is not.

That is the same category as the `bt`/`cmpwi` finding and it is disclosed for
the same reason. It is one branch, it is named, and it is the honest price of
implementing a rule the class cannot fully exercise. The alternative — omitting
Y1's static block — would be worse: the branch would be *absent* rather than
*unwitnessed*, and the next lane to widen this class would rediscover Y1 from
scratch.
