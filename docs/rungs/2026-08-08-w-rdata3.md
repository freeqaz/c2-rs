### §4.1 The `.gl` refusal is ONE ATTRIBUTE BYTE — and the records frame perfectly

Located by hexdumping the `.gl` at each record's terminating NUL
(`work/w-rdata3/p01/glhex.py`, read-only) and walking `data_object_at`'s own
gate sequence. For `??_R4A@@6B@`:

```text
   00   86   06   00 02   01   14   a0 …
   ^NUL ^tag ^kind ^frame ^link ^size ^ATTR
```

tag `86` → align 4 ✔ · frame `00 02` (ORDINARY-DATA, not the `00 04` read-only
form) ✔ · linkage `01` = `LINKAGE_DEFINED_EXTERN` ✔ · size varint `14` = **20** ✔
— and `??_R3` reads 16, `??_R2` reads 8, `??_R1` reads 28, `??_R0` reads 16.
**All five sizes match `OBJ_RDATA_R_SHAPE.md` §3 exactly**, so the frame is not
merely passing, it is *correct*.

Then `DATA_ATTR` = **`a0`**. `data_object_at` models `00` (uninitialized) and
`80` (initialized), documents `60`/`E0` as `__declspec(selectany)`, and **fails
closed on everything else**. `a0` is a fourth value, and **that one byte refuses
all five records**.

The vftable `??_7A@@6B@` refuses one gate *earlier*, at frame **`00 04`** — the
read-only form `data_object_at` refuses by name. Which is correct: a vftable is
`.rdata`, not `.data`.

### §4.2 CORRECTION — `?g@@3UA@@A` is refused by the TYPE TAG, not by `.in` tag `02` (board #1108)

The third row's cause is published in three places as *"because its initializer
carries a **relocation** — the same element tag `02`."* **It is falsifiable now
and it is false**: tag `02` reads that very cell at `symrefs=10 residue=0`, and
the row is unchanged at **1 of 12**. From the bytes:

```text
?g@@3UA@@A   00   c6   81   06   00 02   01   08   00 …
             ^NUL ^tag ^wide ^kind ^frame ^link ^size ^attr
```

Wide mark `81` ✔ · frame `00 02` ✔ · linkage `01` ✔ · size `08` = 8 B (vfptr +
`int`) ✔ · attr `00` ✔ — and then **`align_of_type_tag(0xC6)` returns `None`**.
That function models exactly four tags, `82`/`84`/`86`/`88` = 1/2/4/8 bytes;
`C6` is the **wide aggregate** form and has no entry. A different function, a
different file section, nothing to do with `.in`.

**This is the correction with a cost attached**: a lane briefed off #931 would
pay tag `02` again — already paid — and still read `1 of 12`.

## §6 Item 5 — the only ordering rule in the tree explicitly rules itself out

`coff/order.rs` is the **`.text`** emission order: a readiness loop over the
IL's reference set. Its own module doc says, in terms, that it is not what item
5 needs:

> *"**it is not a DFS from each root either** — a DFS of `f, h, g` with `f→g`
> gives `g, f, h` and c2 gives `h, g, f`"*
>
> *"the caller must pass the IL's reference set, **not the obj's**; a planner fed
> the relocation list alone gets this case wrong"*

Item 5 needs the opposite: a DFS pre-order over the **relocation graph**, per
group, cut at the vftable run (`OBJ_RDATA_R_SHAPE.md` §6.1). The only occurrence
of that phrase in `crates/` is a doc comment in `coff/function.rs` describing
what does not exist.

## §8 What was deliberately NOT done

**No `.gl` gate was widened.** `DATA_ATTR = 0xA0`, the `00 04` read-only frame
and `align_of_type_tag(0xC6)` each fail closed today for a documented reason,
and all three of them mean *COMDAT or read-only*, which `emit_data_obj` refuses
anyway. Accepting `0xA0` without a graded consumer would place a COMDAT record
in a non-COMDAT `.data` — board **#232**'s direction, live on master for 255
commits while the scan read `mismatch 0`.

**No name was added to `PORT_WRITER_SECTIONS`.** That is BREAK 1 of `w-rtti`'s
counterfactual, and `the_writer_vocabulary_is_every_section_name_this_file_emits`
turns red on it. Adding a literal in an uncalled emitter is BREAK 2, and
`every_production_emitter_has_a_lib_rs_caller` (board #927/#301) turns red on
that. Both guards were left to do their job rather than tested again — `w-rtti`
measured them one master ago and this lane's `crates/` diff is empty.

**`crates/c2-core/src/codegen/` was not touched** — concurrent lane `w-front2`'s
seam this wave. Item 3 lives partly there and is **reported, not implemented**.

## §12 Found and deliberately not taken, priced

* **`align_of_type_tag(0xC6)` — the wide aggregate TYPE tag.** It blocks a
  **plain namespace-scope object of a class type** today, with no RTTI involved,
  and `emit_data_obj` is a graded consumer that already handles relocations.
  **Price: one match arm plus the cells that prove the alignment.** Not taken:
  `c2-il`'s `.gl` seam, and it needs its own frozen grid — an alignment nibble
  guessed wrong is a wrong Characteristics word.
* **`DATA_ATTR = 0xA0`.** Cannot be taken alone: the value means COMDAT, and
  `emit_data_obj` places no COMDAT section. Reading it without a writer produces
  records nothing can emit; **it must land with item 4 or not at all.**
* **`scripts/gt_dump.py` still cannot print `.rdata$r` raw bytes.** Filed by
  `w-rdata` §10 at *"price: one line"*, declined by `w-rtti` §8.6, declined again
  here for the same reason — another lane's seam, and `glhex.py` reads `.gl`
  rather than the obj.
* **`docs/STATUS.md`'s generated block is not regenerated.** Nothing this lane
  did moves a metric in it; the `crates/` diff is empty. The coordinator's call
  from the merged tree.
