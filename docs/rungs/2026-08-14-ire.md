### 1.0 The success criterion, stated before the claims

**Required-zero byte delta.** This lane converts zero TUs *by design*. A
conversion would mean behaviour changed, which is this kind's failure mode, not
its prize. Grading is a line-for-line identity diff of the 878-TU scan's
`gap-metric` keys, its 878 per-TU verdict lines, and every gate lane's
fixture-verdict counts, base against tip. **Any byte that moved = FAILED**,
whatever else the lane achieved, reported in that word with the moved byte
named.

Absence is not the check. Every row below is graded **positively on content**:
the scan must print its `gap-metric` block and be digit-for-digit equal; the
gate must print `graded > 0` per lane and the per-lane counts must be equal; the
workspace run must print a pass count **and** a target count. A missing number
is a MISS, never a zero.

### 1.2 What the producer side is, predicted before it was written

One new module `crates/c2-core/src/codegen/cond.rs`, plus an integration in
`block_ir.rs` and a re-expression of two **already-byte-exact** classes:

1. **`CondProducer`** — the two producers §3.2 measures: an explicit compare,
   and a record form. The record form **cannot name a field** (it writes cr0);
   a compare **names its own** in its `BF` field, so `Compare` carries the `crf`
   rather than assuming 6. See §1.3 — the crate's own shipped bytes refute
   `Compare ⇒ cr6` as a biconditional and that refutation is what forces the
   shape of the type.
2. **`Cond`** — producer + `BO` + CR bit, with `bi()` **delegating to
   `encode::cr_bi`** and never re-deriving `4*crf + bit`.
3. **The decode side** — `cr_writer(word)`, three-valued (`Writes(producer)` /
   `Silent` / `Unrecognized`), so a block can be asked *from its own bytes*
   which producer wrote the condition its terminator reads. Unrecognized is a
   distinct answer from "does not write", because absence is not evidence.
4. **The check** — a `BasicBlock` whose body's nearest CR writer wrote a
   different field from the one its `Bc`/`Bclr` reads is **refused** at
   `place`. That is §3.2's hazard (`409a…` where the obj has `4082…`, board
   #188) made structural rather than left to a comment.

### 1.3 Anti-collision check, done before the first type was named

The crate **already contains six private readers** of "which CR field does this
producer write", each locally named, and the model must become the one reader
rather than the seventh:

| reader | value | what it means |
|---|---|---|
| `encode::CR_COMPARE` | 6 | the compare field, §3.2 |
| `ptr_walk_loop::CR_RECORD` | 0 | a record form's field |
| `ptr_walk_chain_loop::CR_RECORD` | 0 | the same fact, a second private copy |
| `close_call_chain::GUARD_CRF` / `RESULT_CRF` | 6 / **0** | a compare into cr6 **and a compare into cr0** |
| `alloc_init_or_fail::CR_MIDDLE` | **0** | a compare into cr0 |
| `guard_ret_chain::GUARD_CRF` | 6 | the compare field again |
| raw `cr_bi(0, …)` in `guard_chain_shared_tail`, `frontier_bytes` | 0 | the fact with no name at all |

Two of those are **compares into cr0** in classes that are byte-exact against
real `c2.dll`. So the model must be *producer + field*, not *producer ⇒ field*:
a `Compare` that assumed cr6 would emit `2b03…`/`409a…` where those objs carry
`2803…`/`4082…`. Frozen here, before the type existed.

Names checked free at base: no `Cond`, `CondProducer`, `CrWriter`, `cr_writer`
or `CR_RECORD` in `c2_il`; `c2_il::CondPlan`/`CondStep`/`CondTailPair` exist and
are **different things** (the IL's conditional-tail plan), so the new module is
**not** glob-re-exported from `codegen/mod.rs`, exactly as `block_ir` is not.
`cond_tail::branch_sense` is an existing shared predicate — the `(BO, bit)`
half — and is **used**, never re-derived or narrowed.

### 1.4 Bounds (`CFG_SHAPE.md` §6.3), all binding

No code motion; no cost model; no loop rotation; no CTR-loop discovery; **no
instruction scheduler** — item **F** was re-priced *upward* by `w-dagorder`
(#3067) and `CEILING.md` §6.1 phase 7, and this lane does not touch or re-price
it; no neutrality or behaviour-preservation classifier. **No second
`BlockOrder` variant** on §3.4.1 alone (#3072). The fixup list stays
`codegen::labels`' (item **B**, #290): this lane adds no second reader of a
pending branch site, its target, or whether the reference is legal, and
`Terminator::TailCall` stays a separate terminator rather than a third `Form`.
Items **F** and **G** stay absent at tip.

### 1.5 How a FAILED outcome is reported

If any byte moved, the header says `Outcome: FAILED`, in that word, with the
moved byte named — not a compound headline, and no rationalisation.
