### 1.2 What the producer side is, predicted before it was written

One new module `crates/c2-core/src/codegen/cond.rs`, plus an integration in
`block_ir.rs` and a re-expression of two **already-byte-exact** classes:

1. **`CondProducer`** — the two producers §3.2 measures: an explicit compare,
   and a record form. The record form **cannot name a field** (it writes cr0);
   a compare **names its own** in its `BF` field, so `Compare` carries the `crf`
   rather than assuming 6. See §1.3 — the crate's own shipped bytes refute
   `Compare ⇒ cr6` as a biconditional and that refutation is what forces the
   shape of the type.
2. **`Cond`** — producer + `BO` + CR bit, with `bi()` **delegating to
   `encode::cr_bi`** and never re-deriving `4*crf + bit`.
3. **The decode side** — `cr_writer(word)`, three-valued (`Writes(producer)` /
   `Silent` / `Unrecognized`), so a block can be asked *from its own bytes*
   which producer wrote the condition its terminator reads. Unrecognized is a
   distinct answer from "does not write", because absence is not evidence.
4. **The check** — a `BasicBlock` whose body's nearest CR writer wrote a
   different field from the one its `Bc`/`Bclr` reads is **refused** at
   `place`. That is §3.2's hazard (`409a…` where the obj has `4082…`, board
   #188) made structural rather than left to a comment.

### 1.3 Anti-collision check, done before the first type was named

The crate **already contains six private readers** of "which CR field does this
producer write", each locally named, and the model must become the one reader
rather than the seventh:

| reader | value | what it means |
|---|---|---|
| `encode::CR_COMPARE` | 6 | the compare field, §3.2 |
| `ptr_walk_loop::CR_RECORD` | 0 | a record form's field |
| `ptr_walk_chain_loop::CR_RECORD` | 0 | the same fact, a second private copy |
| `close_call_chain::GUARD_CRF` / `RESULT_CRF` | 6 / **0** | a compare into cr6 **and a compare into cr0** |
| `alloc_init_or_fail::CR_MIDDLE` | **0** | a compare into cr0 |
| `guard_ret_chain::GUARD_CRF` | 6 | the compare field again |
| raw `cr_bi(0, …)` in `guard_chain_shared_tail`, `frontier_bytes` | 0 | the fact with no name at all |

Two of those are **compares into cr0** in classes that are byte-exact against
real `c2.dll`. So the model must be *producer + field*, not *producer ⇒ field*:
a `Compare` that assumed cr6 would emit `2b03…`/`409a…` where those objs carry
`2803…`/`4082…`. Frozen here, before the type existed.

Names checked free at base: no `Cond`, `CondProducer`, `CrWriter`, `cr_writer`
or `CR_RECORD` in `c2_il`; `c2_il::CondPlan`/`CondStep`/`CondTailPair` exist and
are **different things** (the IL's conditional-tail plan), so the new module is
**not** glob-re-exported from `codegen/mod.rs`, exactly as `block_ir` is not.
`cond_tail::branch_sense` is an existing shared predicate — the `(BO, bit)`
half — and is **used**, never re-derived or narrowed.

### 1.4 Bounds (`CFG_SHAPE.md` §6.3), all binding

No code motion; no cost model; no loop rotation; no CTR-loop discovery; **no
instruction scheduler** — item **F** was re-priced *upward* by `w-dagorder`
(#3067) and `CEILING.md` §6.1 phase 7, and this lane does not touch or re-price
it; no neutrality or behaviour-preservation classifier. **No second
`BlockOrder` variant** on §3.4.1 alone (#3072). The fixup list stays
`codegen::labels`' (item **B**, #290): this lane adds no second reader of a
pending branch site, its target, or whether the reference is legal, and
`Terminator::TailCall` stays a separate terminator rather than a third `Form`.
Items **F** and **G** stay absent at tip.

### 1.5 How a FAILED outcome is reported

If any byte moved, the header says `Outcome: FAILED`, in that word, with the
moved byte named — not a compound headline, and no rationalisation.

## 2. What it admits, and what it refuses

### 2.1 The producer side, in five lines

`crates/c2-core/src/codegen/cond.rs`, one new module, zero new dependencies,
**emits nothing**:

* **`CondProducer`** — §3.2's two producers and no third. `Compare { crf }`
  **carries** its field, because an explicit compare names one in its own `BF`
  bits; `RecordForm` carries nothing, because a record form writes cr0 or it is
  not a record form. §1.3's finding is the whole reason for that asymmetry.
* **`Cond`** — producer + `BO` + CR bit. `bi()` is **derived** from the producer
  through `encode::cr_bi`, so a lowering that says which instruction wrote its
  condition can no longer name a different field beside it.
* **`cr_effect(word)`** — what one instruction word does to the condition
  register, **four-valued**: `Compare { crf }`, `Record`, `Untouched`,
  `Unmodelled`. The last is a distinct answer from the third on purpose.
* **`cond_source(run)`** — scans a straight-line run **backwards** for the
  nearest writer; three-valued (`InBlock`, `NotInThisBlock`, `Unknown`).
  Backwards because the last writer wins: `?b_ifn` writes cr6 three times in one
  body, each branch consuming its own (§3.2).
* **`producer_at(run, site)`** — the one reader of "turn a scan into a producer
  or refuse", so three lowerings do not write three copies of one `match`.

And in `block_ir.rs` (item **A**'s module, whose representation is untouched):
`Terminator::bc`/`bclr` build the raw variants **from a `Cond`**;
`Terminator::reads_crf()` says which field a branch reads;
`BasicBlock::cond_source()` says which instruction wrote it; and
`BodyLayout::place` refuses a positive disagreement between the two.

### 2.2 What it refuses, by name

| refusal | why it is a refusal and not a repair |
|---|---|
| a block whose branch reads a CR field **its own instruction run did not write** | §3.2's hazard: `409a…` where the obj has `4082…` — two bytes, in a word that still disassembles to a plausible branch (board **#188**) |
| a lowering asking for a producer where **nothing in the run writes a CR field** | the producer is in a predecessor, so *this* caller cannot derive a field from what it holds, and assuming cr6 is exactly the defect |
| a lowering asking for a producer where the run reaches an **unmodelled word first** | a call clobbers the volatile CR fields; walking past one would name bits that are gone |

The first fires on a **positive** disagreement only. `NotInThisBlock` and
`Unknown` are separate variants precisely so the check cannot turn *"I could not
read the run"* into *"the run is wrong"* — absence-is-not-evidence, applied to a
decoder.

### 2.3 What it delegates rather than restates

* `encode::cr_bi` stays the only reader of `BI = 4*crf + bit`;
* `encode::CR_COMPARE` stays the only reader of "§3.2's compare field is cr6",
  and is **used** by `CondProducer::compare()`;
* `cond_tail::branch_sense` stays the only reader of "which `(BO, bit)` an IL
  relation becomes" — its doc already said *"the caller adds the CR field"*, and
  `Cond` is the caller it was waiting for;
* `codegen::labels` stays the single reader of a pending intra-section branch
  site, its target and whether the reference is legal (item **B**, #290). This
  lane adds no second fixup list, no second label identity, and
  `Terminator::TailCall` stays a separate terminator rather than a third `Form`.

### 2.4 What it does NOT build

| item | state at tip | why not here |
|---|---|---|
| **F** — values live across block boundaries | absent, **and not re-priced** | `w-dagorder` (#3067) showed live ranges are a property of a *scheduled* order, and `CEILING.md` §6.1 phase 7 re-prices it upward. Out of this lane's bounds by §1.4 |
| **G** — a per-shape record of §3.5's folds | absent | needs the band-1↔band-2 decision (§8.1 B1), unmeasured |
| an instruction scheduler | absent | §6.3, and explicitly not this lane's |
| a second `BlockOrder` variant | absent | #3072's reasoning is unchanged |
| a `CondProducer` variant for cr1 | absent | the FP record forms write cr1 and this crate emits none; `cr_effect` reports them `Unmodelled` rather than inventing a producer for a word with no witness |

### 2.5 The re-expression — three classes, both producers

| class | branch | producer, as the bytes name it | field |
|---|---|---|---|
| `cond_tail` (`?MemFree`, §4.1) | the `bc` to the else entry | explicit compare | cr6 |
| `ptr_walk_loop` (`?HashString`) | the entry guard at 0x10 | **explicit compare** `cmplwi cr0,r11,0` | cr0 |
| `ptr_walk_loop` | the back edge at 0x44 | **record form** `mr. r11,r10` | cr0 |
| `ptr_walk_chain_loop` | the entry guard | `cmplwi cr0` *or* `extsb.` — it varies by cell | cr0 |
| `ptr_walk_chain_loop` | the back edge | record form, at a schedule-dependent slot | cr0 |

Every one of these was **already byte-exact against real `c2.dll`**, which is
what makes them the right classes to re-express: a disagreement would have been
a defect in the new mechanism, visible immediately against published bytes. It
is: mutating the decoder to assume cr6 turns `?HashString`'s twenty transcribed
words red (§4.2).

## 5. Found and not taken

Ranked, with the frame axis applied.

1. **`close_call_chain`, `alloc_init_or_fail` and `guard_ret_chain` still carry
   their own CR-field constants, and two of them are the evidence this lane's
   type shape rests on.** `RESULT_CRF = 0`, `CR_MIDDLE = 0`, `GUARD_CRF = 6`
   name the field by *role*, which is information the model does not carry and
   should not lose. **Not taken** because pointing them at
   `CondProducer::compare_into(CR0)` would trade a role name for a producer
   name and neither subsumes the other; the honest move is to keep the role
   constant and *derive* the field beside it, which is a change to three
   framed-body emitters and wants its own zero-delta lane. Sized: small, three
   files, and it converts nothing.
2. **The producer-side check has one client class and the two loops have
   none.** `BodyLayout::place`'s refusal only fires for lowerings built on
   item A, and `cond_tail` is still the only one. `ptr_walk_loop` and
   `ptr_walk_chain_loop` now use the *model* but not the *layout* — they cannot,
   because a loop has a backward branch and `labels::LabelMap` refuses those by
   invariant 4 (the compiler-label charge, `docs/LABEL_COUNTER.md` §4.2). So the
   ceiling on how much of this port can be expressed as blocks is, today, the
   label counter and not the IR. **That is the sentence a lane proposing "move
   the loops onto `BodyLayout`" needs to read first.**
3. **`cr_effect`'s vocabulary is this crate's, and it is not the architecture's.**
   `SILENT_PRIMARIES` is a list read off `encode.rs`'s own encoders, and a word
   outside it is `Unmodelled` — safe, but it means a future encoder silently
   costs the scan its answer unless the list grows with it. The cheap guard is a
   test that enumerates `encode`'s public functions; **not taken** because there
