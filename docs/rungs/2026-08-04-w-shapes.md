### Where this departs from w-modes' pricing, and why

w-modes priced **`static` functions, static locals and `try`/`throw` at one
afternoon each** and told the coordinator to close a zero row before widening the
flag cross further. **The advice was right and the pricing was ~3× pessimistic**:
all three took about an hour, because a `sweep.d/` fragment is a Python function
and the whole cost is deciding which axes are structural. Checking rather than
inheriting the estimate is what the brief asked for; the answer is that a zero
row is cheaper than w-modes thought and the ranking it implied still holds.

Two rows moved:

* **`#include` was priced last and belongs fifth.** The measurement is in §4.5:
  adding a single `#line 100 "other.cpp"` in front of `int f(int a){return a+1;}`
  takes it from `Port=Match` to `Port=NotImplemented` with blocker
  `module-end-0x4F`. That is a *decode* boundary reachable by one line of source,
  and the corpus had never crossed it because every case is one self-contained
  file. It is worth more than `union` and much more than `shift`.
* **`shift` fell to last.** The rule this project uses — *when a row's blocker is
  a class whose emitter already exists, the ceiling IS the estimate* — reads the
  other way here. `expr-shl` is a `vocab-gap` in `crates/c2-il`: **no emitter
  exists**, so every case refuses and will keep refusing. It is still worth
  writing (271 cases enumerated before the widening rather than four chosen
  after it), and it is honestly the weakest row of the eight.

## 3. The measurement each fragment is built on

Every line below was taken with `scripts/gt_capture.sh` on this tip and is the
COFF section-name list with `.drectve`, `.debug$S` and the two `.XBLD$W` dropped.

### 3.1 `.xdata$x` — the EH table the `/EHsc` axis has never contained

```
int f(int a){ if(a) throw 1; return a+1; }
  /Ox /GS- /c      .text .xdata$x .pdata .xdata$x .xdata$x .data
  /O1 /Oi /EHsc    .text .xdata$x .pdata .xdata$x .xdata$x .data .text

int h(); int f(int a){ try{ return h(); } catch(int e){ return e; } }
  /Ox /GS- /c      .text .pdata .rdata .data
  /O1 /Oi /EHsc    .text .pdata .pdata .rdata .data
```

`try/catch` and `throw` are **two rows because they are two obj shapes**: only
`throw` mints `.xdata$x`, and only `try` mints the `.rdata` + `.data` pair. A
fragment writing one would have left the other unreached.

One trap the fragment records: at `/O1 /Oi /EHsc`, `try{ return a+1; }
catch(...){ return 0; }` compiles to the **same 845-byte obj** as
`int f(int a){return a+1;}` — the optimizer proves the region cannot throw and
deletes it. At `/Ox` it does not. A `try` around a pure expression is a control,
not an EH case, and it is kept as one.

### 3.2 `.text$yd` and the guard object — from inside a body

```
int f(int a){static int k;k=k+a;return k;}         .text .bss
int f(int a){static int k=5;return k+a;}           .text .data
int f(int a){static int k;static int j=2;…}        .text .bss .data
int g; int f(int a){static int k;…return k+g;}     .bss .text .bss     <- ORDER
int c(); int f(int a){static int k=c();…}          .text .bss .bss .pdata
struct S{S();~S();int a;};
int f(int a){static S s;return a+1;}               .text .bss .bss .pdata .text$yd
int f(int a){static const int k=5;return k+a;}     .text               <- FOLDED
```

Four things there are new and three are load-bearing: `.text$yd`; **`.bss` on
both sides of `.text`**, which no walk assuming "data first" survives and which
`64-data-only-tu.py` cannot produce because it writes no functions; **two `.data`
sections, not one**, for two static locals in two functions; and a **guard
object** that appears nowhere in the source.

### 3.3 The emit-set — the census claims a function the obj does not have

```
$ cat r1.cpp
static int u(int a){return a+2;}
int f(int a){return a+1;}

$ c2rs census r1.cpp
r1.cpp -> 2/2 functions in class
  [  0] ok  straight-line  cflow-straight+expr-modeled  eh-none   99 B  (unnamed)
  [  1] ok  straight-line  cflow-straight+expr-modeled  eh-none  107 B  (unnamed)

$ c2rs diff r1.cpp
ReferenceReplay=ByteExact (ref=853B)  Port=NotImplemented     # ONE function in the obj
```

c2 drops an unreferenced internal-linkage function. The census's verdict is
per-`.ex`-segment, so it says 2/2, and **factor A is exactly this count**. The
port refuses — but not because it knows about the drop: it refuses because
`Bindings::per_record` will not bind names when `.gl` has fewer defined-name
records than `.ex` has segments. That is a different subsystem's guard doing this
one's job, which is the sort of arrangement that stops holding.

And "internal linkage" is *not* the predicate:

```
namespace { int u(int a){return a+2;} }
int f(int a){return a+1;}          ->  903 B, .text, **Port=Match**
```

An unreferenced anonymous-namespace function survives. A fragment carrying only
`static` would have fitted the wrong rule — which is the whole argument for
crossing structural axes rather than varying values.

The section shape moves under the same one-word edit:

```
static int u… int f(int a){return u(a)+1;}     .text
inline int u… int f(int a){return u(a)+1;}     .text .text
static int u… int (*p)(int)=u; int f(…)        .data .text
inline int u… int (*p)(int)=u; int f(…)        .data .text .text
namespace { int g; } int f(int a){return a+1;} .bss  .text
```

`static` and `inline` produce identical census verdicts, identical names and
different objs.

### 3.4 `??_G` / `??_E` — four COMDATs from a five-token expression

```
struct S{S();~S();int a;};  S* f(){return new S;}      .text .pdata
struct S{S();~S();int a;};  S* f(){return new S[4];}   4x (.text .pdata)
struct S{S();~S();int a;};  void f(S*p){delete p;}     2x (.text .pdata)
struct S{S();~S();int a;};  void f(S*p){delete[] p;}   3x (.text .pdata)
struct S{S();virtual ~S();int a;}; void f(S*p){delete p;}   .text
```

The last line is the structural one: `delete` through a **virtual** destructor is
an indirect call and generates nothing, while the identical source without
`virtual` generates two extra functions. Any rule keyed on "the TU says `delete`"
is wrong on one of those two.

### 3.5 One `#line` flips the verdict

```
int f(int a){return a+1;}                  ->  Port=Match
#line 100 "other.cpp"
int f(int a){return a+1;}                  ->  Port=NotImplemented

$ c2rs census line1.cpp
0/1 functions in class
  [  0] GAP module-end-0x4F  cflow-straight+expr-modeled  107 B  ?f@@YAHH@Z
      … 54 01 54 00 >4f< 02 e3 09 4f 01 65 4d
```

The body is byte-identical and still named; the bundle carries a second `4f`
module record. `44-member-source-lines.py` and `46-source-line-collisions.py`
vary line **numbers** inside one file; nothing had ever varied the **file**, so
`module-end-0x4F` was unreachable.

The toolchain under `compilers/` ships `cl.exe` and **no `include/` directory**,
so `#include <…>` has nothing to open — which is presumably why the corpus was
written single-file. Two routes work anyway and the fragment uses both:
`#include __FILE__` behind a guard (a real second file, opened exactly twice) and
`#line`. They are different rows: `#include __FILE__` with an **empty** other
half is still `Port=Match`, so the record and the include are separable.

### 3.6 `.CRT$XCU` and `.text$yc` — the only emitter that has moved TU match

```
struct S{S();int a;};      S g;            .text$yc .bss .CRT$XCU
struct S{S();int a;};      S g; S h;       .text$yc .text$yc .bss .CRT$XCU
int c();                   int g = c();    .text$yc .pdata .bss .CRT$XCU
struct S{S();~S();int a;}; S g;            + .text$yd
struct S{S();~S();int a;}; S g[3];         + 2x (.text .pdata)   __ehvec_*
const char* g = "hi";                      .rdata .data      <- NOT dynamic
int gi; int* gp = &gi;                     .bss .data        <- NOT dynamic
```

**One `.text$yc` per object, one `.CRT$XCU` per TU**, so the two counts move
independently and a single-object grid cannot separate them. `docs/STATUS.md`:
TU match was flat at 6 for the project's entire history and moved to 8 by
`IlBundle::dyninit_tu`, with the **census +0** across the change — the
per-function census structurally cannot see that emitter, and until this fragment
neither could any generated case. The last two lines are why the controls matter:
they look dynamic in the source and are constant expressions resolved by a
relocation.

## 5. The counterfactual — the fragments do go red

The standard on record is w-order's (`63`: 15 mismatches with the planner forced
to the identity, 0 with it) and w-sect's (`64`: **154 → 0** across the fix). This
lane meets it with **two transient mutations of `crates/`, applied, measured and
reverted in one script** (`work/w-shapes/counterfactual.sh`; `git status
--porcelain crates/` is `0` afterwards, checked, and nothing from `crates/` is in
any commit on this branch).

### Mutation 2 — `PortC2::build` emits the bare shell for **any** functionless TU

One word: `if il.shell_only_tu() {` → `if true {`. This removes w-sect's guard.

| fragment | clean | mutated |
|---|---|---|
| `64-data-only-tu` *(calibration)* | 94 Match, 88 NI, **0 mismatch** | 19 Match, 9 NI, **154 mismatch** |
| **`86-union`** *(this lane)* | 73 Match, 168 NI, **0 mismatch** | 35 Match, 167 NI, **39 mismatch** |
| **`87-dyninit`** *(this lane)* | 9 Match, 139 NI, **0 mismatch** | 4 Match, 133 NI, **11 mismatch** |
| `65-linkage-comdat` *(specificity)* | 37 Match, 173 NI, 0 mismatch | **unchanged** |
| `10-int-chains` *(specificity)* | 962 Match, 1390 NI, 0 mismatch | **unchanged** |

**The `154` is w-sect's own published number, reproduced to the case.** That is
what makes this a calibrated counterfactual rather than an assertion: the
harness is known to produce the right figure on a defect whose figure is on
record. And **two of this lane's fragments raise the same alarm independently** —
`86-union` reaches the class through a *type* and `87-dyninit` through a
*dynamic initializer*, neither of which `64-data-only-tu.py` writes. Two
fragments that cannot see it are unchanged, so the mutation is not a blanket
breaker.

### Mutation 1 — `Bindings::per_record` falls back to a positional guess

One character: `if bound.len() != segs.len()` → `if bound.len() > segs.len()` in
`crates/c2-il/src/func/bind.rs`. This is the guard that refuses the emit-set
shape in §3.3, and the hypothesis was that relaxing it would put a dropped
function's **body** under a surviving function's **name**.

**The hypothesis is wrong, and the negative result is the more useful one.** Over
the whole corpus under the mutation:

```
checked=16164 mismatches=0 graded=16068 ungraded=96 unknown=0
```

and `65-linkage-comdat` goes **37 → 45 `Port=Match`** with every other fragment
tested byte-for-byte unchanged. So one character of relaxation gains 8 matches
and breaks nothing the generated corpus can see. That is **not** a
recommendation — the fixture lanes and the 878-TU workload were not re-gated
under it, and the guard's comment gives a specific reason ("a wrong callee name
is a relocation against the wrong symbol") that this measurement does not
address. It is a routable observation with an instrument attached, and it is
**exactly the widening `65-linkage-comdat.py` exists to grade**: whoever tries it
now has 210 cases and 37 known-positive controls instead of four cases they
thought of.

### The rows no single-line mutation can turn red

`66`, `67`, `68`, `69` and `85` refuse at *decode*, not at emit — `expr-shl`,
`module-end-0x4F`, `assign-ret-nonformal`, EH funclets the writer has no model
for. No one-line mutation makes the port emit those classes, so no counterfactual
of this shape exists for them today. What they assert is the **contract**: 683
cases that must stay `NotImplemented`, with the obj shape each one would have to
produce recorded beside it in the fragment header. The day one of those decoders
lands, the fragment is the instrument, and §4.5's pairs say what it will catch.
