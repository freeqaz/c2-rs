## 2. Deliverable 1 — the duplicate-reader adjudication

### 2.1 The named pair is NOT a duplicate

`crates/c2-core/src/codegen/encode.rs` is the **selection** layer: each helper
names a c2 opcode number and fixes which operand plays which role.
`crates/c2-core/src/codegen/mop.rs` is the **composition** layer: `base_word[op]`
from the read table, fields placed by the read `FieldPlan`.

Measured, not argued: **the live half of `encode.rs` (lines 1–2006) contains
zero `to_be_bytes`, and every `<<` in it is inside a doc comment.** Every word
the file yields goes through `MachineOp::word()` → `encode_op`. The two files
cannot disagree about *bits* because only one of them has any.

`encode.rs` does hold a genuine second producer — `mod incumbent`, the 85
pre-`w-s1` encoders kept verbatim — and it is the **opposite** of the failure
mode: `#[cfg(test)]`, uncallable from non-test code, and graded against the
general composition by `mod cross_check` over each function's whole operand
domain. That is a duplicate reader **with an armed detector**, which is what
this repo keeps wishing the others had.

### 2.2 …and the real one is in `calls.rs` and `frame.rs`

Enumerating every live (non-`cfg(test)`) instruction-word production in
`crates/c2-core/src` returns **eleven** sites outside `mop::encode_op`. Full
table with c2 opcode, form and arm: `P_ENCODE.md` §10.5. The shape:

* **Seven produce a word the port's own `OPCODES` table already carries** —
  `b`, `addi`, `addis`, `stw`, `lwz` (twice), `mtspr`. Worked against this
  page's own §5 rules, `mop` reproduces each **exactly**; e.g. `stw r12,-8(r1)`
  through form 58 is `0x9181FFF8`, which is `FRAME_LR_STORE` to the bit.
* **Four name an opcode the port's table does not carry at all** — `bl`
  (`0x002b`, form 7), `mfspr` (`0x00e6`, form 54), `stwux` (`0x017f`, form 61,
  plan but no row), and `li`/`lis`'s dedicated opcodes (form 33), which the
  port reaches through `addi`/`addis` instead.

**They agree today. That is why nothing caught them** — `mismatch 0` is silent
about a second producer that happens to concur, and this is the latent form of
`ARCHITECTURE_SEAMS.md` §1 class 4.

**Reported, not repaired**, per the charter: routing `calls.rs`/`frame.rs`
through `mop` is an **emit change** needing its own two-sided price, and
`codegen/**` is `w-disclose`'s fence this wave. Filed `#3637`.

### 2.3 The pledge that is false

`mop.rs:38-39`, `mop.rs:111` and `encode.rs:36` all say `base_word` is the
port's **only** source of a primary opcode. `calls.rs` sources primary 18 and
14/15 from its own literals; `frame.rs` sources 31/32/36 from baked words.
Filed `#3638`. **Same class as `#3632`, same file, found by a different route** —
a module doc on the emit path has now been wrong about its own provenance
twice, and both times the detector was a lane reading it for another purpose.

## 3. Deliverable 1b — `#3634`

Both `#3634` and decision 16 quote **the same `//!` block**, which says
opposite things 27 lines apart: `encode.rs:8-25` is the pre-read paragraph
(*"This file is a black-box re-derivation … nothing here changes"*, describing
R2 as future work), and `encode.rs:35-58` is `w-s1`'s *"THE BLACK-BOX
RE-DERIVATION IS RETIRED"*. The first was never struck.

Per object (full table in `P_ENCODE.md` §11): the 85 opcode literals are
**retired** (`#3634` right); the 11 named constants are **9 S + 2 O, 0 F**
(`#3634` right); the 89 helpers' **choice of opcode and operand role** is

from, not which opcode a lowering should name).

**So `#3634` is not corrected.** It is a census of constants and is right as
such; it would be an over-read only if quoted as *"nothing in `encode.rs` is
black-box-derived any more"*, which its own text does not say. The file is what
is wrong, and **its fix site is a peer's fence — STOPPED and reported**
(`#3640`).

`P_ENCODE.md` §8.1 is **amended beside** (owned surface): its sentence is true
in the past tense, and `#3617` drew a consequence from it that does not follow.

`crates/c2-harness/src/subsys.rs`. The encode row's `ported` is
`Cell::Measured { num: 27, den: 79, … }` **plus**
`ported_recount: Some(PortedRecount::EncodeArms)`, and `verify()` **recomputes**
it every run:

* denominator — a file read of `ENCODE_ARMS.txt`, exactly as the band
  denominators read `FUNCS.tsv`;
* numerator — a query against `c2_core::codegen::mop`'s **public** `plan()` and
  `OPCODES`.

**Nothing is transcribed into `crates/`.** A lane that adds an opcode moves the
number without touching this file; a lane that types a wrong number reddens
`cargo test`.

`verify()` also now refuses a `ported` **number** on a row with **no** recount.

on the `coff` row, and it is shut.

## 6. `#3641` — the instrument's page can move the instrument's number

**Observed on this lane's own first draft.** `count_marks` counts every literal
`[R]`/`[O]`/`[I]` after a page's first `---`. `P_ENCODE.md` §10/§11 *discuss*
the mark legend and quote `#3634`'s *"9 `[S]` and 2 `[O]`"* — and the counter
cannot tell a mark from a mention.

Measured: `encode-marks-obj` 9 → **13**, `encode-marks-total` 28 → **34**, from
four prose sites — **one of which was the sentence explicitly warning against
the hazard.** Respelled (`obj-marks`, `O-marks`); census verified back to
**9 of 28**; §10 now carries zero counted tokens by construction.

**No existing control can catch this.** Every one fabricates a *number*; this
moves the number by editing the *page*, which is what the census is meant to
track. `w-submetric` said a mark *"is a page annotation, not a site"*; the
sharper form is that **a mark is not reliably an annotation.** Any lane amending
a `P_*.md` page moves that page's agreement cell as a side effect, in a
direction with nothing to do with evidence. Not fixed here — a delimiter
convention is the natural repair and it is a change to a shared counting rule.
