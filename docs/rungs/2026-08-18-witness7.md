## 5. Board **#3281** — `w-mutcensus`' `B9` RED is the defect, and here is the mechanism

`#3281`: `B9` reads **RED 1,647/1** in `w-mutcensus` while `w-deadsites`
measured its site (`bind.rs:1036`, `if o.size == 0` in `resolve_bss_def`)
**unreached** under two screens and a `panic!()`. `B9`'s mutation is `false &&`
on that condition — a semantic no-op on a branch never taken, hence unkillable,
hence necessarily GREEN. The two cannot both be right.

**The measurement.** `M-B9` at this base: **GREEN 1,671 / 0 / 46**, and at the
tip **GREEN 1,677 / 0 / 48** — in an environment whose named control is RED
with the right pair and whose `census_gate` graded for 66.86 s and 80.90 s.
`w-mutcensus`' RED does not reproduce.

**Which instrument is wrong: `w-mutcensus`' colour.** Two independent reasons,
and the first is decisive on its own.

**(1) The mutation is invisible to that test by construction.** `B9`'s sole
guard is
`reloc_identity::the_cells_population_is_three_functions_one_of_which_disagrees`,
and its cell is GRID-S `s12`, held as a literal in the test file:

```c
void ext();
void g() { ext(); }
void f() { g(); }
void ext_anchor();
void anchor() { ext_anchor(); }
```

**That TU declares no data object at all.** `resolve_bss_def` is reached only
from `shape_to_function`'s `BodyShape::GlobalStoreLeaf` arm, and none of those
four bodies is a global-store leaf — they are void tail calls. So
`resolve_bss_def` is **never invoked** for that cell, and `if o.size == 0` is
never evaluated, let alone taken. No mutation of it can change that test's
outcome.

**(2) The mechanism has a name, an address and a date.** `reloc_identity.rs`'s
three tests shared **one** scratch directory, `c2rs-w-relo-{pid}`, so
`cargo test` ran three concurrent captures into it — a write-write race on five
files: `TMP`/`TEMP` point at the work dir so all three `cl.exe`s write the same
hashed `_CL_*` names, `capture_reference_with` deletes every `_CL_*` on entry so
one test deletes another's live bundle, and all three compile to the same
`/Fo out.obj`. The failure reads **`Unbound` on all three symbols**, and the
assertion messages then say *"the fence stopped firing and the port is emitting
a wrong relocation again"*. That file's own comment records the measurement:
**0 failures in 18 runs at low load, 6 failures in 30 runs under load**, and
*"a shared temp path presents as a port defect"*.

**It was fixed at `71b844fcd`, 2026-08-18 11:14 UTC.** `w-mutcensus`' rung
commit is `2a0f54ae7`, **2026-08-17 19:07 UTC** — `git merge-base --is-ancestor`
says the fix is **not** an ancestor of it. That campaign's 159 runs therefore
