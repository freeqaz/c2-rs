### 2.1 Why the removal of 2026-08-25 could not see it

The second-order reason is on the board already: the audit that eventually
found it first reached for `grep -P '\x00'`, filed as non-firing on 2026-08-08
and still in the reflex eighteen days later. §4 corrects **that** row too, in

## 4. THE NUL GUARD — A MISS, AND A CORRECTION TO THREE BOARD ROWS

**Predicted: 3 live broken sites, biased low, interval 1–12. Actual: 0. This is
a MISS.**

The sweep covered all 9,754 tracked files for a NUL predicate in any spelling.
**Exactly one grep-based NUL test exists in a script anywhere in the repo** —
`work/w-gen2/scrub.sh:48` — and it reads

    LC_ALL=C grep -q -a -P '\x00' "$f"

**which works.** Every other hit in the sweep is prose *about* the broken form:
board rows `#1236`/`#3544`/`#3673`, two rung files, decision 18's own text,
`tracked_artifact_audit.sh`'s comment block, and this lane's prereg. A prose
mention is not a site and was excluded by the prereg before the sweep ran.

### 4.1 The discriminator is `-a`, and no row names it

Measured at lane time on `printf 'a\000b\n'` vs `printf 'ab\n'`, both
implementations on this box (**0 = fired, 1 = silent**):

| detector | NUL file | text file | |
|---|---:|---:|---|
| ugrep 7.5.0 `grep -qP '\x00'` | 1 | 1 | **SILENT — broken** |
| GNU 3.12 `grep -qP '\x00'` | 1 | 1 | **SILENT — broken** |
| ugrep 7.5.0 `grep -q -a -P '\x00'` | **0** | 1 | correct |
| GNU 3.12 `grep -q -a -P '\x00'` | **0** | 1 | correct |
| `tr -d '\000'` + `wc -c` byte count | **0** | 1 | correct |

and the `grep -c` dollar-NUL spelling is **not merely silent, it is
anti-correlated**: GNU prints **2** on the NUL file and **1** on a plain text
file, because that pattern is the empty string in argv (the shell truncates at
the NUL) so it matches every line and counts lines.

**So `tracked_artifact_audit.sh`'s standing comment — *"`grep` cannot test for
a NUL byte and is not used to"* — is FALSE**, and it is retracted in this
lane's commit. What is true, and what actually cost this project a 3.8 MB ELF,
is narrower and more useful: **the spelling everyone reaches for omits `-a`,
and its failure is silent.** `#1236`, `#3544` and `#3673` are all true as
written and all incomplete in a way that reads as "grep cannot do this". The
correction is `#3677`.

### 4.2 What was shipped anyway, and why

The byte count was adopted at that site regardless — **not for correctness**,
which `-a` already had, but because it is correct without depending on a flag
whose absence is invisible. **The real gain is the self-test**, which is new:
`sh work/w-gen2/scrub.sh --self-test` watches the byte count fire on a planted
NUL and stay green on plain text, watches the **flagless** grep form stay
silent on that same NUL file, and watches the `-a` form fire — so the record is
a measurement rather than a caricature and nobody reinstates the flagless one.
Transcript: `work/w-shelf/nul_guard_evidence.txt`.

## 5. THE AUDIT, WIDENED

`scripts/tracked_artifact_audit.sh`'s class-2 scope was
`git ls-files -- crates scripts fixtures c2host c1host`, so **`work/` was
outside the population it examined**: it printed *"absolute machine paths in
code surfaces: 0"* while eleven offending files were staged (`#3615`). Four
classes now, each with its **own denominator**:

    tracked files examined: 9759
    class 1  forbidden artifact NAMES      — examined 9759, violations 0
    class 2  absolute paths, CODE surfaces — examined  801, violations 0
    class 3  absolute paths, work/ SHELF   — examined 8119, violations 0   NEW
    class 4  BINARY content (a NUL byte)   — examined 9759, violations 0   NEW
             read 189,814,209 bytes; 2448 NUL byte(s) total,
             2448 of them in 11 allowlisted file(s)
    SUMMARY: examined 9759 tracked files across 4 classes; 0 violation(s).

Whole run: **1.2 s**.

Five properties, each with a corpse behind it:

1. **A class that examined ZERO files FAILS the run**, even when every other
   class is clean. `#3470`/`#1002`: only a denominator can catch an absence.
2. **The summary is POSITIVE** — *"examined N across 4 classes, M
   violations"* — not an enumeration of ways to be empty. A run that examined
   nothing must be loud.
3. **Class 4 is defined by CONTENT.** §2.1 is the reason. Class 1 (names) is
   kept because a forbidden name is forbidden even at 0 bytes.
4. **Class 3 scans BOTH spellings** (§3.2).
5. **The allowlist is scoped to the class that justified the entry**, and
   prints how many files each entry matched. A flat list would have exempted
   `corpus_sample/`'s sixteen files from the absolute-path classes too, which
   nothing justifies; and a prefix that silently grows from 10 files to 400 is
   a regex wearing a list's clothes. Class 1 has no allowlist at all.

The shelf stays sanctioned: evidence under `work/` is **not** reported as a
violation for being tracked-and-ignored. The `.gitignore`-wide 8,119 is still
printed as an advisory, with decision 18 as the reason it is not gated — the
audit's own comment block argued that a `.gitignore`-scoped gate cannot ship,
and that reasoning is honoured, not overturned.

A defect found while writing it, recorded because the mechanism generalises:
**POSIX `sh` has no `local`**, so `allowed()`'s `for a in $1` clobbered the
allowlist printer's own loop variable, and the report named one entry four
times with the class column reading `?`. It was caught **only because the
printed list disagreed with itself**. A report read solely for its final number
would not have shown it — which is the argument for printing the list.
