### 3.1 The reference, at the workload's own flags

`work/w-frame/refobj.sh` + `scripts/gt_dump.py`. **The census names the CALLEE**

**Answering my lead's §3 question directly:** `xboxheap` needs **none** of
`w-conv` §3's top three mechanisms — there is no intra-section `b`, no cr0
record-form branch, and no label→offset map (`$M2595`/`$M2596` are line-table
LABEL symbols, not branch targets). It *does* need a callee-saved GPR home, but
in the **weak** form — one open-coded `std r31,-16(r1)` / `ld r31,-16(r1)` pair,
not `__savegprlr`. So `w-conv`'s row 4 applies and rows 1–3 do not, and the
`cflow-straight` classification is **not** refuted.

**And `w-conv`'s "every instruction in vocabulary" is CORROBORATED, positively
rather than by absence**: `crates/c2-core/src/codegen/encode.rs:433,444` already
encode `fbe1fff0`/`ebe1fff0`, `frame.rs:206` already knows *"2 saved GPRs are
open-coded `std`s, 3 are the helper"*, `calls.rs:666` already allocates `r31`
first, and `coff/pdata.rs:59` already carries a two-call `r30/r31` frame word.
**The distance is entirely in the body-shape parse layer plus one scheduling
decision.**

* **F2 — a member's ADDRESS as a stored value.** One decision: `27` in *value*
  position lowers to `addi rD,rBase,k`, and the designator layer only reads `27`

* **F3 — a call after a store run.** One decision: `StoreRun`'s tail admits only

### 5.3 What they refuted

* **They refuted the widening I would have written.** `s5_addr_signed_off` sits
  at offset **32768** — the first offset a signed 16-bit `addi` displacement
  cannot encode — and `s7_bound_32764` at **32764** is the last one that can.
  Sink off, `s7` is `1/1 in class` via **`addr-leaf`** and `s5` falls through to
  `expr-op-0x27`. That reads exactly like *"`addr-leaf`'s bound is too
  conservative, relax it"* — the shape of the `!=`→`>` trap on record. **It is
  wrong.** `crates/c2-il/src/func/body/shapes/leaf_addr.rs:129` bounds `off` to
  `-0x8000..=0x7FFF` because `AddrLeaf` lowers to **one `addi`**, and one `addi`
  genuinely cannot hold 32768. Real c2 emits **two** instructions there —
  `addis 3,3,1 ; addi 3,3,-32768` — and 80000 is `addis 3,3,1 ; addi 3,3,14464`.
  Relaxing the bound would have shipped a wrong object. The sink's path is
  byte-exact **only because it is a different lowering**
  (`[Load, Lit(k), Add]` through the generic constant materialiser), not because
  the bound was wrong.
* **They confirmed the `Vocab::CallArg` correspondence guard, and confirmed it
  REFUSES rather than mis-emits.** `expr.rs:400`'s comment warns that widening
  `parse_expr` obliges `mcall::eat_int_operands`'s `Vocab::CallArg` to widen in
  lockstep *"or §9.14.6's correspondence guard goes red."* Measured: with the
  sink on, `s9_callarg_big` (**one** computed-address argument) enters class and
  is byte-exact, while `s10_callarg_two` (`g(&p->b, &p->a)`) and
  `s11_callarg_mixed` (`g(&p->b, x)`) refuse at **`call-arg-computed:eof`** and
  return `not_implemented`. So the coupled widening is what you would need to
  **gain** the multi-argument cases; it is not what stands between the promotion
  and a wrong emit. That is a **narrowing** of #364's cost estimate in the
  direction that makes it cheaper — while §4 makes the *payoff* very much
  smaller, so the ratio still points at decline.

## 8. What it would cost to take `xboxheap.cpp` anyway

For whoever revisits this. In dependency order, none of it optional:

1. **A producer slot in `StoreRun`** — a value-producing instruction placed
   *before* the run it feeds, at a distance the schedule fixes rather than the
   source. `w-pair`'s §4 probe grid refuted six candidate placement rules on this
   axis already; `work/w-frame/…/leaf_store.rs` records four *register
   allocation* rules each refuted by another cell. **This is the seam, and it is
   unresolved.**
2. **`27` in value position** — `[Load, Lit(k), Add]` through the generic
   constant materialiser, which §5.1 proves is byte-exact at 4, 32768 and 80000.
   This is the cheapest of the four and it is worth **+0** on its own.
3. **`StoreRun` ∘ `CallSeq`** — a framed call after a store run, with `this`
   homed in `r31` across it for the constructor's return value. The encoder,
   frame layout and `.pdata` word all already exist.
4. **The schedule.** Even with 1–3, instruction 0 must be `li 10,0` and not
   `stw 5,16(3)`.

`Pool.cpp` (×2) and `EncryptXTEA.cpp` (×2) carry `0x27` too, and #269 already
prices both above 4 for other reasons, so none of this converts a TU either.
