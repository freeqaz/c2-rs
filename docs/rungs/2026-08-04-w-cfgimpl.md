## 2. What it admits, and what it refuses

Named **`cond-tail-pair`**. The whole class:

```cpp
void MemFree(void *v1, void *v2, unsigned long ul) {
    if (v1 == nullptr) { XMemFree(v2, ul); return; }
    RtlFreeHeap(v1, 0, v2);
}
```

— a conditional whose **both** arms end in a tail call to a **different**
external, each marshalling formals and small literals only.

### 2.1 The class is a fold band, spelled as a syntax rule

This is the part worth reading. `docs/CFG_SHAPE.md` §3.5 measured that a
`cflow-if-1` body usually emits **no branch at all** — six of seven leaf probes
fold — and then **declined** the band-1/band-2 decision: *"every fitted rule I
could state is consistent with the eighteen rows above and none of them is
tested by them"*. §8.1 **B1** prices the ~30-cell probe that would settle it.

This rung did **not** run that probe and did **not** reproduce the cost model.
Instead it draws the class so that the model cannot be needed:

* band 2 (`bclr`) is reached "when one successor **is** the function's
  epilogue";
* band 1 (branchless select) needs **both arms to be constants**;
* a body whose both arms end in a tail call to a different external **is
  neither**, on §3.5's own definitions.

So the accepted shape sits inside band 3 by construction. `docs/CFG_SHAPE.md`
§6.2 item G asks for exactly this — *"the port must be able to say 'this
`cflow-if-1` is band 3' and refuse otherwise, rather than emitting a branch and
being wrong on 6 of 7 leaf bodies"* — and a syntactic predicate that implies the
band is a stronger answer than a fitted cost model would have been.

### 2.2 The refusals, each one a measurement

| refused | why, and where the measurement is |
|---|---|
| one arm falls through to the epilogue | fold band 2 — `bnelr cr6`, no branch, no label, no displacement. `w8_cond_tail_neg.cpp::b2`. |
| both arms call the **same** callee | board **#193** / §3.4.1 — c2 tail-merges the two `bl` sites, empties the then-block, hoists its argument above the compare and **inverts the layout**. Block order is downstream of code motion; this port models none. `w8_cond_tail_neg.cpp::merged`, and a unit test that rewrites `?MemFree`'s else-arm callee token to its then-arm's. |
| a computed argument in an arm | the arms carry `SlotArg::Formal`/`Lit` and nothing else — the vocabulary `tail_call_shape` already has. |
| a data symbol's address in an arm | WR1's `lis` is hoisted ahead of the *whole* setup; where that lands relative to a branch has no capture. |
| a **second** value needing the scratch register | the park is measured at r11 and only at r11. A second would descend to r10 on an allocator `docs/CODEGEN_W6_COMPARE.md` §6 records as **demonstrably richer than a descending counter and not characterized**. |
| a value both arms want whose home register **neither** arm overwrites | needs no park at all; each arm would simply read it. Plausible, unwitnessed, refused. |
| a branch past ±32764 | §3.3.1's expansion (invert, branch over an unconditional `b`) is measured but not built. `encode_bc` returns `None`; a truncated `BD` is a legal-looking branch to the wrong place. |
| a comparison operand type outside `int`/`unsigned`/`long`/`unsigned long`/`ptr` | the generic `is_int4_type` would admit an `enum`/`typedef`/`const int` and **cannot say whether it is signed** — which here is `2f……` against `2b……` in the emitted word. |

### 2.3 The register plan is fitted, and is therefore *verified* rather than trusted

`docs/CFG_SHAPE.md` §8.1 **B3** says the entry-block rule "needed on both paths"
**fits** `?MemFree` and `?MemAlloc` and is **tested by** neither. That is still
true, and `plan_cond_pair` says so in its doc comment. What it does about it is
the point: after applying the three placement rules it **simulates the schedule
register by register** and refuses any schedule that does not deliver every slot
its value.

So a shape the rules mis-handle comes out as a **refusal**, which is a gap,
rather than as a plausible-looking wrong branch, which is a mis-emit. That is
the only defensible way to ship a fitted placement rule, and it is why the
`cmp_reg` is taken from the plan rather than from the formal's home register —
`?mmioGetInfo` compares **r11**, because r3 is about to be overwritten.

The three rules, and their witnesses:

1. **same destination in both arms → hoist the move into the entry block.**
   `?MemAlloc`'s `mr r4,r5`: the then-arm passes `attrs`, the else-arm passes
   `(attrs>>27)&8`, both in r4.
2. **different destinations in both arms → park in r11.** `?MemFree`'s
   `mr r11,r4`: `v2` goes to r3 in one arm and r5 in the other.
3. **everything else stays in its arm.** Within every block, **descending
   destination register** — the incumbent `moves_descending` rule, unchanged,
   with literals interleaved rather than grouped.

### 2.4 One place this rung disagrees with the spec, on purpose

`docs/CFG_SHAPE.md` §6.2 item B says a **fixup list** is required "even for §4's
single-branch minimal instance", because `38`/`3A` carry no direction. That is
true of a general lowering and **false for this class**: three blocks in a fixed
order make the `bc`'s displacement `4 * (then_steps + 2)`, a function of a length
the emitter already has. No fixup list was built. The **range check** of item D
*was* built, because it is not a mechanism, it is a refusal.

The block/instruction IR §6 specifies was likewise **not** built. §6.1's argument
that `IlFunction`'s parallel-`Option` design "cannot be extended" is right about
a general CFG and is not what this class needed: `cond_pair: Option<CondTailPair>`
is one more mutually-exclusive field, and the restructure stays due for the first
shape with a *variable* block order. Building it here would have been a mechanism
with no fact behind it.

## 4. Why `xboxmem.cpp` did not convert — the probe, not the guess

Two of its four functions are still out of class, and **neither is control
flow**. Both were probed rather than estimated.

### 4.1 `?GetXAllocAttributes` — `(unsigned)(i != 0) << 30 | 0x249b0000`

```text
  3163ffff  addic  r11,r3,-1
  3d40249b  lis    r10,0x249b        <- SECOND, between the two spine words
  7d6b1910  subfe  r11,r11,r3
  516af002  rlwimi r10,r11,30,0,1
  7d435378  mr     r3,r10
  4e800020  blr
```

A 10-cell probe (`work/w-cfgimpl/p/ga.cpp`, workload flags) varying the
constant, the shift, the relation, the formal position and the operand type
says this is **four independent unmeasured facts**, not one fold:

| cell | emitted | what it separates |
|---|---|---|
| `!= 0`, `<<30`, `\| 0x249b0000` | the six words above | the reference |
| same, constant `0x11220000` | identical but `lis r10,0x1122` | the constant is a field |
| same, constant `7` | `li r10,7` replaces the `lis` | **constant materialization is a choice**, and it changes the instruction |
| same, `<<0` | `addic ; subfe ; oris r3,r11,0x249b` — **16 bytes, no `rlwimi` at all** | a different fold entirely |
| `== 0` instead of `!= 0` | `cntlzw r11,r3 ; lis r3,0x249b ; rlwimi r3,r11,25,1,1` | **a different bool spine and a different mask** |
| no `\| K` | `rlwinm` replaces `rlwimi` | |
| the value in **r4**, not r3 | `lis r3,…` and **no final `mr`** | the destination register is an allocation decision driven by operand overlap |

And the `rlwimi` mask is **not** derivable from the shift: `<<30` and `<<29`
both emit `MB=0, ME=1`. It is derived from the *constant's* free high field.
Four facts — bool spine by relation, constant materialization by value, mask by
constant, destination by operand overlap — plus the `lis`'s **schedule** (slot 1,
between the two spine words, which is w-pair's wall and `GAPS.md` §6 instance
#10). Fitting any of them from one cell is precisely what this project has paid
for before. **DECLINED**, and the grid above is the deliverable instead.

### 4.2 `?MemAlloc` — a local assignment inside an arm

Its else-arm is not two instructions of marshalling; it is a whole statement:

```text
  26 6b 0f · b9 67 0f <ulong> · 33 <int> 1b · 0a · 33 <int> 08 · 0b · 32 <ulong> 4b
     flags  =        attrs         >> 27      &        8         store
```

emitted as one `rlwinm r4,r4,5,28,28` in the else block. That needs (a) an
assignment-to-a-local statement **inside** a conditional arm, (b) the
`(x >> s) & (1<<b)` → `rlwinm rD,rS,32-s,31-b,31-b` fold, and (c) an extension
of the entry-block rule to treat "the then-arm wants formal *f* in r4" and "the
else-arm wants a *computation of* formal *f* in r4" as the same destination —
which is what makes `mr r4,r5` hoist. (c) is forced by the bytes and has exactly
**one** witness. **DECLINED.**

**And declining either one costs the whole TU**, so declining both costs
nothing more than declining one. That asymmetry is why this rung stopped here
rather than taking the cheaper of the two.

## 6. Found and not taken

Ranked by TUs, per §5.0 Trap 2.

1. **`?GetXAllocAttributes`'s four folds and `?MemAlloc`'s in-arm assignment** —
   together **1 TU** (`xboxmem.cpp`), and neither alone is worth anything. §4
   has the probe grid; the `!=0`/`==0` spine split and the constant-derived
   `rlwimi` mask are the two that need their own grids. This is
   `docs/CODEGEN_W6_COMPARE.md`'s seam, not the CFG step's.
2. **`if-2` / `if-n` as *chains* of conditional tail calls** — `docs/CFG_SHAPE.md`
   §5.2 prices `if-1`+`if-2`+`if-n` at 8 frontier TUs, and this rung took the
   `if-1` two-arm case only. **The other seven TUs are not reachable by widening
   the branch count.** All five single-blocked-function frontier TUs were
   disassembled (`osfinfo`, `undname`, `vswprnc`, `xlrcimpl`, `negate_test`) and
   every one of them is **framed**, with data-symbol `REFHI`/`REFLO` pairs, cr0
   record-form branches, stack locals, `srawi`/`mulli`/`lwzx`, or
   `__savegprlr_26`. The `cflow-*` class was never their real distance.
3. **Board #187's ~30-cell fold probe** (§8.1 B1) — still the highest-value
   follow-up in `CFG_SHAPE.md`, and this rung deliberately **did not need it**.
   Worth running before any rung tries to admit a *single*-call conditional.
4. **Loops and `switch`** — out of scope by brief and not started. §3.7c's CTR
   loops (`mtctr`/`bdnz`) are an instruction family absent from the port and from
   `docs/`; `switch` unblocks 0 frontier TUs.
5. **The frontier ranking is by blocked-function count and that is the wrong
   key** — third lane in a row to find this. `xboxmem.cpp` was joint-last at 4
   blocked and was the *cheapest* real target; `mmio.cpp` was advertised as the
   best CFG target at 3 blocked of 11 and is one of the most expensive. A
   frontier ranked by *distinct unmodeled constructs* would have said so.

## 7. What was deliberately not done

* **No fold cost model.** §3.5's band-1/band-2 decision is declined here as it
  was there; the class is drawn to make it unnecessary.
* **No block/instruction IR.** §6's restructure stays due for the first shape
  with a variable block order.
* **No fixup list.** §2.4 — it would have been a mechanism with no fact.
* **No seventh store-scheduling rule.** `scripts/gt_store_sched.sh` was not
  needed: this class's straight-line portion is a register permutation, and the
  reference emits it in the incumbent descending order.
* **No loop, no `switch`, no CTR.**
* **`Pool.cpp` was not graded on** — it is the wrong TU twice over, and
  `w8_cond_tail_neg.cpp::b2` is its band-2 shape in a fixture instead.
