### §1.1 The two grammars are the same grammar

| | |
|---|---:|
| tag-02 symbol-address elements read over 850 TUs | **1,885,700** |
| ... whose offset short form is `0x81..0xFF` — **the only byte the two readers disagree on** | **0** |
| ... whose decoded offset **value** is outside `00..7F` (negative or ≥ 128) | **0** |
| ... whose trailing `<n>` is not `04` | **0** |
| `.in` streams consumed to the last byte, strict grammar | **850 / 850** |
| `.in` records framed, incumbent vs strict | **879,377 / 879,377** |
| TUs where the two readers differ in any count | **0** |

`work/w-mark/instream.py` spells the element `02 <varU tok> <i32c addend>
<i32c width>`; `work/w-tag02/GRAMMAR.md` and
`crates/c2-il/src/func/ininit.rs::read_offset` spell it `02 <varU tok> <offset:
00..7F | 80+LE32> <n == 04>`.  `i32c` (`0x10c1f9e9`) is a *signed byte, or `0x80`
escape then LE32*, so the two can differ **only** on an offset byte in
`0x81..0xFF`.  There are none.  Not "few" — **zero of 1,885,700**.  And **no
decoded offset value is outside `00..7F` either**, so the `80`+LE32 escape that
w-tag02 built five cells to pin (`t18`–`t22`) is a shape this workload's `.in`
streams do not contain at all — which is worth knowing before anyone treats the
grid's coverage as the corpus's.

### §2.1 And the residue is green over 56 % of the stream — trap 0, one rung down

`w-tag02` §4 repaired the `.in` totality identity to `records == accepted +
residue` after it fired at 826 of 878 TUs, and published `duplicate_records`
beside it.  That identity is **correct and it is still a statement about the
population the anchor scan reaches**:

| | records |
|---|---:|
| framed by a sequential parse of the same 850 streams | **879,377** |
| **never anchored** — first element is a tag-`03` blob or a tag-`08` zero fill, so `00 01`/`00 02` never matches | **144,850** |
| **fail-closed** — a `00 02` candidate that does not frame all the way to its `07` is *"not a record"* and the scan resumes one byte on | **239,279** |

**384,129 records — 43.7 % of the stream — are in neither `records` nor the
residue.**  Every one of them is invisible to the totality control, to the
arity control and to the residue histogram at the same time.  This is
`docs/STATUS.md` trap 0 in its purest form yet: not a control that is green
because the shape is rare, but a control whose denominator is chosen by the same
predicate that decides the numerator.

**The fix is not to widen the identity, it is to publish the denominator.** An
`unanchored` counter next to `records` would have made this visible without any
grammar work at all, and it is the cheapest thing on this page (§8, item 1).

## §4 The instruments, and which of them is a transcription

Three readers, one stream, and **no reader is another's witness**:

* **INSTREAM** — `work/w-mark/instream.py`, imported, not copied.
* **STRICT** — `work/w-emitp2/strictin.py`, written from `work/w-tag02/GRAMMAR.md`
  and `ininit.rs`'s field layout, in another language, importing no field
  definition from `instream`.
* **CRATE** — `crates/c2-il/tests/in_init_probe.rs`, the shipping reader's own
  cursor, over `work/w-emitp2/probeil` (850 symlink cells; nothing is copied and
  nothing is written into the capture cache).

### §4.1 Grading the crate-shape transcription, because a model built on it is only as good as it

`strictin.parse_records_crate` reproduces `ininit.rs`'s **acceptance** on top of
the sequential framing so the two line up record for record.  It is a
transcription and it is graded as one:

| | transcript | the crate's cursor | ratio |
|---|---:|---:|---:|
| **tag-02 symbol addresses** | 1,427,984 | 1,429,596 | **0.9989** |
| elements | 2,726,484 | 2,737,801 | 0.9959 |
| records carrying a symbol address | 440,113 | 441,725 | 0.9964 |
| records | 495,248 | 518,098 | 0.9559 |
| residue records | 13,087 | 24,651 | 0.5309 |

**The disagreement is uniform and one-directional**: the transcript is short by
**exactly 2 symbol addresses on 806 of 850 TUs** and equal on the other 44
(`Σ|Δ| = 1,612 = 806 × 2`, max per-TU |Δ| = 2).  The cause is the crate's
**resync** — after a refusal it resumes scanning and can re-anchor inside the
tail of the record it just refused, which a sequential parser cannot do; that is
also why the *record* and *residue* columns diverge much further than the
symbol-address column.

So §1.4's `−19 / −213` are computed on a reader that is **pessimistic by ≤ 2
symbol addresses per TU** and they are stated as such.  The record and residue
counts of the transcript are **not** load-bearing anywhere and are printed only
to show where it stops matching.

**No spec for spending it is written**, because the brief conditions writing one
on the measured model reaching a precision worth it, and the measured model's
precision is **unchanged to five decimal places**.

## §8 Found and not taken — ranked, sized, and this is the next lane's brief

   the scan skips a byte without framing a record. Zero grammar work; it makes

2. **Teach `read_elements` element tag `08` (zero fill).** **315,553 symbol
   addresses on 812 TUs**, the single largest cause. Unmeasured by w-tag02's
   grid; needs cells that put a zero-fill element in the same record as a
   pointer.
3. **Teach it scalar types `03` and `04` at width 4.** 132,488 + 9,675 symbol
   addresses. **Both types are unmeasured** — no cell in the 24 produced either,
   so this is a grammar rung, not a widening: somebody has to find the C++ that
   mints them and grade the bytes.
4. **Then re-measure the model, and THEN consider the quarantine gate** (§5).
   The widened reader's model has a new node universe and therefore a real
   held-out question; today's does not.
5. **The 13 TUs one symbol from exact and the 60 within three** (§6). Named in
   `work/w-emitp2/scan2.jsonl`; not characterised further here.
6. **The 510 outside-`U` names on 162 TUs** — w-emitp §3.2's channel, still the
   sole blocker on 43 TUs, still unmodelled by anything.
7. **The crate's resync**, which is why §4.1's transcript and the shipping
   reader disagree on record counts. Counted, not decoded.
