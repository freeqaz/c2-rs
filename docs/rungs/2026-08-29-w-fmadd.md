## 2. The lane kind, stated rather than assumed — and it is not the one it was dispatched as

`w-encarms` was `Kind: construct` with `Census: +0` and a **required-zero byte
delta**, because its two adopted arms were folds: `calls.rs` and `frame.rs`
were *already emitting* `bl`, `mfspr` and `stwux` from baked literals, so the
table row changed where the word came from and not what it was.

**None of that is available here, and the difference is the substance of this
lane.** Before it, `mop::plan` had no arm for form 24 and `mop::op` had no
`fmadd`-family constant, so the port could not compose the word **at all** —
`encode_op` would have returned `NotImplemented` for every one of the arm's 18
opcodes, and no site asked. The lowering refused the shape class outright. So:

* `Fixtures:` is not `none` — a positive fixture is the only way the byte judge
  can see the emit;
* `Census:` is not `+0` — the IL parser's `has_mul && has_addsub` gate is gone;
* the byte delta is **not zero and must not be**, because a zero delta would
  mean nothing was emitted.

`docs/rungs/README.md`'s construct-rung definition is *"re-expressing already
byte-exact classes"*, and this class was not byte-exact — it was refused. The
honest kind is **fixture-claim**, and the `Fail axis:` field is carried anyway
rather than dropped on the technicality that `rung_registry.rs` only enforces
it for construct rungs.

So the right instruction to a successor lane is not *"the arm is reachable"*
but **"check both halves; the brief may have checked neither."**

## 3. The read — arm `0x10bfa49a`

`work/w-fmadd/dumparm.py`, whose PE section mapping is **parsed, not
hard-coded**, and whose `--self-test` re-derives five anchors this repo already
published from other tools before any byte is quoted:

```
  T1 ICE arm 0x10bfa81d = bad9030000 (want bad9030000)
  T2 arm 0x10bf9f91 = 833d78e9c21000 (want 833d78e9c21000)
  T3 form[0x0077] = 24 (want 24)
  T4 base[0x0077] = fc00003a (want fc00003a)
  T5 armtable[form 24] = 0x10bfa49a (want 0x10bfa49a)
SELF-TEST PASS
```

T5 is the one worth naming: it reads `0x10bfae2d + 4*23` and **independently
fixes form 24 → this arm** from the jump table, rather than trusting
`ENCODE_ARMS.txt`'s attribution.

### 3.1 The arm, and it is form 23 plus one register

```
10bfa49a  eax = [[eax+0x1c]+0x28]        ; reg(S)
10bfa4a3  esi = [[ecx+0x1c]+0x28]        ; reg(D1)   -- ecx arrives as D1
10bfa4a6  edx = [[esi+0x1c]+0x28]        ; reg(D0)
10bfa4a9  ecx = [[[edi+0x28]]]           ; D2, RE-WALKED from the tuple:
                                         ;   [edi+0x28] is D0, [D0] is D1,
                                         ;   [D1] is D2 -- a linked list
10bfa4b6  eax = eax<<5 | edx             ; reg(S)<<5  | reg(D0)
10bfa4bb  eax = eax<<5 | [ecx+0x28]      ;   ...  <<5 | reg(D2)
10bfa4c1  eax = eax<<5 | esi             ;   ...  <<5 | reg(D1)
10bfa4c6  jmp 0x10bfa492                 ; <- FORM 23's OWN TAIL:
                                         ;    shl eax,6 ; jmp 0x10bfae19
```

`= reg(S)<<21 | reg(D0)<<16 | reg(D2)<<11 | reg(D1)<<6`.

**The arm literally jumps into `fmul`'s last two instructions**, which is the
structural confirmation that form 24 is form 23 with one more register — and
it is why the assignment is believable rather than surprising: `mop.rs:888`
already puts form 23's `D1` at bit 6.

**PREREG P3 is a HIT**, at ~65 % registered confidence: c2's slots follow the
mnemonic `fmadd FRT,FRA,FRC,FRB`, so `D1` → `C` (bit 6) and `D2` → `B`
(bit 11), the non-monotone assignment. Board **#3791**. Full transcript:
`work/w-fmadd/arm_form24.txt`.

### 3.2 Confirmed against c2's own listing, at four assignments

The `/FAsc` seam (`c2rs listing`) makes c2 narrate its own output by mnemonic,
which is a *different* instrument from the arm and answers a question the arm
cannot: **which source operand becomes which slot.** From
`work/w-fmadd/probe/fma.cod`:

| source | c2's own line | our composition |
|---|---|---|
| `a*b + c` | `ec2118ba  fmadds fr1,fr1,fr2,fr3` | `base \| 1<<21 \| 1<<16 \| 3<<11 \| 2<<6` ✓ |
| `b*c + a` | `ec2208fa  fmadds fr1,fr2,fr3,fr1` | ✓ |
| `l*m + k` (13 params) | `ec2c5b7a  fmadds fr1,fr12,fr13,fr11` | ✓ — all four fields distinct and > 10 |
| `double a*b + c` | `fc2118ba  fmadd fr1,fr1,fr2,fr3` | ✓ primary 63 |

### 3.3 One thing c2 does that the port does not, and it is unreachable

**c2's arm masks nothing.** There is no `and eax,0x1f` anywhere in it, unlike
the VMX arm `0x10bf9f91` which masks all three of its fields; this port masks
each field to 5 bits in `mop::compose`. Since all four of form 24's fields are
FPR numbers and the file is `f0..f31`, the two rules are **the same function on
every input**, and no obj can separate them. Stated as a domain fact rather
than left as a coincidence, and rendered by the `float.contraction` surface.

## 4. The adoption

Six rows, one field plan, three encoder pairs, and the lowering.

| c2 row | opcode | base | form | arm |
|---|---|---|---:|---|
| `fmadd` | `0x0077` | `fc00003a` | 24 | `0x10bfa49a` |
| `fmadds` | `0x0079` | `ec00003a` | 24 | " |
| `fmsub` | `0x007d` | `fc000038` | 24 | " |
| `fmsubs` | `0x007f` | `ec000038` | 24 | " |
| `fnmsub` | `0x008d` | `fc00003c` | 24 | " |
| `fnmsubs` | `0x008f` | `ec00003c` | 24 | " |

`OPCODE_ROWS` 88 → **94**; `plan` answers 37 → **38** forms; `[encode] ported`
**29/79 → 30/79**, and `c2rs subsys`'s own recount reproduces it
(`VERIFY: PASS`). Strict 26 → **27** and loose 30 → **31**, both re-derived
rather than incremented; all three readings move together because

**Twelve of the arm's eighteen opcodes are deliberately NOT transcribed.**
`fnmadd`/`fnmadds` and every `.` record variant have no row, because the IL's
unary-negate node is refused by `leaf_float`'s parser — a row nothing can reach
would move a published numerator by construction, which is `#3505`'s shape and
what PREREG §4 said would be out of scope. `DISCLOSURE.md` `W-FMADD-1` names
the arm address and was filed in the same commit as the code.

### 4.1 The lowering — a deferred product, and its PARENT decides

The structural change is one sentence: **a `*` no longer emits anything when it
is read.** It pushes a pending `(A, C)` pair, and the parent node decides
whether that pair becomes an `fmul` or the `A`/`C` half of a fused
instruction.

| the parent | the instruction | why the side matters |
|---|---|---|
| `+`, product on either side | `fmadd` — `A*C + B` | identical bytes both ways; the addend is `B` |
| `-`, product on the **left** | `fmsub` — `A*C − B` | |
| `-`, product on the **right** | **`fnmsub`** — `−(A*C − B)` = `B − A*C` | one opcode apart, **opposite sign**; using `fmsub` here negates the result |
| a `*` or a `/` | the pending product is materialised into an `fmul` first | |

`fp_node_plan` is **one function with three consumers** —
`fp_contract_instructions` runs it to find out how many instructions the body
emits (the last of which targets `f1`), the evaluator runs it to emit them, and
`try_parse_float_leaf` runs it to **accept**. Two implementations that agree
are invisible for exactly as long as they agree (**#3637**), so
`the_counter_and_the_emitter_agree` drives the first two over every op stream
of up to four leaves and requires the counts to match.

### 4.1.1 Where the rule lives, and a test chose the answer

**The rule is in `c2-il`, not beside the emitter, and that was not the first
draft.** This lane wrote the whole of it in
`c2_core::codegen::leaf::float`, and the workspace suite went red in exactly
the words `docs/GAPS.md` §6 uses:

```
A NEW census/gate refusal family appeared over the generated corpus
(fn_level_linking=false):
  not implemented: an FP `+` chain whose product is not its first term …
The census counts these functions in class and PortC2 refuses them, so the
published coverage numerator over-claims by that many. It is NOT a mis-emit —
no bytes were produced — but acceptance belongs in the IL parser.
```

**Two functions over 19,549 generated cases**, and the invariant is right: a
refusal that lives only in codegen is a coverage over-claim, not a gap. The
obvious repair — restate the predicate in the parser — is the
two-implementations hazard **#3637** in its purest form, on a rule whose two
copies would be a `match` on the same enum. So the rule **moved** to
`c2_il::func::body::chain` instead, which both sides call. `c2-core` depends on
`c2-il`, so that direction is the only one that admits a single
implementation.

### 4.2 What was refused, and each has a reason that is not "we ran out of time"

* **`a + b + c*d` and its family** — c2 *reassociates*; §6.
* **A pooled FP constant inside a contracted expression** (`a*b + 1.0f`). The
  one-constant lowering's whole warrant is six bodies in which the `addis`/`lfs`
  pair sits immediately before its use, and **none of them is a fused one**. No
  witness for the scheduling; refuse.
* **A product on both sides of a node that cannot contract** (`(a*b)*(c*d)`).
  Needs source parentheses, which the `0x59` marker already rejects, so there is
  no witness at all.
* **Everything the pre-existing gates already refused stays refused**: descending
  leaves (`b*a + c` reaches c2 as the *canonicalized* `fmadds f1,f1,f2,f3` and
  this port does not model FP canonicalization), the `0x59` parenthesis marker,
  repeated leaves, `n_spill`.

### 5.1 C-2a is the finding, and it is `#3723` in its purest form

`w-encarms`'s **C-C2** perturbed form 54's SPR high half and moved **zero byte
tests**, because every SPR the port names is `< 32`. This lane has the same
shape twice, and the second is sharper than anything the board has recorded:

* **C-2b** narrows form 24's `B` field to 4 bits. Zero byte tests move, because
  every FPR this port can name is `f0..f13` (parameters `f1..f13`, scratch pool
  `f0` and `f13..f1`) and the mutation is observable only at `f ≥ 16`. **A
  wrong field placement that no fixture, in any corpus this project could
  build, can reach.**
* **C-2a** widens the field 5 → 6 bits. That is a **no-op on the entire
  representable domain** — `x & 0x3f == x & 0x1f` for every `x ≤ 31` — so no
  obj could *ever* move, not merely no obj we have. The registry catches it
  anyway, because it renders the field **spelling** (`D2<<11/5`) as well as the
  words. Over-sensitive by design, and this is the case that shows why that is
  the right design.

Board **#3793**.

Recorded because both cost real time and both are the *harness* failing, not

1. **C-2 was originally registered RED on byte tests and came back GREEN.** The

## 6. What this lane emitted wrongly, and what caught it

**`float f(float a,float b,float c,float d){ return a + b + c*d; }` was a live
wrong emit in this lane's first working draft.** The new sweep fragment
`scripts/sweep.d/36-fp-contract.py` caught it on its **first run**:

```
MISMATCH  36-fp-contract-0003.cpp  |  float f(...) { return a + b + c * d; }
MISMATCH  36-fp-contract-0044.cpp  |  double f(...) { return a + b + c * d; }
checked=4597 mismatches=2 graded=4580 ungraded=17 unknown=0
```

c2 does not lower the source tree `((a+b) + c*d)`. It **reassociates the `+`
chain** so the product is fused with the *first* term:

```
  a + b + c*d      fmadds f0,f3,f4,f1   ; c*d + a
                   fadds  f1,f0,f2      ;      + b
```

Bounded to exactly *"an `Add` fusing against an addend produced by an `Add`"*
by eight measured pairs against real `c2.dll`
(`work/w-fmadd/shapes_in.txt`, `shapes_in2.txt`):

| shape | fusing node | addend from | c2 |
|---|---|---|---|
| `a + b + c*d`, `a - b + c + d*e`, `a*b + c + d*e`, `a + b + c*d*e`, `a + b + c*d + e`, `a*b + c + d + e*g` | `Add` | `Add` | **reassociates** → refused |
| `a - b + c*d`, `a - b - c + d*e` | `Add` | `Sub` | does not → in class |
| `a + b - c*d`, `a + b + c - d*e` | `Sub` | `Add` | does not → in class |
| `a*b + c*d + e` | `Add` | `Mul` | does not → in class |

**Priced two-sided (`#1042`) before it shipped**: every shape the fence costs
was measured as a **MISMATCH** without it, so the refusal replaces a wrong
emit, not a green one — which is the direction `docs/PROGRESS_METRIC.md`'s
scoring rule requires. Board **#3792**.

**The hand-written probe set did not contain this case and would not have.**
Every shape written by hand in this lane put the product first, because that is
how one thinks about `fmadd`. Enumeration has no such bias — `docs/GAPS.md`'s
standing lesson, earned again on a class described as understood.

## 6.5 The gate FAILED once, on a wrong emit this lane did not write — `FpTempPolicy`

**`scripts/mode_cross.sh` returned `GATE: FAIL — the port emitted wrong bytes
on 108 case(s)`**, all 108 in this lane's own new fragment, over 17 distinct
cases at six `/O1` variants. The `expr-sweep` lane was green over the same
19,638 cases at its own profile, so it is a **mode** divergence.

**The first thing established was whether this lane caused it. It did not.**
`crates/` was checked out at master `12d3c0558`, rebuilt, and the 17 cases
re-graded at `/O1`: **17 of 17 mismatch at master too**
(`work/w-fmadd/repro/`). And none of them is a contraction case — they are
four-leaf `+`/`-` chains and one four-leaf `*` chain, with no `*` under a `+`
anywhere.

### 6.5.1 The defect

```
float f(float a,float b,float c,float d){ return a+b+c+d; }

/Ox   fadds f0,f1,f2 ; fadds f13,f0,f3 ; fadds f1,f13,f4
/O1   fadds f0,f1,f2 ; fadds f0,f0,f3  ; fadds f1,f0,f4
```

At `/O1` the temporary is **recycled by the very instruction that kills it**;
at `/Ox` the pool cursor never revisits. Same pool, same skip-if-live rule, one
bit of difference. Measured over **six shapes and three depths** — four-, five-
and six-leaf `+` chains, a four-leaf `*` chain, a four-leaf `-` chain and a
contracted body — in `work/w-fmadd/repro/deep_O1.cod` / `deep_Ox.cod`, so it is
not the two-point fit `#1767` bans.

### 6.5.2 Why nothing caught it, and it is `#3723` a third time

**The two policies AGREE at depth 1, and every FP body in this project's corpus
was depth 1.** Three leaves need exactly one intermediate, and one intermediate
cannot separate `f0, f13, f12, …` from `f0, f0, f0, …`. `30-fp-leaves.py`
stops at three leaves; the hand-written W13 fixtures are two- and three-leaf.
So the byte judge was *structurally* blind to the choice — not "we had not got
round to it", but "no case in the corpus could distinguish the two answers".

**And the port had the wrong one on the mode the goal is measured in.**
`work/dc3-workload/flags.txt` is `/O1 /Oi /EHsc`.

### 6.5.3 What shipped

`FpTempPolicy { Carried, FirstFree }`, defaulted by `OptMode` — a named,
settable parameter rather than an `if mode ==` at the use site, per
`docs/GOAL_DECISION_2026-08-21.md` § AMENDED. Two supporting changes:

* **Sources retire BEFORE the destination is chosen.** That is what lets
  `FirstFree` take the register the instruction just freed; under `Carried` the
  order provably cannot matter, because the cursor advances regardless.
* **`float.contraction` gains block 4**, rendering both policies' register
  sequences to depth 8 (nine leaves — nothing generates that), with **depth 1
  rendered identically for both**, so the blindness itself is committed text.
* The fixture gains three two-temporary bodies (`f_chain4`, `f_mad4`,
  `d_chain4`) and `the_fp_scratch_policy_follows_the_optimization_mode` pins
  both modes' words against c2's own listing — including the depth-1 equality,
  asserted so a future change cannot break the agreement silently.

**18 of 18 cross cases match at `/O1` and at `/Ox`.**

## 9. What this lane refuted

1. **The brief's own reason for dispatching it.** §2.1, board **#3790**. The
   arm was not reachable; both halves of the encoder were missing. The
   conclusion survived; the premise did not.
2. **`mop::plan`'s own doc, which went stale again within 48 hours of `#3643`
   correcting it.** At master `12d3c0558` the line read *"the port's 88 opcodes
   reach **34** of the **104** … the **27** arms below cover **35** form
   numbers"*; the tree gave **88 / 36 / 29 / 37**. `w-encarms` added forms 7 and
   54 on 2026-08-28 and left the sentence alone — and **its own rung contradicts
   it**, reporting *"`plan` answers 35 → 37 forms"*. **The only number that
   stayed true is the one `#3683` BOUND with a `COUNT[…]` recipe.** Board
   **#3794**, and the three unbound neighbours are still unbindable because
   `run_recipe` has no distinct-value counter.
3. **My own P6 and P8.** §8. The two functions predicted to stay refused are not
   the two that do, and the mutation family the fail axis named is not the one
   the byte judge is blind to.
4. **"A control that fails is the harness working" is only half of it** — a
   control that *passes* when you registered RED is the harness working too, and
   C-2 was that. §5.2.
5. **The port's FP scratch-register policy, at master and on the workload's own
   mode.** §6.5. Seventeen cases, 108 cross cells, a live wrong emit that
   predates this lane by an unknown number of waves and that no corpus in this
   project could have exposed, because every FP body it contained needed one
   temporary and one temporary cannot separate the two answers.
6. **My own first placement of the contraction rule.** Putting the refusal in
   codegen alone over-claimed the published coverage numerator by 2 over 19,549
   generated bodies, and `census_gate.rs` said so in `GAPS.md` §6's own words.
   §4.1.1 — the rule lives in `c2-il` now, with one implementation and three
   consumers.

## 10. Found and not taken

Ranked, with the frame axis applied.

1. **The `+`-chain reassociation itself — the fence's whole cost, and it is a
   general rule, not an FP one.** c2 sinks the fused instruction to the first
   term of a `+` chain; `w13_freassoc.cpp` already fences the *non*-contracted
   half of the same family, and the integer side has `canonicalize_chain`.
   Six measured shapes are in `shapes_in2.txt` with c2's words beside them. The
   read that would settle it is c2's expression-tree canonicaliser, not another
   probe grid — **read-before-probe applies and this lane did not price it.**
2. **`fnmadd`/`fnmadds` and the twelve `.` record variants of this same arm.**
   Blocked one layer up: the IL's unary-negate node (`0x08`) is refused by
   `leaf_float`'s op loop, so `-(a*b+c)` never reaches codegen — and c2 emits
   `ec2118be fnmadds` for it (`work/w-fmadd/probe/fma2.cod`, `q_neg_fma`). The
   arm is already ported; this is a **parser** rung, and it is cheap.
3. **FP commutative canonicalization**, which now blocks strictly more than it
   did. `b*a + c` reaches c2 as the canonicalized `fmadds f1,f1,f2,f3` — i.e.
   the contraction and the canonicalization compose, and every descending-leaf
   shape in this class is refused for the canonicalization's sake alone.
   `w13_fneg.cpp` §1 has had this open since W13.
4. **A `values={…}` renderer for `Surface`**, which `w-encarms` §5.3 reported
   as owed and this lane's `float.contraction` needs for the same reason:
   `mop.encode_form`'s summary line prints 47 comma-separated "values" and is a
   faithful rendering of nothing. The per-row diff is unaffected. Still owned by
   whoever holds `surface.rs` next.
5. **The 7,995 workload words are `fmadds` and nothing else** —
   `work/w-fmadd/armhist_rerun.out` attributes **5,927** uniquely to `fmadds`
   (`0x0079`) and the rest ambiguously within form 24. So five of the six
   adopted rows are unexercised by the graded workload, which is a coverage
   fact about the corpus and not about the read.
