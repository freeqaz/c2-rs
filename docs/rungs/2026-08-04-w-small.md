## 2. Lead 1 — `Bindings::per_record`'s `!=` does NOT relax to `>`

### 2.1 What the relaxation admits, established before running anything

`crates/c2-il/src/func/bind.rs:446` refuses unless the `.gl` framed
defined-name records are exactly the `.ex` split points, in order and 1:1.
Relaxing `!=` to `>` admits `bound.len() < segs.len()` **with the records'
offsets a prefix match** on the split points — a missing *leading* record still
refuses, because then `bound[0].off == starts[1]`.

The downstream consequence is **not** the one w-shapes hypothesised. The emit
loop at `bundle.rs:1176` is `names.iter().take(n).zip(&segs)`, bounded by the
*name* count, so a short `names` does not misname a body — it makes the port
**drop the trailing segments**.

### 2.2 The +8 reproduces, and it has a real rule behind it

Both halves of w-shapes' measurement reproduce on this tip, measured in **both**
directions with the same instrument (`work/w-small/verdicts.sh`, per-case
verdicts over the fragment's own 210 generated cases):

| `65-linkage-comdat` | `Port=Match` | `NotImplemented` |
|---|---:|---:|
| master | **37** | 173 |
| under `bound.len() > segs.len()` | **45** | 165 |

The eight that flip (`work/w-small/l65_flipped.txt`) are **one shape**: an
external-linkage function first, then unreferenced internal-linkage or `inline`
ones — `static`, `inline`, `static inline`, `__forceinline`,
`__declspec(noinline) static`, and runs of one, two and three of them. c2 drops
those, and **their symbols are absent from `.gl` entirely** — case 0012's `.gl`
carries exactly two runs, `?f@@YAHH@Z` and `__C1_11886`, and no `?u@@YAHH@Z`. So
`unclaimed` is empty and the truncated name list drops exactly the segments c2
dropped. The gain is real and it is not a coincidence.

### 2.3 It is still wrong, and here is the case

"No record for this segment" has a **second** cause the generated corpus never
writes: a record `codec::gl_offset_framed` cannot **see**. That framing pins the
record's preceding `80 <LE32>` field into `0x1000..=0x10FF` — the field is the
signature's CodeView type index — and a TU with enough distinct types walks a
later record out of the window while the earlier ones stay inside it.

Two guards catch most of that, and this lane checked both rather than assuming:

* `gl_defined_names` has **five** total-refusal paths (name > 32 bytes away or
  absent, name not `looks_mangled`, run ending at `26`, `dllexport` linkage,
  `26`-introduced defined name). All five make `bound` **empty**, and
  `PortC2::build` then refuses because `IlBundle::shell_only_tu` asks
  `is_empty_module(.ex)`, which a TU with code fails. **The prereg's first
  candidate, a bare `extern "C"` TU, dies here** — measured `NotImplemented`
  under the relaxation, not `Mismatch`.
* A **mangled** name no record claimed lands in `unclaimed`, which
  `functions()` refuses.

An `extern "C"` name contains no `@@`, so `looks_mangled` is false and it never
reaches `unclaimed`. That is the one shape that slips both guards, and combining
it with an unseeable record is the counterexample:

```cpp
// work/w-small/probe/l1_counterexample.cpp, /Ox /GS- /c
int f(int a){return a+1;}
int h(int a,int b){return a+b;}
struct T0{int x;}; static int w0(T0* p){return p->x+0;}   // × 63
extern "C" int g(char* p){return (int)*p + 7;}
```

The three records' type indices are **`0x10FD`, `0x10FF`, `0x1101`** — the first
two framed, the third not.

| | verdict |
|---|---|
| master | `Port=NotImplemented` |
| under `bound.len() > segs.len()` | **`Port=Mismatch @ offset 8`** |

`offset 8` is `PointerToSymbolTable`. The reference obj carries **three**
functions — `?f@@YAHH@Z`, `?h@@YAHHH@Z` and, as symbol 15, `g` in `.text` — and
the port emits two. It drops a function c2 emitted, with external linkage.

**The breaker is specific, not blanket.** The burner count is a *boundary*: 62
burners (all three records framed) and 64 (none framed) both still **refuse**
under the relaxation; only 63 mis-emits. That is the counterfactual standard
w-shapes set, applied to the lead w-shapes routed.

**DECLINED.** Decline clause **D1** fired on the first reproduced mismatch. What
ships is the refusal, unchanged, plus the test that was missing: the `!=` had
coverage only in the `>` direction (`segs[..1]` against two records) and none at
all in the `<` direction the relaxation opens. That test fails under the
one-character mutation and is **the only one of 408 that does**.

## 3. Lead 2 — the short-circuit `&&` guard, shipped

### 3.1 The IL says the shape plainly

`if (a != 0 && b != 0) return 5;` is byte-for-byte the single-guard IL with 15
bytes inserted:

```text
  b9 e7 09 86 41 74 33 86 41 74 00 20  38 eb 09     test a, brFALSE -> eb
  b9 e8 09 86 41 74 33 86 41 74 00 20  38 eb 09     test b, brFALSE -> eb  (SAME)
  53 33 86 41 74 05 41 …                            the ONE arm
  29 eb 09                                          eb defined once, after it
```

Two separate `if`s are the other production — two labels, two arms — and they
already parsed. So the decode is a bounded inner loop that requires the label to
be **identical**, and the emit is one more `cmp ; bc` at the same target with the
same sense. At `/Ox`: `2f030000 419a0020 2f040000 419a0018`, both forward, the
target's predecessor count **2**.

This is the multi-reference case `codegen/labels.rs` was built for and **the
first shape in the port that actually uses it**. `coff::plan_labels` is
untouched: w-label measured `ho-and`/`ho-or` at `stride 5 / extra 0`, so the
counter charges **+0**, and every reference is forward, so `labels.rs`
invariant 4 (AA-a's backward refusal) never fires.

### 3.2 The wrong emit this lane made, and how it was caught

**The void arm is a different block plan, and assuming it was not produced 12
live `Port=Mismatch` cells** on this lane's own grid — every void cell in it and
no other. The oracle caught it on the first grid run, which is the system
working; it was never on master and never in a commit.

```text
  void P(int a,int b){ if (a!=0 && b!=0) return; v0(); v1(); }   /Ox, 52 B
    2f030000 cmpwi cr6,r3,0
    419a000c bf 26 -> 0x001c    the SEQUENCE, negated sense
    2f040000 cmpwi cr6,r4,0
    409a000c bt 26 -> 0x0024    the EPILOGUE, the relation itself
    001c     bl ?v0 ; bl ?v1
    0024     epilogue
```

Two targets and two senses: every conjunct **but the last** steps to the
sequence start carrying the negation, and only the last carries the empty-arm
inversion. The sequence start is a **third label** no production here mints, and
its counter cost is unmeasured — which w-label's AA-b/AA-c say cannot be
recovered from the emitted obj or from the `.gl` seed. **Refused**, in the IL
parser and backstopped in `call_seq_text`, with the disassembly at both sites.
Emitting the value form's uniform loop there computes `||` where the source says
`&&`.

**This narrows w-label's own reading.** `ho-and` was an `int gp(int)` body, so
*"two branches naming one two-predecessor interior target"* is a fact about the
**value** arm. The void arm does not have it. A lane that had taken w-label's
sentence as covering both would have shipped exactly the emit that mismatched.

`||` is refused too, and for its own reason rather than by omission: its first
branch names the **arm**, not the skip label, and it moves the arm block to the
end, after the fall-through path's epilogue.

## 6. What grades this, and what does not — said before it can read as coverage

**No fixture is added.** `fixtures/cpp/` is another lane's seam, and
`scripts/mode_lane.sh` globs that directory, so **the `&&` widening has no
standing instrument at gate time**. The 12-lane grid in §3.3 is a **one-time
measurement**, not a watch. This is F-c's situation and it is worse than
w-label's, because there the ungraded code was a *refusal* and here it is an
**emitter**. A fixture is proposed as a lettered row below and should be the
next thing anyone does with this rung.

`scripts/sweep.d/95-control-flow.py:40` does carry `'a && b'` and `'a || b'` in
its `CONDS` list, so the generated sweep has *some* coverage of the axis. That
is stated as what it is and not leaned on: the fragment's own line 62 substitutes
`i < a` for both in one of its templates.

**The coverage sweep instrument cannot see `crates/c2-il` at any
`C2RS_SWEEP_KEEP` value** (w-label §5) — it reads `c2-core` only. Lead 1 lands
**entirely** in `c2-il`, and Lead 2 lands in both. So any coverage figure quoted
here is about `c2-core` alone, and **Lead 1 has no coverage figure at all**. The
*grading* sweep, `scripts/expr_sweep.sh`, is a different instrument with a
similar name and does run the whole port end to end, so it does grade `c2-il`

## 9. Found and deliberately not taken, priced

1. **A fixture for the `&&` guard — the single highest-value follow-up, and the
   only thing this rung is missing.** One file in `fixtures/cpp/` puts the shape
   under all 12 gate lanes on every future run. The 26 positive and 25 negative
   cells are already written and named in `work/w-small/gen_grid.py`; the fixture
   is a transcription, not a measurement. Out of seam here, ~0 risk there.
2. **`||` is 3 independent refusals, and two of them are already understood.**
   The IL's other branch-sense byte (`39` against `38`), and a block layout that
   puts the arm **after** the fall-through path's epilogue. The third is the
   counter cost of that layout, which is unmeasured and — per AA-b/AA-c — cannot
   be read off the obj or the seed. Priced so the next lane starts with the
   number.
3. **The void `&&` needs one measurement, not a model.** Its block plan is fully
   determined by §3.2's disassembly; what is missing is only what the
   compiler-label counter charges for the third label. `work/w-label/cflabels.py`
   is the instrument that would answer it, and it takes a probe list, not new
   code.
4. **`gl_offset_framed`'s window is a latent refusal on ordinary TUs, and
   nobody has counted it.** The field is a CodeView type index and it leaves
   `0x1000..=0x10FF` after roughly 64 distinct types — measured here, and the
   `src/App.cpp` figures in `bind.rs` (38 framed of 9,033 bodies) are the same
   effect at scale. Every such TU refuses today, so this is a **gap and not a
   defect**, but it is very likely a large share of `vocab-gap 863` and it is
   cheap to measure: count, over the workload's captured `.gl`s, how many TUs
   have at least one framed and at least one unframed record. Not attempted here
   — it needs the census tooling, which is another lane's seam.
5. **`pos_same` matched** — `if (a != 0 && a != 3)`, the same formal compared
   twice in one guard. Recorded because it means the conjuncts are independent
   compares with no CR-reuse optimization, which a future comparison rung might
   otherwise assume it has to model.
