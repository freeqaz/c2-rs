## 4. THE BOUNDARY, PAID

`crates/c2-il/src/func/body/shapes/step5.rs`. `CFG_SHAPE.md` §6.3's 2026-08-13
amendment, adopted by the user, says the emission gate is a **decidable
pre-emission predicate** and that an enumerated list of named functions is one
*implementation* of that rule and not the rule. `codegen/fold.rs`'s
`FoldShape::admit` is the reference form on the emitter side; this is the
reader-side counterpart.

### 4.1 The token→position map, which is a product of the first pass and was being discarded

§14.2 step 5: *"build a token → position map in a first pass over the body, since
`3A` carries no direction."* **The first pass already existed** — it is
`control_flow::scan_full`, and there is no cheaper one, because finding a `29` at
all requires every field width before it and a byte scan for `0x29` hits operand
payload. What was missing is that only `CfShape` survived it: `shape_of`
re-derived the single question it needed by a nested search it did not keep.

`LabelTable` keeps it, and it answers three questions nothing in this tree could
ask:

| question | what it catches | today |
|---|---|---|
| `unresolved()` | a `38`/`39`/`3A` names a token **no `29` defines** — the position is not late, it is *unknown* | a body `CfShape` calls `Forward` |
| `duplicate_defs()` | two `29`s carry one token: the map is **not a function**, so `position_of` has no referent | — |
| `dead_defs()` | a `29` nothing branches to — **the control**, which must be allowed to be non-zero | `il_stmt_early_return.cpp` has one |

`unresolved` is the one that earns the map. Retarget `il_stmt_if_else`'s `38` to
a token nothing defines and the shape is **unchanged** — one conditional, no
backward reference — while the CFG has stopped being readable. Before the map
that body was indistinguishable from the diamond. The test is
`a_dangling_branch_target_refuses_while_the_shape_still_reads_forward`.

### 4.2 The clauses, and which orderings are load-bearing

```
1  not decoded                -> Undecoded
2  shape == Switch            -> Switch
3  duplicate_defs() > 0       -> AmbiguousLabel
4  unresolved()   > 0         -> UnresolvedTarget
5  back_edges()   > 0         -> BackEdge          <- §14.2 step 5's own clause
6  residue != Modeled         -> UnmodeledOperand
7                                Admit(shape)
```

**Three of the five orderings are load-bearing and the module says which**, since
stating that is the difference between a rule and a ritual:

* **2 before 3–5.** `LabelTable` records `29`/`38`/`39`/`3A` and nothing else,
  while `3B`/`3C`/`3D` carry label tokens of their own (§11). On a `switch` body
  the map is incomplete **by construction**, so clauses 3–5 read off it would be
  answers about a different body. The test asserts the partiality directly: the
  synthetic switch's `3D` target is genuinely absent from the table.
* **3 before 4 and 5.** Both call `position_of`, which returns *the first*
  definition. With two, "the position of `tok`" has no referent.
* **4 before 5.** `back_edges` treats an unknown position as *not backward* —
  the permissive reading — which is safe only because a body with an unknown
  position has already been refused. Swapped, an undefined target passes as a
  forward DAG. Mutant **M8** does exactly that swap and is red on a body that is
  both.
* **5 before 6 is NOT load-bearing**, and was registered as a green mutant in
  advance. Neither clause reads anything the other computes.

### 4.3 The back-edge clause is kept even though fence A was lifted, and why

`LabelMap`'s fixup pass exists with nine production clients, and **#3151** lifted
fence A because its enforcing line never matched its own sentence. So §14.2's
*"and the port's codegen has no fixup pass"* is no longer universally true, and a
lane refusing every back edge on the strength of the original text would be
enforcing a fence that was lifted.

**The clause is kept anyway.** `LabelMap::admitting_back_edges` takes a
**`ChargedClass`** — a closed enum whose every variant is graded against the
label-counter gate — so what exists is not *"back edges are fine now"*, it is
*"a back edge is admissible for a class that has been charged"*. A reader-side
predicate admitting a back edge for an **unnamed** class would hand codegen a
body with no charge behind it, which is the wrong-`$M` case invariant 4 was built
for. The refusal is therefore **parameterless on purpose**: when a charged CFG
class exists, this predicate takes the class as a parameter exactly as
`FoldShape::admit` takes its band, and not before.

### 4.5 What the module does NOT do, and the measurement behind that decision

**It admits nothing into `BodyShape` and moves no byte. Nothing calls it from the
accepting parser.** That is measured, not an oversight.

An accept built on it would be a **membership check standing in for a model**.
`CfResidue::Modeled` says every operand token is *inside the vocabulary the
port's emitters consume*; it does not say an expression tree was built. Moving
`fnbyte-refused-parse` on that basis would move the phase's own numerator without
the phase having happened — and `w-readphase` §6.1's rule, that a body leaving
`fnbyte-refused-parse` lands in `fnbyte-refused-codegen` **meaning the emitter
declined**, would become false in the tree that publishes it. For **5 functions**
(§3). The brief's own warning applies to itself: *a conversion here would be
surprising and should be treated as a signal to check your work.*

## 5. THE CONTROLS FOUND THREE DEFECTS IN THIS LANE'S OWN WORK

Recorded because a lane that only reports what worked is not evidence.

### 5.1 §9 is falsified: a body can define its epilogue label and never jump to it

The liveness guard was written `defs == 0 || refs == 0`, on `IL_STMT_GRAMMAR.md`
§9's *"every body has an epilogue `3A` and the `29` it targets"*. It fired on
**three real bodies** — and §9 is what is wrong:

```
4C 4F 11 · 53 · 54 02 · 29 <tok> · 4F 12 47 54 01 54 00
```

Sixteen bytes: the body scope opens, closes, the epilogue label is defined, and
**nothing jumps to it** — it is reached by fallthrough. `src/Main.cpp`,
`src/system/midi/MidiParserMgr.cpp` and `src/system/midi/MidiReader.cpp`, one
each, of 2,410,886 scanned bodies. Two of the three were scoring `admit-straight`
and were **right** to: a body with no branch at all is the most admissible body
there is, and the guard was refusing it for having exactly the property
`LabelTable::dead_defs` is documented as tolerating.

The guard is `&&` now — a **wholly** empty map, which is the failure mode it
exists for, since an instrument that stopped collecting sites answers *no* to
every question and passes every clause. The count is kept as its own axis value
(`admit-fallthrough-epilogue`, **2** on the emitted column) rather than discarded
with the guard: a grammar counterexample found by an over-strong control is the
most valuable thing that control produced. The body is pinned to the byte in
`step5`'s tests and mutant **M9** puts the `||` back.

### 5.2 An `admit-` name reached before the residue clause

The fallthrough axis value was first reached **before** `CfgAdmit::of` ran, so it
relabelled one body that `refuse-unmodeled-operand` had refused into a name
beginning `admit-` — the census reporting an admission for a body the predicate
rejects, which is the exact confusion *"decoding a production is not licence to
emit it"* is a rule against. It is gated on `v.admits()` now and the cell reads
**2**, not 3. **Caught by `step5-refuse-unmodeled-operand-BLOCKED` moving by
one**, and by nothing else. Mutant **S2** reproduces it on demand.

### 5.3 The boundary's rows doubled a published key, and the rule was one field away

The `step5-*` rows were written into `TuResult::fn_cflow`, with a comment arguing
a seventh map was unnecessary because it is the same walk's verdict over the same
population. `GapReport::cflow_residue_control` sweeps every `fn_cflow` row ending
`|IN-CLASS` that does not end `+expr-modeled|IN-CLASS` into its off-class total:

    cflow-residue-inclass-offclass   517,425  ->  1,222,684

517,425 + 187,834 + 517,415 + 10, to the digit. **The rule was already written
down one field away**, in `TuResult::fn_cflow_off`'s own doc, in these words:
*"Its own map and not a row of `fn_cflow`, and that is not tidiness… the
published number would have roughly doubled with nothing in git to show for it…
Two maps cannot collide."* It was read **after** the fact.

**What caught it was the base-vs-tip `gap-metric` identity diff and nothing
else** — no test covered it, and it is not a number this lane would have thought
to read. The axis has its own map now; the separation is pinned both ways in the
harness test; mutant **S5** puts the rows back and the key doubles on demand.
