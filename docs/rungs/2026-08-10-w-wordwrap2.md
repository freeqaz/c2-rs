## 6. WHAT SHIPPED — `bss_shell`

`emit_comdat_obj` gains a fifth parameter, the TU's shared non-COMDAT `.bss` in
`.gl` record order, and splices a section at index 3 — between the two `.XBLD$W`
watermarks — lengthening the symbol prefix by `2 + n` and shifting every section
index and symbol index downstream. The **walk and the allocator are
`coff::data`'s own, CALLED and not copied**, which is board #1120's rule:
`section_nibble` was already a second copy of `align_nibble`'s table once, and a
lane edited one of the two.

Class, every clause a refusal, decode bound in `c2-il` and layout bound in
`c2-core` so neither crate assumes the other ran:

1. **1 or 2** objects (`MAX_OBJECTS_PER_SECTION`, board #184);
2. every one **eager EXTERNAL** — internal linkage is slot `C` (`p5`);
3. not COMDAT, not thread-local, size > 0;
4. every function unframed and non-float (M23, unchanged and named);
5. every `uninitialized` def must name one of the TU's own objects — **and this
   test is unconditional**, see §8.

### 6.1 The reader's two refusals are NOT one refusal

`IlBundle::bss_shell_objects` separates:

* **`bad_uninit`** — a non-COMDAT uninitialized object this path cannot place.
  **Always `None`.** `resolve_bss_def` will already have admitted it into some
  function's `data_defs`, so something must own it. This is exactly the refusal
  `emit_comdat_obj` made unconditionally before this lane, so a TU with one is
  refused now for the reason it was refused then.
* **`other_section`** — a COMDAT `.bss` or a non-COMDAT `.data`, neither of which
  any resolver admits, so neither is a dangling relocation. Only a refusal **when
  a shared `.bss` is actually being placed.** Gating it that way is what keeps
  this method from tightening the port on TUs with nothing to do with its class,
  and the 878-TU neutrality run (§9.1) is the evidence that it does not.

## 7. THE 160-WORD BODY, AND THE AFTER-EPILOGUE BLOCK

`?WordWrap_CanBreakLineAt` is 640 bytes / 160 words over ~40 basic blocks, with
r31 = `ch`, r30 = the table base, r29 = the option word, and `mr 5,3` in the
prologue so r3 is free for the two `bl` sites. Its three binary searches are the
same six-instruction idiom at three different result fields (`cantBreakBefore`
twice, `cantBreakAfter` once).

**The block after the epilogue is the third search's result load.** The epilogue
is at `+0x26c` (`addi 1,1,112`) and `+0x270` (`b __restgprlr_29`); at `+0x274`
sits

```text
   0274  397e0003  addi 11,30,3
   0278  7d6a58ae  lbzx 11,10,11
   027c  4bffffe0  b .-32          -> +0x25c
```

— the `result = g_LineBreakTable[mid].cantBreakAfter` arm of the third search,
reached only from `+0x230`'s `bt 26` and branching *back* into the body. The
first search's identical arm is at `+0x1e0` and the second's at `+0x240`, both
**inline**; only the third is sunk.

**`wb-loop`'s flag is the right reading and it is confirmed here**: a block
reachable only as a loop exit is sunk past the return. All three arms are loop
exits; the third is the one whose sinking costs nothing because nothing follows
it. **`plan_text_order` has never had to place a block after the return**, and
this lane did not teach it to — M18 stays live, priced and named, because the
rule *"which loop-exit block gets sunk"* has one witness here and three candidate
readings (last-in-source, last-in-block-order, the one whose fallthrough is the
epilogue) that this body cannot separate. Two witnesses are not a rule and one is
not either (#2306).

## 8. THE PANIC, AND WHY ITS REPAIR IS TWO REPAIRS

For one commit `bss_shell` shipped a crash. `IlBundle::bss_shell_objects`
returned `Some(vec![])` whenever its admitted list came out empty, **before**
testing its refusal flag. A TU whose only uninitialized object is `static`

minted no symbol; and the REFHI/PAIR/REFLO/PAIR quad that `resolve_bss_def` had
already put on the function had nothing to resolve against.

```text

   every relocation target got a symbol
```

It fired inside the `/O1` fixture lane, on `wwbss_static_neg.cpp` — a cell
this lane wrote to grade a *different* clause.

**`docs/STATUS.md` trap 5 — absence reads as success — with the absence being the
object the reader declined to report.** Both repairs are kept and both are
graded (§9.3, M6):

* the reader separates *"cannot place this uninitialized object"* (always `None`)
  from *"cannot place this OTHER section"* (`None` only when a shared `.bss` is
  being placed);
* the writer's dangling-def test is **unconditional**. It read
  `if !bss.is_empty() { … }` for that one commit, and gating a check on the
  suspect input being non-empty **is asking the broken input to report itself**.

Two crates, two independent statements of one rule, on purpose.
