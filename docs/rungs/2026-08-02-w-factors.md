**One-line statement:** *`ROADMAP.md` §10.19's four-factor model of Phase 7 was
the project's front-page planning model and only half of it was computed by any
instrument; C and D are now first-class `gap.rs` keys, the factorization prints

## 1. What it admits, and what it refuses

Nothing about the port changed. This rung admits **measurements**, and it
refuses to compute any of them twice:

| factor | predicate over the graded TUs | key | who owns the rule |
|---|---|---|---|
| **A** | `.ex` segments == obj `.text` COMDATs | `emit-set-ceiling-gate` | step 1g, unchanged |
| **B** | every emitted symbol binds | `emit-set-ceiling-today` | step 1e, unchanged |
| **C** | obj section set ⊆ `PORT_WRITER_SECTIONS` | `emit-sec-reachable` | **new**, step 1h |
| **D** | every emitted COMDAT in the port's codegen class | `emit-class-complete` | **new**, step 1h, built from 1e's own `emit-in-class`/`emit-emitted` |

New keys, all pure additions: `emit-sec-{readable,unreadable,count,distinct}`,
`emit-sec-name|<name>` (one per **distinct** name per TU, so the aggregate reads
*objs carrying it*), `emit-sec-extra|<name>`, `emit-sec-{reachable,blocked}`,
`emit-class-{known,complete,empty}`. 28 rows in total on this workload.

`ObjImage::section_names()` is new in `c2-obj`, and the section-name decode and
the COFF header-bounds check were **extracted into shared helpers** so both walks
— the emitted-set one and this one — use one decoder. §10.14 is the record of a
second reader of a rule the harness owns; the emitted-set walk cannot see a
`.data` or a `.bss` at all, so C needed a reader, and the choice was where to put
it, not whether to write a second one.

### What it refuses, by name

* **It refuses to re-derive the codegen-class rule.** D reads
  `emit-in-class == emit-emitted`, both written by step 1e's join, so the
  in-class predicate stays `FnVerdict::in_class()`. An emitted symbol that fails
  to bind is *not* counted in class — D fails closed.
* **It refuses to treat an undecodable obj as satisfying C.** No section list
  means no C, and `emit-sec-unreadable` is printed as a count. An empty section
  list would read as "carries nothing outside the writer's set", i.e. as *inside*
  C: absence reading as success, on the flattering side (§9.18.8).
* **It refuses to multiply marginals.** `B∧C` and `A∧B∧C∧D` are measured per TU
  (§8.6). The unit test pins a four-TU case where every marginal is 3/4 and the
  joint is **0**.
* **It refuses to own the writer's section list.** `PORT_WRITER_SECTIONS` is a
  transcription of six `name: ".…"` lines in `crates/c2-core/src/coff.rs` with
  its provenance named. Its home is a published constant in `c2-core`; minting
  one is a cross-seam change and is left to the coordinator. What stands in for
  ownership is a control that can go red — see §4.

### What a clean sweep is and is not worth

**11/11 with a declared confirmatory bias is weak evidence about the world and
strong evidence about the instrument.** Two implementations had already measured
these numbers; a third agreeing does not make them more true so much as it makes
them *reproducible on demand*, which is the deliverable. The lane's registered
mitigation was that the predicates be fixed in prose before the code existed —
writer set, unreadable-obj convention, vacuous-truth convention — and they were;
the first full scan is the recorded one and none of the three conventions was
revisited.

The two things this lane learned that were **not** in the prediction (B = 338,
and the 16-TU frontier) both arrived from writing down joints nobody had asked
for, not from the eleven registered numbers. That is the shape to expect from a
reproduction lane, and it is an argument for registering the *joints* rather than
only the marginals next time.

## 4. The controls, and which of them can go red

| control | known answer | measured |
|---|---|---|
| matching TUs failing factor **A** / **B** / **C** / **D** | 0 each | **0 / 0 / 0 / 0** over 6 matching TUs |
| `emit-sec-unreadable` | 0 (`emit-obj-unreadable` is 0; both walks fail closed on the same conditions) | **0**, over 871 readable |
| `emit-sec-reachable + emit-sec-blocked == graded` | 871 | **84 + 787 = 871** |
| every pre-existing `emit-*` key, base → tip | identical | **identical**, twice, on two workload-tree states |

**The C control is the only executable check on `PORT_WRITER_SECTIONS`.** A
matching obj *is* the port's own output, so a section name missing from that list
puts a `match` TU outside C and the scan says so — no argument about whether the
list is complete. It cannot catch the opposite error: a name in the list the
writer never emits would inflate C silently. That is why the list is a
transcription of six source lines rather than a generalization of them, and why
this asymmetry is written down instead of implied.

Four unit tests carry the invariants portably (no toolchain):
`the_factorization_is_a_joint_and_not_a_product_of_marginals` (every marginal
3/4, joint 0), `a_matching_tu_outside_any_factor_is_a_red_control` (the mutation
that must go red, with the `match` count held fixed so the control cannot pass by
changing the class filter), `an_unreadable_obj_is_outside_factor_c_…`,
`the_greedy_ladder_runs_through_a_zero_gain_step`, plus
`the_section_vocabulary_counts_objs_and_not_sections` and
`the_frontier_is_the_tus_whose_only_remaining_factor_is_codegen`.

### The trap this file is famous for, and what was done about it

§10.18 happened in `gap.rs` the day before this lane: a variable with two
consumers was changed for one of them, `vocab-gap 865 → 0` and
`codegen-gap 0 → 865`, with `mismatch 0`, `match 6` and nothing red. Step 1h
therefore **reads `captured.ref_obj` afresh and shares no variable with step 1e,
step 1g or step 3**. The questions are different — *what sections does this obj
have* is not *which COMDAT `.text` leaders are there*, and a `.bss` is invisible
to the second — and the E1 control (every pre-existing key, per TU, on the same
workload-tree state) is what would have caught a substitution had one occurred.

## 6. What this does not do

* **It converts nothing.** TU match is 6 at both ends, by design.
* **C = 871 would convert nothing either.** All four factors are necessary and
  none is sufficient; the ladder makes TUs *reachable*, and only D converts them.
* **The factorization is a model of today's port**, not of c2. A changes when the
  port gains an emit-set model, C changes when the writer learns a section, D
  changes with every widening rung. It is a dashboard, and dashboards go stale
  silently — which is the whole reason it is now recomputed by the scan instead
  of living in a document.
* **`PORT_WRITER_SECTIONS` still lives in the wrong crate.** Filed for the
  coordinator: a published constant beside the writers in `c2-core/src/coff.rs`,
  with `gap.rs` importing it, removes the one hand-maintained list this rung
  added.
