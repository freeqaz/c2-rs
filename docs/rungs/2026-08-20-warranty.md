## What it admits, and what it refuses

Nothing about the port moved. `crates/{c2-il,c2-core,c2-obj,c2-reference}`
read `git diff --name-only` **empty** at the tip; the only `crates/` file this
lane changed is `c2-harness/tests/cli_flags.rs`, which is `#[cfg(test)]` by
construction. Two mutations were applied to judge crates during the campaign
and both were reverted in the same session, with the revert verified before the
first commit.

What it admits is three guards and one counter, and **each was proven to fire
by mutation before it was claimed**. That rule is the lane, not a preamble to
it: adding an assertion that cannot fail, while closing three instances of
assertions that could not fail, would have been a net loss no matter how many
lines it produced.

## 0. The correction, first, because it changed the deliverable

`docs/REFACTOR_REVIEW_2026-08-20.md` §0.1 found the hole and specified the fix:
the three tests that are 99.1 % of `cli_flags.rs` run `c2rs selftest`, `c2rs
bench` and `c2rs perf` to completion over all 386 fixtures and assert only
`assert_ne!(code, Some(2))` — *"the parser did not refuse this argv"* — so a
corpus-wide failure, which exits **1**, passes. That is exactly right, the
coordinator verified it independently, and this lane re-verified it.

The prescription was: *"additionally `assert_eq!(code, Some(0))`"*. **Read-only
inspection said that would not catch a wrong emit, and mutation M1 proved it.**

Two facts:

1. **`c2rs perf` exits 0 on a port `Mismatch`, deliberately.** `cli/perf.rs`,
   verbatim: *"the reference is the sole judge, so a port
   Match/Mismatch/NotImplemented is per-TU reporting, not a harness failure.
   Only a capture/replay error or a broken P0.1 replay is a hard failure of the
   benchmark itself."* The `Port=Mismatch → ExitCode::FAILURE` the review cites
   is in **`cmd_diff`**, the per-fixture command.
2. **`bench` and `selftest` never invoke the port.** Both loop
   `oracle_selftest`, which is *reference* determinism plus *reference* capture
   stability. `cmd_bench`'s `fail == 0 && err == 0` is a statement about
   `c2.dll`'s own reproducibility.

M1 plants a wrong emit in `PortC2::compile_to`. The result, from
`work/w-warranty/logs/M1-RED-full.log`:

```
summary: 0 port Match, 153 mismatch, 233 not-implemented (of 386)
...
command: `c2rs perf`
exit: Some(0)
```

**153 of 386 fixtures emit wrong bytes and the process exits 0.** An
exit-code-only guard would have gone green, and it would have gone green *under
a name that reads as a corpus-wide byte gate*. That is this repo's defining
defect family arriving one level up: not an absent check, but a present check
whose name promises more than it can fire on.

So the wrong-emit guard reads `perf`'s **stdout summary**, and `perf`'s
exit-code contract is left exactly as it was. The exit-code assertion is kept
too — for `bench` and `selftest`, where it means something, and for `perf`'s
`ERROR` / `[!ref-replay-inexact]` rows, where it also means something — but it
is not the wrong-emit catch and the code says so where a reader will find it.

**The transferable point:** the brief, the review and the coordinator all
converged on a fix that one mutation refutes in a single run. When a dispatch
names the assertion to add, the mutation still decides whether it fires.

## 1. What each guard catches, what it CANNOT catch, and how it reads
   unprovisioned

| guard | catches | CANNOT catch | unprovisioned worktree |
|---|---|---|---|
| **G1** `accepted_perf` asserts `0 mismatch` in `perf`'s corpus summary | **a wrong emit on any of the 386 fixtures** — the corpus-wide byte compare reaching an assertion inside `cargo test` for the first time | a wrong emit on IL outside the fixture corpus (the 878-TU workload — that is `gate.sh`'s rows); a class the port *refuses* (`NotImplemented` is not a mismatch and must not be); anything `perf` skips | **GREEN**, and it says so: it records the absence branch it took and returns `false` to a caller that counts `graded` separately from `guarded` |
| **G2** `accepted_selftest` / `accepted_bench` assert exit 0 **and** a clean corpus | reference non-determinism, capture instability, per-fixture reference ERRORs — corpus-wide | **a wrong emit** (the port is never invoked — M1 proves this, GREEN under a 153-fixture wrong emit); the eight `Rest` roster rows, which are deliberately not covered | **GREEN** (both exit 0 with `SKIP`) |
| **G3** `partest.sh` demands `C2RS_REQUIRE_TOOLCHAIN=1` | a whole suite run that graded **nothing** — the fresh-worktree case where 132 of ~179 integration tests early-return and the totals are byte-identical | a **partially** provisioned run (`compilers/` present, `strace`/mingw absent) — `locate()` succeeds and the per-test guards still skip silently | **RED**, by design. That is the deliverable |
| **G4** `gate.sh` row-liveness counter | a standing gate row that stopped executing and stayed that way | a row that executes and is wrong; and it cannot say how long `hatch-red` has *already* been stale — the history starts at this commit, so an `N` is a **floor** | unaffected (the counter is toolchain-free) |

The roster is mixed and the guard was **scoped rather than softened**. `c2rs
diff` exits 1 on `Port=Mismatch` on purpose; `census`, `capture`, `compile`,
`gap` and `prefilter --schema` each have their own contract and this lane did
not read them line by line. So the other eight rows keep the roster assertion
alone, `corpus_verdict_kind` says why in the source, and
`the_corpus_verdict_guard_covers_exactly_the_three_whole_corpus_rows` pins
**both** the covered and the uncovered sets **by name**. A narrow assertion
that fires beats a broad one that had to be weakened.

Three properties every guard has, each a recorded lesson:

* **Absence is decided positively.** The guard asks `Toolchain::locate()`,
  `has_strace()` and `has_mingw()` — the same calls the CLI makes — and
  computes what the command was *obliged* to do. It never greps stdout for the
  word `SKIP`, which would let any silent early return read as a clean skip.
* **A short run is not a pass.** Every row count is floored against
  `c2_harness::all_fixtures().len()`, read from the same source the command
  reads.
* **Two derivations, diffed** (#3288). The mismatch count comes from the
  summary line *and* from counting per-fixture rows, and the two must agree;
  `bench`'s failure count comes from the summary *and* from the exit code.

## 3. `C2RS_REQUIRE_TOOLCHAIN` — closed at the root, and one thing NOT closed

`scripts/partest.sh` now exports `C2RS_REQUIRE_TOOLCHAIN=1` by default, with
`--portable` opting out and an explicit environment value always winning. The
demand is **unconditional** rather than gated on probing for `compilers/`,
because a shell-side "does the toolchain resolve" predicate would be a second
implementation of a rule `Toolchain::locate()` already owns — the one-rule-two-
implementations shape the review's §2.1 flags and #3134 already paid for. The
script carries the demand; `require_toolchain.rs` stays the single authority.

**`gate.sh` deliberately does not get this.** It runs no `cargo test` at all —
its only two `cargo test` strings are inside comments — and `--require-graded`
is a differently-scoped demand about the port. The review left this as a
question; the answer is no.

**Not closed:** a partially provisioned run. `compilers/` present with `strace`
or mingw absent still skips a subset silently, because `locate()` succeeds.
The demand is total over *"did this run have a toolchain at all"*, never over
*"did every gated test execute"*.

### 3.1 And the check the brief asked for is vacuous — board #3341

The dispatch asked this lane to *"assert **0** `SKIP: toolchain absent`"* at the
tip. **That assertion is satisfied by the failure it is meant to detect.**
libtest swallows stdout for a *passing* test, and every toolchain-gated test
here passes when it skips. Measured, under a deliberately unresolvable
toolchain:

* `cli_flags::two_profiles_must_not_produce_one_bundle` and
  `…_one_obj` both **pass in 0.00 s having graded nothing**, and
  `grep -c 'SKIP: toolchain absent'` over the run log returns **0**.
* The same two tests under `--nocapture` print the line **twice**.

So a run log with zero SKIP lines is exactly what an unprovisioned worktree
produces. The non-vacuous forms are the ones `docs/rungs/README.md` already
prescribes and that a natural-language paraphrase loses: **a positive check on
a name** (`C2RS_REQUIRE_TOOLCHAIN=1`, which fails by name), and **a duration**
(`census_gate` non-zero). This lane used both, and used `-- --nocapture` where
it wanted the SKIP count itself.

## 4. The row-liveness counter — board #3339, closing #3219's second half

`--selftest` proves every row **can** go red. Nothing proved any row **had
run**. `hatch-red` reads `REFUSED HATCH-STALE 0/14 arms` in every observed run,
in every tree including clean master — confirmed at this lane's base *and* tip,
so it is master's pre-existing state and not any lane's — and the table could
not distinguish *"REFUSED this run for a local reason"* from *"REFUSED for a
month"*.

The rule is deliberately narrow. **EXECUTED = the verdict word is `PASS` or
`FAIL`.** `REFUSED`, `NO-RESULT`, `SKIP` and an **absent tuple** are not
executions, whatever their reason, and each keeps its own word in the note. The
counter resets on an execution, so it answers *"consecutive"*, never *"ever"*.

**It prints and it never fails the gate.** A threshold would be a new fence, a
fence is priced two-sided before it ships (#1042, NC-5/#2691), this lane priced
none, so it shipped none. The instrument that makes such a fence *priceable* is
the deliverable.

The number ships with its limits printed beside it, because a counter that
looks like an age and is a floor is the same defect wearing a number: the
history starts empty at this commit, so `N` is a **floor**; it is per-worktree;
and two gates in one worktree can interleave their rewrites.

Sixteen `--selftest` cases, floor **183 → 199**, walking a history forward
across runs rather than testing one call. The case most likely to be got wrong
is pinned explicitly — **`FAIL` is an EXECUTION** — because folding it in with
`REFUSED` would make a row that goes red every run look like a row that never
runs.

## 5. A flaky cluster in `gate.sh --selftest`, and two wrong attributions —
   board #3340

Four runs of the same file on one tree produced three distinct failure sets:

| run | outcome |
|---|---|
| 1 | died mid-file at `corpus-concurrent-publish-converges` (the two-publisher race), 59 `ok`s |
| 2 | `FAIL pid-reuse-is-reapable` — *"a live `sleep` reads as NOT a gate"* |
| 3 | `PASS — 199 cases` |
| 4 | `PASS — 199 cases` |

All the failures are in cases that either read a `/tmp` shared with every peer
lane's gate (`reaper-*`), or race a `fork` against an `exec` (`gate_pid_live`
reads `/proc/<pid>/cmdline`, which is still the parent's until the child
`exec`s — a window that widens under load).

**This is a row because of the attribution trap, not because of the flake.**
The lane's first instinct was that its own edit had broken the file, and a
base-comparison run *appeared* to confirm a difference — while itself failing
four cases **because the base copy had been given a temporary filename that
`gate_pid_live`'s `grep 'gate\.sh'` does not match.** Two wrong attributions in
one afternoon, both from a single run of a flaky suite. Re-running settled it.

## Found and not taken

1. **The review's steps 4-6** (dead `header_closure_warning`, the duplicated
   capture arm, the ~15 hand-rolled skip sites, `WORKLOAD_FLAGS`' 14 copies,
   the `bench`/`selftest` engine merge). All still open, all still cheap, none
   of them a warranty hole — they are one-rule-two-implementations hazards, a
   different and lesser family. The skip funnel (§2.2) is the one with a
   warranty edge: it is what would make G3's guarantee *total* over partially
   provisioned runs rather than total only over toolchain-less ones.
2. **`hatch.py`'s needles (#1389, open since 2026-08-08).** Not this lane's to
   design, and the counter deliberately does not fix it — it measures it. The
   first gate run after this commit prints `hatch-red: REFUSED for 1
   consecutive run(s)`, and the number becomes worth reading in a week.
3. **A threshold on the liveness counter.** Available, obvious, and not shipped
   because it was not priced. The two-sided price a future lane owes: what a
   `REFUSED for N runs → FAIL` fence costs in blocked merges on a box where
   `REFUSED DIRTY-TREE` is a routine consequence of a peer lane's work in
   flight, against what it buys over the printed number.
4. **The flaky `--selftest` cluster (#3340).** Three named clusters, a
   mechanism for two of them, and no fix. A merge funnel that re-runs on a
   `pid-*`/`reaper-*`/`corpus-*` failure and escalates only on a repeat would
   cost nothing and is not this lane's to install.
