## 3. What is refuted

### 3.1 `Main.cpp` is not "a real refusal with no lift" — the refusal is the parser's own class stack

`w-front3` §2.1 groups the seventeen by what stopped the climb and gives a
two-row bucket: *"a real refusal with no lift — `Main` (`expr-convert-no-value-0x2C`),
`xlrcimpl` (`assign-rhs-call-0x26`)"*. The second is right. The first is not.

`expr.rs`'s `0x2C` arm reads the source class off `cstack`, and refuses when it
is empty:

```rust
// A conversion with nothing to convert is not a conversion. This
// cannot be reached by a well-formed stream and refuses rather than
// guessing a class.
let Some(cls) = cstack.last().copied() else {
    return Err(blk(seg, start, "expr-convert-no-value"));
};
```

**The workload witnesses it 4,973 times as a FIRST blocker across 829 of 878
TUs**, read off the **unhatched, unsunk** base scan — so either the comment is wrong or 94.4 % of
this workload's IL is not well-formed. It is the comment. `cstack` is a partial
model by construction: every arm whose stack effect `parse_expr` does not follow
advances the cursor without pushing (`0x27`'s implicit second operand says so in
its own comment, and every sink skip sets `cstack_ok = false` for exactly this
reason). A `2C` after any of them sees an empty stack.

Lifted — the hatch assumes `Int4`, which is precisely the guess the shipped
guard refuses to make, which is why it is uncommitted and why nothing but
`fn_blockers` is read off it — `Main.cpp` climbs and the row reads:

```text
  rnd0  sinks=op:41              hatches=                          param-width-undetermined:mid
  rnd1  sinks=op:41              hatches=param-width               expr-call-in-expr-recv-object-then-op-0x5C
  rnd2  sinks=op:41,op:26        hatches=param-width               expr-convert-no-value-0x2C
  rnd3  sinks=op:41,op:26        hatches=param-width,convert-no-value
                                                                   expr-call-in-expr-recv-object-then-op-0x5C
```

**The ladder is a CYCLE, and the cycle is the answer.** Rounds 1 and 3 are the
same key. `Main.cpp` — six lines, `App app(argc,argv); app.Run();` — carries
both refusals, and granting `op:26` traded one for the other. The leave-one-out
(§4) confirms it from the other side: `op:26` is **not load-bearing at the final
state**, so the driver's `net=3` is 2 rungs and one token that bought nothing.

**`0x5C` is the EH LIVE-STATE marker.** `control_flow.rs` reads it as
`5C <TYPE> <varint>` into `cf-eh-live-type` / `cf-eh-live-state` and increments
`eh.live_stmts`; `func/mod.rs`'s own fixtures call the same bytes the *statement
trailer*, with the EH bit set or clear. Its rung `cf-expr-0x5C` is **"309,804
bodies, the largest single row on the control-flow axis"** in that file's own
words. `Main.cpp` is `/EHsc` with a local object with a destructor, so the
marker it needs is the one carrying a live EH state — this is the cheapest row
of the seven and it is a row on the EH state machine.

### 3.2 A first-blocker key names an opcode its own driver could not reach — and the naive repair MANUFACTURED TWO RUNGS

`expr-call-in-expr-recv-object-then-op-0x5C` names two things: the production it
was inside and the byte it stopped on. `ladder.py`'s prefix table matches the
first and returns `op:26`, already granted — so the driver reported STUCK on a
byte its own key had named.

The obvious repair — grant the opcode the key's tail names — **is wrong, and it
was measured wrong on this lane before it was believed**:

```text
  granting op:5C on Main.cpp      -> identical blocker set    net 3 -> 4
  granting op:26 on xlrcimpl.cpp  -> identical blocker set    net 0 -> 1
```

Two rungs counted for nothing. That is `Pool.cpp`'s defect (`w-front3` §4.1) in
a new place, and it would have been published as a price. The rule shipped here
is **speculative and self-controlling**: each tail-opcode candidate is TRIED,
kept only if the blocker set MOVES, and otherwise discarded and named in
`tail_inert`. Both rows come back to 0 and 3.

### 3.3 `xlrcimpl.cpp`'s rung is rare, which is a fact nobody had

`assign-rhs-call-0x26` is witnessed **11 times over 9 TUs** in the whole 878-TU
workload. It is the only one of the seven with genuinely **zero** climbable
rungs — the production is unimplemented, not guarded, so nothing below it can be
seen and its READER cell is a `BOUND` and not a price. What is new is the size:
a lane that writes it serves nine TUs, and it is the sole reader blocker on
exactly one of them.

### 4.4 The refusal-key reachability screen — one finding, and a denominator that is NOT one

`work/w-one/keyreach.py` takes every refusal key `crates/c2-il` can mint and
compares it with every key the workload witnesses.

```text
  keys minted in crates/c2-il (non-test):  218
  keys witnessed as a FIRST blocker:        34
  UNREPORTED (shadowed OR unreachable):    184
  witnessed AND declared impossible:         1
```

**The 184 is not a list of unreachable rungs and is printed with that sentence
attached.** `fn_blockers` is a FIRST-BLOCKER histogram, so "no function reports
this key" means *no function stops here first* — a statement about what shadows
it. That is this project's own *a first-blocker key is a NAME, not a DISTANCE*
one level up, and it is why the number is 184 and not 4.

The screen's yield is the **other** direction, and it is §3.1: one key whose own
source says the state cannot occur and which the workload witnesses 4,973 times
as a first blocker — 5,344 across the three maps this screen sums, and the two
figures are printed together because they are different populations.
Two further keys are declared impossible *and* unreported
(`call-arg-lit-classified-twice`, `call-arg-sym-classified-twice`) — consistent,
and nothing follows from it either way.

**No new structurally-unreachable rung was found on these seven** (prereg P7,
HIT). `w-front3`'s `value_bound` remains the only confirmed one; its variant
screen read 0 of 21 and this lane adds no second instance. What it adds is the
*mirror*: a **false** unreachability, which costs more than a true one, because
it is what sends the next lane to record a row as unliftable.
