## What it admits, and what it refuses

**It admits nothing into the emit path.** One reader width is corrected:

> `33 <TYPE> <payload>` — the INT LITERAL — has an escape width set by its
> operand TYPE. Four payload bytes for tags `82`/`84`/`86`, **eight for tag
> `88`**. The short form is one byte at every width.

**That rule is not this lane's.** `docs/IL_CAST_CONVERT.md` §3.2 states it
outright, §5.5 lists *"`read_varint` must take the operand type"* as an owed
prerequisite, and `read_varint`'s own NOTE in `readers.rs` says the same. What
had not been noticed is that the **chain sink walks straight into it**: the
`type` sink token exists precisely to step past the operand-TYPE gate, so it
hands the literal arm a 64-bit literal and a 4-byte reader, and the cursor stops
four bytes inside the payload.

Refused, by name, each with its own cells:

* **`0x2C` (CONVERT) is NOT widened.** Measured at three targets — `unsigned
  long long`, `unsigned`, `double` — and its trailer is the single byte `00` at
  all three. It keeps `SkipForm::TypeVarint`.
* **Floating-point literals are NOT fixed.** §3.1 gives them a different payload
  (`<8 IEEE bytes> <u16 size>`, no `0x80` marker); they take the short-form
  branch and are wrong by nine bytes. Left refusing, with a test that says so,
  rather than half-handled.
* **The VALUE is not widened, only the WIDTH.** `IlOp::Lit` is an `i32` and a
  64-bit literal does not fit it. The wide reader is reachable only where the
  operand-TYPE gate *refused* and the sink carried the walk past it — a
  structural fence, not a flag — so no **accepted** literal can take it.

## The exit key, and #1792

The base ladder reproduces boards **#1465** and **#1430** to the unit:

```
net=17  stepped=16  EXIT: expr-chain-noform-0x00 (noform)   RENAME: op:00
```

**The exit is an artifact, and not the one #1465 named.** `0x00` is not an
unpinned opcode. It is byte 5 of the 8-byte payload of `nonce & 0xFFFFFFFF`:

```
33 88 82 23 · 80 ff ff ff ff 00 00 00 00 · 0B
                          ^^ the reader stops here
```

#1465's **conclusion** is right — the `op:00` rung buys zero decode distance —
and its **mechanism** is wrong in the direction that matters. A rename can be
fixed by pinning the opcode; a desync cannot be fixed by any entry in a width
table at all. #1465 filed this rung under "unpinned"; it belongs under
"unfixable by pinning".

After the repair:

```
net=17  stepped=17  EXIT: expr-shr-mixed-sign:mid          RENAME: none
```

Three of the four blocked bodies now walk to the function tail
(`expr-chain-noform-0x4F`, which the driver treats as a terminal because `4F 12`
*is* the tail). The fourth exits on a real, named, unlifted refusal in the port.

**So P5's answer is "was the instrument's, is now the TU's".** The published
`net` is **unchanged at 17** while the thing it proxies changed completely —
which is exactly **#1103**'s standing instruction to quote the **exit key** and
not the depth. A lane ranking by `D` would have seen nothing happen here.

One discrepancy recorded rather than resolved: board #1792's summary sweeps
`EncryptXTEA` into a five-TU `LIFTED→LIMIT` list, while
`rungs/2026-08-08-w-xlr.md` §10 names **four** and prices `EncryptXTEA`
separately at **≥ 26**. Both were right about different things — the ladder *was*
instrument-bounded, and ≥ 26 *is* a genuine lower bound.

## The label charge — measured, and the table would have been wrong

`docs/LABEL_COUNTER.md` has been measured wrong by four consecutive lanes, so
this one measured its own, by counterfactual over TUs one body apart, at `/O1`
**and** `/Ox` (`work/w-xtea/lab/`). `Encipher` is function **4 of 5** and the
framed `Encrypt` is function **5**, so the cell is **LIVE** — a wrong charge here
moves a later function's `$M`, which is the ordering `w-blockir` §6 requires and
the reason a cell on the *last* function would have been inert.

| cell | `Encipher`'s control flow | obj B | `Encrypt`'s `$M`, `/O1` |
|---|---|---|---|
| **A** | `for (i < 4)` | 1950 | **2643 / 2644** |
| E | `for (i < 2)` | 1950 | no move |
| F | `while` | 1950 | no move |
| G | `for` + 4 extra straight-line statements | 1966 | no move |
| **D** | no loop at all | 1882 | **2642 / 2643** |
| **H** | `do { … } while` | 1950 | **2642 / 2643** |

Controls held: **G** is the size control (16 more bytes of object, control flow
unchanged, counter does not move — so the A/D step is not a volume artifact),
**E** says the charge ignores the trip count, **F** says `while` charges as
`for`.

```
   /O1, relative to the same TU with no loop:   for +1   while +1   do/while +0
   docs/LABEL_COUNTER.md §4:                    for +2   while +2   do/while +1
```

**Every value is one less.** Whether that is a different baseline or a different
charge for this body shape is not decidable from six cells, and it does not need
to be: taking the number from the table would have put `$M2756` and every later
label in this TU **off by one**. Fifth consecutive lane, first time on this TU.

**`/Ox` is not the same experiment.** There the TU packs into a single `.text`
and `Encipher`'s framing *flips* — it mints a triple of its own in A/E/F/G and
not in D/H. So the minting is mode-dependent as well as the charge, and no
single number covers both profiles.

## Found and not taken

1. **`expr-shr-mixed-sign`** is now `Encipher`'s terminal, and it is a real
   refusal — the ladder's `verify` marks the hatch **INERT**, i.e. granting it
   does not unstick the body. This is the same key `osfinfo` and `jsonwriter`
   exit on (**#1103**), so it is a **three-TU** blocker, not a one-TU one. Not
   priced here.
2. **Floating-point literals still desync by nine bytes** (§3.1 /
   `read_float_literal`). A test records it. Every body with an FP literal is
   walking a corrupted stream under the sink today, so any ladder depth
   published for such a TU is measuring garbage after that point — the same
   defect class this rung found on the integer side, unfixed on the float side.
   **This is the highest-value thing this lane found and did not take.**
3. **The `2C` trailer at a `long long` target** is measured (`00`, one byte) but
   only for the three targets probed. `5C`'s width is untouched and unwitnessed.
4. **No 64-bit rotate/mask encoder exists in `c2-core`** — `rldicl`, `rldimi`,
   `clrldi`, `sradi`, `srdi`, `sldi`, `extsw` are zero hits across the whole
   crate. Three of the frontier's remaining bodies need them. That is a
   self-contained encoder rung with no label-counter exposure, and it is the
   cheapest real thing adjacent to this TU.
5. **The label charge for `for`/`while`/`do-while` disagrees with the published
   table by a constant −1 on this TU.** Six cells is not enough to say which
   number is the general one. A lane that re-ran `w-label`'s 24-cell grid
   against this reading would settle it, and the answer gates every loop-bearing
   TU with a framed function — which is most of the frontier.
