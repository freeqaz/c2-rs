## 0. The one-paragraph answer

Three named failures, each of which three or more actors had walked into, and
in every one of the three the **prescription on the board was the wrong
shape**:

* **`#3552`** prescribes a check inside `scripts/wt_reap.py`. That script
  never passes `--force` and was not involved in any of the three losses —
  all three were a hand-typed `git worktree remove --force`. The fence that
  works is **git's own**: `git worktree lock` makes a plain `--force` refuse
  with exit 128 *and print the pin reason*. Measured before writing anything.
* **`#3552`** also says the cost protocol *"exited 0 having graded nothing"*.
  **It did not** — `cost_arms.py` refused, with exit 1, and the surviving log
  proves it. What was actually wrong was smaller and had been invisible under
  the wrong headline: the refusal **named the wrong cause**, and it fired
  after the expensive setup.
* **`#3510`** offers two candidate diagnoses and the registered pick was the
  anchor conflation. **Wrong mechanism**: the two anchors *agree* at 1260 on
  the violating TU. The predicate's other premise is the false one, and the
  consequence is bigger than a count — **the match set is not a subset of the
  "ceiling" set**, so the published bound is not a bound.

Everything shipped here is watched going red on a planted case before its
green is quoted, per `#1236`.

## 1. Item 1 — the reap guard (`#3573`, `#3574`)

### 1.1 What the recorded prescription would have bought

`#3552`: *"before a `worktree remove --force`, refuse if the tree holds a
pinned binary or a registered-unrun experiment, or move it out first."* Read
as a change to the funnel's reaper, that check **could not have fired on any
of the three occurrences**. `wt_reap.py`'s own docstring: *"No removal ever
passes `--force`: git's own refusal on a dirty tree is the backstop."* The
destroyer in all three cases was a person typing `git worktree remove
--force`, with the reaper nowhere in the loop.

That is `#1236` exactly — a guard that passes precisely when it matters.

### 1.2 The fence that does fire, measured on git 2.55.0

```
$ git worktree lock --reason "pinned experiment-F arms: c2rs-b1" wt1
$ git worktree remove --force wt1
fatal: cannot remove a locked working tree, lock reason: pinned experiment-F arms: c2rs-b1
use 'remove -f -f' to override or unlock first                        [exit 128]
$ git worktree remove --force --force wt1                             [exit 0, GONE]
```

A single `--force` is refused; only `-f -f` gets through; **the refusal prints
the pin reason**, so the person about to destroy the artifact is told what it
is. This is re-checked on every run of the guard's `--self-test` rather than
recorded once in a comment — it is a claim about the installed `git`, not
about this repo.

### 1.3 The detector, and the two wide numbers that forced its shape

`#3545`'s rule: measure the wide prescription before scoping to it. Applied
twice, and **both numbers are printed on every run** so neither can be
re-proposed without its price.

| | reading | why it is not the guard |
|---|---|---|
| **WIDE-1** executables outside `target/` | **3,053** primary · **336** per worktree | `compilers/X360` (Microsoft binaries, gitignored, re-fetchable) plus every tracked `.sh`/`.py` |
| **WIDE-2** ELF among them, outside `.git/`/`compilers/`/nested worktrees | **28** primary · **1** per worktree | that 1 is `work/w-biquad/c2rs.base`, which `setup_worktree.sh` **reflinks into every tree it creates** — reaping destroys nothing |

The predicate that survives is about **uniqueness, not shape**:

> an artifact is at risk from a reap only if it exists **only** in the tree
> being reaped.

Path + size against the primary. That drops all six inherited copies and keeps
exactly the cost arms — which is what all three losses were.

**The `.claude/` prune is not hygiene.** Without it the primary's own walk
descends into the nested worktrees and reports every other tree's files as its
own: 34 rather than 28, and every tree looks pinned by every other tree.

**Class P2 exists because prose is not machine-readable.** Two of the three
losses were of things a rung had *declared* pinned — *"the arms stay pinned"*,
*"registered and unrun"*. A `.c2rs-pin` file is the channel, and it is the only
class that can cover a non-binary: `w-3475`'s 14 GB corpus snapshot, a gate
base table, an unrun experiment.

### 1.4 Watched going red

`scripts/wt_pin_audit.sh --self-test`, 0.13 s, in a throwaway repo:

```
  control: a tree holding only an INHERITED binary   GREEN
  plant P1 unique cost-arm binary                    -> RED
  plant P1b binary rebuilt in place (same path, new size) -> RED
  plant P2 .c2rs-pin manifest (no binary anywhere)        -> RED
  same tree, now LOCKED                                  -> GREEN
  'git worktree remove --force' on the locked tree       -> REFUSED
  'git worktree remove --force --force' still works       -> GONE
  a repo with ZERO linked worktrees -> exit 2 (not a clean estate)
```

The **inherited-binary control** is the one that matters most: without it, a
detector that flagged every ELF would score three-for-three on the reds and
then be red on all six live worktrees.

### 1.5 The first real run found two live violations — in this wave's peers

```
  UNLOCKED AND PINNED  .claude/worktrees/w-decodereach
    P1 unique-binary  work/w-decodereach/c2rs-base
  UNLOCKED AND PINNED  .claude/worktrees/w-unfuse
    P1 unique-binary  work/w-unfuse/bin/c2rs_base
  worktrees examined: 5 · candidate files examined: 7        [exit 1]
```

Neither lane did anything wrong: building a base binary in your own scratch
tree is the correct way to run a pair, and it is exactly what `w-adjacency`,
`w-permute` and `w-hygiene` each did before losing it. `--lock` armed both and
**re-audited itself** rather than asserting it had fixed the estate.

**The rate is the finding, not the two names.** Three losses across three
consecutive waves, and the very next scan finds two more live instances inside
a single wave. The base rate of unlocked pinned artifacts is roughly *one per
active lane that runs a pair*; the three recorded losses are a sample of it,
not a run of bad luck.

### 1.6 Two-sided price

**Cost of the fence:** the two locked trees now need a deliberate
`git worktree unlock` before the funnel can reap them — one command per landed
lane that ran a pair. `wt_reap.py` reports them as `LOCKED … kept`, so nothing
silently accumulates.

**Cost of not having it, over three waves:** three cost arms destroyed
(`w-adjacency` §7.6, its own numbers unre-derivable), `w-permute`'s binaries
(`#3523`), three fresh `cargo build --release` to rebuild experiment F's arms,
one void measurement run, and a commit that had to be materialised with
`git archive` because no ref named it.

### 1.7 `wt_reap.py`'s veto, and why it does not short-circuit

The reaper gains a `PINNED` veto that no flag overrides — `--reap-unlanded`
and `--reap-empty-lanes` exist to widen what is reapable and neither may widen
past it. It is a **second line, not the fence**, and the file says so.

The pin scan records on the row and vetoes at the **action** stage rather than
returning early from `classify`. `GAPS.md` §7's lane-registry trap (`#1236`)
is that an earlier guard returns first and every later assertion silently never
runs; a row reading `MERGED … KEPT: PINNED` is the useful output, and a row
reading only `PINNED` hides which reap would have taken it.

Nothing on the live estate exercises the veto — the two pinned trees are
locked, and the lock short-circuits before the scan. So it is driven red in a
throwaway repo under `cargo test`, with `--active-hours 0` and
`--reap-empty-lanes` both required: without them the plant tree is kept as
ACTIVE or EMPTY-LANE and the test passes on the wrong evidence. **The first
version of that test did exactly that**, and the assertion that caught it is
now `would have been EMPTY-LANE` + `would reap: 0` — the veto must override a
reap the flags *authorised*.

The two implementations of the P1/P2 predicate (shell, so the audit needs only
`git`; Python, so the reaper keeps its "git and nothing else" property) are
**compared against each other** on one planted tree, four readings, because two
implementations of one predicate that nobody compares are two predicates.

## 2. Item 2 — `#3470` bites backwards (`#3575`, `#3576`)

### 2.1 The recorded claim is not what happened, and the correction is the finding

`#3552`: *"the first F run printed `SKIP: toolchain absent` and the protocol
exited 0 having graded nothing."*

Measured against the surviving artefact:

* `scripts/cost_arms.py`'s `run_arm` has refused on `SKIP: toolchain absent`
  **since the file was created** (`a2757c7f6`).
* `work/coordinator/expF/runF.txt` **ends on that refusal**.
* `SystemExit(str)` is **rc 1**, verified directly.

**The ARM exited 0 having graded nothing — which is `#3470` exactly. The
protocol above it caught that and stopped.** The registered prediction that no
preflight existed (P2.1, p 0.75) is scored a **MISS** in §5.

That correction matters because the wrong headline hid two real defects:

1. **The refusal named the wrong cause.** *"the cost protocol needs the
   oracle"* — the oracle was installed and present; the **arm** could not see
   it. A reader goes hunting for a missing toolchain that is not missing, which
   is the re-derivation the coordinator then paid for.
2. **It fired mid-flight**, after the identity block, the rotation certificate
   and `load_at_start`. Cheap at `--port-iters 10`; not cheap on the quiet box
   you waited for.

### 2.2 What ships: the remedy applied, not documented

The remedy has now been re-derived by hand **three times** — `w-s1c3` first,
then `scan_pair.sh`, then the coordinator mid-run. Re-deriving a known remedy
three times is what a script is for.

* `pin_toolchain()` resolves and exports `C2RS_COMPILERS` / `C2RS_WIBO` in
  **`scan_pair.sh`'s exact order**, deliberately: two protocols that pin the
  same toolchain differently are two toolchains.
* `preflight_arm()` proves **each** arm can grade at `--port-iters 1`, prints
  its **denominator**, and refuses before any setup.
* On a `SKIP`-and-exit-0 arm the refusal now **checks which case it is** and
  says so: if this repo has a resolvable toolchain and the arm still SKIPs,
  that is not a missing oracle, it is `#3470` biting backwards.

`#3470` **cannot be fixed forwards**: an explicit env pin is taken verbatim by
`Toolchain::locate` and never goes through `repo_root()`, so it is the only
thing that reaches a pre-fix binary — and **every arm of every historical
re-run is a pre-fix binary by construction**, which is what "historical" means.

### 2.3 Watched going loud

```
PREFLIGHT REFUSED — arm 'a' (…/arm-a) printed 'SKIP: toolchain absent' and exited 0. It graded NOTHING.
  This repo HAS a toolchain and C2RS_COMPILERS/C2RS_WIBO are exported, so the oracle is not what is missing.
  This is #3470 biting BACKWARDS: the arm is built from a commit PREDATING w-hygiene's
  runtime repo_root() fix, so it resolves compilers/ against its own build tree.
  …                                                                        [exit 1]
```

Three shapes red — `skip-exit-0`, `zero-match`, `nonzero-exit` — plus **one
green control**, a fabricated `Match` row with denominator 1. The green control
**earned its place immediately**: its first version used a `µs` escape that did
not survive the shell, so it was refused and the self-test went red. Three reds
and no green is also what a detector that refuses everything scores.

### 2.4 `--self-test` was wired into nothing

`cost_arms.py`'s own `self_test` docstring cites `#1406` — *"an instrument
whose output is quoted as evidence should run under `cargo test` or
`scripts/gate.sh`"* — and then nothing ran it, for a protocol that has
published two readings disagreeing in **sign**. Now two `cargo test` targets,
and the end-to-end one asserts on the **wording**, not just the exit code.

### 2.5 `f6f56df78` was one `gc` from gone

`git cat-file -t` → `commit`. `git for-each-ref --contains` → **empty**.
`git reflog --all` → **1** entry. Reflog entries expire and `gc` prunes what no
ref names, so the commit experiment F's three arms were built at — the
provenance of `#3551`'s published result — was on a countdown. Tagged
`pin/expF-arms`, annotated with the reason.

**`#3573` stops a reap destroying the binaries; this stops `gc` destroying the
source they were built from.** Same omission, two layers, neither covered
before. A standing rule is *proposed and not enforced*: there is no cheap
predicate for "a number was published from this commit", and a fence over a
population nobody can enumerate is worse than none.

## 3. Item 3 — `#3510`, the voided ceiling (`#3577`, `#3578`)

### 3.1 The measurement, at full workload scale

878-TU scan at `a604adfb5`, re-derived from the `--jsonl` rather than read off
the scan's own summary line:

| | |
|---|---|
| graded | **870** |
| match | **25** |
| emit-set ceiling, LO-anchored | **26** |
| emit-set ceiling, GATE-anchored | **29** |
| `emit_set_violations` | **1** — `src/system/decomp_pch.cpp`, `fn_total` **1260** vs `emit-emitted` **0** |
| gate-anchored control | **1 of 25**, same TU |

The first four reproduce `docs/STATUS.md`'s generated block **to the digit**.

### 3.2 Both halves of the data are CORRECT

**`emit-emitted 0`** — read out of the bytes, not taken from the record. The
reference obj is **905 B, 5 sections**: `.drectve` (132), `.debug$S` (152), two
`.XBLD$W` (16 each), one `.rdata` (4). **Zero `.text`.**

**`fn_total 1260`** — and `emit-gate-segments` is **1260 as well**. The two
anchors *agree*. So this is **not** the `4C 4F 11` vs `4F 1F` conflation that
was the registered hypothesis, and a lane that had asserted on only one anchor
would not have been reading a weaker version of the same fact — it would have
been asserting on an accident.

### 3.3 The false premise, read out of `PortC2::build`

`emit_set_reachable_tus`'s doc argues: *"`PortC2::build` takes
`il.functions()`, one entry per `.ex` function segment, and under `/Gy` pushes
exactly one `.text` COMDAT per entry."*

**`build` has four emit paths and three of them return before `functions()` or
on its refusal** (`crates/c2-core/src/lib.rs:321-400`):

| path | line | what it emits |
|---|---|---|
| `dyninit_tu()` | `:333` | the `??__E` dynamic-initializer TU |
| `eh_scope_tu()` | `:359` | two code regions in **one** `.text` COMDAT |
| `provide_data_tu()` | `:395` | the shell plus one COMDAT per provide-always data record — **no `.text` at all** |
| `functions()` | `:387` | the one path the premise describes |

`decomp_pch.cpp` takes the third — W-NPOS, in the source's own words *"the
empty-main-file / pch-creator shape"*, where `functions()` returns `None`
because its `.gl` walk stops at a 26-introduced name. So the port emits zero
`.text`, the reference has zero `.text`, and the TU matches byte-exact while
`fn_total` reads 1260.

**The answer to `#3510`'s question is: the ceiling's PREDICATE, not
`decomp_pch.cpp`'s data.**

### 3.4 The set relation, which is stronger than the count

The ceiling is published as *"the most TU match can reach"*. Computed as sets:

```
MATCHING TUs NOT IN THE CEILING SET: 1 ['src/system/decomp_pch.cpp']
is match set a subset of the ceiling set? False
```

`25 ≤ 26` holds numerically **while the match set is not a subset of the
ceiling set**. The two numbers are similar in size by coincidence; the bound is
unsound *as a bound*. And it errs **SMALL** — the predicate `fn_total ==
emit-emitted` excludes a TU that is already over the ceiling it claims to
impose.

**Repairing the predicate is deliberately NOT done here** (out of scope; a
separate priced decision). Its shape is now known: any repair must be a
disjunction over `build`'s four emit paths, not a comparison of two counts.

### 3.5 The assertion

`scripts/status.sh` now parses the ceiling's own control, publishes it as its
own registry row (**28 metrics**, was 27), and renders **both** ceiling rows as
`VOID — n violation(s) … (#3510)` when it is nonzero.

Verified against the **real HEAD scan log**, not only the shipped probe: the
parsers read `26 of 870` and `29 of 870` — digit-for-digit what `STATUS.md`
carries today — beside a control of `1` and `1 of 25`. Both rows go VOID at the
next regeneration.

The decision is **one implementation** (`ceiling_row`), called by `collect_gap`
and by `--check`, extracted precisely so the check exercises the real branch
rather than a copy of it (`#3494`: a guard can be correct about its own
question and not be the guard you wrote).

Two mutations, distinct messages, revert green:

| mutation | `--check` says |
|---|---|
| delete the VOID branch | `CHECK FAIL: a RED control still published a ceiling number: '25 of 871 …'` |
| break the `sed` that builds the red probe | `CHECK FAIL: the voided-probe rewrite did not take — the red case would test the clean path` |

**The second is the one worth keeping.** The red case is manufactured by
rewriting the probe log, and a `sed` that matched nothing would leave a clean
log and report a control that fired while testing the clean path twice —
`#3516`'s mutation-not-applied failure, arriving through the control rather
than the subject.

### 3.6 `--check` had no caller

`status.sh --check` exists for exactly this class of defect, says so in its own
header, and was wired into **no** `cargo test` target and **no** `gate.sh` row.
So the one instrument that could have caught `#3510` was itself ungated for as
long as `#3510` was open. Three `cargo test` targets now, no toolchain, 1.08 s.

**`docs/STATUS.md` is NOT regenerated here** — decision 13 lists that as the
coordinator's and it needs a quiet box. What changes is that the next
regeneration cannot publish the voided number.

## 7. The fourth artifact, and why it took a number outside the block

`scripts/gate_identity_diff.sh` (**#3579**) was not in the brief. It was built
because §4.2's proof-of-failure had to be done by hand, and doing it by hand is
`#3451`'s complaint verbatim — *"the instrument four lanes have retyped and
none committed"* — one artifact over from the cost protocol that row was filed
against.

The identity diff is the **only** instrument that can see `w-latent`'s class of
failure: `GATE: PASS`, `GATE_EXIT=0`, `mismatch 0`, six matched TUs gone. It
lived as three prose steps in `HOWTO_DIFF.md`, and each of the three is a place
a retyped version silently goes wrong — the free-prose `flags` column, the
PID-named run dir, the two `n/a` rows. A lane that skips step 1 sees rows
"move" between two runs that graded identically; a lane that skips step 3
computes a denominator of 23 and diffs two refusal messages.

**Its own test caught a defect in it on the first run**, and the defect is the
shape this whole rung is about. `rows()`'s final `grep` exits 1 when it matches
nothing; under `set -eu` that aborted the command substitution *before* the
row-count check. So pointing the tool at a file that is not a gate table exited
**2 — the correct verdict — with no diagnostic at all**, on exactly the input a
mistyped path produces. The self-test did not find it, because the self-test
feeds it well-formed tables. The test that drove a non-table through it did.
