## §2 The grammar, as measured

24 cells, one axis each, frozen and `sha256`'d and committed **before the first
compile** (`work/w-tag02/grid.sha256`, commits `75a92a8` / `dc4228e`), captured
at the workload's own profile through real `cl.exe` + `c2.dll` under wibo.
`work/w-tag02/GRAMMAR.md` is the byte table.

```text
  element := 02 <target-token> <offset> <n>

    <target-token>  read_token_var — 2 bytes, or 4 when the second stream byte
                    has its high bit. BOTH FORMS MEASURED.
    <offset>        a varint: one byte below 0x80, else `80` + a 4-byte LE i32.
                    MEASURED at 0, 4, 8, 128, 160, 1200, 65536 and -4.
    <n>             04 on every one of the 31 tag-02 elements in the grid.
```

The element contributes `<offset>` to the object's raw bytes as a **big-endian
i32**, and the obj carries one `IMAGE_REL_PPC_ADDR32` (`0x0002`, **no PAIR**) at
that byte position naming the target's COFF symbol.

### §2.1 Two registered claims LOST, and they are the reason the grid existed

* **P2 is REFUTED.** The prereg called the byte between the target token and
  `<n>` a *constant separator* and predicted `&s.b` would still spell `00`
  there. `t09_struct_offset` spells `02 ec 09 · 04 · 04` and
  `t10_array_offset` spells `02 e3 09 · 08 · 04`: **it is the offset**. Board
  **#644**'s shape — the payload is not one contiguous field — with `00` and
  `04` turning out to be two different fields carrying two different things.
* **P2′ is REFUTED with it.** It named three places the offset might be, in
  order of belief, and the offset is in none of them: not in `<n>`, not in an
  extra element, not folded into the raw bytes by some other route. It is in the
  slot P2 had already misidentified.
* **P17 is REFUTED.** Registered in addendum A *before* `t18`–`t22` were
  compiled: *"the offset is a byte at `0x80`, not a varint escape; dies if
  `0x80` is followed by a payload"*. `t18_offset_128` spells
  `80 80 00 00 00`. It is a varint.
* **P18 HELD** — the escape is `80` + LE**32**, the same width the scalar value
  uses at width 4, and *not* `inlit.rs`'s `80` + LE16.

**The offset field's short form is restricted to `00..7F`, deliberately**, even
though `readers::read_varint`'s short form is a **signed** byte (the brief's own
w-ilx note). Every measured negative offset **escapes** — `-4` is
`80 fc ff ff ff`, never `fc` — so a high-bit byte there is a desync, and reading
it as `-5` would put four wrong bytes in a `.data` *and* claim a wrong addend.
`ininit.rs` already applies that rule to scalar values; the two agree on purpose.

**`<n>` = `04` is an OBSERVED constant and is written down as one.** Nothing on a
32-bit target can vary it, so no cell in the grid separates *"the pointer slot's
width"* from *"a tag byte that happens to be 4"*. Any other value refuses.

| `t07_char_array` (`char s[4] = "abc";`) | element tag **`03`**, inline bytes, no relocation | the tag-03 boundary is about where the bytes come from, not about being a `char*` |
| `t12_ptr_to_member` (`int A::*pm = &A::b;`) | element tag **`01`**, `.data` `00 00 00 04`, no relocation | **P7 HELD** |

### §2.3 Board #931's own cell reproduces, and the RTTI graph is all there

`t11_vfptr` (`struct A{virtual void f();int a;}; A g;`) mints twelve sections,
four of them `.rdata$r`, and `.in` spells the whole `??_R*` graph. The three
integers `OBJ_RDATA_R_SHAPE.md` §4 called *"not recoverable from a mangled
symbol"* are visible in it: `??_R1`'s `pdisp = -1` (`01 01 04 80 ffffffff`) and
`attributes = 0x40` (`01 02 04 40`), and `??_R3`'s `numBaseClasses = 1`
(`01 02 04 01`). **#931 is confirmed on a fresh capture** — and the TU is still

## §3 Two instruments, and the one place they disagreed

The `w-divsplit` discipline: a decoded grammar is believed when two independent
instruments agree, and **neither may be the other's witness**.

* **Instrument 1** — `work/w-tag02/scan.py`, a forward whole-stream record
  parser written from the grammar, in another language, importing nothing from
  the crate.
* **Instrument 2** — `crates/c2-il/tests/in_init_probe.rs`, the production
  reader's own cursor, reported through `IlBundle::in_init_report`.

`work/w-tag02/two_instruments.py` reconciles them: **24 cells, 24 agree, 0
disagree**, 30 reader-acceptable tag-02 elements on both sides.

**The reconciliation earned its keep twice.**

1. Instrument 1 scored **0** tag-02 elements on `t18`–`t22`, the five cells built
   to put a large offset in the field — because its first revision read the
   offset as one byte. That is how §2.1's P17 was refuted: the disagreement sent
   me to the hexdump. The wrong reading is kept as a comment in the file rather
   than silently corrected.
2. On `t11_vfptr` the instruments read **9** and **8**, and the difference is
   explained rather than waved at: the `??_R0` record carries a tag-`03` name
   string (`03 08 ".?AUA@@\0"`), which the reader still refuses, so its tag-02
   element is in a record instrument 2 never accepts. `two_instruments.py`
   computes instrument 1's count **both ways** and prints the residual.

## §4 The control that fired — `values` counts TOKENS, `records` counts RECORDS

**`in-init-accounting-broken` went 0 → 826 of 878 TUs** the moment tag `02` was
read. This is board **#937** and it is the most valuable thing the lane found.

The identity the reader had carried since it was written is

```text
  values + residue + conflicts == records
```

and `values` is a `BTreeMap` keyed by **token** while `records` counts
**records**. Two records carrying one token and *the same bytes* are not a
conflict — the reader's own test says so, by name — and they are two records. So
the identity reads `1 == 2` on that shape.

It held on the workload because the accepted population was 43,113 tokens of
scalars. The widening took it to 496,135 and the shape appears **9,914** times.

**Repaired, not adjusted:**

```text
  records == accepted + residue          (both counts of RECORDS)
```

with `duplicate_records` published beside it rather than absorbed into it, and
`IlBundle::data_tu` gating on the repaired identity. A unit test now asserts the
new identity closes **and that the old one does not**, on the two-record case,
so the repair cannot be undone by someone restoring the "simpler" line.

Worth stating plainly: **the control was written by a previous lane, it was 0 on
every scan for the whole life of the reader, and it was 0 because the population
that breaks it was not being reached.** A green control is a statement about the
population, which is `docs/STATUS.md` trap 1 one level down.

## §5 The writer, and the #232 clause

`.in` tag `02` decodes to **exactly `size` bytes** — the addend, usually four
zeroes. So the naive widening hands `data_tu` an object that satisfies its
existing *"bytes decoded to exactly its size"* clause, and `emit_data_obj` emits
a `.data` whose contents are right and whose **relocation table is empty**. A
wrong obj, produced out of what had been an honest refusal: board **#232**'s
exact direction, and prereg **P13** registered the mechanism before any code.

The mitigation is that the bytes and the addresses travel together, in a
separate channel, all the way down:

```text
  InInitCensus::refs  ->  DataObject::relocs  ->  DataObj::relocs  ->  the table
```

and `emit_data_obj` **refuses** rather than dropping any entry it cannot place:

| refusal | why | cell |
|---|---|---|
| target is not one of this call's objects | an **undefined external** needs a symbol record spliced in at index **5**, between `.debug$S`'s aux and the C2 watermark — and a *function* target additionally carries `Type = 0x0020` where a data one carries `0x0000` | `t03`, `t05` |
| `at + 4 > size` | the slot runs off the end of its object | — |
| relocation into a `.bss` object | there are no file bytes to patch | — |
| `<n>` ≠ `04`, or a high-bit short-form offset | unmeasured, and a desync, respectively | — |

### §5.1 The differential caught a field a reader cannot see

First run of the graded grid: **13 mismatches**. The port's `.data` had the right
raw bytes, the right relocation, the right `VirtualAddress`, the right
`SymbolTableIndex` and the right `Type` — and the **section symbol's aux record
read `NumberOfRelocations = 0`** while the section *header* read `1`. Two places
hold that count and only one had been written. `emit_data_obj` passes it from the
same vector the records come from now, and a unit test asserts **both** fields
out of the emitted bytes.

The other thing the same run caught: my first relocation unit tests asserted a
`SymbolTableIndex` of `6` where the obj said `10`, because the test helper
`symbols_of` skips aux records and a relocation's index does not. A
`sym_index_of` helper reads the raw table; the confusion is recorded in its doc.

### §5.2 What converted

**Grid: match 2 → 15, mismatch 0.** The 13 conversions are

`t01_ptr_to_global`, `t04_ptr_to_static`, `t08_ptr_array`, `t09_struct_offset`,
`t10_array_offset`, `t13_mixed_struct`, `t15_two_ptrs`, `t16_ptr_to_self`,
`t18_offset_128`, `t19_offset_160`, `t20_offset_1200`, `t21_offset_negative`,
`t22_offset_65540`

— every one **byte-exact against real `c2`** with the `TimeDateStamp` zeroed,
and they include the negative addend (`.data` = `ff ff ff fc`), the 65,536
offset, the self-reference (`N n = {&n};`), the two-slot array and the mixed
aggregate whose relocation is at offset **4**, not 0.

The two that already matched (`t12_ptr_to_member`, `t14_const_ptr`) still match;
the eight that refuse do so for the reasons in §5's table plus §2.2's; `t11` is
still `vocab-gap`.

## §8 What this lane did NOT do, priced

1. **The undefined-external relocation target.** `t03` (`extern int ge;`) and
   `t05` (a function pointer) are read fine and refused by the writer. The cost
   is a symbol record at index **5** — which shifts every shell index after it —
   plus the `Type = 0x0020` distinction for a function target, plus whatever
   decides the order when there is more than one. **Three facts, one of them
   unmeasured** (the multi-external order).
2. **The `.rdata` COMDAT target.** `t06` (`const char* s = "abc";`) needs a
   `/GF`-shaped string COMDAT, which `data_tu` clause 5 refuses for reasons that
   predate this lane.
3. **Element tag `03` inside a mixed record.** `t11`'s `??_R0` carries one, and
   it is the single residual between the two instruments. `inlit.rs` reads tag
   `03` as a whole record; reading it as an *element* is a small job and was not
   taken, because nothing consumes it — the `.rdata$r` writer is declined
   (**#926**) and `??_R0` lands in a COMDAT this writer cannot place.
4. **The relocation ORDER within a section** is emitted ascending by
   `VirtualAddress` and **the grid does not separate that from the walk order** —
   `t08` and `t15` have the two coincide. Written down as unseparated in the
   writer's own comment, not as established.
5. **A `<n>` other than `04`** cannot be produced by any construct on this
   target. Refused; not closed.
