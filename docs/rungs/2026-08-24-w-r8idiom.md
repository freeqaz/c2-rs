## What it admits, and what it refuses

**Admits.** `mr r8,r8` is **`emit 0x7d084378`** — final-expansion arm
`0x10c0e194` builds an instruction of opcode `0x290` (the mnemonic table calls
it `emit`, the raw-word emitter) carrying a **baked 32-bit literal**. It is
reached by **pseudo-opcode `0x2e4`** and nothing else. **Arm 14's handler
`FUN_10c16d83` read in full** (214 B) — and it has **zero** guards; the delete
is unconditional, exactly like arm 6's. The peephole `FUN_10c182b4` **bounds its
opcode three times** (`0x295`, `0x295`, `0x292`) before it indexes any arm, and
`0x2e4` is above all three. c2's **nine pseudo-nops decoded** from their encoder
arms, excluding the whole family, plus the new byte table `0x10c37dcc`. On the
obj side, **C++ EH is necessary and not sufficient**, the self-moves come in
**runs bracketing a call**, and **run length == catch-handler count on 95.19 %**.

**Refuses.** **What `0x2e4` IS is not named.** Three things about it are read
and its identity is not, and the story that fits — a branch-like marker given
an address — is stated as a story and kept out of the claims. `0x10c3b270` (the
optional third item) was **not read**, as the prereg predicted. The 506
callback sites `w-tailread` left uncounted stay uncounted.

**The contradiction `P_OPATTR.md` §6 published is dissolved, not overturned.**
That page found an unconditional redundant-move eliminator **and** 3,792
surviving self-moves, and could only say *"what is refuted is the LICENCE, not
the read"*. Both halves were right. **The survivor was never a `mr` inside c2.**
§6 listed three candidate explanations — *"runs after the peephole, or is not
subject to it, or satisfies none of the handler's guards"* — and the answer is
the middle one, the only one that leaves both earlier claims standing.

## The transferable part: the answer was already in the record, one column short

`ref/P_EXPAND.md` §3 has carried the row `0x10c0e194 | 1..1 | 0x2e4` since
`w-read-r6`. `dump_tailclass.py:496` uses that arm as a **CONTROL** — an arm
known to mint. Two lanes have therefore read, cited and depended on the exact
instruction that emits the idiom, while the idiom was written up as
*"unexplained"* one page away.

**A word-count instrument that never prints the word cannot answer "what is
this instruction".** `--words` was built to grade a *count*, and it graded it
correctly; the cost is that `1..1` reads as complete. The repair is cheap and
general: **when an instrument reduces a thing to a number, have it print the
thing too.** `dump_movearms.py --chain` does, and the finding is eleven
instructions long.

### The lane's own evidence, which is not a gate row

* `docs/whitebox/scripts/probe_r8idiom.py` — obj-side census, denominator and
  control. **Its corpus fence is tied to the pinned image by construction**:
  every `entry.bin` records `tool c2.dll <len>:<digest128>`, so the probe
  sha256-verifies the image, **recomputes that line from those very bytes**
  (`digest128` ported from `crates/c2-il/src/cachefmt.rs`, `--selftest`
  checking the port), and refuses to measure any obj recording a different one.
* `docs/whitebox/scripts/dump_movearms.py` — `--arms`, `--nops`, `--word`,
  `--chain`; sha256-fenced, disassembling the pinned PE directly.

**Six fences were each watched refusing deliberately broken input** before any
number above was quoted: truncated image (`REFUSE`, exit 1, both tools); one
flipped byte (`REFUSE`, exit 1, both tools); empty cache (`VACUOUS … NOT a
pass`, exit 2); an obj whose `entry.bin` names a **different** c2
(`0 measured, 1 foreign` → `VACUOUS`, exit 2); a cache whose *only* move form
is a self-move (measured, **not** called vacuous — `w-tailread`'s ordering bug,
avoided by testing for it); an unknown mode (`REFUSE`, exit 1).

**Three defects were found by running these, and all three were mine.**

1. **The guard classifier counted the compare's own not-equal exit as a
   guard**, so all four arms scored `GUARDED` — including arm 6, which
   `P_OPATTR.md` §6.1 reads as unconditional. **Four for four is the tell**: a
   classifier that returns the same answer for every input is measuring itself.
   It contradicted a published read, and that is how it surfaced.
2. **Two of four thunk addresses were hard-coded and wrong.** They came from
   `P_OPATTR.md` §6.1, which names *handlers* and never claimed to give thunks.
   `--arms` printed `MISMATCH (thunk calls 0x10c1772b)`. Thunks are now
   *found*, by scanning for every `call rel32` landing on the handler — which
   also produced the finding that all four are consecutive.
3. **`probe_r8idiom.py`'s `entry.bin` parser paired every value with the next
   key** (the newline-keyed preamble is not NUL-terminated). `--show` printed
   `src-arg: ?` on an obj that plainly has one.

### The near-miss worth more than the fences

The **first** search for the literal `0x7d084378` found **all four sites**, and
I dismissed them. I converted the file offsets to VAs **in my head**, got
`0x10bf8fda` instead of `0x10bf12da`, disassembled 31 kB away, and objdump —
starting mid-instruction — printed plausible nonsense (`adc ah,al`,
`test BYTE PTR [edi-0x407b31f0],bh`). I wrote "byte coincidences" in my notes
and went looking elsewhere for an hour.

**Print hex. Never disassemble from an address computed by hand without
checking that it decodes.** The tool now prints the VA and the owning function
for every hit and labels each one `IMMEDIATE of …` or `coincidence`, so the
same mistake cannot be made silently twice.

## Found and not taken

Ranked, and the first is the one a follow-up should buy.

1. **Name `0x2e4`.** It is minted in `ehexcept.c` (`FUN_10be3e4c`, 4 sites in a
   list walk), `except.c`, `fg.c` ×2, `inline.c`, `p2symtab.c` ×2 and `lower.c`;
   it is tested with `je` in **18 TUs**; and three published predicates group it
   with `bc`/`bca`. Reading **`fg.c`'s edge construction** around
   `0x10b372ea` / `0x10b39937` should give its contract in one lane. Until then
   `WB_R8IDIOM_FINDINGS.md` §6 stands as a refusal.
2. **`P_EXPAND.md` §3's signed re-score is now priceable**, which is what
   `#3466` deliberately deferred until arm 14 was read. Both primitives are
   named (`0x10bd3824` mint / `0x10bd5516` delete) and this lane adds the
   observation that makes the instrument useful: **make `--words` print the
   word**, not just the count. Four arms scored `0..0` in fact delete.
3. **The other three `push 0x7d084378` sites are unread** — `0x10bf12d9`,
   `0x10bf1a62`, `0x10bf80d8`, all `cgintrin.c`. The first emits **two `nop`
   (`0x276`) then the literal**, which is a *different* idiom from the EH one
   and is probably an intrinsic. Cheap: three function bodies.
4. **`0x10c3b270`** — same `0x298` extent, two consumers bound-checked at
   `0x295` with out-of-range default `0x64`, in no document. Dropped here as
   registered (P3.3); still open, still cheap.
5. **`nopcapenter` / `nopcapexit` (`or r13,r13,r13` / `or r14,r14,r14`) are
   now decoded but not explained.** "cap" is almost certainly the `/callcap`
   `/fastcap` profiling instrumentation, and if so a whole flag's codegen is
   two opcodes wide. Nothing in this repo records it.
6. **`WB_EXPAND_FINDINGS.md:79` and board `#3432` still carry the false
   "unrecorded" sentence** that `P_EXPAND.md` §1.2 did. `w-tailread` flagged
   this as its item 5; it was outside that lane's rows and it is outside mine.
   **Two lanes have now declined it for the same reason** — it needs a row of
   somebody's budget, not another flag.
