## §2 The incumbent was a refusal, and that set the bar

Board **#1148** closed a **live wrong emit that was already on master** by
refusing every `.bss` holding an internal-linkage object. So the thing this lane
had to beat was **a refusal that is right 100 % of the time on what it refuses**.

The prereg registered the consequence explicitly, because it inverts the usual
scoring: *a rule that is mostly right is strictly worse than what ships today,
because the only currency it can pay in is wrong bytes.* The decline floor was
therefore **100 % byte-exact on everything admitted, at two or more profiles**,
with anything unseparated refused rather than guessed.

That floor was met on the admitted set and **two regions were declined on it**
(§5), which is the lane working as designed rather than a shortfall.

## §4 What c2 actually does — and Rule S1 has THREE insertion points for a `.bss`, not one

`OBJ_DATA_BSS_SHAPE.md` §2.2's Rule S1 reads as though the *kind* of section
picks its slot. It does not. **The slot is picked by which contributor
materialised the section first**, and for a `.bss` there are three answers:

```text
  .drectve .debug$S [/GF .rdata] [.bss:A] .XBLD$W(C2) [.bss:B]
                    .XBLD$W(C1) [.data] <code groups> [.bss:C] [.CRT$XCU]

  A  a STATIC object first reached from a `.data` initializer
  B  an EAGER EXTERNAL object          <- this is S1's middle clause
  C  a STATIC first reached from a FUNCTION body, and every DEFERRED
     (dynamic-initializer) object, whatever its linkage
```

The whole grid, read off the objs (`work/w-order3/objread.py`):

| cell | source | slot |
|---|---|---|
| `O01` | `static A g; A* p=&g;` | **`A`** |
| `O02` | `A g; A* p=&g;` | `B` |
| `O03` | `A g;` | `B` |
| `O04` | `static A g; void f(){g.a=1;}` | **`C`** |
| `O05` | `A g; void f(){g.a=1;}` | `B` |
| `O06` | `static A g; A* p=&g; void f(){…}` | **`A`** — the earlier referrer wins |
| `O07` | `A g; A* p=&g; void f(){…}` | `B` |
| `O08` | `A g; static A h; A* p=&h;` | **`A`** |
| `O09` `O16` | two / three statics + `.data` pointers | **`A`** |
| `O10` `O11` | `O01` at align 8 / 16 | **`A`** |
| `O12` `O17` | scalar / array static | **`A`** |
| `O13` | `O01` + a second `.data` object | **`A`** |
| `O14` | `O01` + a `/GF` string literal | **`A`**, *after* the `.rdata` |
| `O15` | `static A g; int d=7;` (unreferenced) | no `.bss` — the drop, 5 sections |
| `O18` | the `.data` pointer is itself `static` | **`A`** |

### §4.1 `O04` is the lane's most valuable cell, and it is one line of C++

**`O04` was not in the brief and nothing predicted it.** A `static` `.bss`
object kept alive by a **function reference** — no `.data`, no relocation
anywhere — lands *after* `.text`:

```text
  .drectve .debug$S .XBLD$W(C2) .XBLD$W(C1) .text .bss
```

Rule S1 has no insertion point there. The document *did* have this position, in
§2.1's rows 11–13, and read it as a property of **deferred** objects — the
dyninit `.bss`. It is not: `O04`'s `g` has no dynamic initializer at all. A
static is materialised **lazily, at its first reference**, and that reference is
in the function body. `O06` settles the tie-break: give the same object both
referrers and slot `A` wins, the earlier of the two.

§2.2's own sentence — *"the position is decided by the section's earliest
contributor"* — was right, and was written as a remark about dyninit.

**This is board #1148's shape a second time.** That defect was invisible because
`wsect_drop_static.cpp` recorded the static-`.bss` drop and nobody had written
the one line that routes around it, `A* p = &g;`. Slot `C` was invisible for the
same reason and the other line: `void f(){ g.a = 1; }`. A recorded
unreachability is a statement about the cells someone thought of, and the brief's
instruction to *write the line that gets around it* paid twice.

Slot `C` is **not** a live wrong emit — `coff::data::emit_data_obj` serves
functionless TUs only and cannot reach it. It is a boundary with a cell on its
far side now: `fixtures/cpp/worder3_bss_slot_after_text.cpp`, board **#1179**.

### §4.2 Eight rivals, each killed by its own cell

Board #259's method: a rival dies to a probe, not to an argument. Every rival
below agrees with S1′ on all three of #1148's cells — which is exactly why #1148
declined to pick one, and #1152 said so in as many words.

| rival | it says `.bss` moves iff … | killed by | it predicted | c2 said |
|---|---|---|---|---|
| **reloc** | a `.data` relocation targets an object in the `.bss` | **`O02`** | moves | slot `B` |
| **address-taken** | the object's address is taken | **`O02`** | moves | slot `B` |
| **functionless** | the TU defines no functions | **`O03`** | moves | slot `B` |
| **functionless** (other side) | — | **`O04`** | slot `B` | slot **`C`** |
| **all-static** | *every* object in the `.bss` is internal | **`O08`** | slot `B` | slot `A` |
| **`.data` present** | the obj has a non-COMDAT `.data` | **`O03`**,**`O04`** | `O04` slot `B` | slot `C` |
| **alignment** | the nibble is above some threshold | **`O01`/`O12`/`O17`** (align 4) | slot `B` | slot `A` |
| **object count** | more than one object | **`O01`** | slot `B` | slot `A` |
| **aggregate type** | the object is a class, not a scalar | **`O12`** | slot `B` | slot `A` |

**`O02` is the cell #1152 asked for.** Its warning was *"nothing here separates
'internal linkage moves it' from 'a `.data` relocation into `.bss` moves it',
because every surviving cell has both."* `O02` is `A g; A* p = &g;` — the
relocation, and the address-taken, **without** the internal linkage — and the
section does not move. Two rivals, one cell.

## §5 Rule Y3, and the two regions declined

### §5.1 Rule Y1's STATIC clause is REFUTED on a functionless TU — and it was NOT live

> **Rule Y1 (eager `.bss`).** Every EXTERNAL first in reverse `.gl` order; then
> every STATIC in **declaration** order.

`O09` is the **first functionless TU with two statics in one `.bss`** anyone has
compiled, and it is the cell on which the two candidate orders disagree:

```text
   .gl record order    h g      <- c2's answer; addresses h@0 g@4
   declaration order   g h      <- Rule Y1's static clause
```

> **Rule Y3 (slot-`A` `.bss`, functionless).** The group's defined symbols are
> emitted in **`.gl` record order** — the same permutation as Rule A1's walk, so
> also **ascending** address.

Confirmed out of sample at n = 3 by `O16`: `.gl`, the addresses and the symbol
table are all `i h g` while declaration order is `g h i`. The same obj is its own
control — its `.data` group **is** in declaration order — so one obj carries both
permutations, which is why no single walk serves both sections.

**Is that a sixth alarm? No, and the distinction is the point.** The brief asked
for a stop-and-report if Y1 is wrong on functionless TUs. It **is** wrong, and it
is **not live**: #1148 fenced it on 2026-08-08 by refusing every internal-linkage
`.bss`, so `emit_data_obj` had not applied Y1's static clause since `8fa6b119`
and no wrong bytes ever reached an obj through it. A scope error already closed
fail-closed is not a firing alarm; it is the fence doing its job. Board **#1180**.

Y1's **external** clause is in scope — §7.1's families B and C are functionless
cells — and is untouched. **Still open and untested by either lane: whether Y1's
mixed row holds for a TU *with* functions**, which is where it was fitted.

### §5.2 MIXED linkage is REFUSED, with the answer in hand

`O08` (`A g; static A h; A* p = &h;`) is measured and understood:

```text
  sym[ 5] .bss + aux    sym[ 7] h            val=0 sec=3 STATIC
  sym[ 8] .XBLD$W + aux sym[10] __C2_11886
  sym[11] ?g@@3UA@@A    val=4 sec=3 EXTERNAL   <- OUTSIDE the group,
                                                  at the slot-`B` position
```

It is **not a symbol-order question**: both objects are in `.gl` order at
ascending addresses. What differs is *where the external's record is written* —
at the slot the whole group would have taken had the external created the
section, which is §4's first-contributor model one level down.

**It is still one obj at n = 2.** `MAX_OBJECTS_PER_SECTION` is 2 (board #184), so
every cell available here has n = 2, and at n = 2 that reading is
indistinguishable from several orderings that would differ at n = 3. Prereg floor
**F3** applies and the writer refuses. `fixtures/cpp/worder3_bss_slot_mixed.cpp`
grades the refusal, so a later widening that forgets the record position becomes
a `mismatch` in every mode lane rather than a comment nobody runs. Board **#1178**.

## §6 The workload CANNOT move — measured, not assumed

`w-align16` set the standard here: *"cannot" is a much more useful answer than
"did not"*. The section census already carries this rung's question, so it is one
query and not an inference from a flat scan.
`work/w-bss/census/sections.jsonl` — 871 objs, each with its full section `order`
array and every `.bss` symbol's storage class. 247 non-COMDAT `.bss` sections:

| | extern-only | static-only | mixed |
|---|---:|---:|---:|
| **slot `A`** — before `.XBLD$W:C2` | **0** | **0** | **0** |
| slot `B` — between the watermarks | 118 | **0** | 20 |
| slot `C` — after the code groups | 76 | 25 | 8 |

* **Slot `A` has zero workload instances**, so #1177 converts fixtures and
  **cannot** convert one workload TU. Functionless objs on the whole workload:
  **6**, none with a surviving static `.bss`.
* **Two out-of-sample predictions of the model hold on 247 real sections it never
  saw**: no purely-static `.bss` is ever in Rule S1's middle slot (0 of 25), and
  every section that *is* in that slot contains an external (138 of 138). S1's
  middle clause is exactly the extern-eager slot and is not refuted.
* **Slot `C` is the workload's common case for a static `.bss`** — 33 of the 53
  static-bearing sections — which is what makes #1179 worth a fixture.

Registered as prereg **P8**/**P9** before the census was run. Board **#1181**.
