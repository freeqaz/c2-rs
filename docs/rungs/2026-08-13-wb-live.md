## What it admits, and what it refuses

**This lane ships no `crates/` change, adds no `DISCLOSURE.md` row, and admits
no function class.** It was commissioned to remove a *reason* rather than a
blocker: `docs/CFG_SHAPE.md` §6.2 item **F** — values live across block
boundaries, *"the item that makes the restructure a restructure"* — says in its
own text that it *"depends on work nobody has done, not merely on work nobody
has scheduled"*, citing `docs/CODEGEN_W6_COMPARE.md` §6's record of c2's
allocator as *"demonstrably richer than a descending counter and **not**
characterized"*.

**It is characterized now.** [`WB_LIVE_FINDINGS.md`](../whitebox/WB_LIVE_FINDINGS.md)
answers all five commissioned questions with addresses, and seven of them with
obj confirmation:

| # | question | answer | address | obj |
|---|---|---|---|---|
| 1 | interference representation | **none stored** — a per-candidate *allowed physical register* bitset, narrowed by every physical def the range spans; the neighbour set is **recomputed** per colouring | `0x10b54d32`, `0x10b2d630`, `0x10b30517` | yes (#3049, #3054) |
| 2 | how liveness is computed | **backward round-robin dataflow fixpoint**, `live_in = use ∪ (live_out ∖ def)`, reverse layout order, exact set-equality convergence, then **intersected with a forward availability problem** | `0x10b54904`, `0x10c207ec`, `0x10b54848`, `0x10b549b5` | no — declared |
| 3 | what a "value" is | a **c2-minted symbol of kind 2** with a monotonic function-scoped id; minted at joins by the renamer and again during allocation | `0x10b54d32`, `0x10b55732` | indirect |
| 4 | what feeds the cost | neighbour **preference weights**, a `100 × spill-benefit` singleton term, own preferences, and `2^loop-depth` frequency (a real profile count under POGO) | `0x10b2e7f8`, `0x10b2d630` | **no** — inert on all 25 cells |
| 5 | where callee-saved enters | **nowhere as a policy.** A call's clobber list is an **operand** (kind `0x0b`); a crossing value loses every volatile and #1820's fixed order hands it `r31` | `0x10b2d630`, `0x10c37de0` | yes, 4 cells + a negative control (#3051) |

**What it refuses to claim** is in `WB_LIVE_FINDINGS.md` §10 and is the section
to read before reusing any of this: the cost function has **no obj support at
all**; the non-call physical-register def (§6.2 F's `r4 → r11` half) has no
cell; the spiller, the live-range splitter, `dag.c`'s lowering order and the
globregs *promotion policy* were not read; and `wbl_x2`'s assignment order
(`a → r30`, `b → r31`) is recorded as unexplained rather than smoothed over.

## Estimate vs outcome

**Predicted reach: exactly 0 TUs, registered before the first grep** (PREREG
P7.1, `p = 0.80`) and realized at 0. Function census `714556` **+0**, emitted
census `+0`, TU match unchanged, and every `gap-metric` key unchanged — this
lane touches no code, so the neutrality is total by construction rather than by
measurement, and §4 below records it as such.

**Where the estimate was wrong is inside the lane, not at its edge.** Two grid
cells (`wbl_v1`, `wbl_v3`) were frozen predicting that N independent statements
give N *sequential* live ranges and therefore one register. c2 emitted six
simultaneously-live address registers for three statements and exhausted the
volatiles for eight. The cause is in the obj: **c2 hoists every `lis <sym>@ha`
to the top of the block**, ahead of every `lwz`, so the ranges overlap.

Per `C2_MAP_METHOD.md` §7 the cells are **not** re-scored in the reading's
favour. They keep their MISS, and what they buy is board **#3053**: the live
ranges are a property of the **lowered instruction order**, so the blocking item
for §6.2 F has moved from `color.c` (read) to `dag.c` @ `0x10b3219f` (unread by
`wb-regalloc`, which says so in its §4, and unread here).

## Found and not taken

Ranked, with the frame axis applied.

1. **`dag.c`'s tree-to-tuple walk (`0x10b3219f`) — now the binding item for
   §6.2 F.** #3053 is the receipt. Sized: unknown, and that is the point —
   `wb-regalloc` §4 explicitly declined to claim it (*"'the emitter does not
   reorder' is a much weaker claim than 'the port can predict the order'"*) and
   this lane found the first concrete consequence of not having it. **A lane
   that reads it should freeze a grid on the hoisting axis** — the `lis` hoist
   is one instance of whatever rule that walk implements, and one instance is
   #1767's two-point fit with one point.
2. **The globregs *promotion policy* (`0x10b55732`).** Read only far enough to
   establish that it mints candidates and inserts merge candidates at joins.
   *Which* symbols become candidates is uncharacterized, and a port that gets
   that wrong has the wrong value set before any of #3057's seven steps
   applies. Larger than it looks and **not** cheap.
3. **The `r4 → r11` half of §6.2 F item 1.** Needs a cell producing a
   non-call physical-register def with a value live across it. Not obviously
   constructible in C at `/O1` on PowerPC — every fixed-register def this
   project has seen is a call's argument setup, which also supplies the
   clobber. **Declared, not attempted.**
4. **The cost function.** Four terms named at `0x10b2e7f8`, **zero obj
   support**, and measured inert on all 25 cells this project has compiled for
   this question. A lane that ships it inherits `WB_LIVE_FINDINGS.md` §10's
   first paragraph and needs `DISCLOSURE` rows for `0x10b2e7f8`, `0x10b54904`,
   `0x10b54848`, `0b10b549b5` and `0x10b2d630` in the same commit. **Worth
   ~nothing today**, since the order decides every case at these widths.
5. **The spiller and the splitter** (`0x10b31544`, `0x10b2dfe2`, `0x10b2e4ae`,
   `0x10b3032a`). Named, not opened. `wbl_v3` is evidence they are far away:
   c2 took four callee-saved registers rather than spill one value.
