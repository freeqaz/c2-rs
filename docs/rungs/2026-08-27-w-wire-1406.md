## 1. `#1406` — what was wired and what deliberately was not

`crates/c2-harness/tests/provenance.rs`, two tests:

| test | invokes |
|---|---|
| `provenance_census_self_test_passes` | `python3 scripts/provenance_census.py --self-test` |
| `prose_audit_self_test_passes` | `python3 scripts/prose_audit.py --self-test` |

Each asserts exit 0, requires the literal `SELF-TEST: PASS` verdict line
(a status is not evidence in this repo), requires a **nonzero** count of `PASS`
lines and **zero** `FAIL` lines, and prints the count it saw:

```
scripts/prose_audit.py --self-test: PASS over 48 checks
scripts/provenance_census.py --self-test: PASS over 52 checks
```

The denominator is deliberately **not a pinned floor**. `#1496`'s ladder row
pins one and that is right for a fixed arm list; here peers add self-test
sections routinely, and a pinned number would redden on growth — a false alarm
on the one surface that must not cry wolf. `passes > 0 && fails == 0` catches
the empty-run shape (`#3470`, `#1002`) and needs no maintenance.

**Not wired: the two TREE runs.** Both are green at base (`prose_audit.py`:
`VERDICT: CLEAN over 574 checked claims`; `provenance_census.py`: exit 0 over
999 items) and both are cheap (1.22 s and 0.66 s measured), and
`tracked_artifact_audit.rs` is a same-repo precedent for gating a tree run
beside its self-test. They are out because a tree audit under `cargo test`
makes every lane's `cargo test` depend on every doc in the tree being
count-clean, and twenty worktrees were live. **The cost of that choice is
stated, not hidden — see §3.3.**

## 2. The `gate.sh` row: NO, and the reason is mechanical, not a preference

Registered in the prereg before the first edit, with its condition. `#1406`
reads *"under `cargo test` **or** `scripts/gate.sh`"*, so the `cargo test` half
discharges it alone.

The charter framed the cost as *"it changes the 21-row denominator"*. It is
worse than that, and the difference is what decides it.
`scripts/gate_identity_diff.sh` selects count-bearing rows **by shape** —

```
awk '/^[A-Za-z][A-Za-z0-9-]* +(PASS|FAIL|REFUSED|SKIP|NO-RESULT) /{print $1,$2,$3,$4}'
```

— and excludes **by hard-coded name**, `grep -Ev '^(hatch-red|ladder-red) '`.
So a new row is counted **even with `n/a` in the mismatch column**; there is no
"n/a rows are dropped" rule, only a two-name allow-list. Demonstrated, not
asserted (`work/w-wire/gatediff_22row.out`): a 21-row table plus one synthetic
`prov-audit … n/a` row gives

```
gate_identity_diff.sh: <TMP>/tip22.txt yielded 22 count-bearing rows, expected 21.
  Refusing to diff (board #3470, #1002).
EXIT=2
```

That is not a denominator lanes could absorb — it is a **refusal to diff at
all**, for every live lane holding a 21-row base table, on a tree they did not
touch. Repairing it means editing `gate_identity_diff.sh` (outside this fence),
updating `WANT_ROWS`, updating its self-test enumeration, updating
`HOWTO_DIFF.md`, and re-basing every live lane's base table. **P1a: HIT.**

**If a verdict line in the funnel is later judged worth it**, the coherent way
is to add the row's name to the exclusion list *in the same commit*, so
`WANT_ROWS` stays 21 and no base table is invalidated. Named here so the next
lane does not rediscover the trap.

## 3. What this lane got wrong, or nearly did

### 3.1 Both bindings handed to this lane were wrong — one recipe, one value

`w-provaudit` supplied, verbatim (quoted inline and backticked, which is the
only spelling that makes a binding a *mention* — see the note at the end of this
section): `COUNT[rs-array:crates/c2-core/src/codegen/mop.rs:OPCODES] = 85` and
`COUNT[rs-consts:crates/c2-core/src/codegen/mop.rs] = 91`.

Recounted at `bce2bfc68` before the first edit:

| supplied | recount | why it moved |
|---|---|---|
| `rs-array:…:OPCODES` = 85 | **does not resolve** | `OPCODES` is `pub static OPCODES: &[OpRow] = OPCODE_ROWS;` — an alias, not an array literal. `array_entries` returns `None`, which `run_recipe` turns into a C4 **finding**. The literal is `OPCODE_ROWS` and it has **85** entries. |
| `rs-consts:…mop.rs` = 91 | **92** | `w-mopfold` added `const OPCODE_ROWS` after the number was quoted. 85 `op::` constants + 7 others. |

Landed unbackticked and comment-only in `mop.rs`:
`COUNT[rs-consts:crates/c2-core/src/codegen/mop.rs] = 92` in the module doc and
`COUNT[rs-array:crates/c2-core/src/codegen/mop.rs:OPCODE_ROWS] = 85` on
`OPCODE_ROWS`. Both green, and both watched going **red**: with the numbers
bumped to 93 and 86 the audit prints two findings naming each recount
(`work/w-wire/binding_control.out`), and returns to `CLEAN` on revert.

**A FENCED CODE BLOCK IS NOT A MENTION — only inline backticks are**, and this
rung learned it by going red on itself. The first draft of this section quoted
all four bindings in ``` fences; `_is_mention` tests for a backtick immediately
before and after the match, so a fenced binding is a **live claim**, and the
audit reported three findings against this file: the two wrong supplied
bindings recounted as wrong (which is the tool being *right*), and the correct
`OPCODE_ROWS` one DETACHED, because a fenced block has no prose number beside
it. `#3669` established the mention rule for backticks on the strength of
`w-provaudit`'s rung doc going red the same way; the fenced-block case is the
same rule's blind spot and is worth knowing before writing about a binding.

**The general lesson is `#3626`'s, one instrument over.** A binding is a
machine-checked claim, and a *recommended* binding is not machine-checked at
all — it is prose about a binding, and it decayed within one day of being
written, in both of its two fields. `prose_audit.py` already knows this about
itself (`#3669`: a backticked binding is a mention), and the mention rule is
precisely why the recommendation could sit in a rung doc being wrong.

### 3.2 `575` and `34 of 104` are NOT bindable — and `660` is

Re-derived by hand at `bce2bfc68`, all three correct: the dump has **660** rows
(`ENCODE_OPCODES.txt`, 661 lines less one `#` header), the port transcribes

### 3.4 The runtime-root rule was written the way the charter said, and it was WRONG here — measured

The charter says resolve the repo root at runtime, never `CARGO_MANIFEST_DIR`
(`#3525`: the literal sets `.rodata` size, so three builds of one commit in
`b1` / `b2xx` / `b3yyyyyy` differ; `#3470`: a binary built in a scratch tree
resolves everything relative to that tree). It also says to follow
`c2-reference::repo_root`, which **prefers the nearest ancestor that carries
what the caller needs** rather than the nearest marker.

The first draft copied that preference, keyed on `scripts/<script>`. Then the
missing-instrument path was tested by moving `scripts/prose_audit.py` out of
the worktree, and the test printed:

```
scripts/prose_audit.py --self-test: PASS over 48 checks
test result: ok. 2 passed; 0 failed
```

**A green verdict about a tree the test was not testing.** Every lane worktree
lives at `<repo>/.claude/worktrees/<lane>`, so the main repo is an *ancestor*
and it carries `scripts/` too; the preference walked up past the worktree and
audited the parent.

The fix is nearest-marker-**only**, and the reason the two functions differ is
worth keeping: `c2-reference`'s fallback for "not found" is a **silent**
`SKIP: toolchain absent` + exit 0, so preferring is how that silence is
avoided. Here the fallback is a **loud assertion** — a missing script is a
failure naming the path, `#1496`'s `LADDER-NOSUBJECT` split — so preferring
buys nothing and costs the cross-tree jump. After the fix, the same experiment
gives:

```
scripts/prose_audit.py DOES NOT EXIST at <WORKTREE>/scripts/prose_audit.py
— the instrument is gone.
```

This is the third variant of one shape in this repo's log: `#3470` (a scratch
tree read as the real one, silently), `#3525` (a build path baked into
`.rodata`), and now a *worktree* read as its parent, silently. **A root
resolution that can fall back to a different tree must fail loudly, not
resolve quietly.**

## 4. The namespace collision — documented at both ends, renamed nowhere

Per decision 19. Two blocks, each naming the other's claim:

* `docs/whitebox/DISCLOSURE.md` § "`W-<NAME>-<N>` IS CLAIMED BY TWO REGISTRIES
  — CITE THIS ONE BY NAME"
* `docs/rungs/README.md` § "`W-<NAME>-<N>` is claimed by two registries — a
  bare one is a RUNG TAG"

The rule both state: **a provenance citation must be qualified —
`DISCLOSURE W-MOP-1`, never a bare `W-MOP-1`** — which is already the practice
at `crates/c2-il/src/middle_interfaces.rs:634` and is exactly what C1 keys on.

adds one forward-looking line: prefer the plain `W<N>` form for new tags,
because every new hyphenated one is another token a provenance grep cannot
disambiguate.
