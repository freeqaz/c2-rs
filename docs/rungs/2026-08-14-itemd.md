## 2. What it admits, and what it refuses

`crates/c2-core/src/codegen/reach.rs`, in five lines:

* **`Reach`** — the verdict for **one** reference site. `Direct(word)` /
  `Expanded(LongBranch)` / `Misaligned` / `Unmeasured(why)`.
* **`LongBranch`** — §3.3.1's expansion *as the two words it is*: the inverted
  `bc` over the `b`, then the `b` carrying the far target. Never a `bcctr`.
* **`Reach::of(form, disp)`** — the decision, in §3.3.1's own clause order:
  misalignment first, then "does it fit" asked of the **encoder**, then three
  ways of not fitting that §3.3.1 never swept.
* **`reach::direct(form, disp, site)`** — the gate: the word iff the site is in
  range, else a refusal naming the site, the verdict and **what c2 does
  instead**.
* **`cond::invert_sense` / `Cond::inverted`** — the `BO` sense flip, refusing
  exactly what `BO_IGNORES_CR` covers.

**It refuses** three things §3.3.1 has no cell for, each as its own verdict:

1. a **backward** overflow — the inserted word does not move a target already
   behind it, so the `b` would need `disp − 4`; arithmetic, not measurement;
2. a **misaligned** displacement — checked *before* any range question, because
   `encode_bc` returns `None` for it too and reading that as "too far" hands it
   an expansion whose `b` is misaligned the same way;
3. a `BO` with **no sense to invert** (`BO_ALWAYS`, `BO_DNZ`).

**It admits** a backward branch that *fits* as `Direct`, and that is not an
oversight: `ptr_walk_loop` and `ptr_walk_chain_loop` both emit a backward `bc`
and both are byte-exact against real `c2.dll`. A "forward only" reading of
§3.3.1 would have refused two shipped classes and moved bytes — item G's trap,
one item along, and the reason the title and the sentence were read separately
before either half was implemented (§1.3).

**It performs no expansion.** No corpus body is 32 KB; a relaxation pass would
be an ungraded code path by construction (w-frame row **F-c**). The bytes are
defined and graded; the pass has a stated home.

### 2.1 The re-expression, and what it proves

Twenty-three private `out_of_class("… out of range")` sites over **thirteen**
lowerings now call `reach::direct`. Byte-identity is by construction —
`direct` returns exactly what the site's own `encode_bc`/`encode_b_intra`
returned — and is asserted across **all 16,384 representable `BD` values** plus
the `b` field's edges. The sites' real-obj byte oracles are **untouched** and
still assert against `encode_bc` *directly*, which makes them an independent
check on the new path rather than a restatement of it.

> **The header said "twenty" when it was frozen and the measured count is
> twenty-three.** §1.2 was written from a first grep filtered on the words
> *range / field / displacement*, which misses `"does not fit a `bc`"` and two
> `patch(Option<[u8;4]>)` helpers. The header carries the measured number; the
> prereg body is left as written. Nothing about the delta depends on it.

Four combinations are exercised by shipped classes, which is what stops the
predicate being a tautology at one call site: **forward `bc`** (every guard),
**backward `bc`** (`ptr_walk_loop`, `ptr_walk_chain_loop` back edges),
**forward `b`** (join branches, the chain loop's entry jump), and the **mixed
patch helpers** that pick the form at run time (`guard_chain_shared_tail`,
`close_call_chain`).

### 6.1 A negative result worth the line

**The obvious reading of item D would have shipped a relaxation pass into
`LabelMap::resolve` and it would not have compiled.** That is the cheap version
of the finding. The expensive version is the one in §1.3 and `AD-a`: it would
not have compiled *for the right reason*, and an implementer who reached for
`&mut Vec<u8>` to make it compile would have shipped a pass that corrupts every
other pending site in the same map — a legal-looking branch to the wrong place,
which is the exact failure class §3.3.1 exists to prevent.
