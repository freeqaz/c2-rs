### 1.0 The success criterion, stated before the claims

**Required-zero byte delta.** This lane converts zero TUs *by design*. A
conversion would mean behaviour changed, which is this kind's failure mode and
not its prize. Grading is a line-for-line identity diff of the 878-TU scan's
`gap-metric` keys, its 878 per-TU verdict lines, and every gate lane's
fixture-verdict counts, base against tip. **Any byte that moved = FAILED**,
whatever else the lane achieved, reported in that word with the moved byte
named and not rationalised.

Absence is not the check. Every row below is graded **positively on content**:
the scan must print its `gap-metric` block and be digit-for-digit equal; the
gate must print `graded > 0` per lane and the per-lane counts must be equal; the
workspace run must print a pass count **and** a target count. A missing number
is a MISS, never a zero.

### 1.2 What is being built, stated before it exists

`crates/c2-core/src/codegen/reach.rs`:

* **`Reach`** — the verdict for **one** reference site: `Direct(word)`,
  `Expanded(LongBranch)`, `Misaligned`, `Unmeasured(why)`. Four-valued because
  §3.3.1 measured one of those four and this crate must not read the other three
  as it.
* **`LongBranch`** — §3.3.1's expansion **as bytes**: the inverted `bc` over the
  `b`, then the `b` carrying the far target. Two words, **never** a
  register-indirect `bcctr`.
* **`reach::direct(form, disp, site)`** — the gate every shipped emitter calls:
  the one word if and only if the site is in range, and otherwise a refusal that
  names the site, the verdict and §3.3.1.
* The threshold is **derived through `encode_bc`/`encode_b_intra`**, never
  spelled beside `BC_MAX_DISP`; the form is `labels::Form` (item C, board #191),
  never a second enum for the same fact.

`crates/c2-core/src/codegen/cond.rs` gains **`invert_sense`** / `Cond::inverted`
— the `BO` sense flip the expansion needs — refusing every `BO` that
[`BO_IGNORES_CR`] covers, because such a branch has no sense to invert.

### 1.3 The two halves of item D, read separately — `w-ir-g`'s rule

`w-ir-g` found that item G's **sentence** ("band 3 or refuse") would have
refused a shipped byte-exact class and that the item's **title** ("per accepted
shape") was the half that bound. Item D is read the same way, before
implementing either half:

* **Title** — *"A displacement range check with a **defined expansion**."* The
  check ships. **Defined** is the word this lane is graded on: §3.3.1's bytes,
  its arithmetic and its preconditions, decidable before emission.
* **Sentence** — *"This must be in the fixup pass, because the overflow is only
  visible after layout."* The **because** is right and the **must** is
  registered here as **predicted false**: the expansion inserts a word, and
  `LabelMap::resolve` takes `&mut [u8]`. A slice cannot grow. *Prediction P15:
  the expansion is not performable by the fixup pass at all — it is a
  re-layout, not a patch — and the fixup pass's own signature is the witness.*
  (p 0.9)

### 1.4 What is NOT built, registered as a decline before it is tempting

* **No relaxation pass.** Nothing in the corpus is 32 KB, so a pass that
  performed the expansion would be an ungraded code path by construction —
  w-frame row **F-c**, and `encode_b_intra`'s own header records that exact
  mistake being made and reverted once already.
* **No loops, no `label_slots` fence** (#746 — peer `w-fenceb` holds it), no
  code motion, no cost model, no scheduler, no CTR-loop discovery (§6.3).
* **Item F is not re-priced.** Its floor is `w-merger4`'s and this lane does not
  touch it.
* **`labels.rs` is not edited** — peer-owned. Its invariant 5 keeps its own
  refusal; pointing it at this module is a one-line change belonging to its
  owner, and is recorded in §6 rather than taken.
