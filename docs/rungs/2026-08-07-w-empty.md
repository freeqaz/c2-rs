### 2.2 `c19` is the discriminator and it COSTS us a match

`int g(int a){ return a; }` emits the identical single `blr` as `void g(){}`,
and at the workload's own flags **its caller is also one `blr` word** — so at
`/O1` it is observationally indistinguishable from an E caller. Only the `/Ob0`
compilation separates them, and it says mechanism **I**.

The shipped predicate reads the *body*, not the bytes, so it declines `c19` and
that function stays `fnbyte-differs` — a match the port could have had by
guessing. `INLINE_PREDICATE.md` §7 leaves I's 2.8 % residual `NOT MODELLED`, and
2.8 % of a guess is a wrong emit. `empty_elision.rs`'s
`a_returning_callee_is_not_elided` is that decision as a test, with the reason in
its failure message.

## 4. THE FINDING — the predicate was right and the name was wrong

The first shipped version (`f25ddca`) is identical to the final one except that
it looked the callee up in `IlFunction::mangled_name`. On the 878-TU workload it
produced:

```
  fnbyte-exact   34,466 -> 34,452   (-14)
  fnbyte-differs  4,711 ->  4,725   (+14)
  functions that LEFT differs: 0     functions that ENTERED: 14
```

**Fourteen previously byte-exact bodies turned wrong and not one of family A's
1,886 was reached** — an almost perfect anti-correlation, which is the signature
of a lookup landing on the wrong row rather than of a wrong rule. Thirteen of the
fourteen are `?Replace@?$ObjRefConcrete@…`; `work/w-empty/wdiff.py` prints all of
them by name.

A census row carries **two** names from **two** bindings. `bind.rs`'s own module
doc says they disagree; nobody had put a number on it:

> **`IlFunction::mangled_name`** is paired **positionally** over `.ex` segments.
> **`FnCensus::emit_name`** is the per-record emitted-symbol binding — the one
> FBM's walk already uses to decide which row *is* which `.text` COMDAT.
> **They differ on 74,955 rows of this workload**, and on many more the
> positional name is the empty string.

`TuEmptyCallees::of_named` takes the name as an **argument**, so each caller
passes the binding it trusts for everything else about that row: `PortC2::build`
passes `mangled_name` (the gate's binding, which its own in-TU-callee refusal
already compares resolved callee names against) and the FBM walk passes
`emit_name`. Re-keyed, the same predicate on the same corpus reads
**1,373 / 1,373 / 0 regressions**.

`fnbyte-name-disagree` is now printed on every scan. It is not this lane's
instrument — it is a **standing warning to the next lane that keys a name-matched
fact off a census row.** STATUS trap 2's shape, one level down: a claim that can
be attached to the wrong function is not a claim about the function it names.

## 6. §1 of the SPEC is refuted as written — E is a FIXPOINT

`docs/INLINE_PREDICATE.md` §1: *"c2 emits no call … for a call whose callee is
defined in this TU and whose **source body is empty**."* GRID-2's
`g07_empty_calls_empty` is three functions:

```cpp
void h() {}
void g() { h(); }
void f() { g(); }
```

`?h` is empty, `?g`'s source body is **not** — and **c2 emits `?f` and `?g` both
as a bare `blr`**, dropping both calls. So the predicate is not *"the callee's
source body is empty"* but *"the callee's body **reduces to nothing**"*, closed
under E itself.

**The shipped rule is the one-step version and stops there.** After the change,
`?g` converts and `?f` does not — visible in the cell diff as the one GRID-2 row
where a witness survives. Taking the fixpoint is a rule with **n = 1 cell**
behind it, and it is worth **143** workload functions on the evidence available;
it is registered as board **#924** with the grid that would earn it, not shipped
on one probe.

## 7. THE HAZARD, and why it is a test and not a paragraph

`f09_fnptr`:

```cpp
void g() {}
void f() { void (*p)() = g; p(); }
```

The callee is `empty-body`; c2 folds the pointer to a direct `b ?g` and **keeps
the relocation**. E does not fire through a function-pointer site — the same
thing `INLINE_PREDICATE.md` §2 says of an indirect site from mechanism I's side.

**E is a property of the call SITE as well as of the callee, and `elide.rs` does
not model the site.** The port is safe only because the IL parser refuses that
caller (`expr-call-in-expr-data-addr-then-plain-call-whole`), and `f10`'s
likewise (`body-0x67`). A widening of either production puts a wrong emit one
line away — board #232's shape.

`crates/c2-harness/tests/empty_elision.rs::an_indirect_call_site_is_still_refused_by_the_il_parser`
compiles both cells against the real toolchain and asserts the refusal, with a
failure message that says what has to be built **before** the parser may widen.
Board **#921**.

## 11. Found and not taken

1. **The fixpoint (§6) is worth 143 and has one cell.** The grid that would earn
   it: a chain of empty-bodied callers 1…4 deep, crossed with a non-empty body at
   each depth, at both flag settings. Board **#924**.
2. **c2's E is post-DCE and the port's is syntactic (§5).** 370 workload
   functions sit behind one parser production (`expr-intrinsic-memset`). Widening
   the parser is a `c2-il` rung and it converts these for free — *provided* the
   emptiness question is asked of the widened body and not of the production.
3. **Family A is ONE idiom.** All 1,373 conversions are
   `??1?$_STLP_alloc_proxy<…>::~_STLP_alloc_proxy()` — 545 distinct
   instantiations of one STLport template. A 40 %-of-4,711 family that is one
   idiom is a warning about generalizing from it, and it is why §5's residual is
   published by symbol family rather than as a count. Board **#925**.
4. **`seq` has an E population and it is not modeled.** `f06_two_calls` (both
   calls dropped, c2 emits `blr`) and `f08_mixed` (one dropped, one kept, c2
   emits a bare tail branch) are graded E in c2 and `Selected::Seq` in the port;
   both keep today's behaviour and stay `fnbyte-differs`. Taking them means
   re-deciding the body's frame class after the elision, which is a composition
   rung and not a predicate one.
5. **`c18_calls_extern` is `fnbyte-exact` and the port is wrong about it.**
   `void ext(); void g(){ext();} void f(){g();}` — c2 inlines `g` into `f` and
   emits `b ?ext`; the port emits `b ?g`. **The bytes are identical
   (`48000000`) and the relocation targets are not.** That is
   `fnbyte-exact-relocated` (4,664 credited functions, board #882) with a
   four-line reproducer, which the counter did not have before.
