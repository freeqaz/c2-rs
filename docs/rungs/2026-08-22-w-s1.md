## 1. What was built

`crates/c2-core/src/codegen/encode.rs` held **85 hand-written encoders**, each
carrying its own copy of a PPC primary opcode and an extended opcode as
literals. That file's own module doc named itself, in advance, as *"a black-box
re-derivation of two tables c2 states plainly"*. Read **R2** (`w-read-r2`,
2026-08-22) dumped both tables. So the re-derivation is retired:

* **`crates/c2-core/src/codegen/mop.rs`** (new) — `MachineOp`, a per-op value
  carrying **`C2Op`, c2's own opcode number**, plus the operand slots c2's form
  arms read (`S`, `D0`…`D3`, and a displacement); `OPCODES`, **85 rows of c2's
  base-word table transcribed from the read**; `plan(form)`, the field
  placements from `P_ENCODE.md` §5 arm by arm; and **`encode_op`, the one place
  in the crate that turns an instruction into a word.**
* **`encode.rs`** — every encoder is now a `MachineOp` constructor. Signatures,
  returned words and per-function evidence notes are unchanged.

### 1.1 Three positional helpers deleted, and the reason is the finding

`xo31`, `fp_a_form` and `fp_primary` are gone, and `encode_logical_x` takes a
`C2Op` instead of a bare `xo: u32`. The reason is worth keeping:

> **`xo31`'s first argument was the DESTINATION for `subfc` (c2 form 49) and the
> SOURCE for `extsb` (c2 form 38).** One positional helper, two different field
> meanings, decided by which caller you were looking at.

That is exactly the confusion `encode_logical_x`'s own doc warns about at
length — *"produces a valid `and` with the destination and the left operand
exchanged — bytes that assemble, disassemble and fuzz-match, and compute the
wrong thing"* — living **inside the helper written to prevent it**. Under the
general layer the slot roles are named per opcode and the form decides the bits,
so the class is unspellable.

### 1.2 Two opcodes the port was composing by hand are single c2 rows

* **`bctrl` is opcode `0x002a`, base word `4c000421`, form 55** — not a `bcctr`
  with `LK` set. The port composed it from a primary, a `BO`, an extended opcode
  and a literal `1`: four facts where c2 has one row.
* **`mr` is opcode `0x0272`, form 36** — not an `or` with a repeated operand.
  Form 36 reads `D0` **twice**, into `RS` and `RB`, which is why c2 needs no
  second source operand for it.

### 1.3 The decision surface (`GOAL_DECISION` § AMENDED; `README` DECISION-SURFACE CLAUSE)

`EncodeParams` carries the base-word table and the per-form `FieldPlan` as
**data**. `EncodeParams::C2` is the default, reproduces c2 byte-exactly, and is
the only value any emit path uses — **grading is at the default and nowhere
else.** Board **#3379**'s four mask mutations (`D` 16→12 bits, `RB` 5→4, drop
`RA`, `SPR` unsplit) were hand-edits to `encode.rs`; they are
`with_field_width` / `without_field` parameter values now, so the control can be
re-run without a patch.

**Nothing here is fitted.** Base words and forms are READ
(`docs/whitebox/ref/ENCODE_OPCODES.txt`, tables `0x10c3a578` / `0x10c39b18`,
arm jump table `0x10bfae2d`); placements are `P_ENCODE.md` §5.
`P_ENCODE.md` §9's bound is respected and is why this rung stops here: that spec
is a total function **from a finished machine tuple**, and building the tuple is
read **R5, unstarted**. The slots are the **port's own** operands, named for
c2's because that is what the form rules read — not a claim to reproduce c2's
tuple construction.

### 2.2 The part that does NOT depend on a toolchain, and is stronger

The gate exercises the operand combinations its **fixtures happen to contain**.
A portable exhaustive cross-check does not have that hole, so the required-zero
delta here is **provable in the portable lane**:

`#[cfg(test)] mod incumbent` keeps the **81 rewritten bodies verbatim** —
deliberately *not* re-derived from the same read table, so the check compares
**two independent derivations** rather than c2's table against itself — and six
tests sweep each encoder's whole operand domain:

| test | domain |
|---|---|
| `every_three_register_encoder_reproduces_its_incumbent_word` | 23 encoders × 32×32×32 |
| `every_two_register_encoder_reproduces_its_incumbent_word` | 12 encoders × 32×32, + `mtctr` × 32, + `blr`/`bctrl` |
| `every_displacement_encoder_reproduces_its_incumbent_word` | 28 encoders × 32×32×12, both signs, both boundary magnitudes, and non-multiples of 4 |
| `every_rotate_encoder_reproduces_its_incumbent_word` | `SH`×`MB`×`ME` entire (32³), plus `0..64` on the split six-bit fields |
| `every_fp_encoder_reproduces_its_incumbent_word` | 4 encoders × 32×32×32 × both precisions |
| `every_branch_encoder_reproduces_its_incumbent_word_and_its_refusal` | every legal displacement across both range boundaries, **and the refusals** |

**Board #3379's own lesson, applied rather than cited.** Its purpose-built
46-word probe *"could not distinguish a 4-bit `RB` from a 5-bit one, because no
word in it used a register ≥ 16"* — a control is only capable of failing on the
population you ran it on. So these sweeps are the **whole** 0..32, not a sample.

## 3. Criterion C — the `after0` opcode-agreement RATIO (instrument, never a gate)

    after0 opcode agreement: 82 of 85 distinct c2 opcodes the port emits
    the shape of M - N (3 rows):
      blr      op 0x0285 form 55  base 4c000020  after0 4e800020  delta 02800000
      bctrl    op 0x002a form 55  base 4c000421  after0 4e800421  delta 02800000
      bdnz     op 0x0288 form 1   base 40000000  after0 42000000  delta 02000000

Run it: `cargo test -p c2-core --lib after0 -- --nocapture`.

**It asserts the SHAPE of the residual, never a ratio floor.** A floor on a
characterization number is a gate wearing an instrument's clothes: it goes red
the day someone adds an opcode whose arm supplies a field, which is a fact about
c2 and not a regression in the port. What is pinned is the property #3379 found,
stated as a property instead of a count — **every residual is exactly its form's
`fixed` constant, and no residual is ever a primary or an extended opcode** —
plus the converse, that an opcode whose form ORs nothing **must** agree or its
base word was mistranscribed.

### 3.1 TWO corrections to the figure, both about the denominator

**(a) It is 85 opcodes, not #3379's 89.** That count was of **encoder
functions**. The populations differ by the convenience wrappers —
`encode_srwi31` and `encode_clrlwi31` are `rlwinm` with the mask baked, not
opcodes — and by the `double` flag, where one function reaches two rows
(`fadd`/`fadds`). Neither number is wrong; they answer different questions, and
**the ratio is meaningless without saying which** (standing rule 4, #3356).

**(b) `82/85` and `82/89` have equal numerators and that is a COINCIDENCE.**
Recorded explicitly so nobody reads it as the two derivations agreeing on a
number. #3379's **seven** residuals went to **three**, for two different reasons
a single count blurs:

| #3379 residual | fate | why |
|---|---|---|
| `BO = 20` ×2 (`blr`, `bctrl`) | **survives** | c2's form-55 arm really does `or ebx,0x2800000` with no operand read |
| `BO = 16` (`bdnz`) | **survives** | form 1's `or 0x2000000` |
| the split `SPR` | **dissolved — a REAL gain** | `encode_mtctr` baked `0x120`; it now passes SPR 9 through form 62's split placement, so `mtspr`'s `after0` **is** its base word. One fitted field became a read one |
| `SH`/`MB`/`ME` ×3 | **dissolved — DEFINITIONAL, bought nothing** | they were `encode_srwi31`, `encode_clrlwi31`, `encode_clrlwi_record` — three wrappers over one opcode. `rlwinm` itself always agreed; counting them as three residuals was an artifact of counting functions |

So the honest reading is **one** residual genuinely closed, **three** genuinely
remaining, and **three** that were never residuals of c2 at all.

### 5.1 A voided run, recorded rather than deleted

**The lane's first base-gate run is VOID and the gate said so itself.** Its
tree-content hash moved under it — `f6d22d95811b` (764 files) →
`4ea68fcd3f9c` (765) — because this lane edited `crates/` while the run was in
flight, and board #3048's detector printed *"the verdict above was produced
partly from each, so it is evidence about NEITHER tree."* The run was discarded
and both ends re-run on clean, committed trees with nothing else touching
`crates fixtures scripts`.

Worth keeping for two reasons. It is a **positive result for the instrument** —
that detector exists because #2907 was a gate verdict attributed to the wrong
tree, and it fired the first time a lane gave it the chance. And it is the
concrete reason a construct rung's two gate runs must be **sequential and
quiet**: the identity diff is the whole grading instrument, and a diff between
two smeared trees is not zero-or-nonzero, it is meaningless.
