## Headline

The object plan — everything about the output obj that is **independent of the
instruction bytes** — is now read off real `c2`'s obj on **870 of 870** graded
TUs and predicted from IL, **without emitting**, on **854** of them. That is the
continuous curve `ARCHITECTURE_PROPOSAL_2026-08-20.md` §5 step 3 asks for, and
it exists because the predictor is forbidden by a source-level test from asking
`IlBundle::functions()` — the admission gate that returns `None` on 844 of 870.

And the first thing it measured **refutes the rule the roadmap's emit-set lane
was going to be built on.** `C2_MAP.md` §3E's `0x20` bit at `sym+0x4c` — seed
set, closed under "referenced by an already-emitted function" — is present on
**331** names across the whole workload against **158,802** functions `c2`
actually emitted, and the seed is **EMPTY on 739 of the 854** TUs where the
reader answers. A closure over an empty seed is empty. §3E's cascade was
measured on a 20-function probe bundle; this is 870 real TUs.

The byte is not mis-decoded, and that is established rather than assumed: bit 6
(`FN_FLAG_INLINABLE`) is set on **28,104 of 28,107** records and **zero** records
read `0x00`, which rules out the uniform-zero signature `gl_function_attrs`' own
doc records having produced once. The bit is simply rare, and the reader's map
covers **28,107 of 158,802** emitted functions — a **17.7 %** ceiling on anything
keyed off it, whichever bit is chosen.

Where the seed *is* non-empty it is startlingly good: **exact** against `c2`'s
own emitted set on **27** TUs, **9** of them TUs the port does not convert, and
it over-claims exactly **once** in the whole workload.

## 1. The plan defect in the handed brief, and the fix

Deliverable 3 as literally briefed — *"REQUIRED-EXACT on the 26 matched TUs: if
the manifest is not identical on a TU we already reproduce byte-exactly, the
manifest is wrong"* — is **vacuous** if the port side of the manifest is
`observe(port_obj)`. On a `match` TU the port's obj **is** the reference's bytes
(`ObjImage::diff`, timestamp-normalized), so `manifest(port) == manifest(ref)`
follows from `port_bytes == ref_bytes` for *any* pure `manifest`. And on the
other 844 the port emits no obj at all, so the port side is **undefined** and
there is no curve. The naive reading delivers **neither** deliverable 3 nor
deliverable 4.

The fix, and it is the whole design: **two independent producers.**

* `c2_obj::ObjPlan::observe(&ObjImage)` — ground truth, off the **reference**
  obj. `Some` on **870 of 870** graded TUs.
* `c2_core::plan::predict(&IlBundle, &PlanInputs)` — the port's plan, computed
  **from IL without emitting**, and **forbidden from calling the emitter or
  `IlBundle::functions()`** by a source-level test.

### 1.1 The residual defect the control then exposed, which the plan did not anticipate

The control's rule (*"`Unknown` on a control TU is a failure — the port
demonstrably had the information"*) assumes `predict` **is** the port's emit-set
decision procedure. **It is not.** The 26 matched TUs are matched by whole-TU and
per-function recognizers that never consult the `0x20` bit. So `Differs` on a
control TU is not automatically a bug: on `TomCryptLicense.cpp` and
`ZlibLicense.cpp` it is *correct and informative*, and the instrument **names
the symbol** rather than leaving it to be re-derived by hand:

```
src/system/synth/tomcrypt/TomCryptLicense.cpp  emitset-members = differs
    — the seed does not carry `??__EsLicense@@YAXXZ` (1 name(s) missing here)
src/system/zlib/ZlibLicense.cpp                emitset-members = differs
    — the seed does not carry `??__EsLicense@@YAXXZ` (1 name(s) missing here)
```

Both are the `??__E` **dynamic initializer** — compiler-generated, carrying no
`.gl` function record for the seed to read — and both TUs are exactly the two
`IlBundle::dyninit_tu` converts, by a path that never consults the bit. The
hypothesis was *"probably the dyninit"*; the witness makes it a measurement.

`plan_control` therefore counts three things apart —
`plan-control-exact` / `-differs` / `-unknown` — and **only `differs` reds the
lane**. Folding them would have made the control unreadable the moment a
component was demoted, which is exactly what its first run caused (§2.2).

### 2.4 THE DECIDING PROBE: the byte is right, the bit is rare

A number with two stories is not a measurement. Either the bit is genuinely rare
in `.gl` and `c2` sets it elsewhere, **or** the walk is landing on the wrong
field and returning a plausible byte — which is the exact failure
`gl_function_attrs`' own doc records having made once (*"nine of eleven records
decoded as attribute `0x00` … a uniform answer where the grid predicts a split …
a mis-decoded displacement does not look like an error, it looks like a fact"*).

Bit 6 has a shipped consumer graded elsewhere, so it is the discriminator:

| key | value |
|---|---|
| `plan-glattr-names` | **28,107** `.gl` function records the reader names |
| `plan-glattr-bit6` | **28,104** — 99.99 % carry `FN_FLAG_INLINABLE` |
| `plan-glattr-zero` | **0** — no record decodes to `0x00` |
| `plan-glattr-seed` | **331** — 1.18 % carry `0x20` |

**The byte is decoded correctly. The bit is rare. And the map reaches only
28,107 of 158,802 emitted functions — 17.7 %.** Whichever bit is chosen, nothing
built on this reader can exceed that ceiling. `c2` must set `0x20` during IL load
from a source that is not this field; the deciding probe for *what* is registered
in the `W-OBJPLAN-1` DISCLOSURE row.

## 4. What the manifest CANNOT see — stated, because #3237

* Every instruction byte, and therefore `.text` section sizes, the COMDAT aux
  `CheckSum`, symbol `Value` for in-body labels, relocation `VirtualAddress`
  inside code, `.pdata` prolog/epilog fields, and any `.debug$S` subsection
  keyed to a code offset.
* The 8 `capture-fail` TUs. No reference obj → **not a row**, never a false row.
* Anything about **correctness**. `plan-*-exact` is **necessary but not
  sufficient** for `match`; a TU can be plan-exact and mismatch on every byte.
* One thing deliberately **retained and flagged** rather than dropped:
  `PlanSection::byte_len` for **non**-`.text` sections. `.pdata`'s length is
  `8 × nfunctions` and `.debug$S`'s is a function of the `-Fo` path — neither is
  a function of the *instruction bytes*, so both sit inside the
  body-independence invariant, but both are body-*correlated* in the weaker
  sense that a different emit set moves them. They live in `sections` and are
  graded in their own component, never folded into the emit-set curve.

**Denominator: TUs.** Option A's target is stated in TUs (870 of 878), so the
curve's denominator is the goal's. This sidesteps #3254 entirely — the `fnbyte`
denominator is 71.2 % bodies the shipped image never contains because `/Gy`
COMDATs get discarded by the linker, which is a *function*-level denominator
problem. A TU is a TU; there is no discard.

## 5. Found and NOT taken

Ranked, sized, each with the deciding probe named.

1. **The SECTION component (P7) was not built, and the reason is not time.**
   The section predictor's only walk-free substrate is the whole-TU recognizers
   (`shell_only_tu`, `data_tu`, `provide_data_tu`, `bss_shell_objects`), which
   are `IlBundle` methods on the admission side of the reader — the exact route
   §1's fence exists to keep out of `plan/`. Shipping them would have produced
   `known ≈ 30 of 870` and re-published `vocab-gap 844` under new keys.
   **The observe side is built and published** (`plan-obs-sections`,
   `-sections-names-distinct` 853, `-sections-attrs-distinct` 854), so a section
   lane starts with its ground truth already graded on 870 TUs and owes only a
   walk-free predictor. **Deciding probe: does `mangled_names` + the `.gl` data
   rows determine the section-name multiset without `functions()`?**
2. **WEAK EXTERNALS (P8) were not made a component**, for the same reason: the
   port models none, so the component would be `Unknown` on 870 of 870 and the
   key would say nothing the `Unknown` histogram does not. The *population* is
   published instead — **674 TUs, 4,009 records** — which is what a weak-external
   lane actually needs, and it re-derives a figure the roadmap had only carried.
3. **`plan_text_order` (#259) is now priced.** Any order model has to beat
   **18 of 854**. The `.gl`-record-order rule is dead; `coff::order`'s
   DFS-preorder rule is the next candidate and was not tried here.
4. **THE EMIT-SET CLOSURE LANE IS RE-PRICED AND SHOULD NOT BE DISPATCHED AS
   BRIEFED.** §2.4's 17.7 % ceiling and 739 empty seeds mean seed-plus-closure
   over `.gl` cannot reach the emitted set. **Deciding probe, registered in the
   DISCLOSURE row: read `+0x4c` WHOLE — not its low byte, and not through
   `gl_function_attrs`' framing — on a large TU, and find the field that IS set
   per emitted function.**
5. **`STATUS.md`'s generated block was NOT regenerated**, deliberately. The
   sibling workload stamp moved four times inside this lane and 43 of 439 keys
   moved with it between two runs of one binary; regenerating here would put a
   peer's movement in this lane's commit. The three `plan-*` rows are registered
   in `scripts/status.sh` (with known-answer, prefix-collision and absent-key
   probes, `--check` PASS) and appear on the next regeneration at a quiet stamp.
   The **hand-written** trap section did gain its row (trap 0b).
6. **The four existing `c2-obj` accessors were NOT replaced.** `observe` is a
   new walk plus an agreement assertion, which is cheaper, uncontended, and
   catches the same drift the one-fact-one-locator rule exists for. Replacement
   is a later construct lane and it touches every consumer of all four.
7. **`TempoMap.cpp` is the single over-claim in 870 TUs** — the seed names one
   function `c2` did not emit. One TU is too small to generalize from and it is
   named here so the next lane does not have to re-find it.

## 6. Three defects this lane's own controls found in this lane's own instrument

Each is the failure mode the instrument exists to prevent, arriving inside it.

1. **A key that read `0` because nobody looked.** `plan-emitset-order-distinct`
   read **0** on run 1 because no signature was ever recorded for that
   component. #3237 in the instrument built to stop it. `plan_distinct` now
   reports only keys with a producer.
2. **A containment claim with no claimant size** — §2.3.
3. **A source fence that its own explanation tripped.** The
   `plan/`-may-not-name-the-emitter test went red on the module doc that
   *explains the ban by naming `PortC2`*. The pressure would have been to delete
   the explanation rather than the dependency, which is the wrong direction —
   the explanation is what a reviewer reads. Comments are stripped before
   scanning, what that gives up is stated at the site, and the fence now asserts
   one needle that **is** present first, because a scanner looking for absent
   needles passes trivially when the needle list is wrong.

A fourth, in the test harness rather than the instrument: the synthetic COFF
builder wrote a string-table offset of `at + 4` where `str_at` indexes from the
table's start, so `?f@@YAXXZ` decoded as `"YAXXZ"` — a plausible mangled-looking
name, four bytes in. `observe` decoded the wrong offset faithfully, which is how
a bad synthetic fixture certifies a good reader.
