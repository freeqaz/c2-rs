## 1. The result, stated first

> ### The gate's exit-code contract is unchanged, and a caller can now demand more than it. `--require-graded` turns **any** outcome that would exit 0 having graded **0 units** into `GATE: FAIL (NOTHING GRADED)`, exit 1. The quantity is a **count** — lane fixture-verdicts **+** sweep cases graded **+** cross cells graded — and it is compared at the **single point in `decide` where every branch above returns 1 and every branch below returns 0**, so it covers every zero-exit outcome the gate has *and* every one a future lane adds.

Three acceptance runs, all on this tree:

| run | outcome |
|---|---|
| `scripts/gate.sh --jobs 6` | **GATE: PASS — 18/18 lanes**, 0 FAIL, 0 SKIP, 0 NO-RESULT, **4,770 fixture-verdicts**; sweep **16,710/16,710 reached, 16,614 graded, 0 mismatch**; cross **81,905 selected, 81,517 graded, 0 mismatch**. **exit 0.** Digit-for-digit the baseline taken at `f57fe61e` before the first edit |
| `--require-graded` + `C2RS_COMPILERS`/`C2RS_WIBO` pointed at a nonexistent path | **`GATE: FAIL (NOTHING GRADED)`, exit 1**, naming the count (`units graded, summed over this whole gate: 0`), the 18 lanes that skipped, and the two overrides that are wrong |
| no demand, same unresolvable overrides | **`GATE: SKIPPED`, exit 0** — unchanged, plus the resolution hint |

Nothing was moved or deleted to produce the second and third rows: both are the
real script with `C2RS_COMPILERS=/nonexistent/w-gate/compilers` and
`C2RS_WIBO=/nonexistent/w-gate/wibo` in the environment.

## 2. What this is the thirteenth of

Lane `w-root` (merge `f57fe61e`) filed:

> The first `scripts/gate.sh` run from the lane's worktree printed **`GATE:
> SKIPPED — NOTHING WAS GRADED`** and **exited 0** … **A lane checking only the
> exit code would have reported a pass over a run that graded nothing.**

It had happened before, in the same shape, three days earlier —
`rungs/2026-08-05-w-subclass.md` §10.1:

> A bare `scripts/gate.sh --jobs 6` from a worktree reported **18 SKIP, exit 0**.
> The script says so itself … which is the mitigation working, and it is trap 5
> exactly: a lane that read the exit code would have banked a green gate over
> nothing graded.

**Both payments bought legibility, and legibility was not the binding
constraint.** `gate.sh` already printed `NOTHING WAS GRADED` in the headline, in
capitals, with an explicit *"this exits 0 by design and is NOT a green gate"*
underneath. Nobody read it. The gap is not that the run was illegible; it is that
**a shell caller's only cheap machine-readable output is `$?`, and `$?` said 0.**

So the fix is not more prose. It is a way for the caller to put its expectation
into `$?`.

## 4. The shipped check, and exactly what it counts

```
_d_units = _d_graded            # Σ LANE-RESULT graded=  over the registry walk
         + num(_d_swg)          # expr-sweep   `graded=` (NOT `checked=`)
         + num(_d_cxg)          # mode-cross   `graded=`
```

`_d_units == 0` under the demand ⇒ exit 1. The banner also prints
`lanes that graded a corpus  <k> of <n>`, which is the second counted quantity —
`_d_graded` is a sum and one busy lane can carry it.

Four properties, each with the reason for its shape:

- **`graded`, not `checked`.** The sweep's `checked` is "cases the loop reached";
  `graded` is "cases the oracle ruled on", and w-modes found 96 of 14,635 sitting
  in the gap. Summing `checked` would count cases nothing judged.
- **`num()` maps absent-or-unparseable to 0**, and that is the safe direction
  *here and only here*: the comparison is `> 0`, so an unreadable field can only
  make the demand **fail**. It is the exact inverse of the defect this project
  keeps recording, where a missing number read as 0 made a check **pass**.
  Mutation **M9** shows what the guard is worth: without it `$(( 0 + + ))` is a
  bash expansion error, a non-interactive shell **exits** on one, and the whole
  selftest dies mid-run with no verdict line at all. An absent count without
  `num()` is not a demand that fails; it is a gate that stops having opinions.
- **One site, at the last zero-exit point.** Not four copies at the four
  `return 0`s. Everything above the block returns 1 (completeness; the generated
  instruments' FAIL and NO-RESULT; the lanes' NO-RESULT; the lanes' FAIL);
  everything below returns 0 (`SKIPPED`, `PASS (LANES FILTERED)`,
  `PASS (SAMPLED)`, `PASS`). **That placement is the non-enumeration.** An
  enumeration of today's empty outcomes would be blind to tomorrow's; this covers
  a zero-exit outcome that does not exist yet, by construction. The comment says
  so, and says that a `return 1` added below it invalidates the comment.
- **It duplicates nothing.** Partial skip, vacuous lane, short sweep, NO-RESULT
  are all already failures and all already behind it. Cases 6 and 7 of the
  selftest assert exactly that: under the demand a partial skip still fails with
  the **partial-skip** message and a mismatch still raises the **mismatch alarm**,
  and neither prints `NOTHING GRADED`.

## 5. SAMPLED and partial-skip: the decision, and why

**SAMPLED and `--lane`-filtered runs SATISFY the demand.** A strided 400-case
sample graded 400 things; the demand is `graded > 0`, not `graded == corpus`. Both
already refuse an unqualified PASS and name in the headline what they did not
establish — that is the right instrument for "less than everything", and
conflating it with "nothing at all" would make one flag mean two things and leave
a lane no way to iterate under the demand.

**Partial skip is not covered**, for the stronger reason that it is *already* a
FAIL. Covering it again would be a second implementation of a rule that has one —
the "one rule, two implementations" shape `docs/GAPS.md` §6 keeps recording, and
the shape that produced this bug's own ancestor (`mode_lane.sh` shipped without the
guard `sweep_mode.sh` had already grown).

**`--reap-only` under the demand is refused as usage (exit 2).** It grades nothing
by construction and its documented exit 0 means *the disk is clear*, never *the
port is right* — it is the one non-run mode a caller could substitute for a gate
and then read `$?` of. `--list` / `--check` / `--selftest` are inspection modes
that nobody substitutes for a gate; the demand does not bind them and **says so on
stderr**, because a demand quietly ignored is this file's own bug class.

## 6. The smaller half: a SKIP now says which path did not resolve

w-root read a clean skip and had to derive for itself that `compilers/` is
gitignored (so it does not follow a `git worktree add`) and that the `../wibo`
fallback resolves relative to the **worktree**, three directories below the main
repo. `toolchain_hint` is printed under every `GATE: SKIPPED` and under the demand
banner. As it reads on this tree with the overrides pointed at nothing:

```
  WHY: the toolchain did not resolve from <worktree>
       This tree is a git WORKTREE (.git is a file, not a directory), and
       every default below is relative to IT, not to the main repo. That is
       the cause both recorded times: rungs/2026-08-05-w-subclass.md §10.1
       and lane w-root, 2026-08-08.
       compilers  MISSING  /nonexistent/w-gate/compilers
                  override: C2RS_COMPILERS — SET in this environment, taken verbatim (no fallback)
       cl.exe     MISSING  /nonexistent/w-gate/compilers/X360/16.00.11886.00/cl.exe
                  override: C2RS_CL_EXE (unset — this is the default)
       c2.dll     MISSING  /nonexistent/w-gate/compilers/X360/16.00.11886.00/c2.dll
                  override: C2RS_C2_DLL (unset — this is the default)
       wibo       MISSING  /nonexistent/w-gate/wibo
                  override: C2RS_WIBO — SET in this environment, taken verbatim (no fallback)
                  ...or `wibo` anywhere on PATH

  FIX, from the main repo:  scripts/configure_existing_worktree.sh <worktree>
      (symlinks compilers/, reflinks target/, and links ../wibo beside the
       worktrees — then REBUILDS and refuses to finish if it still SKIPs)
  If compilers/ is missing in the main repo too:  scripts/fetch_compilers.sh
  `Toolchain::locate()` in crates/c2-reference/src/lib.rs is the authority;
  the lines above report what was FOUND and resolve nothing themselves.
```

Four things about it are deliberate:

- **`C2RS_DC3` is NOT named**, although the brief offered it and
  `rungs/2026-08-05-w-subclass.md` §10.1 lists it beside the other two. It points
  at the dc3-decomp **source** tree for `scripts/status.sh`; **no lane in this
  gate reads it**, and naming it would send a reader to set a variable that cannot
  fix this. A selftest case asserts it stays out.
- **It reports the EFFECTIVE path, not the default.** `Toolchain::locate` takes an
  override verbatim and does not fall back, so the compilers root, and therefore
  the `cl.exe`/`c2.dll` lines under it, follow `C2RS_COMPILERS` when it is set.
  The first draft printed the defaults and reported `found` for two files the
  resolver never opens — see §7, defect (a).
- **It decides nothing, and it cannot silently go stale.** The version directory
  is `sed`-ed out of `crates/c2-reference/src/lib.rs` at run time rather than
  copied, and if it cannot be read the line says so instead of printing a literal
  that used to be right. A selftest case extracts every `C2RS_*` the hint prints
  and requires each to still be read by `crates/c2-reference/src/lib.rs`.
- **It refuses to lie when everything is present.** If all four defaults exist —
  which is the case when an *override* is the problem, or when the skip has a
  lane-local cause — it says so and hands over to the resolver's own voice rather
  than printing four `found` lines under a heading that says the toolchain did not
  resolve.

## 7. Three defects the mutation harness found in this lane's own work

Written down because each one is a check that would never have failed:

- **(a) The hint pointed at the wrong file.** With `C2RS_COMPILERS` set, the
  `cl.exe` and `c2.dll` lines printed `<repo>/compilers/X360/…` and reported
  **`found`** — for paths the resolver had not consulted. A signpost aimed at the
  wrong road is worse than no signpost. Fixed by transcribing `compilers_root`'s
  documented precedence for *reporting only*, with the transcription labelled as
  such.
- **(b) `hint-names-every-override` grepped the whole block**, so it stayed
  **green** under a mutation that deleted the override from the path it belongs
  to — the name was still mentioned in a prose sentence lower down. A name in
  prose is not a name attached to the path that failed. Now `override: <NAME>`, on
  the line under the path.
- **(c) The anti-drift arm compared a list repeated in the selftest** against
  `lib.rs`, so a hint that *invented* a name was invisible to it: the fixed list
  went on agreeing with itself. Now the names are extracted from the hint's own
  output. Mutation **M13** renames one and reddens (b) and (c) together, which is
  the correct pair.

All three were found by writing the mutations, not by reading the code.

## 9. What this lane deliberately did not do

- **It did not make `SKIPPED` exit non-zero.** That exit code is documented at
  `gate.sh` line ~228 and is required by the root `CLAUDE.md` hard constraint that
  the toolchain-absent path degrade cleanly. The portable lane has no toolchain
  *by design*; breaking it would trade one silent failure for a noisy one in the
  only lane entitled to be empty.
- **It touched no file under `crates/`.** Concurrent lanes own `crates/c2-il/`
  (w-memset) and `crates/c2-core/src/codegen/alloc.rs` (w-alloc3). The anti-drift
  assertion *reads* `crates/c2-reference/src/lib.rs` and does not write it.
- **It changed no printed count, key, or metric.** The gate's table, its
  `lanes:` / `graded:` / `sweep:` / `cross:` block and every verdict string are
  byte-identical to `f57fe61e` on a green run; the only additions are a new
  failure banner that cannot occur unless the caller opts in, and text under
  `GATE: SKIPPED`, which by definition accompanies a run that graded nothing. No
  scan key exists in this file, so `work/w-splice/peerkeys.py` has nothing to
  compare.
- **It did not add a `--require-full`.** SAMPLED and `--lane` already carry
  qualified headlines; a second flag for "graded everything" was considered and
  declined in §5. If it is ever wanted, it is a different quantity
  (`graded == corpus`) and belongs beside this one, not inside it.

## 10. Found and not taken

- **The demand cannot be expressed by `mode_lane.sh` or `expr_sweep.sh` callers.**
  Both are run directly by lanes and both have the same silent-skip shape
  (`SKIP: toolchain absent`, exit 0). This lane put the demand only in `gate.sh`,
  which is the command the standing brief tells lanes to run. Sized: two small
  additions, same pattern. **Not taken** — a flag on three scripts with three
  copies of the rule is exactly the "one rule, N implementations" trap; if this is
  wanted, the honest form is a shared shell fragment, and that is its own rung.
- **`scripts/status.sh --write` has the same hole in a worse place — board
  #1086.** It renders
  `NO-RESULT` for each metric it cannot produce, and then **overwrites the
  generated block in `docs/STATUS.md` with them** (board #424 records a worktree
  turning 19 of 23 metrics into `NO-RESULT`). It already refuses nothing. A
  `--require-complete` there would be the same shape as this rung and would guard
  a *committed artifact*, which is a strictly larger blast radius than an exit
  code. **Not taken; sized as small. This is the row the next lane should read.**
- **Twelve `C2RS_*` overrides exist and no one document lists them.** They are
  spread across `crates/c2-reference/src/lib.rs`, `scripts/status.sh`,
  `scripts/regen_census.sh` and `gate.sh`'s own header, and this lane had to grep
  four files to be sure `C2RS_DC3` was not one of the toolchain's. Not taken —
  a table is cheap, but a hand-maintained table of env names is the thing that
  drifts, and the generated form needs a reader that does not exist yet.
