## 2. X-d reproduced — and it is six cases, not one

`work/w-cross/alarm/explicit.cpp` reproduces on this tip at
`Port=Mismatch @ offset 8`, with a forced rebuild of every workspace crate.
**Offset 8 is `PointerToSymbolTable`**, and it is a *consequence*: the port's
`.text` is 52 bytes against the reference's 56, so every file offset after the
section table shifts. The `.debug$S` difference you will see if you dump a
`c2rs compile` obj beside a `c2rs prefilter` obj is **not** part of it — that is
the embedded `-Fo` path, which differs because the two commands use different
scratch directories. `c2rs diff` threads one path into both.

```text
reference   .text 56 B   ??1M@0x00 (4 B + 4 pad)   ??0D@0x08 (48 B)   $M2581 $M2582 $T2583
port        .text 52 B   ??0D@0x00 (48 B)          ??1M@0x30 (4 B)    $M2580 $M2581 $T2582
```

The `.ex` order is `??0D, ??1M` (`c2rs census` prints it) and so is the `.gl`
record order. c2 emits the reverse.

**Then the grid.** `work/w-order/p/`, 47 hand-built TUs at the differential's
own `/Ox /GS- /c` profile, read straight off the oracle's obj by
`work/w-order/p/order.sh`. **Six were live `Port=Mismatch` on master**, and X-d
is the *least* ordinary of them:

| case | source | verdict on master |
|---|---|---|
| `c1_basedtor_here` | `struct B{B();~B();int x;}; struct D:B{D();}; D::D(){} B::~B(){}` | `Mismatch @ 8` |
| `c8_dtor_nonempty` | the same with `B::~B(){h();}` | `Mismatch @ 8` |
| `c6_two_ctors` | two derived constructors ahead of the base destructor | `Mismatch @ 8` |
| `b6_xd_plus_plain` | X-d plus an unrelated leaf | `Mismatch @ 576` |
| `b7_plain_first` | the same, leaf first | `Mismatch @ 8` |
| `xd_explicit` | X-d itself | `Mismatch @ 8` |

`c1_basedtor_here` is four lines with no implicit anything, no `0x26`, no
sibling class — two user-written definitions where one references the other. It
is a strictly smaller reproducer than the row that was filed.

### 2.1 The rule, and the three rivals it had to beat

> c2 emits a function only once every function it **references** *and defines*
> has been emitted, rescanning the `.ex` order until a pass emits nothing.

Twenty-one TUs. Each of the three properties below is a rival that fits the
first four probes and that one probe kills:

| property | the probe that separates it | rival it kills |
|---|---|---|
| **stable** — a satisfied caller does not move | `e1_gfh`: `g; f(){g();}; h` stays `g, f, h` | "defer every caller to the end", which predicts `g, h, f` |
| **as many passes as the chain is deep** | `e4_abc`: `a→b→c` written `a,b,c` comes out `c, b, a` | one deferral pass, which predicts `c, a, b` |
| **not a DFS** | `e2_fhg`: `f,h,g` with `f→g` comes out `h, g, f` | DFS post-order, which predicts `g, f, h` |
| a self-reference is not an edge | `g1_self_rec` | — |

Six permutations of a three-chain, six of a four-chain, fan-in (`g8_common`),
fan-out, two independent pairs, and a repeated callee all agree.

**And the same rule holds at `/O1` (`/Gy`)**, where it orders the per-function
COMDAT `.text` **sections** and therefore the section table, the section
indices, the symbol indices and the `.pdata` association numbers — far more
bytes than the packed case, and on the workload's own profile.

### 2.2 The ordering edge is NOT in the obj

`c1_basedtor_here` is the case that decides how the planner is fed.

```text
-- .text #5 (56 B) ??1B@@QAA@XZ
   0000  4e800020  blr
   0004  00000000
   0008  7d8802a6  mflr 12          <- ??0D starts here
   ...
   001c  4bffffe5  bl .-28            ; REL24 -> ??0B@@QAA@XZ   (UNDEFINED)
```

`??0D`'s only relocation names `??0B`, which this TU does not define. **Nothing
in the object mentions `??1B` — no branch, no relocation, no symbol** — and c2
emits it first. The edge is the `26` **unwind action** in `??0D`'s IL, already
decoded as `c2_il::IlFunction::eh_unwind_callees`, whose own doc says it
"contributes nothing to `callees()`, which is what the emitter reads". True of
the emitter and false of the scheduler.

A planner fed the relocation list gets `c1_basedtor_here` wrong and **every
other probe in the grid right**, which is exactly the shape that survives
review. `f1_control_no_unwind` and `f2_dtor_unrelated` are the controls: give
`D` a base with no destructor, so no `26` names `??1B`, and the order is source
order again.

Two predictions were registered against the rule before compiling and both
held: `f3_unwind_plus` → `??1B, ??0E, ??0D`, `f4_unwind_mid` → `?k, ??1B, ??0D`.

## 3. The decision: CORRECT, not refuse — and why that is not the usual answer

The standing guidance is that a fitted ordering rule in the COFF writer is where
both of this project's six-wrong-bytes defects came from, and that one witness
either way means refuse. Three things make this the other case.

1. **The rule is not fitted to a point.** Twenty-one TUs, three reference kinds
   (a framed `bl`, a tail branch, a byte-invisible unwind action), function
   counts 2–4, both directions of source order, both section layouts, and three
   named rivals each killed by a probe rather than by preference.
2. **`b5_xd_swapped`, `c7_dtor_first_src`, `f1` and `f2` prove the order is the
   ONLY missing input.** Write the same TU with the callee first and the port is
   already byte-exact — labels, padding, symbol table, everything. The port was
   one permutation away, not one model away.
3. **The failure is asymmetric in the safe direction.** With an empty edge set
   `plan_text_order` is the identity permutation, which is precisely what the
   port did before. A reference the caller *fails* to report degrades to the old
   behaviour; only a *spurious* edge can regress anything, and edges come only
   from names the decoder read out of a decoded body. That asymmetry is the
   whole argument, and it does not exist for the ordering questions that were
   correctly refused (the COMDAT-vs-packed placement w-cross left open has no
   such default).

**And where the witnesses run out, it refuses.** A dependency **cycle** stalls
the scan, and c2 does something else entirely there — it folds the recursion.
The three cycle probes contradict every single tie-break rule: `g3_cycle3`
(`a→b→c→a` written `a,b,c`) comes out `b, a, c`, while `g4_cycle_plus` (`a↔b`
beside a leaf) comes out unpermuted with the **leaf last**, which no dependency
worklist can produce at all. `plan_text_order` returns `None` and the caller
returns `NotImplemented`.

**Price, demonstrated rather than asserted.** Six mismatches → zero. Every
previously-matching probe in the 47-case grid unchanged. Gate 12/12 with
per-lane match counts equal to master's plus this branch's own fixtures
(`108/108/108/108/108/108/106/106/108/108/1/1`). Scan, census, FRONTIER,
disagreement, `A/B/C/D` all identical. `perf` 106 → 108, both new.

## 4. The second defect — found because the fix converted four of six

Correcting the order left **two** of the six mismatching at `/EHsc` only. The
`/EHsc` half of `scripts/lanes.txt` is the reason that was visible at all.

It is **not** an ordering residue. `c7_dtor_first_src.cpp` — `B::~B(){}` written
*before* `D::D(){}`, so `plan_text_order` is the identity on it — mismatched on
master and mismatches after the order fix, at `/O1 /EHsc`, which **is the dc3
workload's own profile**. The port emitted `$M2571/$M2572/$T2573` where c2 emits
`$M2570/$M2571/$T2572`: six wrong bytes in an obj that links, and
`expr_sweep.sh` cannot see it because the sweep runs only `/Ox`.

> **`IlFunction::eh_bare`'s `/EHsc` `+1` label slot is not charged when the `26`
> unwind action's target is defined in this TU with an EMPTY body.**

Measured seed-free and in-TU against `int a0(int a){return ga(a)+1;}` as a
leading framed anchor (stride 4 packed), reading `first(P) − first(a0)`.
`work/w-order/p/h*.cpp`; `D : B`, so `??0D`'s unwind action names `??1B`:

```text
  probe                                no /EH  /EHsc  lead   ??1B is
  h0  a0 ; D::D                            4      5     1    not defined here
  h1  a0 ; C::~C{} ; D::D                  5      6     1    "  (C unrelated)
  h2  a0 ; C::~C{} ; E::~E{} ; D::D        6      7     1    "
  h3  a0 ; z(int) ; D::D                   5      6     1    "
  h5  a0 ; B::~B{} ; D::D                  5      5     0    defined, EMPTY
  h6  a0 ; C::~C{} ; B::~B{} ; D::D        6      6     0    defined, EMPTY
  h8  a0 ; B::~B{} ; D::D ; F::F         5,4    5,4   0,0    defined, EMPTY
  hf  a0 ; B::~B{gh();} ; D::D             6      1          defined, NOT empty
  hg  a0 ; M::~M{} ; D::D  (D:M:Bd)        7      1          defined, DELEGATES
```

**Why `eh_bare`'s own table could not have caught this.** Every probe behind it
was a single-purpose TU in which the base destructor was an undefined external —
the table is exhaustive on the axis it varies (`/EHsc` vs not, leaf vs framed,
led vs not) and holds this one fixed. That is board **#198**'s shape and
w-frame's §4.5.3, and X-c recorded it one layer up for `il_gl_sep26.cpp`. It is
now the same finding three times.

**`hf` and `hg` are why the predicate is not "defined here".** That simpler rule
fits `h5`/`h6`/`h8`/`h9` perfectly. It was implemented first, and it turned
**five byte-exact objs into mismatches** (`b5`, `b6`, `b7`, `c8`,
`xd_explicit`). The `/EHsc` gate lanes rejected it within one build. The
discriminator is the target's *body*: only a bare `blr` suppresses the slot;
a tail call (`hf`) or the delegating `b ??1Bd` (`hg`) still pays.

**It is per FUNCTION, and `h9_mixed_targets` separates that inside one obj.**
`??1B` defined-empty and `??1G` external: `D::D` takes lead **0** and `H::H`
takes lead **1**, five slots apart in the same symbol table.
`ha_mixed_swapped` swaps their source order and each lead follows its own class,
not its position. A per-TU reading fits `h5`/`h6`/`h8` exactly as well and is
wrong. A **mixed** unwind list refuses.

## 5. The structural axis cross, and what else it turned up

The brief's instruction was to enumerate the structural axes and cross them,
because this project's grids have varied *values* exhaustively three times and
missed on arity, register position and structural counts. Crossed here:
reference kind × callee position × function count × unrelated-function position
× chain depth × fan-in/fan-out × base-vs-derived-vs-unrelated × implicit-vs-explicit
destructor × cycle shape. Values (types, literals, member offsets) held fixed at
`int`.

Beyond the six mismatches and the `/EHsc` slot, the cross produced:

1. **The reachable half of the planner is the unwind edge, and only that.**
   `c2_il::IlBundle::functions()` refuses a bundle whose **callee** is defined in
   the same TU (`d2`, `d3`, `hc`, `c2_basector_here`, `c5`, every `g*` cycle —
   all `il-decode-failed`). So today every ordering edge the port can reach is a
   `26` unwind action, the planner's call-edge half and its cycle refusal have
   **no coverage under the GRADED profile**, and they are pinned by portable
   assertions and by nothing the oracle has seen. **w-frame's row F-c, stated
   rather than discovered later**; `wor_emit_order_neg.cpp` says it in the
   corpus so the next widening cannot miss it.
2. **A locally-defined *delegation* target is a different shape: c2 INLINES it.**
   `hc_dtor_target_here` (`Bd::~Bd(){}` defined beside `M::~M(){}` which
   delegates to it) puts **9** slots between the anchors where the sum of the two
   strides is 6. The port refuses it at `functions()` today. Left open.
3. **c2 folds infinite mutual recursion.** `g3`/`g6`'s first function is a
   `b .+0` self-branch with **no relocation** — the cycle was collapsed, not
   ordered. Any future cycle model has to start there and not from a tie-break.
4. **8-byte inter-function padding is order-sensitive and cost-blind.** The
   reference's `.text` is 56 B in `xd_explicit` and 52 B if the same two
   functions are emitted the other way round; `b3_ctor_then_dtor` shows c2 taking
   the order that costs 4 bytes of padding and `b4` shows it taking the order
   that saves them. The order is not a packing decision.

## 9. What was deliberately not done

* **No cycle tie-break.** Three probes, three different answers, and c2 is
  folding rather than ordering. Refused by name.
* **No widening of `functions()`** to admit a locally-defined callee, which is
  what would make the planner's call-edge half reachable. That is a decode gate
  with its own reasons and it is not this rung's.
* **No packed-vs-COMDAT placement model.** w-cross's X-d half about *which*
  functions get their own COMDAT is untouched; this rung orders the functions,
  it does not decide their sections. `w232_gl_sep26_implicit.cpp` still refuses.
* **No `hc` inlining model** (§5.2).
* **No `BOARD.md` / `STATUS.md` / `ROADMAP.md` / `gate.sh` edit** — concurrent
  lanes own those. Rows proposed in §10.

| **Y-d** | **A destructor whose delegation target is defined in the same TU is INLINED, and its label stride is not the sum** | **OPEN** | `work/w-order/p/hc_dtor_target_here.cpp`: `Bd::~Bd(){}` beside `M::~M(){}` puts **9** slots between two framed anchors where the two strides sum to 6, at `/Ox` and `/EHsc` alike.
