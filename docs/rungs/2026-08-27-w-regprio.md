## 1. What it admits, and what it refuses

**Admits:** `crates/c2-core/src/codegen/regalloc_worklist.rs` — the sorted
insert `FUN_10b316b1` threads every candidate of a class through, expressed as
executable Rust:

```text
insert new before n  iff  n->[0x0c] <  new->[0x0c]                            /* signed   */
                     or  (n->[0x0c] == new->[0x0c] && n->[0x44] <= new->[0x44]) /* unsigned */
```

Seven decisions, all exposed as named, settable parameters whose default
reproduces the read (`docs/rungs/README.md`'s DECISION-SURFACE CLAUSE): both key
**fields**, both **directions**, both **signednesses**, the **`<=` tie tier**,
and the spill **re-entry policy**. `WorklistComparator::C2` is the default.

**Refuses**, and each is an instruction rather than a shortfall:

* **A register allocator.** Decision 20 §2. The comparator **consumes**
  `cand+0x0c` and `cand+0x44` and computes neither; `cand+0x0c` accumulates over
  the code *the scheduler produced* and `cand+0x44` is stamped over the
  *lowered* tuple list, and the `dag` scoreboard row reads *"the port schedules
  nothing"*. **The work never started needing one**, because the comparator is
  genuinely downstream of nothing.
* **A production caller**, for the same reason — the rung is **additive**, and
  says so rather than manufacturing one.
* **A `ported` numerator for regalloc** (`#3505`, four for four).
* **A count-bearing gate row** (`#3691`).
* **Any promotion of the comparator from `[R]` to `[O]`.** §3 is why.
* **Any re-read of `c2.dll`.** No disassembler ran; `W-REGPRIO-1` says the read
  is inherited, not re-taken.

## 3. THE RESULT — the 20 cells cannot confirm the comparator, and the brief's framing of them is half right

The brief calls these cells *"the densest evidence any allocator claim in this
repo has"* and *"your test population"*. **Both are true of the ORDER and
neither is true of the COMPARATOR**, and the difference is measurable.

`cand+0x0c` and `cand+0x44` **are not observable in any obj**. So *"does the
comparator reproduce cell X"* is not well-posed until a key model is supplied.
With none supplied:

> **Every one of the 40 cell-profiles is reproducible under c2's comparator AND
> under all five planted mutants — including the reversed-direction one.**
> `population_power_over_the_twenty_cells`: five mutants, **five zeros**.

Each witness is *constructed and then run through the worklist*, never asserted.
Board **#3701**.

**The consequence is a `WHITEBOX_LEVERAGE` case at its sharpest**: no black-box
experiment this project can run distinguishes `0x10b2b82d`'s rule from its own
reversal. Only the read does. That is not "the read was cheaper" — it is "the
observation cannot reach the fact at all".

### 3.1 And the record's own model of the `/O1` cells is REFUTED — 6 of 8

`WB_DAGORDER2_FINDINGS.md` §5 explains the `/O1` cells with *"the benefit keys
are equal and the order is decided entirely by insertion sequence"*; §5.0 makes
that sequence the bucket walk, and read **R1** makes the counter per-function
and dense from 1, so bucket order is mint order. Call it **M-TIE**. Under `<=`
it predicts the finished list is the **reverse of mint order**.

Run against the A series as code:

| n | observed | M-TIE predicts | |
|---:|---|---|---|
| 1 | `a` | `a` | ✔ |
| 2 | `ba` | `ba` | ✔ |
| 3 | `bac` | `cba` | ✘ |
| 4 | `dbac` | `dcba` | ✘ |
| 5 | `ebacd` | `edcba` | ✘ |
| 6 | `febacd` | `fedcba` | ✘ |
| 7 | `gfbacde` | `gfedcba` | ✘ |
| 8 | `hgfbacde` | `hgfedcba` | ✘ |

**2 of 8.** §5.0 discloses the n=3 miss and fences its own claim on it; **the
miss is the entire series past n=2**, and the `<` mutant does worse (1 of 8), so
the population refutes the model under *both* tiers.

**Read R4 already contained the reason, and nobody had drawn the line.**
`cand+0x44` is a **dense tuple-visit ordinal** — sole origination `0x10b55fac`,
incremented once per real tuple — so an exact tie in **both** keys is the
exception, not the rule. M-TIE's premise is wrong *in kind*.
`P_REGALLOC` §4's consequence-3 revision box states the entailment (*"the bucket
walk is reached only when two candidates tie on `+0x0c` AND on `+0x44`"*) — and
**§4.1's sentence "at `/O1` most cells are ties" survived R4 unstruck for four
days**, in the same file, two subsections apart. Struck beside it in this lane's
commit, per `ref/README.md` §2.1. Board **#3702**.

### 3.2 The `<=` tier — the answer is conditional, and a flat answer would have been wrong either way

The brief asks specifically: does any of the 20 separate `<=` from `<`? The two
differ on exactly one input class — an exact tie in **both** keys.

| model | separating cell-profiles (of 40) | split |
|---|---:|---|
| **M-FREE** (keys unconstrained — the honest one) | **0** | — |
| **M-TIE** (both keys 0 — the refuted one) | **20** | **11 for `<=`, 9 for `<`** |

> **The 20 cells separate `<=` from `<` only under a key model those same 20
> cells refute — and even there they split 11–9, a coin flip.**

Reporting *"no cell separates them"* would have hidden the 20; reporting *"the
cells confirm `<=`"* would have hidden that the model is refuted and that it
selects nothing anyway. Board **#3703**.

### 3.3 Re-entry: confirmed synthetically, and by nothing else

Consequence 2 is now executable. `reentry_by_priority_differs_from_both_stack_
and_queue` shows all three policies disagree on one input — `ByPriority`
`[1,3,2]`, stack `[3,1,2]`, queue `[1,2,3]` — so *"wrong in both directions"* is
a thing that runs.

**But nothing in the 20 spills.** `cnd_a8` is the widest cell at 8 candidates
against an 18-register callee-saved run. Power over `ReentryPolicy`: **0**. The
cell that would take the claim to `[O]` does not exist and is named as the
cheapest conversion this row points at. Board **#3704**.

### 3.4 A settable parameter nothing can ever grade

c2 reads `cand+0x44` **unsigned**. Signed and unsigned agree at every value
below 2³¹ and differ only at or above it, and the field is a tuple counter — so
separating them needs a function with two billion lowered tuples. **The
observable set is empty, permanently, on this workload.** Said out loud so
nobody later quotes it as confirmed, which is the shape `#3388` punished. Board
**#3705**.

## 6.1 AN INCIDENT THIS LANE CAUSED, IN OTHER LANES' EVIDENCE

**`w-regprio` killed four peer lanes' running workspace suites.** Full write-up:
`docs/rungs/_2026-08-27-w-regprio-incident.md`.

Wanting to kill a stale run of my own, I ran `pkill -f '[c]argo test
--workspace'` from this worktree. The bracket trick is correct and stops the
pattern matching its own argv — **and that was not the hazard.** `pkill -f`
matches a *command line*, and a command line is worktree-independent: every lane
on this box runs a process spelled `cargo test --workspace --release
--no-fail-fast`. It killed `w-inlfit`, `w-regsel`, `w-f0price` and the
coordinator's merged-regcells suite. **My own run had already exited**, so it
bought nothing.

**No file, branch, index or worktree of any peer was touched** — only processes.
But each of those four transcripts is now truncated with no completion marker,
which reads as a *short* transcript rather than a failure, and `w-regsel`'s
wrapper `touch`es a `rtest.marker` on the line after its redirect, so **a marker
may exist for a suite that never finished**. That is this repo's most-repeated
defect class and I manufactured four fresh instances of it in other lanes'
evidence.

`SendMessage` to `w-regsel` returned *"No agent named 'w-regsel' is reachable"*
— peer lanes are separate sessions, and the worktree rule forbids writing a
notice into their trees — **so this is escalated to the coordinator, who must
tell those four lanes to re-run and not to trust a short transcript or a marker
they did not watch complete.**

**The transferable rule, because the standing one covers only half of this.**
`~/.claude/CLAUDE.md` warns that a `pgrep`/`pkill` pattern can match *its own*
argv and gives the bracket trick. It says nothing about matching a *peer's*
argv, and on a box running one worktree per lane that is the likelier failure.
**A `-f` pattern naming a command not unique to this lane is unsafe however it
is escaped.** Kill a PID you launched, or anchor on something lane-unique — the
output path, never the binary.
