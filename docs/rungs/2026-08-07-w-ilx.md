## 1. The result, stated first

> ### **#891's deciding difference IS in the IL, it is three fields, and none of them has an instruction of its own.** `q.a0 = (int)&s->inner;` and `q.a0 = (int)&q;` — same obj, same bind, same layout, same source order, the same emitted `addi rX,r3,K` — differ in the `.ex` at exactly three places: the value's base **token** (`0x0a0c`, the formal `s`, against `0x0a11`, the bound local `q`), its pointer **type** (`86 43 81 20` against `86 43 85 20`), and a whole `33 <int> 60 27 <L*>` **offset-add production present on one side and absent on the other**. `&q` is a bare **load** in the IL; `&s->inner` is a load **plus an add**. `.db`, `.in` and `.sy` are byte-identical and `.gl` differs only in its source-content hash.

> ### **GRID S's `self`-vs-`cross` row is ONE VARINT.** `(int)&s->inner` and `(int)&s->inner2`, which disagree at 1-use-against-1-use, differ in the `.ex` in exactly **one field**: the literal of that same offset-add, `60` against `80 80 00 00 00` — **96 against 128**. `.db`, `.in`, `.sy` byte-identical. It is the same field w-refbind's `#856` found its one byte in, and the escape form is why the streams differ in length: `read_varint`'s short form is a **signed** byte, so 96 fits and 128 cannot.

> ### **And the controls say the bytes alone cannot be the rule.** The *identical* `.ex` difference is present at `(1,1)`, where the objs **agree**, and at `(3,5)`, where they do not — in both pairs. So no predicate over the IL bytes on their own decides this; the decision is a function of the IL fact **and** the use counts, and PREREG §2 registered that reading before the grids were built.

> ### **KEY ILX is REFUTED on a frozen holdout — the SIXTH allocation key to die on fresh cells.** Stated entirely in IL fields, 32 of 32 on every published configuration of GRID S and GRID X, frozen with its sources' and its `.ex` streams' sha256 committed at `96c12b5` before an obj was compiled, and then **31 of 45** on cells no grid had reached. `hit 31 | MISS 14`, `0 MOVED`, `0 out-of-domain`, `0 compile-failed`.

Naming the IL bytes was worth **−4 cells** against a two-parameter arithmetic rule. Both lose to the shipped refusal, which is wrong on **0 of 77**.

The `.gl` column reads *"content hash only"* because with the source path and
every identifier held fixed, the whole `.gl` difference of a minimal pair is one

### 3.1 Two confounds, and the first revision that hit both

**Names are in the IL** — w-refbind's `ilcmp.py` says so and this lane inherited
the mitigation: both cells of a pair carry the same struct name, the same
function name, the same locals and the same formals.

**And so is the source PATH.** The first run of `ilx.py` put each cell in its own
directory and the `.gl` streams differed in **22 byte-runs that were all the
directory name** (`s-11-self/c.cpp` against `s-11-cross/c.cpp`) plus the content
hash that follows it. Every cell now compiles at one shared path,
`work/w-ilx/cell/c.cpp`, serially, and the artefacts are copied out afterwards.
What remains in a `.gl` diff is then the 16-byte source-content hash, which is a
property of the text and cannot be removed. **Board #907.** It is recorded rather
than repaired-and-forgotten because the first run's `.gl` column looked like a
finding.

### 3.2 The decode, against the crate's own readers

`work/w-ilx/exdec.py` — PREREG §3 calls it `decode.py`; the file was renamed
when it turned out to be the *predictor's* engine as well as the decode, and the
rename is recorded here rather than back-edited into the prereg — transliterates
`read_token_var`
(`crates/c2-il/src/func/readers.rs:67`), `read_type` (`:319`), `read_varint`
(`:423`) and `eat_offset_adds`
(`crates/c2-il/src/func/body/shapes/designator.rs:284`) into Python so the decode
is checked against a reader that ships rather than invented here.

One producer statement of `S-11 self`, whole:

```text
  4F 01 0B                          line marker
  B9 0C0A 86 43 81 20               load formal `s`, type S*        <- lvalue
  33 86 41 74 60 27 86 43 86 20     + 96 -> L*
  33 86 41 74 00 27 86 43 F4 08     +  0 -> int*
  B9 0C0A 86 43 81 20               load formal `s`, type S*        <- value
  33 86 41 74 60 27 86 43 86 20     + 96 -> L*
  2C 86 41 74 00                    convert to int
  32 86 41 74                       assign, int
  4B                                end of statement
```

`cross` differs in the value's **one** literal, `60` → `80 80 00 00 00`. `X-35 B`
drops the value's entire `33 … 27 …` line and changes `B9 0C0A 86 43 81 20` to
`B9 110A 86 43 85 20`.

> ### **`eat_offset_adds` returns the SUM.** The fact GRID I found is *one chain being a byte-exact PREFIX of another*, which the shipping reader structurally cannot state: it accumulates `total` and keeps only the last retype. That is **#644 applied to the IL** — a fact that is not one contiguous field, and here not one number either. `exdec.py` keeps the list. **Board #908**, and it is a spec input, not a defect: nothing in the port needs the list today.

### 3.3 Why the two streams differ in *length*, which is not decoration

`read_varint`'s short form is a **signed** byte (`readers.rs:441`, and the
comment there says why). 96 is `60`; 128 does not fit and takes the `80` escape
plus a 4-byte LE `i32`. So the one-field edit is `+4` bytes in `S-11` and `+8` in
`S-21` — one per producer store — which is the arithmetic that makes I4's control
checkable by size alone.

## 6. What the IL fact is, exactly — for the next lane

Stated so it can be implemented or refuted without re-reading this document.
**It is a fact about the `.ex`, and it is not a rule about registers.**

1. A store's value that is a **sub-object address** is
   `B9 <tok> <TYPE> ( 33 <int-TYPE> <varint> 27 <PTR> )* 2C <int> 00`. The
   **presence and the literals** of the offset-add chain are the axis w-spell
   called *"the producer's spelling"* — and the axis is invisible in the
   disassembly, because c2 folds a bind and emits one `addi` for every member of
   the family.
2. `&q` for a bound reference is `vadds == []`. `&s->inner` is `vadds == [96]`.
   **That, and nothing else, is board #891's IL difference** (with its token and
   type, which follow from it).
3. `self` against `cross` is `vadds == [96]` against `vadds == [128]`, where 96
   is also the store designator's first literal. **That is GRID S's whole
   `self`/`cross` row.**
4. **Neither decides on its own** — I4, and §5.1.

### 6.1 The spec, if a lane wants to read it — and why this lane does not

`ProducerKind` (`crates/c2-core/src/codegen/alloc.rs:142`) has three variants and
none can hold any of the above; §6's facts are relations between **two**
expressions, so the carrier is not a per-producer enum at all. The minimal
honest change is to `crates/c2-il`:

* `eat_offset_adds` gains a sibling that returns the literal **list** as well as
  the sum, leaving today's callers on the sum (**#908**);
* a store run records, per producer, `(base token, literal list)` for **both** the
  value and the lvalue, plus the resolved bind;
* `alloc::Producer` gains those and `allocate` reads them.

**None of it is done here, and it should not be done until a key survives a
holdout.** Every field above is reachable and the rule that would consume them is
refuted; shipping the carrier for a refuted rule is how a refutation becomes a
maintenance burden. §5.2's table is the argument: the best-scoring rule on record
over these 77 cells reads none of these fields.
