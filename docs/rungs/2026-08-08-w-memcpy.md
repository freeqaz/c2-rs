## 3. THE THIRD CLAUSE — `call-arg-lit-permuted`, and why it is not a bare widening

The two clauses the board names are real and this lane took both. What it found
between them is that **`?mmioGetInfo`'s slot list never reaches
`seq_call_arg_slots` at all**: `tail_call_shape` refuses it first.

```text
  void g3(void *, void *, int);
  void f(void *a0, void *a1, void *a2) { g3(a1, a0, 72); }
      ->  call-arg-lit-permuted:eof
```

`work/w-memcpy/diag/nog.cpp` and `nog2.cpp` are that cell with and without a
trailing second call; both report the same key. WLA's own doc gives the reason
positively — *"every non-literal slot must be `Formal(slot)`"* — and prices it
at **733 functions** for the tail form. On this workload it is **35** as a first
blocker (`:eof` 34, `:mid` 1).

**It is one locator for two classes.** `tail_call_shape` produces the
`MultiArgTailCall` that the *tail* form emits directly and that the *framed
sequence* form re-reads through `seq_call_arg_slots`. Relaxing the literal gate
there admits the shape into **both**, and the tail form's own emitter
(`lit_slots_text`) carries an `in_place` backstop that would then return
`NotImplemented` — a `codegen-gap` with `fn_gate_refusals` non-empty, which is
board **#139** exactly, and which both `w-clear` and `w-mmio` hit. So it is not
a one-line widening; it is a rung with its own grid, and GRID-L's `tail_*`
control cells (18, at n = 3 only) are not it.

**This lane did not take it, and says so rather than reporting two clauses of
three as two of two.**

## 5. THE TWO `Port=Mismatch`, and the crash behind a refusal

### 5.1 A block plan chosen by an argument's value

The first tip emitted `g3(5, a1, a2)` behind `if (a0 == 0) return 5;` as
prologue · compare · `bf` · the early return's `li r3,5` · `b` · the argument's
`li r3,5` · `bl` — 56 bytes, and it read fine. c2 emits **48**:

```text
   2b030000  cmplwi cr6,r3,0
   38600005  li     r3,5      <- ONE materialization, above the branch, shared
   419a000c  bt     26,+12       by the early return AND by the call
   4bffffe9  bl     ?g3
```

One constant hoisted into the entry block, the **branch inverted** (`bt` where
every other cell of 747 has `bf`), one word dropped. `c2rs gap` said
**`mismatch 2`**; nothing else could have.

**The mechanism was already on record one exit over.**
`SeqEarlyReturnShape::value`'s own doc says *"every exit value in the body must
be distinct, including the sequence's own `SeqTail::Lit`, and the parser
enforces it. Where two exits share a value c2 **merges the arms**"* — and
records that the merge also costs a sixth compiler-label slot where the class
costs five. What is new is that an **argument** literal joins that equivalence
class. It is not an exit, so no exit-distinctness check could ever see it.

**The refusal is on the register, not on the value**, and that is the
conservative direction deliberately: an early return's value and the tail's
`Lit` both materialize into `r3`, and **slot 0 is the only argument slot that
shares a register with them**. Refusing the value collision would rest on having
enumerated every literal the body puts in `r3`; refusing the slot rests on which
register it is. `?mmioGetInfo`'s literal is in slot 2. `mismatch` **2 → 0**.

### 5.2 A 34 GB allocation, and two unbounded walks

`slot_sources` gives a literal slot a **fixed point** — the value is already
where it belongs, because a `li` is about to put it there. A literal in slot `k`
beside a formal *of index* `k` therefore maps two slots to `k`, and the sequence
stops being a permutation. Both the park's chain walks were unbounded loops that
had been safe only because a framed sequence call's slots were all formals and
`tail_call_shape` refuses a value passed twice.

`c2rs gap` over GRID-L died at cell 526:

```text
   memory allocation of 34359738368 bytes failed
```

Repaired at three levels, because one of them is not enough: `park_in_class`
requires a permutation, `park_call_moves` is bounded and returns `Option`, and
the aliasing shape is refused by name (`callseq-multiarg-lit-aliased`). Three
unit tests, one per failure. This is `permutation_cycles`' own doc four hundred
lines up in the same file — *"a crash sitting behind a refusal is latent right
up to the moment somebody needs to look past the refusal"* — arriving for the
second time in that file.

## 6. CLAUSE TWO — GRID-M and GRID-M2, and the decline

### 6.1 GRID-M: `memcpy` is not always a `bl`

232 cells, frozen at `066e00d8` before the first `cl.exe`, 0 compile errors,
every one graded against real `c2.dll`. Six rivals, including **four separately
frozen thresholds** so that no constant is fitted to the grid that produced it.

| rival | score |
|---|---:|
| M-THRESH-32 | 182 / 232 |
| M-THRESH-16 | 174 / 232 |
| M-THRESH-64 | 166 / 232 |
| M-THRESH-8 | 158 / 232 |
| M-VARCALL | 118 / 232 |
| **M-ALWAYSCALL** — the id-keyed rule | **114 / 232** |

The boundary is a size **per alignment**:

```text
   char*    (hint 1)   inline <= 5    call >= 7
   int*     (hint 4)   inline <= 20   call >= 24
   double*  (hint 8)   inline <= 44   call >= 48
   16-byte struct      identical to double* at every size on the axis
   size 0              NO call and NO copy, at both callees
```

`memset` agrees with `memcpy` on every (size, alignment) cell of the boundary.
`docs/IL_INTRINSIC_CALL.md` §5.1's argument — *"the emission depends on the
literal argument values, not on the id"* — now has a number: **118 of 232**, and
they are wrong in the **emit** direction, not the gap direction.

### 6.2 GRID-M2: the one unanimous sub-class is refuted, and a control saves it from being refuted wrongly

GRID-M left exactly one sub-class unanimous — *constant size ≥ 48 ⇒ `bl`*, at
every alignment, for both callees. That fence is fitted to the grid that
produced it, so **GRID-M2 was frozen at `6966e7ad` before it was compiled**: 176
cells, four pointer types GRID-M never used (`void*` among them — the target
function's own), four operand kinds, the 44–96 band. `F-48` scores **114 of
176**, the same as `F-ALL`.

* **Below 48 it predicts inline and c2 CALLS**: `void*` and a 4-byte struct call
  at 44, 46 and 47, where `long long*` and a 32-byte struct inline.
* **When both operands are LOCALS the copy is eliminated entirely** — bare
  `blr`, 4 bytes — at every size up to 96. 44 of 176.

**The control is the part worth carrying.** `gridm2.py`'s first verdict function
had no `none` arm and labelled those 44 bodies `inline`, which reported the
fence refuted *by an inline expansion at 96 bytes*. That reading was false and
was one step from this document. What separated it was reading the **byte count**
beside the relocation instead of the relocation alone — board **#984**'s method,
one lane over, where a byte test read a substitution as a deletion.

Corrected, and split by whether the copy is live:

```text
   'constant size >= 48  =>  bl'      96 / 96   over live copies
   'constant size <  48  => not bl'   18 / 36
   copies ELIMINATED entirely         44
```

So even the surviving direction is conditional on a mechanism the IL does not
carry. **PREREG's decision rule for clause B — ships only if P8 comes back false
— is not met. P8 came back true, twice.**

### 6.3 What clause two would cost, priced

Beyond the expansion rule, from §2's re-derivation: the `40` token is not a call
head to `eat_call_head`; the callee has **no `.gl` token at all**, so

registered "≥ 4 independent refusals" and named four of these five.**
