# W-BK — `/Bk` and `/BK` ground truth, and the hunt for the `lk`/`md` IL suffixes

    Record:    this file

Source: `docs/PRIOR_ART.md` §3.3 (Chappell, verdict ADOPT). Two claims to
verify empirically on XDK `16.00.11886.00` under wibo: (1) `/Bk[path]` becomes
the `-il` argument and `/BK <path>` resumes where the front end left off;
(2) seven IL suffixes exist (`db ex gl in lk md sy`) of which this project has
only ever seen five (`db ex gl in sy`).

## Registered predictions (written BEFORE running anything)

Static evidence in hand at registration time: `strings -a -el -n 2 cl.exe`
shows the option table rows

    BK  →  D=Bk,=bil`*,=bd`1,=bd`P,=*`*
    Bk  →  D=Bk,=bil`*,=*`*

read against the grammar of neighbouring rows as: both set internal flag `Bk`
and variable `bil` (the IL base) from the argument; `BK` additionally sets
`bd` for passes `1` and `P` — i.e. disables the front end. Also present:
`-il%t` (the default `-il` argv template) and the literal `_CL_XXXXXXXXgl`.

1. **P1 — `/Bk` keeps the bundle without strace.** A full `/Bk<base>` compile
   will complete, produce the obj, and leave the IL bundle on disk at `<base>*`
   with no strace unlink-inject needed. Confidence: high.
2. **P2 — `/BK <base>` resumes.** Given a bundle from P1, `/BK` will skip
   c1xx (no c1xx argv echo under `/Bd`) and drive c2 on the bundle, producing
   an obj byte-identical to the pipeline obj after zeroing `TimeDateStamp`
   bytes 4..8. Confidence: medium-high (the pass-disable in the option table
   is static evidence, not behaviour).
3. **P3 — `lk` and `md` do not appear under any flag set this project uses.**
   The five-file model holds for `/Ox /GS- /c`, the workload's
   `/O1 /Oi /EHsc /GR /c`, and the `/Bd /d2nop` capture. If they appear at
   all, it will be under a flag we never pass — candidates: `/GL` (LTCG),
   driving the linker (no `/c`), `/clr`, `/analyze`, PCH (`/Yc`).
   Confidence: medium. I will count every compilation inspected and enumerate
   every file produced, not just the five we look for.
4. **P4 — adopt/decline.** Expected outcome: **decline `/BK` as a replacement
   for the replay seam** (it still spawns `cl.exe`, so it cannot beat
   `c2host` driving `c2.dll` directly, and the replay is already byte-exact),
   but **possibly adopt `/Bk` for capture** if and only if it removes the
   strace dependency while producing (a) the identical bundle bytes and
   (b) the identical reference obj as the current strace path.

**Decline criteria, registered:** I decline `/BK` if its c2 argv differs from
the captured pipeline argv beyond `-il`/`-Fo`, or its obj is not byte-identical
(timestamp zeroed), or it removes no dependency and saves no time. I decline
`/Bk`-for-capture if the bundle it leaves differs in bytes from the
strace-captured bundle, or the obj differs, or it cannot land the bundle in a
caller-chosen directory.

## What `/Bk` and `/BK` actually do (measured)

All runs: `wibo` `1.0.1-23-g4a9dd6f` fork build, `cl.exe` XDK
`16.00.11886.00`, fixture `fixtures/cpp/add3.cpp` unless stated. Lane scratch
(commands, traces, all A/B objs) under the wt-w-bk worktree's `work/w-bk/`;
every claim below names its experiment directory.

### `/Bk` — keep the IL, vendor-sanctioned

* **Bare `/Bk`**: a full pipeline compile completes, produces the obj, and the
  `_CL_<8-hex>` five-file bundle survives in `TMP` — **provided
  `WIBO_KEEP_TEMP=1`**. Without it the bundle silently vanishes: cl opens the
  `/Bk` files `FILE_ATTRIBUTE_TEMPORARY` even though it no longer deletes
  them, and wibo's temp reaper removes them at guest exit (`work/w-bk/{b,c}`;
  re-verified for the path form in `work/w-bk/keeptest`). This is the lane's
  one operational trap and it is exactly the absence-reads-as-success shape.
* **`/Bk<path>` (argument attached)**: the base is taken verbatim; the bundle
  lands at `<path>{db,ex,gl,in,sy}` and `<path>` becomes the `-il` value in
  the `/Bd` echo (`work/w-bk/d`).
* **Case-sensitive; attached-only.** `/bk` → `D9002 ignoring unknown option`;
  `/BK <path>` with a *separated* argument is read as a source file
  (`D9024 unrecognized source file type`) (`work/w-bk/{f,g}`).
* **`/Bk` does not perturb the obj**: plain vs `/Bk` vs `/Bk<path>` at the
  same `/Fo` and cwd are **byte-identical** without even zeroing the
  timestamp context (`work/w-bk/h`).
* **The bundle is a pure function of source + flags, not of the `-il` path**:
  strace-captured `_CL_<hash>*` vs `/Bk`-captured `mybase*` are byte-identical
  stream for stream on 3 fixtures (`work/w-bk/bundlecmp`); the only obj
  difference between those legs is the embedded `/Fo` absolute path in
  `.debug$S` (2 bytes at 0x1c4 here — the `st`/`bk` directory name).

### `/BK<base>` — resume where the front end left off

* Skips the front end: under `/Bd` there is **no c1xx echo line at all**, and
  the c2 argv it constructs is **token-identical to the pipeline's except
  `-il` and `-Fo`** — verified token-for-token (17 tokens, 2 differ,
  `work/w-bk/argvcmp`). Those are precisely the two tokens
  `Toolchain::replay` swaps, so Microsoft's own resume switch independently
  sanctions the replay seam's argv reconstruction.
* At the same `/Fo`, the `/BK` obj is **byte-identical (timestamp zeroed)**
  to the pipeline obj (`work/w-bk/d`, re-proven in `work/w-bk/argvcmp`).
* **Incomplete bundles** (`work/w-bk/inc`): missing `ex`, `gl`, `in` or `sy`
  → `fatal error C1083: Cannot open compiler intermediate file`, no obj.
  Missing `db` → the compile **succeeds** but the obj **differs** from the
  full-bundle obj — `db` is optional-but-consequential input, consistent with
  the five-stream model.
* In cl.exe's own option table (wide strings, offsets in `work/w-bk`):
  `BK → D=Bk,=bil`\*`,=bd`1`,=bd`P`,=*`\*`` vs ``Bk → D=Bk,=bil`\*`,=*`\*`` —
  `BK` is `Bk` plus disabling passes `1` and `P`. Chappell's description is
  correct on all three counts for this build.

### The `lk`/`md` hunt — both found, neither is IL

**Count of compilations inspected: 515** — 25 probe compiles across 15 flag
sets (`work/w-bk/bat`, plus baseline/keep/incomplete runs), and a 490-compile
sweep: **all 245 fixtures at `/Ox /GS- /c` and all 245 at the workload's
`/O1 /Oi /EHsc /GR /GS- /c`, every one leaving exactly the five files
`db ex gl in sy`** (`work/w-bk/sweep-{ox,o1}`; odd-count rows printed by the
sweep loop: zero).

The reason the two extra suffixes exist, settled at the binary level:

* **Every compile stats all seven.** strace of a plain compile shows
  `_CL_*lk` and `_CL_*md` being `newfstatat`'d (ENOENT) and `unlink`'d —
  never created (`work/w-bk/e/trace.txt`). Ghidra decompilation of
  `FUN_0040cb30` in cl.exe (x86, stock `/opt/ghidra`) shows why: the 8-hex
  `_CL_` base comes from `CryptGenRandom`, accepted only if **none of the
  seven** suffix files exists — the seven-name knowledge is collision
  probing plus exit cleanup, from a 7-pointer table at VA `0x4068c0`.
* **`lk` is cl.exe's linker response file, written by cl itself**
  (`FUN_00410987`: `wcscat_s(base, L"lk")`, `_wfsopen(L"wb")`), only when the
  driver goes on to run `link.exe` (no `/c`). Captured via `/Bk` + `/Fe`
  (`work/w-bk/bat/lkkeep`): 50 bytes, UTF-16LE with BOM, CRLF —
  `/out:out.exe` + one obj per line (a `%cdef:%s` arm exists for `/def`
  module-definition files). It is **input to link, never to c2**.
* **`md` is the managed-metadata file of the `/clr` path, written by the
  front end** — the wide `md` string in c1xx.dll (file offset `0x39d6c`) sits
  between `SecurityPermissionAttribute`/`Save` and
  `System.Security.Permissions`, and its single code ref
  (`0x10641445`) appends it to a base name inside COM vtable calls that build
  a `SkipVerification` permission blob and invoke a metadata `Save`. This XDK
  edition **rejects `/clr`** (`D9002 ignoring unknown option '/clr'`,
  `work/w-bk/bat/clr`), so `md` is unreachable in our toolchain. c1.dll
  carries the same string; **c2.dll contains only the five suffixes**
  `db sy ex in gl` (wide, file offsets `0x12760..0x1279c`) — at the binary
  level the back end has no concept of `lk` or `md`.

### The verdict on `crates/c2-il`'s five-file model — NO CHANGE NEEDED

The five-file bundle model is **correct, not lucky**: c2.dll itself
enumerates exactly five stream suffixes; `lk` is a driver→linker artifact;
`md` is front-end CLR metadata that this toolchain cannot emit. No replay has
ever been handed less than c2 originally got. (Evidence only — no `c2-il`
edit, per the lane brief.)

### Adopt / decline

* **ADOPTED (prototype behind the seam): `/Bk` capture.**
  `Toolchain::capture_reference_bk_with` — same contract as the strace path,
  no strace: cl keeps the bundle because its own switch says to. Gated by
  `reference::bk_capture_matches_strace_capture_and_replay`: five streams
  byte-identical to the strace capture, argv token-identical except
  `-il`/`-Fo`, and P0.1 replay byte-exact from the `/Bk`-captured bundle.
  The strace path **remains the default**; switching the default is a
  coordinator decision, not this lane's.
* **DECLINED: `/BK` as a replacement for the replay seam.** Per the
  registered criteria: it removes no dependency (still wibo + cl.exe + the
  full driver), saves no time over `c2host` driving `c2.dll` directly, and
  would replace a *verbatim captured argv* with a *re-derivation from driver
  flags* — a second place to be wrong where today there is none. Its real
  value is banked above: it independently proves the `-il`/`-Fo`-only swap is
  the vendor's own resume semantics.

## Estimate vs outcome

Registered P1 (Bk keeps bundle, no strace): **CONFIRMED**, with one
unpredicted trap — `WIBO_KEEP_TEMP=1` is still required because the reaper,
not cl, was the deleter. P2 (BK resumes, byte-exact): **CONFIRMED** exactly.
P3 (lk/md never appear under our flags): **CONFIRMED for md, REFUTED in the
letter for lk** — `lk` *does* appear under a flag set within reach (`/Fe`,
i.e. driving the linker), which the prediction's candidate list ("linker
feedback") half-anticipated; neither is IL and neither touches c2. P4
(decline /BK, maybe adopt /Bk): **CONFIRMED on both halves**, and both
registered adoption criteria for /Bk were met (bundle bytes identical, obj
identical, caller-chosen dir).
