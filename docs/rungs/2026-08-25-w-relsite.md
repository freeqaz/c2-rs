## 0. The one-paragraph answer

**`FUN_10bbffbb` @ `0x10bbffbb`** — 98 bytes, one caller, reached from arm 7 of
the IL-record dispatch at `0x10bc38a1`. It converts the IL opcode with
`sub eax,0x1f` + four `dec eax`/`je` + a fallthrough, **six arms, each one
`mov bl,imm8`**: `1F→2, 20→1, 21→4, 22→6, 23→3, 24→5`, stored into the **high
nibble of `[[node+0x2c]+0x15]`**. **`relation code = IL opcode − 0x1E` is
refuted from the code on 6 of 6** — including `EQ`/`NE` — because **the site
stores the COMPLEMENT of the source relation**, confirmed by a capture against
real `c2.dll` in which **exactly one byte of a 2 760-byte `.ex` differs** across
six TUs and takes the values `1F`..`24` for `== != <= < >= >`. And it was
already named: `whitebox/ref/P_ILRECORD.md`'s arm table gave arm 7 and its
callee, published by `w-read-r5`, and **neither `w-c7` nor `w-relread` read
it** — `#3098`'s family, **seventh instance**, and the first where the prior art
was a `docs/whitebox/` spec rather than a board row.

## 2. The thing to carry off this lane, and it is not the address

`w-relread` closed with: *"the algebra of a permutation table determines the
labelling only up to the automorphisms of that algebra — a consumer or a name is
required."* That is true and it is **not sufficient**.

> **A name and a consumer fix a permutation's LABELLING. Neither fixes its
> SENSE.**

The enum was read out of the image, six consumers agreed with it, a seventh
route with no image access agreed — and **the map from the IL opcode was still
off by a global complement**, because every one of those consumers reads a
carrier **two hops downstream of the producer**. The producer had to be read.

**That is the argument for location reads over value reads in one sentence**,
and it retroactively justifies `w-c7`'s prereg **W2** scoring a MISS for
recovering a value instead of a location — *even in the case where the value
had looked right*. Board **#3550**.

The sub-rule, which cost me prereg **S7**: **a consumer's field is not the
producer's field.** This compiler carries one enum in **three** differently
shaped carriers — a 4-bit nibble, a byte, and a 5-bit masked field — and a read
that assumes one of them is *the* enum will get the sense wrong without any
table ever catching it.

## 3. The confirmation probe — one byte of 2 760 `[O]`

Prereg **M4**, and the standing caveat's whole point: `[R]` means *the
instructions were read correctly*, not *this is what c2 does*.

Six one-function TUs, identical but for the operator, captured with
`c2rs capture`. Every `.ex` is **2 760 bytes**. The number of byte offsets that
differ across all six is **one** — `0x0aa7` — and it takes `1f 20 21 22 23 24`
for `== != <= < >= >`. Denominator: all 2 760 positions.

This measures source-relation → IL-opcode **without going through the port's
naming at all**, which is what makes the complement a measured fact rather than
a re-labelling argument. `Rel::from_opcode` is **confirmed, not corrected**.
