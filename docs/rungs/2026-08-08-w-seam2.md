## 2. What #844 turned out to be

`w-heap` §5's price lists **F3** (`crates/c2-il`) and **#844**'s seam
(`crates/c2-core`) as two rows. `w-f23` measured them as **one refusal seen from
two ends** and this lane confirms it from the other end: the emitter was never
missing. `codegen::frame` owns the prologue and the 96-byte class,
`calls::call_seq_text` owns the `bl`'s self-encoded displacement and the REL24
site, `leaf::store::scheduled_gpr_run` owns the run, `coff::pdata` and
`coff::label` own the unwind word and the `$M`/`$T` labels. Board **#842**'s
lesson applied — *for each fact the obj states, go read whether a module already
produces it* — and five of six already did.

**What was missing is a CARRIER**, and it is a model defect:

> `IlFunction` carried an op stream **or** a call, and `codegen::select_function`
> tries them in a **fixed order**. A function carrying both emitted one and
> silently dropped the other — board **#232**'s exact mechanism, live for 255
> commits under a scan reading `mismatch 0`.

### 2.1 The repair is not an ordering fix, and that distinction is the rung

Trying the composition earlier leaves **two fields that can both be set and one
that wins**; the next widening reintroduces the race somewhere else. So the run
lives *inside* the sequence it belongs to — `CallSeq::store_run:
Option<StoreRunPrefix>` — and `IlFunction::ops` stays **empty** for the shape.
There is nothing for a dispatch order to get wrong.

`IlFunction::store_run_carried_twice` is the backstop and `select_function`
refuses a violation **by name** rather than picking a winner, because picking a
winner is the defect itself.

The rest of the shape was already modelled and is reused rather than restated —
this is `EmptyCtorBaseDelegation`'s own sequence with a run in front of it:
`saved = [this]` (#869: the one value live across the one call),
`SeqTail::SavedFormal { param: 0 }` (the constructor's implicit `return this`,
already emitting `mr r3,r31`), one call, no guard, no early returns. `w-heap`'s
prereg **P2** recorded *"`CallSeq` has no `SeqTail` for return-the-saved-formal"*
— it does, and has since the generated base delegation landed.

**Consequence: the selection is `Selected::Seq`.** That is one of the four shapes
#322 closed, which is what makes §3 a measurement rather than an argument.

### 4.2 What the FIXTURE said, twice

```text
  void P::lf(unsigned a, unsigned b) { m0=0; m1=b; m2=a; }         LEAF
      li 11,0 ; stw 5,4(3) ; stw 4,8(3) ; stw 11,0(3) ; blr
```

**The two unproduced stores swap — and only when the call passes `a`.** `a` is
live until the `bl`; `b` dies at its own store. With a nullary callee nothing is
kept alive and the run is the leaf's, word for word.

itself. Not one of its 36 accept cells stores the formal the call passes. That is
`w-heap` §5's own sentence landing on this lane: *"a generated axis is only as
good as the axes it varies"* — and the axis it did not vary was inherited from
the sweep fragment's vocabulary, which does not vary it either.

**And GRID S2 had it all along and could not report it.** Seven of its sixteen
holdout cells store `mA = initSize`, and all seven graded `mismatch` when they
were first run through the differential. They were built to score the `mr` slot
rule, which they scored correctly on all sixteen — a grid measuring one axis is
blind to a second one it happens to cross.

## 5. The `mr r31,r3` slot: #867 ships UNCHANGED, and its domain is located

The one modelled fact this lane registered as *shipping* (prereg §2.4).
`w-seam`/#867 fitted it on 24 cells and held it on an 18/18 fresh holdout, and it
had never shipped:

```text
  stores_before_mr = nprod - 1 + min(u, 2)
```

Scored cell by cell against real `c2` bytes:

| grid | cells | HIT | MISS |
|---|---:|---:|---:|
| **GRID S** (frozen fit set) | 36 | **32** | 4 |
| **GRID S2** (declared post-hoc holdout: `nprod = 3`, `u = 2/4/5/6`) | 16 | **16** | 0 |

**Every miss is `nprod == 0` with `u ≤ 1`**, where the formula is negative or off
by one — `(0,0) → −1` against an observed 0, `(0,1) → 0` against an observed
**1** — and at `nprod == 0, u ≥ 2` it is right on five distinct `u` levels.

So **the rule ships unchanged and its domain is refused rather than patched.**
The correcting clause (`min(u, 1)` at `nprod == 0`) is named and not taken: it
would rest on **one** structural cell, and clamping the formula at zero would
emit `mr 31,3 ; stw 5,16(3)` where c2 emits `stw 5,16(3) ; mr 31,3` — two right
words in the wrong order, an obj that still links.
`the_mr_slot_domain_boundary_is_refused_with_its_counterexample` pins the
counterexample beside the refusal.

**`u` has a second reading and the two are provably the same number.**
`layout_slots`'s `u` is the *leading run* of unproduced stores in the final order
(#584), not the total. `store_order` forbids a store whose producer has rank `j`
from occupying a position below `u + j`, so the leading run is always at least
`min(2, total)` and therefore `min(leading, 2) == min(total, 2)` identically.
That is an argument, not a coincidence of the grids — recorded because 52 cells
agreeing would otherwise read as an unseparated axis.

### 5.1 A third refusal the grids did not predict either

`WD::WD(unsigned a, unsigned b) { m1 = 70000; m2 = b; p0 = this; Alloc(a); }`

```text
  lis 11,1 ; stw 5,8(3) ; stw 3,0(3) ; mr 31,3 ; ori 11,11,4464 ; stw 11,4(3)
```

**The `mr r31,r3` lands BETWEEN the `lis` and the `ori`.** `collect_store_run`
refuses a multi-word literal only *beside another producer*, and says so with its
reason: a run whose only producer is wide is one live range with nothing to
interleave with. **True of a leaf.** In a framed body the copy is a second thing
that can land there, and the splice places words *between* slots — a producer is
one slot — so it can never reproduce this. Refused, in the reader, with the obj
in the comment.

## 6. Where the refusals live, and why they moved

Both §4 and §5.1 shipped in `codegen::store_run_call` first.
**`crates/c2-harness/tests/census_gate.rs` failed**, naming three functions the
census counted in class and `PortC2` refused — an error term on the published

**backstops**, so the two locators cannot drift and a parser that widened past
its witness comes out as a gap rather than as bytes.

### 6.1 The gate that silently never fired

The live-argument gate was first written as
`st.value_is_load && st.ops.get(1) == Some(&IlOp::Load(live))` and **matched
nothing**. `StoreStmt::value_is_load` means the value is an *indirect load*
(`s->m = t->n`); a **formal**-valued store has it `false`, with
`IlOp::Load(tok)` in the value position. The predicate read correctly and was
inert.

Recorded rather than quietly fixed, because of how it was caught: not by reading
the predicate, and not by any grid — **by `census_gate.rs` still naming two
functions after the gate had supposedly landed**. A gate that refuses nothing is
indistinguishable from a gate that is not there, and the only instrument that
could tell was the one that compares two independent answers.

## 10. Found and not taken

1. **The hoist rule for a live-argument store** (§4.4). Visible in
   `work/w-seam2/grid3/`, worth the widest remaining slice of this family, and it
   needs a grid built for *it* — not the four cells that refuted this lane.
   Whoever takes it inherits GRID S3 and GRID S4 and must not fit on them.
2. **#868/#836, `alloc`'s mixed-kind refusal** — now the frontier's blocker for
   `xboxheap` and the row `w-seam` and `w-heap` both measured and declined.
   `w-heap` §4.1 names the route (`admit only IlOp::AddrOf`) and §4.1.1 names the
   counterexample that kills the obvious lift.
3. **#839, the reference bind** — `w-f23` §5.1 prices it to the byte: two reader
   obligations, a local as a store destination and the same local as a store base
   carrying its own symbol. It is what makes `xboxheap.cpp` itself unreachable.
4. **A run AFTER the call** (#872) — six PLAN-only and six DIFFER cells in
   `w-seam` §3.3 with a visible mechanism and no rule fitted. This lane's
   `gate_composition` refuses a multi-call sequence by name for that reason.
5. **The sweep fragment does not vary the live-argument axis.**
   `88-store-run-call.py`'s runs store `mSize = size` and `mFreeHead = this` and
   never the call's own argument — which is why 1,576 generated cases were at 0
   mismatch through both of this lane's wrong emits. A fragment that crossed the
   stored value against the call's argument list would have caught them; that is
   the cheapest instrument on this page and it is not built here.
