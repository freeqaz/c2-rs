## What it admits, and what it refuses

Three commits of decode, one of obj shape, and an explicit refusal in between.

**Decode** (`crates/c2-il`). `ops_start(seg, lo)` replaces the hard-coded
`lo + 3` at the three forward body readers. W-LO taught the splitter and the
codec that a `??__E`/`??__F` body opens on a bare `4C` with no `4F 11` record and
deliberately left the parser behind; handing those readers a bare `4C` did not
make them refuse, it made them **start two bytes into the body**. `eat_fn_tail`
accepts an optional empty module-level scope `53 54 00` before the `4D`, present
exactly when the last function in the module is a `??__E` (separated by a
source-order-swapped control pair; `??__F` does not carry it).
`sym_addr_tail_call` admits **two** symbol operands when, and only when, the body
opened on the bare `4C`.

**Obj shape** (`crates/c2-core/src/coff.rs`). `emit_dyninit_obj` builds the
8-section obj, with `string_comdat_name` computing the `??_C@_0…` name from the
literal's bytes. Three places `OBJ_DYNINIT_SHAPE.md` and the reference bytes
disagreed, with the bytes winning, are marked `CORRECTION` in the source.

**The refusal that remains, and it is the whole result.** A body admitted by the
widened decode reaches `codegen::calls::sym_slots_text`, whose independent
`count != 1` backstop returns `NotImplemented`. Nothing can mis-emit: the honest
bucket for "decoded, not yet emittable" is `codegen-gap`, and the license TUs do
not even reach it — they still refuse one step earlier, at data-symbol
resolution.

## The prereg's §5 decline hypothesis is REFUTED — measured, not argued

§5 pre-registered the most plausible reason to decline: *"the IL does not carry
the object's `sizeof`, its alignment, or the literal's bytes."* **It carries all
three.** Nine captures, `/Ox /GS- /c`, one TU per row, `struct L { L(const
char*, int); <members> }; static L sL("abc", 0);`:

### The object — `.gl`, immediately after the `$sL` name run

```text
  24 73 4c 00  <tag> 06 00 02 04 <size> 00 61 00 80 07 10 00 00 01 00 <ix> 0a
  $  s  L  \0
```

| members | `sizeof` | `alignof` | `<tag>` | `<size>` |
|---|---:|---:|---|---|
| `char c;`        |  1 | 1 | `82` | `01` |
| `short c;`       |  2 | 2 | `84` | `02` |
| `int c;`         |  4 | 4 | `86` | `04` |
| `double c;`      |  8 | 8 | `88` | `08` |
| `int a,b,c;`     | 12 | 4 | `86` | `0c` |
| `double a,b;`    | 16 | 8 | `88` | `10` |
| *(empty)*        |  1 | 1 | `82` | `01` |

**Correction to `IL_TYPE_TAGS.md` §1.** That table is headed `| size | tag |`
and reads 1→`82`, 2→`84`, 4→`86`, 8→`88`. In this slot the tag is the object's
**alignment**, not its size: rows 5 and 6 hold the tag fixed while `sizeof`
moves to 12 and 16. Scalars cannot separate the two readings because their size
*is* their alignment, which is why the scalar capture matrix could not see it.
This is the aggregate matrix §1 says is owed ("the aggregate form needs its own
capture matrix"); it does not contradict §1's positional rule, it fills the hole
§1 names. `emit_dyninit_obj` wants exactly these two fields as
`BssObject::natural_align` and `BssObject::size`.

`$sL$initializer$` follows as the very next name run — `BssObject::
initializer_symbol`, read rather than synthesized.

### The literal — `.in`, a file this port has never parsed

```text
  <token:2> 00 03 <len:1> <bytes…> 07
```

| source | bytes |
|---|---|
| `"abc"`      | `ef 09 00 03 04 61 62 63 00 07` |
| `"abcdefgh"` | `ef 09 00 03 09 61 62 63 64 65 66 67 68 00 07` |

`<len>` counts the trailing NUL, so the payload is `StringLiteral::bytes`
verbatim. `.in` is carried by `IlBundle` and read by nothing:
`grep IL_SUFFIXES` finds it in the suffix list and in two round-trip tests, and
there is no parser.

So the decline is **not** "the input is missing". It is "the input is present,
behind two readers nobody has written". That is a strictly better-priced
position than the prereg expected to be in, and it is why this rung declines the
target without declining the item.

## Found and not taken

Ranked. The first is the whole remaining lane.

1. **The four pieces between the two halves.** In dependency order:
   (a) a `.gl` data-symbol reader — align tag, `sizeof`, linkage, and the
   `$initializer$` name (the grid above is the whole specification, plus one
   `size > 127` probe for the varint and one `extern`-linkage probe for the
   decorated-name/EXTERNAL pair);
   (b) a `.in` string-literal reader — the record above, plus escape/wide/
   embedded-NUL probes, though `string_comdat_name` already declines outside its
   measured escape set so the fence exists;
   (c) `resolve_data` widening so a same-TU-defined symbol and a `25`-separated
   string COMDAT resolve;
   (d) the `PortC2::build` recognizer that calls `emit_dyninit_obj`, plus
   `sym_slots_text`'s two-symbol schedule.
   **(c) is the dangerous one and should not be rushed.** It is global: 39,967
   functions currently file under `data-sym-*`, and a widening that names the
   wrong symbol is a relocation against the wrong symbol — a wrong-bytes emit,
   which prereg §3.2 registers as *the single worst outcome of this lane*,
   strictly worse than the honest refusal standing today.

2. **The general two-symbol tail call is measured and still declined.** Six
   captures at `/O1 /Oi /EHsc` — two `.rdata` strings, two `.bss` externs, one of
   each, with a literal on either side — show **one independent `lis`/`addi` pair
   per symbol and no pool-offset difference anywhere**, which refutes the
   mechanism `IL_CALL_IN_EXPR.md` §17.3 (a)/(b) states for its 18,933 functions.
   Not taken because §17.3's population implies an argument emission order this
   port does not ship: `g(&gA, 7, "cc")` puts `li r4,7` **after** both `addi`s,
   where `permute_args_parts`' descending walk puts it before. That is an
   emit-side rung with its own captures. The refusal is fenced to the bare `4C`
   in the meantime — a scope decline with a measured ceiling, not an unknown.

3. **`PORT_WRITER_SECTIONS` is still a transcription, and this rung leaves it
   there — deliberately, and stated so.** `gap.rs`'s six-name list mirrors
   `coff.rs`'s shell sections by hand. This rung did **not** change the shell's
   section list; `emit_dyninit_obj` adds `.text$yc`, `.bss` and `.CRT$XCU`, but
   it has no caller, so the port's *reachable* section set is byte-for-byte what
   it was and the transcription is still accurate. It stops being accurate the
   moment item 1(d) lands, so that rung must publish the constant from `coff.rs`
   and have `gap.rs` import it. Filing this as "left in place, with the trigger
   named" rather than fixing it blind.

4. **`.debug$S` is 0xac for both license TUs and 0x94 for the fixture.** The
   shell emitter builds it from the source path; nothing has graded it against a
   reference for this class, because nothing has emitted this class. It is a
   silent input to 1(d) and should be byte-compared before the recognizer is
   trusted.
