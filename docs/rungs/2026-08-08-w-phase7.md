## 2. The three populations, and why they are three

The spec's §6 is written as if there were one channel. There are three, they
are nested, and only the innermost is a defect:

| | count | of |
|---|---:|---|
| `.in` tag-02 references whose target is in `dom(alias)` — **reachability** | **94,786** | 1,934,614 refs, on **832 of 878** TUs |
| relocations `data_tu` would hand the writer | **0** | — |
| …of those, naming an alias — **the live defect count** | **0** | a **zero denominator**, not a passed test |

**`alias-inref-alias` and `alias-inref-records` are the same number to the
digit — 94,786 and 94,786.** That is not a coding accident: it says **every
`.in` record that names an alias names exactly one**, which is what a vftable
looks like — one deleting-destructor slot per table. It is stated because two
keys reading equal is the shape a lane should check rather than admire, and
this one survives the check.

`alias-datatu-relocs` is **0** across the whole workload, so
`alias-datatu-relocs-alias 0` is `w-emitp` §4's `StreamNull.cpp` rule in its
purest form: **a zero denominator is printed as a zero denominator.** The
class is kept out today by `funcs.is_empty()` and by `data_tu`'s exhaustive
`.gl` accounting — **two fences that have nothing to do with aliases**, which
is precisely board #232's shape and the reason the clause was written anyway.

## 3. THE REFUTATION — read the oracle's own relocations, over every section

`ObjImage::text_comdat_relocs` could not have answered this. A vftable is
`.rdata`, and that reader skips non-`.text` sections **by construction** — so
asking it *"does c2 ever relocate against an alias"* returns `0` for a reason
that has nothing to do with aliases. `docs/STATUS.md` trap 5, in the shape
where the instrument's **scope** supplies the zero. `ObjImage::relocs_named`
is the widened walk, and its unit test asserts both halves: the new reader
sees the `.rdata` record and the old one sees none of it.

Over 878 TUs: **1,819,168 relocations, 4,248 of them naming a `dom(alias)`
symbol, on 675 TUs.** Two sites, both real:

```
.rdata  va=0x04  ty=0x02 (ADDR32)  ??_EMessage@@UAAPAXI@Z      the vftable slot
.text   va=0x08  ty=0x06 (REL24)   ??_ELocalUser@@UAAPAXI@Z    an adjustor thunk's branch
```

And the symbol table says what the name means
(`src/lazer/game/HamUser.cpp`, `work/w-phase7/symdump.py`):

```
#535  sec=0    class=EXTERNAL       ??_GLocalUser@@UAAPAXI@Z
#536  sec=0    class=WEAK_EXTERNAL  ??_ELocalUser@@UAAPAXI@Z
                 -> default sym #535, Characteristics = 2
#633  sec=160  class=EXTERNAL       ??_GLocalUser@@UAAPAXI@Z
```

The standard MSVC weak-external triple: an **undefined placeholder** for the
default, the weak record, and the COMDAT **definition** of the same default
name.

> ### So `dom(alias) ∩ E = 0` is a statement about **COMDAT LEADERS**, not about the symbol table. c2 **does** write a symbol record named `??_E<X>`. §6 step 4 read as *"the name never appears"* is false; read as *"the name is never a `.text` COMDAT leader"* it is true, and this scan re-measures it at **0** over 878 TUs — `alias-dom-emitted 0`, `alias-dom-emitted-tus 0`.

`Characteristics = 2` is `IMAGE_WEAK_EXTERN_SEARCH_LIBRARY`, on **all 4,013**
records (`alias-weak-not-search-library 0`). The reader **returns** the word
rather than filtering on it, and a unit test pins that: a reader that filtered
would report a different value as *absence*.

94,250 of 98,263 entries produce no weak external, so *which* entries are

graded:

| | |

## 5. WHAT SHIPPED, AND BEHIND WHAT FENCE

**Behaviour, one clause.** `IlBundle::data_tu` **refuses** a TU when an
emitted object's name is in `dom(alias)`, or when any relocation it would
emit names one. It does **not** resolve — resolving is what the measurement
above refutes. The reasoning is in the code and is worth restating: the
relocation's *name* is already right; what is missing is a **weak-external
record and its undefined default placeholder**, and this writer has neither.

The clause is guarded on `dom_with_body`, which is a **precondition and not a
statistic**: suppressing a name that has a body would be a symbol deletion,
not a filter. Measured **0** over 96,220 records; the reader refuses the TU
outright if it is ever nonzero, rather than applying a rule whose safety
condition has failed.

**Population today: 0.** The three `cfg(test)` bodies are the only things that
exercise any of it — which is the point, and is said in their doc comments.

**Readers, three.** `ObjImage::weak_externals`, `ObjImage::relocs_named`,
`IlBundle::in_alias_report`. All read-only, all fail-closed, none in an accept
path.

**Instrument, 46 keys.** Four groups that answer four different questions and
must not be summed: the decode's invariants with both nulls; `dom(alias) ∩ E`
against the real obj; the reachable `.in` population; and the live writer
population. Plus the weak-external grade, rule R, and the three
`alias-weak-needed-*` intersections.

**What did NOT ship, and why:**

* **The weak-external EMITTER.** 675 TUs need it and
  `alias-weak-needed-in-b-and-c` is **0** — it converts nothing on this
  population and cannot until `B∧C` grows past 151 in a direction that
  includes a realised alias. Priced at: two symbol records and one aux record
  per realised alias, plus their placement in the symbol table's order, which
  is unmeasured. **Board #1506.**
* **A Rust port of the emit-set model.** Prereg decline clause **D3**, fired
  as registered. §7.2.

4. `IlBundle::emit_set()` — the fixpoint, `Seed | R(π)`, alias applied once at
