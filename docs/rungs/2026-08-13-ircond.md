## 2. What it admits, and what it refuses

### 2.1 The IR, in five lines

`crates/c2-core/src/codegen/block_ir.rs`, one new module, zero new dependencies:

* **`BasicBlock`** — a straight-line instruction run (`body: Vec<u8>`, control
  transfers excluded) plus **exactly one** `Terminator`. "Exactly one" is the
  *type*, not a check: the terminator is a field and not a list, so a block with
  two or with none is unspellable.
* **`Terminator`** — all six of item A's kinds and no seventh: `FallThrough`,
  `Bc { bo, bi, taken }`, `B { target }`, `Bclr { bo, bi }`, `Blr`, `TailCall`.
* **`BodyLayout`** — two phases. `declare(name) -> BlockId` mints identity and
  nothing else; `place(id, body, term)` appends the block to the **emission
  order**. Emission order is therefore *placement* order — something a lowering
  did on purpose and can be asked about — never a traversal's incidental order.
* **`BlockOrder`** — the order the lowering *claims*, travelling with the bytes
  it produced. One variant, `IlStatement` (§3.4).
* **`finish() -> FinishedBody`** — walks the emission order once, lays the bytes
  down, hands every intra-section branch to `labels::LabelMap`, and returns
  `{ text, tail_sites, order }`.

Every terminator is backed by an encoder that **already existed** in
`codegen::encode` and was **already byte-graded by a shipped lowering**, so none
of the six is a mechanism invented for the IR: `Bc`/`B` via `labels::Form`
(`cond_tail`, `calls`' early return), `Bclr` via `encode_bclr` (`pool_free_list`,
`counted_accum_loop`, `float_walk_loop`), `Blr` via `encode_blr` (every leaf),
`TailCall` as the placeholder `Selected::Tail` already hands back.

### 2.2 What it refuses, by name

Six refusals, all ordinary `Err` and never a panic — the release build the gate
actually runs has `debug_assert` compiled out:

| refusal | why it is a refusal and not a repair |
|---|---|
| a body with **no blocks** | an empty `.text` for a function is a shape no measured byte backs |
| a block **declared and never placed** | it has an identity and no position; the map would catch it only if something happened to branch there, and would then blame the label |
| a block **placed twice** | two positions claiming one block makes the emission order ambiguous — the one property item A requires to be explicit |
| a block whose body is **not a whole number of words** | every later block, displacement and relocation offset would be out by the remainder |
| the **last block falling through** | control would run off the end of the function's own `.text` |
| a **`BlockId` from another layout**, on both the place path and the branch path | otherwise it silently names a neighbour's block |

### 2.3 The four rules it delegates rather than restates

Everything that makes a branch *correct* stays in `codegen::labels` — §6.2 item
**B**, board **#290** — and is delegated to, never re-derived:

1. **the two encodings** (item C, #191): a `bc`/intra-section `b` carries a true
   self-relative displacement and takes no relocation; an external `b`/`bl`
   carries a section-start placeholder and a `REL24`. `Form` has no external
   variant, which is exactly why `Terminator::TailCall` is a *different
   terminator* rather than a third `Form`;
2. **the forward-only rule** (`resolve` invariant 4) — the compiler-label
   counter;
3. **the displacement range check** (item D), and the long-branch expansion's
   continued absence;
4. **the placeholder and definedness invariants.**

A block IR is the obvious place to grow a second, friendlier copy of rule 2.
`tests::a_backward_branch_is_refused_by_the_label_maps_own_rule` reads the
refusal for `labels.rs`'s **own words** — `plan_labels`, the counter — and not
merely for "backward", so a second copy makes it go red.

### 2.4 What it does NOT build, and where each was declined

| item | state at tip | why not here |
|---|---|---|
| **E** — condition-code model, two producers | absent | `Terminator::Bc` carries the raw `(BO, BI)`, so `BI` already *encodes* `cr6` bit 26 vs `cr0` bit 2. The distinction is **carried without being modelled**; an item-E lane adds the producer side without changing a byte here |
| **F** — values live across block boundaries | absent | `wb-live` (#3049–#3057) made it specifiable; `w-dagorder` has just repriced what still blocks it. Out of scope by this lane's own bounds |
| **G** — a per-shape record of §3.5's folds | absent | needs the band-1↔band-2 decision (§8.1 B1), which is unmeasured |
| an instruction scheduler | absent | §6.3, and `w-dagorder`'s finding. The IR is *shaped so one could later be a pass over a block's `body`* — that is what a block owning its instruction run buys — and that is the whole of the claim |
| a second `BlockOrder` variant for §3.4.1 | absent | §3.4.1's inverted layout is downstream of **code motion**, which §6.3 declines to characterize. A variant would name a layout no lowering here can produce |

### 2.5 The re-expression

`cond_tail.rs`'s `cond_pair_parts` is now three declared blocks — `entry`,
`then`, `else` — placed in the order §3.4 measured, and the `bc`'s displacement
is **derived by the label map from where `else` actually landed** rather than
computed as `4 * (then_steps.len() + 2)`.

The module's own doc named this gap, and the correction is filed **in place**
beside the paragraph it retires rather than overwriting it — that paragraph is
cited by line number in `STRATEGY_REVIEW_2026-08-13.md` §2 as the moment the CFG
phase was scoped down to a single shape.

* **It was RIGHT when it was written, and it stopped being right eleven hours
  later.** `cond_tail.rs` landed in `be2f00cd`, 2026-08-04 **09:38 UTC**;
  `labels::LabelMap` landed in `b662bc63`, **20:32 UTC the same day**, in a
  commit that has this one as an ancestor (`git merge-base --is-ancestor`
  confirms the direction; the first draft of this rung asserted the opposite and
  is corrected here rather than quietly). So "building it now would be a
  mechanism with no fact behind it" was a correct reading of the tree it was
  written against. **The checkable finding is the other one: the map arrived,
  this file was never revisited, and for nine days and ~150 landed rungs neither
  module pointed at the other.** The failure was not the judgement — it was that
  nothing re-asked the question when its premise expired.
* **the trigger it waits for is the wrong trigger.** A displacement computed from
  `then_steps.len()` is a second, private encoding of where the else block
  landed. Two encodings of one fact is the shape `GAPS.md` §6 keeps recording —
  it is what got `calls.rs` a fixup list with one implicit target whose identity
  was carried by *the shape of a tuple*.

The arithmetic it replaces **agreed with the map** (`4*(n+2)` *is*
`else_start − bc_site` for this shape), which is precisely why this class was
the right one to re-express: a disagreement would have been a defect in the new
mechanism, visible immediately against §4.1's published bytes.

`CondPairParts` keeps its exact shape — `{ text, branch_offsets: [u32; 2] }` —
so `lib.rs`'s packed emitter and `comdat.rs`'s `/Gy` emitter are untouched, as
§1.2 predicted.
