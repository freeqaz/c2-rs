# WCR — `return a->m() > b->n();`, and the 760-function residue that was a `float` row

    Tag:       WCR
    Slug:      cmp-order
    Date:      2026-07-31
    Fixtures:  wcr_cmp_order.cpp wcr_cmp_order_neg.cpp
    Census:    673006 → 673073 (27.33 % → 27.33 %), +67
    Record:    this file; the family's decomposition is `docs/CMP_PRODUCES_A_VALUE.md`
               and `docs/rungs/2026-07-31-cmp-two-calls.md`

WCB shipped the two-call comparator's `==` and left one non-zero refusal behind:
`mcall-cmp-rel`, **760 functions**, "any relation but `==`". This rung admits `>`
and `<` — the only two of the five with any witness at all — and realizes
**67**.

**The other 693 compare `float`s.** The ceiling was named by *relation* and never
crossed with the *operand type*, and the row underneath it is a conditional
branch and a saved FPR, not a comparison spine. That is the same failure this
family has now produced twice: `docs/CMP_PRODUCES_A_VALUE.md` was declined
because a comparison row turned out to be a **frame class**; this one is a
comparison row that turns out to be a **floating-point class**.

## What it admits, and what it refuses

```text
  26 <m1> B9 <r1> <ptr4> [2C…] 99 <ptr4> 00  BD <ret> 00 <id>  4C
  26 <m2> B9 <r2> <ptr4> [2C…] 99 <ptr4> 00  BD <ret> 00 <id>  4C
  22 | 24                 the `<` or `>` operator (`1F` is WCB's `==`)
  [ 2C <int4> 00 ]        an `int`/`unsigned` result converts; a `bool` one does not
  41 <TYPE> …             returned
```

```text
  bool f(const U* p, const U* q) { return p->m() > q->n(); }      84 B, F = 112
    … mr r31,r4 ; bl ?m ; mr r30,r3 ; mr r3,r31 ; bl ?n
    subfc r11,r30,r3 ; eqv r10,r30,r3 ; srwi r9,r10,31 ; addze r8,r9
    clrlwi r3,r8,31                                            (/Ox; /O1 r11,r11)

  bool f(const U* p, const U* q) { return p->mp() < q->mp(); }    76 B, F = 112
    subc r11,r30,r3 ; subfe r11,r11,r11 ; clrlwi r3,r11,31     — POINTERS
```

**Four things are measured here and none is guessable from the source.**

### 1. Signedness is not in the operator byte, and a POINTER is unsigned

`22` is both `<`s. The only thing separating a five-word spine from a three-word
one is the two callees' result TYPEs — `86 41 74` against `86 42 75` — so
`operand_signedness` peeks both `BD` tokens and is the sole reader of that fact.
It refuses when they disagree, which is a **second lock**: c1xx already inserts an
explicit `2C` convert on whichever side needs one, and a mixed comparison
therefore refuses in the grammar, in either of the two byte positions the convert
can occupy (measured in both directions, for `int`/`unsigned` and for
`void*`/`const char*`).

**And a 4-byte pointer takes the unsigned spine byte for byte** — `p->mp() <
q->mp()` is the same three words `p->um() < q->un()` emits. That is **66 of this
rung's 67 realized functions**. It is read off a reference obj rather than
deduced from "a pointer is an unsigned number", and every pointee width lands on
the same `86 43` in a `BD` result position (`char*`, `void*`, `double*`, `long
long*` and a struct pointer captured together), which is why the shared
`is_ptr4_kind` predicate is the right one and a literal triple would not be.

### 2. `<` is `>` with the operands exchanged — and that composes with `lhs_first`

Two independent exchanges. `lhs_first` is c2's call order (WCB's `alloc_rank`,
`this` numbered last); the relation is the spine's own operand roles. Applying
one and not the other emits `<` for `>` in exactly the cells where both are
non-trivial and nowhere else, which is why the sweep takes every ordered receiver
pair in both source orders crossed with both relations. Dropping the relation's
exchange is **118 mismatches** in `scripts/sweep.d/98-cmp-order.py`.

### 3. The signed order spine takes TWO label slots ahead of its own `$M` triple

`docs/CMP_PRODUCES_A_VALUE.md` reading 3 predicted a surcharge for the *literal*
comparison; the register-register form has its own table, measured seed-free and
in-TU with the anchor control holding on every row (`scripts/gt_cmp_rr.py
--stride`):

```text
                                      /Gy      packed
  two calls, arithmetic tail        5    0     4    0
  two calls, cmp `==`               5    0     4    0
  two calls, cmp UNSIGNED, any rel  5    0     4    0
  two calls, cmp SIGNED  `>` `<`    7    2     6    2
                                  stride lead stride lead
```

The literal form's "`k == 0` escapes to 1" clause has no analogue — a register
operand is not a zero literal — so the signed order relations pay it
unconditionally. `coff::plan_labels` gained the **per-function leading count**
`docs/CMP_PRODUCES_A_VALUE.md` said it lacked, and `coff::Function` the
`label_lead` field that feeds it, defaulting to 0 for every other class.

**The size and the placement are two claims.** Dropping the surcharge entirely
and moving the same two slots to *after* the triple both cost **121** mismatches,
so a grid that graded only the total would have said nothing about where the
slots go. Both are pinned, in the sweep and in a `plan_labels` unit test.

### 4. The `bool` result is not a different spine — for the two relations admitted

Reading 1 of that document warns that a `bool` result costs two extra words for
signed `>=`/`<=` against a non-zero literal. Over two call results the same two
relations diverge — `>=` grows `adde r11,…` + `clrlwi r3,r11,24` — and **`>`,
`<`, `==` and `!=` are byte-identical in `int`, `bool` and `unsigned` in all four
modes** (`scripts/gt_cmp_rr.py`, 20 cells per mode, printed as a verdict per
relation). The two cells that would have walked into the trap are exactly the two
refused by name, and that is not a coincidence: it is why they are refused.

## Estimate vs outcome

`work/WCR/ESTIMATE.md`, written before any scan, with the pre-filter named.

| | estimate | outcome | bias |
|---|---|---|---|
| **E1** functions reachable after the widening | **760**, range 700–765 | **67** | **11.3× HIGH**, range missed |
| **E2** realized census delta | **+755**, range 640–765 | **+67** | **11.3× HIGH**, range missed |

**The estimate applied the rule correctly and the rule was not the problem.** It
took the ceiling neat, exactly as ROADMAP §6n prescribes when the blocker is a
class whose emitter already exists, and refused to discount for the four
independent things between ceiling and emitter — all four of which turned out to
be real work and none of which was the reason it missed. The Class B emitter did
exist; the spine, the surcharge, the signedness and the composition were all
built and are all graded green.

**It missed because the ceiling was not a population of what it was named
after.** `mcall-cmp-rel` is keyed on the RELATION. Its 760 members were 91 %
`float`. The estimate's pre-filter list names the operator grant, `-whole`, the
frame class, the recognizer's own parse and WCB's `==` arm — five filters, none
of which is the operand type, and the census key could not have told anyone
either.

So the entry for the ranking table is the frame-class rule with one word changed:

> **A refusal key is an upper bound on the FEATURE IT IS NAMED AFTER and on
> nothing else.** `mcall-cmp-rel` says "not `==`" and says nothing about what is
> being compared. Cross a refusal row with the **operand type** before quoting
> it, the same way `docs/CMP_PRODUCES_A_VALUE.md` says to cross a `-whole` row
> with the frame class — and for the same reason, which is that the key is
> computed at one byte and the population lives at another. The instrument is
> free: `blk_type` puts the three type bytes in the key, and re-keying this one
> row turned "760 integer comparisons" into "693 float, 66 pointer, 1 integer"
> in one 1.9-second scan.

Measured this way so far: `-whole` × frame class **89.8 %** removed (realized 0);
this refusal key × operand type **91.2 %** removed (realized 67 of 760).

### Which of §6n's five categories this row was

**(3), real but far smaller than its size** — with the twist that the shrinkage
is not a discount rate, it is a *different construct* inside the row. The 693 are
not a harder version of the same thing; they are a floating-point conditional
branch. Category (5), "mis-described", is the closer match for how it *read*: the
row was scheduled as "the relational comparison of two call results" and 91 % of
it does not compare integers at all.

## What this refuted

* **`docs/CMP_PRODUCES_A_VALUE.md`'s "found and not taken" #1 is refuted as a
  ranking.** It put Class B at "the only thing between this port and 6,760
  complete bodies in this row", and named the relational spines as the residue
  worth sizing "with the register-register spines counted". They were counted;
  they are worth 67.
* **Its reading 1's trap is real and lands one relation over from where the
  brief for this rung placed it.** The warning was that `a->m() > b->m()` returns
  `bool` and so "walks straight into" the two-word divergence. It does not:
  `>` and `<` are `bool`-invariant over two call results, and the divergence is
  `>=`/`<=`. The trap is real, the relations were wrong, and only the 20-cell
  register-register grid separates them.
* **Reading 3's stride table does not transfer to the register-register form
  unchanged.** Its "signed `<`/`>=` with `k == 0` costs 1" escape has no
  analogue: with no literal there is no zero, so every signed order relation pays
  the surcharge. Predicted (`work/WCR/ESTIMATE.md` prediction 2) and confirmed.
* **Prediction 3 held**: `>` and `<` are one spine with the operands exchanged.
* **Prediction 1 held**, and it was flagged as most likely wrong: the
  register-register form is a different word count from the literal one *and*
  the `bool` divergence does not apply to the two relations this rung takes.

## Found and not taken

Ranked, and the axis applied first is the **operand type**, because that is what
this rung learned.

1. **The `float` two-call comparator — 693, and it is a CONTROL-FLOW rung, not a
   comparison one.** `fcmpu` + `bt` is a branch; `stfd f31`/`lfd f31` is an FPR
   in the callee-saved frame. It needs whatever admits basic blocks
   (`body-cflow-label`, 48,102) plus an FP frame model, and it should be ranked
   with those rather than with the comparison family. Captured, in
   `wcr_cmp_order_neg.cpp`'s `n_fp_*` comment.
2. **`expr-call-in-expr-recv-load-then-cmp-lt-and-type-int1-whole2` — 68, all
   `calls-1`.** `bool f(const S* p, int k){ return p->m() < k; }`:
   `docs/CMP_PRODUCES_A_VALUE.md`'s 66-shape, one rung later and now the largest
   *integer* comparison row left. Class B with one saved GPR, and the difference
   is formed against a **formal** rather than a second call's result — so
   `call_seq_parts` needs a tail whose second operand is a parameter register,
   and the spines are the ones this rung just built. Its `==` and `!=` siblings
   are 1 each. **Read the operand types before ranking it**: it is `type-int1`,
   so the *result* is `bool`, and nothing in the key says what is compared.
3. **`expr-call-in-expr-recv-intrinsic-vbase-upcast-then-cmp-ne-and-type-int1-whole2`
   — 699, all `calls-1`, and it is ONE source function** inlined into 699 TUs
   (`ObjDirPtr<T>::IsDirPtr`). A **receiver** widening, not a comparison one, and
   unchanged by this rung. Still the cheapest large thing in the family.
4. **`>=` and `<=` — 0 workload witnesses, and a genuinely different job.** They
   are the only cells in the whole register-register grid where the result type
   moves the bytes, and the `/O1` `<=` form also **reschedules** (`subc` hoisted
   ahead of the second `srwi`). Cheap to build from `gt_cmp_rr.py`'s table and
   worth exactly 0 today. Do not build them for census.
5. **The riskiest thing left unmeasured.** **The SIGNED spine has exactly ONE
   workload witness.** Measured, not estimated: refusing `signed` and rescanning
   moves the census by 1, so 66 of the 67 realized functions are the *unsigned*
   three-word spine — which means the five-word spine, the `/O1` temp collapse
   and **the entire label surcharge** are graded by 356 generated cases, one
   fixture and four mode lanes, and by nothing else on the workload. That is the
   asymmetry WCB's own §5 records (its whole realized population had wide tokens
   and its whole graded corpus had narrow ones), in the other direction: here the
   graded corpus is rich and the realized population is one function. The
   surcharge is the part that would be silent — it is six wrong bytes in an obj
   that still links, and only a *following* function in the same TU sees it.
