## 2. What the brief said, and what the IL said

The brief, board **#979** and `DIFF_STRUCTURE.md` §3.2 all said the same thing:

> the port's `seq` recognizer emits **two of three calls and drops the third** …
> a wrong emit today, not a refusal … the ONLY cluster where the port emits
> *less* than c2.

**All of it is wrong, and the source settles it in four lines.**
`src/system/obj/Data.h`:

```cpp
template <class T> T *DataArray::Obj(int i) const { return Node(i).Obj<T>(this); }
template <class T> T *DataNode::Obj(const DataArray *source) const {
    return dynamic_cast<T *>(GetObj(source));
}
```

**There are two calls in `DataArray::Obj<T>`, not three**, and the port reads
both correctly. Its parse — `c2rs census` plus a segment dump, on
`src/lazer/game/Game.cpp`'s `??$Obj@VHamUser@@@DataArray@@QBAPAVHamUser@@H@Z`:

```text
verdict = call-sequence-value
call_seq: 2 calls, tail=CallValue{add_k:0}, saved=[0], guard=false, early=0
  call[0] ?Node@DataArray@@QBAAAVDataNode@@H@Z            arg_sources=[0,1]
  call[1] ??$Obj@VHamUser@@@DataNode@@QBAPAVHamUser@@PBVDataArray@@@Z
                                                          link_args=[Formal(0)]
```

`link_args` is the tell: this is not the statement-sequence production at all,
it is **WCH/WCL**, the chained member call (`p->a()->b(k)`,
`crates/c2-il/src/func/body/shapes/mcall_chain.rs`). The port's two calls are
exactly `Node(i)` and `.Obj<T>(this)`.

### 2.1 H-SKIP is refuted, and it could not have been true

`PREREG.md` §1.2 registered that the seq loop's return-plumbing probe succeeds
where the third element begins and the element is dropped silently. **It does
not, and no production in this parser can**: `eat_fn_tail` returns `Ok` only at
`p == seg.len()` (`crates/c2-il/src/func/body/mod.rs`), so a body with unread
bytes refuses. The lane's §4 deliverable — *make a silent skip structurally
impossible* — was **already satisfied before the lane started**, which is worth
recording as a place the codebase was ahead of its brief.

**Rivals R1 (a call-count cap) and R3 (the value-call arm) are refuted with it**;
R2 and R4 never fired. §1.2's registered hypothesis is a **LOSS** and §7 scores
it as one.

## 3. What c2 actually emits, from its own relocation table

`c2rs compile … --flags-file work/dc3-workload/flags.txt`, dumped with
`scripts/gt_dump.py`. The caller:

```text
-- .text #592 (80 B) ??$Obj@VHamUser@@@DataArray@@QBAPAVHamUser@@H@Z
   0014  4bffffed  bl .-20    ; REL24 -> ?Node@DataArray@@QBAAAVDataNode@@H@Z
   001c  4bffffe5  bl .-28    ; REL24 -> ?GetObj@DataNode@@QBAPAVObject@Hmx@@PBVDataArray@@@Z
   0020  3d600000  lis 11,0   ; REFHI -> ??_R0?AVObject@Hmx@@@8   ; PAIR
   0024  3d400000  lis 10,0   ; REFHI -> ??_R0?AVHamUser@@@8      ; PAIR
   0028  38ab0000  addi 5,11,0; REFLO -> ??_R0?AVObject@Hmx@@@8   ; PAIR
   002c  38ca0000  addi 6,10,0; REFLO -> ??_R0?AVHamUser@@@8      ; PAIR
   0030  38800000  li 4,0
   0034  38e00000  li 7,0
   0038  4bffffc9  bl .-56    ; REL24 -> __RTDynamicCast
```

**c2's second `bl` relocates to `?GetObj@DataNode@@`, not to the callee the port
names.** And the callee the port names is sitting in the same obj, as the
missing seven words verbatim:

```text
-- .text #368 (60 B) ??$Obj@VHamUser@@@DataNode@@QBAPAVHamUser@@PBVDataArray@@@Z
   000c  4bfffff5  bl .-12    ; REL24 -> ?GetObj@DataNode@@…
   0010..0024     lis 11 / lis 10 / addi 5 / addi 6 / li 4,0 / li 7,0
   0028  4bffffd9  bl .-40    ; REL24 -> __RTDynamicCast
```

c2 **inlined `DataNode::Obj<T>`** into its caller — its interior, minus its own
three-word prologue and four-word epilogue, is exactly the eight words c2
substitutes for the port's one `bl`. **This is mechanism I**, `w-seq`'s family
(a), and not a new mechanism at all.

The port refuses that callee, and the key is the one `w-seq` §5 counted:

```text
idx=8536 ??$Obj@VHamUser@@@DataNode@@…  verdict=expr-intrinsic-dynamic-cast
```

**`w-seq`'s `expr-intrinsic-dynamic-cast | 140` and `w-bytes`' 140-body cluster
are the SAME population** — registered in `PREREG.md` §1.1 as a prediction with
`w-seq` §7.1's coincidence warning attached, and it holds.

### 3.1 Why it looked like a deletion

Under `/Gy` every function starts at offset 0 of its own COMDAT, and c2 writes a
call out of it with the placeholder displacement **`-(offset of the branch
word)`** — pointing at offset 0 — for **every callee alike**. So

```text
port  0x1c  4bffffe5  bl → ??$Obj@V…@@DataNode@@…
c2    0x1c  4bffffe5  bl → ?GetObj@DataNode@@…
```

are the same four bytes. `fndiff`'s alignment is an LCS over 4-byte words under
**byte** equality, so it scored word 7 `=` and reported **7 deletions** where
the truth is **1 substitution + 7 insertions**. Board **#989**: a cluster's
*edit shape* is only as fine as the equality it is built on.

### 3.2 §3.2's `.rdata` string pair is RTTI

`DIFF_STRUCTURE.md` §3.2 read the two relocated address halves as "a `.rdata`
string pair, by shape". They are `??_R0?AVObject@Hmx@@@8` and
`??_R0?AVHamUser@@@8` — the **RTTI type descriptors** of
`__RTDynamicCast(pv, VfDelta, SrcType, TargetType, isReference)`, with `r4` and
`r7` its `VfDelta` and `isReference`, both 0, ABI slot for slot.

**The 11 relocations decompose as `3 REL24 + 2 × (REFHI + PAIR) + 2 × (REFLO +
PAIR)`**, which `PREREG.md` §2 registered as arithmetic *before* the obj was
read. Board **#987**.

**Two readings, and the second costs something.**

1. **All 3,195 differing bodies call the wrong things.** `DIFF_STRUCTURE.md` §3
   derived "one mechanism" from opcodes; this derives it from the symbol table,
   with no alignment in the loop. Independent, and they agree.
2. **861 bodies FBM CREDITS relocate against a different symbol.** Hand-verified
   from an obj this lane compiled (`src/lazer/game/BustAMovePanel.cpp`):

   ```text
   -- .text #777 (4 B) ??1?$list@HV?$StlNodeAlloc@H@stlpmtx_std@@@stlpmtx_std@@QAA@XZ
      0000  48000000  b .+0  ; REL24 -> ?clear@?$_List_base@H…@QAAXXZ      <- c2
   -- .text #757 (4 B) ??1?$_List_base@HV?$StlNodeAlloc@H@stlpmtx_std@@@stlpmtx_std@@QAA@XZ
      0000  48000000  b .+0  ; REL24 -> ?clear@?$_List_base@H…@QAAXXZ
   ```

   The port emits `48000000` for `??1?$list@H…` relocating to
   **`??1?$_List_base@H…`**. c2 inlined `~_List_base()`, itself a one-word tail
   call to `clear`. Same four bytes; `fnbyte-exact` counts it.

   This is `w-fix` **#954**'s shape one mechanism over — *mid-chain emits a bare
   `blr` at every level* becomes *mid-chain emits a bare `b` at every level* —
   and the port stops one level short.

### 5.1 The 861 are SEVEN families, not one — and one of them is not STL

Witness keys are minted for the `exact` bucket only and capped at **4 per TU**,
so **694 of the 861** are named. Grouped by *(the callee the port names → the
callee c2 names)*, from `work/w-drop3/rows-rows.jsonl`:

| n | port calls | c2 calls |
|---:|---|---|
| 305 | `??1?$_List_base@…` | `?clear@?$_List_base@…` |
| 89 | `??1?$list@…` | `?clear@?$_List_base@…` |
| 72 | `??1logic_error@…` | `??1exception@…` |
| 70 | `??1?$_Rb_tree@…` | `?clear@?$_Rb_tree@…` |
| 67 | `??1__Named_exception@…` | `??1exception@…` |
| **50** | **`?SetObj@…`** | **`?SetObjConcrete@…`** | 
| 23 | `??1?$map@…` | `?clear@?$_Rb_tree@…` |
| 14 + 2 + 1 | `?Node@…` · `?GetDXQuery@…` · `?Keys@…` | a different instantiation of the same name |

**Six of the seven are a destructor chain**: c2 expanded the base destructor —
itself a one-word tail call — and the port stops at the base destructor. **The
seventh is ordinary game code**, `?SetObj@…` → `?SetObjConcrete@…`, 50 bodies,
no template and no STL. So this is **not** #925's one-template caution repeating:
the shape is general and the port's exposure to it is not a property of STLport.

**Every one of the 694 is a SAME-COUNT disagreement** — 678 at `1 → 1` and 16 at
`2 → 2`, never a differing number of calls, which is what a byte-identical pair
of bodies should give: the same branch words at the same offsets, with only the
symbol behind each one moved.

**It is not, however, *forced*, and the totals do not pin it.** A byte-identical
body could in principle carry a `REL24` on one side and not the other at the
same word — mechanism E emits `blr` where the port's shape names a callee, and
a `Plain` body could contain the bit pattern of a branch. And the arithmetic is
consistent for *any* split: if `x` of the 861 were count-type, `differs` would
absorb `x` on each side and still sum to 3,195. So **"all 861 are name-type" is
a statement about the 694 witnessed and not about the 861**, and the missing 167
are the per-TU cap, not a residue anyone measured.

**`mismatch` is still 0 and `IlBundle::functions()` is untouched.** Every one of
the 861 sits in a TU the parser refuses, so none has reached an obj. What is
wrong is the *credit*, exactly as board #878 says of the 3,195, and **the hazard
is the next `functions()` widening**, now 861 functions larger than it looked.

**Not repaired by moving them out of `exact`.** That is an instrument change
scored on a number this lane also reports, and `w-fnbyte` §8.1's rule (a lane
does not ship the change it measured) applies. The count is published beside the
bucket instead. Board **#986**.

### 5.1 This is the FOURTH retraction of one sentence, and the pattern is the point

`STATUS.md`'s *"the port is byte-exact on every shape a standing instrument
grades"* has now been retracted by an instrument widening four times — #322
(`partial` 9,375 → 0, of which 4,711 wrong), trap 0's `.in` totality identity

## 6. Why NEITHER landing was available

`PREREG.md` §2 registered a fork: **A — FIX** (0.30) or **B — HONEST REFUSAL**
(0.70). **Both are dead, and B's death is the finding.** Board **#988**.

**A is dead** for the reason the prereg priced at 0.70 against it, and worse.
Emitting the call needs (i) an inline **decision procedure** — *whether* c2
expands `DataNode::Obj<T>` — which is `INLINE_PREDICATE.md`'s open residual at
2.84 % NOT MODELLED, and 2.84 % of a guess is a wrong emit (`w-empty` §2.2
declined a match on exactly this ground); and (ii) the RTTI type descriptors,
the `REFHI/PAIR/REFLO/PAIR` quads and an external `__RTDynamicCast` — the
`.rdata$r` machinery `w-rdata` priced at **seven independent refusals** and
`w-rtti` re-derived as **all seven still unpaid** at a later master.

**B is dead because the 140 are not separable.** The escape hatch presumes the
port emits a *distinguishable wrong subset*; once §2 lands, the 140 are 140 of
3,195 bodies of one mechanism, and the only property that picks them out is the
template name, which `PREREG.md` §5.1 forbids. The one grammar-grounded
candidate — *refuse a call naming a same-bundle callee the port cannot parse* —
is `w-seq` family 1's population (**1,403** differs) and is **not disjoint from
the `fnbyte-exact` bodies**: a `tail` or `seq` body whose same-TU callee c2 did
*not* inline is exact today and would be refused by that rule. `PREREG.md` §2.1
registered `exact` shrinking as an unconditional stop.

**So the landing is neither: the framing was refuted, and what ships is the
instrument that would have prevented it.** Stated plainly because the brief
asked for an emitter change and did not get one.

### 6.1 What the next lane would need, and it is one number

Refusing mechanism I wholesale is a **real option and a different rung**. It
needs the count this lane did not build: **how many `fnbyte-exact` bodies name a
same-bundle callee the port refuses.** If that number is 0 the rule is free and
converts ~1,540 differs to honest refusals; if it is positive the rule is
forbidden as written and needs a discriminator. `fnbyte-calltarget-*` is the
natural place to add it — the walk already has the port's call list, the census
row and `TuEmptyCallees` in scope.

## 10. Found and not taken

1. **The count that decides §6.1's rung** — `fnbyte-exact` bodies naming a
   same-bundle refused callee. One `if` in a walk that already has every input.
   Not taken because a lane that builds a number and then acts on it in the same
   commit has no before.
2. **Relocation-aware alignment in `fndiff`.** It would dissolve cluster 4's key
   correctly (1 substitution + 7 insertions) and reclassify the 861 out of
   `exact`. **Not taken**: it moves every count in `DIFF_STRUCTURE.md` §2's
   published table *and* moves `fnbyte-exact`, so it is a lane with its own
   before/after. Board **#989**.
3. **The `data_refs` side is unmeasured.** This lane compares `REL24` only. The
   port also emits `REFHI`/`REFLO` pairs for named data symbols
   (`comdat_function_body`'s `data_refs`), and whether *those* point where c2's
   point is the same question one field over. Zero rows today; the reader is
   already general enough that adding it is a filter change.

   > The `PAIR` records are the reason it is not a *one-line* filter change: a
   > `PAIR`'s `sym` field is a displacement, so a `REFHI`/`REFLO` walk has to
   > pair records positionally, and getting that wrong is a reader that names
   > the wrong global. The exclusion is unit-tested here precisely so the next
   > lane starts from a refusal rather than from a plausible-looking answer.
4. **The lane's own tooling shipped with trap 5 in it.** `work/w-drop3/scan.sh`
   derived the main repo by counting `..` one level short; a worktree is three
