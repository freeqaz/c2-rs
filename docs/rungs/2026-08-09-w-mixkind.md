### 3.2.1 It dies on the DIRECTION, and the prereg named the cell

```text
  M5  CHAINBIND   T& a = y->blk.q0;  T& c = a;   c.w0 = (int)&a;   const
  M9  REVERSE     T& a = y->blk.q0;  T& c = a;   a.w0 = (int)&c;   const
```

The same two declarations with the two roles exchanged, and **c2 answers `const`
on both**. `H-CHAIN` walks only the *store root's* chain; in `M9` the store root
is the shallower bind `a`, whose chain is `{a}` with a non-bind base, so `c` is
not on it and the rule grants the bonus.

So the relation is **symmetric in the bind lineage** while remaining asymmetric
in the two tokens — `MIRROR` and `DEEP-MIRROR` are `const` because the store root
is not a bind at all, which is a *different* clause. This is the **third** key
this seam has killed on an asymmetry (`H-2X` on `MIRROR`, `H-2Z` on `CHAINBIND`,
`H-CHAIN` on `REVERSE`) and **the first where the answer came back more symmetric
than the rule**.

## 4. THE CARRIER IS ONE BIND LINK SHORT — board #1266, and #1267

This is worth more than the count, and it is a correction to **#1244's scope**
rather than to its content.

`alloc::Root::base` carries what a root is itself rooted at and stops. So every
relation statable over `(tok, is_bind, base, offsets)` of the two sides is a
**one-link** relation, and the fact the bytes obey is the **transitive** bind
lineage. `M6` (`DEEP-GP`) prices the difference:

```text
  T& a = y->blk.q0;  T& c = a;  T& f = c;   f.w0 = (int)&a;      c2: const

  store root 0x160a  base 0x150a  -> 0x140a          TWO links up
  value  root 0x140a

  one-link reading   "unrelated"  =>  prod     ** WRONG **
  transitive walk    "ancestor"   =>  const
```

`M5` (`CHAINBIND`) is the same shape at **one** link and the carrier answers it
correctly, which is what makes this a **reach limit and not a wrong predicate**.
Over the twelve decoded families the one-link reading is wrong on **`M6` and only
`M6`** (`work/w-mixkind/lineage.out`).

**PREREG P4 landed and it was not free.** `M6`, `M7`, `M10` and `M12` committed
in advance to the claim that a chained reference produces a **depth-3 bind chain
in the `.ex`** rather than being flattened, and registered that a flat chain
would make those families out of regime and **not evidence for anything**.
Decoded through `w-ilx`'s `exdec.py`, it survives — `0x160a -> 0x150a -> 0x140a
-> 0x0f0a [80, 0]`, three bind heads each based on the one above. **Board
#1267**, and the first time any lane has compiled a bind chain deeper than one
link. It is what makes #1266 a measurement rather than a guess: the `.ex` plainly
contains the whole lineage and `exdec.py` walks it in nine lines, so the
shortfall is in the **carrier**, not in the IL.

### 4.1 The transitive walk is deliberately NOT added

`alloc::Root` is constructed in `codegen/leaf/store.rs`, a concurrent lane's
file, and PREREG F-2 forbids this lane shipping a decision. What ships instead is
**`ProducerRoots::bind_linked`** — the one link the carrier *actually* holds,
with a doc that says where it is wrong and a test that pins it. The shortfall as
an executable fact rather than a paragraph.

### 4.2 A defect in this lane's own diagnostic, recorded rather than fixed silently

The first version of `lineage.py`'s one-level column omitted the *"and that base
is ITSELF a bind head"* conjunct that `H-DERIV`, `H-STEP` and `H-2Z` all carry.
It therefore read `SELF-2B` — whose bind hangs off the **formal's** path — as
related, and came back wrong on `M3` as well as `M6`, **overstating the one-level
reading's failure by a whole family**. Walking a bind link into a formal is not a
bind link. The correction is in the file, and
`a_link_into_a_formal_is_not_a_bind_link` pins it in `crates/`.

The same shape bit the *table* test: `bind_linked` must be composed with
`store_root_is_distinct_bind`, because **a root is not linked to itself**.
Written without that, the column is wrong on `LOAD` and `DEEP-SELF` too — which
would blame the **reach** for a **missing clause**. Both counts are asserted.
