### 0.1 What I expect the instrument to actually count (P1–P3)

| # | p | prediction |
|---|---|---|
| **P1** | 0.90 | The published *"blocked emitted functions"* distance is `emit-emitted − emit-in-class`, and `emit-in-class` is only ever incremented for an emitted symbol that binds to **exactly one** census row. So the distance **silently includes the unbound residue** — `emit-residue-generated`, `emit-residue-unbound`, `emit-name-two-rows` — which are not blocked functions at all. The label is wrong in the same way three published distances were wrong this week. |
| **P2** | 0.65 | Consequently, in the `≤1` band, **≥ 8 of the 21 TUs** will have an **empty** `emit_blockers` map: their entire distance is residue, and there is no blocking function to name. |
| **P3** | 0.80 | `emit-in-class` is a **census** verdict (`f.verdict.in_class()`), not a byte verdict, so it inherits the fail-open w-inlfence measured on 845/871 TUs. A TU at emitted-distance 0 that does not `match` is therefore expected to exist. |

### 0.4 The question that matters — deliverable 4 (P9–P11)

A **mutually exclusive distribution**, per #2095's instruction, so that one
branch can hit without the lane claiming a win:

| # | p | prediction |
|---|---|---|
| **P9** | **0.35** | There **is** a cluster whose removal (granting that one key, everything else held) leaves **> 1 TU** at blocked-emitted distance 0. |
| **P10** | **0.45** | There is **no** such cluster: the best single key converts exactly **1** TU, and the `≤10` band is 82 near-independent one-TU problems. |
| **P11** | **0.20** | The best single key converts **0** TUs — every band TU is blocked by ≥ 2 distinct keys, so the "cluster" framing has no purchase at all and the band's TUs need a conjunction. |

Register also: **P12** (p = 0.50) — if a >1-TU cluster exists, it is a **reader
admission** (a decode refusal the parser can be taught) rather than a **new
lowering**, per §10.26.4's distinction.

### 0.5 The byte cross-check (P13–P14)

| # | p | prediction |
|---|---|---|
| **P13** | 0.85 | The blocked functions in every top cluster are overwhelmingly **`fnbyte-refused`** (≥ 90 %) — the port refuses what the census blocks — so no cluster is *worth less* for being a wrong emit. |
| **P14** | 0.30 | At least one band TU carries a non-zero **`fnbyte-differs`**, i.e. the port would emit a wrong body for a function the census calls in-class, on a TU that is otherwise ≤ 1 away. If so, that TU is **not** the cheap conversion its distance advertises. |

### 0.6 Pre-armed instrument

The failure mode this lane is most likely to commit is **naming a cluster off a
histogram**. Pre-armed against it: *no cluster is reported as a conversion
candidate unless the **counterfactual** is computed per TU — the set of distinct
blocking keys on that TU's blocked emitted functions — and the TU has **exactly
one** distinct key.* A histogram row's size is never its yield (#150, §10.24).
