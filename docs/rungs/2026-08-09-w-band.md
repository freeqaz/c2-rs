## 1. What "distance" actually counts, read from the source

### 1.1 The two measures, and where they live

`crates/c2-harness/src/gap/report.rs`:

* `near_match_tus(max)` — **blocked BODIES**. Filters
  `class != CaptureFail && fn_total > 0`, keeps `fn_total - fn_in_class <= max`.
  `fn_total` is the `.ex` segment count; `fn_in_class` is how many of those the
  IL parser accepts.
* `near_match_tus_emitted(max)` — **blocked EMITTED functions**. Filters
  `class != CaptureFail && emit-emitted > 0`, keeps
  `emit-emitted.saturating_sub(emit-in-class) <= max`.

`emit-emitted` is `ref_obj.text_comdat_functions().len()` — c2's own `.text`
COMDAT leaders. So far so good. **`emit-in-class` is where the label goes
wrong.** In `gap/scan.rs` step 1e it is incremented in exactly one arm:

```rust
for name in &emitted {
    match claim.get(name.as_str()).map(Vec::as_slice) {
        Some([row]) => {                      // EXACTLY ONE census row claims it
            *res.emit.entry("emit-bound".into()).or_insert(0) += 1;
            let f = &census[*row].0;
            if f.verdict.in_class() { … "emit-in-class" … }
            else                    { … res.emit_blockers[f.verdict.key()] … }
        }
        Some(_)                          => … "emit-name-two-rows" …
        None if is_compiler_generated(n) => … "emit-residue-generated" …
        None                             => … "emit-residue-unbound" …
    }
}
```

### 1.2 So the published "distance" is a SUM OF FOUR THINGS, three of which are not blocked functions

    emit-emitted − emit-in-class
      = blocked-bound            ← the only term that is a blocked function
      + emit-name-two-rows       ← two census rows claim one symbol
      + emit-residue-generated   ← c2 synthesized it; no IL body exists
      + emit-residue-unbound     ← the binding lost the row

The identity is **asserted per TU** by this lane's script and holds on all 865
TUs with a readable obj (`[2] … breaks 0 of 865`). **`docs/STATUS.md`'s row is
labelled "blocked emitted functions" and three of its four terms are
bookkeeping.** Concretely: `src/system/os/NetworkSocket.cpp` is published at
distance 2 and has **zero** blocked functions — both units are
`emit-residue-unbound`, and no widening of any kind can move them, because there
is no census row to admit.

This is the fourth published distance this week whose name is not what it
counts. **PREREG P1 (p = 0.90) HITS.**

### 1.3 The scratch instrument

Nothing in the tree joins the per-name census verdict to the per-name byte
verdict — the scan aggregates both per TU. 46 lines added to
`crates/c2-harness/src/gap/fnbytes.rs`, inside the emitted-leader walk
(`measure()`, immediately after `let v = graded.verdict;`), writing one TSV row
per emitted `.text` COMDAT leader when `C2RS_BAND_DUMP` is set. **Reverted; the
tree is byte-identical to master's `crates/`.** In full:

```rust

            use std::io::Write;
            let (ck, cf, coff, cmpl, cn, sl) = match row {

            let line = format!(
                "{}\t{}\t{}\t{}\t{}\t{}\t{}\t{}\t{}\t{}\n",
                tu_label, name, v.bare(),

            if let Ok(mut fh) = std::fs::OpenOptions::new()
                .create(true).append(true).open(&p) {

```

so nothing was lost to the concurrent appends. The reader is
`work/w-band/bands.py` (uncommittable: `/work` is gitignored); its two
assertions are the accounting identity above and that row count.

## 4. THE DELIVERABLE — is there a cluster that converts more than one TU?

### 4.1 The naive counterfactual says yes: `expr-cmp-eq`, 2 TUs

A TU converts under a single key K iff every blocked emitted function on it
carries K **and** its unbound/generated residue is 0 (no key grant binds a
symbol no row claims). Of the 69 live band TUs:

* **11** are single-key with zero residue — the only ones a single grant can reach
* **56** carry ≥ 2 distinct blocking keys
* **1** carries residue beside its blocked functions (`NetworkSocket.cpp`)
* **1** is at distance 0 already and still not a match (`vec.cpp`, which is
  `-BCD-` — it fails **factor A**: 811 `.ex` segments against 2 emitted COMDATs)

Exactly one key owns more than one of the 11:

| key | TUs |
|---|---|
| **`expr-cmp-eq`** | **`src/system/synth_xbox/IPP_basicmath_xbox.cpp`, `src/xdk/nuispeech/mmio.cpp`** |
| every other (9 keys) | 1 each |

Both are `ABC--`, so both are **frontier** TUs — factor A, B and C already hold
and codegen is the whole remaining distance. On the face of it this is the
multi-TU rung the commission was looking for.

### 4.3 The answer, plainly

> **NO. There is no cluster in the `≤10` band whose removal converts more than
> one TU.** The single multi-TU candidate — `expr-cmp-eq` over
> `IPP_basicmath_xbox.cpp` and `mmio.cpp` — is not removable by a reader
> widening: all seven of its bodies sit behind control flow the port has no IR
> for, and all seven read `complete-none`, so the key is the first thing that
> stopped the decode and promises nothing about what is behind it. Once the
> block-IR gate is applied, **the best key converts exactly one TU, and the five
> surviving candidates carry five different keys.**

**PREREG P10 (p = 0.45) HITS; P9 (0.35) and P11 (0.20) miss.** P9's naive form
would have "hit" and this lane declines to score it as one: the pre-armed

and it converts zero for the same reason. **Two independent populations, one
answer.**
