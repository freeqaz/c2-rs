## 3. THE COLUMN EXISTS — AND THE PUBLISHED ONE WAS 100 % READER

`grade_one` (`fnbytes.rs`) has had the split since board #322:

```rust
let Ok(func) = gate else {
    return g(FnByte::Refused, "parse-refused", Some(Decline::Selector));  // ← BEFORE
};
match complete_comdat(func, census.opt_word, tu) { … }
```

`gate` is `Result<IlFunction, &'static str>` and `census_functions` sets it `Ok`
in **exactly** the arm that yields `FnVerdict::InClass`, so `gate.is_ok()` is
`verdict.in_class()` — the reader's own verdict. The `Err` arm therefore means
*the IL parser refused*, and `select_function` is **never called**: there is no
`IlFunction` to call it with. Filing that under `Decline::Selector` published
every reader refusal under a codegen name.

Measured at base, before any edit:

| key | base |
|---|---:|
| `fnbyte-decline-selector` | **130,575** |
| `fnbyte-shape-parse-refused-refused` | **130,575** |
| `fnbyte-decline-opt-mode` / `-gy-shape` / `-data-ref` | 0 / 0 / 0 |

The first two being **equal to the unit** is the proof: every refusal the
instrument recorded was a parse refusal, and the codegen half was zero and
invisible.

**A third corroboration, and it is a check on the binding rather than an
independent measurement.** `emit_blockers` sums to **130,575** — the same number,
off a different walk (`emit-bound`, in `scan.rs`, against FBM's own COMDAT
iteration in `fnbytes.rs`). The two count the *same set* by construction —
uniquely-bound emitted symbols whose census row is out of class, and out-of-class
is exactly `gate.is_err()` — so agreement is what a correct pair of walks owes,
and disagreement would have meant the two bind different symbols
(`emit-name-two-rows` and friends). What the equality **does** establish is
#1464's claim in arithmetic rather than in prose: **`emit_blockers`' every last
unit is a body the reader refused**, so nothing in it was ever a codegen reading.

### 3.2 WHEN THE STATE IS LEGAL — the invariant, and it is the rung

The brief's tension: if every emitter refusal must have a parser counterpart, can
a "reader accepted, emitter could not lower" state exist at all?

**It can, and the condition is that the refusal is not a function of the IL body
alone.** #139 requires a parser counterpart; a parser counterpart can only exist
for a fact the parser can *see*. Each `Decline` stage now carries its own
classification in its doc comment:

| stage | a function of the body alone? | so |
|---|---|---|
| `OptMode` | yes — `.ex` records the word per function | **0 by construction.** `census_functions`' gate (b) raises `OPT_MODE` before a row can be `InClass` |
| `Selector` | yes | **0 by construction.** Counts exactly `fn_gate_refusals`' population by the same procedure (`function_gate` *is* `select_function` plus one `/Gy` arm), so anything here is the census over-claiming |
| `GyShape` | **no** — `/Gy` is an argv flag, absent from the bundle | **legitimately nonzero forever.** No parser clause could express it |
| `DataRef` | **no** — the question is about the composed body's bytes | **legitimately nonzero forever** |

So the answer to the brief's three possibilities is **1**, and its invariant is
the row above. **A number that is zero by construction is not a measurement**, and
the code now says exactly that where a lane would read it: `Selector`'s doc reads
*"it is an ALARM and not a measurement… do not size codegen work off it."*

**Nothing was added to the census.** No `FnVerdict` variant, no resting bucket, no
path by which an emitter refusal could exist without a parser counterpart. That
is #139's exact shape and an over-claim is worse than the gap it fills.

### 4.1 THE VACUITY STATEMENT, PRINTED FROM THE NUMBERS AND IN BOTH DIRECTIONS

`frontier-codegen-measured` is a **lower bound of unknown tightness**, never a
price: the true distance is `wrong + cg-refused` **plus an unknown amount hiding
inside `reader`**. That is `cflow-emitted-modeled`'s "718" shape (#1343/#1344),
and the block says so in its own header rather than in a doc nobody re-reads. It
prints the *opposite* caveat when the price is nonzero, so a later frontier with
real codegen debt does not inherit today's wording.

Symmetrically, **`cg-refused == 0` is not "codegen is done"** — three of its four
stages are zero by construction (§3.2), so it is an alarm that did not fire.
`a_wrong_emit_raises_the_codegen_price_and_never_lowers_it` pins the direction:
widening the reader onto a body the port then gets wrong moves a function out of
`reader` and into `wrong`, so the price goes **up**, and the only way back down is
emitting c2's bytes. `measured == 0` is distinguished from the refusing case by
`exact`, so it is never on its own evidence of progress.

## 6. THE LABELLING HALF

`docs/BOARD.md`'s Conventions now define **HAND-COUNT** (a person enumerated
refusals, clauses or bytes by reading the obj and the IL; reproducible only by
repeating the reading) against **INSTRUMENT** (a key a scan prints, named so a
successor can re-read it at their own tree). **The tag is on the number, not on
the row**, and **an untagged codegen number in a row written before 2026-08-08 is
a HAND-COUNT by default** — which is what #1464 proved and therefore needs no
per-row edit to be true.

Five rows carry the tag in place: **#1105** (`>= 15` / `>= 21`), **#1418** (776
bytes, `>= 8` clauses), **#770** (eleven-not-eight), **#483** and **#506** (mmio's
17, twice, and the second row now says *two independent hand-counts, not one
hand-count and one instrument*). **#827 already self-labelled** — its headline
reads *"RE-PRICED BY HAND"* — and was left alone.

**This is not distrust of the hand-counts.** They are the only numbers that exist
for the 48, because the instrument structurally cannot see behind a reader
refusal, and a lane that deleted them would be left with `1` and call it the
frontier. The rule is the narrow one: **never quote a hand-count and a scan
reading in the same sum.**

`docs/STATUS.md` gets the trap in the traps section; `docs/FUNCTION_BYTE_MATCH.md`
gets §2.1b, the `Decline` table with the legality column, and the new keys in §9.
