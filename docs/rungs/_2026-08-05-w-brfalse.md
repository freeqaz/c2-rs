## 2. THE HEADLINE — `expr-brfalse` IS A FALL-THROUGH KEY, AND SO IS THE WHOLE SKELETON

### 2.1 Why one sink could not have answered this

`expr-brfalse` is `Block { ctx: "expr", byte: 0x38 }` — the fall-through arm of
`parse_expr`. The production that raises it on these bodies is
`body/mod.rs:1593`, `parse_expr_classed(seg, &mut p, 0x41)`: the **return-value
expression of the straight-line leaf class**, reached only after
`try_parse_empty_dtor_delegation`, `try_parse_store_leaf`, `try_parse_store_run`
and every recognizer above them have declined.

So the key never said *"this body needs a branch instruction"*. It said **"the
dispatcher fell through to the straight-line class and the body turned out to
have control flow in it"** — which is structurally the position `expr-op-0x27`
occupies, and `0x27` is worth six emitted functions and zero TUs.

`C2RS_SINK_BRANCH` therefore has **four nested levels**, each a superset of the
last, so that the question the key's *name* asks and the question the *rung* asks
get separate answers instead of one being read off the other:

| level | consumes |
|---|---|
| `expr` | `38 <tok>` / `39 <tok>` |
| `cflow` | + `29 <tok>` label, `3A <tok>` jump, `4B` stmt-end |
| `stmt` | + `53` / `54 <depth>` scope brackets, + `4F 01 <varint>` line markers |

Measurement-only by construction, on w-cmp's exact pattern: **no `IlOp` is
pushed**, and a walk that reaches the end having consumed one refuses under
`expr-branch-sink-poison`. **Decoding is not accepting.** Every level is run with
`C2RS_SINK_REL=expr` also ON, because four of the five named TUs only acquire
`expr-brfalse` under w-cmp's relational sink; measuring them with REL off would
be measuring a frontier that does not exist.

## 3. WHY THIS KEEPS HAPPENING — the ladder's head is a FIXED POINT of the sink

Board **#420** found one fall-through key. **#421** found that closing a key
*substitutes* a successor. This lane found the thing both are instances of.

| B4 arm | `expr-call-in-expr-other` **tied with `expr-op-0x27`** | 2 | **`expr-op-0x27` is the canonical zero-TU key of board #150 itself**, with seven prior confirmations |

> ### A ranking instrument whose corrected output promotes the project's best-documented worthless key into a tie for first place is not measuring work.

**The mechanism is not subtle, and stating it is the deliverable.** A blocker key
is the census label on the **first** refusal of a walk. The ladder therefore ranks
**where a walk stopped**, and freeing tokens only moves the stopping point later
in the same body. The ladder is *guaranteed* to have a non-empty head for as long
as any body is refused at all — **whether or not the head names any work**. There
is no arrangement of the frontier in which this instrument reports "nothing here
is worth doing", which is precisely the report the last three lanes each had to
produce by hand.

This is **board #250's shape one level further in.** There, a proxy (micro-F1)
was a genuinely better model of the wrong quantity. Here the proxy cannot even be
empty, which is the defect `STATUS.md` trap 3 records for a residue that shrinks
monotonically while covering nothing. **Board #441.**

## 4. THE COUNTEREXAMPLE — and it is against MY OWN intermediate result

My brief warned that a constructed counterexample would refute one of my own
premises, and required a grid before shipping anything that emits bytes. **I
shipped nothing that emits bytes, so no lowering grid was owed and I did not
manufacture one.** What I do owe, and what follows, is the constructed check that
killed my own headline before it was written.

**Arm B3 — `stmt` before the line-marker skip existed, the one arm on the earlier
binary (§0) — produced `expr-op-0x4F` +5,424, by a wide margin the largest
successor, and in 10 of 13 substituting frontier TUs it was the *sole* residual
key.** `IPP_basicmath_xbox` read `{expr-op-0x4F: 4}`.

`4F 12` opens the function tail. The natural reading is therefore spectacular:

> *the walk reached the end of the function, so these bodies contain nothing but
> control flow and already-modelled expression tokens; the port is one body-class
> away from all of them.*

**That reading is false, and it is false by a complete inversion.** `0x4F` is
**also** the line-marker prefix — `4F 01 <varint>` — which
`shapes::control_flow::Scan::line_markers` has always skipped and `parse_expr`
never has. Adding a line-marker arm (level `stmt`, arm B4) is a pure
disambiguation that consumes a token carrying no semantics, and it moves:

```
  expr-op-0x4F           5424 -> 7          (5,417 of 5,424 were LINE MARKERS)
  expr-call-in-expr-*   37273 -> 40785      +3512
  expr-op-0x27          23650 -> 24208      +558
  expr-rel-sink-poison     11 -> 907        +896
```

**Seven** of the 5,424 were the function tail. The bodies do not contain "nothing
but control flow"; they contain **calls**, which is the opposite conclusion and
the one §3.1 reports.

> ### Any census key on a `0x4F` byte raised out of an expression production is ambiguous between a source-line crossing and the end of the function, and **no instrument in the tree distinguishes them**. Board **#442**.

The generalizing lesson is `STATUS.md` trap 5 in a position it has not been
recorded in before: **the reading that made the result look bigger was the wrong
one**, absence of a disambiguation read as presence of a finding, and only a
positive check with a printed count caught it. It would have been a rung headline.

**Prereg R11 registered that at least one of my own premises would be refuted by
my own measurement. It is a HIT twice over** — this, and R5 below.

## 9. Found and not taken

1. **`scripts/configure_existing_worktree.sh` exited 101 with NO error output on
   a healthy worktree — FIXED here, and the first diagnosis was wrong.**
   Board **#443**. I first wrote this up as an off-by-one: `census` gained a
   `profile:` banner, so `| head -n1` no longer selects the verdict line. **That
   is true and it is not what killed the script.** Reproduced:

   ```
   $ c2rs census fixtures/cpp/w5_chain.cpp            # exit 0, 9 lines
   $ c2rs census fixtures/cpp/w5_chain.cpp | head -n1 # exit 101
     thread 'main' panicked at library/std/src/io/stdio.rs:1166:9:
     failed printing to stdout: Broken pipe (os error 32)
   ```

   `head -n1` closes the pipe, `c2rs` keeps writing, and Rust's `println!`
   **panics on `EPIPE`** rather than exiting. With `set -euo pipefail` at the top
   of the script, the command substitution's **101 kills it before the `case`
   ever runs** — and because the pipeline was `2>&1`, the panic message went into
   the closed pipe too, so the script died **silently**. A lane that trusted the
   exit code would spend its morning looking for a missing toolchain.

   Fixed by capturing the whole output and selecting with `grep -m1`, which has
   no pipe to break and does not care which line the verdict lands on — verified
