## 3. The thirty words, and the five things about them

Ground truth: the real obj at the workload's own flags
(`work/w-extdata/ref/vswprnc/dis.txt`, committed) plus the IL body decoded token
by token **before the rung** (`work/w-extdata/VSWPRNC_BODY.md`, committed).

The full annotated listing is `codegen::guard_chain_shared_tail`'s module doc.
The five facts a general lowering gets wrong:

1. **The `||` chain is three branches to ONE block, not a computed boolean.**
   Every guard is `cmplwi cr6,rX,0 ; bt EQ`, all three naming the same target. A
   lowering that materialised the disjunction emits `or` and one branch: the
   right program, and every displacement after word 7 wrong.
2. **c2 SINKS the guard block to the END of the function.** In the IL it is
   `L47`, textually *before* the call; in `.text` it is the second-to-last block.
   IL order is not block order here, so nothing may be derived from it.
3. **The two error arms are TAIL-MERGED on four words**, the range arm reaching
   the shared tail through a `b`. They differ in exactly one `li` immediate.
   Board **#1400**'s finding pointing the other way: there the sharing looked
   like a peephole and deleting it was the defect; here the sharing **is** the
   class, and duplicating it would be twelve bytes longer and still link. A
   `#[test]` asserts the length and the `b`.
4. **Two condition registers.** `r < 0` reads **cr0** and `r != S` reads **cr6**.
   Nothing in the source distinguishes them; a class using one CR for both emits
   the right program with the wrong `bf` operand. A `#[test]` asserts they differ.
5. **The first argument is a FUNCTION'S ADDRESS** — `Type 0x0020`, REFHI/REFLO,
   and the one argument that is a `26` designator where the other six are `B9`
   reads.

**Four free immediate fields** (`k_guard`, `k_range`, `sentinel`, `ret_fail`) and
**zero words chosen by a scheduler or an allocator**, which is exactly what
PREREG **D1** registered and is why the fence has to live in the reader
(board #1706: anything the emitter cannot vary must be refused by the READER).

## 4. What the conversion actually needed

The survey priced five refusals. **Six fired**, and the sixth is the one worth
the page.

### 4.1 The last refusal was a `.gl` clause standing in for the 8-byte COFF name field (#1721)

With the recognizer, the emitter, the symbol type and the WR1 relaxation all
built, `c2rs census` read `1/1 functions in class` and `c2rs gap` still read
`vocab-gap … il function decode failed`. `IlBundle::decode_causes` names it in
one word:

```text
  undname   ["body-out-of-class", "unclaimed-gl-symbol"]
  osfinfo   ["gl-stop-name-not-mangled", "body-out-of-class"]
  vswprnc   ["gl-stop-name-not-mangled"]
```

`gl_defined_names_framed` refuses a bound record name with no `@@`. **Its own doc
gives the ground, and the ground is a different property:**

> *"an undecorated `extern "C"` name is stored **inline in the 8-byte COFF symbol
> name field** rather than in the string table, which every mangled name uses — a
> different encoding path, characterized by one capture."*

That is a statement about the name's **length**. `@@` was a **proxy** for it, and
the two agreed on the entire shipped population because every MSVC-mangled name
is longer than eight bytes. `_vswprintf_s_l` separates them: **fourteen bytes**,
`extern "C"`, and therefore in the string table — the path
`coff::symbol::emit_symbol` has branched on (`if name.len() <= 8`) since it was
written. **The reader was refusing a shape the writer already builds.**

The clause is the length test now, and the refusal it keeps is exactly the
uncharacterized half: a bound record name that **fits inline**. That is a
strictly smaller widening than "admit every unmangled name".

**Blast radius, measured over all 878 TUs rather than argued:** `vocab-gap`
858 → 857 and `mismatch` 0. **Exactly one TU moved.**

#### 4.1.1 The cost of the widening, stated rather than left to be found

`Bindings::unclaimed` is built by filtering `.gl` symbol runs through
`looks_mangled`, so **for a TU with no mangled name anywhere it comes back
EMPTY** — and `IlBundle::functions`' unclaimed-`.gl`-name gate is then *vacuous*
rather than *satisfied* on such a TU. `docs/STATUS.md` trap 0 in its exact shape,
and this lane creates it rather than finding it.

It is **not** widened here, and the reason is a measurement: `vswprnc.cpp`'s own
`.gl` symbol runs are

```text
  z:\…\vswprnc.cpp   _vswprintf_s_l   r   size_t
  _invalid_parameter_noinfo   _woutput_s_l   __C1_11886   _errno   _vswprintf_helper
```

— a source path, a **typedef name**, a one-letter **local**, and the `__C1_11886`
build marker, none of which any record claims and none of which the obj carries.
A filter separating those from a real symbol is a rung of its own. The
compensating control is the 878-TU differential, which grades every obj this
widening lets through, and it reads `mismatch 0`.

### 4.2 The label lead is +1, measured against the oracle (#1724)

With no lead term the port emitted `$M2903`/`$M2902`/`$T2904` where the reference
has `$M2904`/`$M2903`/`$T2905`: **three symbol records wrong by one and nothing
else in the obj different**. Adding `+1` makes the obj byte-exact.

**The measurement is a different one from w-cfgclass's and the difference is
worth stating.** `negate_test.cpp` has two functions of one class, so W-CFG1's
stride was readable **in-TU and seed-free** as the difference between two
triples. `vswprnc.cpp` has exactly one emitted function, so there is no
difference to take: what was compared is the port's whole obj against real
`c2.dll`'s. It is a **one-witness** number, and the fence around it is the
recognizer's — this class admits one block plan, so there is no second shape for
the charge to be wrong about.

### 4.3 A REFHI/REFLO whose target is a FUNCTION carries `Type 0x0020` (#1723)

Measured side by side, in one workload obj each:

```text
  vswprnc  [18] _woutput_s_l              sec=0  type=0x0020   REFHI/REFLO
  undname  [15] ?pairNode_vtable@@3PAXA   sec=0  type=0x0000   REFHI/REFLO
           [17] ?gHeapManager@@3V…@A      sec=0  type=0x0000   REFHI/REFLO
```

Same relocation quad, different symbol record. `coff::DataRef::is_function`
carries it, and it is a **field rather than a name test** because nothing lexical
separates `_errno` from `_nhandle`. On the IL side it is
`IlFunction::fn_addr_sym`, its own field and not a widening of `data_sym`, with
its own accounting clause in `IlBundle::functions` — and deliberately **not** in
`callees()`, whose contract is *"every name the body branches to"* and which
`coff::plan_text_order` consumes as a call edge.

The reader tells the two apart by the **`2C` function-to-pointer decay**, which
emits no instruction. `_neg`'s `n5` is the cell that says the decay is required
rather than tolerated.

### 4.4 WR1's "the `lis` is the body's FIRST word" was silently providing a symbol-table guarantee (#1725, #1720)

`vswprnc`'s `lis` is **word 14**, interleaved into a five-deep argument rotate,
so the position rule refuses a body c2 emits. `data_refs_of` derives the high
half by searching for the **unique** `addis rT,0,0` now, and refuses on two —
which is not hypothetical: `undname` has exactly two.

**The discipline the original clause was written for is kept**: the site is
derived from the bytes, never declared by the class. What was *not* obvious is
that the position rule was doing a second job:

> `coff::writer` emits **callees first, then data symbols** (two loops, two index
> lists). The reference tables are **one list in reverse first-reference order**.
> The two agree exactly when every data reference precedes every call — which a
> first-word `lis` guarantees for free. **Relaxing one without the other is a
> wrong symbol table.**

`crate::check_external_order` re-imposes it explicitly, on both emission paths,
right where the calls and the data refs are both in hand. §5 is the grid that
measured the real rule.

## 5. GRID A — the two-loop symbol order is REFUTED on three of five cells (#1720)

Five one-function TUs, four rivals, per-cell predictions frozen and separation
asserted **before the first `cl.exe`** (`work/w-extdata/GRID_A.md`); result and
scoring in `work/w-extdata/GRID_A_RESULT.md`; sources and dumps committed under
`work/w-extdata/grida/`.

| cell | `.text` reference order | symbol table from index 15 | A1 | A2 |
|---|---|---|:-:|:-:|
| a1 | `gI g1 g0` | `g0 g1 gI` | ✔ | ✔ |
| **a2** | `g0 gI g1` | **`g1 gI g0`** | ✔ | **✘** |
| **a3** | `gI g1 g0 gJ g2` | **`g2 gJ g0 g1 gI`** | ✔ | **✘** |
| **a4** | `gI g1 gJ g2` | **`g2 gJ g1 gI`** | ✔ | **✘** |
| a5 | `g0 g3` | `g3 g0` | ✔ | ✔ (control) |

**A1 — one list over callees ∪ data names, reverse `.text` first-reference order,
kind ignored — is confirmed 5 of 5. A2 (the shipped writer's shape) is refuted on
three.** A3 (declaration order) is refuted on four; A4 (`.gl` order) is refuted
on a2, whose `.gl` order is `gI g0 g1` against a table of `g1 gI g0`.

**`a2` is the smallest refutation of the shipped writer: four lines of C++**,
one call and one data-symbol argument. The writer would emit `g1 g0 gI`; c2 emits
`g1 gI g0`, because the data symbol's `lis` sits *between* the two calls.
**`a3` is `undname.cpp`'s shape in four lines** — `data · callee · data`.

**Read the second way**, as the grid required (w-data's GRID C caught a defect
only on the second reading): each table was also read by the relocation targeting
each index. On a3 the sequence down `.text` is
`REFHI/REFLO(19) · REL24(18) · REL24(17) · REFHI/REFLO(16) · REL24(15)` —
strictly descending index against ascending offset, for both kinds alike. The two
readings agree, so the key is the first-reference offset and not the `Type` or
the name.

### 5.1 Two of the five frozen predictions were wrong, and about the SCHEDULE (#1727)

`a2` was predicted `gI, g1, g0` and reads `g1, gI, g0`; `a3` was predicted
`gJ, g2, …` and reads `g2, gJ, …`. Both errors are the same one: the prediction
assumed c2 hoists a `lis` above the *preceding* call, and it does not — the `lis`
stays with the call whose argument it is.

Recorded rather than quietly corrected. **The rule A1 predicts every observed
table; the lane's transcription of A1 into two cells did not.** The separation
survives because A2 fails those cells *whatever* the schedule — it puts every
data name after every callee unconditionally — but a grid whose confound had
touched the *separating* clause would have been worthless.

> **The generalization: a per-cell prediction that needs a fact the grid is not
> measuring must say so, or it is not a prediction about the rival.** This is
> w-cfgclass §6.2's confound one level up: there the confound was in the negative
> cells' *bracing*, here it is in the positive cells' *arithmetic*.

### 5.2 What is NOT shipped, and why

**A1 is not in the writer.** It converts nothing on its own — `undname` needs
four more things (§6) — and putting it in today would change the symbol table on
**every** obj the port emits while the gate exercised the new arm over a
population of **zero** cells. That is `docs/STATUS.md` trap 0 in its exact shape.
`check_external_order` keeps refusing the disagreeing shape. **The rule ships
with its consumer, in the same commit, or not at all.**
