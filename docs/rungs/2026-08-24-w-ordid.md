## 1. Read before probe, and it decided the whole design

`docs/WHITEBOX_LEVERAGE_2026-08-21.md`'s doctrine, applied literally: the
question *"is there a name reachable from the function record?"* was priced as
a binary read, and the read answered it in three hops before a line was
written. `DISCLOSURE.md` **`W-STAGETAP-6`** carries them.

```
  func + 0x00  -> the .gl SYMBOL record     FUN_10bc4715: *(int *)pbVar3 = param_1
  sym  + 0x04  -> char *, NUL-terminated    0x10b9acd0  mov eax,[ecx+0x4]
  sym  + 0x30 / +0x31 -> kind / sub-kind    0x10b97f6b  movzx eax,BYTE PTR [ecx+0x30]
```

`0x10b9acd0` is inside **c2's own symbol-name getter**, `FUN_10b9acc4`, which
is what makes the reading a fact about the field rather than about a pointer
that happened to look like a string.

### 1.1 The part that was read and DELIBERATELY not ported

`FUN_10b9acc4` returns `[sym+4]` verbatim only when `FUN_10b97f37` allows it —
kind 4, kind 9, or a kind-1 `?`-name. **For kind 3, which is what a function
is, it goes through `FUN_10b99dfe`**, which copies `[sym+4]` and returns it
unchanged the moment it starts with `'?'`, and otherwise decorates by sub-kind:
`"__unwind$"` for `'T'`, `"__catch$"` for `'V'`, `"$M"` for `'W'`, a trailing
`"$"` for `'\0'`.

**None of that is reimplemented in the tap.** It publishes the RAW field plus
the two kind bytes, and the consumer matches by exact string equality; a name
that does not match is reported unmatched and counted. Porting the decoration
would have put a guess between the read and the check, which is how an identity
stops being one. **The cost of not porting it is measured and it is zero**: on
349 fixtures the raw field matches `.text` on every function the obj contains
(§3), because X360 C++ names are `?`-mangled and `FUN_10b99dfe` returns those
untouched.

## 2. What shipped

**The tap** (`c2host/stagetap.c`, `ap_symid`). Fail-closed in the same
three-spellings discipline `rd32` already follows, now four: the name, or
`<unread>` / `<empty>` / `<nonascii>` / `<toolong>`. **None is a legal
identifier or mangled name**, so a refusal cannot be mistaken for an identity —
the reason they are words and not an empty string. The scan runs **twice**,
validate then emit, so a string that turns out unprintable halfway through
never appears half-written. A byte pointer needed its own plausibility filter:
`plausible()` demands 4-byte alignment, which is right for every record pointer
it guards and would have refused three `char *` in four.

**The seam** (`crates/c2-reference/src/stage.rs`). `FuncWalk::{sym, sym_kind,
identity}`; `TapReport::pair_by_identity` / `verify_ordinals` returning an
`OrdinalVerdict`. `SCHEMA 1 -> 2`, and the identity is IN the canonical stream —
a stream that omitted it would call two runs identical while the
function-to-ordinal binding moved.

**The API separates two questions the old code could not tell apart:**

1. *Which walk is this function's?* — the pairing. **Order-independent by
   construction**, so it is right even when the ordinals are offset.
2. *Did the ordinal happen to equal the caller's order anyway?* —
   `Verified { ordinal_order_agrees }`. The pre-#3459 assumption, now
   **measured on every TU instead of assumed on all of them**. Reported, never
   required: a `false` is a fact about c2, not a failure.

A partial pairing is returned even on `Unmatched`. A function whose name
matched **is** correctly paired, and discarding the TU would re-create the
whole-TU quarantine this exists to remove.

### 3.3 #3478 — the hazard is an OFFSET

| measurement | value |
|---|---|
| identity resolves on `after0` walks | **100 %** — no `NoIdentity`, no refusal spelling |
| fixtures reaching a full bijection against `.text` | **342 / 349** |
| `.text` functions left unpaired | **0** |

The eight are `??_GN3@@UAAPAXI@Z` (scalar-deleting destructor),
`??__Egs@@YAXXZ` (dynamic initializer), `??0D@@QAA@XZ`, and four
inlined-away `static`/`__forceinline` callees. On `wkg_splice_pos.cpp` the two

which is precisely a **shift of 2** and explains every one of that fixture's
seven quarantined rows at once.

**A count fence cannot see this and a name fence cannot miss it.** The old
quarantine fired only when the two counts differed. A TU where c2 walks one
extra function **and** `.text` gains one COMDAT passes the count check with
every row paired to the wrong function — silently.

### 5.3 THE PREREG'S OWN FENCE WAS WRONG ABOUT THE DESIGN IT FENCED (#3480)

Prereg §3 F2 registered: *"the rotated expected-name list MUST NOT be
`Verified`."*

**It cannot be, and it must not be.** A rotation is a permutation of the **same
name set**, and `pair_by_identity` is order-independent **by construction** —
that is the fix working. The registered assertion was aimed at a property the
design deliberately does not have, and would have failed on a correct
implementation.

The repair is to ask what the corruption is *supposed* to break and point the
assertion at that. The check splits:

* **F2a** — corrupt one expected NAME; the pairing must refuse. Fired on **282**
  fixtures.
* **F2b** — ROTATE; the pairing must survive and `ordinal_order_agrees` must go
  **false**. Fired on **280**.

**This is the second recorded instance of `w-pwords` §6.1's lesson and the
first where the prereg was wrong about the MECHANISM rather than about the
numbers.** §6.1's check went vacuous because the measured value could not move;
this one was pointed at a property that does not exist. *Registering a check in
advance does not make it a check.*

### 5.4 And the gate caught the control being empty — again, in the same file

## 8. Found and not taken, ranked

1. **The `??_G` / `??__E` walk-but-do-not-emit set is a characterization lane
   nobody has run.** #3478 names the mechanism from 8 witnesses on one corpus.
   *Which* functions c2 walks and declines to emit is a fact about the emit-set
   closure `W-OBJPLAN-1` is stuck on (its seed is empty on 739 of 854 TUs), and
   the funcwalk now enumerates them by name for free. Highest-value follow-up
   and it needs no new mechanism.
2. **The tap has no capture-cache path, so none of this reaches the 878-TU
   workload.** `w-pwords` §3 records the same bound. The bijection runs on 349
   fixtures; the obj corpus behind #3431's 12,610 carries no tuple counts. Cost
   is a cache format change, not an instrument change.
3. **`sym_kind` is published and unread.** The `(kind, sub-kind)` pair is in the
   payload precisely so a future consumer that needs c2's DECORATED name can
   apply `FUN_10b99dfe`'s rules without re-tapping. Nothing reads it today and
   nothing should until something needs it.
4. **The upstream sites are still ordinal-paired in effect.** `pair_by_identity`
   works at any phase, and §3's numbers are `after0`. `#3458`'s 2.32–3.19 % at
   `sched1`/`globregs`/`sched2`/`color`/`sched3` was measured under the old
   pairing; re-taking it by name is cheap and this lane did not do it.
5. **`plausible_bytes` is weaker than `plausible` and that is a real widening.**
   It drops the alignment requirement because a `char *` has none. The string
   walk is bounded at 512 and stops at the first non-printable byte, and the
   neutrality test watches the obj, but the read is the least bounded thing this
   tap does and it is named here rather than left implicit.

## 9. What this changes, and what it does not

**Changes.** `#3459` is closed. Every funcwalk consumer in the tree either
verifies its pairing (1, 2, 3), displays the identity (4), or provably does not
pair to an obj at all (5) — enumerated, not floored. `w-pwords` §5's
"permuted pairing" is superseded by #3478's **offset**, which is a stronger and
more actionable statement: it names where the hazard lives.

**Does not change.** No emit is licensed, no gate is added, and the byte judge
is untouched. The bijection is **still not promotable to the corpus** —
`w-pwords` §3's first bullet stands, and `encode()`'s two-form subset is a
separate, untouched constraint. `#3456`'s refutation of the AMENDED demotion is
strengthened (2,928/2,928 instead of 2,903/2,922) and not altered in kind. The
100 % is at `after0` only.
