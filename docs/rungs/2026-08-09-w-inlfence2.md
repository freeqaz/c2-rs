## 3. THE CRUX — what the port can see about a callee at accept time

The commission named this the crux and it splits in two, which is the whole
result.

### 3.1 DEFINEDNESS is visible, cheaply, and the port already uses it — TWICE

`Bindings::names()` is the `.gl`-defined names bound to `.ex` segments;
`IlFunction::callees()` is the call edges. `IlBundle::functions()` has crossed
them since long before this lane (`bundle.rs:1854`):

```rust
// A callee that is also DEFINED here is out of class: c2 may inline it,
// and the port cannot. […] Refused wholesale rather than by callee size,
// because what makes c2 inline […] is uncharacterized.
if funcs.iter().any(|f| f.callees().any(|c| names.iter().any(|n| n == c))) {
    return None;
}
```

and `c2_core::splice::TuContext` carries the same fact per name at the
composition seam, with the parsed body and the callee's own `.ex` optimization
word beside it. **This lane invented no reading.**

### 3.2 SIZE is NOT visible without lowering the callee — and size is what decides

`WB_INLINE_FINDINGS` F1/F9: c2 inlines the small callee and keeps the call to
the large one. So the port needs the callee's size, and the only size it has is
the one it computes by **lowering the callee** — which requires the callee to be
in class. Measured per call site (`work/w-inlfence/crossing.md` §3):

| | `port` ≤ 64 B | `port = none` |
|---|--:|--:|
| differs | **1,177** | 2,329 |
| reloc-differs | **329** | 531 |
| **exact** | **0** | **1,081** |

That is the fence and its residue in one table. Where the port can measure, it
is right 100 % of the time; where it cannot, the answer is 68 % wrong and 32 %
right and **the port has no way to tell which**.

### 3.3 So the port CAN fence, and only on a proper subset — which is the honest answer to the commission's question

Definedness alone is not enough (it costs 1,074 exact). Definedness **and** a
measurable size is enough, and it covers 1,004 of the 3,416 `localcallee`
functions. The rest is named in §6 and is not guessed at.

## 4. THE FENCE, exactly as it ships

`c2_core::comdat::fenced_inlined_callee`, called from
`comdat_body_from_selected` — so both `PortC2::build` and the FBM instrument run
it, and neither runs a copy.

> **Refuse a composed body that emits a `REL24` against a name this TU DEFINES,
> when the port can lower that callee and the callee's own lowered `/Gy` body is
> at most `splice::INLINE_UNBOUNDED_BYTES` (64) bytes.**

Every `false` from `callee_is_one_c2_expands` is a *"not proven"*, never a
*"proven not"*. Its clauses, each with a cell in §5:

| clause | why | source |
|---|---|---|
| the name ends `ZZ` (varargs) | `N_max = 0` categorically | `INLINE_PREDICATE.md` §6.18.5, `WB_INLINE` F5 |
| `TuContext::definition` is `None` | an external, or a name TWO rows claim — the ambiguity refusal is inherited, not re-decided | `TuContext`'s own contract |
| the callee **is** the caller | direct recursion is never inlined; compared by ADDRESS, because `mangled_name` is the positional binding #918 measured wrong on 74,955 rows | `WB_INLINE` F5, `INLINE_PREDICATE.md` §4 (336/336) |
| the callee's mode is unreadable, or the selector refuses it | no size exists to test | — |
| the lowered body is empty | that is mechanism **E**'s, not this one's. One function, one rule | `elide.rs`, S7's own exclusion |
| the lowered body is over 64 bytes | c2 keeps the call | `WB_INLINE` F1, and §1's 1,071-against-7 |

### 4.1 The size probe calls `body_of`, NOT `comdat_body_from_selected`, and both reasons are load-bearing

1. **Termination.** `A` calls `B` and `B` calls `A`, both small, is a legal TU;
   a fenced probe would ask the question back and forth forever. This asks one
   level and stops — no recursion to bound, no cycle set to carry.
2. **It is the right question.** What is wanted is the callee's emitted SIZE.
   Whether the callee is itself refused for *its* callees says nothing about how
   big it is.

### 4.2 Why a mis-prediction here cannot cost a byte — and why that INVERTS WB-INLINE's warning

`WB_INLINE_FINDINGS` §7 offers only decline rules and says *"the accept side is
not offered"*, on the ground that **a mis-predicted accept is a wrong obj**.
That warning was written for a lane that would **perform** the inline. Here the
accept prediction drives a **refusal**: predicting *"c2 inlines this"* when c2
did not makes the port **decline** a function it would have got right. It costs
reach and it cannot emit a wrong byte.

**This is the one place the accept side of the inline decision is safe to
consult**, and §6 is why saying so matters.

## 5. Eight cells, and TWO CONFOUND GUARDS FIRED WHILE WRITING THEM

`crates/c2-core/src/comdat.rs`, `mod inlfence_tests`. One positive and **six
negatives, each declined by a DIFFERENT clause** — `w-bdnz`'s rule, which that
lane paid for twice. Every negative additionally asserts **the `REL24`
survives**, so no cell can pass by the body having no call at all.

| cell | clause | assertion |
|---|---|---|
| **P** | the size clause, firing | `Err(InlinedCallee)` |
| **N1** | external callee | `Ok`, 1 call, target `?ext` |
| **N2** | callee **over** 64 B | `Ok`, 1 call |
| **N3** | varargs (`ZZ`) | `Ok`, 1 call |
| **N4** | direct recursion | `Ok`, 1 call, target is its own name |
| **N5** | mechanism **I** already took the body | `Ok`, **0 calls**, body == the callee's |
| **N6** | the callee is unlowerable | `Ok`, 1 call |
| **must-fail pair** | one caller, two callees differing only in size | opposite verdicts |

### 5.1 The confound guards caught two real defects, and one of them is WB-INLINE's own

`big_leaf` was `a + 1 + 2 + … + 20` and lowered to **8 bytes** — the port folds
the constant chain — so `n2` would have been a green cell decided by the clause
its positive twin tests. That is `WB_INLINE_FINDINGS` §3.1's GRID-I v1 failure
**verbatim**:

> v1's ladder was `a = a*3 + i` repeated *k* times. **c2 folds the whole chain to
> two words at every k**, so the size axis did not occur: 159 cells that all
> measured the same 28-byte callee.

The replacement is `a + a + a + …` — no constant to fold — and `n2` **asserts**
the resulting size rather than trusting a comment. Second: `compose()` unwrapped
the selector, so `n6` — whose precondition is that the selector refuses —
panicked on its own precondition instead of testing it.

**Neither would have been visible without the guards.** Both are recorded here
rather than quietly fixed.

## 6. TWO REAL-TOOLCHAIN CELLS MOVED, and they are the lane in miniature

Both are integration tests against real `c2` under wibo. Both now assert their
finding **against c2's own relocation table** instead of inferring it from the
port agreeing — strictly stronger evidence, because a verdict of `Exact` never
said *what* the two sides agreed on.

### 6.1 `reloc_identity` `s12` — `RelocDiffers(Target)` → **`Refused`**. THE REPAIR.

`void g(){ext();} void f(){g();}`. c2 expands `g` and emits `b ?ext`; the port
emitted `b ?g`. Both words are `48000000`, so the byte compare was blind to it
until `w-relo` widened FBM — and then it read a **measured wrong emit**. The
fence removes it. `s12` is the canonical reproducer of the family: **858 of the
workload's 861 `fnbyte-reloc-differs` bodies relocate against a name their own
TU defines**, and the fence takes 329.

### 6.2 `noinline_boundary` `w04a` — `Exact` → **`Refused`**. THE COST.

`__declspec(noinline) void g(){ext();} void f(){g();}`. c2 obeys the attribute
and keeps the call; the port was right and is now refused, because `?g` is
4 bytes and the fence cannot see the attribute. **Board #1039 measured that
discriminator to be an undecoded two-byte `.gl` field** — `.ex`, `.sy`, `.in`
and `.db` are byte-identical across a matched pair and the optimization word is
`00a00005` either way — so no clause over the body IL or the opt word separates
the two cases, and `w-target` recorded that decoding it is a whole-workload
blast radius belonging to another lane.

**This is the fence's reach cost and it is one function.** On the 878-TU
workload it is **zero**: the corpus's three `noinline` functions
(`src/lazer/game/BustAMovePanel.cpp`, TU #4) are not bodies either mechanism
reaches. When the port learns the field, the test goes red and the fixing commit
restores `Exact` — the same contract `w10` already carries with the sign
flipped: `w10` pins a wrong **emit**, `w04a` now pins a conservative
**refusal**.

## 7. THE 444 — untouched, and the reason is not the expected one

**All 444 survive the fence, and 444 of 444 are `localcallee`**
(`work/w-inlfence/r2arm.py`, a SET intersection and not two totals):

```
-- R2: (bucket at the FENCED tip, fence arm) --
     444  fnbyte-differs         localcallee
```

The fence sees every one. It declines because `Timer::Split` and `Timer::Ms` are
`expr-op-0x27` — the IL parser refuses them, `TuContext::definition` hands back
`None`, and there is **no size to test**. 434 of the 444 are the single symbol
`?SplitMs@Timer@@QAAMXZ`.

### 7.1 The coarse alternative, priced at the FUNCTION level

Measured at the **fenced** tip, so it is the marginal price and not a
double-count:

| refusing every `localcallee` body | additionally REMOVES | COSTS |
|---|--:|--:|
| `fnbyte-differs` | **1,855** — *including all 444* | — |
| `fnbyte-reloc-differs` | **529** | — |
| **`fnbyte-exact`** | — | **1,074** |

**D2 forbids it at 25 and it exceeds that by 43×.** The lane declines it and
says so with the arithmetic rather than shipping it and calling the exact loss
acceptable.

### 7.2 What WOULD close it, named and not attempted

The port needs the callee's size **without lowering it** — which is what c2
itself uses: `WORD [sym+0x50]`, a pre-codegen instruction COUNT
(`WB_INLINE_FINDINGS` §2.1, with `"INL:\tInlining %s (%d instrs) into "` naming
the unit, and §5's *"the index is a COUNT, and emitted bytes over-credit a
loop"*). The IL is a pre-codegen representation and a callee's own `.ex` segment
length is readable for **every** callee, including the ones the parser refuses.

**That is a fitted model and this lane ships no fit.** It needs its own frozen
grid. It is also **safe to fit**, for §4.2's reason, and that is the single most
useful thing this lane can hand the next one.

### 7.3 What this lane recommends about the shipped class

**It does not recommend reverting it, and it does not recommend leaving it
alone.** #2089 is the standing caution and this lane adds one number to it: the
444 are not a peculiarity of the float value tail — they are **13 % of a 3,416**
`localcallee` population that has been on this board since the MVP, and the same
defect is live in `int-tail-call` (#2091). A revert of w-fltret would move
`fnbyte-differs` by −444 and the emitted census by −444 and would leave 1,411
identical functions behind it. **The fence is the general repair and the revert
is not**; the decision on the class is the coordinator's and this lane did not
touch it (**decline clause D7**).
