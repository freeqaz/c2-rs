## 4. THE DECISION SURFACE — a stated NULL, again, and the same reason

`GOAL_DECISION_2026-08-21.md` § AMENDED requires a general layer to ship its
arbitrary choices as named, settable parameters.

**Registered before measuring: this lane exposes NO new parameter, and that is
a stated null rather than an omission.** A producer's op stream is a
*representation* change: the same decisions, one rendering step later. There is
no configuration in which a different value reproduces c2, so a parameter would
be a fake surface — worse than saying so. The real surface is S1a's
`EncodeParams`, inherited unchanged.

**One thing is genuinely new and it is still not a parameter**: `reach::direct`
gains an op-valued sibling, so a branch word's *reachability verdict* now
survives as a `MachineOp`. That is the same "`C2Op` reaches the producer
boundary" property S1c (i) exists for, extended to the one branch site that
still computes its own displacement — not a knob.

## 5. THE REQUIRED-ZERO METHOD, fixed here so it cannot be chosen after the fact

`w-s1c2` §5's method, adopted verbatim in substance:

* **Instrument**: `work/w-s1c3/extract_gate.py`, written and run against the
  base log **before** any `crates/` edit. It keeps every count-bearing line the
  gate prints and drops run-local ones (wall clock, `/tmp` paths, disk
  low-water, the elapsed `(Ns)` marks).
* **It EXCLUDES the `graded tree:` content-hash lines, and that is stated rather
  than hidden**: those MUST move because `crates/` moves. They are an identity
  of *what was graded*, not a count. Each tree hash is printed twice per run and
  is checked **stable within its own run** (#2907).
* **The denominator prints beside the diff.** A zero difference between two
  empty sets is this project's most-repeated defect (`w-s1c2` §3.2 caught it
  live at `0 lines over 0 keys`). Base is **35** rows; a tip run extracting a
  different count is a FAILURE of the instrument, not a pass.
* **`gap-metric` keys**: extracted with a pattern that tolerates the scan's
  indentation — the exact bug §3.2 hit — and the key count is printed at both
  ends.

## 6. CONTROLS, AND WHAT THEY CANNOT CATCH

Registered in advance:

1. **`ops_to_bytes` is concatenated encoder output by construction**
   (`mop.rs::ops_tests::ops_to_bytes_is_concatenated_encoder_output`), and every
   `encode_X` is `mop_X(..).word()`. So a producer conversion is required-zero
   *by construction* — which means the gate mostly cannot fail on it, and a
   green gate is therefore **weak evidence** about these conversions
   specifically. What the gate can catch is an op emitted in the wrong **order**
   or **dropped**, which is what mutations M4/M5 model.
2. **The `#[cfg(test)] mod incumbent` cross-check proves PRESERVATION, never
   correctness.** Two derivations wrong the same way agree. Only real `c2.dll`
   under wibo does the latter.
3. **The gate exercises the shapes its fixtures contain.**
   `fnbyte-refused-parse` is ~70 % of the function population; no identity diff
   can see a defect in a shape the parser refuses.
4. **`hatch-red` is `REFUSED` at both ends**, contributing 0 lines to every
   identity diff; per #1406 neither run establishes what a full run would.
5. **A required-zero byte delta is silent about everything that is not a byte**
   (#3336, demonstrated live by #3428 and again by §1.2). The whole diff is read
   before every commit, and every `///` block is checked to still sit on the
   function it describes — the specific way a `_text` → `_ops` split goes wrong.
6. **A mutation that goes red proves the control is wired, not that it is
   sufficient.** A sixth defect class none of the five models is not excluded.
7. **`cargo`'s own dead-code warning is a control this project was not
   reading.** §1.2 was found by reading a build warning in a gate log. It is
   recorded as a control because it caught something no test did.
