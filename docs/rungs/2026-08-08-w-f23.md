## 3. F2, and the one gate this lane got wrong first

### 3.1 The production, and why the emitter provably declines

The value position gains one arm: a designator plus an offset-add run **with no
`30`**, terminated by the ordinary `32 <PTR>` `4B`. It produces `IlOp::AddrOf`,
so the statement's op group is **four** ops where every group `c2-core` models is
three. That single fact is the whole safety argument, and it holds at all three
locators:

```text
  parse_simple_gpr_run     `while let [Load(b), v, StoreInd, tail @ ..]`
                           — position 2 is the AddrOf, so the pattern cannot
                           match; `scheduled_gpr_run_text` returns None BEFORE
                           order::schedule or alloc::allocate is asked anything
  store_leaf_text's walk    no arm matches [Load, Load, AddrOf, StoreInd];
                           terminal is Some(Err("store run with an unmodeled
                           residue")) once any group has been emitted, None when
                           none has
  straightline              IlOp::AddrOf => Err(out_of_class("sub-object address
                           feeding arithmetic; out of class"))
```

The third is the one the graded cells actually print, which is how *traced* became
*measured*.

### 3.2 The zero-offset address is excluded, and that is a rule and not caution

`AddrOf { off: 0 }` emits **nothing**, so `s->p = &s->m;` with `m` at offset 0 is
the same bare `stw` the plain pointer value emits — a shape the formal path was
byte-graded on rungs ago. Admitting it here would put a **second production over
one fact**, which is `GAPS.md` §6's "one fact, two locators", and it is also why
`w-gen` §5's 44 already-`Port=Match` cells are the offset-0 ones. `f2_leaf_g0`
holds the line and `f2_leaves_the_zero_offset_address_refused_…` pins it.

### 3.3 THE GATE THIS LANE GOT WRONG FIRST, and reversed with evidence

F2 first shipped with an extra refusal: *a run may not mix an address value with
a literal*, on the reasoning that such a run is the **mixed-kind** run
`alloc::allocate` refuses (#836) and `w-seam` declined to lift (#868), and that
the four ALLOC/ORDER clauses beside it were fitted on `li`-only producers.

**That gate made F3 unreachable on its own target.** `xboxheap`'s run is
`mSize = size · mFreeHead = this · mCount = 0 · mUsedHead = this ·
mListHead.mNext = &mListHead · mListHead.mPrev = &mListHead` — **one literal and
two addresses**. The conservative reader gate refused the whole run, so
`f2_xboxheap_direct` never reached the composition and the F3 production could
not be exercised on the shape it was built for. The symptom was a cell that kept
printing `expr-op-0x27` after the production landed.

It was reversed, and the reversal is not a relaxation — it is the §3.1 argument
applied to the same cells:

* the four clauses protect `order::schedule` and `alloc::allocate`, and **neither
  is reached** on a run containing an address, because `parse_simple_gpr_run`
  declines one group earlier;
* so admitting the address adds **no reachable model claim**, while refusing it
  hid a composition the sweep can generate 1,576 variants of;
* the clauses still apply to the **literals**, so they only ever refuse more.

Both directions are graded: `f2_run_addr_lit` (the mixed-kind cell) is
`codegen-gap` after the reversal and `vocab-gap` before it, and the 1,576
generated cases are at 0 mismatch either way. **The record is here because the
first choice was defensible and wrong**, and a lane that reads only the shipped
gate would re-derive it.

## 4. F3, and the finding: items 2 and 3 of `w-heap`'s price are ONE refusal

### 4.1 The regime gate is board #1129's, and the reader makes it stricter

`w-heap` §3.2 refines #870's *"a call that takes an ARGUMENT breaks the run"* to
**"the call's argument setup writes `r3`"**, with `f3_a3_c1b` (`Alloc(size)`,
setup `mr 4,5`) as the separating cell. Consumed here, not re-derived. The reader
expresses it as: **every slot `i` must already hold `params[i]`**, receiver
included, so the call emits no move at all.

That is **stricter** than the sentence, and deliberately so: the reader sees an
IL argument *spelling*, not a register. A member load, a literal or a converted
value in a slot cannot be shown to leave `r3` alone without a capture each, so
each refuses. Axes **D** (callee kind) and **E** (receiver slot 0) are not
crossed for the reason `w-gen` §3 gives — they are *determined by* C — and a free
callee or a member call on another object refuses through the receiver walk
rather than through a second gate.

The call is read through the **same four locators** `try_parse_member_tail_call`
uses (`eat_callee_push`, `eat_receiver_this`, `eat_call_token`, `eat_call_args`).
A private copy of the receiver walk is the drift `GAPS.md` §6 instance #9
records, and the `volatile` gate `eat_receiver_this` inherits through
`eat_operand_type` is the thirteenth live wrong-bytes emit on this project.

Likewise the **run** half: `collect_store_run` is split out of
`try_parse_store_run` as a pure code move, so the overlap gate, the mixed-file
gate, the `/Ox` pool floor and the widened-literal clauses have one home and two
tails, rather than two copies that drift.

### 4.2 The model has no carrier, and that is #844 — seen from the reader's end

`IlFunction` carries an op stream **or** a call. `codegen::select` tries
`store_leaf_text` first and the call fields after. A function built from this
shape's `ops` plus any call field therefore emits the store run and **drops the
`bl`** — a complete, plausible, *wrong* body. That is not a hypothetical: it is
board **#232**'s mechanism verbatim, and #232 was live for **255 commits** while
the scan read `mismatch 0`.

So `shape_to_function` returns `None`, with the fields named rather than dropped
with `..` so a future carrier must come back to the arm, and the census files the
body under its own `:eof` key. The key is its own and not one of the
`callee-unresolved-*` family, because **the callee resolves perfectly** in every
one of these bodies — nothing about the symbol is missing. What is missing is the
seam.

**The consequence for the price.** `w-heap` §5's table lists F3 (`crates/c2-il`)
and #844's composition seam (`crates/c2-core`) as items **2** and **3**, two
independent rows. Measured here they are **one refusal with two ends**: the
reader can recognise the composition and can go no further, because the thing it
would hand over does not exist. A lane that pays #844 gets F3's second half for
free; a lane that "pays F3" without #844 has bought a census key. This rung
bought the census key **and says so**.

### 4.3 What the key is worth, stated as a number

**8 IL bodies, 3 of them emitted**, across the 878-TU workload — moved out of
`expr-op-0x27`, which `w-heap` records as a **fall-through** here and not a
construct (#622/#662/#970 are the same dead end). The eight:

### 5.1 The bind, priced to the byte

The shipped source's line 8 is `auto& listHead = mListHead;`, and c1xx spells it
as a **store into a local**:

```text
  26 11 0a                          the destination — a LOCAL reference variable
  b9 0f 0a a6 43 81 20              `this`
  33 86 41 74 08 27 a6 43 98 20     + 8            <- F2's value, and the ONLY F2
  32 86 43 9b 20 4b                 stored, discarded    site in this spelling
```

and lines 9–10 then use that **local's token as the store BASE**:

```text
  b9 11 0a 86 43 8d 20  33 86 41 74 00 27 …  b9 11 0a 86 43 8d 20  32 …  4b
```

`parse_store_stmt` requires the base to be one of the function's own formals
(`params.iter().position(base_tok)?`), so both statements refuse and the run
never forms. So the bind is **two** reader obligations, not one:

1. a `26 <tok>` **local** admitted as a store *destination*;
2. that local admitted as a store *base*, carrying **its own base symbol** —
   which is `w-heap` §4.2's obligation, and the reason it is load-bearing is that
   collapsing the two spellings to one emits the other body's words:

```text
  BIND    li 10,0 ; stw 5,16(3) ; addi 11,3,8 ; stw 3,0(3) ; stw 10,20(3) ;
          [mr 31,3] ; stw 3,4(3) ; stw 11,8(3) ; stw 11,12(3)
  DIRECT  addi 11,3,8 ; stw 5,16(3) ; li 10,0 ; stw 3,0(3) ; stw 3,4(3) ;
          [mr 31,3] ; stw 10,20(3) ; stw 11,8(3) ; stw 11,12(3)
```

**Both producers swap and one store moves.** This lane's F3 test is built on the
**direct** segment for exactly that reason, and it is labelled as such in the
source so nobody mistakes it for the shipped TU.
