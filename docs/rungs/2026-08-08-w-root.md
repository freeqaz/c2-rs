## §3 The candidates — what makes a defined data object a root, and how each answer died

The brief's question was *is it the definition alone, a section property, an
initializer property, or a linkage property?* All of §3 is the **FIT** (650 TUs,
in sample, `sweep_fit650.txt`) and is labelled as such; §1 is the only
out-of-sample table on this page.

### 3.1 The definition alone — **REFUTED**

`ALLW` (every `.in` owner is a root) takes exact **238 → 27** and precision
**0.998 → 0.186**. The owner population is **537 216** over 650 TUs and
**507 206** of them are idle; **94.5 %** are `??_7`/`??_R` vftable/RTTI names.
This is `w-mark`'s unfiltered reading and `w-db`'s `rd_all`, reproduced as this
lane's degenerate case, and it fails the same way.

### 3.2 Linkage — **REFUTED TWICE, and the second way is the more useful**

* `UNDEC` — `extern "C"` data, which is unambiguously external linkage: **652
  owners, 0 wanted, exact unchanged at 238.** External linkage does not make a
  data object a root here.
* The `.gl` storage-class byte is **DEGENERATE**: `sc == 0x00` on **all 537 216**
  owners, and the kind-1 `+0x4d` byte is `0x00` on all of them too. **There is no
  linkage channel to read in the kind-1 header.** A lane that fits a `SC<k>` rule
  is fitting a constant. `w-db/joint.py` ships an `rd_sc` and its `M11` scored
  `SC_STATIC` at `|Rd ∩ W| = 0`; this says *why*.

### 3.3 An initializer property — **REFUTED**

`NPTR_GE5` and `NPTR_GE17` (a "big" initializer, regardless of what the object is
called) lose **199** TUs each at precision 0.23 / 0.33. The size of the
initializer is not the signal, even though the wanted owners skew large
(391 of 470 have 17–64 pointees).

### 3.4 The flag word — **REAL, NEW, AND STRICTLY DOMINATED**

`w-db/joint.py`'s twelve-rule `M11` enumeration tried `+0x20` bits `0x80`,
`0x400`, `0x480`, `0x1000`, `0x2000`, `0x4000` and the `0x60` mask. All six
reproduce here as losers (−200 to −211 TUs).

**Bits 17 (`0x20000`) and 18 (`0x40000`) were never in that enumeration.** The
fit-side probe surfaced them at `W/(W+I)` **0.3370** and **0.4619** against an
overall base of **0.0009**, and out of sample `F20_40000` is **+25 / −3** and
`F20_20000` **+24 / −4**. That is a genuine, previously unrecorded signal in a
field this project has been reading for six lanes. **It is not the rule** — it
loses TUs where `M3A` loses none, and it is dominated on every column.

### 3.5 A section property — **NOT MEASURED**, and named so absence does not read as success

`glowner.read_symbols` decodes tag, kind, storage class, `+0x4d`, `+0x20` and the
type token; it does **not** surface the section or segment the object lands in.
`docs/OBJ_DATA_BSS_SHAPE.md` §4.4 is the reason to want it — it records that
*internal*-linkage `const` is dropped when unreferenced while `extern const` is
**kept**, which is a section-adjacent distinction. This lane did not test it.

### 3.6 The name class — **SURVIVES**

`cls == "other (3)"` is `boundary2.kind` reporting that the character after `@@`
is `3`, i.e. MSVC's mangling for a **file-scope variable**. On the fit side:

## §4 THE MECHANISM IS NOT IDENTIFIED — and this is the finding's real limit

`M3A` keys off the **mangled name**. c2 is not plausibly parsing mangled names to
decide rootness; c1xx already knows the entity kind and must be handing it over
in some field. `mech.py` cross-tabulates `M3A` against **every** truth-free
`.gl` field on the fit side, asking for a predicate that is set-equal to it —
covers all 409 roots and selects no non-root.

**None is.** (`cls == "other (3)"` and `cv == "A"` are the rule's own components
and are excluded as tautologies.) The closest field-level candidates are the two
new flag bits, and the cross-tab shows why they are not it:

| `M3A` | bit 17 | bit 18 | owners |
|---|---|---|---:|
| ✓ | ✓ | ✓ | **333** |
| ✓ | ✗ | ✗ | **75** |
| ✓ | ✗ | ✓ | 1 |
| ✗ | ✓ | ✓ | **284** |
| ✗ | ✓ | ✗ | 463 |
| ✗ | ✗ | ✓ | 131 |
| ✗ | ✗ | ✗ | 535 929 |

`bit17 ∧ bit18` covers **334 of 409** roots and over-selects **284**.

> ### So the claim this lane is entitled to is **extensional**: the predicate predicts c2's behaviour out of sample at 132/200 with 0 TUs lost. It is **not** a claim about which byte c2 reads. A port implementing it would be matching mangled-name shapes — acceptable under this project's I/O-behavioural criterion, and still the weakest part of the result. **Finding the field is the next lane's rung** (§10 item 1).
