### 2.1 T2 is the row worth reading

T2 registered the weaker half of the transfer claim **and gave itself an escape
hatch**: *"expected to be OUT OF REGIME on every configuration that stores a
formal"*, on the argument that a formal is dead after a call and the body
therefore cannot be the same one. **The hatch never fired.** Zero of the twelve
`Q` cells came back out of regime; c2 compiled all twelve, and what it did was
not decline the shape but **re-allocate it** — the object and every live formal
move to callee-saved registers, and with three of them the frame switches to the
`__savegprlr_29` helper.

The registered prediction and its escape hatch were **both** wrong, in the same
direction: they assumed a boundary where there is a *rule*. That is the useful
form of a miss, and it is why §3.3 states what the rule looks like rather than
recording "Q refuses".

## 3. GRID T and GRID T2 — the transfer, and its boundary

`work/w-seam/gridt.py` (60 cells) and `gridt2.py` (36), every cell one function
in its own TU, compiled through `work/w-frame/refobj.sh` at the workload's own
flags and disassembled with `scripts/gt_dump.py`. Both were committed before
compiling.

Each configuration is a **store run**, emitted in up to five body kinds, and the
verdict is over the **run text** — the disassembly with the frame words, the
`bl` and the callee-saved copies stripped. Two verdicts are printed side by
side: **IDENT** (string-identical to the leaf's) and **PLAN** (identical once the
store base register is canonicalised). Reporting only the strong one would score
a callee-saved rename as a refutation; reporting only the weak one would score it
as a licence.

```text
  GRID T   60 selected | 60 reached | 60 GRADED | 0 out-of-regime
             P   12/12 IDENT      P2  12/12 IDENT      R  12/12 IDENT
             Q    0/12 IDENT  —   6 PLAN-only, 6 DIFFER
  GRID T2  36 selected | 36 reached | 36 GRADED | 0 out-of-regime
             34 IDENT, 0 PLAN-only, 2 DIFFER — both `D11-argcall`
```

**Board #866.** GRID T2's fresh configurations vary the axes GRID T holds
fixed and every one of them still transfers: six formals (the pool floor), mixed
`stb`/`sth`/`stw`/`std` widths, **two base symbols**, a `lis`+`ori` **wide**
literal whose halves board #644 says split, a wide literal *beside* a `li`, a run
of **seven**, and a **non-void** trailing call whose result is stored after the
run.

### 3.1 A lone trailing void call is TAIL-CALLED, even behind a store run

**Board #869.** Every `P` cell (`<run> gx();`) came back with a frame word count
of **1** — one `b`, no `mflr`, no `stwu`. So `void f(S* s,int u,int v){ s->f0=7;
gx(); }` is `li r11,7 ; stw r11,0(r3) ; b gx`, an unframed five-section leaf.

This is only visible because the frame-word count is **printed beside every
verdict** rather than asserted. A grid that had trusted the source shape would
have published twelve framed cells that are not framed, and the headline claim
would have rested on them. `P2` — two trailing calls, frame word count **9** —
is the row that carries the framed claim, and it was in the grid because the
prereg put it there for exactly this risk.

The consequence for #844 is concrete: **a "framed store run" needs two calls, or
one value live across one call.** One void call is a different (and much
cheaper) composition.

### 3.2 The transfer BOUNDARY — a call with an ARGUMENT breaks it

**Board #870, and it is GRID T2's whole deliverable.** T5 registered `argcall`
as a row that could lose, and it lost:

```text
  D11-argcall  L    li 11,7 ; li 10,9 ; stw 11,0(3) ; stw 11,4(3) ; stw 10,32(3)
  D11-argcall  P2   mr 10,3 ; li 11,7 ; li 9,9 ; stw 11,0(3) ; mr 3,4 ;
                    stw 11,4(10) ; stw 9,32(10)
  D11-argcall  R    li 11,7 ; li 10,9 ; stw 11,0(3) ; mr 3,4 ;
                    stw 11,4(31) ; stw 10,32(31)
```

Three separate things move at once. c2 **parks the object in `r10`, a
VOLATILE**, because `r3` is wanted for the argument; the **store base changes
mid-run** (`0(r3)` then `4(r10)`); and the constant pool **re-ranks** to
`r11`/`r9` where the leaf takes `r11`/`r10`. None of the three is expressible in
`alloc::allocate`'s inputs, which know nothing about a call.

So the transfer statement is not *"a store run in a framed body keeps its leaf
plan"*. It is:

> ### the run keeps its leaf plan **iff nothing between the run and the epilogue competes for the run's registers** — no argument setup, and the object's own register unchanged.

`D12-nonvoid` is the control that says the boundary is the *argument* and not the
call's return type: an `int`-returning call whose result is stored **after** the
run transfers at IDENT in both framed kinds.

### 3.3 Q — the run AFTER the call does not transfer, and it is a rule not a refusal

**Board #872.** All twelve `Q` cells compile. Six are PLAN-only — a pure rename
of the store base from `r3` to `r31`, the schedule and the relative allocation
untouched. The other six DIFFER, and the pattern is uniform: every value that
must survive the `bl` goes to a **callee-saved** register (`r31`, `r30`, `r29`
in that order — `saved`'s own order), and the *volatile* pool then re-ranks over
whatever is left.

```text
  C6-xboxheap  L   addi 11,3,64 ; li 10,0 ; stw 11,64(3) ; stw 11,68(3) ; stw 10,0(3)
  C6-xboxheap  Q   addi 30,3,64 ; li 11,0 ; stw 30,64(31) ; stw 30,68(31) ; stw 11,0(31)
```

`C1-formals` needs **three** saved GPRs and crosses `FrameLayout`'s
`needs_gpr_helper` threshold into `__savegprlr_29`, which the frame emitter
refuses by name — so that configuration is out of the port's frame class before
any of this matters.

### 3.4 The reference binding is held FIXED, deliberately

Board **#839** (the C++ reference binding `L& q = s->inner;` moves both the
schedule and the allocation) is live in this class, and **every kind of every
configuration in both grids carries it identically**. This grid asks whether a
*plan transfers*, not what the plan is; comparing a framed cell against a leaf
carrying a different binding would be measuring #839 and calling it transfer.

## 4. GRID M and GRID M2 — where the `mr r31,r3` sits

**Board #867.** The registered hypothesis H-mr — the copy is placed by
`layout_slots` as one more producer — is **refuted**, as registered.
`layout_slots` puts producer `i` before store slot `min(i, u)`, which
mispredicts `C1` (0 producers) and `C4` (2 producers). What the twelve `R` cells
fit instead is

```text
  stores_before_mr  =  nprod - 1 + u
```

with `nprod` the run's distinct producers and `u` the leading run of
**unproduced** stores in the **emitted** order — both read off the same
disassembly. It reproduces `xboxheap.cpp`'s own body (`nprod` 2, `u` 2 → 3
stores before the `mr 31,3`, which is what the obj shows).

### 4.1 It was fitted, so it went to a holdout, and the holdout killed it

`work/w-seam/gridm.py`, **24 selected / 24 reached / 24 GRADED / 0
out-of-regime, 19 hit, 5 MISS**. **Every miss has a leading unproduced run of 3
and every one is off by exactly one.** That is a shape that was right and an
*observable* that was wrong: `store_order`'s own `u` is `min(2, #unproduced)`
(`docs/ORDER.md`), and the raw leading run is not it.

```text
  stores_before_mr  =  nprod - 1 + min(u, 2)
```

`work/w-seam/gridm2.py` is that correction's own fresh holdout — leading runs of
**4, 5 and 6**, strictly outside every GRID M cell, plus source orders where the
produced stores come first and two multi-width runs — and reads **18 selected /
18 reached / 18 GRADED / 18 hit / 0 MISS**.

### 4.2 It is NOT shipped, and that was registered before it existed

ADDENDUM 1's **M2** says so in advance: no `mr r31,r3` emitter is written under
either outcome. The shape it would serve is a value live across a call, which
needs the mixed-kind allocation §5 leaves refused, so the emitter would be
unreachable. **A rule that survives two holdouts and ships nothing is still the
right outcome when the thing it would feed does not exist.**

`D11-argcall`'s `R` cell puts the copy at run index **0**, against a predicted
1 — and it is **outside the rule's regime rather than a miss**, because that
cell's run does not transfer at all (§3.2). Recorded rather than quietly
excluded.

## 5. GRID A — the narrow lift, refuted

**Board #868.** The sub-case, stated in the prereg before the grid existed: two
producers, one register-derived and one single-word constant, with
`reg.uses > const.uses` **strictly** — so clause 1 decides with **no tie**, and
no tie-break clause, no kind bonus and neither refuted key (w-next's
`uses + (reg ? 1 : 0)`, w-alloc2's `H-self`) is consulted. It looks like pure
clause 1 and therefore like conservatism.

`work/w-seam/grida.py`, three spellings × six use-count gaps × two body kinds:
**36 selected / 36 reached / 36 GRADED / 0 out-of-regime**, 24 hit, **12 MISS**.

```text
  spelling         hit / miss / out-of-regime
  addi-interior    12 /  0 / 0     (int)&q    — xboxheap's own spelling
  add              12 /  0 / 0     (u + v)
  slwi              0 / 12 / 0     (u << 3)   — the CONSTANT takes r11
```

**The `slwi` row loses at a use-count advantage of three** (reg 4 uses against
const 1) exactly as flatly as at one, so there is no threshold the lift could be
narrowed around, and both body kinds agree cell for cell, so a frame does not
rescue it either. The separating axis is the **spelling** — which
`ProducerKind::RegisterDerived` cannot represent at all.

**The three spellings were in the grid because the prereg required them.**
w-alloc2's `F4-shift-r2k1` was already on record as a `(2,1)` cell where the
constant takes `r11`; a grid built without `slwi` would have come back 24/24 and
licensed a widening that is wrong on a third of its own domain. That is stated
in `grida.py`'s docstring, above the code that tests it.

> ### **The standing instruction is taken as binding: the refusal STANDS, `xboxheap.cpp` does not convert in this lane, that is recorded, and nothing is patched.**

## 6. WHY NO SEAM SHIPPED — and the deciding reason is not the allocator

**Board #871.** Recorded in `work/w-seam/PREREG.md` ADDENDUM 2 §A2.4, committed
**before** any emitter existed, so it is a decision and not a rationalisation.

Two blockers. The first is §5: `xboxheap`'s own configuration is refused by
`codegen::alloc`, so it cannot be emitted however the frame composes. The second
decides the general case:

> ### **Every composition board #844 names is INVISIBLE to `fnbyte-differs`.**

`crates/c2-harness/src/gap/fnbytes.rs` maps `Selected::{Tail, Framed, Seq,
CondPair}` to `FnByte::Partial` **by construction** — a body whose missing words
encode their own `.text` offset is one the harness *must not* reconstruct, and
its module doc says why: doing it in the harness is *"the one way to inflate
FBM"*, moving functions into `fnbyte-exact` with zero change to the port. The
baseline scan prints the population already sitting there:

```text
  partial by shape: tail 7098 · seq 2150 · framed 123 · cond-pair 4     (9,375)
```

A store-run-before-a-call seam adds **its whole population** to that bucket. The
standing alarm this lane is instructed to watch would read `0` whether the seam
were right or wrong — which is board **#232**'s shape with the alarm *removed*
rather than merely unwatched, and #232 was a live wrong emit that survived 255
commits under a green gate.

`fnbytes.rs` already names the fix and where it belongs: a **per-function entry
point in `c2-core`**, board **#322**.

> ### So **#322 is a PREREQUISITE of #844, not a neighbour of it.** Until it exists, any seam #844 asks for is an accept path over thousands of workload functions with no standing per-function grader, and this lane declines to open one. **Zero conversions is a better outcome than one wrong emit**, and this is what that instruction looks like when it binds.

### 6.1 What a next lane inherits, priced

The composition itself is **licensed by measurement** and its three parts already
exist and are already graded — `codegen::frame`'s prologue/epilogue,
`scheduled_gpr_run_text`'s plan, and `calls::call_seq_text`'s call block. What is
missing, in order:

1. **#322** — a per-function entry point in `c2-core` so `Selected::Tail`/`Seq`
   can be graded per function. Without it the seam has no alarm.
2. **A parser production.** `try_parse_store_run` walks store statements and
   then requires a *return* tail; a store run followed by a call sequence is a
   new `BodyShape`, not a relaxed gate.
3. **The argument gate (§3.2).** Any framed seam must refuse a call whose
   argument setup competes with the run, because the run does not transfer there
   — and that refusal has to be syntactic, so census and gate cannot disagree.
4. `codegen::alloc`'s mixed refusal stays (§5), so the seam covers pure-constant
   and pure-formal runs only until somebody models the spelling axis.

   this list that widens the warranty without widening the accept surface.
2. **#870, the argument gate.** The one measured rule a framed seam needs and
   the one nobody has modelled: what happens to a run when the call's argument
   setup competes for its registers. Two cells exist; a grid does not.
3. **#872, the run after the call.** Six PLAN-only and six DIFFER cells with a
   visible mechanism (live values to `r31`/`r30`/`r29`, volatiles re-ranked over
   the remainder) and no rule fitted. It is `CallSeq::saved`'s rule extended to
   store runs.
4. **The spelling axis of `ProducerKind`.** #836, #837, #839 and now #868 all
   land on it. The enum distinguishes "reads a register"; the answer turns on
   *which* register and *what is done with the value*.
