Five grids, one classifier, every bucket decided from bytes:

| grid | cells | what it varies |
|---|---:|---|
| **A** | 32 | the whole loop vocabulary — bottom-test, top-test, leaf, call-bearing, CTR-eligible, `break`, `continue`, and a four-cell **exit-block** axis (§3.1 corrects what that axis does and does not hold fixed) |

| **E** | 8 | **held out** from H-SUF's fitting set, sentinel walks only |

Four buckets, plus three that are **excluded from every rate with the exclusion
printed** (`NOLOOP`, `MULTI`, `SELFLOOP`):

```
  GUARD     a conditional branch before the loop top, branching OUT
  GUARDRET  the same, folded to `bclr` — no displacement at all
  JUMPIN    an UNCONDITIONAL forward `b` before the loop top, into the test

```

Every rate in this rung is `n of m` with `m` printed beside it, and a cell that
failed to capture is a failure and not a zero. Reached and graded are separate
counters and both are printed even when equal.

## 3. P2 — the one clean rule the lane produced, at 46 of 46

> ### The rotation guard is a branch to the block the loop falls out to, and it folds to `bclr` **exactly** when that block is a bare `blr`.

Registered as P2 before any measurement. Graded **46 of 46** across all five
grids, with **both poles present** — 14 cells take the `bc` form and 32 take the
`bclr` form, so the number is a reading and not a base rate.

The four-cell exit-block axis in Grid A moves only the exit expression:

```text
  exit-bare    while(*s){r=r+*s;s++;} return r;     -> bare `blr`      GUARDRET
  exit-plus1   ... return r+1;                      -> `addi ; blr`    GUARD
  exit-second  while(a){r=r+a;a=a-1;} return r;     -> bare `blr`      GUARDRET
  exit-secondk ... return r*3;                      -> `mulli ; blr`   GUARD
```

### 3.1 The correction — this pair does NOT hold the loop fixed, and that matters

An earlier draft of this section claimed `while-ptr` and `exit-plus1` *"emit the
same ten words of loop and take different guard instructions"*. **That is false,
and the bytes say so:**

```text
  while-ptr  (return r)       exit-plus1  (return r+1)
  lbz    r11,0(r3)            lbz    r11,0(r3)
  mr     r10,r3               li     r10,0        <- NO pointer copy
  li     r3,0                 extsb. r11,r11         the accumulator is r10
  extsb. r11,r11              bt     2,+20           and r3 stays the POINTER
  bclr   12,2                 lbzu   r9,1(r3)
  lbzu   r9,1(r10)            add    r10,r11,r10
  add    r3,r11,r3            extsb. r11,r9
  extsb. r11,r9               bf     2,-12
  bf     2,-12                addi   r3,r10,1
  blr                         blr
```

Both are ten words and **the whole register plan differs**. Changing the exit
expression moved the *coalescing* — whether the accumulator can live in r3 — and
the guard form moved **with** it, because a coalesced accumulator is exactly what
makes the fall-out block a bare `blr`.

**So P2 is a rule about two consequences of one upstream decision, and it is
honest to say so.** It predicts the guard form from the **emitted** fall-out
block at 46 of 46 and it does **not** predict it from the IL, because the
fall-out block's content depends on the coalescing. An emitter that has already
allocated can evaluate P2; one that has not, cannot. **That is the same status
as H-SUF (§5.3), and the fact that the lane's cleanest rule lands there too is
the strongest single piece of evidence for §5.3's conclusion.**

The draft claim was checked against a disassembly rather than believed, which is
the only reason it is a correction and not a published error. Board **#771**
carries the corrected form.

**It survives board #644.** The predicate is about the *content* of the fall-out
block, not about a position: the classifier reads the words from the back edge's
fall-through to the end of the function and asks whether they are exactly one
`blr`. A producer split across other instructions cannot move it.

**And it is the rule w-hash's transcription would have needed to widen.**
`codegen::ptr_walk_loop` emits its guard as a `bc` to the exit because
`Sort.cpp`'s exit block is `mr r3,r10 ; blr`. The moment the class admits a
member whose accumulator coalesces into r3 — w-hash's own `hashgrid.py` shows c2
doing exactly that when the pointer formal moves to slot 1 — that `bc` must
become a `bclr`. **It is deliberately NOT built here** (§7.2), for w-loop §5.3's
reason 2: no caller would reach it, so it would be an ungraded code path by
construction.

## 4. H-EXIT — registered, and refuted at 10 of 17

Grid A produced **two** JUMPIN cells out of 42. A rule fitted to two cells is
what this project forbids, so the candidate was written down first
(`PREREG.md` §6, commit `9d0a9df`, **before Grid C existed**):

> **H-EXIT.** c2 duplicates the loop test iff the loop produces a value the exit
> block consumes.

**10 of 17 graded cells.** It is left in the prereg exactly as registered. The
minimal pairs that killed it sit on opposite sides of the predicate *and*
opposite sides of the answer, both times the wrong way round:

| cell | source | H-EXIT said | c2 emits |
|---|---|---|---|
| `c-strlen` | `int n=0; while(*s){n++;s++;} return n;` | ROT (n is returned) | **JUMPIN** |
| `c-global` | `while(*s){gS=gS+*s;s++;}` (void) | JUMPIN (nothing returned) | **ROT** |

Registering it bought the two cells that made §5 findable. Its named rival
**R-H-EXIT** (a size model) is refuted on the page too: `b-add` rotates at **10
words** where the JUMPIN form of the same loop would be **9**, so c2 chose the
*longer* form.

## 5. What actually decides the entry form — and why that closes L4 by dissolving it

### 5.1 H-REG, 37 of 38 held out

Read off the bytes of five named cells after Grid C, and **labelled in the
prereg as fitted**, so only the held-out number counts. Grid D is twelve fresh
cells written for that purpose.

> **H-REG.** The entry form is **JUMPIN** iff the peeled load and the loop's
> update-form load write the **same register** — the entry and the back edge
> then reach an *identical* test block, so c2 emits it once and jumps in. Where
> they write **different** registers the block cannot be shared and the test is
> **duplicated**: rotation proper.

**37 of 38 on the held-out set; 42 of 43 including the fitting set.** Both poles
predicted (18 JUMPIN, 25 ROT).

```text
  b-add     peel lbz r11 · carry lbzu r9    different -> DUPLICATED  (GUARDRET)
  c-store   peel lbz r11 · carry lbzu r11   same      -> SHARED      (JUMPIN)
```

### 5.2 The single miss refines it — H-SUF, 8 of 8 held out

`d-cmp-k` (`while (*s != 120)`) has different registers and is JUMPIN anyway.
Its bytes say why, and the four buckets cannot express it:

```text
  while-ptr (ROT)     0c  extsb. r11,r11    the test IS the record form:
                      10  bclr  12,2        one instruction, DUPLICATED

  d-cmp-k  (JUMPIN)   0c  extsb  r11,r11    the VALUE is duplicated
                      10  b     .+16        and the COMPARE is SHARED
                      20  cmpwi cr6,r11,120
```

> **H-SUF.** c2 shares the **maximal common suffix** of the two test blocks and
> duplicates the differing prefix. JUMPIN when that suffix is non-empty,
> GUARD/GUARDRET when it is empty. Mechanically: JUMPIN iff the peel and the
> induction load write the same register, **or** the back edge's CR bit is
> produced by an explicit compare.

Fitted on `d-cmp-k` alone; **8 of 8 on Grid E**, eight fresh sentinel walks,
5 JUMPIN and 3 ROT.

**Scoped to the sentinel walk, and the scope is measured rather than assumed.**
`for-break`'s entry test is `cmpwi cr6,r3,0` where its back edge is
`cmpw cr6,r11,r3` — a **constant-folded specialization** of the loop test at
`i = 0`, not a copy of it. There is no common suffix to share, so the compare
half of H-SUF does not apply to the counted family, and claiming it there would
have been the eleventh refuted placement rule.

**The producer is found as the LAST WRITER of the back edge's CR field, never as
the nearest compare** — board #644's shape. `c-break` carries an unrelated
`cmpwi cr6` at its loop top and a record form on cr0 feeding its back edge; a
nearest-compare rule reads the `break`'s compare and gets the cell backwards.

### 5.3 The finding, stated plainly

> ### `CFG_SHAPE.md` §8.2 **L4 — "Loop entry form"** is NOT AN INDEPENDENT OPEN ITEM, and no grid over loop *shapes* can ever close it.

Both of H-SUF's inputs — which register the induction load writes, and which
producer feeds the CR bit — exist only **after scheduling and allocation**. The
causal chain the 80 cells establish is:

```
  SCHEDULE            where `lbzu` lands relative to the body's last use of
   (S1, §6)           the carried char
      |
      v
  REGISTER NEED       one register if the char is dead before the load, two if
   (L1)               it is live across it
      |
      v
  ENTRY FORM          identical test blocks -> share and jump in;
   (L4)               different -> duplicate, i.e. ROTATE
```

L4 sits at the **bottom** of that chain. It was filed as a peer of L1 and it is
a consequence of it. A lane that opened on L4 alone — which is what this lane
did — can measure the correspondence to 8 of 8 and still not be able to
*evaluate* it, because the port would have to have done the allocation first.

## 6. S1 — the fourth mechanism, and it is not one of w-hash's three

Registered in `PREREG.md` §6 before Grid D and Grid E existed.

**P8 lost, in the direction the prereg said it wanted it to.** Over Grid B's ten
accumulate bodies with the signature held exactly fixed, the plan outside the
body is **byte-identical** — **one** distinct `(entry, tail)` pair over ten
cells — while the body length moves **10 → 12 words**:

```text
  entry (all ten, byte for byte)        tail (all ten)
  89630000  lbz    r11,0(r3)   PEEL     4e800020  blr
  7c6a1b78  mr     r10,r3
  38600000  li     r3,0
  7d6b0775  extsb. r11,r11     TEST
  4d820020  bclr   12,2        GUARD
```

**So register allocation is NOT what blocks a body-parameterized lowering of
this family.** w-hash's mechanism #11 is real where the *signature* moves and is
a **constant** where only the body moves. That is a genuine narrowing of #770.

**What blocks it instead is the SCHEDULE**, and it is a fourth mechanism —
distinct from rotation, from peeling, and from allocation, because the registers
are stable across all ten cells and only the *order* moves:

```text
  1-op body   lbzu · op1 · extsb. · bf
  2-op body   lbzu · op1 · extsb. · op2 · bf
  3-op body   op1 · lbzu · op2 · extsb. · op3 · bf
```

The loop-carried `lbzu` and the record-form test are **interleaved into the
accumulate chain** at positions that change with the chain's length — `lbzu` at
slot 0 for a 1- and 2-op body and slot 1 for a 3-op body, with the record form
always exactly **two slots after it**. Three lengths is three cells, and this
lane **does not fit a schedule to three cells**: w-hash declined the same thing
for the `twi 6` placement (§5.1 there, two placements, discriminator unknown),
and `w-pair` §4 and `leaf_store.rs` have ten refuted placement rules between
them.

**This is the sixth consecutive frontier mechanism to re-price dearer on
contact.** w-loop enumerated eight refusals, w-hash came back with eleven, and
the eleventh (allocation) turns out to be a constant in this family while a
**twelfth** — the interleave — is what actually stands in the way.

## 7. Why `cflow-loop` did NOT enter `PORT_CFG_CLASSES`

`PORT_CFG_CLASSES` (`crates/c2-harness/src/gap/factors.rs:44`) is an
**instrument** — the CFG-reachability screen — and it licenses no emit. Adding
`cflow-loop` to it is a claim that the port can lower the class. The 80 cells say
it cannot, and they say it precisely:

1. **The entry form is not evaluable from IL** (§5.3). The port would have to
   schedule and allocate first, and both are unmodelled.
2. **The interleave is unstated** (§6), so a body of a length the class has not
   measured cannot be emitted — which is exactly the free parameter a lowering
   would need to have.
3. **The list cannot express a restriction.** It is a flat `&[&str]` matched
   against a census key that is the bare string `cflow-loop`. There is no way to
   say *"`cflow-loop`, restricted to the sentinel walk at `/O1` with a one-op
   body"*, so the only available move is the wholesale claim, and the wholesale
   claim is false. **This is a structural blocker to the brief's own success
   condition** and it is filed as **#778** rather than worked around.

**Adding it anyway would have been World C**, which the prereg declared a
failure before any measurement.

### 7.1 The witness that would change it

A **schedule rung**: the interleave of §6 graded over a chain-length axis of at
least 6 lengths × 3 operator families, with the position of `lbzu` and of the
record form predicted per cell and graded `n of m` against real `c2`. If that
comes back stateable, then — and only then — the sentinel walk has a
body-parameterized lowering, because §3 already gives the guard form, §5 gives
the entry form once the allocation is known, and §6 shows the allocation is a
constant in this family. **Everything except the schedule is now measured.**

That rung also owes the fixture board **#747** requires, and the prereg §4 states
its shape in advance: **two bodies of different lengths in the same class**,
because a grid of one length proves nothing a transcription would not also pass.

### 7.2 What was deliberately not built

* **The P2 guard-form rule is not shipped into `codegen::ptr_walk_loop`.** It is
  correct and graded 46/46, and no caller could reach it — the parser admits one
  exit shape. w-loop §5.3 reason 2 and w-frame row **F-c**: an ungraded code path
  by construction is worse than an absent one.
* **No `Selected` variant was added.** Nothing needs one.
* **The schedule was not fitted** (§6).
* **H-SUF was not extended to the counted family** (§5.2) — `for-break` measures
  why not.

## 8. Corrections to standing documents

`docs/CFG_SHAPE.md` is *"the specification the control-flow step is meant to be
built from"*, and three of its statements move:

* **§3.7a's `?d_cont` characterization does not reproduce.** The published cell
  says a `continue` plus a call jumps into the test. This lane's `for-call-cont`
  — a `continue` and a call — is **GUARD**, and `while-call-cont` is GUARD too.
  The JUMPIN cells in this grid have nothing to do with `continue`. Board #776.
* **§8.2 L4 is re-filed as a consequence of L1, not a peer of it** (§5.3).
* **§8.2 L5 gains TWO measured exceptions, and they have a common cause.**
  w-loop reports *"0 of 28 backward intra-section branches is unconditional"*.
  This grid finds **74 of 75** loop-bearing cells conditional and **two**
  unconditional back edges, both in loops with **no exit at all** — which is
  exactly why there is no condition to branch on:

  ```text
    inf-loop   void P(void){ for(;;){} }          0000  48000000  b .+0   (to ITSELF)
    inf-call   void P(int a){ for(;;){ gi(a); } }  001c  4bfffff8  b .-8
  ```

  Neither is of the slightest interest to a lowering and both are counterexamples
  to the sentence as written. **The instrument had to be repaired twice to see
  them**: the first classifier required a *negative* displacement, so `b .+0`
  fell through to `NOLOOP` — absence read as success, committed by the grid built
  to avoid it — and the first draft of this rung then asserted **75 of 75** from
  arithmetic rather than from a count, which missed `inf-call` entirely. The
  script now **counts** unconditional back edges and self-loops per grid and
  prints both. Board #777.

`docs/OPT_MODE.md` is untouched: every cell here is `/O1`.

## 11. Found and not taken

1. **The schedule rung** (§7.1) — the one thing between here and a
   body-parameterized sentinel-walk lowering, with everything else measured.
2. **The `bclr` fold is general, and this lane only measured it on loops.**
   `CFG_SHAPE.md` §3.5 already records `cflow-if-1` bodies folding to `beqlr`,
   and §1's C6 records the epilogue being emitted even when unreachable. P2's
   predicate — *the target block is a bare `blr`* — may be the same rule in both
   places. Not measured here; it would be a cheap grid.
3. **The unsigned sentinel emits `mr.`, the signed one `extsb.`** (`e-uns`
   against `b-add`). `Sort.cpp` casts to `unsigned char*` and takes the `mr.`
   path, which is why w-hash's transcription carries `mr.` and every cell in
   Grid B carries `extsb.`. Both rotate; the class boundary between them is
   unmeasured.
4. **`d-two-ptr` — two walked pointers — is `GUARD` at 15 words** and is the
   only Grid D cell that is not `GUARDRET`. A second induction variable is a
   class nobody has priced.
