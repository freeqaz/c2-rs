### 2.3 `A2` MISSED, and following the miss is what found the answer

`A2` registered the lead at **2** at P = 0.50 and the objs say **3**. The prereg
said in advance that a miss here does **not** decline the arm — *"the obj is the
judge and the number is read, not predicted"* — so the question was which 3.

**The series decides it.** One, two and three loops charge 3, 5, 7. That is
`2n + 1`; a per-function charge of 3 would give 3, 6, 9. **So one of those slots
is not the loop's**, and two more cells name it:

* **`ctl_floatleaf`** — a plain float leaf with **zero** loops — reads **+1**;
* **`ctl_floatleaf_plus_loop`** — that leaf *and* one loop — reads **+3**, not
  +4, so the `+1` is charged **once per TU** and not per function.

That `+1` is `_fltused`, and **`coff::plan_labels` already charges it**
(`coff/label.rs:66,118`) for any function whose `IlFunction::touches_floating_point()`
is true — a predicate that **already contains `float_walk_loop`**
(`func/mod.rs:3762`), because `w-blockir` needed it for the symbol table. So the
per-function charge is **2** and installing 3 charges the TU slot twice.

**This reproduces the eleven-row table `label_slots`' own float tail already
carries** — *"every function consumes 1, plus one extra slot for the TU if any
function touches floating point"* — from cells that table did not use, and
extends it by one row. **Residual zero on all ten cells.** Nothing is quoted

**The gap is exactly the counter gap, on every row**: `10 = 3 + (2546 − 2539)`
and `11 = 3 + (2547 − 2539)`. Shape C's "extra slot" is its own mangled source

Its three findings, scored:

**This is the third time in two weeks that a published label number made a fence
