## 2. What discovery already establishes (measured, not hypothesised)

1. **The residual is exactly two families plus a five-cell measurement
   artifact.** Of `w-alloc`'s 38 fit + 31 holdout misses:
   * **family A** — counts `(2,2,1)`, **zero** unproduced stores: 35 + 9 = 44;
   * **family B** — counts `(2,1)`, **two** unproduced stores: 0 + 20 = 20;
   * **5 cells of kind `W`** (`lis`+`ori`). A `W` producer is **two**
     instructions and `w-alloc`'s `predict_seq` emits one token per producer,
     so these are misses of the observation model, not of the order. They are
     **out of domain** for this lane and it refuses them. Board **#562**.
2. **Family B is not a new regime — it is the published hoist, un-gated.**
   Within family B the miss is exactly the 20 cells whose produced sub-word
   begins with the **use-count-1** value (`abb`, `baa` shapes); the 42 whose
   produced sub-word begins with the shared value are all hits. `w-alloc`'s
   hoist fires only when the *unproduced* stores run out; the data says it
   fires whenever a producer holds the **strictly** greatest count, however
   many unproduced stores there are.
3. **Family A is a rank effect, not a count effect.** In every family-A cell
   two producers tie at count 2 and one has count 1, and the store of the
   **count-1** value is displaced to store position 2 when source order would
   have put it at 0 or 1 — while in counts `(2,1)` with no unproduced store
   (`aba`) the count-1 store stays at position 1. Nothing that reads only a
   store's own use count can separate those two.
4. **The producer emission order in the contiguous block is the RANK order**
   `(count desc, first-use asc)`, **not** the order of first consumption.
   `abbcc` emits `r10 r11 r9` while its final store order first consumes
   `r10`, `r9`, `r11`. This is the axis `w-alloc`'s `predict_seq` had wrong.

## 3. THE RULE, frozen here before any new cell is compiled

> **ORDER.** Rank the run's distinct value-producers by
> **(use count descending, first-use source index ascending)**. Then
>
> * **Producer emission order** is the rank order.
> * **Store order** is greedy over store slots `q = 0, 1, 2, …`: emit the
>   earliest source-order store that is **allowed**, where a store is allowed
>   iff
>     * *(a)* — `w-sched` rule 1 — if `q < 2` and any unproduced store is still
>       unemitted, the store must be **unproduced**; and
>     * *(b)* if the store is produced, the number of produced stores
>       **already emitted** is `>=` the **rank** of its producer.
> * **Layout** is `w-sched` rule 2 with `w-alloc`'s scope condition:
>   `u = min(2, #unproduced)` head slots take one producer apiece, in rank
>   order, and every remaining producer is emitted **contiguously**
>   immediately before store slot `u`.

Clause **(b)** is the whole new content, and it has **no free parameter** — the
only constant is `w-sched`'s own `2` in clause (a). The two published special
cases fall out of it:

* `w-sched` rule 1's *"a produced store may not be at store position 0 or 1"*
  is what clause (b) degenerates to when produced stores are scarce;
* `w-alloc`'s *"hoist the first consumer of the strictly greatest count"* is
  clause (b) at rank `j = 0`.

**On the discovery set ORDER is 479 of 479 (100.0 %), 42 refused, and the
relaxation branch of clause (b) never fires.** That number is FIT and is
reported as FIT everywhere.

**Domain.** A single base symbol; at most three distinct producers; no
multiply; no `W` (`lis`+`ori`) producer. All four are read off the IL, never
off the answer. Outside it the model returns `None`.

## 4. The two `STORE_SCHEDULE` corrections this lane must rule on

`w-alloc` measured both and deliberately changed nothing, because it had
evidence for the correction and not for the widening (board **#232**).

1. **The pool is not `{r11, r10, r9}`** — it reaches `r8`, then freed formal
   registers `r5`/`r4`, then `r3`, then `r30`/`r31` with save and restore.
   This is an **`alloc.rs`** fact, not a `schedule.rs` fact.
2. **SCHED rule 2 needs a scope condition** — `{a=1;b=2;c=3;}` is `P P P S S S`.
   This lane's §3 layout clause **is** that scope condition, and this lane will
   have it under a preregistered holdout. **Predeclared decision rule: apply
   correction 2 to `schedule.rs` iff the holdout scores it clean; leave
   correction 1 documented, because no cell of this lane's grid measures the
   pool.**

## 5. The corroborating negative, declared before it is run

`work/w-order2/search.py`, an **exhaustive** search over the class every
answer-that-is-not-this-one lives in — a per-store release time:

```
counter  in {absolute store slot q, produced-store index}     2
T        : class -> {0,1,2,3}, over the 9 classes
           {unproduced} u {(count in {1,2,3,>=4}) x (is first use?)}   4^9
                                                             = 262,144
tiebreak in {earliest source, latest source}                        2
                                                     total = 1,048,576
```

Every textbook "release time / priority" answer is in this class, including
`w-sched` rule 1 itself (`T(produced) = 2`, absolute counter) and every rule of
the form *"a store whose value is used once is blocked from the first k
positions"*. **ORDER is not**, because rank is not a function of a store's own
`(produced, count, first-use)`: family A has two producers at the **same** count
and **different** ranks.

`search.py` **refuses to open any path containing `holdout`** — a raise, not a
convention — and is scored on FIT only.

## 6. The HOLDOUT partition, decided here before `grid.py` exists

`grid.py` writes `fit.tsv` and `holdout.tsv`. A cell is **held out** iff any of:

1. `sha1(cid) % 3 == 0`;
2. it is in **tier 2** — the *tie tier*: three producers whose two greatest use
   counts are **equal and `>= 2`** (`(2,2,2)`, `(3,3,1)`, `(3,3,2)`, …). This
   is the regime clause (b) is most exposed on and the regime discovery
   contained only at counts `(2,2,1)`;
3. its run is **7 statements or longer**;
4. it is in **tier 6** — the `this`-valued filler tier.

`model.py` opens `holdout.tsv` only under an explicit `--holdout` flag, and
`search.py` cannot open it at all.

## 8. What this lane ships

A **positive guard**, in the shape `w-sched` and `w-alloc` shipped: a new
`crates/c2-core/src/codegen/order.rs` carrying ORDER, and the store emitter
asks it and **refuses when the answer disagrees with what it is about to
emit**. Inert today by construction — the parser admits no run whose order
ORDER would move. That pattern is why sixteen refuted rules produced zero wrong
objs, and it is the board **#232** defence.
