CALL 4.** `work/w-fix/grade3.py`, output in `grid3.out`, `grid3b.out`,

**Graded per EDGE, not per cell.** A depth-4 chain has four call edges and each
is scored separately; a per-cell verdict cannot tell *"the whole chain
collapsed"* from *"only the bottom link did"*, which is the entire question this
lane was commissioned to answer. Beside each verdict the grader prints the
caller's **whole `.text` COMDAT**, because a link can lose its relocation and
still not be nothing — and one of them is.

### 2.3 The cycle, and the observable that lies about it

`k10_cycle2` — `void a(){b();} void b(){a();}` plus `void f(){a();}`:
`a → b` is **CALL**, `b → a` is **I**, `f → a` is **I**. Neither member is a
bare `blr`; each is one branch word. **c2 does not elide a cycle.**

`k11_self` — `void r(){r();}` — is the cell that justifies printing the bytes
next to every verdict. It grades **E** on the relocation observable, and its
body is `48000000`: a **self-branch, which takes no relocation at all**. "No
REL24 at either setting" and "the call was dropped" are the same reading here and
different facts, exactly as `INLINE_PREDICATE.md` §4 records for `virt-ptr` from
the other side. `?f → ?r` is **CALL**. Board **#950**.

`INLINE_PREDICATE.md` §4's `recurse` family said c2 refuses to *inline*
recursion and said nothing about elision. It does not elide it either — and the
port reaches the same answer **by construction**: a cycle is never *seeded*, so
a least fixpoint never admits it. No special case was written.

## 3. What shipped

`crates/c2-core/src/elide.rs`. `TuEmptyCallees` is now the **least fixpoint** of

> * `empty_body(g)` ⟹ `g` reduces to nothing (the seed — `w-empty`'s rule), and
> * `g` is an **elidable step** — a tail call to `h`, with no data symbol and
>   none of the body kinds the selector asks about ahead of `tail_call` — and
>   `h` reduces to nothing ⟹ so does `g`.

computed **once per TU**, with the **same three conditions per step** as
`drops_tail_call` imposes on the caller, because it is the same question asked
one level down: *does c2 emit anything at all for this function*.

`drops_tail_call` itself is unchanged except for the name of what it consults.
`TuEmptyCallees::of_named` takes `(&str, &IlFunction)` pairs now instead of
`(&str, bool)` — the step needs the callee, the data symbol and the body kind,
and #918's rule is untouched: **the name is still the caller's argument**, so
`PortC2::build` passes `mangled_name` and the FBM walk passes
`FnCensus::emit_name`.

### 3.1 Termination is structural, and the ceiling is why a broken edit is red rather than hung

A name is admitted only on a `false → true` transition, so a productive round
admits at least one of the bundle's finitely many names and there can be at most
that many productive rounds. That is the whole termination argument, and a
**round ceiling** backs it: past `names + 1` rounds the context reports
`overflowed()` and **admits nothing at all**.

It cannot fire as written — `the_round_ceiling_cannot_fire` says so on a bundle
carrying a chain, a cycle and a fan-in at once — and it exists so that an edit
which breaks monotonicity *terminates and goes red* instead of spinning an
878-TU scan forever. §6's mutation 1 is that edit, and the workload reads
`fnbyte-elided 0` under it.

### 3.2 What it REFUSES, each with the cell that graded it

* **A `Seq` mid-node all of whose calls elide.** `k8`/`k9` grade it **E in c2**.
  The step declines it because `Selected::Seq` does not model E, so admitting it
  would put *"this function emits nothing"* in the closure while the emitter
  emits two calls for it — one rule with two answers. Board **#948**; the
  population is bounded above by `fnbyte-shape-seq-differs` **1,541** and is not
  sized.
* **Everything behind c2's own dead-code elimination** (`k13`) — board **#949**,
  #922's population one level up.
* **A mid-node that materializes a data symbol** (`k16`), for the reason
  condition 3 exists at all.
* **Mechanism I** (`k12`), on the body and never on the bytes.

**The packed path's `NotImplemented` mirror (#919) stayed in lockstep by
construction, not by review**: it calls the same `drops_tail_call` against the
same context the `/Gy` arm consults, so the widening widened the refusal in the
same line. A copy of the predicate would have had to be found and changed; there
is none.

**`IlBundle::functions()` is NOT widened by this lane.** `git diff
master..HEAD -- crates/c2-il/` is empty, so `mismatch` cannot move, and it did
not.

## 4. THE FINDING — a must-fail mutation came back GREEN, and it was the mutation's fault

`PREREG.md` P9 mutation 1 is *"remove the recursion guard"*. It was first written
as

```rust
if in_r[j] { in_r[i] = true; }
changed = changed || in_r[j];      // instead of setting it on the TRANSITION
```

and it reported **GREEN across the unit tests, the cell tests and the whole
878-TU workload** — `fnbyte-exact 35982`, identical to the shipped tree.

The reason is one line above it: `if in_r[i] { continue; }` means a node whose
callee is already admitted is **never revisited**, so `in_r[j]` is false for
every node the loop actually evaluates and `changed` never gets set. **The edit
looks like the same edit and is not.** The guard is the *skip*, and a mutation
that leaves the skip in place tests nothing.

Rewritten to delete the skip itself, mutation 1 goes **RED with the ceiling
firing**, and the workload reads `fnbyte-elided 0 · exact 34,466 · differs
4,711` — `w-empty`'s **pre-E baseline, restored exactly**, which is the closure
having been switched off wholesale rather than perturbed.

Both forms are kept in `work/w-fix/mutate.sh`, the dead one as a comment with the
reason. Board **#951**. It is `docs/STATUS.md` trap 5 inside the instrument built
to enforce trap 5: **a mutation that does not mutate reads exactly like a
mutation that is caught by nothing.**

## 5. The conversions, and the caution attached to them

**143 of 143 are `??1?$_Rb_tree_base@…`**, across **97** TUs, all `shape=tail`
(`work/w-fix/moved.py`, which prints by shape and by symbol family and prints
the `ENTERED` direction even when it is empty).

`w-empty`'s 1,373 were 545 instantiations of `??1?$_STLP_alloc_proxy`. This
rung's 143 are the STL container tier **directly above them** — the fixpoint
step is literally `_Rb_tree_base::~_Rb_tree_base` → `_STLP_alloc_proxy::
~_STLP_alloc_proxy` → empty. **Two consecutive E rungs have converted exactly
one idiom each.** Board **#952**; **#925** said this once already and it is worth
saying twice, because the count is what makes it look like breadth. The breadth
behind the rule is the **34 hand cells**, which span linkage, member-ness,
`virtual`, constructors, destructors, FP and integer arguments, permutations,
definition order and depth 1…8 — not the 143.

**The RESIDUAL is not one idiom, and that is the useful half of the same
measurement.** What is left at `shape=tail` is **1,531 functions over 533 TUs and
468 distinct symbol families** — `?Release@…` 286, `?front@…` 89,
`??$_Destroy_Range@…` in three instantiation groups, `??C?$_Rb_tree_iterator@…`
58, `??1?$pair@…` 41. So the *converted* population being one template is a fact
about which idiom happened to be next, not about the corpus: the next E rung does
not get a 468-family head start, it gets 468 separate reasons the port keeps a
branch.

### 5.1 And a hand-written cell cannot reach the family's own production

The obvious cell for #924's family — `struct A{~A(){}}; struct B{A a;~B();};
struct C{B b;~C();};` — is graded **E at both edges by c2** and **parse-refused
by the port at both**: `expr-call-in-expr-recv-field-off0-whole` for the member
spelling, `…-recv-intrinsic-this-adjust-whole` for the inheritance spelling, at
`/Ox` **and** at the workload's own flags. The 143 workload rows decode through
`empty-dtor-member` instead.

So the integration test for the family shape asserts the **refusal**, and says in
its failure message what going red would mean. Asserting the conversion there
would have been asserting something the port cannot reach. Board **#953** — and
the general form is worth stating: **a hand grid and the workload can exercise
the same source idiom through different productions, so neither substitutes for
the other.**

## 10. Found and not taken

1. **The `Seq` tier** (#948). `k8`/`k9` say c2's fixpoint is wider than the
   port's at a `Seq` mid-node. Taking it means eliding *inside* `Seq` first;
   the closure then follows for free. `m4` bounds it: a mixed `Seq` node is not
   nothing, so the rule needs *every* callee in the set.
2. **c2's own DCE crossing the chain** (#949). `k13` is `E` at both edges and the
   port keeps both branches. Same shape as #922's 370 `??$_Destroy_Range@…` and
   the same fix — a parser widening, provided the emptiness question is asked of
   the widened body **and the closure is asked too**, which it now is.
3. **Depth is unbounded in the rule and graded to 8** (#955). A cap was
   considered and rejected as a constant fitted to the grid's own edge; the
   workload's deepest converted chain is **2**, so nothing shipped depends on the
   extrapolation. Re-grade before assuming a deeper corpus behaves.
4. **The relocation observable cannot see a self-branch** (#950). Every grid in
   this family reads verdicts from REL24 presence; `k11` is the case where that
   returns `E` for a body that is an infinite loop. The mitigation shipped here
   is printing the caller's whole `.text` beside every verdict — cheap, and it
   caught this one.
