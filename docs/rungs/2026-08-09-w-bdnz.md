## 3. What ships

### 3.1 The class, and the eight words

At `/O1` **and** `/Ox`:

```c
    int f(int n, int k) {           // exactly two formals; slot 0 is the BOUND
        int s = INIT;               // INIT a simm16 literal
        for (C i = 0; i < n; ++i)   // C = int or unsigned; start 0, step +1
            s OP= k;                // ONE compound assignment, operand = formal 1
        return s;                   // the loop is the function TAIL
    }
```

`OP ∈ { -=, *=, &=, |=, ^=, <<=, >>= }`, and the bound's type must equal the
counter's.

```text
    mr     r11, r3
    li     r3, INIT
    cmp{w,lw}i cr6, r11, 0        <- PASS 1: the rotated pre-test, in cr6
    bclr   {4,25 | 12,26}         <- realised as a CONDITIONAL RETURN
    mtctr  r11                    <- PASS 2: the trip count
    <OP>   r3, r3, r4
    bdnz   .-4                    <- PASS 2: the latch
    blr
```

`wb-loop` §3 predicted the guard's *form* in advance — *"the START expression
against the BOUND, with the loop's own signedness, in `cr6`; a conditional RETURN
when the loop is the function tail"* — and every cell confirms it. What that
rules out is the natural rival: it is **not** a `trip_count > 0` test. Four
branch conditions appear across `work/w-bdnz/probe/L4.obj` (`bclr 4,25`,
`bclr 12,26`, `bclr 12,24`, and a forward `bf 25` when the loop is not the tail)
and all four fall out of the one rule; a trip-count rule predicts one of them.
This class ships **two** of the four and refuses the others by name.

**Two of `wb-loop`'s three passes, and the third cannot apply.** §7.7's
counterfactual runs are the evidence the split is real: `/d2QXnobdnz` removes all
29 `bdnz` and 29 of the 31 `mtctr` (the two survivors a `bctrl` and a `bctr` —
genuine indirect branches), while `/d2QXnopreinc` removes all 28 update forms and
leaves every `bdnz`. §9 item 1 states the increment this class is:
*"shipping only rule 1 + rule 2 reproduces c2's obj exactly for every loop where
the update form does not apply"*.

### 3.2 FENCE ORDER — last, and that is the one load-bearing ordering claim

Frozen in `work/w-bdnz/PREREG.md` §1.2 before a line of `crates/`: the recognizer
goes **LAST** in `parse_segment_shape`'s `0x26` arm, after `ptr_walk_loop`,
`if_call_join`, `static_scan_loop`, `ptr_walk_chain_loop`, `store_run_bind`,
`xlrc_create_guard` and `json_utf8_copy`, immediately ahead of
`try_parse_assign_body_detail`.

The four existing loop classes each argue disjointness *at the second statement*
and each says "the order is free" — true, and unproved. This class's second
statement is `53` then a literal assignment to an `int` local, which is **one
`53` away** from `xlrc_create_guard`'s stated separator. Rather than assert a
disjointness no cell proves, going last makes the claim **checkable**: no body
any earlier production accepts today can move, because no earlier production is
asked any differently. §4's three zeros follow from that rather than confirming
it. Board **#1986**.

The recognizer is **non-committal**: its own cursor, `Err` on the first byte
outside its grammar, no `prod_tag`, no `disp` on decline. A declining body keeps
`assign`'s blocker and no census key moves — which is why the negative fixture's
cells all report `expr-jump` to the census and their own clause only to a
reverted scratch (§5.1).

### 3.3 `.sy` grows a fourth positive list, and that is board #764 again

**The unsigned half of the class is byte-exact against real `c2` and was blocked
by the reader, not by codegen.** A scratch that disabled the `locals.contains`
gate made a 12-cell TU — including the `unsigned` counter and a `long`
accumulator — a whole-TU `match` at `/O1`. So the emitter was never the question.

`.sy`'s admission predicate is `kind == 1 && size == 4 && tid == 0x74`: plain
`int` automatics and nothing else, plus `w-hash`'s width-4 data pointers and
`w-XLR`'s address-taken scalars. That is board **#764** verbatim — *"`.sy`
admitted plain `int` automatics only, so the induction variable had no positive
automatic-local test"* — and `read_record`'s own 21-cell table has carried the
`unsigned` row (`86 02 4 0001 0x75`) unconsumed since that lane measured it.

The repair is a **fourth list**, `SyBlock::uint_locals`:

* **additive by construction.** An `unsigned` local used to fall through
  `admissible`, miss the address-taken arm on its flags, and leave `read_record`
  as `Record::Stepped`. So the new clause can only take from that residue, and
  `int_locals` / `ptr_locals` / `addr_locals` are byte-identical **by
  construction** rather than by measurement. (They were measured anyway: §4.)
* **a separate list rather than a widening**, for board **#1788**'s reason one
  layer down. The two are the same storage and a different `cmp`, so merging them
  would hand every consumer of `int_locals` a type whose `cmpwi` must be a
  `cmplwi` — with the IL byte that says so already discarded. A consumer opts in;
  today exactly one does.
* **narrow.** `size` and `tid` are both required, so `unsigned char`,
  `unsigned long`, `const unsigned` and an address-taken `unsigned` each still
  refuse, on a different field of the table. Four cells assert it.

**And the two layers must AGREE.** The recognizer reads the signedness from
`.ex`'s TYPE byte *and* asks which `.sy` list holds the token, and refuses if
they disagree (`ctr-loop-ctr-signedness-disagree`). Neither layer is trusted
alone: one that read only `.ex` would trust a signedness `.sy` contradicts, and
one that read only `.sy` would emit `cmpwi` for a body whose IL says `86 42 75`.

### 5.1 The per-cell clause probe, and the two confounded cells it caught

The recognizer is non-committal, so a declining cell reports `assign`'s
`expr-jump` to the census and **not** its own clause. A reverted scratch
instrument — the ladder arm changed to commit the recognizer's `Err` — produced
the per-cell clause table (`work/w-bdnz/neg_clauses.txt`); the patch is in no
commit.

It caught two cells that were **confounded**, i.e. firing on an earlier clause
than the one they were written for:

* **`n_i64`** was `long long s` *and* `long long i`, so it fired on the
  accumulator's `.sy` membership and never reached the counter clause. Repaired
  to `int s` with a `long long` counter; it now reports
  `ctr-loop-ctr-not-a-local`.
* **`n_litop`** had **one** formal, so it fired on `ctr-loop-formals-not-2`.
  Repaired to two; it now reports `ctr-loop-body-operand-load`.

**A `_neg` cell that fires on the wrong clause passes the fixture gate exactly as
a correct one does**, so nothing but this probe could have found them. That is
the same class of defect as #1965's stale `_neg` header, one level down: the
property the gate grades (whole-TU `NotImplemented`) held in both cases and the
property the *file claims to test* did not.

The remaining pair that shares a key is honest: `n_long` and `n_uacc` both refuse
at the accumulator's `.sy` membership, because that is genuinely the same clause

## 6. The label lead — MEASURED, and mode-dependent

`work/w-bdnz/LABEL_LEAD.md` has the whole table; `work/w-bdnz/label.sh`
reproduces it. The commission required the lead to be measured against the obj
and **not** read off `docs/LABEL_COUNTER.md`, because w-json measured its §1.1
surcharge two low for a back-edge class.

w-json's counterfactual form: two TUs differing in exactly one function body, the
**same** framed `int z9(int a){return gz(a)+7;}` second in every one, its
`$M`/`$M`/`$T` triple the readout. Real `c2.dll` under wibo, at the workload's
own `/O1 /Oi /EHsc /GR` and again at `/Ox`.

| the first function's body | `/O1` `$M` | lead | `/Ox` `$M` | lead |
|---|---:|---:|---:|---:|
| `leaf-none`, 0 locals | 2556 | — | 2550 | — |
| straight line, **2 locals** | 2558 | +2 | 2552 | +2 |
| **THIS CLASS** (`for`, `s -= k`) | 2563 | **+7** | 2558 | **+8** |
| the `while` spelling — **byte-identical text** | 2563 | +7 | 2558 | +8 |
| the `do/while` spelling — different text, **no `bdnz`** | 2562 | +6 | 2556 | +6 |
| `?HashString`'s pointer walk | 2564 | +8 | 2559 | +9 |
| this class with `*=` | 2563 | +7 | 2558 | +8 |
| this class with `unsigned` | 2563 | +7 | 2558 | +8 |

Four readings:

1. **§4.2.1's `for` row is not the number for this class.** It records `+2`
   against `leaf-none = 1` — a lead of `+1` — where the obj says **+7** (`+5` net
   of the two locals, which the straight-line control prices at `+2`). The
   commission's warning holds and at a wider margin than w-json's two.
2. **THE CHARGE IS MODE-DEPENDENT, and that is what decides the code.** `+7` at
   `/O1` and `+8` at `/Ox`, on the same source, and `label_slots` has **no mode
   parameter**. Any `Some(k)` is right at one mode and one `$M` triple low at the
   other: six wrong bytes in an obj that still links, board #263's shape. This
   class accepts both modes, so it would meet the wrong one immediately. **`None`
   is not conservatism here; it is the only value that can be right.**
3. **The confound the other three loop classes cite is ABSENT for this class.**
   `for` and `while` emit byte-identical text *and* charge identically at both
   modes — so the two spellings a port cannot tell apart are not the two that
   charge differently. `do/while`, which charges differently, is **not in the
   class at all**: c2 emits no `mtctr` and no `bdnz` for it, which is `wb-loop`'s
   own P3.4 miss (`cal_dowhile`) reproduced on this lane's cell. Reading 2 is
   what replaces the inherited argument.
4. **Within the class the charge is constant on both free axes** — a different
   accumulate opcode and a different guard compare both read the same numbers —
   so a `Some(k)` meets #1767's two-point bar on the *class* axes and fails
   outright on the *mode* axis.

**Two must-fail mutations, both verified:**

* `Some(self.label_lead() + 1)` turns `wbdnz_ctr_then_framed_neg.cpp` from
  `NotImplemented` into a live **`mismatch`** against real `c2.dll`, while the
  separating control `wbdnz_ctr.cpp` stays `match`.
* **`Some(8)` — the charge this lane actually measured — does NOT produce a match
  either.** It produces a *refusal*, because `IlBundle::functions`' gate is
  `label_slots(false)? != label_lead() + 1`: the question it asks is not "is the
  charge right" but "does the charge agree with what `plan_labels` **advances**",
  and `plan_labels` advances exactly 1 for a non-framed function. **So the seam
  has two layers, not one**, and a later rung owes three things: a `label_slots`
  that takes the optimization word, a `plan_labels` that can be asked at two
  modes, and a mixed-frame-class fixture per mode.

## 9. DISCLOSURE — none carried, and why

**No row is carried and none was needed.** `WB_LOOP_FINDINGS.md` §10 pre-drafted
four rows and states the position this lane took:

* **W-LOOP-1** (the `mtctr`/`bdnz` conversion is a separate innermost-first pass
  that refuses when CTR is not free) — *"the black-box alternative is
  **complete**: cells `a1`–`a14` + `d4` exhibit the whole predicate, and
  `/d2QXnobdnz` isolates the pass without any address."* This lane derived its
  boundary from **its own manufactured cells** graded against real `c2.dll`
  (`work/w-bdnz/probe/L1`–`L5`, `N1`), and every clause in
  `shapes::counted_accum_loop` names one. **No row.**
* **W-LOOP-3** (the update form is a separate machine-independent pass) — the
  same, and moot: the pass is declined by name and the class cannot reach it.
  **No row.**
* **W-LOOP-2** (the tuple opcode numbers `0x2d4`/`0x2af`/`0x2c6`/`0x288`/`0xf8`,
  the CTR register operand `0x54`, the pseudo-symbol `DAT_10c31008`, and the size
  table `0x10b18990`) — **has no obj exposure**, and **not one of those constants
  appears anywhere in `crates/`.** The recognizer works on the port's **own** IL
  byte vocabulary (`26`, `33`, `3A`, `29`, `38`, `22`, `0F`, `10`/`11`/`15`…`19`,
  `32`, `4B`), which is c1xx's output and not c2's internal IR, and clause 3 is
  stated as *"the counter is a 32-bit integer"* — which §10 says explicitly needs
  no row. **No row.**
* **W-LOOP-4** (`-loopopt`'s dead flag) — not adoptable, nothing taken.

The one place a reading is *quoted* rather than derived is the
`encode_mtctr`/`encode_bdnz` doc comments, which cite §7.7's **counterfactual obj
counts** (`/d2QXnobdnz` removing 29 `bdnz` and 29 of 31 `mtctr`). Those are
observations of shipped-compiler output under a documented switch — the black-box
half of §10 — and carry no address.

## 10. What this lane deliberately did NOT do

* **It did not attempt the update-form pass** (D9), declined by name, and drew
  the class so the pass cannot apply.
* **It did not widen `int_locals`** — the `unsigned` automatic went to a new
  list, so no existing consumer changed.
* **It did not give `label_slots` a number**, and the second counterfactual
  (§6) is why: even the *correct* number is refused by a gate one layer up.
* **It did not reorder anything in the `0x26` arm** — the new production went
  **behind** all seven, so every existing refusal key is byte-identical by
  construction.
* **It adopted nothing from `docs/whitebox/`** (§9).
* **It did not move `n_three`, `n_long` or `n_down` into the positive file**,
  although real `c2` emits bytes this port already has for all three. A `_neg`
  cell recording where the boundary sits is worth more than a wider class nobody
  graded.
