### 2.1 Two spellings, one producer — and the base symbol does NOT collapse

The address reaches the emitter two ways and they are deliberately
indistinguishable **once parsed**:

```text
  BIND     BE& r = h->mBlk;  r.n0 = &r;
             [BoundAddr{tok:r, base:h, off:20}, BoundAddr{…}, StoreInd{0,4}]
  DIRECT   h->mBlk.n0 = &h->mBlk;
             [Load(h), Load(h), AddrOf{20}, StoreInd{20,4}]        FOUR ops
```

`Prod::Addr { base_reg, off }` is the same value for both, so they CSE to one
`addi` — which is right: `&r` and `&h->mBlk` are the same address.

**What does not collapse is `SimpleStore::base_tok`**, and that is board **#1128**.
The bind is a second base symbol, so `order::store_order` answers the two
spellings differently, and the objs differ:

```text
  m_bl_u1_f1_af   addi 11,3,20 ; stw 11,20(3) ; stw 5,16(3)    source order
  m_dl_u1_f1_af   addi 11,3,20 ; stw 5,16(3) ; stw 11,20(3)    order [1, 0]
```

Both are real `c2.dll`'s own words (`work/w-midrun/grid/*/dis.txt`) and
`order::schedule` predicts both from the base symbol alone, with **no new model**.
Collapsing the spellings in `Prod` is correct; collapsing them in `base_tok`
would be board #232's direction.

### 2.2 The four-op arm is tried FIRST, and that ordering is load-bearing

`parse_simple_gpr_run` matched an exact three-op window. It matches three **or**
four now, and the two-op value arm is tried before the one-op arm — both begin
with `IlOp::Load`. A prefix match on the one-op arm would read `&h->mBlk` as the
formal `h` and emit `stw r3` where c2 emits `addi r11,r3,20 ; stw r11`: two right
words for the wrong value, an obj that links. `GAPS.md` §6's empty-prefix shape,
in the position where it costs the most.

### 4.2 The `twop` class is ANSWERED by the shipped models — and is NOT shipped
