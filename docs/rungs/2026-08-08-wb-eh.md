## 1. The result

> ### The EH record set is **not in the IL**. `5C`'s operand is neither the ip-to-state state nor `maxState` — measured on four objs — because c2 **derives** the state map in its IR. That refutes this lane's own registered prediction, and it is what turns `Main.cpp` from "the highest-worth frontier row" into a **priced decline at fifteen named refusals, eleven of them in seams that do not exist.**

Three deliverables, in the order they matter.

**Deliverable 3 — the stuck rung, NAMED.** `src/Main.cpp` has one emitted
function. Its `.ex` body is **41 tokens** and this lane tokenised **every one**
with c2's own 192-entry operand-class table (`DAT_10b25e48`, read straight out of
the pinned image) and its own scalar primitives, landing exactly on the `4D`
end-of-stream with zero desync. The construct is:

```
2C a6 43 81 20 00
│  └──────┘ │  └── one raw byte, READ AND DISCARDED (0x10b3d6b2 -> 0x10b3d694)
│   TYPE    └───── the globally gated id skip
└── opcode 0x2C, operand class 05
```

The `TYPE` is the 3-byte word `0x432681` — class `1` (signed), size index `3`
(4 bytes) — i.e. `int`. **`0x2C` carries no source operand at all**: `.ex` is a
stack machine and the convert takes the stack top. So `expr-convert-no-value` is
a fact about the port's `cstack`, not about the stream — board #1354's reading,
now with the mechanism. **The rung is `26`'s VALUE** (the member-call spine,
board #1534's 36,751-function family), **not `2C`'s type.**

And at master the row does not even reach it: `c2rs gap` reports first blocker
**`param-width-undetermined:mid`**, in the formals header, four tokens before the
body marker (#1864). The two published "reader = 2, then STUCK at `0x2C`" prices
are both about a *hatched* instrument.

**Deliverables 1 and 2 — the machinery.** Located and read with VAs
(`WB_EH_FINDINGS.md` §1–§3):

| | |
|---|---|
| the `.pdata` record | 8 bytes, align 4, `{ADDR32 BeginAddress, u32 unwind word}`, `0x10c217fd` |
| the unwind word | `hasHandler<<31 \| 1<<30 \| (len_words & 0x3FFFFF)<<8 \| prolog_words&0xFF`, computed in a **deferred patch pass** at `0x10bff811` |
| bit 30 | `or ebx,0x400000` at `0x10bff893` — **unconditional**, on every record |
| bit 31 | `setne` at `0x10bff87d` on the **same** argument `0x10c21907` tests to emit the prefix |
| the funclet split | `0x10c21fd2`: cut `.text` at every `'V'` (`__catch$`) / `'T'` (`__unwind$`) label + the end (`0x10c22046`–`0x10c2205f`) |
| the unwind-funclet mask | `0x10c220ab` `cmp [ebx+0x31],0x54`, then `neg/sbb/not/and` twice at `0x10c22080`–`0x10c22095` |
| `__ehfuncinfo$` | 9 dwords, magic `0x19930522` at `0x10be1425`, built by `0x10be12c7` |

**Deliverable 4 — the black-box cells, run in-lane.** Four objs at the workload

**Deliverable 5 — the pre-drafted DISCLOSURE rows**: `W-EH-1` (the word's bit

## 6. What this lane did NOT do

* **It did not re-tread `.rdata$r`.** w-eh5 settled it: RTTI, not EH. It appears
  here only as `??_R0H@8` in `.data`, which is the catch type descriptor.
* **It did not touch the throw side.** `.xdata$x` located (`0x10be7b4b`) and
  left; 67 objs, all STLport, and `Main.cpp` needs none of it.
* **It did not establish `maxState`'s arithmetic.** Three points (1, 2, 3) is a
  line through anything.
* **It did not establish what `5C`'s two operand values mean.** Two values, four
  witnesses — exactly the shape #1767 refuses. §5.5 of the findings names the
  cell (a third `5C` value: nested `try`, `catch(...)`, `__try`) that would fix
  or kill it, and it is the cheapest open thing in the lane.
* **It did not model the state-propagation fixpoint** (`0x10c219c4`). Seed,
  monotone update and consumer were read; the fixpoint was not.
* **It did not promote a fixture.** The four cells stayed in `work/wb-eh/src/`.
* **It did not price any other frontier row.** §6 of the findings ends with a
  redirection, not a survey — and #1792's own warning about re-surveys applies to
  it.
