## 2. Deliverable A — `--since <sha>`

`git archive` extracts the scanned roots at `<sha>` into a temp dir; the working
tree is never touched, so the mode is safe on a dirty tree and safe beside a
concurrent peer session. Three required properties, each a repo failure it is
built not to repeat:

**Δpop beside Δcov, always.** `#3045` is the local canon: an accuracy moved
0.0035 while its denominator moved 10.8 %, and *the two numbers together were
the finding*. A coverage delta with no population delta beside it is a defect of
the instrument, not terseness.

**"Tagged" is never summed with "appeared".** They have opposite meanings for
the goal — one is understanding recorded, the other is unprovenanced surface
added. Second table, five columns, and the legend says which is which.

**A pre-convention base is a labelled outcome.** Against an unmarked base every
marker reads as "added" and the coverage delta *equals the tip level*. The tool
says so in a banner and withholds the progress reading.

### 2.1 Item identity is `(path, name, ordinal)`, never a line number

Not defensive. A comment-only tagging pass moves **every** line number in the
file it touches, so a line-keyed identity reports the whole file as
vanished-and-reappeared. And `(path, name)` alone is not unique in this tree:
`c2-il/src/func/body/expr.rs` declares **five** distinct function-local
`const ON`.

### 2.2 The decomposition identity is the thing that makes it trustworthy

    Δ[X] = appeared − vanished + retagged-in − retagged-out

checked at runtime for every class **including the untagged residue**, printed
with every run, exit 1 when it fails. A differ that folds an appeared-already-
tagged constant into the retag column still prints a plausible Δ; the identity
is what refuses it.

The break applied to a throw-away copy: in `diff_rows()`, a constant that

## 4. `#3649` — the defect the instrument had, found while extending it

A glob written inside a `///` doc comment — `coff/*.rs`, `fixtures/cpp/*.cpp` —
was read as an **unterminated block comment**. From that line to EOF the file's
brace depth stopped tracking, so every `#[cfg(test)]` region below one stopped
being excluded and its constants were counted as production population.
**Eighteen files in `crates/` contain such a glob.**

One-line fix: look for the `/*` opener in `strip_for_braces(line)`, which has
already removed `//` comments and string literals.

Re-measured with the fixed scanner:

| tree | published | corrected |
|---|---|---|
| `4d48a4e77` (the `w-provenance` tip) | 189 / **1,051** = 18.0 % | 189 / **989** = **19.1 %** |
| `e548f01fd` (this lane's base) | — | 189 / **996** = 19.0 % |

**The numerator does not move at either tree.** No tagged constant was ever
inside a test region, so `#3630`'s 100/49/4/18/18 split stands unchanged and only
its denominator was wrong — by 62, in the direction that **understates coverage
and inflates a residue lanes are dispatched off**.

Watched failing (`control_red_since.txt` §6): with the fix reverted, section
[10] goes 3 red at EXIT=1, and the diagnostic check is the defect stated as a
property — *"removing the glob moves NOTHING"* read `got (2, 2), want (4, 4)`.
A doc comment's contents were changing a count.

   agree. The image **confirmed** it; it did not establish it. A ledger row
   naming both derivations would be worth more than the letter.
5. **`--since` cannot see a rename.** A file moved between the two trees reads
   as its whole population vanishing and reappearing. Correct as a *population*
   statement, misleading as a *provenance* one. `git archive` gives no rename
   detection; `git diff -M --name-status` between the two shas would, and would
   let the mode report `moved` as a fourth category.
6. **The `PROV-BLOCK` form's one hazard, stated on both blocks that use it**:
   a top-level block marker covers the file to EOF, so a constant added later
   inherits it silently. `c2-obj/src/reloc.rs`'s module doc says so and names
   the escape (an item marker beats its block). Nothing enforces it.
7. **The marker grammar was NOT changed.** `MARK_RE` and `BLOCK_RE` are

   `w-disclose` citation still count — verified by `--since e548f01fd` reading
   `[R] 100 → 100, +0` with 0 retag-out on the `c2-core` and `c2-reference`
