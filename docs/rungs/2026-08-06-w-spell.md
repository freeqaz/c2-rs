### 2.1 S2 is the row worth reading

S2 was written to be the *boring* row — the claim that the four axes this lane
enumerates are the axes. It is the one that decides the lane. `self` and `cross`
differ in **no instruction byte**: both are `addi rX, r3, K` with a different
`K`, both store into an eight-word sub-object, both at one use against one use.
The producer whose value is stored **into the object it points at** takes the top
register and the one pointing at a *different* sub-object does not.

So the axis the brief calls *"the producer's spelling"* is at least three things
that a `ProducerKind` cannot hold and that a mnemonic table cannot hold either:
the **selected instruction** (`srawi` beats `srwi`, S5), the **relationship
between the value and its store target** (`self` beats `cross`), and — GRID X —
the **C++ name the address is written through**.

## 3. GRID S — the population table

`work/w-spell/spellgrid.py` / `spellgrid.out` / `gridS_dis.txt`, committed before
compiling. **160 selected · 160 reached · 146 GRADED · 14 out-of-regime · 0
compile-failed.** Every cell is one function in its own TU at the workload's own
`/O1 /Oi /EHsc /GR` through `work/w-frame/refobj.sh`, disassembled with
`scripts/gt_dump.py`.

`P` = the register-derived producer takes the top pool register; `c` = the
single-word constant does; `-` = out of regime.

```text
  spelling   mnemonic  1base:1/1 2/1 3/1 2/2 2/3 | 2base:1/1 2/1 3/1 2/2 2/3
  self       addi        P    P    P    P    P   |   P    P    P    P    P
  cross      addi        c    P    P    P    P   |   c    P    P    P    P
  addi       addi        c    P    P    P    P   |   c    P    P    P    P
  add        add         c    P    P    P    P   |   c    P    P    P    P
  srawi      srawi       c    P    P    P    P   |   c    P    P    P    P
  extsh      extsh       P    P    P    c    c   |   P    P    P    c    c
  lwz        lwz         P    P    P    c    c   |   P    -    -    -    -
  sub        sub         c    P    P    c    c   |   c    c    c    c    c
  and        and         c    P    P    c    c   |   c    c    c    c    c
  or         or          c    P    P    c    c   |   c    c    c    c    c
  xor        xor         c    P    P    c    c   |   c    c    c    c    c
  neg        neg         c    P    P    c    c   |   c    c    c    c    c
  nor        not         c    P    P    c    c   |   c    c    c    c    c
  slwi       slwi        c    P    P    c    c   |   c    c    c    c    c
  srwi       srwi        c    P    P    c    c   |   c    c    c    c    c
  formal     —           -    -    -    -    -   |   -    -    -    -    -
```

Four groups, and the group membership is **not** the mnemonic:

| group | members | reads |
|---|---|---|
| **G0** | `self` | wins everywhere in this range |
| **G1** | `cross` `addi` `add` `srawi` | wins iff `ru ≥ 2`, at any `cu` in `1..3` |
| **G2** | `extsh` `lwz` | wins iff `cu == 1`, at any `ru` in `1..3` |
| **G3** | `sub and or xor neg nor slwi srwi` | wins iff `ru ≥ 2` **and** `cu == 1` **and** one store base |

**Board #890.** The three instrument findings the table depends on:

* `formal` — storing `u` itself — has **no producer instruction at all**: the
  formal is stored straight out of its own register and there is nothing to
  allocate. Ten cells, all out of regime, and it is a population row rather
  than an instrument failure.
* `lwz` at two or more uses under a bind is **rematerialised** — `lwz r11,…`
  twice — and #644 declines it. w-refbind §6.3 hit the same thing; it
  reproduces here at a different layout.
* c2 prints **`not`** for `~u` and **`sub`** for `u - v`. The grader never
  matches a per-spelling regex: it reads the producer's register off its own
  store and then records the mnemonic c2 printed. That is board **#843**'s
  mitigation built in rather than applied after the fact, and §5 shows it
  paying off on a mnemonic nobody predicted.

### 3.1 S3 — the negative that makes the table worth publishing

`G1` wins at `(ru 2, cu 3)` and loses at `(1,1)`. Any key of the form
`f(ru) + b > g(cu)` that gets the first also gets the second, so no additive
key over the two use counts and a per-spelling constant can reach this table.
The exhaustive search prints the residual: **11 cells**, over both base modes.
This is `alloc.rs`'s own 52,416-allocator negative and `w-sched`'s 13,104-
configuration negative in a third setting.

### 3.2 ORDER and ALLOC are separable here too

Read independently in every cell and printed side by side. Under two store bases
the **constant is emitted first in 70 of 71 graded cells** — against **33 of 75**
at one base — which reproduces w-refbind §3.2 at a fresh layout and a fresh
signature. The *winner* is not the same question: **the two columns disagree in
45 of the 146**, so a lane reading only the emission order would get a different
table.

**The one exception is `lwz`**, the same dependence w-refbind §3.2 recorded as
its own two exceptions: the load of `s->f8` must precede the store to `s->f0`
because c2 cannot prove they do not alias. It is stated as a limit rather than
excluded from the count.

### 4.4 H4 — the class principle, and the one it misplaced

The frozen class table had to decide eleven mnemonics GRID S never contained,
by a stated principle (*add forms and algebraic right shifts* carry `B`;
*loads and sign/zero extensions* carry `A`), and the grade looks up **the
mnemonic c2 printed**, not the one the C++ predicted.

| tag | predicted mnemonic | printed | frozen class | verdict |
|---|---|---|---|---|
| `subfic` | `subfic` | `subfic` | neither | **MISPLACED — behaves as an add form** |
| `andi` | `andi.` | **`clrlwi`** | neither | class right, mnemonic wrong |
| `ori` `xori` `andc` `mullw` | as predicted | as predicted | neither | correct |
| `extsb` | `extsb` | `extsb` | A | correct |
| `lhz` | `lha` | `lha` | A | correct |
| `slw` `srw` `sraw` `lbz` | — | — | — | **UNGRADED**, §4.5 |

`u & 7` is **`clrlwi`**, not `andi.` — board **#843** a fourth time, and the
first time it has cost nothing, because the grader reads the printed mnemonic.
Had this lane matched a predicted regex, six cells would have been scored out of
regime and H4 would have looked cleaner than it is.

**`subfic` is the refutation.** The principle put it outside the add family
because `subf` was *measured* outside it, and `subfic` is not `subf`: it wins at
`(2,1)` under two bases and at `(2,2)` under both, exactly where the add family
does and where the bottom group does not. **One misplaced mnemonic of eight
graded means the class table is a lookup and not a principle**, which is what
PREREG §3 registered it would take.

### 4.5 Four fresh mnemonics never reached the grader, and the reason is the frozen source

`slw`, `srw`, `sraw` and `lbz` are **26 of the 26 out-of-regime cells**.

* the variable shifts were spelled `(u << (v & 31))`, and the mask is a second
  instruction, so the producer's register is defined twice and #644 declines it;
* `(int)s->c0` is `lbz` **then** `extsb` — signed `char` — two definitions
  again.

Both are the instrument working, and both are **frozen source**: the sha256 pin
that makes the holdout worth anything is also what forbids fixing the spelling
after seeing the result. It is recorded rather than repaired, and `sraw` — the
single riskiest prediction the class principle made — is **ungraded**, which is
stated here so that nobody reads H4's 7-of-8 as covering it.

## 5. GRID X — the same address, written two ways, gets two registers

**Board #891**, declared in ADDENDUM 3 before any of its cells existed, after
GRID H turned up a disagreement between this lane's obj and w-alloc2's at what
should be one configuration.

`work/w-spell/bisect.py`, six configurations × three use-count points, 18 cells,
18 graded.

```text
  config                       3/5     2/4     1/1
  A  (int)&s->inner , bind, w-spell layout    prod    prod    prod
  B  (int)&q        , bind, w-spell layout    const   const   prod
  C  (int)&s->inner , bind, w-alloc2 layout   prod    prod    prod
  D  (int)&q        , bind, w-alloc2 layout   const   const   prod
  E  (int)&s->inner , NO bind, direct stores  const   const   prod
  F  (int)&q        , bind, register run first  const const   prod
```

* **X1 HIT** — A against B: the disagreement reproduces with the layout, the
  bind, the store targets, the use counts and the source order all held fixed.
* **X2 HIT** — A against C: moving to w-alloc2's own struct layout changes
  nothing.
* **X3 HIT** — the control. All six are `prod` at `(1,1)`, so the grid can go
  red in the direction that would have made X1 meaningless.
* **D reproduces w-alloc2's `F1-r3k5` exactly** — `const`, which is what that
  lane recorded. **Neither lane's obj was wrong; the two cells were not the same
  cell.**

> ### So `(int)&q` and `(int)&s->inner` are two different producers to c2, and they emit the same `addi rX,r3,K`. The difference is one the IL carries and the instruction stream does not — `&q` reads a bound temp, `&s->inner` recomputes from the base — which is board **#856**'s finding in a second place: a schedule and an allocation decided by a difference with no instruction of its own.

**E is the row that stops this being read as "the bind is the axis".** `&s->inner`
with **no** bind, storing directly, is `const` — so it is neither the address
spelling alone nor the bind alone but the pair. And the whole effect is
**invisible below `cu = 4`**: every configuration agrees at `(1,1)`, which is why
four lanes of 1-vs-1 and 2-vs-1 grids never saw it.

**Nothing is fitted on GRID X.** It is registered, graded, and reported as an
axis nobody has controlled — the successor to §4.2's list, not a rule.
