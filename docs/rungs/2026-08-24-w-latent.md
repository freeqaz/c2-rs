## 1. THE INSTRUMENT DEFECT THIS LANE FOUND IN ITSELF, AND IT PRODUCED A FALSE FINDING FIRST

**This section is first because the result it corrects was already reported to
the coordinator as provisional, and because the mechanism affects every agent
session on this box, not just this lane.**

`crates/c2-il/src/func/bundle.rs` — **4,120 lines**, the home of
`IlBundle::functions` (`:1995`), the TU-level gate that **19 doc sites in
`crates/c2-core` alone** cite as the thing that refuses TUs — **contains three
NUL bytes**, at `:3440`, `:3449` and `:3458`. All three are the same test line
shape:

```rust
assert!(bundle(ex, b"junkjunk\0".to_vec()).provide_data_tu().is_none());
```

where the `\0` is a **literal 0x00 byte in the file**, not the two-character
escape. `rustc` accepts it. Every grep-family tool classifies the file as
**binary**:

| tool | behaviour on `bundle.rs` |
|---|---|
| GNU `grep -rn` (`/usr/bin/grep`) | prints `binary file matches` — **a match with no line and no content** |
| `ugrep -I` — the wrapper this box's agent sessions run as `grep` | the file is **silently omitted entirely**; not even a "binary" notice |
| `python3 open(...).read()` | reads it fine |

**It is the only `.rs` file in `crates/` with this property.** Verified by
walking every tracked file: 34 tracked files contain NUL bytes, and 33 of them
are deliberate binaries (`corpus_sample/` IL + obj fixtures, `perf_scale.png`,
and `work/w-biquad/`'s objs and `_CL_*` captures — the last of which is a
separate `CLAUDE.md` matter, noted in §8.3 and not this lane's business).

**What it cost, measured on this lane.** The first pass of axis C used the
wrapped `grep` and reported `IlFunction::is_pure_expression_leaf`
(`crates/c2-il/src/func/mod.rs:3682`) as an **orphan with zero callers** — a
26-line doc-commented allowlist whose own doc says *"the direction of an error
is a **wrong emit**"*, cited by `docs/BOARD.md`, by
`docs/rungs/2026-08-10-w-mmio3.md`, and by
`crates/c2-core/src/codegen/close_call_chain.rs:68` as *"the fact that licenses
the omission … established at `c2_il::IlBundle::functions`"*. That would have
been this lane's headline: a safety conjunct asserted by three documents and
enforced by nothing.

**It is false.** The NUL-safe re-read finds it called **twice**, at
`bundle.rs:2352` and `:2358`, inside `IlBundle::functions` — exactly where every
document says it is. The predicate is **wired, fenced and correct**; the
instrument was blind.

The same blindness moved the lane's own denominators: `pub const` names
**225 → 235**, `pub fn` names **856 → 881**, and the orphan `pub fn` list
**5 → 4**. Every number in §4 is from the NUL-safe reader.

**Two things follow, and the second is the one worth keeping.**

1. `docs/rungs/README.md`'s instrument-defect rule normally fires on a *count*.
   Here it fired on a **population**: the instrument was not miscounting, it was
   **not reading one file at all**, and the shape of that error is that it makes
   things look *more* orphaned, never less — so it manufactures findings.
2. **A single NUL byte in a source file removes 4,120 lines from every
   text-search audit in the repo.** This lane files it as a defect
   (**#3513**) with a one-character fix (`\0` → `\\0` in three test literals)
   and does not apply it: the fence is analysis-first, and `crates/c2-il` is not
   this lane's to edit.
