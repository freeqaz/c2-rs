### 3.2 Why this bounds every category-1 mechanism too

The sink's arm is **maximally permissive at the byte** — `expr.rs:1491` consumes
`27` and then accepts *any* well-formed TYPE, with no `Ptr4` or `is_ptr_any`
restriction. The measurement confirms the consequence: **`expr-op-0x27` is

So there is no body anywhere in the workload that still stops at this byte when
the token is granted, **whatever upstream production sent it there.** A private
limit in a sibling recognizer that manufactures fall-through *to this key* is
therefore inside the ±8, by construction. That is the reason §5's divergence,
real as it is, cannot re-price this row.

## 5. The category-1 grep found something, and it is NOT this row: two predicates guard byte `27` and disagree on 16 of 20 type pairs

The brief's cheapest question is *"is there a private limit inside a recognizer
that already exists — grep every sibling in BOTH directions"*. Done, over every
live (non-test) site that reads `0x27`:

| site | what may follow the `27` |
|---|---|
| `shapes/designator.rs:346` (`eat_offset_adds`) | `is_ptr_any` — **16 tags × kind `0x43`** |
| `shapes/calls.rs:872` (the data-address walk) | `is_ptr4_kind` via `eat_operand_type` — **4 tags × kinds `0x43`/`0x44`** |
| `shapes/ctor_dtor.rs:540` (the `this`-adjust) | `is_ptr4_kind` via `eat_value_type` — same 4 × 2 |
| `shapes/control_flow.rs:722` (`cf-offadd-type`) | any well-formed TYPE |
| `body/expr.rs:1491` (the sink, off by default) | any well-formed TYPE |
| `shapes/leaf_addr.rs:129` | not a type limit — an offset bound, `-0x8000..=0x7FFF` |

Enumerated, the two predicates **disagree in BOTH directions on 16 of the 20
pairs either admits**:

* **12 pairs `designator.rs` takes and the other two refuse** — `82 43`,
  `84 43`, `88 43` and their volatile / const / const-volatile spellings.
* **4 pairs the other two take and `designator.rs` refuses** — `86 44`,
  `96 44`, `A6 44`, `B6 44`, the code-pointer kind that `is_ptr_any`'s own doc
  comment refuses **by name**.
* **4 agreed** — `86 43` and its cv spellings.

**This is not a tidiness complaint: the divergence is witnessed by the tree's own
captured IL.** `designator.rs`'s existing test
`the_offset_add_run_is_one_walk_with_two_readings` walks
`27 82 43` (a `char *` retype) beside `27 86 43` (an `int *` one) **in a single
run**. So a `char *` member offset is admitted in one production and refused two
productions over, on the same byte of the same construct.

**`leaf_addr.rs`'s bound is NOT one of these and must not be relaxed.** It is
`-0x8000..=0x7FFF` because `AddrLeaf` lowers to one `addi`, and `w-dclass`/B §5.3
measured that real c2 emits **two** instructions past it (`addis 3,3,1 ;
addi 3,3,-32768` at 32768). Relaxing it ships a wrong obj. It reads like the
`!=`→`>` trap and it is not one; recorded here so the next grep does not
re-derive it as a finding.

### 5.1 What I shipped for it, and what I deliberately did not

**Shipped: one test, and no behaviour.**
`designator.rs::the_two_pointer_predicates_guarding_byte_27_disagree_in_both_directions`
asserts the split `(both, any_only, ptr4_only) == (4, 12, 4)` and names the two
witnesses. It fails the moment **either** predicate moves — which is the point,
because a sibling recognizer's private limit is invisible to every other gate:
it emits nothing, so no byte compare catches it, and it agrees with the census
by construction.

**Not shipped: any change to either predicate.** I do not know which answer is
right, and the counterfactual in §3.2 says closing the gap cannot be worth more
than 8 *on this row*. The part that is **not** bounded by that 8 is the route
where the divergence's fall-through lands on some **other** key; that is
unmeasured and is board **#1336**, filed open rather than priced. Pricing it
needs an instrument that reports the *first* reader's refusal, which §9.16.5
called the highest-value instrument job on the board and which is still not
built.
