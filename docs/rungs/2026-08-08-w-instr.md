## §0 The one-paragraph answer

Two defects in two instruments that decide where this project works, plus a
third item declined on its population. **The largest single finding is that a
repair the board had already specified by name is worth exactly zero.**

`permutation_cycles` panicked whenever `call-arg-outer-formal` was lifted, so

#1344's **518,991**, was one bucket holding twenty-one distinct facts, so
#1345's demand for a *pair* could not even be computed.

**No widening ships, no fixture is added, and no TU converts.** What ships is
the ability to price a widening on both sides at one tree. Using it: `div-mod`
— the gap #1345 named positively, on the good grounds that `div_mod_leaf` has
shipped and grades 185 of 185 — recovers **0** of the 518,991 and costs **+6**
on the over-claim. Three more of the five largest arms recover **0** as well,
and admitting more arms makes the two-sided error **worse**, not better.

### §4.3 The counterfactual — board **#1376** — and why NO widening ships

#1345 forbids a bare widening because it *"publishes a second single number with
the same unexamined status as the first"*. A shipped widening also cannot
satisfy the pair, for a reason worth stating plainly: **after it ships there is
nothing left to compare it against.** The pair has to be measurable at one tree.

So `C2RS_CFRESIDUE_ADMIT` names arms to admit and one run reports what the
counterfactual *would* become **and** what the over-claim on the other side
becomes. It is safe to commit for the reason #1345 gives itself:
`control_flow.rs` is **decode-only** — nothing reads `CfResidue` except the
census report, not acceptance, not `shape_to_function`, not the emitter — so no
value of the variable can move an obj byte in either direction. That is a
stronger guarantee than `C2RS_SINK_CHAIN`'s poison, which exists precisely
because the sink *can* reach the emitter. A run that sets it prints
`gap-metric cflow-residue-admit`; the key is **absent** otherwise, never empty,
so a grep cannot confuse a counterfactual with a measurement.
