## 1. Why these four, and why the instrument lane goes first

§12.5 ranks two coordinator-sized instrument debts ahead of the adoption work,
for a reason this wave takes literally: **the inliner clause table is the
owner's named exemplar metric and its `absent` column is currently only as
honest as token-spelling luck.** `w-inlclause` found that C14 and C18 had
counterparts in the port for a full wave and stayed `absent` because the
screen checks one spelling — which means **C3 and C19 converted in wave 18
only because the adopting lane happened to pick colliding tokens**, and
nothing detected either case. Adopting more clauses before fixing that is
adding rows to a scoreboard that cannot count.

So **L1 is an instrument lane and it owns both artifacts** — the page and the
table — which is `#3814`'s whole finding. The other three lanes are seamed to
never touch either.

**What the clause table actually says today**, re-derived rather than relayed
(`awk -F'\t' '$5=="absent"{print $NF}' work/w-inlmetric/CLAUSES.tsv | sort | uniq -c`):

```
  5 emit-change      C7, C9, C10, C11, C12   derivable, but each is an EMIT
                                             change needing a two-sided price
  4 no-instr-count   C2, C4, C16, C17        ONE missing link, four rows
  2 no-instr-stream  C5, C6
  1 writer-unread    C1
```

`no-instr-count` is the **highest-fan-out single read on the board**: the port
has no pre-codegen instruction count, and that one absence blocks four rows and
is also what pins C20 at `fitted`. That is L2. It is a **read**, not an
adoption — the adoption belongs to a later wave using L1's repaired screen,
and this brief does not fund it.

### L2 — `w-instrcount`: the pre-codegen instruction count

**Kind:** characterization. **Outcome:** `built` (or `FAILED`).

The single read that unblocks four `absent` clauses. What is already known and
address-cited, from `CLAUSES.tsv` and the pages it points at:

| clause | address | what it does with the count |
|---|---|---|
| C2 | `0x10b62703` | **seeds** `DAT_10c3f5cc` = `(ushort)[fn+0x50]` |
| C4 | `0x10b6276e` | driver entry `FUN_10b61ee1(fn, level=1, budget=B, 0, 100000000, 0)` |
| C16 | `0x10b60a63` | `cmp DWORD PTR ds:0x10c3f5cc, 0x88b8` — the 35,000 caller-huge decline |
| C17 | `0x10b60a73` | `cmp DWORD PTR [ebp+0x10], eax` — budget vs instrs, `> 0x28` declines |

**The question is what `[fn+0x50]` IS** — when it is written, by what, in what
unit, and whether the port has anything that could carry it. Read
`0x10b62703`'s producer chain. A `ushort` truncation is already visible in the
seed and is worth a sentence: a caller of ≥ 65,536 whatevers wraps.

**Prefer the read to the grid** (read-before-probe, standing doctrine). If a
probe is needed to settle a unit, price the read that would answer it first
and say why the read did not.

**This lane writes NO `crates/` code and does NOT touch `P_INLINE.md` or
`CLAUSES.tsv`.** Those are L1's, by construction, this wave. Publish to your
own findings page; L1's repaired instrument and a later wave adopt from it.
Name in your rung, explicitly, **which of C2/C4/C16/C17 your read would
unblock and which it would not** — that list is the deliverable the next wave
is dispatched off, and a lane that overstates it costs a wave.

**F7 is the standing counterexample and you must engage it.** `CLAUSES.tsv`
records for C2: *"caller 48 B vs 5,640 B gives identical verdicts on 12
cells"*. If the count is load-bearing, why did a 117× size range not move a
verdict? Either the cells were the wrong axis, or the count enters somewhere
narrower than the clause suggests. **Answering that is worth more than the
addresses**, and a lane that publishes the read without addressing it has
left the interesting half undone.

### L3 — `w-globset`: the candidate SET as a settable parameter

**Kind:** **construct rung** — `Fixtures: none`, `Census: +0`, **required-zero
byte delta**, **non-empty `Fail axis:`** (`rung_registry.rs` asserts it for
construct rungs dated 2026-08-28 or later). **Outcome:** `built`.

`[globregs]` moved further than any other row this era, and the order half is
finished as a model: the mint-order key is `[O]` **exact 42/42** with seven
rivals refuted. **This lane does for the candidate SET what is already done
for the order** — expresses it as a named, settable parameter in the port,
which is goal (1)'s stated purpose for this port (an instrumentable model with
exposed decision points).

The read is done and is `w-globarms`' (`#3808`–`#3810`), so this is a
construct rung and not a read:

* the `kind` byte has **one deciding writer**, `FUN_10bd2913` at
  `0x10bd2a1d`, keyed on the front end's **3-bit COFF linkage field**
  `([gl+0x37]>>0x15)&7` through an 8-entry jump table at `0x10bd2a9f`;
* **kinds 4 and 5 = linkage 1/3 = exactly the symbols that never reach the
  object file** (compose with `P_SYMBOL` §3) — the ordinary autos;
* **A6 needs TWO parameters, not one**: the linkage class *and* a **per-symbol
  escape flag** (`sym+0x05 & 2`, sole setter `FUN_10bd2db7`, which walks the
  leader's `+0x0c` chain — so it is a property of a symbol *group*). And it is
  **not** "address taken": `int *q = &x` with no escape is still PROMOTED.

**`#3723` binds this lane and a byte delta alone does NOT discharge it.** A
required-zero byte delta **passed a real emit widening** — `w-regsel`'s control
opened the allowed set to `r0..r31` and 471/475 tests still passed with the
gate green, because the criterion sees only emissions the corpus exercises.
**Register a REFUSAL-DOMAIN check in prereg**: perturb your parameter to a
value that must change behaviour, and show `crates/c2-core/src/surface/DOMAIN.txt`
moving while the byte delta stays zero. That headline pair — **byte delta 0 /
domain moved N lines** — is the construct-rung template (`w-doctrine`,
wave 17), and it has since caught two widenings the byte gate scored zero on.

**Define no `ported` numerator** (decision 21 §4, unchanged, and `#3809`
argued the point at length: 6 of gate A's 12 arms are `CONSTR` for one shared
structural reason, so a 12-arm ratio carries a 6/12 ceiling on day one, and
the arms are not equally weighted — A6 and A8 cover every symbol a C++
compiland declares while A1 covers one record per compilation). Twelve equal
sites would measure the binary's branch structure, not the compiler's
behaviour.

## 5. Standing method — the parts that have cost lanes a day each

* **Prereg first**, committed before the image is opened or the first cell
  compiles.
* **Controls watched RED** before any verdict from them is quoted (`#3336`).
  `w-globarms` shipped a control that reported on one path while the
  publishing path stayed green — second wave running that this cost something.
* **Restoring a mutation control with `cp`/`mv` preserves the backup's older
  mtime**, so cargo does not rebuild and **the mutated binary runs for the
  closing check**. Two lanes hit this independently in wave 18; one saw 67
  failures over a tree `git status` called clean. `touch` the file after
  restoring, and verify the rebuild happened.
* **`pgrep -f` / `pkill -f` match a COMMAND LINE and are worktree-independent** —
  on this shared box they match peers' runs, and a lane once killed four peers'
  suites. Wait on a PID with `kill -0`, and bound every wait with a deadline.
* **Read the `GATE:` verdict LINE, never the exit code.** `REFUSED` exits 0 and
  `PASS` can exit 1. An unqualified `GATE: PASS` is available on this base — if
  your run says `(HATCH-RED REFUSED)`, that is **your tree**, not an inherited
  condition, and `#3786` is how it gets diagnosed.
* **`scripts/gate.sh` exceeds the 600 s tool cap.** Launch it with
  `setsid nohup … </dev/null & disown` and poll with a bounded loop.
* **A thing being printed is not a thing being watched** (`#3689`, `#3787`,
  `#3814` — three instances in three days). Before trusting any
  `--check`/`--verify` you build or rely on, **watch it fail on deliberately
  broken input**. L1 is funded because of this rule; do not ship a new checker
  that has never been seen red.
* **Bind every published count to a recipe.** `mop::plan`'s doc counts went
  stale 48 hours after they were corrected; only the figure carrying a
  `COUNT[…]` recipe survived.
