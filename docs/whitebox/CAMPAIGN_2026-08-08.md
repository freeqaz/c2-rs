# WB CAMPAIGN 2026-08-08 — take the stuck questions to the binary

> **PROVENANCE — DISASSEMBLY-DERIVED.** Lanes working this campaign read the
> static disassembly of Microsoft's `c2.dll` (the exact image pinned in
> [`C2_MAP_METHOD.md`](C2_MAP_METHOD.md) §0 — verify the sha256 before trusting
> any address). Everything they produce is **navigation** until it earns a
> [`DISCLOSURE.md`](DISCLOSURE.md) row. **The obj is the sole judge**: a reading
> that disagrees with what c2 emitted is wrong, however clean the code looked
> (§7 of the method doc — the `.bss` retraction).

## Why this campaign exists

The 2026-08-08 review established that the project is **reader-bound and priced
out on its current channels**:

- `match = A ∧ B ∧ C ∧ (D ∨ E)` sits at **11 of 871**; `A∧B∧C` = 27; the
  FRONTIER (TUs whose only remaining factor is function bytes) is **16 TUs =
  59 functions**, of which **48 (81%) are behind a reader refusal** where
  nothing downstream can even be priced (board #1474).
- `vocab-gap` is **860 of 878**; `codegen-gap` is **0**. `fn_blockers` holds
  671 keys summing 1,751,957.
- The conversion rate of black-box-only lanes is ~5 TUs per ~161 lanes, and the
  frontier estimate streak (board #770) runs ~10 optimistic / 2 pessimistic /
  1 hit.

Against that, the one structural win of the week — the tag-0x10 ALIAS model,
+340 per-TU exact over the incumbent — came from **exactly one method**: the
disassembly named the mechanism (W-ALIAS-1/2), a black-box intervention
confirmed it (15/15 draws, 0/15 parity control), the corpus graded it, and the
adoption was disclosed by address. The black-box alternative was tried first
and measured insufficient (binds at 0.019/0.026 one byte either side).

**This campaign scales that method to the three questions the project is
demonstrably stuck on.** The user has explicitly authorized the analysis
(2026-08-08); the disclosure discipline is unchanged.

## Standing rules for every WB lane

1. **Verify the image**: `sha256sum ~/ghidra-projects/bin/c2dll` must equal
   `c80981…6258` (method doc §0) before quoting any VA. If the export directory
   is missing, regenerate per method doc §3–§4 (mind the dot-path trap §2);
   never open the Ghidra project concurrently — grep the flat export only.
2. **Obj-check before you believe.** `high` confidence means "I read the
   instructions correctly", not "this is what c2 does." Every reading that will
   be handed to a code lane must survive a black-box check against real
   `c2.dll` under wibo, designed *before* the check is run (frozen predictions,
   w-clear discipline). A reading an obj refutes is **retracted**, not hedged.
3. **Navigation is free; adoption is not.** These lanes adopt nothing into
   `crates/` — they deliver readings plus *pre-drafted* DISCLOSURE rows
   (addresses named) for a later code lane to carry in the same commit as the
   code change. Scratch-only local instrument patches in a lane's own worktree
   are fine for measurement but are never committed.
4. **Never commit**: bulk decompiled C (`decomp_all.c` excerpts beyond short
   quoted fragments needed to defend a reading), Microsoft binaries, absolute
   machine paths, captured IL, objs.
5. New or changed labels go in `docs/whitebox/labels/*.tsv` (tracked,
   deliberately) and the tables regenerate via the method doc §5 scripts.
   `unknown` remains a respectable value.

## Lane WB-A — `wb-reader`: the frontier's 48 reader refusals

**Question.** What do the IL constructs behind the 48 reader-refused frontier
functions *mean*, per c2's own IL reader?

**Why it is first.** These 48 functions are the whole distance between the
16 frontier TUs and conversion (10 of the other 11 are already exact; 1 is
WB-B's defect). Every one of them dies at the port's reader, so no black-box
instrument can currently price them. The W-IL label cluster (42 labels) and
the il-open/mapper functions are the entry points.

**Firm deliverables.**
1. **The listing**: the 48 functions grouped by first-blocker key — per key:
   count, TUs touched, example function. (Derive from the board #1474
   instrument plus `fn_blockers` restricted to the frontier; a scratch-only
   local print in the lane worktree is acceptable and is not committed.)
2. For the **top ≥3 families by frontier count**: a reading of c2's IL reader
   for that construct — record layout, operand grammar, semantics — with exact
   VAs, filed as navigation in a lane findings doc under `docs/whitebox/`.
3. Per reading: a **black-box confirmation design** (the cheap oracle
   experiment that would confirm or refute it), and run it where feasible
   within the lane.
4. Per family: what the port's reader would need to accept the construct, and
   a predicted **recovered vs renamed** split on the 48 (the rename trap,
   board #1465, applies to whitebox-derived predictions too).
5. Pre-drafted DISCLOSURE rows for anything obj-confirmed.

**Success floor**: the single largest frontier family has a grammar reading
that survived a black-box check — or a written, specific finding of why it
cannot (also a result).

**Seams**: docs/whitebox/ + work/wb-reader/ only. Does not touch `crates/`
(concurrent lanes w-mass and w-phase7 own the readers and the `.gl` decode).
Board rows **#1590–#1609**.

## Lane WB-B — `wb-frame`: the frame-opening predicate

**Question.** When does c2 open a stack frame, and how is the frame size
computed? Ground truth anchor: `?supershuffle@@YAXPAD@Z` (`keygen_xbox.cpp`),
the port's only measured wrong emit on the frontier — 21 words vs c2's 26,
first divergence at word 2 (`port=fbe1fff0`, `ref=9421ffa0`: c2 opens a
96-byte frame, the port does not). Board #1477.

**Firm deliverables.**
1. Locate the prolog/frame-size decision in the emitter (W-EMIT cluster is the
   entry); read the **predicate** (which functions get a frame) and the **size
   computation** (alignment, save areas, locals), with VAs.
2. The specific answer for `?supershuffle`: which of its properties trip the
   predicate, and the arithmetic that lands on 96.
3. An **obj-check grid**, frozen with every rival predicate's per-cell
   prediction before the first `cl.exe`, with an asserted minimum of
   discriminating cells (w-clear's confound, checked for in advance). The
   reading must survive the grid or be retracted.
4. Pre-drafted DISCLOSURE rows for the adoption-ready core, so the follow-on
   code lane (absorbing task w-frame / board #1477) can ship a frame RULE, not
   a per-TU patch.

**Seams**: docs/whitebox/ + work/wb-frame/ only. Board rows **#1570–#1589**
(inherited from the undisdispatched w-frame reservation — noted here so the
range is not double-minted).

## Lane WB-C — `wb-memcpy`: the intrinsic expansion decision function

**Question.** The exact inline / call / eliminate decision for `memcpy`.
Ground truth anchor: w-memcpy's 1,155 frozen grid cells — the best id-keyed
rule scores 114/232; the measured boundaries are size-per-alignment (`char*`
5/7, `int*` 20/24, `double*` and a 16-byte struct 44/48); a third mechanism
*eliminates* the copy (bare `blr`) when both operands are local, at every size
to 96. Two facts on no board row: `memcpy` never appears in the `.gl` name
stream (c2 mints the name), and each pointer argument carries a `2C`
conversion beside two alignment hints.

**Firm deliverables.**
1. Find the intrinsic lowering (the minted `memcpy` string and its xrefs are
   the entry; `strings.tsv` / `xrefs.tsv`).
2. Read the **decision function** — thresholds, the alignment input, and the
   elimination mechanism — with VAs.
3. Check the reading against the **existing measured grid results** (they are
   already-paid-for obj checks: every boundary the reading implies must
   reproduce the measured 5/7, 20/24, 44/48 boundaries and the elimination
   class, and should explain the 24 R-DESC misses if it can).
4. Pre-drafted DISCLOSURE rows.

**Seams**: docs/whitebox/ + work/wb-memcpy/ only. Board rows **#1610–#1629**.

## What DONE looks like for the campaign

Each lane lands a findings doc under `docs/whitebox/`, a rung doc under
`docs/rungs/`, board rows from its range, and (where earned) pre-drafted
DISCLOSURE rows. The coordinator then edits `docs/ROADMAP.md` with the
campaign's outcome and dispatches code lanes to adopt what survived its
obj-checks — adoption commits carry the DISCLOSURE rows, per the ledger's
checklist.
