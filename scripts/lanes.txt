# THE MODE-LANE REGISTRY — the list of lanes lives HERE, and only here.
#
# Adding a lane is adding a line to this file. It is not remembering a command.
#
# ---- why this file exists ------------------------------------------------------
#
# `scripts/mode_lane.sh` has always taken a mode plus arbitrary flags and it has
# always worked. Nothing enumerated the lanes. So the four lanes recorded through
# `docs/` — `/Ox`, `/O1`, `/O2`, `/Ox /Gy` — were the four somebody happened to
# type, and **not one of them compiles `/EH`**, on a workload whose every single TU
# is compiled `/EHsc`. Two `/EHsc` lanes were added on 2026-07-31, both green, and
# they caught a live wrong-bytes emit every other lane was blind to; whether they
# ran again the next day depended entirely on whoever was at the keyboard
# remembering they existed.
#
# That is the same defect one level up from the one `sweep_mode.sh` was written
# for, and it has now been paid for twice: **a green run is sound only over the
# configurations it was RUN at, and a lane that is not enumerated is a lane that
# does not run.** The `/EHsc` gap alone made the entire EH surface vacuous once —
# a defect exposing 35,964 already-in-class functions survived two rungs because
# every standing lane compiled without `/EH`, so the row collapsed onto its own
# control.
#
# ---- format --------------------------------------------------------------------
#
#   <slug>  <cl flags...>
#
# First field is the lane's name (used by `gate.sh --lane <slug>` and in the
# result table). The rest of the line is spliced into `<flags> /GS- /c` by
# `mode_lane.sh`. Blank lines and `#` comments are ignored. Slugs must be unique —
# `gate.sh --check` enforces that, and enforces that this file is non-empty,
# because an empty registry is a gate that grades nothing while exiting 0.
#
# ---- what the lane set IS, and how it was chosen --------------------------------
#
# Six code-shape configurations crossed with the exception-handling axis: 6 x 2 =
# 12 lanes. The cross is deliberate rather than ad hoc, and the configurations were
# picked by MEASUREMENT (2026-07-31, 197 fixtures, master 814ba7d) — a candidate
# lane was kept only if it graded the corpus differently from a lane already in the
# list. Rows differing, per-TU verdicts compared over the whole scan JSONL:
#
#     /Ox /Gy   vs /Ox    8 rows differ   KEPT   section layout is a real axis
#     /O1 /Oi   vs /O1    6 rows differ   KEPT   and it is what the workload uses
#     /O2       vs /O1    6 rows differ   KEPT
#     /O1 /Gy   vs /O1    0 rows differ   DROPPED — /O1 implies /Gy (OPT_MODE.md
#     /O2 /Gy   vs /O2    0 rows differ   DROPPED   §3.3), confirmed here
#     /Ox /Oi   vs /Ox    0 rows differ   DROPPED — /Ox implies /Oi
#
# So `/Gy` is crossed only over `/Ox` and `/Oi` only over `/O1`: crossing them
# everywhere would have added four lanes that grade nothing the list already has.
# **A cross that manufactures aliases buys breadth on paper and none in fact.**
#
# The `/EHsc` axis is crossed over ALL SIX, and that is the point of the file. Note
# carefully what its measurement does and does not say: `/O1 /EHsc` vs `/O1` also
# differs in **0** verdict rows today — but the reference obj is NOT the same obj
# (byte-compared: the `/EHsc` capture of `w27_fp_reg` is 4,662 bytes against
# 4,654), so the port is reproducing a genuinely different output and merely
# arriving at the same verdict. **Verdict-identical is not redundant.** `/Gy` on
# `/O1` is dropped because the flag is already implied, not because its rows
# matched; the two situations look alike in a verdict table and are not alike.
#
# ---- the `/GR` axis, added 2026-08-04 by lane w-gr (task #40) -------------------
#
# The registry was written because a workload that is **100 % `/EHsc`** had no
# `/EHsc` lane. It shipped for four days with the identical hole one flag over:
# `work/dc3-workload/flags.txt` reads
#
#     /nologo /wd4355 /wd4164 /c /GR /O1 /Oi /EHsc /I …
#
# and **not one of the twelve lanes above passes `/GR`.** `/GR` is what mints
# `.rdata$r` — **24,163 sections across 676 of 871 objs**, factor C's largest
# single step (169 -> 590), and the last workload section name the generated
# corpus could not produce.
#
# **`/GR` is NOT this compiler's default.** MSVC documents `/GR` as on by
# default; this `cl.exe` (X360 16.00.11886.00) behaves as `/GR-` unless `/GR` is
# passed — measured, `.rdata$r` present with it and absent both without it and
# with an explicit `/GR-`. So the flag is a genuine axis and not a spelling, and
# no amount of new *source* would have reached the section without a lane.
#
# ---- what /GR changes, and where the cross is REAL ------------------------------
#
# MEASURED 2026-08-04, `scripts/sweep.d/91-rtti-vftable.py`'s 230 cases captured
# at nine profiles, comparing per case the `.rdata$r` record set and the section
# NAME ORDER (`work/w-gr/sig.py`). Rows are "cases out of 230 that differ":
#
#                                              rtti records   section order
#     /O1 /GR      vs /O1 /Oi /GR                        0              0
#     /O2 /GR      vs /O1 /Oi /GR                        0              0
#     /Ox /Gy /GR  vs /O1 /Oi /GR                        0              0
#     /Ox /GR      vs /O1 /Oi /GR                        0            145   KEPT
#     /Od /GR      vs /Ox /GR                            2             75   KEPT
#     … /EHsc      vs the same base                      0             43   KEPT
#
# Three classes, and each earns its lane:
#
#   * **COMDAT-per-function** (`/O1`, `/O1 /Oi`, `/O2`, `/Ox /Gy`) — these four
#     are **indistinguishable on this axis**: 0 and 0, over 230 cases. One lane
#     covers them, and it is `/O1 /Oi` because that is the workload's own mode.
#   * **packed** (`/Ox`) — 145 of 230 cases put the RTTI block at a different
#     point in the section table. Section index drives symbol index drives the
#     `.pdata` association number, so this is the part the port must be right
#     about.
#   * **unoptimized** (`/Od`) — the only profile that changes *which records
#     exist*. `struct A{…virtual…}; struct S:A{…}; A::~A(){} S::~S(){}` emits
#     **one** vftable + 4 `.rdata$r` at every optimized mode and **two** + 8 at
#     `/Od`. Two cases, eight sections, and no other lane can see it.
#
# `/EHsc` moves the RTTI block's position in 43 of 230 at every base, so the
# exception cross applies here exactly as it does above.
#
# **Deliberately NOT added, each on the measurement above:** `/O2 /GR`,
# `/Ox /Gy /GR` and `/O1 /GR` (0 and 0 against `/O1 /Oi /GR` — the `/O1 /Gy`
# situation, a flag not being varied, not the `/O1 /EHsc` situation), and `/GR-`
# (byte-identical to the default, so it is a spelling). `/Od /GR` **was** on that
# declined list when this lane registered its prediction and the measurement
# refuted it; the row is kept above so the refutation is legible.
#
# ---- cost ----------------------------------------------------------------------
#
# Measured 2026-07-31 on a 32-core host at `C2RS_JOBS=8`, 2,364 fixture-verdicts:
#
#     COLD (2,364 real cl.exe captures — every lane's flag string is a new
#     cache key):                                      6 s at `--jobs 4`
#     WARM:                        4 s at `--jobs 1`,  1 s at `--jobs 4`
#
# Quote the cold number; it is what the gate costs the first time a tree runs it.
# Either way this is nowhere near impractical, which is the whole reason there is
# no excuse for the list to be implicit. Re-measure before adding an axis, and do
# not add a lane whose cost you have not measured.
#
# **The `/GR` axis's cost is +4.0 %, measured after the fact and not estimated.**
# `scripts/mode_classes.txt` regenerated at 18 lanes (5 m 37 s, 24 cases per
# fragment, 23,292 cells) and the two registries scored over the SAME 16,394-case
# corpus with the SAME measurement:
#
#     12 lanes   73,313 gradings
#     18 lanes   76,217 gradings      +2,904   +4.0 %
#     (the unreduced 18-lane cross would be 295,092)
#
# **Every one of those 2,904 is on a fragment that can actually see the axis.**
# Exactly three of 58 separate the `/GR` lanes rather than merging them into
# their plain twins — `91-rtti-vftable` (230 cases), `67-eh-try-throw` (148) and
# `62-ctor-base-delegation` (106), each going from 8 equivalence classes at 12
# lanes to **14** at 18, the widest in the corpus against a median of 4. On the
# other 55 the six lanes collapse and cost nothing.
#
# And before it was added, over the 245
# tracked fixtures, `X` and `X /GR` produce **byte-identical objs on 242 of
# 245** at every base configuration (TimeDateStamp zeroed, and captured to a
# FIXED `-Fo` — c2 bakes the output path into `.debug$S` as `S_OBJNAME`, so a
# per-half output path makes every pair differ for a reason that is not the
# flag). Only the 3 fixtures that emit a vftable differ:
# `w14_dtor_delegate_neg`, `w19_ctor_this_neg`, `wec_ctor_base_neg`. That is why
# the six lanes are affordable: `scripts/mode_invariance.py` merges a lane whose
# IL, `gy` and reference obj all match one already graded, so the `/GR` lanes
# collapse onto their plain twins wherever there is no vftable and cost is paid
# only where the axis buys something.
